매우 날카롭고 핵심적인 질문입니다. 결론부터 말씀드리면 **"네, 맞습니다. 하지만 그 두 공간을 연결해주는 '브릿지(Bridge)' 역할을 하는 행렬이 반드시 존재해야 합니다."**

그래픽스에서는 이를 **로컬 좌표계(Local Space)**, **월드 좌표계(World Space)**, 그리고 이를 잇는 **모델 행렬(Model Matrix/Transformation Matrix)**의 관계로 설명합니다.

### 1. 로컬 공간 (Local Space / Object Space)

각 메쉬(Mesh)는 자기 자신만의 "우주"를 가지고 있습니다.

- 예를 들어, 큐브 메쉬는 파일로 저장될 때 그 중심이 $(0, 0, 0)$이고, 각 버텍스 좌표는 큐브의 크기에 맞춰 정의되어 있습니다.
- 이 상태에서는 이 큐브가 월드 어디에 있는지, 얼마나 큰지 알 수 없습니다. 오직 **"자기 자신으로부터의 상대적 위치"**만 알고 있는 상태입니다.
- 질문하신 **"각각 변형을 가한다"**는 행위는 바로 이 로컬 공간 내에서의 변형(크기 조절, 모양 비틀기 등)을 의미합니다.

### 2. 월드 공간 (World Space)

모든 메쉬가 공통으로 사용하는 "절대적인 좌표계"입니다.

- 월드 좌표계의 $(0, 0, 0)$은 전체 씬(Scene)의 중심입니다.
- 모든 메쉬는 이 월드 좌표계 위에서 서로 어떤 위치에 있는지, 어떤 거리에 있는지 비교될 수 있습니다.

### 3. 로컬과 월드를 잇는 '모델 행렬 (Model Matrix)'

이 부분이 질문의 핵심입니다. 메쉬가 로컬 공간에서 변형되었다고 해서 자동으로 월드에 나타나는 것이 아닙니다. **로컬 공간의 점들을 월드 공간의 점들로 '번역(Translate)'해주는 행렬**이 필요합니다.

우리가 흔히 말하는 **Model Matrix ($M$)**는 다음과 같은 순서로 구성됩니다.
$M = \text{Translation} \times \text{Rotation} \times \text{Scale}$

이 행렬이 수행하는 역할은 다음과 같습니다:

1. **Scale:** 로컬 공간에서 메쉬를 키우거나 줄입니다.
2. **Rotation:** 로컬 공간에서 메쉬를 회전시킵니다.
3. **Translation:** 로컬 공간의 중심을 월드 공간의 특정 좌표로 이동시킵니다.

### 4. 수학적 흐름 (Pipeline)

실제로 컴퓨터가 버텍스를 화면에 그릴 때는 다음과 같은 연쇄적인 행렬 곱셈이 일어납니다.

$\vec{V}_{final} = \text{Projection} \times \text{View} \times \text{Model} \times \vec{V}_{local}$

1. $\vec{V}_{local}$: 메쉬 자체의 좌표 (로컬)
2. $\text{Model} \times \vec{V}_{local}$: **로컬 좌표를 월드 좌표로 변환** (이때 메쉬가 월드 어디에 있는지 결정됨)
3. $\text{View} \times (\dots)$: 월드 좌표를 카메라(눈) 기준 좌표로 변환
4. $\text{Projection} \times (\dots)$: 3D 좌표를 우리가 보는 2D 화면 좌표로 변환

### 요약하자면

- **로컬 공간:** 각 메쉬가 가진 고유한 형태와 변형(Shape 변형)이 정의되는 곳.
- **월드 공간:** 모든 메쉬가 놓여 있는 공통의 무대.
- **행렬의 역할:** 로컬의 변형된 형태를 월드의 특정 위치/방향으로 **"배치"**하는 도구.

따라서, "메쉬 각각에 변형을 가한다"는 것은 각 메쉬의 **Model Matrix**를 다르게 설정하거나, Model Matrix를 계산하기 전 단계인 **로컬 좌표 자체를 수정**하는 행위라고 이해하시면 완벽합니다.

우리가 3D 소프트웨어(Blender, Maya, Unity, Unreal 등)의 뷰포트에서 마우스로 물체를 잡고 돌리거나 크기를 조절할 때, **그 변화가 실시간(Real-time)으로 부드럽게 보이는 이유는 컴퓨터가 초당 수십~수백 번씩 이 행렬 연산을 반복해서 수행하기 때문**입니다.

이 과정을 조금 더 구체적으로 들여다보면, 다음과 같은 메커니즘이 작동하고 있습니다.

### 1. 매 프레임(Frame)마다의 재계산

우리가 뷰포트에서 물체를 움직이면, 소프트웨어는 내부적으로 다음과 같은 루프를 아주 빠르게 돌립니다.

1. **입력 감지:** 사용자가 마우스를 움직였다는 것을 감지합니다.
2. **행렬 업데이트:** 마우스 이동량에 따라 물체의 **Model Matrix(위치, 회전, 크기 값)**를 새로 계산합니다.
3. **GPU로 전달:** 업데이트된 새로운 행렬 값을 그래픽 카드(GPU)로 보냅니다.
4. **병렬 연산:** GPU는 수만 개의 버텍스 좌표에 이 행렬을 **동시에(Parallel)** 곱해서 새로운 위치를 찾아냅니다.
5. **렌더링:** 바뀐 위치의 점들을 화면에 그립니다.

이 과정이 1초에 60번(60 FPS) 이상 일어나기 때문에, 우리 눈에는 끊김 없이 "실시간으로 변하고 있다"고 느껴지는 것입니다.

### 2. CPU와 GPU의 역할 분담

이 엄청난 양의 계산을 효율적으로 처리하기 위해 역할이 나뉩니다.

- **CPU (지휘관):** "사용자가 물체를 $30^\circ$ 돌렸어. 그럼 새로운 Model Matrix는 이거야!"라고 **행렬의 값 자체를 계산**하고 명령을 내립니다.
- **GPU (병사):** CPU가 준 행렬을 받아서, **수백만 개의 버텍스 좌표에 실제로 곱하는 노가다**를 수행합니다. GPU는 수천 개의 코어가 동시에 계산할 수 있도록 설계되어 있어서, 모든 점의 위치를 한꺼번에 계산하는 데 압도적으로 빠릅니다.

### 3. 뷰포트의 "환상" (View & Projection)

사용자가 물체를 움직일 때, 사실은 **물체만 움직이는 게 아니라 카메라(View)와 화면(Projection)의 행렬도 계속 계산**되고 있습니다.

- 물체를 돌리면 $\rightarrow$ **Model Matrix**가 변하고,
- 카메라를 움직이면 $\rightarrow$ **View Matrix**가 변하며,
- 줌인을 하면 $\rightarrow$ **Projection Matrix**가 변합니다.

이 세 가지 행렬이 결합된 결과물이 매 순간 화면에 그려지기 때문에, 우리는 마치 가상 공간 속에 실제로 들어가서 물체를 만지고 있는 듯한 **시각적 환상**을 경험하게 됩니다.

### 결론적으로

사용자님이 느끼시는 "순식간에 일어나는 변화"는 **[사용자의 입력 $\rightarrow$ 행렬 값 업데이트 $\rightarrow$ GPU의 초고속 병렬 행렬 연산 $\rightarrow$ 화면 갱신]**이라는 거대한 파이프라인이 아주 짧은 시간(밀리초 단위) 안에 반복되는 결과물입니다.

결국 **"행렬 연산의 속도 = 3D 그래픽스의 성능"**이라고 해도 과언이 아닙니다.
