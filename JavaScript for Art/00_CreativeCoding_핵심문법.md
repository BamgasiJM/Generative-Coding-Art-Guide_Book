# Creative Coding을 위한 JavaScript 핵심 문법

***

본 문서는 자바스크립트의 핵심 개념을 독립적인 단위로 나누어 정리했습니다. 각 개념이 \*\*p5.js(2D/Sketches)\*\*와 **Three.js(3D/Architecture)** 환경에서 어떻게 다르게 적용되는지 비교하며 학습하세요.

***

## 1. 변수와 스코프 (Variables & Scope)

변수가 어디서 살아남고 어디서 사라지는지에 대한 규칙입니다. `let`과 `const`의 블록 스코프 이해가 필수입니다.

### p5.js의 경우

* `setup()`과 `draw()` 외부 상단에 선언된 변수는 **전역 변수**로 취급되어 스케치 전체에서 상태를 공유합니다.
* `draw()` 내부에서 선언된 `let` 변수는 매 프레임마다 초기화되므로, 프레임 간에 값을 유지하려면 반드시 `draw()` 밖으로 빼야 합니다.

### Three.js의 경우

* 장면(Scene), 카메라(Camera), 렌더러(Renderer) 등은 애플리케이션 수명 내내 유지되어야 하므로 주로 상위 스코프나 모듈의 최상단에서 관리합니다.
* `requestAnimationFrame` 루프 내부에서 `new THREE.Vector3()` 같은 객체를 변수로 계속 선언하면 가비지 컬렉션(GC) 부하가 걸리므로, 임시 변수는 루프 밖에서 미리 만들어두고 재사용하는 패턴이 중요합니다.

***

## 2. 데이터 타입과 참조 (References)

객체(Object)나 배열(Array)을 변수에 담을 때, 값이 복사되는 것이 아니라 메모리 주소가 연결된다는 개념입니다.

### p5.js의 경우

* `p5.Vector`를 다룰 때 가장 중요합니다. `v1 = v2`라고 쓰면 `v2`를 수정할 때 `v1`도 같이 바뀝니다. 이를 막기 위해 `v1 = v2.copy()` 메서드를 사용해야 합니다.

### Three.js의 경우

* `position`, `rotation`, `scale`은 모두 객체(`Vector3`, `Euler`)입니다. `mesh.position = newPos`처럼 할당하기보다, `mesh.position.copy(newPos)` 또는 `mesh.position.set(x, y, z)`을 사용하여 기존 객체의 값을 업데이트하는 것이 성능상 유리하고 참조 오류를 막습니다.

***

## 3. 구조 분해 할당 (Destructuring Assignment)

객체나 배열 내부의 값을 개별 변수로 추출해내는 현대적 문법입니다.

### p5.js의 경우

* 외부 API에서 가져온 복잡한 JSON 데이터(날씨 정보, 픽셀 배열 등)에서 필요한 좌표값이나 색상값만 쏙 뽑아낼 때 유용합니다.

### Three.js의 경우

* 함수에 옵션을 전달할 때 매우 많이 쓰입니다. `Geometry`나 `Material`을 생성할 때 `{ color, wireframe, opacity }`처럼 필요한 속성만 정의하거나 추출하여 코드를 간결하게 만듭니다.

***

## 4. 전개 연산자 (Spread Operator)

배열이나 객체를 펼쳐서 복사하거나 병합하는 문법(`...`)입니다.

### p5.js의 경우

* 배열에 담긴 파티클 리스트에 새로운 파티클들을 추가하거나, 기존 설정 객체에 새로운 설정을 덮어쓸 때 유용합니다.
* `min(...values)`처럼 배열의 값을 함수의 개별 인자로 전달할 때 씁니다.

### Three.js의 경우

* 기본(Default) 머티리얼 설정 객체를 만들어두고, 특정 메쉬만 설정을 다르게 할 때 `const newMat = { ...baseOptions, color: 0xff0000 }` 형태로 설정을 상속받아 사용합니다.

***

## 5. 화살표 함수와 this (Arrow Functions)

함수 선언 방식에 따라 `this`가 가리키는 대상이 달라지는 현상을 다룹니다.

### p5.js의 경우

* 라이브러리 자체가 전역 함수(`setup`, `draw`) 기반인 경우가 많아 화살표 함수보다는 `function` 키워드가 자주 보입니다.
* `setTimeout`이나 클릭 이벤트 내부에서 스케치 인스턴스에 접근할 때는 화살표 함수가 필수적입니다.

### Three.js의 경우

* 클래스 기반으로 코드를 짤 때 핵심입니다. 애니메이션 루프 메서드(`animate()`)를 `requestAnimationFrame`에 넘길 때, 일반 함수를 쓰면 `this`를 잃어버립니다. 화살표 함수나 `.bind(this)`를 써야 클래스 멤버 변수(`scene`, `camera`)에 접근할 수 있습니다.

***

## 6. 고차 함수 (Higher-Order Functions)

함수를 인자로 받거나, 배열을 순회하며 함수를 실행하는 `map`, `filter`, `forEach` 등을 말합니다.

### p5.js의 경우

* 파티클 시스템에서 화면 밖으로 나간 파티클을 제거할 때 `particles.filter()`를 사용하거나, 모든 파티클을 업데이트할 때 `particles.forEach()`를 사용하여 `for` 루프보다 직관적인 코드를 작성합니다.

### Three.js의 경우

* 씬 그래프(Scene Graph)의 자식 요소들을 순회하는 `scene.traverse((object) => { ... })` 메서드가 고차 함수의 패턴을 따릅니다. 이를 통해 모든 메쉬의 그림자 설정을 한 번에 켜는 등의 작업을 합니다.

***

## 7. 객체와 프로토타입 (Objects & Prototypes)

자바스크립트가 객체를 생성하고 상속하는 근본적인 메커니즘입니다.

### p5.js의 경우

* 간단한 객체 리터럴 `{ x: 10, y: 10 }`을 사용하여 상태를 저장하는 경우가 많습니다.

### Three.js의 경우

* Three.js의 내부 코드는 프로토타입 체인으로 최적화되어 있습니다. 메모리 절약을 위해 지오메트리나 머티리얼을 인스턴스 간에 **공유**하는 개념을 이해해야 합니다.

***

## 8. 클래스 (Classes)

객체 지향 프로그래밍을 위한 ES6 문법입니다.

### p5.js의 경우

* Daniel Shiffman의 예제에서 보듯 `Mover`, `Particle`, `Walker` 같은 에이전트를 정의하는 표준적인 방법입니다. 데이터(`x`, `y`)와 행동(`update`, `display`)을 하나로 묶습니다.

### Three.js의 경우

* 기존 `THREE.Mesh`나 `THREE.Group`을 `extends`하여 나만의 커스텀 3D 객체(예: `class Robot extends THREE.Group`)를 만들 때 필수적입니다. 이를 통해 복잡한 3D 오브젝트를 모듈화할 수 있습니다.

***

## 9. 배열 (Arrays)

데이터의 순서가 있는 집합입니다.

### p5.js의 경우

* 매 프레임 그려질 도형들의 좌표나 속성을 저장하는 컨테이너입니다. 배열의 길이를 조절하여 화면에 그리는 개체의 수를 동적으로 제어합니다.

### Three.js의 경우

* 일반 배열보다 **Typed Array**(형식화 배열) 개념이 중요합니다. `Float32Array`는 GPU에 버텍스(Vertex) 데이터를 보낼 때 사용되는 고성능 배열로, `BufferAttribute`를 직접 조작할 때 반드시 알아야 합니다.

***

## 10. 컬렉션 (Map & Set)

배열보다 검색과 중복 관리에 특화된 자료구조입니다.

### p5.js의 경우

* 충돌 감지 등에서 이미 검사한 객체 쌍을 저장하거나, 중복된 좌표 생성을 방지할 때 `Set`을 사용하면 배열보다 훨씬 빠릅니다.

### Three.js의 경우

* 수많은 텍스처나 모델 에셋을 로딩할 때, 파일 경로(`String`)를 키(`Key`)로 하고 로드된 객체를 값(`Value`)으로 저장하는 캐시 시스템을 만들 때 `Map`이 유용합니다.

***

## 11. 프로미스 (Promises)

비동기 작업의 완료나 실패를 나타내는 객체입니다.

### p5.js의 경우

* `loadJSON`이나 `loadImage`는 내부적으로 콜백 방식을 주로 사용하지만, 최신 웹 API(`fetch` 등)를 사용할 때는 프로미스 개념이 필요합니다.

### Three.js의 경우

* `GLTFLoader`나 `TextureLoader`의 `.loadAsync()` 메서드는 프로미스를 반환합니다. 로딩 진행률을 관리하거나 여러 에셋 로딩을 제어할 때 사용됩니다.

***

## 12. 비동기/대기 (Async / Await)

프로미스를 동기 코드처럼 읽기 쉽게 작성하는 문법입니다.

### p5.js의 경우

* `preload()` 함수가 없는 환경에서 외부 데이터를 불러온 뒤 스케치를 시작해야 할 때, 실행 순서를 보장하기 위해 사용합니다.

### Three.js의 경우

* "모델 로딩 → 텍스처 적용 → 씬에 추가"라는 순차적인 작업 흐름을 콜백 지옥 없이 깔끔하게 작성할 수 있게 해줍니다. 특히 여러 개의 무거운 3D 모델을 순서대로 로드해야 할 때 필수적입니다.

***

## 13. 모듈 (Modules)

코드를 여러 파일로 나누고 `import`, `export` 하는 기능입니다.

### p5.js의 경우

* 전통적인 방식(HTML에 `script` 태그 여러 개 나열)을 넘어서, `Particle.js`, `System.js` 등으로 파일을 나누어 프로젝트를 체계적으로 관리할 때 사용합니다.

### Three.js의 경우

* 현대 Three.js는 기본적으로 모듈 기반입니다. `import * as THREE from 'three';`와 같이 라이브러리를 불러오고, `OrbitControls` 같은 애드온을 별도로 임포트해서 사용하는 방식에 익숙해져야 합니다.
