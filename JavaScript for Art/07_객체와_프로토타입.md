## 개념 설명

자바스크립트는 클래스(Class) 문법을 쓰더라도 내부적으로는 \*\*프로토타입(Prototype)\*\*을 통해 상속을 구현합니다. "모든 인스턴스가 공통된 메서드 창고(Prototype)를 공유한다"는 점이 핵심입니다. 이를 이해하면 메모리 최적화의 원리를 알 수 있습니다.

## p5.js 예시 : 메서드 공유

상황: 파티클 10,000개를 만들 때, update 함수를 각 객체마다 만들면 사용하는 메모리가 폭증합니다. 프로토타입(또는 클래스)을 써야 함수가 딱 한 번만 메모리에 생성되고 공유됩니다.

```javascript
// [비효율적인 방식] - 팩토리 함수
function createParticle(x, y) {
  return {
    x, y,
    // 이 함수가 파티클 10,000개마다 각각 새로 생성됨 (메모리 낭비)
    update: function() { this.x += 1; } 
  };
}

// [효율적인 방식] - 클래스 (내부적으로 프로토타입 사용)
class Particle {
  constructor(x, y) {
    this.x = x; // 데이터는 각자 가짐
    this.y = y;
  }
  
  // 이 메서드는 메모리에 딱 하나만 존재하고, 모든 Particle이 공유함 (참조)
  update() {
    this.x += 1;
  }
}
```

## Three.js 예시 : 지오메트리와 머티리얼 공유

Three.js의 `Mesh`도 프로토타입 개념과 유사하게 데이터 공유가 핵심입니다. 똑같은 상자 100개를 그릴 때, 지오메트리 객체는 하나만 만들고 100개의 메쉬가 이를 참조(공유)해야 합니다.

```javascript
// [메모리 절약의 핵심]
// 프로토타입처럼 '공유 자원'을 먼저 만듭니다.
const sharedGeometry = new THREE.BoxGeometry(1, 1, 1);
const sharedMaterial = new THREE.MeshNormalMaterial();

const meshes = [];

for (let i = 0; i < 100; i++) {
  // 각 메쉬는 자신만의 위치(position), 회전(rotation) 데이터는 따로 가지지만,
  // 무거운 정점 데이터(geometry)와 쉐이더(material)는 공유합니다.
  const mesh = new THREE.Mesh(sharedGeometry, sharedMaterial);
  
  mesh.position.set(Math.random() * 10, 0, 0);
  scene.add(mesh);
  meshes.push(mesh);
}

// 만약 루프 안에서 new BoxGeometry()를 계속 했다면?
// GPU 메모리가 100배로 낭비됩니다.
```
