# 17.1 재귀와 반복 구조

재귀(recursion)는 함수가 자기 자신을 다시 호출하는 방식이고, 반복(iteration)은 반복문이 같은 작업을 차례로 실행하는 방식이다. 두 방식 모두 간단한 규칙을 여러 번 적용하지만, 구조를 표현하고 상태를 다루는 방법이 다르다. 재귀는 한 요소가 여러 자식 요소를 만드는 계층 구조를 표현하기 쉽고, 반복은 정해진 수의 항목을 차례로 처리하거나 시간에 따라 상태를 갱신할 때 자연스럽다.

## 재귀를 이루는 두 부분

재귀 함수에는 더 진행하지 않고 끝나는 종료 조건과, 아직 끝나지 않았을 때 다음 단계로 이어지는 재귀 단계가 필요하다. 종료 조건을 기본 사례(base case)라고도 부른다. 재귀 단계에서는 문제를 더 작게 만들거나 깊이를 늘려 종료 조건에 가까워져야 한다.

아래 예시는 가지 끝에서 두 갈래를 만들며 길이를 줄이는 간단한 트리다. `position`, `heading`, `length`, `depth`를 매번 인자로 전달하므로 각 가지의 상태가 분명하다.

```text
branch(position, heading, length, depth):
    if depth > maxDepth or length < minLength:
        return

    end = position + direction(heading) * length
    drawLine(position, end)

    nextLength = length * ratio
    branch(end, heading - branchAngle, nextLength, depth + 1)
    branch(end, heading + branchAngle, nextLength, depth + 1)
```

각 호출은 선분 하나를 그리고 자식 가지를 두 번 호출한다. `ratio`는 가지가 짧아지는 비율이며 보통 $0<\text{ratio}<1$로 둔다. `branchAngle`은 두 자식이 부모 방향에서 얼마나 벌어질지를 정한다. 위치와 길이는 같은 캔버스 좌표 단위를 쓰고, `heading`과 `branchAngle`은 같은 각도 단위(보통 라디안)로 표현한다. 여기서는 시작 가지의 `depth`를 0으로 세고, `maxDepth`는 선분을 그릴 수 있는 마지막 단계다. `minLength`는 화면에서 너무 작아진 선분을 더 만들지 않게 하는 최소 길이다. 둘 중 하나라도 충족되면 해당 가지에서 재귀가 끝난다.

반면 한 자식만 계속 만드는 다음 규칙은 분기 트리가 아니라 길이가 줄어드는 선분의 연쇄를 만든다.

```text
segment(length):
    if length < minLength:
        return
    drawSegment(length)
    segment(length * ratio)
```

재귀 호출이 자기 자신을 부른다는 사실만으로 분기가 생기는 것은 아니다. 한 호출에서 자식을 몇 개 만들고, 자식에게 어떤 상태를 넘기는지가 형태를 결정한다. 이 구분은 트리뿐 아니라 작은 도형을 반복 배치하거나 서로 다른 규칙을 계층적으로 연결할 때도 중요하다.

## 반복되는 요소 수와 종료 비용

호출마다 자식이 두 개라면 단계가 하나 늘어날 때 말단 가지의 수는 두 배가 된다. 분기 수를 $b$, 시작 단계를 0으로 둔 최대 깊이를 $d$라고 할 때, 그려지는 요소의 최대 수는 각 단계의 요소를 더한 값이다.

$$
N_d=1+b+b^2+\cdots+b^d=\frac{b^{d+1}-1}{b-1}\qquad (b\ne1)
$$

예를 들어 자식이 둘이고 최대 깊이가 8이면 선분은 최대 511개 그려진다. 깊이를 한 단계 늘리는 일이 단순히 선분 하나만 더하는 것이 아니라는 뜻이다. 이 때문에 화면에서 차이를 알아보기 어려운 세부까지 무조건 확장하면 그리는 요소와 계산량이 빠르게 늘어난다. 반복 깊이와 분기 수는 형태의 복잡도뿐 아니라 실행 비용도 결정한다.

종료 조건은 단순히 코드를 멈추기 위한 장치가 아니다. 최소 길이를 높이면 가는 끝부분이 줄어들고, 깊이를 낮추면 가지의 층이 적어져 더 단순한 형태가 된다. 캔버스 밖의 가지를 종료하면 화면 안에 필요한 부분만 계산할 수도 있다. 재귀 단계마다 깊이가 증가하거나 길이가 감소하는 등 종료 조건에 가까워지는 변화가 반드시 있어야 한다. 같은 인자와 상태로 자신을 다시 호출하면 조건에 도달하지 못해 호출이 끝없이 이어질 수 있다.

## 같은 구조를 반복문으로 표현하기

재귀로 만든 트리는 반복문과 명시적인 자료 구조로도 만들 수 있다. 예를 들어 아직 처리하지 않은 가지의 상태를 스택(stack)에 넣고, 하나씩 꺼내 그린 뒤 자식 상태를 다시 스택에 넣는다.

```text
pending = [(startPosition, startHeading, startLength, 0)]

while pending is not empty:
    position, heading, length, depth = pending.pop()
    if depth > maxDepth or length < minLength:
        continue

    end = position + direction(heading) * length
    drawLine(position, end)
    nextLength = length * ratio

    pending.push((end, heading - branchAngle, nextLength, depth + 1))
    pending.push((end, heading + branchAngle, nextLength, depth + 1))
```

재귀 방식은 부모에서 자식으로 이어지는 관계가 코드의 호출 관계와 닮아 있어 구조를 읽기 쉽다. 반복문 방식은 처리할 작업을 자료 구조에 직접 보관하므로 호출 깊이를 직접 관리할 수 있지만, 스택의 추가와 제거를 직접 다뤄야 한다. 어느 쪽이든 생성되는 선분 수 자체는 같으므로 반복문으로 바꾼다고 분기 수에 따른 작업량이 사라지는 것은 아니다.

재귀 호출이 진행되는 동안 아직 끝나지 않은 부모 함수의 상태는 호출 스택(call stack)에 보관된다. 한 갈래로 깊게 이어지는 재귀는 호출 깊이에 비례해 스택을 사용하고, 여러 갈래로 분기하면 방문할 전체 요소 수가 빠르게 늘어난다. 깊이 제한은 끝없는 호출을 막고, 요소 수 제한은 한 번에 만드는 작업량을 제한한다. 반복문에서 사용하는 `pending` 스택도 처리할 가지를 직접 보관하므로 공간이 필요하다. 반복문이 모든 메모리 비용을 없애는 것은 아니지만, 대기 작업의 수를 직접 확인하고 제한하기 쉽다.

반복문은 같은 규칙을 일정한 순서로 적용하는 작업에 잘 맞는다. 격자의 모든 셀을 한 번씩 검사하거나, 매 프레임 입자의 위치와 나이를 갱신하는 일은 보통 반복문으로 표현한다. 재귀는 가지마다 자식 수나 깊이가 달라지는 계층 구조에 편리하다. 그러나 둘은 서로 배타적인 도구가 아니다. 프랙탈 도형이나 분기 트리도 반복문으로 만들 수 있고, 반복 횟수가 정해진 작업도 재귀로 표현할 수 있다. 어떤 방식이 더 알맞은지는 구조와 상태를 어느 쪽에서 더 명확하게 읽을 수 있는지에 달려 있다.

## 형태와 계산에 함께 적용하기

재귀 함수가 매번 같은 비율로 길이를 줄이거나 각도를 바꾸면 각 단계가 앞 단계의 축소판처럼 이어질 수 있다. 이런 규칙은 프랙탈의 자기 유사성과 연결되며 다음 절에서 자세히 다룬다. 기호를 계속 다시 쓰고 해석해 더 복잡한 분기 구조를 만드는 방식은 17.3절의 L-System에서 살펴본다.

시간에 따라 변하는 시뮬레이션에서는 재귀 호출로 전체 구조를 한 번 만드는 것과, 반복문으로 매 프레임 상태를 갱신하는 일을 구별하면 좋다. 전자는 가지나 계층을 생성하는 절차이고, 후자는 이미 존재하는 요소를 시간에 따라 움직이는 절차다. 한 작품에서 트리를 재귀로 만들고, 각 가지 끝의 입자나 색을 반복문으로 갱신하는 것처럼 두 방식을 함께 사용할 수도 있다.

## 이 절의 핵심

재귀는 자기 호출을 통해 부모와 자식의 계층을 표현하고, 반복은 같은 처리를 차례로 수행한다. 재귀에는 진행을 보장하는 종료 조건과 단계별 상태 변화가 필요하다. 분기 수와 깊이는 요소 수를 빠르게 늘리므로, 화면에서 의미 있는 세부 수준에 맞춰 복잡도를 제한한다. 프랙탈과 L-System은 이러한 반복·재작성 규칙을 형태 생성에 적용하는 사례다.
