# 17.1 재귀와 반복 구조

재귀(recursion)는 함수가 자기 자신을 다시 호출하는 방식이고, 반복(iteration)은 반복문으로 같은 작업을 차례로 수행하는 방식이다. 두 방식 모두 간단한 규칙을 여러 번 적용하지만, 구조를 표현하고 상태를 다루는 방법에는 차이가 있다. 재귀는 한 요소가 여러 자식 요소를 만드는 계층 구조를 표현하기 쉽고, 반복은 정해진 항목을 차례로 처리하거나 시간에 따라 상태를 갱신할 때 자연스럽다.

## 재귀를 이루는 두 부분

재귀 함수에는 처리를 끝내는 종료 조건과, 다음 단계로 이어지는 재귀 단계가 필요하다. 종료 조건은 기본 사례(base case)라고도 한다. 재귀 단계에서는 문제를 더 작은 부분으로 나누거나 깊이를 늘려 종료 조건에 가까워져야 한다.

아래 예시는 가지 끝에서 두 갈래로 나뉘며 길이가 줄어드는 간단한 트리다. `position`, `heading`, `length`, `depth`를 인자로 전달해 각 가지의 상태를 명시한다.

```text
branch(position, heading, length, depth):
    if depth > maxDepth or length < minLength:
        return

    end = position + direction(heading) * length
    drawLine(position, end)

    nextLength = length * ratio
    branch(end, heading - branchAngle, nextLength, depth + 1)
    branch(end, heading + branchAngle, nextLength, depth + 1)
```

각 호출은 선분 하나를 그리고 자식 가지를 두 번 호출한다. `ratio`는 가지가 짧아지는 비율로, 보통 $0<\text{ratio}<1$이다. `branchAngle`은 자식 가지가 부모 방향에서 얼마나 벌어질지 정한다. 위치와 길이는 캔버스 좌표 단위로, `heading`과 `branchAngle`은 같은 각도 단위(보통 라디안)로 표현한다. 이 예에서는 시작 가지의 `depth`를 0으로 세며, `maxDepth`는 선분을 그릴 수 있는 마지막 단계다. `minLength`는 화면에서 너무 작아진 선분을 더 만들지 않도록 정하는 최소 길이다. 두 조건 중 하나라도 충족되면 해당 가지의 재귀가 끝난다.

반면 한 자식만 계속 만드는 다음 규칙은 분기 트리가 아니라 길이가 줄어드는 선분의 연쇄를 만든다.

```text
segment(length):
    if length < minLength:
        return
    drawSegment(length)
    segment(length * ratio)
```

함수가 자기 자신을 호출한다고 해서 반드시 분기가 생기는 것은 아니다. 한 호출이 자식을 몇 개 만들고, 자식에게 어떤 상태를 전달하는지가 형태를 결정한다. 이 점은 트리뿐 아니라 작은 도형을 반복 배치하거나 여러 규칙을 계층적으로 연결할 때도 중요하다.

## 반복되는 요소 수와 종료 비용

호출마다 자식이 두 개라면 단계가 하나 늘 때마다 말단 가지 수는 두 배가 된다. 분기 수를 $b$, 시작 단계를 0으로 둔 최대 깊이를 $d$라고 할 때, 그려지는 요소의 최대 수는 모든 단계의 요소를 합한 값이다.

$$
N_d=1+b+b^2+\cdots+b^d=\frac{b^{d+1}-1}{b-1}\qquad (b\ne1)
$$

예를 들어 자식이 둘이고 최대 깊이가 8이면 선분은 최대 511개 그려진다. 깊이를 한 단계 늘리는 것은 선분 하나를 더하는 데 그치지 않는다. 화면에서 구별하기 어려운 세부까지 계속 확장하면 요소 수와 계산량이 빠르게 증가한다. 반복 깊이와 분기 수는 형태의 복잡도뿐 아니라 실행 비용도 좌우한다.

종료 조건은 코드를 멈추기 위한 장치인 동시에 형태를 조절하는 기준이다. 최소 길이를 높이면 가는 끝부분이 줄고, 깊이를 낮추면 가지의 층이 적어져 더 단순한 형태가 된다. 캔버스 밖으로 벗어난 가지에서 처리를 끝내면 화면에 필요한 부분만 계산할 수도 있다. 재귀 단계에서는 깊이를 늘리거나 길이를 줄이는 등 종료 조건에 가까워지는 변화가 필요하다. 같은 인자와 상태로 자신을 다시 호출하면 종료 조건에 도달하지 못해 호출이 끝없이 이어질 수 있다.

## 같은 구조를 반복문으로 표현하기

재귀로 만든 트리는 반복문과 명시적인 자료 구조로도 만들 수 있다. 예를 들어 아직 처리하지 않은 가지의 상태를 스택(stack)에 넣고, 하나씩 꺼내 그린 뒤 자식 상태를 다시 스택에 넣는다.

```text
pending = [(startPosition, startHeading, startLength, 0)]

while pending is not empty:
    position, heading, length, depth = pending.pop()
    if depth > maxDepth or length < minLength:
        continue

    end = position + direction(heading) * length
    drawLine(position, end)
    nextLength = length * ratio

    pending.push((end, heading - branchAngle, nextLength, depth + 1))
    pending.push((end, heading + branchAngle, nextLength, depth + 1))
```

재귀 방식은 부모와 자식의 관계가 함수 호출 구조와 닮아 있어 코드를 읽기 쉽다. 반복문 방식은 처리할 작업을 자료 구조에 보관하므로 호출 깊이를 직접 관리할 수 있지만, 스택에 상태를 넣고 꺼내는 처리가 필요하다. 어느 방식을 사용해도 생성되는 선분 수는 같으므로, 반복문으로 바꾸더라도 분기 수에 따른 작업량은 줄지 않는다.

재귀가 진행되는 동안 끝나지 않은 부모 함수의 상태는 호출 스택(call stack)에 보관된다. 한 갈래로 깊게 이어지는 재귀는 깊이에 비례해 스택을 사용하고, 여러 갈래로 분기하면 방문할 요소 수가 빠르게 늘어난다. 깊이 제한은 끝없는 호출을 막고, 요소 수 제한은 한 번에 처리할 작업량을 통제한다. 반복문에서 사용하는 `pending` 스택도 아직 처리하지 않은 가지를 저장하므로 메모리가 필요하다. 반복문이 메모리 비용을 없애는 것은 아니지만, 대기 작업 수를 직접 확인하고 제한하기 쉽다.

반복문은 같은 규칙을 일정한 순서로 적용하는 작업에 잘 맞는다. 격자의 모든 셀을 검사하거나 매 프레임 입자의 위치와 나이를 갱신하는 일은 보통 반복문으로 표현한다. 재귀는 가지마다 자식 수나 깊이가 달라지는 계층 구조에 편리하다. 두 방식은 서로 배타적이지 않다. 프랙탈 도형과 분기 트리도 반복문으로 만들 수 있고, 반복 횟수가 정해진 작업도 재귀로 표현할 수 있다. 어떤 방식을 선택할지는 구조와 상태를 어느 쪽에서 더 명확하게 표현할 수 있는지에 달려 있다.

## 형태와 계산에 함께 적용하기

재귀 함수에서 길이를 일정한 비율로 줄이거나 각도를 바꾸면 각 단계가 앞 단계의 축소판처럼 이어질 수 있다. 이런 규칙은 프랙탈의 자기 유사성과 연결되며, 다음 절에서 자세히 살펴본다. 기호를 반복해서 다시 쓰고 해석해 분기 구조를 만드는 방식은 17.3절의 L-System에서 다룬다.

시간에 따라 변하는 시뮬레이션에서는 재귀 호출로 구조를 생성하는 일과 반복문으로 매 프레임 상태를 갱신하는 일을 구분하면 좋다. 재귀는 가지나 계층을 만들고, 반복문은 이미 존재하는 요소를 시간에 따라 움직이는 데 사용할 수 있다. 예를 들어 트리는 재귀로 만들고 각 가지 끝의 입자와 색은 반복문으로 갱신할 수 있다.

## 이 절의 핵심

재귀는 자기 호출을 통해 부모와 자식의 계층을 표현하고, 반복은 같은 처리를 차례로 수행한다. 재귀에는 진행을 보장하는 종료 조건과 단계별 상태 변화가 필요하다. 분기 수와 깊이는 요소 수를 빠르게 늘리므로, 화면에서 의미 있는 세부 수준에 맞춰 복잡도를 제한한다. 프랙탈과 L-System은 이러한 반복·재작성 규칙을 형태 생성에 적용하는 사례다.
