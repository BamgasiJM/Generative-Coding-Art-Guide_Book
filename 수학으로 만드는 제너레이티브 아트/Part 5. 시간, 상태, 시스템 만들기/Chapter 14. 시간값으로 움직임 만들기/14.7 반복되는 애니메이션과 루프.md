# 14.7 반복되는 애니메이션과 루프

루프 애니메이션은 마지막 프레임에서 첫 프레임으로 자연스럽게 이어져야 한다. 시작과 끝의 화면이 비슷한 것만으로는 충분하지 않다. 위치, 색, 형태 같은 값뿐 아니라 변화의 방향과 속도도 경계에서 이어져야 반복이 눈에 띄지 않는다.

루프는 전시 화면, 배경 애니메이션, GIF, 짧은 영상, 실시간 시각화처럼 일정한 시간 구간을 반복 재생하는 작업에서 중요하다. 루프 길이에 맞춰 시간 함수의 매개변수를 설계하면 관람자는 재생이 다시 시작되는 순간을 의식하지 않고 변화의 흐름을 볼 수 있다.

## 루프의 기본 조건

길이가 $T$인 루프에서 시간 $t=0$과 $t=T$는 같은 상태를 나타내야 한다. 주기적인 함수 $F$를 사용한다면 다음 조건을 만족해야 한다.

$$
F(\mathbf{p},0)=F(\mathbf{p},T)
$$

부드러운 루프에서는 값뿐 아니라 변화율도 이어지는 것이 바람직하다.

$$
\frac{\partial F}{\partial t}(\mathbf{p},0)=
\frac{\partial F}{\partial t}(\mathbf{p},T)
$$

사인과 코사인 같은 주기 함수는 이 조건을 자연스럽게 만족한다. 시간 $t$를 한 주기 안의 각도 $\theta$로 바꾸면, 루프의 시작과 끝은 같은 각도로 돌아온다.

$$
\theta(t)=2\pi\frac{t}{T}
$$

```text
loopPhase = TAU * time / loopDuration
value = sin(loopPhase)
```

$t=0$에서는 $\theta=0$, $t=T$에서는 $\theta=2\pi$이므로 `sin`의 값과 기울기는 같다. 루프는 시간값을 처음으로 되돌리는 데 그치지 않는다. 시간 함수의 입력과 출력이 시작 상태에 자연스럽게 이어지도록 설계해야 한다.

## 시간 모듈러와 주기 함수의 차이

`time % loopDuration`을 사용하면 시간값이 $[0,T)$ 범위 안에서 반복된다.

```text
loopTime = time % loopDuration
```

이 연산만으로는 그 시간값을 사용하는 함수가 루프 경계에서 이어진다고 보장할 수 없다. 예를 들어 선형 이동을 그대로 계산하면 마지막 순간과 첫 순간의 위치가 멀리 떨어질 수 있다.

```text
loopTime = time % loopDuration
x = velocity * loopTime
```

이 경우 `loopTime`이 $T$ 근처에서 $0$으로 돌아오는 순간 물체가 오른쪽 끝에서 왼쪽 끝으로 순간 이동한다. 화면을 감싸는 반복 타일에서는 의도한 효과일 수 있지만, 일반 도형이나 카메라를 움직일 때는 이음새가 드러난다.

모듈러 시간은 반복할 시간 범위를 정하고, 주기 함수는 경계에서 값과 변화율을 이어 준다. 두 방법은 함께 쓸 수 있지만 역할은 다르다. 루프를 만들 때는 최종 출력이 경계에서 자연스럽게 이어지는지 확인해야 한다.

## 주기 함수로 위치와 형태를 닫기

원운동은 가장 단순한 닫힌 경로다. 시간 위상에 사인과 코사인을 사용하면 시작 위치와 속도가 모두 이어진다.

$$
\mathbf{p}(t)=
\begin{pmatrix}
c_x+r\cos\theta(t)\\
c_y+r\sin\theta(t)
\end{pmatrix}
$$

```text
theta = TAU * time / loopDuration
position.x = center.x + radius * cos(theta)
position.y = center.y + radius * sin(theta)
```

크기, 회전, 색 보간도 같은 위상을 공유하거나 정수배 위상을 사용하면 루프 길이에 맞출 수 있다.

```text
theta = TAU * time / loopDuration
size = baseSize + sizeAmount * sin(theta * 2 + sizePhase)
rotation = theta * 3
brightness = 0.5 + 0.5 * sin(theta + brightnessPhase)
```

이 예에서 크기는 한 루프 동안 두 번, 회전은 세 번 반복한다. 반복 횟수가 정수이므로 모두 $t=T$에서 처음 상태로 돌아온다. 비정수배를 사용하면 시작과 끝의 위상이 어긋날 수 있다.

## 여러 리듬을 하나의 루프에 맞추기

여러 파형을 겹치면 더 복잡한 움직임을 만들 수 있다. 이때 각 파형이 루프 경계에서 동시에 처음 상태로 돌아와야 한다. 먼저 루프 길이 $T$와 각 리듬의 정수 반복 횟수 $n_i$를 정하면 관리하기 쉽다.

$$
\omega_i=2\pi\frac{n_i}{T},
\qquad n_i\in\mathbb{Z}
$$

```text
theta1 = TAU * 2 * time / loopDuration
theta2 = TAU * 5 * time / loopDuration
value = 0.7 * sin(theta1) + 0.3 * sin(theta2 + phaseOffset)
```

두 파형은 각각 루프 동안 두 번과 다섯 번 반복한다. 중간의 움직임은 단순한 한 번의 진동보다 복잡하지만, 끝에서는 다시 같은 조합으로 돌아온다. 반대로 하나가 2초, 다른 하나가 3초 주기라면 전체 루프 길이는 둘의 공통 배수인 6초로 잡을 수 있다.

| 개별 주기 | 가능한 짧은 루프 길이 | 설명 |
| --- | --- | --- |
| 1초, 2초 | 2초 | 1초 주기가 두 번 반복되는 시점에 만난다. |
| 2초, 3초 | 6초 | 두 변화가 처음 위상으로 동시에 돌아온다. |
| 1.5초, 2초 | 6초 | 정수비로 환산하면 공통 반복 시간을 구할 수 있다. |
| 2초, $\sqrt{2}$초 | 없음 | 정확한 유한 루프를 만들기 어렵다. |

루프 작업에서는 각속도를 무작위로 고르기보다 "루프 안에서 몇 번 반복할 것인가"를 매개변수로 두는 편이 관리하기 쉽다. 짧은 루프에는 1, 2, 3, 5처럼 작은 정수를 조합하면 리듬이 잘 읽힌다. 서로 다른 반복 횟수가 너무 많으면 루프는 닫혀도 내부 움직임이 산만해질 수 있다.

## 노이즈를 루프시키는 원형 시간 좌표

일반 노이즈는 시간축에 넣어도 $t=0$과 $t=T$에서 같은 값을 보장하지 않는다. `time % T`를 적용하면 시간 입력이 $T$ 근처에서 $0$으로 돌아가므로 노이즈 값도 대개 불연속적으로 바뀐다. 시간축을 원형 경로로 바꾸어 노이즈에 입력하면 주기적인 시간 좌표를 만들 수 있다.

$$
\theta(t)=2\pi\frac{t}{T}
$$

4차원 노이즈를 지원한다면 시간 대신 원 위의 두 좌표를 넣는다.

$$
v=n\left(ax,ay,r\cos\theta(t),r\sin\theta(t)\right)
$$

```text
theta = TAU * frameIndex / totalFrames
value = noise4D(
    x * spatialFrequency,
    y * spatialFrequency,
    loopRadius * cos(theta),
    loopRadius * sin(theta)
)
```

$t=0$과 $t=T$에서는 코사인과 사인 좌표가 같으므로 노이즈 입력과 출력도 처음 값으로 돌아온다. `loopRadius`는 원형 경로가 노이즈 공간에서 차지하는 크기다. 값이 작으면 한 루프의 변화가 미묘하고, 크면 더 넓은 노이즈 영역을 지나 변화가 커질 수 있다.

4차원 노이즈를 쓸 수 없다면 반복 가능한 필드 여러 개를 보간하거나 타일 가능한 노이즈 텍스처를 사용할 수 있다. 시작과 끝 프레임의 이미지를 단순히 보간하면 중간에 두 질감이 겹쳐 보일 수 있다. 가능하면 입력 좌표 단계에서 반복성을 만들거나 다차원 노이즈 함수를 사용한다.

## 상태가 있는 시스템의 루프

시간 함수만으로 장면을 계산할 때는 위상과 입력을 맞추면 루프를 닫을 수 있다. 입자의 누적 위치, 잔상 버퍼, 피드백, 물리 시뮬레이션처럼 이전 프레임의 결과가 다음 프레임에 영향을 주는 시스템은 더 까다롭다. 입력이 처음과 같아도 내부 상태가 시작 상태로 돌아오지 않으면 루프는 닫히지 않는다.

상태 $\mathbf{s}$를 가진 업데이트를 다음처럼 쓸 수 있다.

$$
\mathbf{s}_{k+1}=U(\mathbf{s}_k,t_k)
$$

루프의 경계가 자연스럽기 위해서는 다음이 필요하다.

$$
\mathbf{s}(T)=\mathbf{s}(0)
$$

실무에서는 몇 가지 방법을 쓴다. 반복되는 초기 상태와 주기적인 힘을 설계하거나, 프리롤(pre-roll)로 시스템을 충분히 안정시킨 뒤 루프 구간을 기록할 수 있다. 시작 상태와 끝 상태를 보간해 전환을 숨기는 방법도 있다. 다만 이 방법은 시뮬레이션의 연속성을 바꾸므로 물리적 일관성보다 시각적 루프가 중요할 때 적합하다. 상태와 피드백은 다음 장에서 자세히 다룬다.

## 프레임 수와 내보내기

루프 길이가 $T$초이고 프레임 속도가 $r$ fps라면 저장할 프레임 수는 보통 다음과 같다.

$$
N=T r
$$

프레임 인덱스 $i=0,1,\ldots,N-1$에 대한 시간은 다음처럼 정한다.

$$
t_i=\frac{i}{N}T
$$

```text
for frameIndex from 0 to totalFrames - 1:
    time = loopDuration * frameIndex / totalFrames
    renderFrame(time)
```

이 방식에서는 첫 프레임이 $t=0$이고 마지막 저장 프레임은 $t=T-\frac{T}{N}$이다. 재생기가 마지막 프레임 뒤에 첫 프레임을 붙이면 다음 시점이 자연스럽게 $t=T$에 해당한다. $t=0$과 $t=T$는 같은 장면이므로, 두 프레임을 모두 저장하면 같은 프레임이 한 번 더 보이며 루프 끝에서 미세한 멈춤처럼 느껴질 수 있다.

프레임 속도가 고정된 영상에서는 시간 매개변수를 실제 렌더링 시간과 분리하고, 위 식처럼 프레임 인덱스에서 계산하는 편이 좋다. 기기의 처리 속도에 따라 달라지는 실시간 `deltaTime`을 내보내기 시간으로 사용하면 프레임 수와 루프 길이가 흔들릴 수 있다.

## 루프를 점검하는 방법

루프가 자연스럽게 이어지는지 확인할 때 첫 프레임과 마지막 프레임만 비교해서는 부족하다. 경계 전후의 짧은 구간을 반복 재생하거나 다음 항목을 살핀다.

- 값: 위치, 색, 크기, 마스크가 시작 상태와 같은가?
- 변화율: 시작 직후와 종료 직전의 움직임 방향 및 속도가 이어지는가?
- 노이즈: 시간 입력이 원형 경로 또는 타일 가능한 입력으로 설계되었는가?
- 상태: 누적 버퍼, 입자 위치, 난수 생성기 상태가 시작 상태로 돌아오는가?
- 프레임: $t=0$과 $t=T$를 중복 저장하지 않았는가?

작은 미리보기에서는 이음새가 잘 보이지 않을 수 있다. 움직임이 빠르거나 대비가 큰 요소, 화면 가장자리를 드나드는 요소, 잔상이 남는 요소를 주의해서 살핀다. 루프가 눈에 띄어도 길이를 늘리는 것만이 해결책은 아니다. 반복 횟수, 위상, 속도, 기준 구조를 조절하면 반복 자체를 하나의 리듬으로 읽히게 할 수 있다.

## 이 절의 핵심

루프는 시작과 끝의 값뿐 아니라 변화의 흐름도 이어져야 한다. 주기 함수에 정수 반복 횟수와 루프 길이를 지정하면 닫힌 움직임을 만들 수 있다. 일반 노이즈에는 원형 시간 좌표처럼 반복되는 입력이 필요하다. 상태가 있는 시스템은 내부 상태도 시작 상태로 돌아와야 한다. 프레임을 내보낼 때는 $t=0$과 $t=T$를 중복 저장하지 않도록 시간을 표본화한다.
