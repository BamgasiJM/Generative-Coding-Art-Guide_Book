# 14.8 시간과 사용자 입력 연결하기

시간은 자동으로 흐르고, 마우스, 터치, 키보드, 오디오, 센서는 외부 입력을 전달한다. 둘을 연결하면 관람객이 변화의 속도와 방향, 시작 조건에 개입하는 시스템을 만들 수 있다. 입력값을 화면 속성에 그대로 복사하기보다, 작품의 규칙에 맞는 값으로 해석하고 시간에 따라 어떻게 반응할지 설계하는 것이 중요하다.

예를 들어 마우스의 가로 위치는 픽셀 좌표지만, 애니메이션의 목표 속도나 파동의 위상, 노이즈의 시간 주파수, 카메라 중심, 입자 발생 위치로 해석할 수 있다. 같은 입력도 어디에 연결하느냐에 따라 화면을 조종하거나 흐름을 유도하고, 변화의 강도를 조절하는 경험을 만든다.

## 자동 시간과 외부 입력의 역할

시간 기반 애니메이션은 사용자 입력이 없어도 계속 변한다. 사용자 입력은 불규칙한 시점에 들어오고, 장치와 환경에 따라 값의 범위와 갱신 빈도도 달라진다. 두 입력의 성격에 맞춰 역할을 나누는 편이 좋다.

| 입력 | 성격 | 주된 역할 |
| --- | --- | --- |
| 시간 $t$ | 연속적이고 자동으로 증가한다. | 기본 리듬, 자율적인 변화, 재생 위치 |
| 포인터 위치 | 연속값이지만 불규칙하게 갱신된다. | 방향, 중심, 목표값, 공간적 영향 범위 |
| 키보드와 버튼 | 누름과 해제 같은 이산 사건이다. | 시작, 정지, 모드 전환, 트리거 |
| 오디오와 센서 | 잡음과 지연을 포함할 수 있는 연속 신호다. | 진폭, 밀도, 반응 강도, 분위기 |

입력이 없어도 시간 규칙이 작동하면 화면은 스스로 움직이고, 사용자의 행동은 그 흐름을 조절하거나 강조한다. 입력이 없을 때 아무 일도 일어나지 않는 작업도 가능하다. 다만 설치나 모바일 환경에서는 관람객이 잠시 멈추거나 입력 장치가 비활성화될 수 있다는 점을 고려해야 한다.

## 입력을 의미 있는 범위로 정규화하기

장치가 보내는 원시값은 화면이나 작품에서 쓰는 단위와 다를 수 있다. 마우스 $x$ 좌표는 $0$부터 화면 너비 $W$까지이고, 오디오 크기의 범위는 라이브러리마다 다르며, 센서값에는 음수나 큰 이상치가 섞일 수 있다. 먼저 이 값들을 다루기 쉬운 범위로 정규화한다.

$$
u=\operatorname{clamp}\left(\frac{x-x_{\min}}{x_{\max}-x_{\min}},0,1\right)
$$

```text
pointerAmount = clamp(pointerX / width, 0, 1)
```

정규화된 $u$는 화면 크기와 관계없이 같은 의미를 갖는다. $u=0$은 왼쪽 끝, $u=0.5$는 가운데, $u=1$은 오른쪽 끝을 나타낸다. 그런 다음 작품에 맞는 범위로 매핑한다.

$$
v=\operatorname{mix}(v_{\min},v_{\max},u)
$$

```text
targetSpeed = mix(minSpeed, maxSpeed, pointerAmount)
targetRadius = mix(minRadius, maxRadius, pointerAmount)
```

입력을 위치, 속도, 회전처럼 서로 다른 값으로 바꿀 때는 `map`이나 `mix`의 입력 범위와 출력 범위를 코드에 분명히 나타낸다. 정규화하지 않은 픽셀 좌표를 각속도에 직접 더하면 화면 해상도에 따라 작품의 리듬도 달라진다.

## 즉각 반응과 부드러운 반응

입력을 값에 바로 연결하면 반응은 즉각적이지만 마우스의 작은 떨림이나 센서 잡음도 화면에 그대로 나타난다.

```text
speed = targetSpeed
```

목표값과 현재값을 보간하면 관람객의 움직임을 부드럽게 반영할 수 있다.

```text
targetSpeed = mix(minSpeed, maxSpeed, pointerAmount)
speed = lerp(speed, targetSpeed, response)
phase += speed * deltaTime
```

`response`가 $1$에 가까우면 목표값에 즉시 도달하고, 작을수록 천천히 따라간다. 다만 매 프레임 일정한 비율로 보간하면 프레임 속도에 따라 반응 시간이 달라질 수 있다. 프레임 속도와 무관한 완화를 원한다면 시간 간격을 반영한 계수를 사용한다.

$$
\alpha=1-e^{-\lambda\Delta t}
$$

$$
v_{\text{current}}\leftarrow
\operatorname{mix}(v_{\text{current}},v_{\text{target}},\alpha)
$$

```text
responseAmount = 1 - exp(-responseRate * deltaTime)
speed = lerp(speed, targetSpeed, responseAmount)
```

$\lambda$는 반응률이다. 이 방식은 프레임 속도와 관계없이 비슷한 시간 안에 목표값에 접근한다. 완화는 불규칙한 입력 신호를 화면에서 읽기 쉬운 변화로 바꾸는 필터 역할을 한다.

## 데드존, 임계값, 곡선 매핑

미세한 입력까지 모두 반영하면 화면이 쉴 틈 없이 흔들릴 수 있다. 입력 중심 부근의 작은 변화를 무시하는 데드존(dead zone)을 두면 기본 상태를 안정시킬 수 있다.

$$
d(u)=
\begin{cases}
0 & |u|<\varepsilon\\
\operatorname{sign}(u)\frac{|u|-\varepsilon}{1-\varepsilon} & |u|\ge\varepsilon
\end{cases}
$$

```text
centered = pointerAmount * 2 - 1

if abs(centered) < deadZone:
    centered = 0
else:
    centered = sign(centered) *
               (abs(centered) - deadZone) / (1 - deadZone)
```

입력 반응의 감도를 고르게 유지할 필요도 없다. 작은 움직임을 섬세하게 읽고 큰 움직임을 강하게 만들고 싶다면 거듭제곱 곡선을 적용할 수 있다.

$$
u'=u^\gamma
$$

$\gamma>1$이면 낮은 입력의 변화는 줄고 높은 입력에서 반응이 커진다. $0<\gamma<1$이면 약한 입력도 더 잘 드러난다. 이 곡선은 오디오 크기, 압력, 거리 센서처럼 값이 특정 구간에 몰리는 입력에 유용하다.

임계값을 두면 연속 입력을 사건으로 바꿀 수 있다. 예를 들어 오디오 크기가 일정 수준을 넘을 때 입자를 만들거나, 손이 화면에 들어왔을 때 움직임의 모드를 전환할 수 있다. 임계값 부근에서 상태가 빠르게 켜졌다 꺼지는 현상은 켜짐과 꺼짐의 기준을 다르게 두는 히스테리시스(hysteresis)로 줄일 수 있다.

```text
if not active and inputValue > turnOnThreshold:
    active = true

if active and inputValue < turnOffThreshold:
    active = false
```

## 입력으로 시간 자체를 제어하기

입력은 시간 함수의 매개변수뿐 아니라 시간의 진행 방식도 제어할 수 있다. 재생, 일시 정지, 배속, 역재생, 스크러빙은 현재 시간값을 갱신하는 규칙이다.

```text
if isPlaying:
    playhead += playbackSpeed * deltaTime

if isScrubbing:
    playhead = pointerAmount * duration

value = pattern(position, playhead)
```

시간 함수만으로 장면을 계산하면 `playhead`의 어떤 값이든 바로 평가할 수 있다. 따라서 슬라이더로 시간을 앞뒤로 옮기거나 특정 구간을 반복하기 쉽다. 같은 시간에 같은 입력과 시드를 사용하면 같은 결과를 얻는다.

이전 프레임의 상태를 누적하는 시스템은 다르다. 입자의 현재 위치, 피드백 텍스처, 물리 시뮬레이션은 시간값만 바꿔서는 과거 상태를 복원할 수 없다. 되감기를 구현하려면 과거 상태를 저장하거나 원하는 시점까지 시뮬레이션을 다시 실행해야 한다. 시간 함수와 상태 기반 시스템의 차이는 상호작용을 설계할 때도 중요하다.

## 입력을 공간과 시간에 함께 연결하기

포인터 위치를 시간 기반 패턴의 중심이나 영향 범위에 연결할 수 있다. 시간은 계속 흐르고, 관람객은 그 흐름이 나타나는 위치를 조절한다.

```text
center = pointerPosition
distance = length(p - center)
wave = sin(distance * spatialFrequency - time * temporalFrequency)
influence = 1 - smoothstep(innerRadius, outerRadius, distance)
brightness = influence * wave
```

이 예에서는 포인터 주변에서만 시간 파동이 보인다. `distance`를 사용하므로 포인터는 단순한 값이 아니라 공간의 중심점으로 작동한다. 반지름, 감쇠, 시간 주파수를 분리하면 관람객이 파동의 위치, 범위, 속도를 각각 조절할 수 있다.

입력값을 노이즈나 벡터 필드의 매개변수에 연결하는 방법도 있다.

```text
fieldScale = mix(minScale, maxScale, pointerAmount)
fieldSpeed = mix(minFieldSpeed, maxFieldSpeed, audioAmount)
direction = flowField(p, time * fieldSpeed, fieldScale)
```

하나의 입력으로 모든 매개변수를 크게 바꾸면 반응은 화려해도 원인을 파악하기 어렵다. 먼저 입력 하나를 속도, 중심, 진폭, 밀도 중 한 가지에 연결하고, 그 관계가 화면에서 분명히 보이는지 확인한 뒤 확장한다.

## 기본 상태와 안전한 범위

상호작용에는 입력이 없을 때의 기본 상태가 필요하다. 포인터가 캔버스 밖에 있거나 카메라 권한이 없을 때, 오디오가 들어오지 않거나 센서값이 끊겼을 때도 화면은 의미 있게 유지되어야 한다. 기본값은 예외 처리뿐 아니라 작품이 입력 없이 어떻게 작동할지도 정한다.

```text
inputAmount = hasInput ? measuredAmount : defaultAmount
targetSpeed = mix(minSpeed, maxSpeed, inputAmount)
```

입력이 극단값이어도 속도, 크기, 변위, 반복 횟수가 안정된 범위를 벗어나지 않는지 확인한다. `clamp`는 값이 지나치게 커지는 것을 막지만, 경계에서 변화가 갑자기 멈추면 조작이 답답하게 느껴질 수 있다. 이때는 입력 곡선을 완만하게 만들거나 목표값을 제한한 뒤 완화해 경계에 부드럽게 접근시킨다.

개인 정보와 권한도 고려한다. 카메라, 마이크, 위치, 생체 센서처럼 민감한 입력은 사용자의 명시적 허가가 필요할 수 있다. 허가가 없어도 작품이 작동하도록 기본 신호를 준비하면 더 견고해진다.

## 작업 순서와 점검 방법

상호작용을 추가할 때는 시각 효과와 입력 처리를 나누어 점검한다.

1. 입력 없이도 작동하는 시간 기반 장면을 먼저 만든다.
2. 원시 입력을 $[0,1]$ 또는 중심 기준의 $[-1,1]$로 정규화한다.
3. 입력 하나를 시각 매개변수 하나에만 연결한다.
4. 필요한 경우 데드존, 곡선 매핑, 임계값을 적용한다.
5. 완화 전과 후의 반응을 비교해 적절한 지연을 정한다.
6. 입력이 없거나 최솟값, 최댓값일 때도 안전한지 확인한다.

입력이 지나치게 민감하면 정규화 범위와 매핑 곡선, 데드존부터 조절한다. 반응이 둔하면 완화율을 높이기 전에 입력값이 충분한 범위에 들어오는지 확인한다. 시간 제어가 어색하다면 재생 위치를 바꾸는지, 시간 속도를 조절하는지, 상태 시스템을 되감으려는지 구분한다. 이 차이를 분명히 하면 상호작용은 단순한 효과를 넘어 관람객이 시간 규칙에 참여하는 방식이 된다.

## 이 절의 핵심

사용자 입력은 시간 함수의 속도, 위상, 진폭, 중심, 시작 조건을 조절한다. 원시값을 정규화하고 데드존과 매핑 곡선을 적용해 의미를 부여하며, 완화로 입력에 부드럽게 반응하게 한다. 시간 함수로 계산하는 장면은 재생 위치를 자유롭게 제어할 수 있지만, 상태를 누적하는 시스템을 되감으려면 상태를 저장하거나 시뮬레이션을 다시 실행해야 한다.
