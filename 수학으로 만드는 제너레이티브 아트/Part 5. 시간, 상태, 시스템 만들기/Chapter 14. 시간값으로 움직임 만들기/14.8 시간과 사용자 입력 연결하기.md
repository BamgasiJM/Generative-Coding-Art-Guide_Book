# 14.8 시간과 사용자 입력 연결하기

시간은 자동으로 흐르는 입력이고, 마우스, 터치, 키보드, 오디오, 센서는 외부에서 들어오는 입력이다. 둘을 연결하면 관람객이 변화의 속도나 방향, 시작 조건에 개입하는 시스템을 만들 수 있다. 중요한 점은 입력을 화면 속성에 즉시 복사하는 데 있지 않다. 원시 입력을 작품의 규칙 안에서 해석 가능한 값으로 바꾸고, 시간에 따라 어떻게 반응할지 설계하는 데 있다.

예를 들어 마우스의 가로 위치는 단순한 픽셀 좌표지만, 이를 애니메이션의 목표 속도, 파동의 위상, 노이즈의 시간 주파수, 카메라의 중심, 입자 발생 위치로 해석할 수 있다. 같은 입력값이라도 어디에 연결하는지에 따라 관람객은 화면을 조종한다, 흐름을 유도한다, 혹은 변화의 강도를 조절한다는 서로 다른 경험을 하게 된다.

## 자동 시간과 외부 입력의 역할

시간 기반 애니메이션은 입력이 없어도 계속 변한다. 반면 사용자 입력은 보통 불규칙한 시점에 들어오며, 장치와 환경에 따라 값의 범위와 갱신 빈도가 다르다. 두 종류의 입력은 성격이 다르므로, 역할도 다르게 두는 편이 좋다.

| 입력 | 성격 | 주된 역할 |
| --- | --- | --- |
| 시간 $t$ | 연속적이고 자동으로 증가한다. | 기본 리듬, 자율적인 변화, 재생 위치 |
| 포인터 위치 | 연속값이지만 불규칙하게 갱신된다. | 방향, 중심, 목표값, 공간적 영향 범위 |
| 키보드와 버튼 | 누름과 해제 같은 이산 사건이다. | 시작, 정지, 모드 전환, 트리거 |
| 오디오와 센서 | 잡음과 지연을 포함할 수 있는 연속 신호다. | 진폭, 밀도, 반응 강도, 분위기 |

입력이 없을 때에도 시간 규칙이 작동하면 화면은 스스로 살아 있고, 사용자의 행동은 그 흐름을 조절하거나 강조하는 역할을 맡는다. 반대로 입력이 없으면 아무 일도 일어나지 않는 작업도 가능하지만, 설치 환경이나 모바일 환경에서는 관람객이 잠시 멈추거나 입력 장치가 비활성화된 상황을 고려해야 한다.

## 입력을 의미 있는 범위로 정규화하기

장치가 주는 원시값은 화면이나 작품의 단위와 다를 수 있다. 마우스 $x$ 좌표는 $0$에서 화면 너비 $W$까지이고, 오디오 크기는 라이브러리에 따라 다른 범위를 가지며, 센서값에는 음수나 큰 이상치가 섞일 수 있다. 먼저 이 값을 다루기 쉬운 범위로 정규화한다.

$$
u=\operatorname{clamp}\left(\frac{x-x_{\min}}{x_{\max}-x_{\min}},0,1\right)
$$

```text
pointerAmount = clamp(pointerX / width, 0, 1)
```

정규화된 $u$는 화면 크기가 달라져도 같은 의미를 가진다. 예를 들어 $u=0$은 왼쪽 끝, $u=0.5$는 가운데, $u=1$은 오른쪽 끝이다. 이후에는 작품에 맞는 범위로 매핑한다.

$$
v=\operatorname{mix}(v_{\min},v_{\max},u)
$$

```text
targetSpeed = mix(minSpeed, maxSpeed, pointerAmount)
targetRadius = mix(minRadius, maxRadius, pointerAmount)
```

입력을 위치, 속도, 회전처럼 서로 다른 차원의 값으로 바꿀 때는 `map` 또는 `mix`의 입력과 출력 범위를 코드에서 드러내는 편이 좋다. 정규화 없이 픽셀 좌표를 각속도에 직접 더하면, 화면 해상도가 바뀔 때 작품의 리듬도 달라진다.

## 즉각 반응과 부드러운 반응

입력을 값에 바로 연결하면 조작감은 즉각적이지만, 마우스의 작은 떨림이나 센서의 잡음까지 그대로 화면에 드러난다.

```text
speed = targetSpeed
```

목표값과 현재값 사이를 보간하면 관람객의 움직임을 부드러운 변화로 번역할 수 있다.

```text
targetSpeed = mix(minSpeed, maxSpeed, pointerAmount)
speed = lerp(speed, targetSpeed, response)
phase += speed * deltaTime
```

여기서 `response`가 $1$에 가까우면 즉시 목표값에 도달하고, 작을수록 천천히 따라간다. 다만 프레임마다 일정한 비율을 보간하는 방식은 프레임 속도에 따라 반응 시간이 달라질 수 있다. 프레임 독립적인 완화를 원한다면 시간 간격을 반영한 계수를 사용할 수 있다.

$$
\alpha=1-e^{-\lambda\Delta t}
$$

$$
v_{\text{current}}\leftarrow
\operatorname{mix}(v_{\text{current}},v_{\text{target}},\alpha)
$$

```text
responseAmount = 1 - exp(-responseRate * deltaTime)
speed = lerp(speed, targetSpeed, responseAmount)
```

$\lambda$는 반응률이다. 이 방식에서는 프레임이 빠르든 느리든 비슷한 시간 척도로 목표값에 접근한다. 이러한 완화는 단순한 장식이 아니라, 불규칙한 입력 신호를 화면에서 읽을 수 있는 변화로 바꾸는 필터다.

## 데드존, 임계값, 곡선 매핑

모든 미세한 입력에 반응하면 화면이 쉴 틈 없이 흔들릴 수 있다. 입력 중심 근처의 작은 변화를 무시하는 데드존(dead zone)을 두면 안정적인 기본 상태를 만들 수 있다.

$$
d(u)=
\begin{cases}
0 & |u|<\varepsilon\\
\operatorname{sign}(u)\frac{|u|-\varepsilon}{1-\varepsilon} & |u|\ge\varepsilon
\end{cases}
$$

```text
centered = pointerAmount * 2 - 1

if abs(centered) < deadZone:
    centered = 0
else:
    centered = sign(centered) *
               (abs(centered) - deadZone) / (1 - deadZone)
```

입력 반응의 감도를 고르게 유지할 필요도 없다. 작은 움직임을 섬세하게 읽고 큰 움직임을 강하게 만들고 싶다면 거듭제곱 곡선을 적용할 수 있다.

$$
u'=u^\gamma
$$

$\gamma>1$이면 낮은 입력은 더 조용해지고 높은 입력에서 반응이 빠르게 커진다. $0<\gamma<1$이면 약한 입력도 더 잘 드러난다. 오디오 크기, 압력, 거리 센서처럼 값이 특정 구간에 몰리는 입력에서 특히 유용하다.

임계값은 연속적인 입력을 사건으로 바꾼다. 예를 들어 오디오 크기가 일정 수준을 넘을 때만 새 입자를 만들거나, 손이 화면에 들어왔을 때만 움직임의 모드를 전환할 수 있다. 임계값 근처에서 상태가 빠르게 켜지고 꺼지는 것을 막으려면 켜지는 기준과 꺼지는 기준을 다르게 두는 히스테리시스(hysteresis)를 사용한다.

```text
if not active and inputValue > turnOnThreshold:
    active = true

if active and inputValue < turnOffThreshold:
    active = false
```

## 입력으로 시간 자체를 제어하기

입력은 시간 함수의 매개변수뿐 아니라 시간의 진행 방식 자체를 제어할 수 있다. 재생, 일시 정지, 배속, 역재생, 스크러빙은 모두 현재 시간값을 어떻게 갱신할지에 관한 규칙이다.

```text
if isPlaying:
    playhead += playbackSpeed * deltaTime

if isScrubbing:
    playhead = pointerAmount * duration

value = pattern(position, playhead)
```

시간 함수만으로 장면을 계산하는 경우에는 `playhead`의 어떤 값이든 즉시 평가할 수 있다. 그래서 슬라이더로 시간을 앞뒤로 옮기거나, 특정 구간을 반복하는 기능을 만들기 쉽다. 같은 시간에 같은 입력과 시드를 사용하면 언제나 같은 결과를 얻는다.

하지만 이전 프레임의 상태를 누적하는 시스템은 다르다. 입자의 현재 위치, 피드백 텍스처, 물리 시뮬레이션은 현재 시간값만 바꾼다고 과거 상태가 복원되지 않는다. 이 경우 되감기를 구현하려면 과거 상태를 저장하거나, 원하는 시점까지 처음부터 다시 시뮬레이션해야 한다. 시간 기반 함수와 상태 기반 시스템의 차이는 상호작용 설계에서도 중요하다.

## 입력을 공간과 시간에 함께 연결하기

포인터 위치는 시간 기반 패턴의 중심이나 영향 범위를 움직이는 데 쓸 수 있다. 시간은 계속 흐르지만, 관람객은 그 흐름이 발생하는 장소를 바꾸게 된다.

```text
center = pointerPosition
distance = length(p - center)
wave = sin(distance * spatialFrequency - time * temporalFrequency)
influence = 1 - smoothstep(innerRadius, outerRadius, distance)
brightness = influence * wave
```

이 예에서는 포인터 주변에서만 시간 파동이 보인다. `distance`를 사용하므로 입력은 단순한 값이 아니라 공간 안의 중심점으로 작동한다. 반지름, 감쇠, 파동의 시간 주파수를 각각 분리하면 관람객이 파동의 위치, 범위, 속도를 서로 다르게 조절하도록 설계할 수 있다.

입력값을 노이즈나 벡터 필드의 매개변수에 연결하는 방법도 있다.

```text
fieldScale = mix(minScale, maxScale, pointerAmount)
fieldSpeed = mix(minFieldSpeed, maxFieldSpeed, audioAmount)
direction = flowField(p, time * fieldSpeed, fieldScale)
```

한 입력이 모든 매개변수를 동시에 크게 바꾸면 반응은 화려하지만 원인을 읽기 어렵다. 처음에는 입력 하나를 속도, 중심, 진폭, 밀도 중 한 가지 역할에만 연결하고, 화면에서 그 관계가 명확히 보이는지 확인한 뒤 확장하는 편이 좋다.

## 기본 상태와 안전한 범위

상호작용에는 입력이 없을 때의 기본 상태가 필요하다. 포인터가 캔버스 바깥에 있거나, 카메라 권한이 없거나, 오디오가 들어오지 않거나, 센서값이 일시적으로 끊기는 상황에서도 화면이 의미 있게 유지되어야 한다. 기본값은 단순한 예외 처리가 아니라 작품의 자율성을 정한다.

```text
inputAmount = hasInput ? measuredAmount : defaultAmount
targetSpeed = mix(minSpeed, maxSpeed, inputAmount)
```

입력이 극단값일 때도 속도, 크기, 변위, 반복 횟수가 안정적인 범위를 지키는지 확인한다. `clamp`는 값의 폭주를 막는 가장 단순한 안전장치지만, 경계에서 변화가 갑자기 멈추면 답답한 조작감이 생길 수 있다. 필요하다면 입력 곡선을 완만하게 만들거나, 목표값을 제한한 뒤 완화를 적용해 경계에 부드럽게 접근하게 한다.

개인 정보와 권한도 고려해야 한다. 카메라, 마이크, 위치, 생체 센서처럼 민감한 입력은 사용자의 명시적 허가가 필요할 수 있다. 입력을 작품의 필수 조건으로 만들기보다, 허가되지 않았을 때도 다른 기본 신호로 작동하는 경로를 준비하면 더 견고한 작업이 된다.

## 작업 순서와 점검 방법

상호작용을 추가할 때는 시각 효과와 입력 처리 문제를 분리해 점검한다.

1. 입력 없이도 작동하는 시간 기반 장면을 먼저 만든다.
2. 원시 입력을 $[0,1]$ 또는 중심 기준의 $[-1,1]$로 정규화한다.
3. 입력 하나를 시각 매개변수 하나에만 연결한다.
4. 필요한 경우 데드존, 곡선 매핑, 임계값을 적용한다.
5. 완화 전과 후의 반응을 비교해 적절한 지연을 정한다.
6. 입력이 없거나 최솟값, 최댓값일 때도 안전한지 확인한다.

입력이 지나치게 민감하면 정규화 범위와 매핑 곡선, 데드존을 먼저 조절한다. 반응이 둔하면 완화율을 올리기 전에 입력이 실제로 충분한 범위로 들어오는지 확인한다. 시간 제어가 어색하면 재생 위치를 직접 바꾸는지, 시간 속도를 바꾸는지, 상태 시스템을 되감으려 하는지를 구분한다. 이 구분을 명확히 하면 상호작용은 단순한 효과가 아니라 시간 규칙을 관람객과 나누는 방식이 된다.

## 이 절의 핵심

사용자 입력은 시간 함수의 속도, 위상, 진폭, 중심, 시작 조건을 조절할 수 있다. 원시 입력을 정규화하고, 데드존과 매핑 곡선으로 의미를 부여하며, 완화로 읽기 좋은 시간적 반응을 만든다. 시간 함수만으로 계산되는 장면은 재생 위치를 자유롭게 제어할 수 있지만, 상태를 누적하는 시스템의 되감기에는 별도의 상태 저장 또는 재시뮬레이션이 필요하다.
