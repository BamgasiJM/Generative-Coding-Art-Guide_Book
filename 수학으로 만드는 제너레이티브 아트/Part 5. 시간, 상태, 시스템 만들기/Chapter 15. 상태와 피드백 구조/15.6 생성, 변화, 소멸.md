# 15.6 생성, 변화, 소멸

시간에 따라 움직이는 시스템에는 무엇이 언제 화면에 나타나고, 얼마나 머물며, 어떤 조건에서 사라질지 정하는 규칙이 필요하다. 입자나 선, 셀, 에이전트, 화면의 작은 표시 요소는 생성되어 변화하고 결국 사라진다. 생애 주기를 상태로 표현하면 화면의 요소 수와 변화 리듬을 일관된 규칙으로 설계할 수 있다.

생성과 소멸은 객체 목록의 크기뿐 아니라 화면의 인상도 결정한다. 새 요소가 나타나는 빈도는 화면의 에너지를 정하고, 변화 규칙은 시간의 흐름을 만들며, 소멸 방식은 화면에 남는 여백과 기억의 길이를 좌우한다. 요소 수가 같더라도 짧게 나타나 빠르게 사라지는 시스템은 반짝이고 긴장된 인상을 주며, 오래 누적되는 시스템은 밀도와 지층 같은 인상을 만든다.

## 생애 주기를 상태로 표현하기

가장 기본적인 요소는 생성 시각 또는 나이 `age`, 전체 수명 `lifetime`, 그리고 현재의 개별 상태를 가진다.

```text
element = {
    position,
    age: 0,
    lifetime,
    seed
}
```

업데이트마다 나이를 실제 시간 간격만큼 늘린다.

$$
a_{t+\Delta t}=a_t+\Delta t
$$

```text
element.age += deltaTime
```

나이와 수명의 비율은 생애 주기 전체에서 현재 어느 지점에 있는지 나타내는 정규화된 값이다.

$$
u=\operatorname{clamp}\left(
\frac{\text{age}}{\text{lifetime}},0,1
\right)
$$

$u=0$은 막 생성된 순간이고, $u=1$은 수명이 끝나는 순간이다. 이 값 하나를 크기, 투명도, 색, 선 굵기, 회전, 질감의 대비처럼 여러 속성에 연결할 수 있다. 시간의 절대값을 직접 쓰는 것보다 요소마다 다른 수명을 자연스럽게 처리할 수 있다는 장점이 있다.

```text
lifeAmount = clamp(element.age / element.lifetime, 0, 1)
size = mix(birthSize, deathSize, lifeAmount)
opacity = 1 - lifeAmount
color = mix(birthColor, deathColor, lifeAmount)
```

이 예에서는 요소가 시간이 갈수록 작아지고 투명해지며 색이 변한다. 속성마다 다른 곡선을 지정할 수 있다. 예를 들어 처음에는 빠르게 나타나고 중간에는 오래 유지되다가 끝에서 빠르게 사라지도록 곡선을 설계할 수 있다.

## 생애 곡선으로 변화의 성격 만들기

정규화된 생애 값 $u$를 그대로 쓰면 변화는 일정한 속도로 진행된다. 그러나 시각적 변화는 반드시 선형일 필요가 없다. 곡선을 적용하면 같은 수명 안에서도 나타남과 사라짐의 리듬을 바꿀 수 있다.

$$
\operatorname{fadeIn}(u)=\operatorname{smoothstep}(0,a,u)
$$

$$
\operatorname{fadeOut}(u)=1-\operatorname{smoothstep}(b,1,u)
$$

```text
appear = smoothstep(0, fadeInEnd, lifeAmount)
disappear = 1 - smoothstep(fadeOutStart, 1, lifeAmount)
opacity = appear * disappear
```

`fadeInEnd`와 `fadeOutStart` 사이에는 요소가 충분히 보이고, 앞뒤 구간에서는 자연스럽게 나타나고 사라진다. 점이나 선이 삭제 순간 갑자기 깜빡이는 것처럼 보이면 목록에서 지우기 전에 이런 시각적 소멸 구간을 둔다.

생애 곡선은 크기에도 적용할 수 있다. 예를 들어 태어난 직후 빠르게 커졌다가 천천히 작아지는 형태는 다음처럼 설계할 수 있다.

```text
growth = smoothstep(0, growEnd, lifeAmount)
shrink = 1 - smoothstep(shrinkStart, 1, lifeAmount)
size = maximumSize * growth * shrink
```

이 방식은 요소의 이동 규칙과 독립적이다. 같은 위치에 머무는 점, 흐르는 선, 다음 장에서 다룰 입자 모두에 공통으로 적용할 수 있다.

## 생성률은 시간당 새 요소의 양이다

생성을 매 프레임 "하나씩" 처리하면 프레임 속도가 생성량을 바꾼다. 대신 생성률 $r$을 초당 생성할 요소 수로 정의하고, 실제 시간 간격에 따라 기대 생성량을 계산한다.

$$
E[n_{\text{new}}]=r\Delta t
$$

간단한 구현에서는 소수점을 누적해 정수 개수의 생성으로 바꿀 수 있다.

```text
spawnCarry += spawnRate * deltaTime

while spawnCarry >= 1:
    spawnElement()
    spawnCarry -= 1
```

이 방식에서 `spawnRate = 20`이면 프레임 속도와 관계없이 평균적으로 1초에 20개가 생성된다. 보다 불규칙한 발생이 필요하면 기대값 $r\Delta t$를 평균으로 하는 확률적 생성 방식을 쓸 수 있다. 하지만 난수를 매 프레임 일정 확률로 비교할 때도 확률이 `deltaTime`에 맞춰 조정되는지 확인해야 한다.

```text
spawnProbability = 1 - exp(-spawnRate * deltaTime)

if random(0, 1) < spawnProbability:
    spawnElement()
```

이 식은 한 짧은 시간 구간 안에 하나 이상 생성될 가능성을 근사한다. 매우 높은 생성률에서는 한 프레임에 여러 요소가 필요할 수 있으므로, 정확한 생성량이 중요하다면 누적 방식이나 포아송 표본화를 고려한다.

## 생성 위치와 초기 조건

새 요소의 생성 위치와 초기 상태는 시스템의 전체 구조에 영향을 준다. 화면 중앙에서만 생성하면 중심을 향하거나 중심에서 퍼지는 구성이 생기기 쉽고, 경계에서 생성하면 바깥과 안쪽의 방향성이 생긴다. 밀도 필드, 마스크, 이미지 명도, 사용자 입력을 생성 위치의 확률로 활용할 수도 있다.

```text
candidate = randomPoint(bounds)

if random(0, 1) < spawnDensity(candidate):
    spawnElement(position = candidate)
```

이 규칙은 Chapter 13의 밀도 필드를 시간적인 생성 규칙으로 연결한다. 생성 위치는 확률적일 수 있지만, 같은 시드를 사용하면 결과를 다시 재현할 수 있다. 요소마다 `seed`를 저장해 두면 수명 동안의 색 변화, 회전 오프셋, 작은 크기 차이를 프레임마다 새로 뽑지 않고 일관되게 유지할 수 있다.

```text
element.seed = nextRandomSeed()
element.phase = fixedRandom(element.seed) * TAU
element.lifetime = mix(minLifetime, maxLifetime,
                       fixedRandom(element.seed + 1))
```

초깃값의 범위도 명확히 정한다. 초기 크기가 지나치게 크거나 수명이 너무 길고, 화면 밖 좌표나 유효하지 않은 색과 방향이 들어오면 생성 순간부터 문제가 생긴다. `spawnElement`를 하나의 함수로 모아 두면 초기화 규칙을 한곳에서 점검하고 수정할 수 있다.

## 소멸 조건은 시간 하나만이 아니다

수명 `lifetime`을 넘으면 제거하는 방식은 이해하기 쉽고 예측 가능하다.

```text
isAlive = element.age < element.lifetime
```

하지만 소멸은 시간 외의 조건과도 연결할 수 있다. 화면 밖으로 나갔는지, 에너지가 임계값 아래로 떨어졌는지, 마스크 영역을 벗어났는지, 다른 요소와 결합했는지, 사용자 입력으로 장면이 전환되었는지가 소멸 조건이 될 수 있다.

```text
isAlive =
    element.age < element.lifetime and
    insideBounds(element.position, margin) and
    element.energy > minimumEnergy
```

조건을 여러 개 조합한다면 우선순위를 정한다. 시각적인 페이드아웃을 끝까지 보여 주려면 즉시 삭제하지 않고 `dying` 상태로 전환한 뒤 투명도가 충분히 낮아졌을 때 제거한다.

```text
if shouldEnd(element):
    element.phase = "dying"

if element.phase == "dying":
    element.fadeAge += deltaTime

if element.fadeAge > fadeDuration:
    remove(element)
```

이렇게 하면 논리적으로는 활동을 멈춘 요소와, 화면에서 완전히 사라지기 전의 요소를 구분할 수 있다. 화면의 생명감은 종종 이런 전환 구간에서 만들어진다.

## 총량과 균형을 설계하기

생성률과 평균 수명이 정해지면, 안정된 상태에서 화면에 존재하는 요소 수를 대략 예상할 수 있다.

$$
N_{\text{average}}\approx r\,\overline{L}
$$

여기서 $r$은 초당 생성률, $\overline{L}$은 평균 수명이다. 예를 들어 매초 30개를 생성하고 평균 수명이 4초라면, 충분한 시간이 지난 뒤 화면에는 평균 120개 정도의 요소가 존재한다. 이 근사는 화면 밀도와 성능 예산을 함께 계획하는 데 유용하다.

실제 요소 수는 수명 분포, 추가 소멸 조건, 한 번에 생성하는 수, 입력에 따른 생성률 변화에 따라 달라진다. 목표 총량 `targetCount` 또는 최대 총량 `maxCount`를 두면 시스템이 무한히 커지는 것을 막을 수 있다.

```text
available = maxCount - elements.count
spawnCount = min(requestedSpawnCount, max(available, 0))
spawn(spawnCount)
```

단순히 최대 개수에 도달하면 생성을 멈추는 방법 외에도, 요소 수가 많아질수록 생성률을 줄이는 음의 피드백을 줄 수 있다.

$$
r_{\text{effective}}=r_0
\operatorname{clamp}\left(1-\frac{N}{N_{\text{target}}},0,1\right)
$$

이 규칙은 요소 수가 적을 때는 빠르게 채우고, 목표치에 가까워질수록 생성을 늦춘다. 정확히 같은 수를 유지하는 것보다 더 유기적인 밀도 변화가 필요할 때 유용하다.

## 생성과 소멸의 갱신 순서

생성과 소멸을 업데이트 루프의 어느 시점에 처리하는지에 따라 프레임 안의 동작이 달라진다. 다음처럼 단계를 명시하면 규칙을 읽기 쉽다.

```text
input = readInput()
requested = decideSpawns(state, input, deltaTime)

nextElements = []
for each element in state.elements:
    updated = updateElement(element, input, deltaTime)
    if shouldRemain(updated):
        nextElements.add(updated)

nextElements.addAll(createElements(requested))
state.elements = nextElements
```

이 순서에서는 기존 요소가 먼저 한 단계 변화하고, 새 요소는 다음 업데이트부터 움직인다. 새 요소가 생성된 순간부터 변화해야 한다면 `createElements`를 업데이트 전에 실행하거나, 생성 직후에 별도의 초기 업데이트를 한 번 적용할 수 있다. 어느 쪽이 더 자연스러운지는 표현의 의미에 달려 있으므로, 처음 상태가 화면에 보이는지와 `age = 0`의 의미를 일관되게 정한다.

목록을 순회하면서 바로 요소를 제거하기보다 다음 목록을 만드는 방식은 15.3의 읽기와 쓰기 상태 분리 원칙을 따른다. 생성과 삭제가 많아질수록 이 원칙은 객체 수의 오류와 예측하기 어려운 순회 문제를 줄여 준다.

## 생애 주기를 관찰하고 조절하기

순간의 화면만으로는 생성·변화·소멸 시스템의 총량을 판단하기 어려울 수 있다. 생성률, 현재 요소 수, 평균 나이, 제거된 수를 함께 기록하면 의도한 균형을 유지하는지 살펴보기 쉽다.

```text
debug("count", elements.count)
debug("spawn rate", effectiveSpawnRate)
debug("mean age", average(elements.age))
debug("removed this frame", removedCount)
```

요소 수가 계속 증가한다면 생성률이 소멸률보다 높거나, `isAlive` 조건이 기대대로 작동하지 않는지 확인한다. 요소가 거의 보이지 않는다면 생성 위치가 마스크 밖인지, 수명이 너무 짧은지, 페이드인과 페이드아웃 구간이 서로 겹치는지 살핀다. 반복 가능한 결과가 필요하다면 생성 시드와 생성 이벤트의 순서를 기록한다.

생성, 변화, 소멸은 시스템이 시간을 어떻게 사용하는지 눈에 보이게 하는 구조다. 수명과 총량을 명시적으로 설계하면 화면은 일정한 리듬으로 태어나고 변하고 사라지는 과정으로 읽힌다.

## 이 절의 핵심

생성률과 수명은 화면의 총량을 정하고, 생애 주기 값은 각 요소의 크기, 색, 투명도와 같은 변화를 일관되게 제어한다. 생성은 초당 비율로 정의해 프레임 속도와 분리하고, 소멸은 시간·경계·에너지 같은 조건으로 설계한다. 생성과 삭제의 순서, 최대 개수, 초기 조건과 시드를 명시하면 변화하는 시스템을 안정적으로 유지하고 재현할 수 있다.
