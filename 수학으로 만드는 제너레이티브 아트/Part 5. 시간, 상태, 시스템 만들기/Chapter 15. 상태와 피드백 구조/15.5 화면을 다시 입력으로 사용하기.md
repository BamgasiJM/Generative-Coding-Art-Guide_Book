# 15.5 화면을 다시 입력으로 사용하기

이전 절에서는 이전 결과가 다음 상태로 돌아오는 피드백 구조를 살펴보았다. 이 절에서는 그 결과를 **화면 버퍼에서 읽을 수 있는 데이터**로 구체화한다. 이전 프레임을 텍스처처럼 표본화하면 화면은 다음 프레임의 색, 밝기, 방향, 마스크, 밀도를 결정하는 입력 필드가 된다.

이 원리는 셰이더와 GPU 렌더링은 물론 CPU 기반 이미지 버퍼나 오프스크린 캔버스에도 적용된다. 저장된 이미지의 한 위치를 읽고, 그 값을 수치로 해석해 다음 계산에 다시 사용하는 것이 핵심이다.

## 화면은 색상 배열이자 공간 데이터다

버퍼 $B_t$는 위치 $\mathbf{p}$마다 색 또는 여러 채널의 값을 저장한다.

$$
B_t(\mathbf{p})=
\begin{pmatrix}
R(\mathbf{p})\\
G(\mathbf{p})\\
B(\mathbf{p})\\
A(\mathbf{p})
\end{pmatrix}
$$

가장 흔한 해석은 이 값을 그대로 색으로 쓰는 것이다. 그러나 채널은 색 이외의 데이터를 담을 수도 있다. 예를 들어 빨강 채널에는 물질의 농도, 초록 채널에는 속도의 $x$ 성분, 파랑 채널에는 속도의 $y$ 성분, 알파 채널에는 마스크나 수명을 저장할 수 있다. 이렇게 보면 화면 버퍼는 작은 숫자들을 담은 2차원 배열이며, 렌더링은 그 배열을 사람이 볼 수 있는 색으로 해석하는 과정이 된다.

| 버퍼에 저장하는 값 | 다시 읽어 사용할 수 있는 규칙 |
| --- | --- |
| 색상 | 이전 색을 보존하거나 다음 색의 재료로 사용한다. |
| 밝기 | 밀도, 마스크, 입자 발생 확률을 정한다. |
| 알파 | 투명도, 유효 영역, 충돌 가능 영역을 정한다. |
| 거리 또는 높이 | 윤곽선, 경사, 다음 변위의 세기를 정한다. |
| 벡터 성분 | 입자가 따를 방향장이나 좌표 변위를 정한다. |

버퍼에 무엇이 들어 있는지 이름에 드러내는 편이 좋다. `previousFrame`은 색상 이미지처럼 들리지만 실제로 밀도 값을 저장한다면 `densityBuffer`가 더 정확하다. 데이터의 의미가 모호하면 색상 보정이나 블렌딩이 수치 연산을 의도치 않게 바꾸는 문제를 알아차리기 어렵다.

## 픽셀 좌표와 UV 좌표

버퍼를 읽을 때는 두 종류의 좌표를 자주 만난다. 픽셀 좌표 $(x,y)$는 실제 이미지의 인덱스이고, UV 좌표 $\mathbf{u}=(u,v)$는 보통 $[0,1]$ 범위로 정규화된 위치다.

$$
u=\frac{x}{W},
\qquad
v=\frac{y}{H}
$$

여기서 $W$, $H$는 버퍼의 너비와 높이다. UV 좌표를 사용하면 버퍼 해상도가 바뀌어도 $u=0.5$, $v=0.5$가 항상 중앙을 뜻한다. 반면 한 픽셀만 옆을 읽고 싶을 때는 픽셀 크기에 해당하는 UV 간격을 알아야 한다.

$$
\Delta\mathbf{u}=
\left(\frac{1}{W},\frac{1}{H}\right)
$$

```text
texelSize = (1 / bufferWidth, 1 / bufferHeight)
center = sample(previous, uv)
right = sample(previous, uv + (texelSize.x, 0))
up = sample(previous, uv + (0, texelSize.y))
```

해상도와 종횡비를 고려하지 않으면 원형 마스크가 타원으로 보이거나 가로와 세로 방향의 확산 세기가 달라질 수 있다. `texelSize`는 화면 크기가 아니라 실제 버퍼의 크기를 기준으로 계산한다. 낮은 해상도의 오프스크린 버퍼를 확대해 표시하면 화면 해상도와 버퍼 해상도가 서로 다를 수 있다.

환경마다 UV 좌표의 $v=0$이 위쪽인지 아래쪽인지 다를 수 있다. 이전 화면을 읽었더니 위아래가 뒤집혀 보인다면 좌표 원점의 관례를 먼저 확인한다.

```text
sampleUV = (uv.x, 1 - uv.y)
history = sample(previous, sampleUV)
```

필요한 환경에서만 좌표를 반전한다. 비대칭 이미지나 숫자 마커를 버퍼에 그려 좌표 방향을 먼저 확인하면 안전하다.

## 한 지점 읽기와 이웃 읽기

가장 단순한 표본화는 현재 위치의 이전 값을 읽는 것이다.

$$
\mathbf{h}(\mathbf{u})=B_t(\mathbf{u})
$$

```glsl
vec4 history = texture(previous, uv);
```

이 값은 다음 프레임의 색에 섞거나, 밝기를 읽어 새로운 마크의 크기와 투명도를 정하는 데 사용할 수 있다.

```text
history = sample(previous, uv)
brightness = luminance(history.rgb)
markSize = mix(smallSize, largeSize, brightness)
```

이웃 위치를 함께 읽으면 화면 안의 변화량을 계산할 수 있다. 예를 들어 오른쪽과 위쪽의 밝기 차이는 밝기가 어느 방향으로 커지는지 근사하는 재료가 된다.

$$
\nabla L(\mathbf{u})\approx
\left(
\frac{L(\mathbf{u}+\Delta u_x)-L(\mathbf{u}-\Delta u_x)}{2\Delta u_x},
\frac{L(\mathbf{u}+\Delta u_y)-L(\mathbf{u}-\Delta u_y)}{2\Delta u_y}
\right)
$$

```text
left = luminance(sample(previous, uv - (texelSize.x, 0)))
right = luminance(sample(previous, uv + (texelSize.x, 0)))
down = luminance(sample(previous, uv - (0, texelSize.y)))
up = luminance(sample(previous, uv + (0, texelSize.y)))

gradient = ((right - left), (up - down))
```

이 그래디언트는 밝기가 가장 빠르게 증가하는 방향을 가리킨다. 그 반대 방향으로 입자를 이동시키면 밝은 영역으로 끌려가거나, $90^\circ$ 회전한 방향을 사용하면 밝기 윤곽을 따라 흐르게 만들 수 있다. 이때 화면은 단순한 이미지가 아니라, 다음 행동의 방향을 가진 필드가 된다.

## 샘플링 방식은 데이터 변환이다

버퍼의 좌표가 픽셀 중심 사이를 가리킬 때 어떤 값을 반환할지는 샘플링 방식이 결정한다. 최근접 샘플링은 가장 가까운 텍셀 하나를 그대로 읽고, 선형 필터링은 주변 텍셀을 보간한다.

| 방식 | 값의 해석 | 어울리는 결과 |
| --- | --- | --- |
| 최근접 샘플링 | 가장 가까운 셀의 값을 고른다. | 셀룰러 오토마타, 픽셀 질감, 이산 상태 |
| 선형 샘플링 | 주변 값의 가중 평균을 읽는다. | 부드러운 흐름, 연속적인 변위, 잔상 |
| 별도 블러 패스 | 넓은 이웃을 명시적으로 평균 낸다. | 확산, 안개, 큰 반경의 부드러움 |

선형 필터링은 이전 이미지를 부드럽게 확대하거나 미세하게 이동할 때 자연스럽다. 그러나 값의 정확한 보존이 필요한 데이터 버퍼에는 부적절할 수 있다. 예를 들어 ID, 범주, 이산적인 셀 상태를 선형 보간하면 존재하지 않았던 중간값이 생긴다. 데이터를 저장하는 버퍼와 미관을 위해 부드럽게 표시하는 버퍼를 구분하는 이유가 여기에 있다.

선형 필터링은 화면을 부드럽게 보이게 하지만, 색을 물리량으로 읽어 계산할 때는 보간과 색상 공간이 결과에 직접 영향을 준다. 특히 데이터 버퍼에서는 자동 색 보정, 프리멀티플라이드 알파, 색상 프로파일이 수치의 의미를 바꾸지 않는지 확인해야 한다.

## 경계 처리도 규칙의 일부다

버퍼 가장자리 근처에서 이웃을 읽거나 좌표를 변형하면 UV가 $[0,1]$ 범위 밖으로 나갈 수 있다. 이때의 처리는 단순한 오류 방지가 아니라 시스템의 경계를 정의한다.

```text
repeatUV = fract(uv)
clampedUV = clamp(uv, 0, 1)
mirroredUV = mirrorRepeat(uv)
```

- 반복 래핑은 한쪽으로 나간 구조가 반대쪽으로 들어오게 하므로, 닫힌 세계나 타일 패턴을 만든다.
- 가장자리 고정은 경계의 값을 계속 늘려 쓰므로, 벽이나 고정된 외곽처럼 작동할 수 있다.
- 배경색 또는 0으로 처리하면 정보가 가장자리에서 사라져 열린 공간과 소멸을 만든다.
- 거울 반복은 경계에서 방향이 반사되는 대칭적인 흐름을 만든다.

15.4에서 다룬 피드백의 장기적인 형태는 이 경계 규칙에 크게 영향을 받는다. 이 절에서는 먼저 경계 처리를 고정한 뒤, 버퍼를 데이터 필드로 읽는 규칙을 추가하는 편이 문제를 분리하기 쉽다.

## 화면 값을 새 규칙으로 번역하기

저장된 값을 다른 의미로 해석하면 화면의 정보로 더 다양한 시스템을 만들 수 있다.

### 밝기에서 밀도로

이전 프레임의 밝은 영역에서 더 많은 점을 만들도록 할 수 있다.

```text
brightness = luminance(sample(previous, uv).rgb)
spawnProbability = pow(brightness, densityContrast)

if fixedRandom(cellId, frameGroup) < spawnProbability:
    spawnAt(cellPosition)
```

밝기를 곧바로 확률로 쓰기보다 거듭제곱이나 임계값으로 대비를 조절하면 약한 흔적까지 모두 같은 비중으로 증식하는 현상을 막을 수 있다. 이 규칙을 쓰면 화면의 시각적 밀도가 다음 프레임의 객체 분포를 바꾼다.

### 색에서 마스크와 재질로

특정 색상 또는 알파 범위를 마스크로 읽어 다음 패턴의 유효 영역을 정할 수 있다.

```text
history = sample(previous, uv)
mask = smoothstep(maskLow, maskHigh, history.a)
color = mix(backgroundColor, activeColor, mask)
```

예를 들어 이전 버퍼의 알파가 높은 영역에만 새 노이즈 질감을 더하거나, 이전 색의 색조를 다음 도형의 팔레트 선택에 사용할 수 있다. 채널별 의미가 다르면 색상처럼 보이는 버퍼도 사실은 여러 개의 독립적인 제어 필드를 담을 수 있다.

### 화면의 변화량에서 움직임으로

그래디언트나 이웃 차이를 사용하면 밝은 윤곽, 경계, 밀도 변화가 다음 움직임의 방향을 만들 수 있다.

```text
gradient = brightnessGradient(previous, uv, texelSize)

if length(gradient) > epsilon:
    direction = rotate90(normalize(gradient))
    particle.position += direction * speed * deltaTime
```

이 방식에서는 렌더링된 흔적이 이후 입자의 유로를 바꾼다. 단, 입자와 버퍼의 해상도 및 좌표계를 맞춰야 한다. 입자 위치를 UV로 변환할 때 종횡비를 무시하면 방향이 왜곡되고, 버퍼가 낮은 해상도라면 아주 좁은 경계의 방향 정보는 사라질 수 있다.

## 렌더링용 화면과 계산용 버퍼를 구분하기

작업 초반에는 화면에 보이는 버퍼 하나를 곧바로 다음 입력으로 써도 충분하다. 하지만 시스템이 커지면 표시용 이미지와 계산용 데이터를 분리하는 편이 좋다. 표시용 화면에는 색 보정, 블렌딩, 텍스처, 글자 같은 시각적 요소가 섞일 수 있지만, 계산용 버퍼에는 규칙에 필요한 값만 안정적으로 저장한다.

```text
simulationBuffer = updateField(simulationBuffer, input, deltaTime)
displayImage = renderField(simulationBuffer, palette, overlays)
present(displayImage)
```

예를 들어 반응-확산 시스템은 두 물질의 농도를 계산용 버퍼에 저장하고, 최종 화면에서는 두 값의 차이를 팔레트로 바꿔 표시할 수 있다. 이때 팔레트를 바꿔도 물질의 움직임 규칙은 바뀌지 않는다. 반대로 최종 화면을 다시 계산에 읽으면, UI나 후처리 효과가 의도치 않게 시스템 규칙에 섞일 수 있다.

이 분리는 디버깅에도 유리하다. 계산용 버퍼의 각 채널을 회색조 또는 가짜 색으로 따로 표시하면, 문제가 규칙 계산에 있는지 시각화에 있는지 쉽게 구분할 수 있다.

## 해상도와 성능의 선택

화면 전체를 매 프레임 읽고 쓰는 작업은 버퍼 해상도에 비례해 비용이 커진다. 계산용 버퍼를 화면보다 낮은 해상도로 두면 계산 비용을 줄이는 동시에 더 큰 픽셀 단위의 확산과 부드러운 질감을 얻을 수 있다. 얇은 윤곽, 작은 입자의 충돌, 선명한 마스크가 중요하면 충분한 해상도가 필요하다.

```text
simulationWidth = round(screenWidth * simulationScale)
simulationHeight = round(screenHeight * simulationScale)
```

해상도를 바꾸면 `texelSize`, 블러 반경, 변위량, 마스크의 경계 폭도 다시 조절해야 한다. 픽셀 단위로 지정한 값은 해상도에 따라 시각적 크기가 달라지기 때문이다. 성능을 이유로 해상도를 낮출 때는 이 값들을 화면 비율 또는 정규화 좌표 기준으로 다시 해석하는 것이 좋다.

## 점검 방법

화면 버퍼를 데이터로 사용할 때는 먼저 버퍼가 실제로 무엇을 저장하는지, 그 값을 어느 좌표에서 어떻게 읽는지를 확인한다.

1. 저장된 채널을 각각 회색조 또는 가짜 색으로 표시한다.
2. UV 원점과 $v$축 방향을 비대칭 마커로 점검한다.
3. 최근접 샘플링과 선형 샘플링의 차이를 단순한 격자에서 비교한다.
4. 경계 처리 하나를 고정한 상태에서 이웃 읽기나 변위를 추가한다.
5. 표시용 화면과 계산용 버퍼가 섞이지 않았는지 확인한다.

이 과정에서 값이 예상과 다르면 가장 먼저 좌표계, 텍셀 크기, 알파 처리, 색상 공간을 살핀다. 화면은 익숙한 이미지처럼 보이지만, 다시 입력으로 쓰는 순간 수치적 의미를 가진 데이터다. 버퍼의 각 값이 무엇을 뜻하는지 명확하게 유지할수록, 피드백과 시뮬레이션은 더 안정적으로 확장할 수 있다.

## 이 절의 핵심

이전 화면을 텍스처로 읽으면 화면은 다음 프레임의 색뿐 아니라 밀도, 마스크, 방향, 재질을 결정하는 공간 데이터가 된다. 픽셀 좌표와 UV 좌표, 텍셀 크기, 샘플링 방식, 경계 처리는 모두 시스템 규칙의 일부다. 계산용 버퍼와 표시용 화면을 분리하고 각 채널의 의미를 명확히 하면, 화면을 다시 입력으로 쓰는 피드백을 더 정확하고 풍부하게 설계할 수 있다.
