# 16.1 입자의 구성 요소

입자는 화면에 그려지는 작은 점에 한정되지 않는다. 시뮬레이션에서 각자 상태를 유지하고 대체로 같은 갱신 규칙을 적용받는 개별 요소를 입자라고 한다. 입자 하나는 매 업데이트에서 바뀔 수 있는 상태를 담는 데이터 단위다. 화면에서는 점·선·원·복잡한 도형 중 무엇으로든 표현할 수 있다.

```text
particle = {
    id,
    position,
    velocity,
    age,
    lifetime,
    radius,
    color
}
```

각 항목은 서로 다른 역할을 맡는다. 어떤 필드를 둘지는 입자가 시뮬레이션에서 맡는 역할과 화면에 표현하는 방식에 따라 달라진다.

| 종류 | 예시 | 쓰임 |
| --- | --- | --- |
| 운동 상태 | `position`, `velocity` | 입자가 어디에 있고 어떻게 움직이는지 표현 |
| 생애 상태 | `age`, `lifetime` | 생성 후 얼마나 지났고 언제 사라질지 표현 |
| 표시 속성 | `radius`, `color`, `opacity` | 상태를 화면의 크기와 색으로 번역 |
| 식별과 이력 | `id`, `previousPosition` | 개체별 값을 고정하거나 이동 흔적을 그릴 때 사용 |

모든 입자에 이 필드를 빠짐없이 넣을 필요는 없다. 점만 그리는 간단한 시스템에는 위치와 색만 필요할 수 있고, 이동 흔적을 그리려면 직전 위치를 추가할 수 있다. 가속도는 매 업데이트에서 힘으로 계산한 뒤 초기화하는 임시값인 경우가 많으므로, 입자의 지속 상태로 저장하지 않아도 된다. 계속 기억할 값과 현재 상태에서 계산할 값을 구분하면 자료 구조를 간결하게 유지할 수 있다.

## 입자별 상태와 시스템의 규칙

입자 시스템에는 개별 입자의 상태와 여러 입자가 공유하는 설정이 함께 있다. 예를 들어 중력이 모든 입자에 동일하게 작용한다면 중력은 각 입자 안에 복사하기보다 시스템의 공통 설정으로 둘 수 있다. 입자마다 다른 질량이나 색이 필요할 때만 그 차이를 개별 상태로 둔다.

```text
particle = {
    id,
    position,
    velocity,
    age: 0,
    lifetime,
    radius,
    color
}

system = {
    particles,
    gravity,
    emissionRate
}
```

이 구분은 여러 입자를 한꺼번에 조절할 때 유용하다. 시스템의 `gravity`를 바꾸면 모든 입자의 운동 규칙이 달라지고, 특정 입자의 `velocity`를 바꾸면 그 입자만 다른 궤적을 따른다. `id`는 입자마다 고유하게 유지한다. 배열에서의 순번은 입자를 제거하거나 정렬하면 바뀔 수 있지만, 고유한 `id`는 입자의 정체성을 계속 가리킨다. 시드와 함께 해시의 입력으로 사용하면 목록의 순서가 달라져도 입자에 연결한 색이나 초기 방향을 안정적으로 재현할 수 있다.

```text
particle.id = system.nextId
particle.seed = hash(system.seed, particle.id)
particle.phase = random01(particle.seed) * TAU
```

이처럼 입자를 만들 때 정한 난수값을 저장해 두면 같은 입자의 속성이 프레임마다 흔들리지 않는다. 같은 시드와 같은 생성 순서를 다시 사용하면 장면도 재현하기 쉽다. 반면 매 프레임 달라져야 하는 흔들림이나 변동은 시간에 따라 변하는 입력으로 별도로 계산한다.

## 저장할 값과 계산할 값

상태는 시간에 따라 바뀌거나 다음 프레임에도 기억해야 하는 값이다. 위치와 속도, 나이는 보통 계속 갱신되므로 상태에 속한다. 반면 나이를 수명으로 나눈 생애 진행도는 필요할 때 계산할 수 있다.

```text
life01 = clamp(age / lifetime, 0, 1)
opacity = 1 - life01
```

`life01`은 입자의 생애를 0에서 1 사이로 정규화한 값이다. 이를 이용하면 수명이 다른 입자도 생성 직후와 소멸 직전이라는 같은 기준으로 다룰 수 있다. `lifetime`은 0보다 큰 값이어야 나눗셈이 정의된다. 이런 파생값을 매번 계산하면 저장 상태와 렌더링 결과의 관계가 분명해지고, 나중에 표현 규칙을 바꾸기도 쉽다.

입자 필드에는 유효한 값의 범위도 정해 두는 편이 좋다. 수명은 양수여야 하고, 반지름은 음수가 될 수 없으며, 투명도를 사용한다면 보통 0과 1 사이로 제한한다. 위치나 속도에 무한대나 숫자가 아닌 값이 섞이면 이후 계산과 렌더링까지 영향을 받는다. 입자를 생성하거나 갱신하는 경계에서 이런 조건을 확인하면 오류가 어느 단계에서 시작됐는지 찾기 쉽다.

```text
assert(particle.lifetime > 0)
assert(particle.radius >= 0)
assert(isFinite(particle.position.x))
assert(isFinite(particle.position.y))
```

## 운동과 표시의 분리

위치와 속도는 입자의 시뮬레이션 상태이고, 반지름·색·투명도는 그 상태를 어떻게 보일지 정하는 표시 속성이다. 표시 속성을 운동 데이터와 분리해 두면 같은 궤적을 여러 방식으로 그릴 수 있다.

```text
drawPoint(particle.position)
drawCircle(particle.position, particle.radius, particle.color)
drawLine(particle.previousPosition, particle.position)
```

첫 번째 표현은 입자의 현재 위치만 보여준다. 두 번째는 크기와 색까지 드러내고, 세 번째는 직전 위치가 있을 때 이동 경로를 선분으로 보여준다. 입자 데이터는 그대로 두고 그리기 규칙만 바꿀 수 있으므로, 시뮬레이션의 동작과 작품의 시각적 스타일을 별도로 실험할 수 있다.

난수로 정한 개별 속성은 입자가 만들어질 때 저장하거나 `id`에 고정하는 것이 보통이다. 그 값을 그릴 때마다 새로 뽑으면 같은 입자가 프레임마다 다른 색이나 크기로 깜빡일 수 있다. 반대로 나이에 따라 크기를 바꾸고 싶다면 크기를 매 프레임 임의로 다시 정하는 대신, `life01` 같은 생애 진행도로 계산한다.

화면에 그리는 크기와 주변 입자에 영향을 주는 범위도 서로 다른 값일 수 있다. 예를 들어 작은 점을 크게 그려 강조하거나, 눈에 보이는 크기는 작아도 넓은 영역에 영향을 주도록 만들 수 있다. 두 역할이 모두 필요하다면 `visualRadius`와 `interactionRadius`처럼 필드를 나누면 표현과 동작을 독립적으로 조정할 수 있다.

```text
particle = {
    position,
    visualRadius,
    interactionRadius
}
```

## 한 입자의 생애

입자의 처리는 개념적으로 생성, 갱신, 그리기의 순환으로 볼 수 있다. 생성할 때는 위치와 초기 속도, 나이, 수명, 표시 속성을 정한다. 갱신에서는 운동 상태와 나이를 바꾸고, 그리기에서는 현재 상태를 화면 요소로 번역한다. 수명이 끝난 입자를 제거하거나 재사용하는 구체적인 방법은 16.7절에서 다룬다.

이 순서를 분리하면 문제를 찾기도 쉽다. 입자가 원하는 위치로 움직이지 않으면 갱신 규칙을, 움직임은 맞지만 이미지가 어색하면 그리기 규칙을 살펴본다. 먼저 입자 하나의 필드와 역할을 정리한 다음, 같은 구조를 여러 입자에 적용하면 시스템 전체를 단계적으로 확장할 수 있다. 다음 절에서는 위치·속도·가속도의 갱신 관계를 자세히 다룬다.

## 이 절의 핵심

입자는 상태와 규칙을 공유하는 개별 시뮬레이션 요소다. 입자별 상태, 시스템 공통 설정, 임시값, 계산 가능한 파생값을 구분하고, 고유한 식별자와 유효 범위를 관리하면 구조가 분명해진다. 운동 상태와 표시 방식을 나누면 같은 입자 데이터를 여러 시각적 표현에 재사용할 수 있다.
