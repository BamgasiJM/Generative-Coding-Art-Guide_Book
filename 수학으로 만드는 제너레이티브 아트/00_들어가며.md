# 들어가며

제너레이티브 아트에서 중요한 것은 화면에 무엇을 그릴지 하나씩 정하는 일이 아니다. 더 중요한 것은 어떤 규칙이 이미지를 만들어 내는지 정하는 일이다. 선 하나를 어디에서 시작해 어디에서 끝낼지 직접 지정할 수도 있지만, 시작점과 끝점을 계산하는 규칙을 만들 수도 있다. 원 하나를 특정 위치에 그릴 수도 있지만, 화면의 모든 점이 어떤 중심점에서 얼마나 떨어져 있는지 계산한 뒤 그 결과로 원의 경계를 만들 수도 있다.

이 책은 두 번째 관점을 다룬다. 이미지를 완성된 물체의 집합으로 보기보다, 좌표와 함수와 값이 만들어 내는 결과로 본다. 화면 위의 한 점에는 좌표가 있고, 좌표는 함수의 입력이 된다. 함수는 거리, 각도, 밝기, 색, 방향, 속도 같은 값을 만든다. 그 값들이 다시 도형이 되고, 패턴이 되고, 움직임이 되고, 하나의 시스템이 된다.

이 관점에 익숙해지면 그래픽 환경이 달라져도 같은 생각을 옮겨 갈 수 있다. p5.js에서 만든 원형 패턴을 GLSL 프래그먼트 셰이더로 다시 만들 수 있고, Processing에서 만든 반복 구조를 openFrameworks나 nannou로 옮길 수 있다. 더 나아가 화면 위의 2D 패턴을 Blender의 프로시저럴 재질이나 OSL 셰이더로 확장할 수도 있다. 코드의 문법은 달라지지만, 그 아래에서 작동하는 수학적 구조는 자주 반복된다.

이 책의 목표는 수학을 따로 공부한 뒤 그래픽에 적용하는 것이 아니다. 반대로, 이미지를 만들면서 필요한 수학을 만나는 것이다. 좌표를 움직이다 보면 벡터를 만나고, 원을 만들다 보면 거리를 만나고, 부드러운 경계를 만들다 보면 보간을 만나고, 반복 패턴을 만들다 보면 나머지 연산과 정규화된 좌표를 만나게 된다. 수학은 여기서 추상적인 공식의 목록이 아니라, 이미지를 조직하는 도구다.

## 그림을 직접 그리기보다 규칙을 설계한다

일반적인 드로잉에서는 결과가 먼저 떠오른다. 여기에 선을 긋고, 저기에 원을 놓고, 배경색을 정한다. 물론 제너레이티브 아트에서도 시각적 목표는 중요하다. 하지만 작업의 중심은 개별 요소를 배치하는 것에서, 요소를 만들어 내는 관계를 설계하는 쪽으로 이동한다.

예를 들어 화면에 원을 여러 개 배치한다고 해 보자. 가장 단순한 방법은 원의 위치와 크기를 하나씩 정하는 것이다. 이 방식은 즉각적이고 직관적이다. 그러나 원의 개수가 늘어나거나, 각 원이 서로 영향을 주거나, 시간이 지나며 움직여야 한다면 다른 방식이 필요해진다. 원의 위치를 격자 셀의 인덱스로부터 계산하고, 크기를 중심점과의 거리로 정하고, 색을 노이즈 값으로 바꾸고, 시간값을 더해 움직임을 만들 수 있다. 이때 이미지는 고정된 배치가 아니라 계산 가능한 구조가 된다.

제너레이티브 아트에서 규칙은 단순한 자동화가 아니다. 규칙은 작가가 이미지와 맺는 방식이다. 모든 것을 직접 통제하지 않고, 어떤 범위 안에서 변화가 일어나도록 조건을 만든다. 무작위 값을 쓰더라도 완전히 우연에 맡기는 것이 아니라, 시드, 범위, 분포, 제한 조건을 통해 결과의 성격을 조절한다. 반복 구조를 만들더라도 단순히 복사하는 것이 아니라, 각 반복이 조금씩 달라지는 방식을 설계한다.

이 책에서 사용하는 기본 질문은 다음과 같다.

- 이 이미지는 어떤 입력값에서 시작하는가?
- 그 입력값은 어떤 함수나 규칙을 통과하는가?
- 함수의 결과는 색, 위치, 크기, 회전, 밀도, 속도 중 무엇으로 바뀌는가?
- 변화가 있다면 어떤 파라미터로 조절되는가?
- 같은 규칙을 다른 그래픽 환경에서는 어떻게 표현할 수 있는가?

이 질문들은 책 전체에서 반복된다. 좌표를 다룰 때도, 거리장을 다룰 때도, 노이즈와 입자 시스템을 다룰 때도 같은 틀을 사용한다. 처음에는 단순한 값 하나를 색으로 바꾸는 일에서 시작하지만, 마지막에는 여러 규칙이 서로 연결된 하나의 작품 구조를 설계하는 데까지 나아간다.

## 이 책이 다루는 그래픽 환경

제너레이티브 아트는 특정 프로그램이나 특정 언어에만 속한 분야가 아니다. 브라우저에서 실행되는 p5.js로도 만들 수 있고, C++ 기반의 openFrameworks로도 만들 수 있으며, GPU 셰이더로도 만들 수 있다. 같은 수학적 아이디어가 2D 캔버스, 3D 공간, 표면 재질, 실시간 시뮬레이션 안에서 서로 다른 모습으로 나타난다.

이 책은 여러 환경을 모두 깊게 다루는 레퍼런스 책이 아니다. 대신 각 환경이 이미지를 계산하는 방식의 차이를 비교한다. 어떤 환경은 도형을 명령으로 그린다. 어떤 환경은 픽셀마다 함수를 평가한다. 어떤 환경은 프레임마다 상태를 업데이트하고, 어떤 환경은 표면 위의 한 점에서 재질 값을 계산한다. 이 차이를 이해하면 라이브러리나 언어가 달라져도 핵심 아이디어를 잃지 않을 수 있다.

이 책에서 주로 등장하는 환경은 다음과 같다.

| 구분 | 환경 | 이 책에서 보는 관점 |
| --- | --- | --- |
| 크리에이티브 코딩 | p5.js, Processing | 좌표, 도형, 반복, 애니메이션을 빠르게 실험하는 환경 |
| 게임 루프 기반 드로잉 | raylib | 명시적인 루프와 입력 처리를 바탕으로 실시간 그래픽을 구성하는 환경 |
| 함수형 크리에이티브 코딩 | Quil | 상태와 드로잉을 함수 중심으로 조직하는 환경 |
| C++ 크리에이티브 코딩 | openFrameworks | 입력, 미디어, 시뮬레이션, 셰이더를 결합하는 환경 |
| 현대적 크리에이티브 코딩 | nannou, OPENRNDR | Rust와 Kotlin 기반으로 그래픽 구조를 설계하는 환경 |
| 실시간 셰이딩 | GLSL, HLSL | GPU에서 픽셀, 정점, 텍스처, 필드를 계산하는 환경 |
| 프로시저럴 재질 | OSL | 화면이 아니라 표면 위의 재질과 변위를 계산하는 환경 |

이 표는 환경의 우열을 나누기 위한 것이 아니다. 각 환경은 서로 다른 작업 방식과 강점을 가진다. p5.js는 빠른 실험과 교육에 적합하고, openFrameworks는 설치 작업이나 미디어 연동에 강하다. GLSL은 픽셀 단위 패턴과 실시간 효과에 적합하며, OSL은 3D 표면의 재질을 수학적으로 만들 때 유용하다. 중요한 것은 환경을 선택하기 전에 자신이 만들고 싶은 규칙이 어떤 방식의 계산을 요구하는지 아는 것이다.

## 수학적 모델과 구현 환경의 관계

이 책에서 말하는 수학적 모델은 거창한 이론이 아니다. 어떤 이미지를 만들기 위해 필요한 관계를 간단한 수식이나 알고리즘으로 정리한 것이다. 중심점에서 멀어질수록 색이 어두워진다면, 그 이미지는 거리값을 사용하는 모델을 갖는다. 좌표를 일정한 간격으로 반복해 무늬를 만든다면, 그 이미지는 타일링 모델을 갖는다. 입자가 보이지 않는 방향장을 따라 움직인다면, 그 이미지는 벡터 필드와 시간 업데이트를 사용하는 모델을 갖는다.

구현 환경은 이 모델을 실제 코드로 옮기는 장소다. 같은 모델이라도 환경에 따라 표현 방식이 달라진다. 드로잉 API에서는 반복문으로 여러 도형을 그릴 수 있다. 셰이더에서는 화면의 각 픽셀이 자신의 좌표를 입력으로 받아 색을 계산한다. 프로시저럴 재질에서는 표면 위의 점이 자신의 위치, 노멀, UV 좌표를 바탕으로 색과 거칠기, 변위를 계산한다.

예를 들어 원을 만든다고 해 보자. 드로잉 API에서는 `circle()`이나 `ellipse()` 같은 함수를 호출해 원을 그리는 경우가 많다. 셰이더에서는 픽셀 좌표와 중심점 사이의 거리를 계산하고, 그 거리가 반지름보다 작은지 판단해 색을 정한다. OSL에서는 표면 위의 좌표를 기준으로 거리 패턴을 계산해 재질의 색이나 범프 값에 연결할 수 있다. 결과는 모두 원처럼 보일 수 있지만, 원을 만드는 방식은 다르다.

이 차이를 이해하는 일은 중요하다. 어떤 환경에서는 도형이 기본 단위이고, 어떤 환경에서는 픽셀이 기본 단위이며, 어떤 환경에서는 표면 위의 샘플 지점이 기본 단위다. 하지만 더 아래로 내려가면 공통된 질문이 남는다. 좌표는 무엇인가? 거리는 어떻게 계산하는가? 값은 어떤 범위에 있는가? 그 값을 색이나 형태로 어떻게 바꾸는가?

이 책은 바로 그 공통 질문을 중심에 둔다. 특정 라이브러리의 함수 이름을 외우는 것보다, 같은 계산이 여러 환경에서 어떻게 번역되는지 이해하는 것이 더 오래 남는다.

## 이 책의 기본 흐름

이 책은 단순한 개념에서 복잡한 시스템으로 이동한다. 처음에는 좌표와 숫자 값을 다룬다. 그다음 함수를 이용해 형태를 만들고, 좌표를 변형해 패턴을 만든다. 이후 랜덤, 노이즈, 필드, 시간, 상태, 피드백을 더해 이미지가 스스로 변화하는 시스템으로 확장한다. 마지막에는 같은 수학적 아이디어를 여러 그래픽 환경으로 옮기는 방법을 살펴보고, 프로젝트를 통해 전체 흐름을 다시 묶는다.

전체 흐름은 다음과 같이 요약할 수 있다.

| 단계 | 핵심 질문 | 결과 |
| --- | --- | --- |
| 좌표 | 화면의 한 점을 어떻게 표현할 것인가? | 위치, 거리, 방향, 각도 |
| 함수 | 입력값을 어떤 규칙으로 바꿀 것인가? | 그래프, 곡선, 파동 |
| 값 | 계산 결과를 어떻게 시각 요소로 연결할 것인가? | 색, 밝기, 크기, 회전 |
| 변형 | 좌표계를 어떻게 움직일 것인가? | 이동, 회전, 확대, 접기 |
| 도형 | 형태를 어떻게 정의할 것인가? | 원, 선, 사각형, 다각형, SDF |
| 조합 | 여러 형태와 값을 어떻게 합칠 것인가? | 마스크, 레이어, 블렌딩 |
| 반복 | 같은 규칙을 어떻게 배열할 것인가? | 격자, 타일, 패턴 |
| 필드 | 공간 전체에 값을 어떻게 배치할 것인가? | 스칼라 필드, 벡터 필드, 흐름 필드 |
| 시간 | 값이 어떻게 변하게 할 것인가? | 애니메이션, 루프, 움직임 |
| 시스템 | 상태와 피드백을 어떻게 다룰 것인가? | 입자, 성장, 시뮬레이션 |
| 작품 | 여러 규칙을 어떻게 하나로 구성할 것인가? | 정적 이미지, 애니메이션, 인터랙티브 작업 |

이 순서는 절대적인 규칙이 아니다. 실제 작업에서는 특정 시각 효과에서 출발해 필요한 개념으로 거슬러 올라갈 수도 있고, 하나의 수학적 구조를 실험하다가 작품의 방향을 발견할 수도 있다. 그러나 학습의 관점에서는 좌표와 값에서 시작해 시스템으로 확장하는 순서가 가장 안정적이다. 뒤의 장에서 복잡한 구조를 다룰 때도 결국은 앞에서 배운 좌표, 함수, 값의 조합으로 돌아오기 때문이다.

## 각 장의 구성 방식

각 장은 네 가지 층위로 구성된다. 첫째, 수학적 개념을 설명한다. 여기서 수학은 증명을 위한 수학이 아니라 이미지를 만들기 위한 수학이다. 가능한 한 개념이 왜 필요한지, 어떤 시각적 문제를 해결하는지부터 설명한다.

둘째, 그 개념이 이미지에서 어떻게 보이는지 해석한다. 같은 사인 함수라도 선 그래프로 볼 때와 밝기 패턴으로 볼 때, 파동 애니메이션으로 볼 때의 의미가 달라진다. 거리 함수도 단순한 숫자 계산으로 볼 수 있지만, 경계, 외곽선, 그라데이션, 마스크를 만드는 도구로 볼 수도 있다. 이 책은 수식을 이미지의 언어로 바꾸는 과정을 중요하게 다룬다.

셋째, 구현 전략을 정리한다. 어떤 값이 입력이고, 어떤 값이 출력인지, 어느 단계에서 정규화가 필요한지, 어떤 파라미터를 노출하면 조절하기 좋은지 살펴본다. 이 단계는 특정 언어의 문법보다 알고리즘의 뼈대를 이해하는 데 초점을 둔다.

넷째, 환경별 번역을 다룬다. 같은 원리를 p5.js, Processing, raylib, Quil, openFrameworks, nannou, OPENRNDR, GLSL, HLSL, OSL 같은 환경에서 어떻게 다르게 표현하는지 비교한다. 모든 장에서 모든 환경을 같은 깊이로 다루지는 않는다. 대신 해당 개념을 이해하는 데 적합한 환경을 중심으로 설명하고, Part 6과 Part 7에서 여러 환경을 본격적으로 비교한다.

각 장을 읽을 때는 코드를 그대로 옮기는 것보다, 코드가 어떤 계산을 하고 있는지 따라가는 것이 좋다. 변수 이름이 바뀌고 함수 이름이 달라져도, 입력값이 무엇이고 출력값이 무엇인지 알면 다른 환경으로 옮길 수 있다. 반대로 함수 이름만 외우면 환경이 바뀌는 순간 다시 처음부터 시작해야 한다.

## 이 책을 읽는 방법

이 책은 처음부터 끝까지 순서대로 읽을 수 있도록 구성되어 있다. 제너레이티브 아트나 그래픽 프로그래밍을 처음 접한다면 Part 1부터 차근차근 읽는 것이 좋다. 좌표, 값의 범위, 정규화, 보간 같은 기초 개념은 뒤의 거의 모든 장에서 반복해서 사용된다.

이미 p5.js나 Processing 같은 환경에 익숙하다면 Part 2와 Part 3에서 함수 기반 형태와 좌표 변형을 먼저 살펴봐도 좋다. 셰이더에 관심이 있다면 Part 5까지의 개념을 읽은 뒤 Part 6의 셰이딩 언어 부분으로 넘어갈 수 있다. 다만 GLSL이나 HLSL을 처음 접할 때도 앞부분의 좌표와 거리 함수, 반복, 노이즈 개념은 반드시 도움이 된다.

3D 재질이나 Blender 기반 작업에 관심이 있다면 OSL과 프로시저럴 재질을 다루는 장을 중심으로 읽을 수 있다. 이때도 2D 패턴을 단순한 화면 효과로만 보지 말고, 표면 위에서 계산되는 값으로 확장해 보는 것이 중요하다. 원, 격자, 노이즈, 방사형 패턴은 화면에서도 쓰이고 표면에서도 쓰인다. 차이는 그 값이 색으로 갈지, 거칠기로 갈지, 변위로 갈지에 있다.

책의 후반부에 있는 프로젝트는 앞에서 배운 개념을 다시 묶는 역할을 한다. 각 프로젝트는 하나의 완성 예제가 아니라, 여러 환경으로 옮길 수 있는 구조를 보여 주기 위한 출발점이다. 같은 아이디어를 다른 언어로 다시 구현해 보면, 어떤 부분이 수학적 모델이고 어떤 부분이 환경별 문법인지 더 분명해진다.

## 결과보다 구조를 보는 연습

제너레이티브 아트의 즐거움은 예측과 우연 사이에 있다. 규칙을 세웠지만 결과가 항상 완전히 예상대로 나오지는 않는다. 작은 파라미터 변화가 전혀 다른 이미지를 만들기도 하고, 단순한 반복이 복잡한 질감을 만들기도 한다. 이때 중요한 것은 우연히 마음에 드는 결과를 얻는 데서 멈추지 않는 것이다. 왜 그런 결과가 나왔는지, 어떤 값이 이미지의 성격을 바꾸었는지, 그 변화를 다시 조절할 수 있는지 살펴봐야 한다.

좋은 제너레이티브 작업은 보통 하나의 효과로 끝나지 않는다. 좌표를 어떻게 잡는지, 값을 어떤 범위로 제한하는지, 반복 구조를 얼마나 규칙적으로 둘 것인지, 랜덤을 어디에 넣을 것인지, 시간 변화가 어떤 속도로 일어날 것인지가 함께 작동한다. 따라서 이 책은 개별 기법을 나열하기보다, 기법들이 서로 연결되는 방식을 보여 주려 한다.

처음에는 작은 규칙 하나로 시작해도 충분하다. 화면의 중심에서 멀어질수록 색이 바뀌는 규칙, 좌표를 반복해 격자를 만드는 규칙, 시간값으로 파동을 이동시키는 규칙처럼 단순한 구조에서 출발한다. 그런 다음 규칙을 하나씩 더한다. 거리값에 노이즈를 섞고, 반복 좌표를 회전시키고, 필드의 방향을 따라 입자를 움직이고, 이전 프레임의 결과를 다시 입력으로 사용한다. 이렇게 쌓인 규칙은 단순한 도형의 모음이 아니라 하나의 시각 시스템이 된다.

이 책을 읽는 동안 완벽한 공식을 찾으려 하기보다, 이미지를 계산하는 사고방식에 익숙해지는 것이 더 중요하다. 좌표를 입력으로 보고, 함수를 변환 장치로 보고, 값을 시각 요소로 보고, 시간을 또 하나의 축으로 보는 연습을 하다 보면 그래픽 환경이 바뀌어도 같은 아이디어를 계속 사용할 수 있다.

이제 첫 번째 장에서 제너레이티브 아트의 기본 사고방식을 살펴보자. 우리는 그림을 하나씩 그리는 대신, 그림이 만들어지는 조건을 설계하는 일에서 출발할 것이다.
