# 27.3 UV 좌표와 화면 공간

프래그먼트 셰이더에서 패턴을 만들 때 가장 먼저 정할 것은 계산에 사용할 좌표다. 메시가 제공하는 UV 좌표를 쓰면 무늬가 표면에 붙고, `gl_FragCoord`를 쓰면 현재 프레임버퍼의 픽셀 위치를 기준으로 계산한다. 두 방식은 같은 GLSL 수식을 사용하더라도 패턴이 움직이는 기준과 크기가 달라진다. 좌표 공간을 고르는 일반 원칙은 26.3에서 다루었으며, 이 절에서는 GLSL 4.60 코어에서 UV와 화면 좌표를 얻고 정규화하는 구체적인 방법에 집중한다.

## GLSL에서 만나는 좌표 입력

화면에 그린 3D 메시의 좌표는 여러 단계를 거친다. 버텍스 속성으로 들어오는 위치는 보통 오브젝트 공간이고, 버텍스 셰이더가 이를 클립 공간으로 변환한다. 프래그먼트 셰이더에서는 래스터화로 보간된 사용자 정의 값이나 화면 위치를 사용할 수 있다.

| GLSL 값 | 좌표의 의미 | 보통 쓰는 곳 |
| --- | --- | --- |
| `a_position` | 버텍스 버퍼에 저장된 정점 위치 | 기하를 클립 공간으로 변환 |
| `gl_Position` | 버텍스 셰이더의 클립 공간 출력 | 파이프라인의 클리핑과 투영 처리 |
| `v_uv` | 정점에서 전달되어 프래그먼트마다 보간된 UV | 표면의 이미지·패턴 좌표 |
| `gl_FragCoord.xy` | 현재 프래그먼트의 윈도 좌표 | 프레임버퍼 기준 화면 효과 |

`gl_Position`과 `gl_FragCoord`는 이름이 비슷해도 같은 공간의 값이 아니다. 전자는 버텍스 단계가 출력하는 클립 좌표이고, 후자는 래스터화 후 프래그먼트 셰이더에서 읽는 윈도 좌표다. 또한 `v_uv`는 GLSL이 자동으로 만드는 값이 아니다. 메시 또는 호스트가 정점마다 제공하고, 버텍스 셰이더가 다음 단계로 전달해야 한다.

## UV를 프래그먼트까지 전달하기

정점마다 위치와 UV를 입력하고, 버텍스 셰이더에서 UV를 출력하면 래스터화 과정이 삼각형 내부의 값을 보간한다. 다음은 정점의 UV 값을 색으로 보여 주는 단순한 예다.

```glsl
// Vertex shader
#version 460 core

layout(location = 0) in vec3 a_position;
layout(location = 1) in vec2 a_uv;

uniform mat4 u_mvp;
layout(location = 0) out vec2 v_uv;

void main() {
    gl_Position = u_mvp * vec4(a_position, 1.0);
    v_uv = a_uv;
}
```

```glsl
// Fragment shader
#version 460 core

layout(location = 0) in vec2 v_uv;
layout(location = 0) out vec4 outColor;

void main() {
    outColor = vec4(v_uv, 0.0, 1.0);
}
```

프래그먼트 셰이더의 빨강 채널은 `u`, 초록 채널은 `v`를 나타낸다. 평면에 UV를 왼쪽 아래에서 오른쪽 위로 0에서 1까지 지정했다면 화면에는 그 방향을 확인할 수 있는 색 변화가 나타난다. 실제 메시의 UV는 제작 방식에 따라 범위가 0~1을 벗어나거나, 뒤집히거나, 여러 섬으로 나뉠 수 있다. 따라서 UV가 항상 표준 방향과 범위를 가진다고 가정하지 말고, 테스트 그라디언트나 격자로 먼저 매핑을 확인한다.

UV는 표면에 붙어 있으므로 카메라나 물체가 움직여도 그 표면의 같은 지점을 가리킨다. 이미지 텍스처를 읽거나 표면에 타일 패턴을 만들 때 적합하다. 텍스처에서 실제 색을 읽는 `texture()`의 사용과 샘플링 설정은 26.7에서 다루며, 좌표를 반복하거나 변형하는 패턴은 27.6에서 이어서 살펴본다.

## `gl_FragCoord`로 화면 위치 얻기

`gl_FragCoord`는 프래그먼트 셰이더가 현재 처리하는 위치를 담은 내장 입력이다. `.xy`는 윈도 좌표이며 기본 OpenGL 규약에서는 원점이 왼쪽 아래이고 x는 오른쪽, y는 위쪽으로 증가한다. 기본적인 단일 샘플 렌더링에서는 좌표가 픽셀의 중심을 가리키므로 첫 픽셀 중심은 보통 `(0.5, 0.5)`다.

이 값은 자동으로 0~1 범위가 되지 않는다. 정규화하려면 렌더링 영역의 픽셀 위치와 크기를 호스트에서 전달해야 한다. 아래의 `u_viewport`는 `(x, y, width, height)` 순서로, 원점과 크기를 모두 프레임버퍼 픽셀 단위로 담는다고 가정한다.

```glsl
#version 460 core

uniform vec4 u_viewport; // origin x/y, size width/height in framebuffer pixels
layout(location = 0) out vec4 outColor;

void main() {
    vec2 viewportSize = u_viewport.zw;
    vec2 pixel = gl_FragCoord.xy - u_viewport.xy;
    vec2 uv = pixel / viewportSize;

    outColor = vec4(uv, 0.0, 1.0);
}
```

뷰포트가 프레임버퍼 전체를 차지한다면 원점은 `(0, 0)`, 크기는 프레임버퍼 해상도와 같다. 뷰포트가 화면의 일부에만 놓인 경우에는 그 원점을 빼야 그 영역 안에서 0~1로 정규화된다. 호스트가 `u_viewport`에 창의 크기만 보내고 오프스크린 렌더 타깃이나 부분 뷰포트를 사용하면, 좌표와 패턴 크기가 맞지 않을 수 있다.

고해상도 디스플레이에서는 논리 창 크기와 프레임버퍼 픽셀 크기가 다를 수 있다. `gl_FragCoord`와 나눗셈에 사용할 크기는 같은 단위, 즉 실제 렌더 타깃의 픽셀 단위여야 한다. 화면 크기가 바뀌거나 렌더 타깃을 교체하면 해당 크기 유니폼도 함께 갱신한다.

## 중심 좌표와 종횡비 보정

화면 중심을 원점으로 옮기고 세로 픽셀 크기를 기준 단위로 사용하면, 가로와 세로 픽셀의 비율이 다른 화면에서도 거리와 각도를 원형으로 계산할 수 있다.

```glsl
vec2 viewportSize = u_viewport.zw;
vec2 pixel = gl_FragCoord.xy - u_viewport.xy;
vec2 uv = pixel / viewportSize;

vec2 p = (pixel - 0.5 * viewportSize) / viewportSize.y;
float radius = length(p);
float angle = atan(p.y, p.x);
```

`uv`는 렌더 영역 안의 정규화 좌표이고, `p`는 중심이 원점인 종횡비 보정 좌표다. `p.x`와 `p.y`를 모두 높이로 나누므로 x축은 화면의 종횡비만큼 넓게 펼쳐지고 y축은 높이에 맞춰진다. 따라서 `length(p)`는 원형 화면 패턴에 쓸 수 있고, `atan()`은 방사형 각도를 구하는 데 쓸 수 있다. 보정하지 않고 정규화된 UV에서 바로 거리를 계산하면 가로세로 픽셀 수가 다른 화면에서 원이 타원으로 보일 수 있다.

이 식은 세로 방향의 화면 반높이를 한 단위로 정의한다. 반경이나 격자 간격을 화면 전체 크기와 독립적으로 조절하려면 이 기준을 유지하고, 창 크기에 따라 요소가 달라져야 한다면 가로 또는 세로 픽셀 단위를 명시적으로 선택한다. 단위 선택이 달라지면 같은 숫자 파라미터도 화면에서 차지하는 크기가 달라진다.

## 원점 방향과 이미지 방향

OpenGL의 기본 `gl_FragCoord` 원점은 왼쪽 아래지만, 이미지 로더와 프레임워크가 노출하는 텍스처 좌표 또는 캔버스 좌표는 위쪽을 원점으로 삼을 수 있다. 방향을 모르면 색 그라디언트나 위아래가 분명한 격자를 출력해 직접 확인한다. 필요한 경우 화면 UV의 y 성분만 뒤집을 수 있다.

```glsl
uv.y = 1.0 - uv.y;
```

이 뒤집기는 좌표 관례를 맞추는 작업이지 모든 텍스처에 적용해야 하는 규칙은 아니다. 텍스처 업로드 과정에서 이미 뒤집혔다면 다시 뒤집는 순간 방향이 원래대로 돌아갈 수 있다. 셰이더 좌표, 이미지 디코더, 호스트가 사용하는 프레임버퍼 방향을 함께 확인한다.

## 두 좌표 기준을 선택하는 기준

| 원하는 동작 | 적합한 좌표 | 화면에서 보이는 성격 |
| --- | --- | --- |
| 무늬가 메시 표면에 고정됨 | 보간된 UV | 물체와 함께 움직이고 표면의 UV 매핑을 따름 |
| 패턴이 화면에 고정됨 | 뷰포트 기준 `gl_FragCoord` | 물체나 카메라가 움직여도 화면 위치를 따름 |
| 여러 도형·레이어에 걸쳐 하나의 화면 효과 | 공통 화면 좌표 | 각 그리기 요소가 같은 프레임버퍼 기준을 공유 |
| 이미지 또는 표면에 매핑된 패턴 | UV | 텍스처 좌표와 같은 도메인에서 작동 |

표면을 가로지르는 넓은 세계 패턴이 필요하다면 UV와 화면 공간만으로 해결할 수 없는 경우가 있다. 이때는 로컬·월드 공간 위치를 별도로 전달해야 한다. 좌표가 어디에 고정되어야 하는지 먼저 정하고, 그 의미에 맞는 값을 프래그먼트 셰이더 입력으로 준비한다.

## 이 절의 핵심

UV는 정점에서 제공되어 표면을 따라 보간되는 좌표이고, `gl_FragCoord.xy`는 프래그먼트의 윈도 좌표다. 화면 좌표는 뷰포트 원점을 빼고 실제 프레임버퍼 픽셀 크기로 나누어야 일관된 정규화 값을 얻는다. 중심 기반 거리와 각도에는 종횡비를 보정하고, y축 방향은 OpenGL과 이미지·호스트의 좌표 관례를 확인한 뒤 필요할 때만 뒤집는다.
