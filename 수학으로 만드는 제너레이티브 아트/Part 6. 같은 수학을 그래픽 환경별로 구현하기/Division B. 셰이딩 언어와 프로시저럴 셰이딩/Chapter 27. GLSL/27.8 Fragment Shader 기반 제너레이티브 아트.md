# 27.8 Fragment Shader 기반 제너레이티브 아트

프래그먼트 셰이더로 만드는 제너레이티브 아트에서는 전체 화면을 덮는 삼각형이나 사각형 하나를 그리고, 각 프래그먼트에서 색을 직접 계산하는 방식이 자주 쓰인다. 화면에 도형을 하나씩 배치하는 대신 좌표를 노이즈·거리·파동 함수에 넣어 이미지 전체를 하나의 필드로 만든다.

이 절에서는 등고선 지도처럼 보이는 절차적 이미지를 GLSL 4.60으로 구성한다. 셰이더는 화면 좌표에서 두 개의 노이즈 필드로 좌표를 휘고, 그 결과에서 높이값을 계산한 뒤 색상 구간과 등고선을 합성한다. 좌표 변환, SDF, 시간, 노이즈를 앞 절에서 각각 다루었으므로 여기서는 이 요소들을 한 화면에 연결하는 흐름을 살펴본다.

## 프래그먼트 셰이더 전체 예제

다음 코드는 GLSL 프래그먼트 셰이더 소스 하나로 구성되어 있다. 호스트 프로그램은 이 셰이더를 컴파일해 화면을 덮는 도형과 함께 실행하고, `u_viewport`와 `u_time`을 전달해야 한다. `u_viewport`는 `(x, y, width, height)` 순서의 프레임버퍼 픽셀 값이다.

```glsl
#version 460 core

uniform vec4 u_viewport;
uniform float u_time;
layout(location = 0) out vec4 outColor;

float hash12(vec2 p) {
    vec3 p3 = fract(vec3(p.xyx) * 0.1031);
    p3 += dot(p3, p3.yzx + 33.33);
    return fract((p3.x + p3.y) * p3.z);
}

float valueNoise(vec2 p) {
    vec2 cell = floor(p);
    vec2 local = fract(p);
    vec2 fade = local * local * (3.0 - 2.0 * local);

    float a = hash12(cell);
    float b = hash12(cell + vec2(1.0, 0.0));
    float c = hash12(cell + vec2(0.0, 1.0));
    float d = hash12(cell + vec2(1.0, 1.0));

    float lower = mix(a, b, fade.x);
    float upper = mix(c, d, fade.x);
    return mix(lower, upper, fade.y);
}

float fbm(vec2 p) {
    float sum = 0.0;
    float amplitude = 0.5;
    float amplitudeSum = 0.0;

    for (int octave = 0; octave < 5; ++octave) {
        sum += amplitude * valueNoise(p);
        amplitudeSum += amplitude;
        p = p * 2.0 + vec2(13.7, 9.2);
        amplitude *= 0.5;
    }

    return sum / amplitudeSum;
}

void main() {
    vec2 size = u_viewport.zw;
    vec2 pixel = gl_FragCoord.xy - u_viewport.xy;
    vec2 uv = pixel / size;

    vec2 p = uv * 2.0 - 1.0;
    p.x *= size.x / size.y;

    float t = u_time * 0.05;
    vec2 drift = vec2(t, -0.73 * t);
    vec2 warp = vec2(
        fbm(p * 1.15 + drift),
        fbm(p * 1.15 + drift + vec2(8.2, 3.7))
    ) - 0.5;

    vec2 q = p + 0.65 * warp;
    float elevation = fbm(q * 2.4 + vec2(-0.12 * t, 0.08 * t));

    float levels = elevation * 11.0;
    float phase = fract(levels);
    float distanceToLine = min(phase, 1.0 - phase);
    float aa = max(fwidth(levels), 1e-4);
    float contour = 1.0 - smoothstep(0.025 - aa, 0.025 + aa, distanceToLine);

    vec3 deep = vec3(0.015, 0.075, 0.13);
    vec3 middle = vec3(0.035, 0.40, 0.43);
    vec3 high = vec3(0.88, 0.76, 0.49);
    vec3 ink = vec3(0.82, 0.91, 0.83);

    float middleBlend = smoothstep(0.18, 0.58, elevation);
    float highBlend = smoothstep(0.56, 0.84, elevation);
    vec3 color = mix(deep, middle, middleBlend);
    color = mix(color, high, highBlend);
    color = mix(color, ink, contour * 0.78);

    outColor = vec4(color, 1.0);
}
```

이 셰이더에는 정점별 UV 입력이 없다. 프래그먼트마다 `gl_FragCoord`에서 화면 좌표를 얻고, 뷰포트 원점을 빼고 크기로 나누어 현재 렌더 영역 안의 `uv`를 계산한다. 그 좌표를 중심 기준으로 이동한 뒤 종횡비를 보정해 `p`를 만든다. 뷰포트와 화면 좌표의 단위는 27.3에서 다룬 규칙을 따른다.

`hash12`, `valueNoise`, `fbm`은 27.7의 구현을 이 예제 안에 포함한 것이다. GLSL에는 표준 `#include` 지시문이 없으므로, 별도 전처리기를 쓰지 않는다면 함수 정의도 하나의 셰이더 소스에 함께 두어야 한다. 작은 해시 기반 노이즈의 품질 한계도 앞 절의 주의점을 그대로 갖는다.

## 필드를 쌓는 순서

예제는 한 프래그먼트에서 다음 순서로 계산한다.

1. 화면 위치를 중심 기준 좌표 `p`로 변환한다.
2. 서로 다른 입력 위치의 fBm 두 개를 벡터 `warp`로 합친다.
3. `p`를 `warp`만큼 이동한 좌표 `q`에서 높이 필드 `elevation`을 평가한다.
4. 높이를 일정한 단계로 나누어 등고선 마스크를 만든다.
5. 높이 범위에 색을 배정하고 등고선 색을 위에 섞는다.

두 워프 성분은 같은 노이즈를 그대로 재사용하지 않고 좌표 오프셋을 다르게 주었다. 두 값이 비슷하게 움직이면 좌표가 주로 한 방향으로만 밀릴 수 있기 때문이다. 결과를 더 강하게 휘게 하려면 `0.65`를 키우고, 지형이 과도하게 찢기거나 꼬이면 줄인다. `elevation`에 적용한 `q * 2.4`는 큰 지형 구조의 크기를 정하며, 높이색과 등고선 밀도는 서로 독립적으로 조절할 수 있다.

## 안티앨리어싱된 등고선

`levels`는 연속적인 높이값을 등고선의 반복 주기로 바꾼다. `fract(levels)`는 각 구간 안의 위치를 얻고, 그 값과 `1.0 - phase` 중 작은 값을 취해 가까운 정수 단계까지의 거리를 계산한다. 그 거리가 0에 가까운 곳이 등고선이다.

고정된 임계값만 사용하면 선이 프래그먼트보다 얇을 때 깜빡이거나 끊겨 보일 수 있다. `fwidth(levels)`는 화면에서 이 값이 한 픽셀에 걸쳐 얼마나 바뀌는지 추정한다. 그 값을 `smoothstep` 경계에 반영해 선 가장자리를 부드럽게 하므로 해상도 변화에도 비교적 안정적이다. `0.025`는 등고선 두께를 조절하고, `levels = elevation * 11.0`의 11은 등고선 단계의 수를 조절한다. `fwidth`의 사용 조건과 경계 마스크의 원리는 27.5를 참고한다.

## 시간은 장면을 흐르게 한다

`u_time`은 프레임마다 호스트가 갱신하는 초 단위 시간값이다. 여기서는 작은 시간 배율 `t`를 두고, 워프 필드와 높이 필드의 샘플 좌표를 천천히 이동시킨다. 시간은 해시 시드를 바꾸는 데 쓰이지 않는다. 같은 시점과 좌표에는 같은 노이즈값이 대응하므로 프레임 사이에 연속적인 흐름이 유지된다.

현재 예제는 정해진 구간에서 반복되는 루프를 보장하지 않는다. 마지막 프레임과 첫 프레임을 이어 붙여야 하는 작업이라면 27.4에서 설명한 주기적인 시간 매개화가 필요하다. 이 셰이더는 앞선 시간 상태를 저장하지 않는 순수 함수형 화면 패스이므로, 이전 프레임이 남는 잔상이나 시뮬레이션 피드백을 만들려면 별도의 렌더 타깃을 입력으로 추가해야 한다.

## 품질과 성능을 조절하기

예제 한 프래그먼트는 워프를 위한 fBm 두 번과 높이 계산을 위한 fBm 한 번을 호출한다. fBm이 다섯 옥타브이고 각 2D Value Noise가 네 격자점의 해시를 계산하므로, 최적화 전 기준으로 프래그먼트당 약 60회의 해시 평가가 발생할 수 있다. 전체 화면의 모든 픽셀에서 실행되므로 해상도가 커지면 비용도 빠르게 늘어난다.

품질을 조정할 때는 다음 순서가 실용적이다.

- 노이즈 옥타브를 다섯에서 세 개로 줄여 구조와 비용의 변화를 확인한다.
- 두 워프 중 하나를 제거하거나 낮은 주파수 Value Noise로 바꿔 좌표 왜곡 비용을 줄인다.
- `levels`의 계수를 조절해 선 밀도를 바꾸고, 화면에서 뭉개지는 고주파 세부는 제거한다.
- 결과가 정적이라면 한 번 렌더한 뒤 텍스처로 재사용하는 방식을 검토한다.
- 목표 프레임버퍼 해상도에서 실제로 측정한다.

높은 옥타브가 화면 픽셀보다 작아지면 세부가 앨리어싱되거나 시간에 따라 반짝일 수 있다. `fwidth`는 등고선의 경계를 부드럽게 하지만 모든 노이즈 세부를 자동으로 필터링하지는 않는다. fBm 옥타브별로 화면 풋프린트를 고려해 기여도를 줄이거나, 낮은 해상도 렌더 타깃·밉맵 텍스처를 사용할 수 있다.

## 작품으로 확장하기

이 예제의 구조에서 필드 계산과 색상화를 분리하면 다양한 변형을 만들 수 있다. 높이값을 색 대신 원의 반지름이나 마스크에 연결하고, SDF로 화면 일부에만 필드를 드러내거나, 팔레트의 구간을 바꾸어 다른 재료감을 만들 수 있다. `q`에 타일 좌표를 적용하면 셀마다 다른 지형을 만들 수도 있다. 각 변형의 기본 수학은 27.5~27.7에서 다루었으며, 여기서는 여러 기법이 같은 프래그먼트 평가 흐름에 합쳐진다는 점이 핵심이다.

## 이 절의 핵심

전체 화면 프래그먼트 셰이더는 좌표를 필드 함수에 넣고 색으로 변환해 이미지를 만든다. 예제에서는 시간에 따라 움직이는 도메인 워프와 fBm 높이 필드, `fwidth` 기반 등고선, 다단계 팔레트를 한 번의 프래그먼트 패스에 결합했다. 이런 이미지는 픽셀마다 여러 노이즈 평가를 수행하므로, 옥타브·워프 수·출력 해상도를 목표 장치에서 함께 조절해야 한다.
