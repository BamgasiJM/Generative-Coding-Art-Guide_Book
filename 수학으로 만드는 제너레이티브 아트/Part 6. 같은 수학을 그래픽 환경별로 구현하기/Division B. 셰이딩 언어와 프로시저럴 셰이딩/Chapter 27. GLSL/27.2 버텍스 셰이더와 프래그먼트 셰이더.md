# 27.2 버텍스 셰이더와 프래그먼트 셰이더

실시간 그래픽에서 가장 자주 만나는 셰이더 조합은 버텍스 셰이더와 프래그먼트 셰이더다. 버텍스 셰이더는 입력 정점마다 위치와 전달할 값을 계산하고, 그 결과로 만들어진 삼각형을 래스터화한 뒤 프래그먼트 셰이더가 각 표면 표본의 색을 계산한다. 이 절은 GLSL 4.60 코어 문법으로 두 단계를 연결하는 예를 살펴본다. 정점·프래그먼트 단계의 일반적인 역할은 26.2에서 설명했으며, 여기서는 GLSL 프로그램의 입출력과 연결에 집중한다.

## 두 단계가 나누어 맡는 일

버텍스 셰이더는 정점 입력을 받아 화면에 투영될 위치를 출력한다. 위치 외에도 색, UV, 법선 같은 데이터를 다음 단계에 전달할 수 있다. 프래그먼트 셰이더는 래스터화 과정에서 생성된 프래그먼트마다 실행되며, 보통 색과 알파를 출력한다.

```text
정점 버퍼와 유니폼
    -> 버텍스 셰이더: 정점 위치와 전달 데이터 계산
        -> 프리미티브 구성, 클리핑, 래스터화
            -> 전달 데이터 보간
                -> 프래그먼트 셰이더: 각 프래그먼트의 색 계산
                    -> 깊이·스텐실 검사, 블렌딩 등 후속 처리
```

이것은 기본적인 삼각형 렌더링의 흐름이다. 테셀레이션이나 지오메트리 셰이더처럼 중간 단계를 더하는 파이프라인도 있지만, 두 셰이더를 처음 연결할 때는 이 단순한 경로를 기준으로 삼으면 된다.

## 버텍스 입력과 클립 공간 위치

버텍스 셰이더는 입력 데이터 한 묶음에 대해 한 번 실행된다. `layout(location = n) in` 선언은 정점 속성의 슬롯을 지정한다. 아래에서 위치는 0번, 색은 1번 슬롯을 사용한다. 애플리케이션 쪽에서는 정점 버퍼의 자료형과 각 속성 슬롯을 이 선언에 맞춰 연결해야 한다.

```glsl
#version 460 core

layout(location = 0) in vec3 a_position;
layout(location = 1) in vec3 a_color;

uniform mat4 u_mvp;

layout(location = 0) out vec3 v_color;

void main() {
    gl_Position = u_mvp * vec4(a_position, 1.0);
    v_color = a_color;
}
```

`a_position`은 모델의 정점 좌표이고 `a_color`는 그 정점에 붙인 RGB 색이다. `u_mvp`는 모델, 뷰, 투영 변환을 조합한 행렬을 담는 유니폼이다. 이 값은 셰이더 안에서 선언했더라도 저절로 생기지 않으므로, 호스트 애플리케이션이 그리기 전에 설정해야 한다.

`gl_Position`은 버텍스 셰이더가 반드시 제공해야 하는 정점 위치 출력이다. 여기에는 화면 픽셀 좌표가 아니라 동차 좌표계의 클립 공간 위치를 쓴다. 파이프라인은 정점들로 프리미티브를 만들고 클리핑한 다음 원근 나눗셈과 뷰포트 변환을 거쳐 화면상의 위치를 정한다. 따라서 위치 변환을 생략하거나 좌표계가 다른 행렬을 전달하면 기하가 화면 밖에 놓이거나 왜곡될 수 있다.

## 단계 사이 인터페이스와 보간

버텍스 셰이더의 `out` 값은 다음 단계의 같은 위치에 선언한 `in` 값으로 전달된다. 예제의 `v_color`는 양쪽에서 `location = 0`과 `vec3` 타입이 일치한다. 인터페이스 위치와 타입이 맞지 않으면 프로그램을 링크할 때 오류가 나거나 의도하지 않은 값이 연결될 수 있다. 셰이더 단계를 따로 작성한다면 변수의 이름만이 아니라 타입과 위치 선언도 함께 확인한다.

삼각형의 세 꼭짓점이 서로 다른 색을 출력하면, 프래그먼트 셰이더는 각 픽셀 후보에서 그 색의 보간값을 받는다. GLSL의 기본 보간 방식은 `smooth`이며, 원근 투영을 고려한 보간을 수행한다. 이를 명시적으로 표현하면 다음처럼 쓸 수 있다.

```glsl
layout(location = 0) smooth out vec3 v_color;
```

프래그먼트 단계에는 대응하는 `smooth in` 선언이 필요하다. 정수형 ID처럼 꼭짓점 사이에서 섞이면 안 되는 값에는 `flat` 보간을 사용한다. `noperspective`는 화면 공간에서 선형 보간할 때 쓸 수 있다. 보간 한정자는 생산하는 단계와 받는 단계에서 서로 일치시켜야 한다. 단일 플랫 색을 쓰는지, 표면을 가로지르는 색 변화를 원하는지에 따라 보간 방식이 시각 결과를 바꾼다.

## 프래그먼트 색 출력

프래그먼트 셰이더는 보간된 색을 받아 렌더 타깃에 기록할 색으로 출력한다.

```glsl
#version 460 core

layout(location = 0) in vec3 v_color;
layout(location = 0) out vec4 outColor;

void main() {
    outColor = vec4(v_color, 1.0);
}
```

입력한 정점 색이 각 프래그먼트에 보간되어 들어오므로, 이 셰이더는 삼각형 표면에 색의 점진적인 변화를 만든다. `outColor`의 첫 번째 위치는 프레임워크 또는 그래픽 API가 연결한 첫 번째 컬러 출력에 대응한다. 여러 렌더 타깃을 사용하는 경우에는 출력 위치를 각각 지정하고 호스트 쪽에서도 같은 첨부 대상과 연결해야 한다.

프래그먼트 셰이더가 출력한 값이 항상 그대로 모니터에 보이는 것은 아니다. 깊이와 스텐실 검사, 알파 블렌딩, 멀티샘플 처리와 같은 후속 렌더 상태가 최종 결과에 관여한다. 셰이더 로그에는 오류가 없는데 색이 보이지 않거나 다른 색과 섞여 보인다면, 프래그먼트 코드뿐 아니라 렌더 타깃과 그래픽 상태도 점검한다.

## 전체 코드와 호스트의 책임

앞의 두 코드를 연결하면 정점 색을 삼각형 내부에 보간해 출력하는 셰이더 프로그램이 된다. 하지만 GLSL 소스만으로 장면이 렌더링되지는 않는다. 호스트 애플리케이션은 적어도 다음 작업을 맡는다.

- 버텍스 셰이더와 프래그먼트 셰이더를 각각 컴파일하고 하나의 프로그램으로 링크한다.
- 정점 버퍼를 만들고 `a_position`, `a_color`를 선언한 위치와 자료형에 맞게 연결한다.
- `u_mvp` 행렬을 설정하고, 렌더 타깃과 뷰포트를 준비한다.
- 그릴 프리미티브와 정점 범위를 지정해 드로우 호출을 수행한다.

프레임워크나 시각 프로그래밍 도구는 이 과정을 자동화하거나 일부를 사용자에게 노출하지 않을 수 있다. 따라서 GLSL 단계 코드와 호스트의 입력 설정을 구분해 생각해야 한다. 셰이더 컴파일은 성공하지만 결과가 잘못된 경우, 정점 속성의 슬롯과 타입, 유니폼 행렬, 단계 간 인터페이스, 렌더 상태 순으로 확인하면 원인을 찾기 쉽다.

## 단계별로 규칙을 배치하기

기하의 위치 자체를 움직이거나 정점 단위의 값을 만들려면 버텍스 셰이더를 살펴본다. 이미 래스터화된 표면이나 화면 영역의 각 위치에서 색과 마스크를 계산하려면 프래그먼트 셰이더가 적합하다. 예를 들어 버텍스 단계에서 사인파로 메시 높이를 바꾸고, 프래그먼트 단계에서는 보간된 높이나 색에 따라 표면을 채색할 수 있다.

하나의 계산을 양쪽에 무조건 중복하기보다는 데이터가 필요한 단계에서 수행한다. 모든 프래그먼트에서 같은 좌표 변환을 반복하는 대신 버텍스에서 계산한 값을 보간해 전달할 수 있고, 반대로 픽셀 수준의 선명한 패턴을 정점 계산만으로 표현하려 하면 메시 밀도가 충분하지 않을 수 있다. 함수의 출력이 위치인지, 표면 색인지 먼저 정하면 어느 단계에 둘지 결정하기 쉽다.

UV나 화면 좌표를 기준으로 패턴을 만드는 방법은 27.3에서, 프레임마다 시간과 매개변수를 전달하는 방법은 27.4에서 다룬다.

## 이 절의 핵심

버텍스 셰이더는 정점 입력을 `gl_Position`과 후속 단계의 데이터로 바꾸고, 프래그먼트 셰이더는 래스터화와 보간을 거쳐 도착한 값으로 프래그먼트의 색을 출력한다. GLSL 4.60에서는 `layout(location = ...)`과 `in`·`out`으로 정점 속성, 단계 간 전달값, 렌더 타깃 출력을 명시할 수 있다. 셰이더의 정확한 동작에는 호스트가 연결하는 버퍼·유니폼·렌더 상태도 함께 맞아야 한다.
