# 27.7 노이즈와 프로시저럴 텍스처

프로시저럴 텍스처는 이미지를 미리 저장하지 않고 좌표와 매개변수에서 색이나 값을 계산한다. 노이즈는 그 안에서 큰 얼룩부터 잔결까지 자연스러운 변화를 만드는 재료다. GLSL 4.60에는 모든 GPU에서 쓸 수 있는 표준 Perlin 또는 Simplex 노이즈 함수가 없다. 일부 문서에 보이는 `noise1`~`noise4` 이름은 예약되어 있을 뿐, 실제 노이즈 알고리즘이나 결과가 이식 가능하게 보장되지 않는다. 따라서 셰이더 안에 구현을 포함하거나, 검증된 라이브러리·텍스처를 입력으로 사용해야 한다.

노이즈의 연속성, 해시와 Value·Gradient Noise의 수학적 차이, 옥타브의 개념은 Part 4에서 다루었다. 여기서는 GLSL로 간결한 2D Value Noise를 작성하고, 이를 fBm과 색상 필드로 확장하는 흐름을 살펴본다.

## 해시와 노이즈는 다르다

해시 함수는 좌표를 입력받아 의사 난수처럼 보이는 값을 반환한다. 이 값을 정수 격자점에 직접 적용하면 점마다 독립적으로 튀는 값이 생길 뿐, 좌표가 조금 움직여도 출력이 조금만 변하는 연속적인 노이즈는 되지 않는다. Value Noise는 격자점의 해시값을 셀 내부에서 부드럽게 보간해 두 성질을 연결한다.

```glsl
float hash12(vec2 p) {
    vec3 p3 = fract(vec3(p.xyx) * 0.1031);
    p3 += dot(p3, p3.yzx + 33.33);
    return fract((p3.x + p3.y) * p3.z);
}

float valueNoise(vec2 p) {
    vec2 cell = floor(p);
    vec2 local = fract(p);
    vec2 fade = local * local * (3.0 - 2.0 * local);

    float a = hash12(cell);
    float b = hash12(cell + vec2(1.0, 0.0));
    float c = hash12(cell + vec2(0.0, 1.0));
    float d = hash12(cell + vec2(1.0, 1.0));

    float lower = mix(a, b, fade.x);
    float upper = mix(c, d, fade.x);
    return mix(lower, upper, fade.y);
}
```

`floor(p)`는 현재 셀의 정수 좌표를, `fract(p)`는 셀 안의 위치를 만든다. 해시값 `a`~`d`는 그 셀 네 꼭짓점의 값이다. `fade`에 사용한 곡선은 셀 경계에서 기울기가 0이 되도록 만들어 선형 보간보다 경계가 덜 드러난다. 마지막 세 번의 `mix()`는 가로 방향으로 두 번, 세로 방향으로 한 번 값을 섞는다. 입력 좌표가 조금 바뀌면 보간 비율도 조금만 달라지므로 출력은 연속적으로 보인다.

`hash12`는 설명을 위해 짧게 쓴 부동소수점 해시다. 이것은 보안용 난수 생성기가 아니며, 모든 입력 범위와 GPU에서 같은 품질의 무작위성을 보장하지 않는다. 격자 무늬나 반복 흔적이 보이면 해시 함수의 품질, 입력의 정밀도, 좌표 범위를 살핀다. 더 높은 품질이나 정확한 반복성이 필요하면 검증된 Gradient Noise 구현이나 미리 만든 노이즈 텍스처를 사용할 수 있다.

Value Noise가 유일한 선택은 아니다. GLSL 표준에는 아래 알고리즘도 내장되어 있지 않으므로, 사용하려면 직접 구현하거나 라이브러리·텍스처를 준비해야 한다.

| 방법 | 셀에 저장하거나 평가하는 것 | 주로 고려할 때 |
| --- | --- | --- |
| Value Noise | 격자 꼭짓점의 스칼라값을 보간 | 단순한 구름형 명암, 작은 GLSL 예제 |
| Gradient Noise / Perlin 계열 | 꼭짓점의 방향과 입력점의 변위를 이용 | 흐름과 기울기가 자연스러운 필드 |
| Simplex 계열 | 격자 사각형 대신 단순체 분할에서 기여를 계산 | 다차원 입력이나 다른 방향성의 패턴이 필요할 때 |
| Cellular / Worley 계열 | 주변 특징점까지의 거리 | 세포, 돌, 균열처럼 경계가 읽히는 패턴 |
| 노이즈 텍스처 | 미리 계산한 필드의 표본값 | 반복 사용, 비용 절감, 필드의 정확한 재사용 |

알고리즘마다 특징 크기와 방향성, 출력 범위, 계산량이 다르다. 노이즈 수학의 세부는 12.2~12.6을 참고하고, 실제 GLSL 구현을 선택할 때는 목표 프로필에서 컴파일되는지와 반복성·성능을 확인한다.

## Value Noise를 화면에 표시하기

Value Noise 함수는 스칼라값을 반환하므로 색으로 변환해야 결과를 볼 수 있다. 다음 코드는 각 프래그먼트의 화면 좌표에서 노이즈를 평가하고, 두 색 사이에 매핑하는 흐름을 보여 준다. `u_viewport`는 `(x, y, width, height)`이며 픽셀 단위로 호스트가 전달한다고 가정한다.

```glsl
#version 460 core

uniform vec4 u_viewport;
uniform float u_frequency;
uniform vec3 u_darkColor;
uniform vec3 u_lightColor;
layout(location = 0) out vec4 outColor;

// hash12()와 valueNoise()를 앞의 정의와 같이 둔다.

void main() {
    vec2 pixel = gl_FragCoord.xy - u_viewport.xy;
    vec2 uv = pixel / u_viewport.zw;
    vec2 p = uv * u_frequency;

    float n = valueNoise(p);
    vec3 color = mix(u_darkColor, u_lightColor, n);
    outColor = vec4(color, 1.0);
}
```

`u_frequency`를 높이면 화면 안에 더 작고 촘촘한 특징이 나타난다. `u_darkColor`와 `u_lightColor`를 바꾸면 같은 노이즈 필드를 구름, 종이 얼룩, 대리석 같은 서로 다른 색상 분포로 읽히게 할 수 있다. 이 함수의 값은 해시와 보간 방식에서 나오며, 모든 해시 함수가 완벽한 균일 분포나 정확한 0~1 범위를 제공한다고 가정해서는 안 된다. 임계값이나 재질 속성으로 사용하기 전에는 실제 출력 범위를 확인한다.

예제는 전체 프레임버퍼를 채우는 렌더 패스를 가정한다. 부분 뷰포트나 다른 크기의 렌더 타깃에서는 실제 뷰포트의 원점과 크기를 보내야 한다. 좌표 정규화와 픽셀 단위의 뷰포트 처리는 27.3에서 설명한 규칙을 따른다.

## 여러 스케일을 합치는 fBm

하나의 Value Noise는 주된 특징 크기가 하나인 비교적 단순한 필드다. 서로 다른 주파수와 진폭으로 여러 번 평가해 더하면 큰 얼룩 위에 중간 변화와 미세한 결이 쌓인다. 이를 프랙탈 브라운 운동(fBm)이라고 부른다.

```glsl
float fbm(vec2 p) {
    float sum = 0.0;
    float amplitude = 0.5;
    float amplitudeSum = 0.0;

    for (int octave = 0; octave < 5; ++octave) {
        sum += amplitude * valueNoise(p);
        amplitudeSum += amplitude;

        p = p * 2.0 + vec2(13.7, 9.2);
        amplitude *= 0.5;
    }

    return sum / amplitudeSum;
}
```

각 반복이 한 옥타브다. 좌표를 두 배로 키워 다음 옥타브의 특징을 더 촘촘하게 하고, 진폭은 절반으로 줄여 작은 구조가 전체 결과를 압도하지 않게 한다. `amplitudeSum`으로 나누면 옥타브 수가 달라져도 출력 범위가 비교적 일정하게 유지된다. 좌표에 더하는 고정 오프셋은 각 옥타브의 격자 정렬을 조금 달리해 반복적인 인상을 줄인다. 같은 입력에는 언제나 같은 결과가 나온다.

fBm의 주파수 배율과 진폭 감소는 서로 다른 조절값이다. 옥타브 수를 늘리면 세부 계산이 많아지고, 진폭 감소를 완만하게 하면 미세한 옥타브의 영향이 커진다. 이 책의 예제는 컴파일 시 반복 횟수가 정해진 작은 루프를 사용한다. 옥타브 수를 유니폼으로 받아 가변 반복으로 만들 수도 있지만, 목표 장치의 셰이더 컴파일러와 성능을 확인하고 필요한 최대 횟수를 제한한다.

## 노이즈를 움직임과 변형에 연결하기

노이즈는 색상 외에도 좌표 변위, 밝기, 마스크, 재질 거칠기처럼 여러 결과에 연결할 수 있다. 예를 들어 fBm을 사용해 큰 구조와 세부가 함께 있는 색 필드를 만든다.

```glsl
vec2 pixel = gl_FragCoord.xy - u_viewport.xy;
vec2 uv = pixel / u_viewport.zw;
vec2 p = uv * u_frequency;

float n = fbm(p);
vec3 color = mix(u_darkColor, u_lightColor, n);
```

시간에 따라 노이즈 질감이 화면을 흐르도록 하려면 좌표를 시간에 따라 이동시킨다.

다음 조각은 앞 예제의 `p`를 사용하며, `u_time`은 27.4에서 다룬 시간 유니폼이라고 가정한다.

```glsl
vec2 drift = vec2(u_time * 0.03, -u_time * 0.02);
float n = fbm(p + drift);
```

이 방식은 정지된 2D 노이즈 필드를 일정한 방향으로 이동해 샘플링한다. 프레임마다 해시 시드를 새로 바꾸면 연속적인 움직임 대신 값이 순간적으로 바뀌어 깜빡이므로, 시간은 노이즈 좌표에 연속적으로 넣는다. 시간 유니폼의 관리와 절대 시간·상태 갱신의 차이는 27.4, 시간 노이즈의 일반 원리는 14.6에서 다룬다.

다른 노이즈를 좌표에 더해 도메인을 휘게 만드는 방법도 있다.

이 예제의 `warpStrength`도 호스트가 전달하는 `uniform float` 매개변수다.

```glsl
vec2 warp = vec2(
    valueNoise(p + vec2(5.2, 1.3)),
    valueNoise(p + vec2(9.2, 7.1))
) - 0.5;

float warped = fbm(p + warp * warpStrength);
```

이때 `warpStrength`가 커지면 원래 좌표의 순서와 간격이 크게 휘어져 소용돌이나 유체 같은 형태가 나타난다. 하지만 좌표 변형은 노이즈 평가 횟수를 추가하므로, fBm 옥타브와 여러 워프 단계를 함께 늘리면 계산 비용이 빠르게 증가한다. 낮은 진폭과 적은 옥타브에서 시작해 결과를 확인한다.

## 화면 해상도와 계산 비용

프래그먼트 셰이더의 노이즈는 화면의 많은 위치에서 반복 계산된다. 해시 기반 Value Noise 한 번에도 여러 격자점 평가와 보간이 필요하고, fBm은 그 비용을 옥타브 수만큼 늘린다. 좌표 워핑이나 여러 색·마스크 필드까지 더하면 더 높은 비용이 든다. 노이즈가 메모리 없이 계산된다고 해서 텍스처보다 언제나 빠르지는 않다.

또한 화면 픽셀보다 작은 고주파 특징은 안정적으로 표시되지 않고 앨리어싱, 모아레, 시간에 따른 깜빡임을 만들 수 있다. 최종 출력 해상도에서 노이즈를 확인하고, 화면에 나타나지 않는 높은 옥타브를 줄인다. 필요하면 `fwidth`로 각 옥타브의 화면상 좌표 변화량을 추정해 픽셀보다 빠른 옥타브의 기여를 감쇠하거나, 미리 계산한 노이즈 텍스처에 밉맵을 사용한다. 노이즈가 정적이고 매 프레임 계산할 필요가 없다면 한 번 렌더링해 텍스처로 재사용할 수도 있다.

텍스처와 수식 계산은 서로 대체 관계가 아니다. 텍스처는 촬영 이미지나 미리 구운 고품질 필드를 저장해 샘플링하고, 프로시저럴 방식은 매개변수와 좌표로 변화 규칙을 제공한다. 저장 공간, 해상도 독립성, 반복 조절의 필요와 셰이더 계산량을 함께 고려해 선택한다. 이미지·데이터 텍스처의 샘플링은 26.7을 참고한다.

## 이 절의 핵심

GLSL에는 이식 가능한 표준 노이즈 알고리즘이 내장되어 있지 않으므로 해시와 보간으로 Value Noise를 구현하거나, 검증된 라이브러리·텍스처를 사용한다. 여러 주파수와 감소하는 진폭을 더하면 fBm을 만들 수 있고, 노이즈를 색·마스크·좌표에 연결해 프로시저럴 텍스처를 구성한다. 옥타브와 도메인 워핑은 계산 비용을 높이며, 화면 해상도보다 높은 세부는 앨리어싱을 일으킬 수 있다.
