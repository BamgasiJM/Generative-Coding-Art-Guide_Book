# 29.9 Blender Shader Nodes와 OSL의 역할 분담

Blender에서는 OSL을 별도의 렌더러처럼 사용하는 것이 아니라, Cycles의 재질 노드 그래프 안에 Script 노드로 넣는다. 노드는 재질의 연결과 표준 셰이딩 모델을 구성하고, OSL은 노드만으로 표현하기 번거로운 수학적 필드와 알고리즘을 계산한다. 이 절은 Blender 5.2를 기준으로 두 도구를 한 재질 안에서 나누어 사용하는 방법을 설명한다.

## OSL 실행 환경 준비

Blender에서 OSL Script 노드를 사용하려면 렌더 엔진을 Cycles로 설정하고 Render Properties의 Shading 항목에서 Open Shading Language를 활성화한다. 재현성 있는 기본 환경은 Cycles의 CPU 렌더링이다. Blender 5.2에서 일부 OptiX 환경의 제한적 지원을 접할 수 있더라도, 사용할 수 있는 기능은 장치와 빌드에 따라 다를 수 있다. CUDA, HIP, Metal을 포함한 모든 GPU 백엔드에서 같은 OSL 코드가 실행된다고 가정하지 말고, 작업물을 공유하거나 렌더 팜으로 보낼 때는 대상 환경을 확인한다. Eevee는 OSL Script 노드를 실행하지 않는다.

기본 작업 순서는 다음과 같다.

1. Render Properties에서 Cycles를 선택하고, OSL 실행 환경을 활성화한다.
2. Shader Editor에서 재질 노드 그래프에 Script 노드를 추가한다.
3. Script 노드를 Internal 또는 External 모드로 설정하고 OSL 소스를 지정한다.
4. 컴파일이 성공하면 셰이더 선언의 입력과 출력이 노드 소켓으로 나타난다.
5. 생성된 소켓을 다른 노드와 연결하고, 필요하면 소스 갱신 후 노드의 Update 기능으로 인터페이스를 다시 읽는다.

컴파일에 실패하면 기대한 소켓이 생성되지 않거나 갱신되지 않는다. 오류는 시스템 콘솔에 표시되므로, 노드가 비어 보일 때는 소스 문법과 함께 Blender를 실행한 터미널 또는 System Console을 확인한다.

## Script 노드의 소스와 소켓

Internal 모드는 Blender의 Text 데이터블록을 소스로 사용한다. 텍스트가 `.blend` 파일에 함께 저장되어 프로젝트를 다른 컴퓨터로 옮기기 편하다. External 모드는 디스크의 `.osl` 파일을 참조한다. 편집기에서 코드를 관리하고 여러 프로젝트에서 공유하기 편하지만, 파일 경로와 필요한 외부 리소스를 함께 배포해야 한다. Blender는 OSL 소스를 컴파일해 실행하며, 외부 파일을 사용하는 경우에도 원본 `.osl`을 프로젝트의 의존 파일로 관리하는 편이 안전하다.

셰이더의 파라미터 선언은 Script 노드의 인터페이스가 된다. 다음 예제는 좌표와 주파수를 입력받아 색 하나를 출력하는 데이터 계산 노드다.

```c
shader osl_palette(
    point Coord = point(0.0, 0.0, 0.0),
    float Frequency = 2.0,
    color Low = color(0.04, 0.12, 0.2),
    color High = color(0.92, 0.38, 0.12),
    output color Pattern = color(0.0))
{
    float n = noise("perlin", Coord * Frequency);
    float mask = clamp(n, 0.0, 1.0);
    Pattern = mix(Low, High, mask);
}
```

컴파일되면 `Coord`, `Frequency`, `Low`, `High`가 입력 소켓으로, `Pattern`이 출력 소켓으로 나타난다. `point` 입력은 노드 그래프에서 Vector 계열 소켓으로 다뤄지므로 Texture Coordinate나 Mapping 노드의 좌표를 넣을 수 있다. `Pattern`은 Color 출력을 갖는 일반 값이다. 예를 들어 이를 Principled BSDF의 Base Color에 연결하고 Principled BSDF의 Shader 출력을 Material Output의 Surface에 연결하면, OSL은 색 계산을 맡고 표준 노드는 재질 반응을 맡는다.

| OSL 선언 | Blender 노드 그래프에서의 역할 |
| --- | --- |
| `float`, `int`, `color` 입력·출력 | 호환되는 값 소켓으로 계산값을 전달 |
| `point`, `vector`, `normal` 입력·출력 | Vector 계열 소켓으로 위치나 방향 데이터를 전달 |
| `output closure color` | Shader 소켓으로 클로저를 전달해 Surface 등 셰이더 입력에 연결 |
| `string`, `matrix` 등 지원되지 않는 소켓형 | 일반 입력 소켓으로 노출되지 않을 수 있으므로 Blender 5.2의 지원 목록을 확인 |

소켓 이름과 기본값은 OSL 선언에서 온다. 따라서 파라미터를 추가·삭제하거나 자료형을 바꾸면 소스만 저장하는 데 그치지 말고 Script 노드의 인터페이스를 갱신해야 한다. 노드에 드러나지 않는 값은 코드 안의 기본값을 사용하므로, 그래프에서 조절할 값과 셰이더 내부에 고정할 값을 선언 단계에서 구분한다.

## 값 출력과 클로저 출력

Blender에서 OSL을 노드 그래프의 일부로 쓸 때는 일반 데이터 출력과 셰이더 클로저 출력을 구분한다. `output color`는 색 데이터이며, `output float`은 수치 데이터다. 이 출력들은 다른 노드의 호환되는 입력으로 이어진다. 반면 `output closure color`는 최종 픽셀의 RGB가 아니라 조명 계산에 사용할 재질 반응이므로 Shader 소켓으로 표시된다.

클로저 출력을 선언하는 서피스 셰이더는 OSL 안에서 재질의 빛 반응까지 직접 구성한다.

```c
shader osl_matte(
    color BaseColor = color(0.7, 0.75, 0.8),
    output closure color BSDF = 0)
{
    BSDF = diffuse(N) * BaseColor;
}
```

이 `BSDF`는 Blender의 Shader 소켓이므로 Material Output의 Surface에 직접 연결하거나 Mix Shader, Add Shader와 같은 셰이더 조합 노드에 연결할 수 있다. 반대로 색이나 마스크만 계산하는 Script 노드에서는 일반 값 출력을 사용해야 한다. 일반 `color`를 Surface에 직접 꽂을 수 있는 셰이더 클로저로 착각해서는 안 된다.

클로저 함수와 지원 범위는 OSL 문법만으로 결정되지 않는다. Blender에서 실행되는 코드는 Cycles가 구현한 클로저와 기능을 사용해야 하므로, Arnold나 RenderMan용 코드의 클로저 이름이 Cycles에서도 그대로 동작한다고 가정하지 않는다. Blender Script 노드는 서피스·볼륨·디스플레이스먼트 작업에 사용할 수 있지만, OSL 표준에 정의된 Light 셰이더를 Blender의 Light 오브젝트 대용으로 만들지는 못한다. 실제 Blender 노드 네트워크에서의 역할 차이는 29.2의 셰이더 구분과 연결해 이해한다.

## Shader Nodes와 OSL에 맡길 일

노드 그래프는 데이터 흐름을 눈으로 살피고 재질을 조립하는 데 강하다. Texture Coordinate, Mapping, Image Texture, Principled BSDF, Mix Shader, Material Output 같은 노드는 좌표 공급, 이미지 샘플링, 표준 재질과 클로저 조합을 담당한다. OSL은 복잡한 수식, 반복 계산, 사용자 정의 패턴, SDF 마스크처럼 노드만으로 표현하면 연결이 길어지는 계산을 한 Script 노드로 캡슐화할 때 유용하다.

| 작업 | 우선 사용할 도구 | 이유 |
| --- | --- | --- |
| 좌표·텍스처·색상 연결을 시각적으로 조절 | Shader Nodes | 연결 관계와 매개변수를 즉시 읽고 바꾸기 쉽다. |
| Principled 재질과 표준 반사·투명·방출 조합 | Shader Nodes | Blender의 표준 셰이딩 모델과 입력을 그대로 활용한다. |
| 반복문이나 사용자 정의 수학으로 색·마스크 계산 | OSL Script 노드 | 절차를 코드로 간결하게 표현하고 재사용할 수 있다. |
| 여러 셰이더 클로저의 조합 | Shader Nodes 또는 OSL | 노드에서 조합을 조절할지, 코드에서 재질 규칙까지 고정할지에 따라 선택한다. |
| 메시 생성·인스턴싱·기하 처리 | Geometry Nodes 등 기하 도구 | OSL Script 노드는 기하 노드나 범용 GPU 컴퓨트 셰이더가 아니다. |

실용적인 구성은 OSL이 좌표에서 패턴·마스크·색 같은 계산값을 만들고, Shader Nodes가 그 값을 Principled BSDF의 색·거칠기 또는 셰이더 혼합에 연결하는 방식이다. 복잡한 색 함수는 코드 안에서 관리하되, 최종 재질의 물리적 파라미터는 노드에서 노출하면 아티스트가 조명과 재질을 함께 조절하기 쉽다. 반대로 특정 재질 반응 전체를 알고리즘으로 정의하고 싶다면 OSL에서 클로저를 출력할 수 있다.

이 분업은 결과의 이식성에도 영향을 준다. Blender 전용 노드 네트워크는 Blender 안에서 읽고 수정하기 쉽고, OSL은 코드로 규칙을 명시해 재사용하기 좋지만 실행기는 여전히 렌더러에 의존한다. OSL 노드 하나를 복사한다고 해서 모든 렌더러에서 같은 클로저·텍스처 함수·성능이 보장되지는 않는다. 공유할 때는 Blender 버전, Cycles 설정, OSL 소스, 연결된 이미지와 좌표 입력을 함께 점검한다.

## 이 절의 핵심

Blender 5.2에서 OSL은 Cycles Shader Editor의 Script 노드로 노드 그래프에 들어간다. 일반 `float`·`color` 출력은 계산 데이터를 다음 노드에 전달하고, `closure color` 출력은 조명 계산에 사용할 Shader 값을 전달한다. 노드 그래프는 좌표와 표준 재질의 연결·조합을 맡기고, OSL은 복잡한 절차적 계산을 맡기면 서로의 장점을 살릴 수 있다. 실행 환경은 Cycles와 장치 지원에 좌우되므로 안정적인 기본값은 CPU로 확인하고, OptiX 등 GPU 경로는 Blender 5.2 빌드와 사용 함수의 제한을 별도로 점검한다.
