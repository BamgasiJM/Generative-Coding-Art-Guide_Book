# 29.4 실수, 색, 벡터, 노멀, 클로저

OSL에서 여러 값이 숫자 세 개로 보이더라도 자료형의 의미는 같지 않다. 색을 나타내는 `color`, 위치를 나타내는 `point`, 방향을 나타내는 `vector`, 표면의 수직 방향을 나타내는 `normal`은 서로 다른 계산과 변환 규칙을 갖는다. 또 `closure color`는 RGB 색 자체가 아니라 렌더러가 표면의 빛 반응을 해석하도록 전달하는 표현이다.

## 실수: 필드와 재질 매개변수

`float`는 주파수, 거칠기, 마스크, 강도처럼 하나의 수치가 필요한 곳에 쓴다. 거리 함수나 파동의 결과를 계산한 뒤 `clamp`나 `mix`로 재질이 기대하는 범위에 맞출 수 있다.

```c
float raw = 0.5 + 0.5 * sin(P[0] * frequency);
float mask = clamp(raw, 0.0, 1.0);
float roughness = mix(0.08, 0.85, mask);
```

언어 차원에서 실수는 특정 재질 범위에 자동으로 제한되지 않는다. 예를 들어 `roughness` 입력이 일반적으로 $[0,1]$ 범위에서 의미를 갖더라도, 함수 계산이 그 밖의 값을 만들 수 있다. 렌더러가 값을 잘라 주리라 기대하지 말고, 의도한 범위를 셰이더에서 정하거나 대상 재질 노드의 규칙을 확인한다. 반대로 방출 강도처럼 1보다 큰 값이 유효한 입력도 있으므로 모든 실수를 일괄적으로 $[0,1]$에 고정해서는 안 된다.

## 색: 세 성분의 색값

`color`는 RGB 세 성분을 갖는 OSL의 색 자료형이다. 색끼리의 덧셈과 곱셈은 대체로 성분별 연산이며, 스칼라와 곱하면 밝기나 기여량을 조절할 수 있다. 스칼라 마스크로 두 색을 보간하면 절차적 무늬를 팔레트에 연결하기 쉽다.

```c
color dark = color(0.025, 0.08, 0.16);
color light = color(0.95, 0.48, 0.12);
color pigment = mix(dark, light, mask);
```

`color`는 알파를 포함하지 않는다. 투명도나 마스크가 필요하다면 별도의 `float` 출력이나 렌더러가 정의한 재질 입력을 사용한다. 또한 `color` 타입만으로 sRGB, ACEScg 같은 색 공간이 지정되는 것은 아니다. 텍스처를 불러올 때의 색 변환과 셰이더의 숫자가 어떤 작업 색 공간에서 해석되는지는 렌더러와 호스트 설정에 달려 있다. 디스플레이용 색을 셰이더 안에서 임의로 감마 변환하면 렌더러의 색 관리와 중복될 수 있다.

## 점, 벡터, 노멀은 서로 바꿔 쓸 수 없다

`point`는 위치, `vector`는 방향이나 위치 사이의 변위, `normal`은 표면에 수직인 방향을 나타낸다. 세 타입 모두 세 성분을 갖지만, 타입을 통해 연산의 의미와 변환 규칙을 드러낸다.

| 자료형 | 나타내는 것 | 대표 연산 |
| --- | --- | --- |
| `point` | 공간상의 위치 | 두 점의 차이로 변위 벡터 계산 |
| `vector` | 방향·속도·변위 | 내적, 외적, 길이, 정규화 |
| `normal` | 표면의 수직 방향 | 조명 방향과 비교, 좌표계 변환 후 정규화 |

예를 들어 광원 위치와 표면 위치의 차이는 방향 벡터이고, 셰이딩 노멀은 조명 계산 전에 정규화해야 한다.
다음 셰이더는 광원 위치를 입력받아 셰이딩 노멀과의 내적을 계산해 표면이 광원을 향하는 정도를 스칼라로 출력한다.

```c
shader normal_facing(
    point light_position = point(0.0, 4.0, 2.0),
    output float facing = 0.0)
{
    vector to_light = normalize(light_position - P);
    normal shading_normal = normalize(N);
    facing = max(0.0, dot(shading_normal, to_light));
}
```

OSL의 `N`은 셰이딩 노멀, `Ng`는 기하 노멀을 나타낸다. 노멀 맵이나 범프 처리로 `N`을 바꾸어도 실제 표면 기하와 광선 교차를 정의하는 `Ng`는 같은 방식으로 변하지 않는다. 표면 방향을 시각화하거나 양면 처리, 변위 결과를 점검할 때 두 노멀을 구분하면 원인을 찾기 쉽다.

좌표 공간을 바꿀 때도 타입이 중요하다. 점의 변환에는 평행 이동이 포함되지만 벡터에는 포함되지 않는다. 노멀은 비균일 스케일 아래에서 수직성을 보존하기 위해 일반 벡터와 다른 변환을 거친다. OSL의 `transform()`에 실제 의미에 맞는 타입을 전달해야 하며, 공간 선택과 변환 예시는 29.3에서 다루었다.

## 클로저: 색이 아니라 빛 반응의 표현

클로저는 렌더러가 표면에서 빛을 어떻게 산란하거나 방출할지를 나타낸다. `closure color` 출력은 `color` 값과 이름에 `color`가 들어가지만, 화면에 기록할 RGB 삼중항은 아니다. 렌더러가 클로저를 샘플링하고 조명 계산에 결합해 최종 픽셀 색을 만든다.

클로저는 다른 클로저와 더해 여러 산란 성분을 구성할 수 있고, 색이나 실수값을 곱해 그 성분의 색과 기여량을 조절할 수 있다. 다음 예제는 마스크에 따라 확산 반사와 발광의 비중을 바꾼다.

```c
shader matte_or_glow(
    color albedo = color(0.7, 0.75, 0.8),
    color glow_color = color(1.0, 0.25, 0.05),
    float glow_mask = 0.0,
    output closure color BSDF = 0)
{
    float m = clamp(glow_mask, 0.0, 1.0);
    BSDF = diffuse(N) * albedo * (1.0 - m)
         + emission() * glow_color * m;
}
```

이 코드는 렌더러가 `diffuse`와 `emission` 클로저를 제공한다고 가정한다. 클로저 함수의 이름과 지원 범위는 OSL 문법만으로 정해지지 않으므로 대상 렌더러의 문서를 확인한다. `m`은 두 성분의 가중치를 바꾸지만, 임의의 가중치 조합이 에너지 보존을 자동으로 보장하지는 않는다. 반사 성분을 물리적으로 섞어야 한다면 렌더러의 표준 재질 모델이나 에너지 보존 규칙을 고려한다.

클로저의 덧셈은 화면 색을 단순히 더하거나 알파 블렌딩하는 연산과 다르다. 여러 빛 반응을 렌더러에 기술하는 조합이다. 한 표면 위에서 두 재질이 층을 이루는 효과를 만들 때는 단순한 클로저 합만으로 층의 차폐와 상호작용이 자동 표현되지 않는다. 원하는 현상이 표면 로브의 합인지, 재질 레이어링인지 구분하고 그에 맞는 렌더러 기능을 선택한다.

## 자료형을 선택하는 간단한 기준

1. 밝기, 거칠기, 빈도, 마스크처럼 수치 하나가 필요하면 `float`를 쓴다.
2. 팔레트나 베이스 컬러처럼 RGB 값을 다룰 때는 `color`를 쓴다.
3. 위치 계산에는 `point`, 방향과 변위에는 `vector`를 쓴다.
4. 표면의 수직 방향은 `normal`로 표현하고, 노멀 연산 뒤 정규화한다.
5. 렌더러의 조명 계산에 재질 반응을 넘길 때는 `closure color` 출력을 사용한다.

OSL에서는 올바른 자료형을 선택하는 것이 단지 선언을 맞추는 일이 아니다. 좌표 변환, 기하 관계, 색 연산, 렌더러의 조명 해석이 의도대로 이어지게 만드는 계약이다. 특히 색·벡터·노멀·클로저를 모두 “세 숫자”로 취급하지 않는 것이 재질 셰이더를 안정적으로 구성하는 출발점이다.

## 이 절의 핵심

`float`는 수치 필드와 매개변수, `color`는 RGB 색, `point`는 위치, `vector`는 방향과 변위, `normal`은 표면의 수직 방향을 나타낸다. `closure color`는 픽셀 색이 아니라 렌더러가 조명 계산에 사용할 표면 반응이다. 자료형에 맞는 연산과 변환을 선택하고, 클로저의 지원 범위와 의미는 사용하는 렌더러에서 확인한다.
