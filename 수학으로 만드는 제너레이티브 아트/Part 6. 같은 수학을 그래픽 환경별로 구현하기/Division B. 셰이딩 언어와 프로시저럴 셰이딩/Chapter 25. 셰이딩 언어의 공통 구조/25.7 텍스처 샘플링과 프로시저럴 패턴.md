# 25.7 텍스처 샘플링과 프로시저럴 패턴

셰이더가 색이나 값을 얻는 방법은 크게 두 가지다. 하나는 이미지·렌더 타깃·데이터 버퍼처럼 이미 저장된 값을 텍스처에서 읽는 방법이고, 다른 하나는 현재 좌표를 수식에 넣어 즉시 값을 계산하는 프로시저럴(procedural) 방법이다. 둘은 경쟁하는 기술이 아니다. 텍스처는 구체적인 이미지와 이전 계산 결과를 가져오고, 프로시저럴 함수는 해상도와 좌표에 반응하는 규칙을 만든다. 실제 작업에서는 두 방식을 마스크, 좌표 변형, 색상 보정으로 자주 결합한다.

## 텍스처는 좌표에서 값을 읽는 필드다

2D 텍스처는 색 또는 숫자 값이 격자로 저장된 데이터다. 셰이더는 보통 UV 좌표 $(u,v)$로 텍스처의 어느 위치를 읽을지 지정한다.

$$
\mathbf{C}(u,v)=T(u,v)
$$

```glsl
uniform sampler2D imageTexture;

vec4 sampled = texture(imageTexture, uv);
vec3 color = sampled.rgb;
```

GLSL의 `texture()`는 개념적으로 `T(u,v)`를 평가하는 함수다. UV는 대개 $[0,1]$ 범위를 사용하며, $(0,0)$과 $(1,1)$이 텍스처의 양 끝을 가리킨다. 정확한 원점 방향은 이미지 로딩 방식, API, 텍스처 좌표 관례에 따라 달라질 수 있으므로, 글자나 방향성 있는 이미지를 사용해 한 번 확인하는 편이 좋다.

텍스처에는 사진만 들어가는 것이 아니다. 노이즈를 미리 구운 이미지, 이전 프레임의 렌더 결과, 깊이 맵, 법선 맵, 입자 상태를 담은 데이터 텍스처, 카메라 영상도 텍스처로 표본화할 수 있다. 즉 텍스처는 색상이면서 동시에 셰이더가 읽을 수 있는 2차원 또는 3차원 데이터 필드다.

## 샘플링과 필터링

UV 좌표는 연속 실수지만 텍스처의 텍셀(texel)은 이산 격자다. 텍스처 샘플러는 좌표가 텍셀 사이에 있을 때 어떤 값을 돌려줄지 결정한다. 가장 흔한 선택은 최근접 샘플링과 선형 필터링이다.

| 방식 | 동작 | 시각적 성격 | 적합한 대상 |
| --- | --- | --- | --- |
| 최근접(nearest) | 가장 가까운 텍셀 하나를 읽음 | 선명한 계단, 픽셀 형태 | 픽셀 아트, 셀 상태, ID 맵 |
| 선형(linear) | 주변 텍셀을 보간함 | 부드러운 확대·축소 | 사진, 색 필드, 흐림 효과 |
| 밉맵 필터링 | 축소 비율에 맞는 저해상도 레벨을 읽음 | 축소 시 깜빡임 감소 | 반복 재질, 먼 표면 |

```glsl
// 샘플러의 필터링 설정에 따라 결과가 달라진다.
vec4 c = texture(imageTexture, uv);
```

셰이더 코드가 같아도 텍스처 객체의 필터링 설정이 다르면 결과가 달라진다. 선형 필터링은 인접한 색을 섞으므로 부드럽지만, 상태를 정확한 범주로 저장한 텍스처에는 부적합할 수 있다. 예를 들어 셀룰러 오토마타의 0과 1 상태를 선형 필터링으로 읽으면 중간값이 생겨 규칙의 의미가 바뀐다. 이 경우 최근접 샘플링이 맞다.

반대로 작은 텍스처를 크게 확대할 때 최근접 샘플링은 의도적인 픽셀 격자를 드러내고, 선형 필터링은 흐린 이미지를 만든다. 어느 것이 "더 좋은" 것이 아니라 표본값을 이산 기호로 볼지, 연속 필드로 볼지에 대한 선택이다.

## 래핑: 범위 밖 좌표의 처리

UV가 $[0,1]$ 범위를 벗어날 때 샘플러가 무엇을 할지도 설정할 수 있다. 대표적인 래핑 모드는 반복(repeat), 가장자리 고정(clamp), 거울 반복(mirrored repeat)이다.

```glsl
vec2 tiledUV = uv * repeatCount;
vec4 color = texture(imageTexture, tiledUV);
```

| 래핑 방식 | 범위 밖 좌표의 처리 | 활용 예 |
| --- | --- | --- |
| Repeat | 1 단위마다 같은 텍스처 반복 | 타일, 직물, 격자 패턴 |
| Clamp to edge | 가장자리 텍셀 값을 계속 사용 | 화면 후처리, 가장자리 번짐 방지 |
| Mirrored repeat | 반복마다 좌우·상하 반사 | 이음새가 덜 드러나는 반복 질감 |

반복 텍스처의 이음새는 이미지의 왼쪽·오른쪽, 위·아래 경계가 이어지지 않을 때 생긴다. 프로시저럴 타일링은 `fract`로 좌표를 직접 반복하므로, 단위 패턴의 경계를 수식으로 설계할 수 있다는 장점이 있다. 이미지 텍스처를 반복할 때는 처음부터 타일 가능하게 만든 소스를 사용하거나, 거울 반복과 경계 혼합을 고려한다.

## 밉맵과 축소 표본화

표면이 카메라에서 멀어지거나 비스듬해지면, 화면의 한 픽셀이 텍스처의 넓은 영역을 대표하게 된다. 원본 텍스처의 고주파 세부를 그대로 한 점에서 읽으면 작은 무늬가 깜빡이거나 모아레가 생긴다. 밉맵(mipmap)은 원본 텍스처를 절반 크기씩 줄인 여러 해상도 단계로 저장해, 축소 상황에 맞는 수준의 정보를 읽게 하는 방법이다.

```text
original texture
    -> half resolution texture
    -> quarter resolution texture
    -> ...
```

GPU는 표면에서 UV가 얼마나 빠르게 변하는지 보고 적절한 밉 레벨을 고른다. 이 과정은 멀리 있는 벽의 벽돌무늬나 반복 타일이 안정적으로 보이도록 돕는다. 절차적 패턴도 고주파 줄무늬와 작은 셀을 만들면 같은 표본화 문제가 생긴다. 텍스처에는 밉맵이 자동으로 제공될 수 있지만, 수식 패턴에는 `fwidth`를 이용한 안티앨리어싱이나 주파수 제한이 필요할 수 있다.

## 프로시저럴 패턴: 저장하지 않고 계산하기

프로시저럴 패턴은 텍스처에서 값을 읽지 않고, 좌표와 파라미터에서 직접 값을 계산한다. 줄무늬, 체커보드, 도트, 거리 필드, 노이즈, 방사형 파동은 모두 이런 방식으로 만들 수 있다.

```glsl
float stripes(vec2 p, float frequency) {
  return 0.5 + 0.5 * sin(p.x * frequency);
}

float checker(vec2 p, float count) {
  vec2 cell = floor(p * count);
  return mod(cell.x + cell.y, 2.0);
}
```

프로시저럴 방식의 강점은 해상도 독립성, 조절 가능한 파라미터, 좌표 변형과의 결합이다. 원의 반지름, 격자 수, 노이즈 주파수, 색상 팔레트를 유니폼으로 바꾸면 같은 규칙에서 다양한 결과를 얻는다. 표면에 큰 이미지를 저장하지 않아도 되며, 월드 공간 3D 노이즈처럼 UV 이음새를 피하는 패턴도 만들 수 있다.

하지만 모든 패턴을 수식으로 만드는 것이 바람직한 것은 아니다. 사진, 손으로 그린 질감, 문자, 복잡한 스캔 데이터처럼 특정한 시각 정보는 텍스처가 자연스럽다. 또한 높은 옥타브의 노이즈, 복잡한 반복 루프, 다수의 거리 함수 조합은 계산 비용이 커질 수 있다. 필요하면 프로시저럴 결과를 한 번 텍스처에 렌더링해 캐시하는 하이브리드 방식도 쓴다.

## 좌표 변형으로 텍스처와 패턴을 바꾸기

텍스처와 프로시저럴 함수는 모두 좌표를 입력으로 받는다. 따라서 값을 읽거나 계산하기 전에 좌표를 변형하면 이미지와 패턴을 같은 방식으로 왜곡할 수 있다.

```glsl
vec2 q = uv - 0.5;
q = rotate(q, angle);
q += warp(q) * warpStrength;
q += 0.5;

vec4 imageColor = texture(imageTexture, q);
float patternValue = noise(q * frequency);
```

이 예제에서 `q`는 회전과 왜곡을 거친 공통 좌표다. 텍스처와 노이즈가 같은 좌표를 쓰므로, 사진 위의 색 변화와 절차적 패턴이 함께 흐르는 느낌을 만들 수 있다. 반대로 한 요소에는 원래 UV를, 다른 요소에는 변형 UV를 쓰면 의도적인 어긋남과 대비를 만들 수 있다.

좌표를 앞으로 이동시켜 이미지를 그리는 대신, 현재 출력 위치에서 어느 입력 좌표를 읽을지 계산하는 역매핑을 사용한다는 점도 중요하다. `texture(imageTexture, q)`는 현재 픽셀에 어떤 텍스처 위치를 가져올지 묻는 코드다. 이 방식은 픽셀 사이에 빈틈이 생기지 않고, 셰이더의 위치별 평가와 잘 맞는다.

## 텍스처와 프로시저럴 필드의 결합

두 방식은 서로의 약점을 보완한다. 이미지 텍스처에서 큰 구조나 구체적인 소재를 얻고, 프로시저럴 필드로 변형·마스크·색상 변화·미세한 결을 더할 수 있다.

```glsl
vec3 photo = texture(imageTexture, uv).rgb;
float grain = noise(uv * grainFrequency);
float vignette = smoothstep(outerRadius, innerRadius, length(uv - 0.5));

vec3 color = photo * mix(0.9, 1.1, grain);
color *= vignette;
```

거리 필드 마스크로 텍스처를 자르면 사진이나 영상이 수식으로 만든 도형 안에만 나타난다. 노이즈로 UV를 흔들면 이미지를 유체처럼 왜곡할 수 있다. 텍스처의 밝기를 밀도 필드로 읽어 입자 발생 확률을 정하고, 그 입자 위에 프로시저럴 색을 입힐 수도 있다.

```text
texture luminance -> density or mask
procedural noise -> coordinate warp
SDF -> visible region
palette function -> final color mapping
```

이처럼 텍스처를 완성된 그림으로만 보지 않고, 셰이더가 읽는 숫자 필드로 보면 결합 가능성이 넓어진다.

## 텍스처 색 공간과 데이터 텍스처

색상 이미지 텍스처는 보통 sRGB로 저장되며, 렌더링 시스템은 표본화할 때 선형 공간으로 변환하도록 설정할 수 있다. 반면 위치, 법선, 깊이, 마스크, 시뮬레이션 상태처럼 색 자체가 아닌 데이터를 저장한 텍스처는 값이 임의로 색 보정되지 않아야 한다. 이를 데이터 텍스처로 취급한다.

```text
color texture: sRGB decode may be appropriate
data texture: preserve numeric values exactly
```

예를 들어 법선 벡터를 RGB 채널에 저장한 노멀 맵을 sRGB 색상으로 읽으면 방향 값이 왜곡될 수 있다. 이전 프레임의 속도나 반응-확산 농도를 저장한 텍스처도 마찬가지다. 텍스처가 이미지인지 데이터인지 구분하는 습관은 셰이더의 예기치 않은 색·움직임 오류를 줄인다.

## 선택 기준

텍스처와 프로시저럴 패턴 가운데 하나만 골라야 하는 경우는 드물다. 다음 기준은 출발점으로 쓸 수 있다.

| 요구 | 우선 고려할 방법 |
| --- | --- |
| 사진·그림·영상처럼 구체적인 이미지 | 텍스처 표본화 |
| 반지름·주파수·대칭을 즉시 조절할 패턴 | 프로시저럴 함수 |
| 여러 물체에 이어지는 3D 질감 | 오브젝트·월드 공간 프로시저럴 필드 |
| 이전 프레임·깊이·시뮬레이션 값 | 데이터 텍스처 또는 버퍼 |
| 반복 재질의 축소 안정성 | 밉맵을 가진 텍스처 또는 주파수 제한 함수 |
| 이미지와 수학적 변형을 함께 사용 | 공통 좌표 변형 후 결합 |

## 이 절의 핵심

텍스처 샘플링은 저장된 이미지·버퍼에서 좌표로 값을 읽는 방식이고, 프로시저럴 패턴은 좌표와 파라미터에서 값을 직접 계산하는 방식이다. 필터링·래핑·밉맵은 텍스처 표본의 성격을 바꾸며, 프로시저럴 패턴도 픽셀 표본화 한계를 고려해야 한다. 두 방식을 공통 좌표 변형, 거리 마스크, 노이즈, 색상 함수로 결합하면 저장된 이미지와 수학적 규칙을 하나의 셰이더 안에서 유연하게 다룰 수 있다.
