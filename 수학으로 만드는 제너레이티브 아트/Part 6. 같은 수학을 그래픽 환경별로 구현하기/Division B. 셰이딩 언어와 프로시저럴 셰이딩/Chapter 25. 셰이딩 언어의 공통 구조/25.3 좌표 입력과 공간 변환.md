# 25.3 좌표 입력과 공간 변환

셰이더에서 가장 중요한 입력은 대개 좌표다. 거리 함수, 노이즈, 타일링, 극좌표, 조명, 텍스처 표본화는 모두 "어디에서 값을 평가하는가"에 따라 결과가 달라진다. 같은 사인파 식도 화면 좌표에 적용하면 화면을 가로지르는 줄무늬가 되고, 물체의 로컬 좌표에 적용하면 물체 표면에 붙는 줄무늬가 되며, 월드 좌표에 적용하면 여러 물체를 관통하는 공간 패턴이 된다.

셰이더 작업에서 좌표 변환은 단순히 도형을 화면 중앙으로 옮기는 과정이 아니다. 어떤 기준에서 규칙을 정의하고, 그 규칙이 카메라·물체·표면과 어떤 관계를 가질지 결정하는 일이다.

## 좌표 공간의 지도

3D 그래픽의 정점은 대개 메시가 정의된 로컬 공간에서 시작한다. 행렬 변환을 거치면서 월드 공간, 카메라 기준의 뷰 공간, 투영을 위한 클립 공간으로 옮겨 간다. 이후 나눗셈과 뷰포트 변환을 거쳐 화면 좌표가 된다.

$$
\mathbf{p}_{clip}=P\,V\,M\,\mathbf{p}_{local}
$$

| 공간 | 기준 | 주된 용도 | 좌표가 함께 움직이는 대상 |
| --- | --- | --- |
| 로컬/오브젝트 공간 | 메시 자체의 원점 | 기하 변형, 물체에 고정된 패턴 | 물체 |
| 월드 공간 | 장면 전체의 공통 원점 | 여러 물체를 잇는 필드, 공간 효과 | 장면 |
| 뷰/카메라 공간 | 카메라 | 카메라 거리, 시선 관련 계산 | 카메라 |
| 클립 공간 | 투영 직후의 동차 좌표 | 화면에 보일 영역 결정 | 렌더 파이프라인 |
| 화면 공간 | 프레임 버퍼의 픽셀 | 후처리, UI, 화면 효과 | 화면 |
| UV 공간 | 표면에 펼친 2D 좌표 | 텍스처, 표면 타일, 이미지 패턴 | UV 펼침 |

여기서 $M$은 모델 행렬, $V$는 뷰 행렬, $P$는 프로젝션 행렬이다. 정점 위치는 보통 동차 좌표 $(x,y,z,1)$로 행렬과 곱한다. 마지막 성분 $w$는 원근 투영과 변환 조합에 필요하며, 이후 정규화된 장치 좌표를 얻을 때 x, y, z를 $w$로 나눈다.

```glsl
vec4 world = modelMatrix * vec4(localPosition, 1.0);
vec4 view = viewMatrix * world;
vec4 clip = projectionMatrix * view;
gl_Position = clip;
```

이 코드는 버텍스 셰이더의 전형적인 흐름이다. 많은 프레임워크가 모델·뷰·프로젝션 행렬을 자동으로 제공하므로 직접 행렬을 보지 못할 수 있지만, 패턴과 변형을 어느 공간에서 계산하는지 판단하려면 이 흐름을 이해해야 한다.

## 로컬 공간: 물체와 함께 움직이는 규칙

로컬 공간은 메시가 만들어진 기준 좌표계다. 원점 근처에 놓인 정점으로 정의한 큐브를 회전하고 이동해도, 로컬 좌표 자체는 바뀌지 않는다. 따라서 로컬 위치로 노이즈나 줄무늬를 평가하면 재질과 변형이 물체에 붙어 있는 것처럼 보인다.

```glsl
float stripe = sin(localPosition.y * frequency);
```

이 식에서 물체를 월드 공간에서 움직여도 줄무늬는 표면 위의 같은 자리에 남는다. 캐릭터의 피부 무늬, 회전하는 조각의 절차적 재질, 개별 인스턴스마다 다른 로컬 변위에 적합하다. 반면 서로 다른 물체에 적용하면 각 물체의 원점에서 패턴이 다시 시작될 수 있다.

로컬 공간의 크기와 축 방향은 메시 제작 방식에 의존한다. 어떤 모델은 높이가 1인 단위 크기로 만들어지고, 어떤 모델은 수백 또는 수천 단위를 쓸 수 있다. 절차적 패턴의 주파수를 모델마다 맞추려면 바운딩 박스 크기나 별도의 스케일 유니폼으로 정규화할 수 있다.

$$
\mathbf{p}_{normalized}=\frac{\mathbf{p}_{local}-\mathbf{b}_{min}}{\mathbf{b}_{max}-\mathbf{b}_{min}}
$$

## 월드 공간: 장면 전체를 가로지르는 규칙

월드 공간은 장면의 모든 물체가 공유하는 좌표계다. 월드 위치를 입력으로 쓰면 서로 다른 메시에도 하나의 연속적인 필드를 적용할 수 있다.

```glsl
float fog = noise(worldPosition * fogFrequency);
```

바닥과 조각상에 같은 노이즈를 적용했을 때 얼룩이 경계에서 이어지게 하려면 월드 공간이 적합하다. 안개, 높이에 따른 색 변화, 큰 규모의 줄무늬, 여러 오브젝트를 통과하는 거리 필드도 같은 방식으로 만든다.

대신 물체가 움직이면 물체가 패턴을 통과하는 것처럼 보인다. 월드 공간의 대리석 무늬 속에서 물체를 이동하면 표면 무늬가 미끄러지는 결과가 나오는 이유다. 이는 오류가 아니라 좌표 선택의 결과다. 공간을 채우는 안개라면 자연스럽지만, 물체에 칠한 페인트라면 로컬 또는 UV 공간이 더 맞다.

## 뷰와 화면 공간: 카메라에 붙는 규칙

뷰 공간은 카메라를 원점으로 보는 좌표계다. 카메라와의 거리, 시선 방향, 깊이에 따라 달라지는 효과에 유용하다. 예를 들어 먼 물체일수록 안개색으로 섞거나, 카메라 방향과 법선의 각도로 프레넬 효과를 계산할 수 있다.

$$
t=\operatorname{clamp}\left(\frac{z_{view}-z_{near}}{z_{far}-z_{near}},0,1\right)
$$

화면 공간은 최종 프레임 버퍼 기준의 좌표다. 프래그먼트 위치를 해상도로 나누면 보통 $[0,1]$ 범위의 UV 같은 좌표를 만들 수 있다.

```glsl
vec2 uv = fragmentPosition / resolution;
vec2 p = uv - 0.5;
p.x *= resolution.x / resolution.y;
```

화면 공간 규칙은 비네트, 필름 그레인, 색 보정, 전체 화면 SDF, 블러처럼 카메라 영상 자체에 적용하는 효과에 적합하다. 카메라가 움직여도 패턴은 화면에 고정된다. 반대로 3D 물체의 표면에 무늬를 만들고 싶은데 화면 공간을 쓰면, 카메라가 움직일 때 무늬가 표면 위를 미끄러지는 것처럼 보인다.

## UV 공간: 표면에 펼친 2D 도메인

UV 좌표는 3D 표면의 각 점에 대응하는 2D 좌표 $(u,v)$다. 텍스처 이미지의 어느 위치를 읽을지 지정하는 데 쓰이며, 2D에서 배운 반복·거리·극좌표·노이즈 함수를 표면 재질로 가져오는 가장 직접적인 통로다.

```glsl
vec2 tiledUV = fract(uv * tileCount);
float d = length(tiledUV - 0.5) - radius;
```

UV 공간에서 도트와 체커보드를 만들면 표면의 형태가 복잡해도 같은 2D 규칙을 적용할 수 있다. 그러나 UV는 모델을 자르고 펼쳐 만든 지도이므로, 이음새(seam)에서 값이 끊기고 표면에 따라 패턴이 늘어나거나 압축될 수 있다. 구의 극점, 유기적인 메시, 불균일한 UV 펼침에서는 특히 이 문제가 눈에 띈다.

반복 횟수가 높은 패턴은 이음새와 왜곡을 더 드러낼 수 있다. 표면 전체에 자연스럽게 이어지는 질감이 목적이라면 3D 오브젝트 공간 또는 월드 공간 노이즈를 사용하거나, 삼중 평면(triplanar) 표본화처럼 여러 축의 투영을 섞는 방법을 고려할 수 있다.

## 좌표를 정규화하고 중심에 맞추기

어느 공간을 선택했든, 그 좌표의 범위와 단위를 알고 있어야 한다. UV는 보통 $[0,1]$이지만 화면 중심에서의 거리나 회전을 계산하려면 중심을 원점으로 옮긴다.

$$
\mathbf{p}=\mathbf{uv}-\frac{1}{2}
$$

직사각형 화면에서는 x축에 종횡비를 곱해 원형 거리와 각도를 보정한다.

$$
p_x\leftarrow p_x\frac{W}{H}
$$

```glsl
vec2 p = uv - 0.5;
p.x *= resolution.x / resolution.y;
float radius = length(p);
float angle = atan(p.y, p.x);
```

이 작은 정규화 과정이 없으면 거리 함수의 원이 타원처럼 보이고, 방사형 파동과 회전 대칭도 찌그러질 수 있다. 화면 공간에서 쓰던 함수를 UV나 로컬 공간으로 옮길 때는 단순히 변수 이름만 바꾸지 말고, 입력 범위와 축 비율을 다시 확인한다.

## 좌표 변형은 평가 전에 적용한다

이 책의 Part 3에서 다룬 이동, 회전, 확대, 반복, 대칭 접기는 셰이더에서도 같은 방식으로 쓴다. 중요한 원칙은 도형이나 색을 변형하는 대신, 값을 평가할 좌표를 먼저 변형한다는 점이다.

$$
F'(\mathbf{p})=F\left(T^{-1}\mathbf{p}\right)
$$

```glsl
vec2 q = p;
q = rotate(q, -angle);
q -= offset;
float value = pattern(q);
```

역변환을 쓰면 출력 위치마다 원래 패턴의 어느 위치를 읽어야 하는지 계산할 수 있다. 화면의 픽셀을 앞으로 밀어내는 방식보다 빈틈이 생기지 않으며, 셰이더의 위치 기반 함수와 잘 맞는다. 타일링에는 `fract`, 거울 대칭에는 `abs`, 방사형 대칭에는 각도 접기를 적용한 뒤 패턴 함수를 평가한다.

## 여러 공간을 함께 사용하기

하나의 셰이더가 한 좌표 공간만 사용해야 하는 것은 아니다. 예를 들어 표면의 기본 색은 UV의 타일 패턴으로 만들고, 큰 규모의 색 변화는 월드 공간 노이즈로 더하며, 가장자리 반사는 뷰 공간의 관찰 방향으로 계산할 수 있다.

```text
UV space: 작은 반복 무늬
object or world space: 큰 노이즈 변화
view space: 카메라 거리와 프레넬 효과
screen space: 최종 색 보정과 비네트
```

이 조합은 재질에 서로 다른 스케일과 기준을 부여한다. 다만 공간을 섞을수록 어떤 값이 무엇에 고정되어 있는지 추적하기 어려워진다. 변수 이름에 `localPosition`, `worldPosition`, `screenUV`처럼 공간을 드러내고, 변환 직후의 좌표를 재사용하면 실수를 줄일 수 있다.

## 이 절의 핵심

셰이더의 패턴과 변형은 어떤 좌표 공간을 입력으로 쓰는지에 따라 의미가 달라진다. 로컬 공간은 물체에 붙는 규칙, 월드 공간은 장면 전체의 연속 필드, 뷰·화면 공간은 카메라 기준 효과, UV 공간은 표면에 펼친 2D 패턴에 적합하다. 입력 좌표의 범위와 종횡비를 정규화하고, 변형은 패턴을 평가하기 전에 좌표에 적용한다.
