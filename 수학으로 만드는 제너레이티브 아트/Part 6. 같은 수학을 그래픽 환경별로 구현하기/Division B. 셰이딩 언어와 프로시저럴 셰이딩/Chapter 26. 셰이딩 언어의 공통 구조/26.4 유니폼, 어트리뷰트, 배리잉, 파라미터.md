# 26.4 유니폼, 어트리뷰트, 배리잉, 파라미터

셰이더는 함수처럼 보이지만, 일반 함수 호출처럼 모든 인자를 코드 한 줄에서 넘겨받지는 않는다. 시간, 해상도, 정점 위치, UV, 텍스처, 재질 값은 그래픽 파이프라인의 서로 다른 경로를 통해 셰이더에 전달된다. 값을 어디서 오고 얼마나 자주 달라지는지에 따라 유니폼, 어트리뷰트, 배리잉, 파라미터 같은 구조를 구분한다.

이 구분은 문법을 외우기 위한 분류가 아니다. 어떤 값을 CPU에서 매 프레임 한 번 보내야 하는지, 메시의 각 정점에 저장해야 하는지, 삼각형 표면에서 부드럽게 보간해야 하는지 판단하는 기준이다.

| 전달 방식 | 값이 달라지는 단위 | 주로 쓰는 단계 | 예 |
| --- | --- | --- | --- |
| 유니폼 | 드로우 호출 또는 렌더 패스 전체 | 버텍스·프래그먼트·컴퓨트 | 시간, 해상도, 팔레트, 행렬 |
| 어트리뷰트 | 정점 또는 인스턴스마다 | 주로 버텍스 | 위치, 법선, UV, 정점 색 |
| 배리잉 | 삼각형 표면의 프래그먼트마다 | 버텍스에서 프래그먼트로 | 보간된 UV, 월드 위치, 법선 |
| 텍스처·버퍼 | 표본 좌표 또는 인덱스마다 | 여러 단계 | 이미지, 이전 프레임, 입자 데이터 |
| 셰이더 파라미터 | 재질 또는 셰이더 인스턴스마다 | 서피스·노드 환경 | 거칠기, 색, 스케일, 시드 |

환경과 언어에 따라 이름은 달라진다. GLSL의 `uniform`, `in`, `out`은 HLSL의 상수 버퍼, 입력 구조체, `TEXCOORD` 같은 시맨틱과 대응한다. OSL이나 노드 기반 재질에서는 재질 입력 파라미터와 렌더러가 제공하는 표면 정보가 같은 역할을 나누어 맡는다. 먼저 데이터의 변화 단위를 이해하면 문법의 차이는 훨씬 작게 보인다.

## 유니폼: 한 번 설정하고 모두가 공유하는 값

유니폼(uniform)은 하나의 드로우 호출 또는 렌더 패스 동안 모든 셰이더 실행이 같은 값으로 읽는 입력이다. 시간, 화면 크기, 카메라 행렬, 마우스 위치, 전역 색상, 노이즈 주파수처럼 프레임 전체에 공통인 값이 여기에 들어간다.

```glsl
uniform float time;
uniform vec2 resolution;
uniform vec3 paletteA;
uniform vec3 paletteB;
```

프래그먼트 셰이더의 모든 픽셀은 같은 `time`과 `resolution`을 읽지만, 각 픽셀의 위치는 다르다. 따라서 시간과 위치를 함께 쓰면 화면 전체에서 연결된 애니메이션 패턴을 만들 수 있다.

$$
v(\mathbf{p},t)=\sin(kp_x-\omega t)
$$

```glsl
vec2 p = fragmentPosition / resolution;
float wave = sin(p.x * frequency - time * speed);
```

유니폼은 값이 작고 변경 빈도가 비교적 낮을 때 적합하다. 수십만 개 입자의 위치를 각각 별도 유니폼으로 보내는 방식은 일반적으로 적절하지 않다. 많은 항목의 데이터를 다룰 때는 정점 어트리뷰트, 인스턴스 버퍼, 텍스처 버퍼, 구조화된 버퍼 같은 데이터 구조를 사용한다.

유니폼의 범위도 중요하다. 어떤 값이 전역 애플리케이션 설정인지, 한 재질에만 적용되는 값인지, 한 번의 드로우 호출에만 적용되는 값인지 구분한다. 예를 들어 화면 해상도는 전체 렌더 패스의 유니폼일 수 있지만, 개별 물체의 색상은 물체별 유니폼 또는 재질 파라미터가 될 수 있다.

```text
application: time, screen resolution, camera matrices
material: base color, roughness, noise scale
object: model matrix, object ID, instance parameters
```

## 어트리뷰트: 정점 또는 인스턴스에 붙은 데이터

어트리뷰트(attribute)는 메시의 각 정점에 저장된 데이터다. 최소한의 메시에는 위치가 필요하고, 조명과 텍스처를 위해 법선과 UV가 흔히 추가된다. 정점 색, 접선 벡터, 뼈대 가중치, 사용자 정의 값도 어트리뷰트가 될 수 있다.

```glsl
// GLSL 버텍스 셰이더의 개념 예시
in vec3 position;
in vec3 normal;
in vec2 uv;
in vec3 vertexColor;
```

정점 위치 `position`은 메시의 기하를 정의한다. `normal`은 조명과 표면 변위 방향에, `uv`는 텍스처 및 2D 절차적 패턴에, `vertexColor`는 표면 위에서 보간될 색상 값에 쓰일 수 있다. CPU는 메시 버퍼에 이 데이터를 준비하고, GPU는 버텍스 셰이더를 실행할 때 정점마다 해당 항목을 읽는다.

어트리뷰트는 개체별 데이터와도 연결된다. 인스턴싱(instancing)을 사용하면 같은 메시를 수천 번 그리면서, 인스턴스마다 위치·회전·크기·색·시드를 별도 입력으로 줄 수 있다.

```text
unit mesh vertices + per-instance transform and color
    -> draw many repeated objects in one or few draw calls
```

이는 Chapter 19.5에서 드로잉 API의 반복문으로 만든 도형 배치를 GPU로 옮긴 형태다. CPU가 원 1만 개를 각각 호출하는 대신, GPU가 단위 메시 하나와 인스턴스 데이터를 이용해 반복 구조를 처리한다.

## 배리잉: 정점 값이 표면을 가로질러 변하는 방식

버텍스 셰이더가 계산한 값 가운데 일부는 프래그먼트 셰이더까지 전달되어야 한다. UV, 월드 위치, 정점 색, 법선처럼 삼각형 표면 위에서 연속적으로 변해야 하는 값이 대표적이다. GLSL에서 버텍스 셰이더의 `out`과 프래그먼트 셰이더의 `in`으로 연결되는 값을 전통적으로 배리잉(varying)이라고 부른다.

```glsl
// Vertex shader
out vec2 vUv;
out vec3 vWorldPosition;

void main() {
  vUv = uv;
  vWorldPosition = (modelMatrix * vec4(position, 1.0)).xyz;
}

// Fragment shader
in vec2 vUv;
in vec3 vWorldPosition;
```

래스터화 단계는 삼각형의 세 정점에서 나온 `vUv` 값을 내부의 각 프래그먼트 위치에 맞게 보간한다. 따라서 프래그먼트 셰이더는 표면의 각 위치에서 다른 UV와 월드 위치를 받는다. 텍스처가 삼각형 표면에 연속적으로 붙어 보이는 이유가 이 보간에 있다.

개념적으로 삼각형의 한 내부 점은 세 꼭짓점의 값에 가중치를 곱해 계산된다.

$$
\mathbf{v}=w_0\mathbf{v}_0+w_1\mathbf{v}_1+w_2\mathbf{v}_2,qquad
w_0+w_1+w_2=1
$$

일반적인 배리잉은 원근을 고려한 보간을 사용한다. 하지만 값을 부드럽게 섞지 않고 각 면에서 일정하게 유지하고 싶을 때는 `flat` 보간 같은 수식자를 사용할 수 있다. 면마다 다른 ID나 정수형 인덱스는 보간하면 의미가 깨질 수 있으므로 평면 보간이 적합하다.

```glsl
flat out int vFaceId;
```

반대로 법선처럼 조명에 쓰는 벡터는 보간 후 길이가 1이 아닐 수 있다. 프래그먼트 셰이더에서 다시 정규화해야 한다.

```glsl
vec3 normal = normalize(vNormal);
```

## 텍스처와 버퍼: 큰 데이터의 입력 통로

유니폼·어트리뷰트만으로는 이미지, 이전 프레임, 수만 개 입자의 상태처럼 큰 데이터를 전달하기 어렵다. 텍스처와 버퍼는 GPU 메모리에 저장된 많은 값을 셰이더가 읽도록 하는 구조다.

```glsl
uniform sampler2D previousFrame;
uniform sampler2D noiseTexture;

vec4 history = texture(previousFrame, uv);
```

텍스처는 보통 연속적인 UV 좌표로 표본화한다. 필터링과 반복 모드에 따라 인접한 텍셀을 부드럽게 섞거나 가장 가까운 값을 읽고, 가장자리 밖에서는 반복·고정·투명 처리 같은 규칙을 적용한다. 버퍼는 배열 인덱스나 작업 ID로 접근하는 경우가 많으며, 컴퓨트 셰이더와 인스턴싱에서 입자 상태·행렬·구조화된 데이터를 저장하는 데 유용하다.

이 구조는 프레임 간 상태를 만들 때도 중요하다. 프래그먼트 셰이더는 이전 프레임의 지역 변수를 기억하지 못하지만, 이전 렌더 결과를 텍스처로 전달하면 다음 프레임이 그것을 읽을 수 있다.

```text
previous texture -> shader reads it -> next texture
swap previous and next
```

## 파라미터: 재질과 도구의 조절점

서피스 셰이더나 노드 기반 환경에서는 값의 전달이 `uniform`이나 `attribute`라는 문법보다 재질 파라미터의 형태로 드러나는 경우가 많다. 사용자는 노이즈 스케일, 색상, 거칠기, 범프 강도, 시드 같은 노출된 입력을 조절하고, 렌더러는 표면 위치·법선·UV·관찰 방향 같은 내장 정보를 셰이더에 제공한다.

```text
material parameters:
    colorA, colorB, noiseScale, roughness, seed

renderer-provided surface data:
    position, normal, UV, view direction
```

OSL에서는 셰이더 함수의 매개변수가 재질 편집기의 입력으로 나타날 수 있다. Blender Shader Nodes에서는 노드의 소켓이 같은 역할을 한다. 셰이딩 언어의 표현은 달라도, "모든 표본에 공통인 조절값"과 "각 표면점에서 달라지는 좌표·법선"을 구분하는 원리는 같다.

## 데이터의 변화 빈도로 선택하기

어떤 전달 방식을 쓸지 정할 때는 값이 얼마나 자주, 얼마나 많은 항목에서 달라지는지를 기준으로 삼는다.

| 값 | 적합한 전달 방식 | 이유 |
| --- | --- | --- |
| 전체 장면의 시간 | 유니폼 | 모든 실행이 공유하는 작은 값 |
| 메시의 UV | 정점 어트리뷰트와 배리잉 | 정점마다 다르고 표면에서 보간됨 |
| 물체별 색 | 재질·드로우별 유니폼 또는 인스턴스 데이터 | 물체 또는 인스턴스 단위로 다름 |
| 이미지 패턴 | 텍스처 | 위치별로 많은 색상 값 필요 |
| 입자 10만 개의 상태 | 버퍼 또는 텍스처 버퍼 | 대규모 항목별 데이터 필요 |
| 노이즈 스케일 | 재질 파라미터 또는 유니폼 | 조절 가능하고 넓게 공유됨 |

값의 성격과 전달 방식이 맞지 않으면 코드가 복잡해지거나 성능이 나빠진다. 예를 들어 모든 픽셀에 다른 난수값을 유니폼으로 보내는 대신, 픽셀 좌표에서 해시나 노이즈를 계산하는 편이 더 자연스럽다. 반대로 CPU에서 계산한 개별 입자의 위치를 매 프레임 수천 개 유니폼으로 나열하기보다 버퍼로 전달하는 편이 낫다.

## 이름보다 데이터 흐름을 보기

현대 GLSL에서는 예전의 `attribute`와 `varying` 키워드 대신 단계별 `in`과 `out`을 사용한다. HLSL은 구조체 필드에 `POSITION`, `TEXCOORD`, `SV_Position` 같은 시맨틱을 붙이며, 공통값은 상수 버퍼(constant buffer)로 묶는 경우가 많다. WebGPU의 WGSL도 위치 지정과 바인딩 그룹이라는 다른 문법을 쓴다.

이 차이에 압도될 필요는 없다. 다음처럼 데이터 흐름을 먼저 읽는다.

```text
CPU or material system -> shared parameters -> uniform/constant buffer
mesh or instance buffer -> per-item values -> vertex inputs
vertex output -> interpolation -> fragment input
texture or storage buffer -> sampled or indexed data -> shader calculation
```

언어가 바뀌어도 이 경로는 크게 달라지지 않는다. 셰이더 코드를 읽거나 작성할 때 변수의 이름보다 그 값이 어디서 만들어지고, 어떤 단위로 달라지며, 어느 단계에서 소비되는지를 추적하는 습관이 중요하다.

## 이 절의 핵심

유니폼은 드로우 호출 전체가 공유하는 값, 어트리뷰트는 정점·인스턴스마다 다른 값, 배리잉은 정점에서 프래그먼트까지 보간되어 전달되는 값이다. 텍스처와 버퍼는 큰 데이터와 프레임 간 상태를 전달하며, 재질 파라미터는 셰이더의 조절점을 제공한다. 특정 언어의 키워드보다 값의 변화 단위와 데이터 흐름을 기준으로 전달 방식을 선택해야 한다.
