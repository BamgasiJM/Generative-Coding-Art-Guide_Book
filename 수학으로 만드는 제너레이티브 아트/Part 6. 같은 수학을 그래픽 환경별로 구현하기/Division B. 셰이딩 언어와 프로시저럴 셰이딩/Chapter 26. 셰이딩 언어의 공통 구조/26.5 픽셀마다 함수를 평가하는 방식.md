# 26.5 픽셀마다 함수를 평가하는 방식

프래그먼트 셰이더로 만드는 제너레이티브 이미지는 도형 목록을 화면에 차례로 그린 결과라기보다, 화면의 각 위치에서 함수를 평가한 표본들의 집합이다. 셰이더 코드에는 `for each pixel` 반복문이 보이지 않지만, 렌더러는 래스터화된 표면 또는 전체 화면 사각형의 많은 프래그먼트에서 같은 프로그램을 실행한다.

$$
\mathbf{C}(x,y)=F\bigl(\mathbf{p}(x,y),t,\boldsymbol{\theta}\bigr)
$$

여기서 $(x,y)$는 프래그먼트 위치, $\mathbf{p}$는 정규화·변환한 좌표, $t$는 시간, $\boldsymbol{\theta}$는 유니폼과 재질 파라미터다. 함수 $F$의 출력은 보통 색이지만, 그 전에 거리, 마스크, 노이즈, 각도, 벡터 같은 중간값을 단계적으로 계산한다.

```glsl
vec2 p = uv - 0.5;
p.x *= resolution.x / resolution.y;

float distanceValue = length(p) - radius;
float mask = 1.0 - smoothstep(-edge, edge, distanceValue);
vec3 color = mix(backgroundColor, foregroundColor, mask);
```

이 코드에서 각 프래그먼트는 자기 `uv`만으로 원에 대한 값을 계산한다. 다른 픽셀의 계산 결과나 실행 순서를 알 필요가 없다. 이 독립성은 노이즈, 거리 필드, 타일 패턴, 방사형 파동, 색상 보정처럼 위치별 규칙을 대량으로 계산하는 데 적합하다.

## 전체 화면 패스와 표면 패스

픽셀마다 함수를 평가하는 방식은 두 가지 맥락에서 자주 사용된다. 하나는 전체 화면을 덮는 삼각형 또는 사각형을 그리고, 프래그먼트 셰이더가 화면 전체의 이미지 자체를 만드는 방식이다. 다른 하나는 3D 메시를 렌더링하며 각 표면 프래그먼트에서 재질과 색을 계산하는 방식이다.

| 평가 대상 | 좌표의 출발점 | 대표 결과 |
| --- | --- | --- |
| 전체 화면 패스 | 화면 위치, `gl_FragCoord`, 화면 UV | 필드 이미지, 후처리, 합성, 2D 패턴 |
| 3D 표면 패스 | 보간된 UV, 월드 위치, 법선 | 재질, 텍스처, 표면 마스크, 조명 |

전체 화면 패스에서는 단순한 사각형의 기하가 중요하지 않다. 사각형은 셰이더를 모든 화면 위치에서 실행시키기 위한 매개체다. 패턴의 실제 기하는 프래그먼트 셰이더 안의 거리·좌표·함수 계산에서 나온다.

```text
draw fullscreen triangle
    -> rasterizer generates fragments for the screen
    -> fragment shader evaluates F at each position
    -> framebuffer receives the resulting colors
```

이 접근에서는 패턴의 해상도가 메시 정점 수가 아니라 프레임 버퍼의 해상도에 의해 결정된다. 원의 윤곽, 작은 도트, 고주파 노이즈는 최종 픽셀 크기에 따라 보이거나 사라진다.

## 함수는 중간 필드를 만든다

픽셀 셰이더의 코드를 한 줄의 복잡한 색상 식으로 쓰는 것도 가능하지만, 여러 의미 있는 필드로 나누어 생각하는 편이 좋다. 위치에서 계산한 거리, 노이즈, 마스크, 방향, 밝기는 이후 단계의 입력이 된다.

```text
coordinate field: transformed position p
distance field: d(p)
noise field: n(p)
mask field: m(p)
color field: C(p)
```

예를 들어 노이즈로 원의 윤곽을 흔들고 색을 바꾸려면, 같은 노이즈 값을 서로 다른 출력에 연결할 수 있다.

$$
d'(\mathbf{p})=d(\mathbf{p})+A\,n(f\mathbf{p})
$$

```glsl
float n = noise(p * noiseFrequency);
float d = length(p) - radius + n * distortion;
float mask = 1.0 - smoothstep(-edge, edge, d);
vec3 color = mix(colorA, colorB, 0.5 + 0.5 * n);
color = mix(background, color, mask);
```

이 구조에서는 `n`이 표면의 공통 원인이 된다. 윤곽과 색이 같은 공간적 변화를 공유하므로, 서로 무관한 장식이 아니라 하나의 재료처럼 읽힌다.

## 이산 픽셀과 연속 함수 사이

셰이더에서 평가하는 함수는 연속 좌표를 입력으로 받는 것처럼 보이지만, 최종 화면은 유한한 픽셀 격자다. 픽셀은 영역 전체가 아니라 그 주변의 한 표본값만 기록한다. 너무 좁은 선, 너무 촘촘한 반복, 너무 빠르게 흔들리는 패턴은 픽셀 격자가 충분히 표본화하지 못해 깜빡임이나 모아레를 만들 수 있다.

이를 앨리어싱(aliasing)이라고 한다. 예를 들어 경계를 `d < 0.0`으로 딱 잘라 마스크를 만들면, 경계가 픽셀 사이를 움직일 때 밝은 픽셀이 갑자기 켜지고 꺼질 수 있다.

```glsl
// 단단한 경계
float mask = d < 0.0 ? 1.0 : 0.0;
```

부드러운 전환 폭을 넣으면 경계의 일부가 픽셀 안에 걸친 상황을 더 잘 표현할 수 있다.

```glsl
float mask = 1.0 - smoothstep(-edge, edge, d);
```

그러나 고정된 `edge` 값은 화면 해상도와 확대 비율이 바뀌면 두께가 달라진다. GLSL 계열에서는 `fwidth(d)`처럼 현재 프래그먼트 주변에서 값이 얼마나 변하는지 추정하는 미분 함수를 사용해, 픽셀 크기에 맞는 경계 폭을 정할 수 있다.

```glsl
float width = fwidth(d);
float mask = 1.0 - smoothstep(-width, width, d);
```

이 방법은 SDF 윤곽, 절차적 격자선, 얇은 줄무늬의 안티앨리어싱에 유용하다. 모든 셰이딩 언어와 렌더링 맥락이 같은 미분 함수를 제공하는 것은 아니므로, 사용할 환경의 지원 범위를 확인한다.

## 조건문, 마스크, 그리고 병렬성

픽셀별 함수는 조건문을 쓸 수 있다. 예를 들어 원 내부와 외부에 다른 색을 적용하거나, 일정 임계값 위의 노이즈만 남길 수 있다.

```glsl
if (distanceValue < 0.0) {
  color = foregroundColor;
} else {
  color = backgroundColor;
}
```

하지만 같은 GPU 실행 묶음 안의 프래그먼트가 서로 다른 분기로 크게 갈라지면, 하드웨어가 두 경로를 모두 처리해야 할 수 있어 효율이 떨어질 수 있다. 또한 조건문 경계는 안티앨리어싱하기 어렵다. 두 결과를 마스크로 보간하는 표현은 종종 더 부드럽고 조합하기 쉽다.

```glsl
float mask = step(0.0, -distanceValue);
vec3 color = mix(backgroundColor, foregroundColor, mask);
```

`step`은 여전히 단단한 경계지만, 마스크를 다른 값과 곱하거나 더하는 식으로 조합할 수 있다. `smoothstep`은 부드러운 마스크를 만든다. 조건문을 완전히 피해야 하는 것은 아니지만, 위치 기반 패턴에서는 마스크와 함수 조합이 표현과 성능 양쪽에서 자연스러운 경우가 많다.

## 반복과 좌표 재사용

프래그먼트 셰이더의 반복은 두 종류로 나눌 수 있다. 하나는 각 프래그먼트 안에서 작은 횟수만큼 수행하는 명시적 반복문이고, 다른 하나는 좌표 연산으로 공간 패턴을 반복하는 방식이다.

```glsl
// 좌표 반복: 화면의 모든 위치에서 타일 내부 좌표를 만든다.
vec2 cell = fract(uv * gridCount) - 0.5;
```

`fract` 기반 타일링은 셀 수만큼 도형을 실제로 반복하는 것이 아니다. 현재 위치가 어느 셀 안에 있는지를 계산해, 하나의 단위 패턴을 모든 셀에서 재사용한다. 이는 Part 3의 반복 좌표 개념이 픽셀 셰이더에서 매우 효율적으로 작동하는 예다.

반면 광선 행진에서 여러 스텝을 진행하거나 fBm에서 여러 옥타브를 더할 때는 프래그먼트 안의 명시적 반복문을 쓴다.

```glsl
float sum = 0.0;
float amplitude = 1.0;
for (int octave = 0; octave < OCTAVES; ++octave) {
  sum += amplitude * noise(p * frequency);
  frequency *= 2.0;
  amplitude *= 0.5;
}
```

반복 횟수가 크거나 데이터에 따라 달라지면 프래그먼트 하나의 비용이 커지고 실행 묶음마다 작업량이 달라질 수 있다. 가능한 한 상한을 명확히 두고, 필요 없는 고주파 옥타브나 화면 밖 계산을 줄이는 것이 좋다.

## 시간에 따른 평가와 프레임 간 상태

시간을 유니폼으로 넣으면 현재 프레임의 모든 픽셀이 같은 시간값에서 함수를 평가한다.

$$
\mathbf{C}_t(\mathbf{p})=F(\mathbf{p},t)
$$

```glsl
float wave = sin(length(p) * frequency - time * speed);
```

이런 시간 함수는 어느 프레임이든 독립적으로 다시 계산할 수 있다. 반면 이전 프레임의 결과가 필요한 잔상·확산·피드백은 현재 셰이더의 지역 변수만으로 만들 수 없다. 이전 렌더 타깃을 텍스처로 읽고 새 렌더 타깃에 결과를 써야 한다.

```text
previous frame texture -> sample at each pixel -> compute next value -> write next texture
```

이 구조에서도 각 픽셀은 이전 텍스처의 값을 독립적으로 읽는다. 이웃 픽셀을 참조하는 블러, 라플라시안, 셀룰러 오토마타도 주변 UV를 여러 번 표본화해 계산할 수 있다. 읽기와 쓰기 텍스처를 분리하는 ping-pong 구조가 필요한 이유는 Chapter 19.8에서 다룬 원리와 같다.

## 픽셀 함수로 생각하는 습관

프래그먼트 셰이더를 작성할 때는 다음 순서가 유용하다.

1. 이 프래그먼트의 좌표는 어떤 공간에서 얻는가?
2. 좌표를 중심 이동·종횡비 보정·반복·회전으로 어떻게 변형하는가?
3. 변형 좌표에서 어떤 스칼라·벡터 필드를 계산하는가?
4. 그 값을 마스크, 색, 법선, 깊이, 다음 버퍼 값 가운데 어디로 연결하는가?
5. 선과 경계의 크기가 픽셀 해상도에서 안정적으로 표본화되는가?

이 순서는 "무엇을 그릴까"라는 질문을 "이 위치에서 어떤 값을 반환할까"라는 질문으로 바꾼다. 이후의 GLSL, HLSL, OSL 장에서 구체적인 문법은 달라져도, 위치별 함수 평가라는 핵심은 유지된다.

## 이 절의 핵심

프래그먼트 셰이더는 화면 또는 표면의 각 위치에서 좌표·시간·파라미터를 입력으로 함수를 평가해 결과를 만든다. 거리·노이즈·마스크 같은 중간 필드를 나누어 구성하고, 픽셀 격자의 표본 한계에 맞춰 경계를 부드럽게 처리해야 한다. 독립적인 위치 계산에는 강하지만, 이전 프레임이나 이웃 상태가 필요하면 텍스처·버퍼를 통한 별도 데이터 흐름이 필요하다.
