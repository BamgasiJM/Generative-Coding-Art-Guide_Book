# 26.2 버텍스, 프래그먼트, 서피스, 컴퓨트 단계

셰이더는 모두 GPU 또는 렌더러에서 실행되는 함수처럼 보이지만, 실행되는 시점과 다루는 데이터의 단위는 서로 다르다. 정점의 위치를 바꾸는 셰이더와 화면 픽셀의 색을 계산하는 셰이더는 같은 "셰이더"라는 이름을 쓰더라도 입력과 출력이 다르다. 이 차이를 알면 어떤 제너레이티브 규칙을 어느 단계에 넣어야 할지 판단하기 쉬워진다.

이 절에서는 실시간 그래픽에서 흔히 쓰는 버텍스·프래그먼트·컴퓨트 단계를 먼저 살피고, 표면의 재질을 계산하는 서피스 셰이딩을 별도로 다룬다. 실제 API는 더 많은 단계를 제공하거나 일부 단계를 감추지만, 네 관점은 대부분의 셰이더 작업을 이해하는 기준이 된다.

| 단계 | 주된 계산 단위 | 대표 입력 | 대표 출력 | 제너레이티브 활용 |
| --- | --- | --- | --- | --- |
| 버텍스 | 메시의 꼭짓점 | 위치, 법선, UV, 인스턴스 데이터 | 변환된 위치, 전달 속성 | 메시 변형, 파도, 개체 배치 |
| 프래그먼트 | 래스터화된 표면·화면 위치 | 보간된 UV, 위치, 법선, 유니폼 | 색, 알파, 깊이 | SDF, 노이즈, 후처리, 재질 |
| 서피스 | 렌더러가 표본화한 물체 표면점 | 표면 위치, UV, 법선, 조명 맥락 | 재질 반응, 클로저 | 절차적 재질, 범프, 변위 |
| 컴퓨트 | 일반 데이터 항목 | 버퍼, 텍스처, 작업 ID | 수정된 버퍼·텍스처 | 입자, 격자, 대규모 시뮬레이션 |

## 버텍스 단계: 기하의 위치를 계산하기

메시는 점, 선, 삼각형 같은 기하를 이루는 정점(vertex)의 집합이다. 버텍스 셰이더는 각 정점마다 한 번씩 실행되어, 그 정점이 화면에서 어디에 놓일지를 계산한다. 일반적인 3D 렌더링에서는 로컬 좌표의 정점을 모델·뷰·프로젝션 행렬로 변환한다.

$$
\mathbf{p}_{clip}=P\,V\,M\,\mathbf{p}_{local}
$$

```glsl
// GLSL 버텍스 셰이더의 개념 예시
vec3 worldPosition = (modelMatrix * vec4(position, 1.0)).xyz;
gl_Position = projectionMatrix * viewMatrix * vec4(worldPosition, 1.0);
```

버텍스 셰이더에서 정점 위치에 함수를 더하면 기하 자체가 변한다. 예를 들어 평면 메시의 각 정점 높이를 노이즈나 사인파로 바꾸면 지형, 물결, 천처럼 움직이는 표면을 만들 수 있다.

$$
y'=y+A\sin(kx-\omega t)
$$

```glsl
float wave = sin(position.x * frequency - time * speed);
vec3 displaced = position + normal * (wave * amplitude);
```

여기서 `normal` 방향으로 변위하면 표면의 바깥 방향으로 부풀거나 들어간다. 다만 정점 수보다 작은 세부는 표현할 수 없다. 정점이 듬성듬성한 평면에 고주파 노이즈를 넣어도, 변위는 정점 사이에서 보간되어 매끈하고 단순한 형태로 보인다. 세밀한 기하 변형에는 메시 세분화, 테셀레이션, 디스플레이스먼트 렌더링 같은 추가 기법이 필요할 수 있다.

버텍스 셰이더는 정점마다 독립적으로 실행된다. 이웃 정점의 위치를 직접 읽어 평균을 내거나 연결 관계를 탐색하는 일에는 적합하지 않다. 대신 인스턴스 ID, 정점 색, UV 같은 입력을 이용해 많은 개체에 서로 다른 변환과 색상 데이터를 전달할 수 있다.

## 래스터화: 정점에서 표면 표본으로

버텍스 셰이더의 출력은 보통 삼각형으로 조립된다. 래스터화(rasterization)는 이 삼각형이 화면에서 덮는 픽셀 후보를 찾고, 정점에서 전달된 값들을 삼각형 내부 위치에 맞게 보간하는 과정이다. 이 단계는 일반적으로 그래픽 하드웨어가 수행하며, 프로그래머가 직접 코드를 작성하지 않는다.

예를 들어 삼각형의 세 꼭짓점이 각각 다른 UV 좌표를 가진다면, 삼각형 안쪽의 각 프래그먼트는 그 위치에 맞는 보간된 UV를 받는다. 이 보간 덕분에 텍스처와 절차적 패턴이 메시 표면을 연속적으로 덮을 수 있다.

```text
vertex UV values
    -> rasterization interpolates them
    -> fragment shader receives UV at each surface sample
```

정점 데이터가 화면에 그대로 찍히는 것이 아니라, 정점과 정점 사이의 표면까지 채워진다는 점은 중요하다. 버텍스 단계는 기하의 큰 구조를, 프래그먼트 단계는 그 표면 위의 세밀한 색과 재질을 담당하는 경우가 많다.

## 프래그먼트 단계: 표면 또는 화면의 색을 계산하기

프래그먼트 셰이더는 래스터화된 삼각형의 각 프래그먼트에서 실행된다. 프래그먼트는 최종 화면 픽셀이 될 후보라고 생각할 수 있지만, 깊이 검사·블렌딩·다중 샘플링을 거쳐 최종 픽셀이 되므로 엄밀히는 픽셀과 완전히 같지 않다.

프래그먼트 셰이더는 보간된 UV, 월드 위치, 법선, 유니폼, 텍스처를 이용해 색과 알파를 계산한다.

```glsl
// GLSL 프래그먼트 셰이더의 개념 예시
vec2 p = vUv - 0.5;
float d = length(p) - 0.25;
float mask = 1.0 - smoothstep(-0.003, 0.003, d);
vec3 color = mix(backgroundColor, foregroundColor, mask);
```

전체 화면을 덮는 사각형에 이런 프래그먼트 셰이더를 적용하면, 메시의 원래 모양보다 화면 좌표 함수 자체가 이미지가 된다. 거리 함수, 반복 좌표, 극좌표, 노이즈, 색상 필드는 이 방식과 특히 잘 맞는다. 반면 표면 메시 위에 적용하면 같은 함수도 UV·오브젝트 공간·월드 공간에서 평가되어 재질 패턴으로 나타난다.

프래그먼트 셰이더는 색만 계산하는 단계가 아니다. 깊이 값을 변경하거나, 여러 렌더 타깃에 값을 출력하거나, 화면 밖 후처리 패스의 중간 이미지를 만들 수도 있다. 그러나 다른 프래그먼트와 임의 순서로 데이터를 주고받을 수는 없다. 이전 프레임이나 다른 픽셀의 결과가 필요하면 텍스처를 입력으로 받고 별도 버퍼에 결과를 써야 한다.

## 서피스 단계: 재질과 빛의 상호작용을 계산하기

서피스 셰이더(surface shader)는 화면 좌표보다 물체 표면의 한 점을 중심으로 재질을 계산한다. OSL(Open Shading Language)과 많은 오프라인 렌더러의 재질 시스템, Blender의 셰이더 노드가 이 관점에 가깝다. 렌더러가 카메라에서 보이는 표면점을 찾아 셰이더에 넘기고, 셰이더는 그 점이 빛을 어떻게 반사·투과·방출하는지 정의한다.

$$
\text{material}=S(\mathbf{p},\mathbf{n},\mathbf{uv},\mathbf{v},\text{parameters})
$$

여기서 $\mathbf{p}$는 표면 위치, $\mathbf{n}$은 법선, $\mathbf{uv}$는 표면 좌표, $\mathbf{v}$는 관찰 방향이다. 출력은 단순 RGB 색보다 넓은 의미의 재질 반응일 수 있다. 예를 들어 확산 반사, 금속 반사, 유리의 투과, 표면 발광을 조합하는 클로저(closure) 또는 BSDF가 출력이 된다.

```text
noise(surfacePosition) -> base color
noise(surfacePosition) -> roughness
noise(surfacePosition) -> bump or normal perturbation
mask -> mix between two materials
```

서피스 셰이더의 장점은 같은 절차적 패턴이 카메라 화면이 아니라 물체에 붙는다는 점이다. 오브젝트 공간 노이즈를 사용하면 카메라가 움직여도 대리석 무늬가 표면에 고정되어 보인다. UV 공간 패턴을 사용하면 이미지를 표면에 펼칠 수 있다. 월드 공간 패턴은 여러 물체를 가로지르는 안개나 절단면 같은 효과를 만들 수 있다.

실시간 프래그먼트 셰이더도 표면 위치·법선·조명을 사용해 재질을 계산할 수 있으므로, 두 용어의 경계가 구현마다 겹칠 수 있다. 이 책에서는 프래그먼트 셰이더를 GPU 래스터화 단계의 프로그램으로, 서피스 셰이더를 렌더러의 표면 재질 평가 관점으로 구분한다.

## 컴퓨트 단계: 렌더링하지 않고 데이터를 갱신하기

컴퓨트 셰이더(compute shader)는 정점이나 프래그먼트를 생성하기 위해서가 아니라, 일반 데이터를 대량으로 처리하기 위해 실행된다. 실행 항목마다 고유한 작업 ID가 주어지고, 그 ID를 이용해 버퍼 또는 텍스처의 어느 원소를 처리할지 결정한다.

```glsl
// 개념 예시: 각 입자의 위치를 한 항목씩 갱신한다.
uint id = globalInvocationID.x;
velocity[id] += force(position[id]) * deltaTime;
position[id] += velocity[id] * deltaTime;
```

컴퓨트 셰이더는 수십만 개 입자의 상태 갱신, 이미지 필터링, 셀룰러 오토마타, 반응-확산, 행렬·벡터 데이터 처리에 적합하다. 이후 렌더링 단계는 갱신된 버퍼를 정점 위치나 인스턴스 데이터로 읽어 화면에 표시할 수 있다.

컴퓨트는 픽셀 셰이더보다 데이터 처리에 자유로운 면이 있지만, 동기화와 메모리 접근을 더 직접적으로 관리해야 한다. 같은 작업 그룹 안에서만 제한적인 동기화가 가능하며, 다른 작업 그룹의 실행 순서는 보장되지 않는다. 읽기와 쓰기가 얽힌 알고리즘은 데이터 경쟁을 피하도록 버퍼를 나누거나 여러 패스로 나눠야 한다.

## 하나의 규칙을 여러 단계에 연결하기

같은 수학적 함수도 연결 위치에 따라 다른 결과를 만든다. 시간에 따라 변하는 노이즈를 예로 들어 보자.

```text
noise(position, time)
    -> vertex displacement: 흔들리는 메시
    -> fragment color: 흐르는 색상 패턴
    -> surface roughness: 변화하는 재질감
    -> compute force: 노이즈에 따른 입자 운동
```

함수의 입력 공간도 단계마다 달라질 수 있다. 버텍스 셰이더는 보통 메시 로컬 위치를, 프래그먼트 셰이더는 보간된 UV나 화면 위치를, 서피스 셰이더는 오브젝트·월드 공간의 표면 위치를, 컴퓨트 셰이더는 버퍼 ID나 격자 좌표를 출발점으로 얻는다. 알고리즘을 옮길 때는 먼저 어떤 단위에서 반복되고 어떤 공간을 입력으로 쓰는지 확인한다.

## 단계는 직렬 구조이면서 선택 구조다

전형적인 실시간 렌더링 경로는 버텍스 처리, 래스터화, 프래그먼트 처리 순으로 이어진다. 하지만 모든 작업이 항상 이 순서를 거치는 것은 아니다. 전체 화면 후처리는 단순한 사각형의 버텍스와 프래그먼트 셰이더만 사용할 수 있고, 컴퓨트 셰이더는 렌더링 파이프라인 밖에서 먼저 데이터를 갱신한 뒤 나중에 렌더링에 활용할 수 있다. 서피스 셰이더는 레이 트레이싱이나 오프라인 렌더링의 표본화 과정에서 호출될 수 있다.

이 차이를 이해하면 "어떤 셰이더가 더 강력한가"라는 질문보다 "내 규칙이 필요한 데이터와 출력은 무엇인가"라는 질문으로 옮겨 갈 수 있다. 기하를 바꾸려면 버텍스, 표면의 색과 마스크를 만들려면 프래그먼트 또는 서피스, 대량 상태를 갱신하려면 컴퓨트를 우선 검토한다.

## 이 절의 핵심

버텍스 셰이더는 정점과 기하를, 프래그먼트 셰이더는 래스터화된 표면의 색과 화면 효과를, 서피스 셰이더는 표면 재질과 빛의 반응을, 컴퓨트 셰이더는 일반 버퍼·텍스처 데이터를 계산한다. 같은 수학적 규칙도 어느 단계의 어떤 좌표와 출력에 연결하는지에 따라 메시 변형, 절차적 패턴, 재질, 시뮬레이션으로 다르게 나타난다.
