# 28.4 좌표 변환과 행렬

3D 정점은 보통 메시의 로컬 공간에서 출발해 월드 공간, 뷰 공간, 클립 공간을 거쳐 화면에 놓인다. 변환이 필요한 이유와 각 좌표 공간의 의미는 26.3에서 살펴보았다. 여기서는 그 흐름을 HLSL로 작성할 때 중요한 `mul()`의 계산 순서, 행렬의 메모리 배치, Direct3D의 클립 공간 규칙을 정리한다.

HLSL 행렬은 수학적 곱셈과 메모리 배치라는 서로 다른 두 관점으로 읽어야 한다. `mul()`의 인자 순서는 벡터를 행 벡터로 계산할지 열 벡터로 계산할지를 정한다. 반면 `row_major`와 `column_major`는 주로 상수 버퍼에 행렬 성분을 어떤 순서로 배치할지 정한다. 두 설정을 혼동하면 컴파일은 성공해도 모델이 뒤집히거나 비틀려 보일 수 있다.

## 로컬에서 클립 공간까지

아래 버텍스 셰이더는 행 벡터 관례를 사용한다. 위치를 모델, 뷰, 프로젝션 순으로 곱해 클립 공간에 보낸다.

```c
cbuffer TransformData : register(b0)
{
    row_major float4x4 model;
    row_major float4x4 view;
    row_major float4x4 projection;
};

struct VSInput
{
    float3 position : POSITION;
};

struct VSOutput
{
    float4 position : SV_Position;
};

VSOutput VSMain(VSInput input)
{
    VSOutput output;

    float4 localPosition = float4(input.position, 1.0);
    float4 worldPosition = mul(localPosition, model);
    float4 viewPosition = mul(worldPosition, view);
    output.position = mul(viewPosition, projection);

    return output;
}
```

행 벡터 관례에서는 다음과 같이 쓸 수 있다.

$$
\mathbf{p}_{clip}=\mathbf{p}_{local} M V P
$$

HLSL의 `mul(vector, matrix)`는 벡터를 행렬 왼쪽에 둔 곱으로 계산한다. 따라서 `mul(localPosition, model)`은 로컬 위치를 월드 공간으로 옮기고, 뒤이어 뷰와 프로젝션을 적용한다. 행렬을 하나로 미리 합쳤다면 `mul(localPosition, modelViewProjection)`처럼 쓸 수 있다.

반대로 열 벡터 관례를 사용하려면 `mul(matrix, vector)` 순서로 계산하고, 수학적 행렬 조합도 $PVM$처럼 역순으로 구성한다. 어느 관례가 보편적으로 옳은지가 아니라, 행렬을 만드는 CPU 코드와 HLSL의 곱 순서가 일치하는지가 중요하다.

HLSL에서 벡터나 행렬의 `*`는 성분별 곱셈으로 쓰일 수 있으므로 선형대수의 행렬 곱을 표현할 때는 `mul()`을 사용한다. 예를 들어 `mul(a, b)`와 `a * b`를 같은 의미로 취급하면 안 된다. 스케일처럼 각 성분에 같은 비율을 적용하는 연산인지, 좌표계를 변환하는 행렬 곱인지 구분한다.

## 행렬 패킹과 CPU 데이터

`row_major`와 `column_major`는 행렬의 곱셈 방향을 지정하지 않는다. 셰이더가 행렬 성분을 상수 버퍼에 저장하고 읽는 순서를 지정한다. HLSL은 별도 설정이 없으면 일반적으로 `column_major` 패킹을 사용하며, 선언에 한정자를 붙이거나 컴파일 옵션·전처리 지시문으로 기본값을 바꿀 수 있다.

| 항목 | 결정하는 것 | 확인할 대상 |
| --- | --- | --- |
| `mul(v, M)` 또는 `mul(M, v)` | 벡터를 행 벡터/열 벡터 중 어느 방식으로 곱하는지 | HLSL 함수와 CPU에서 행렬을 조합하는 순서 |
| `row_major` 또는 `column_major` | 행렬 성분을 상수 버퍼에 배치하고 읽는 방식 | HLSL 선언, 컴파일 옵션, CPU 업로드 메모리 |

예제의 행렬은 `row_major`로 선언했으므로, CPU에서 업로드하는 배열도 그 배치에 맞춰야 한다. 엔진은 행렬을 자동 전치하거나 상수 버퍼 형식에 맞춰 변환할 수 있으므로 엔진 셰이더에서는 자체 규약을 확인한다. 전치가 필요할 수도 있지만, HLSL의 곱셈 순서와 상수 버퍼의 패킹 중 무엇이 어긋났는지 먼저 확인하지 않고 무조건 전치하면 문제가 더 복잡해진다.

진단할 때는 다음 순서로 확인하면 좋다.

1. 위치가 로컬 공간인지 월드 공간인지, 입력이 점인지 방향 벡터인지 확인한다.
2. CPU가 `M * V * P` 또는 `P * V * M` 중 어떤 규약으로 행렬을 조합했는지 확인한다.
3. HLSL의 `mul()` 인자 순서가 그 규약과 맞는지 확인한다.
4. 행렬 패킹 한정자와 CPU 업로드 메모리의 순서가 맞는지 확인한다.
5. 프로젝션의 깊이 범위, 좌우수계, 뷰포트 설정이 서로 맞는지 점검한다.

## 점, 방향, 노멀의 변환

동차 좌표의 마지막 성분은 변환 대상이 점인지 방향인지를 구별하는 데 쓰인다. 위치는 보통 `float4(position, 1.0)`으로 만들어 이동·회전·스케일의 영향을 모두 받게 한다. 방향은 `float4(direction, 0.0)`으로 표현해 평행 이동의 영향을 받지 않게 한다.

노멀은 방향 벡터처럼 모델 행렬의 3×3 부분을 그대로 적용하면 안 되는 경우가 있다. 특히 비균일 스케일이 있으면 변환된 노멀이 표면의 접선과 직교하지 않을 수 있다. 올바른 노멀 변환에는 모델 행렬의 역전치 3×3 행렬을 사용하고, 결과를 정규화한다.

```c
row_major float3x3 normalMatrix;
float3 worldNormal = normalize(mul(input.normal, normalMatrix));
```

일반적으로 역전치 행렬은 CPU에서 미리 계산해 유니폼이나 상수 버퍼로 전달한다. 모델 변환에 회전과 균일 스케일만 있다면 단순화할 수 있지만, 비균일 스케일이나 전단 변환을 허용하는 모델에서는 역전치를 적용해야 조명 방향이 정확해진다. 노멀의 색상화나 재질 조명과 연결하는 방법은 28.5에서 이어서 다룬다.

## Direct3D 클립 공간과 깊이

버텍스 셰이더의 `SV_Position` 출력은 화면 픽셀 좌표가 아니라 동차 클립 공간 위치다. Direct3D의 일반적인 클립 조건은 다음과 같다.

$$
-w \leq x \leq w,\qquad -w \leq y \leq w,\qquad 0 \leq z \leq w
$$

클리핑 뒤에는 원근 나눗셈으로 $x/w$, $y/w$, $z/w$를 얻는다. Direct3D의 일반적인 정규화 장치 좌표(NDC)에서 x와 y는 $[-1,1]$, 깊이 z는 $[0,1]$ 범위다. 이후 뷰포트 변환으로 픽셀 위치와 깊이 버퍼 값이 정해진다. 이 때문에 OpenGL의 전통적인 클립 깊이 범위를 전제로 만든 프로젝션 행렬을 그대로 쓰면 깊이와 클리핑 결과가 기대와 다를 수 있다.

Direct3D HLSL 자체가 좌수계 또는 우수계를 강제하지는 않는다. 카메라 뷰 행렬과 프로젝션 행렬을 어느 규약으로 만들었는지 일관되게 사용해야 한다. Direct3D의 일반적인 NDC에서는 y가 위쪽으로 증가하지만, 뷰포트 변환 뒤 화면 픽셀 좌표의 y는 아래쪽으로 증가한다. 텍스처 UV의 위아래 방향은 이미지 로딩이나 엔진의 텍스처 처리에 영향을 받으므로, 클립 공간의 y축과 자동으로 같다고 생각하지 않는다.

깊이 버퍼의 기본 매핑을 바꾸는 reversed-Z 기법도 사용할 수 있다. 이 경우 프로젝션 행렬과 깊이 비교 함수, 깊이 초기화 값이 함께 바뀌어야 한다. 셰이더에서 z만 임의로 뒤집는 방식은 클리핑과 깊이 테스트를 불일치하게 만들 수 있다.

## 절차적 패턴을 어느 공간에서 평가할까

좌표 변환은 정점의 화면 위치를 만드는 데만 쓰이지 않는다. HLSL에서 노이즈나 거리 함수를 어느 공간의 좌표로 평가하는지도 작품의 움직임과 패턴 고정을 결정한다. 로컬 좌표를 쓰면 패턴이 오브젝트에 붙고, 월드 좌표를 쓰면 여러 오브젝트를 가로질러 하나의 필드가 이어진다. 화면 좌표를 쓰면 패턴이 카메라 화면에 고정된다. 공간 선택의 일반 원리는 26.3에서 설명한 규칙을 따른다.

그래픽 파이프라인에서는 필요한 위치를 정점 단계에서 전달하고, 픽셀 단계에서 보간된 값을 쓰거나, 픽셀 단계에서 화면 좌표를 직접 참조할 수 있다. 어떤 방식을 택하든 패턴 입력 좌표의 공간과 단위를 변수 이름이나 주석에 드러내면 카메라·오브젝트가 움직일 때 생기는 결과를 예측하기 쉽다.

## 이 절의 핵심

HLSL에서 선형대수 행렬 곱은 `mul()`로 표현하며, `mul(v, M)`과 `mul(M, v)`는 서로 다른 벡터 관례를 사용한다. `row_major`와 `column_major`는 곱셈 방향이 아니라 상수 버퍼의 데이터 배치를 정하므로 CPU 업로드 형식과 맞춰야 한다. 위치·방향·노멀은 각각 다른 방식으로 변환하며, Direct3D의 일반적인 클립 깊이 범위는 $[0,w]$다. 행렬 곱 순서, 패킹, 좌표계, 깊이 규약을 함께 확인하면 변환 오류를 체계적으로 진단할 수 있다.
