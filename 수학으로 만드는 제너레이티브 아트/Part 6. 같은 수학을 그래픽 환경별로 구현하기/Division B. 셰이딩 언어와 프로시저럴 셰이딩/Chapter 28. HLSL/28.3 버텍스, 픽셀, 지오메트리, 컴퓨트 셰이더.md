# 28.3 버텍스, 픽셀, 지오메트리, 컴퓨트 셰이더

HLSL 함수는 어떤 진입점으로 컴파일되는지에 따라 그래픽 파이프라인의 특정 단계에서 실행된다. 버텍스 셰이더는 정점 단위로 위치와 보간할 값을 계산하고, 픽셀 셰이더는 래스터화된 프래그먼트의 출력을 만든다. 지오메트리 셰이더는 입력 프리미티브를 바탕으로 프리미티브를 추가하거나 버리고, 컴퓨트 셰이더는 그래픽 프리미티브와 무관하게 스레드 그룹 단위로 자료를 처리한다.

이 단계들은 같은 언어를 사용하지만 입력 단위와 출력 계약이 다르다. HLSL에서 `POSITION` 같은 의미(semantic)는 셰이더 입력의 역할을 연결하고, `SV_Position`이나 `SV_Target` 같은 시스템 의미는 파이프라인이 요구하거나 사용하는 특수한 값을 나타낸다. 이 절에서는 네 단계의 데이터 흐름과 선택 기준을 살펴본다.

## 단계와 입력 단위

| 셰이더 | 실행되는 단위 | 대표 입력 | 대표 출력과 역할 |
| --- | --- | --- | --- |
| 버텍스(Vertex) | 정점 처리 단위 | 정점 버퍼의 위치, 노멀, UV 등 | 클립 공간 위치와 다음 단계에 전달할 값 |
| 픽셀(Pixel) | 래스터화로 생성된 프래그먼트 | 보간된 값, 픽셀 위치, 텍스처 | 렌더 타깃 색상 등 |
| 지오메트리(Geometry) | 입력 프리미티브 | 점·선·삼각형과 정점별 값 | 0개 이상의 새 프리미티브 |
| 컴퓨트(Compute) | 디스패치된 스레드 | 스레드 ID, 상수, 버퍼와 텍스처 | UAV 버퍼·텍스처의 데이터 |

그래픽 파이프라인의 버텍스 셰이더와 픽셀 셰이더는 보통 한 드로우 호출 안에서 이어진다. 반면 컴퓨트 셰이더는 별도의 디스패치 호출로 실행되며, 그 결과를 나중에 그래픽 파이프라인이 사용할 수 있다. 지오메트리 셰이더는 래스터화 전 단계에 선택적으로 들어간다.

## 버텍스와 픽셀 단계 연결하기

버텍스 단계는 정점 입력을 받아 위치와 다음 단계로 넘길 데이터를 출력한다. 다음의 간단한 예제는 정점 위치가 이미 클립 공간 범위에 있다고 가정하여 변환 행렬을 생략했다. 실제 모델 좌표에서 클립 공간으로의 변환은 28.4에서 다룬다.

```c
struct VSInput
{
    float3 position : POSITION;
    float3 color : COLOR0;
};

struct VSOutput
{
    float4 position : SV_Position;
    float3 color : COLOR0;
};

VSOutput VSMain(VSInput input)
{
    VSOutput output;
    output.position = float4(input.position, 1.0);
    output.color = input.color;
    return output;
}
```

`POSITION`과 `COLOR0`은 입력 레이아웃이 정점 버퍼에 연결하는 의미다. 버텍스 셰이더가 내보내는 `SV_Position`은 래스터화에 필요한 클립 공간 위치이고, `COLOR0`은 다음 단계로 전달할 사용자 데이터다. 정점 입력의 자료형과 입력 레이아웃은 애플리케이션에서 동일하게 맞춰야 한다.

픽셀 셰이더는 버텍스 출력 중 위치 외의 값을 기본적으로 보간된 형태로 받는다.

```c
float4 PSMain(VSOutput input) : SV_Target0
{
    return float4(input.color, 1.0);
}
```

세 정점에 서로 다른 색이 있으면 `input.color`는 삼각형 안에서 위치에 따라 보간된다. `SV_Target0`은 결과를 첫 번째 컬러 렌더 타깃에 기록한다. 위 코드에서 `SV_Position`은 버텍스 셰이더 출력으로 쓰일 때 클립 공간 위치를 뜻하지만, 픽셀 셰이더 입력으로 선언되면 화면의 픽셀 위치 정보를 나타낸다. 같은 시스템 의미라도 파이프라인 단계에 따라 읽고 쓰는 방식이 달라질 수 있다.

일반적인 사용자 데이터는 `TEXCOORD0`, `COLOR0`처럼 시스템 의미가 아닌 의미를 통해 단계 사이로 전달한다. 보간이 필요 없는 정수 ID나 재료 인덱스는 기본 보간을 사용하지 말고 `nointerpolation` 같은 보간 수식자를 고려한다. 반면 `SV_VertexID`, `SV_InstanceID`처럼 `SV_`로 시작하는 시스템 의미는 정점 또는 인스턴스 번호를 파이프라인에서 제공한다. 어떤 의미를 사용할 수 있는지는 셰이더 단계와 프로필에 따라 달라진다.

## 지오메트리 셰이더로 프리미티브 다루기

지오메트리 셰이더는 버텍스 셰이더에서 구성된 점·선·삼각형 같은 프리미티브를 입력으로 받고, 이를 변형하거나 새 프리미티브를 출력한다. 예를 들어 입력 삼각형의 정점을 그대로 내보내는 최소 형태는 다음과 같다.

```c
struct GSInput
{
    float4 position : SV_Position;
    float3 color : COLOR0;
};

struct GSOutput
{
    float4 position : SV_Position;
    float3 color : COLOR0;
};

[maxvertexcount(3)]
void GSMain(triangle GSInput input[3],
            inout TriangleStream<GSOutput> stream)
{
    for (uint i = 0; i < 3; ++i)
    {
        GSOutput output;
        output.position = input[i].position;
        output.color = input[i].color;
        stream.Append(output);
    }

    stream.RestartStrip();
}
```

`triangle`은 입력 프리미티브의 종류를, `TriangleStream`은 출력할 삼각형 스트립을 나타낸다. `[maxvertexcount(3)]`은 이 진입점이 한 번 실행될 때 출력할 수 있는 최대 정점 수를 선언한다. 실제 출력 수는 이보다 작을 수 있다. 점 입력에는 `PointStream`, 선 입력에는 `LineStream`처럼 프리미티브 종류에 맞는 스트림을 사용한다.

지오메트리 셰이더는 입력 프리미티브마다 실행되므로 점에서 카메라를 향하는 사각형을 만들거나, 특정 프리미티브를 생략하거나, 면마다 별도 데이터를 붙이는 작업에 쓸 수 있다. 다만 프리미티브마다 GPU 실행을 추가하고 데이터를 스트림으로 내보내므로, 모든 기하 생성 문제에서 가장 빠른 선택은 아니다. 고정된 메시 구조라면 CPU에서 미리 만들거나 인스턴싱을 쓰는 편이 단순할 수 있고, 대규모 절차적 기하에는 대상 GPU가 지원하는 메시 셰이더 경로도 검토할 수 있다.

## 컴퓨트 셰이더로 데이터 병렬 처리하기

컴퓨트 셰이더는 `Dispatch` 호출이 지정한 스레드 그룹을 실행한다. `[numthreads(x, y, z)]`는 하나의 그룹 안에서 각 차원으로 몇 개의 스레드를 실행할지 선언한다. 아래 예제는 2차원 텍스처의 각 위치에 간단한 절차적 색을 쓰며, 크기가 그룹 크기로 나누어떨어지지 않는 경우를 위해 범위를 검사한다.

```c
RWTexture2D<float4> outputImage : register(u0);

cbuffer Parameters : register(b0)
{
    uint2 imageSize;
    float time;
    float padding;
};

[numthreads(8, 8, 1)]
void CSMain(uint3 dispatchThreadID : SV_DispatchThreadID)
{
    uint2 pixel = dispatchThreadID.xy;
    if (any(pixel >= imageSize))
    {
        return;
    }

    float2 uv = (float2(pixel) + 0.5) / float2(imageSize);
    float wave = 0.5 + 0.5 * sin((uv.x + uv.y) * 20.0 + time);
    outputImage[pixel] = float4(wave, 0.25, 1.0 - wave, 1.0);
}
```

`RWTexture2D`는 셰이더가 읽고 쓸 수 있는 텍스처를 나타내며, `register(u0)`는 Direct3D의 UAV 슬롯에 연결한다. `SV_DispatchThreadID`는 디스패치 전체에서 각 스레드의 좌표를 제공한다. 호스트는 `imageSize`와 시간값을 설정하고, 출력 텍스처를 UAV로 바인딩한 다음 스레드 그룹 수를 정해 디스패치한다. 이 예제에서는 한 스레드가 출력 픽셀 하나를 맡는다.

`numthreads(8, 8, 1)`은 그룹 하나에 64개 스레드가 있다는 뜻이지, 이미지 전체에 64개 스레드만 실행한다는 뜻이 아니다. 예를 들어 가로·세로 그룹 수는 각 이미지 크기를 8로 나눈 값을 올림해 정한다. 그래서 마지막 그룹에서 이미지 범위를 벗어나는 스레드가 생길 수 있고, 코드의 경계 검사가 필요하다. 셰이더가 쓴 UAV를 이후 그래픽 패스에서 읽으려면 리소스 상태 전환과 필요한 메모리 동기화도 호스트 측에서 처리해야 한다.

그룹 관련 시스템 의미는 문제에 따라 다르게 사용한다.

| 시스템 의미 | 제공하는 좌표 |
| --- | --- |
| `SV_DispatchThreadID` | 전체 디스패치 안에서의 스레드 좌표 |
| `SV_GroupID` | 디스패치 안의 스레드 그룹 좌표 |
| `SV_GroupThreadID` | 현재 그룹 내부의 스레드 좌표 |
| `SV_GroupIndex` | 그룹 내부 스레드의 선형 인덱스 |

그룹 내부에서 공유 메모리나 동기화 장벽을 사용하면 스레드 사이의 데이터 교환을 만들 수 있다. 그러나 그룹 밖의 스레드가 항상 같은 순서로 실행된다고 가정해서는 안 된다. 스레드 간 의존 관계가 있다면 그룹 경계, UAV 접근, 메모리 장벽과 호스트의 리소스 동기화를 함께 설계한다.

## 어떤 단계를 선택할까

같은 수학 함수를 어느 셰이더에서 호출할지는 함수 자체보다 필요한 데이터 단위와 결과의 사용처에 따라 결정한다.

- 정점 위치나 법선을 이동해 메시의 실루엣을 바꾸려면 버텍스 셰이더를 고려한다.
- 표면의 색, 마스크, 조명 입력을 화면 표본마다 계산하려면 픽셀 셰이더를 사용한다.
- 입력 프리미티브를 선택적으로 확장하거나 제거해야 할 때 지오메트리 셰이더를 검토한다.
- 이미지·입자·필드처럼 독립적인 데이터 묶음을 대량 계산하고 그 결과를 저장해야 하면 컴퓨트 셰이더가 적합할 수 있다.

픽셀 셰이더는 보통 가시 표면의 여러 프래그먼트에서 실행되므로 복잡한 계산을 넣으면 비용이 커질 수 있다. 컴퓨트 셰이더는 데이터 접근과 출력 위치를 더 자유롭게 정하지만, 텍스처·버퍼 바인딩과 동기화를 직접 설계해야 한다. 단계 선택은 표현력뿐 아니라 작업량, 메모리 이동, 이후 렌더링에서 결과를 재사용하는 방식까지 고려해야 한다.

## 이 절의 핵심

버텍스 셰이더는 정점에서 클립 공간 위치와 전달 데이터를 만들고, 픽셀 셰이더는 보간된 값으로 프래그먼트 출력을 계산한다. 지오메트리 셰이더는 입력 프리미티브를 스트림으로 변형하거나 생성하며, 컴퓨트 셰이더는 `Dispatch`와 스레드 그룹으로 일반 데이터 병렬 작업을 수행한다. `SV_Position`, `SV_Target`, `SV_DispatchThreadID` 같은 의미는 단계별 입출력 계약을 드러낸다. 함수가 처리하는 데이터 단위와 결과가 소비되는 위치를 기준으로 셰이더 단계를 선택한다.
