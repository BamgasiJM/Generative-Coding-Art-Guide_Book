# 28.6 GPU 기반 패턴과 필드

GPU에서 절차적 패턴을 만들 때는 각 프래그먼트의 좌표를 함수에 넣어 스칼라값, 벡터값, 최종 색을 계산한다. HLSL은 이 계산을 픽셀 셰이더에서 병렬로 수행하므로, 전체 화면 패스에서는 한 번의 렌더 호출로 화면의 모든 위치에 패턴을 평가할 수 있다. 색칠을 위해 도형을 많이 만드는 대신 좌표에서 거리·파동·마스크를 계산해 이미지를 만든다.

이 절에서는 HLSL의 벡터 연산과 `lerp`, `frac`, `fwidth`를 사용해 주기적인 필드와 타일 패턴을 구성한다. 노이즈 알고리즘의 종류와 GLSL 전체 화면 예제는 27.7~27.8에서 다루었으므로 반복하지 않는다. 여기서는 HLSL에서 필드 계산을 조합하고 픽셀 결과로 연결하는 구조에 초점을 둔다.

## 픽셀 위치에서 필드까지

패턴 계산은 좌표 도메인을 선택하는 데서 시작한다. 전체 화면 효과라면 화면 UV를 사용하고, 메시 표면에 붙는 패턴이라면 정점 셰이더에서 전달한 오브젝트 위치나 UV를 쓴다. 월드 좌표를 사용하면 서로 다른 물체를 가로질러 이어지는 필드를 만들 수 있다. 어떤 공간의 좌표를 택하는지에 따라 패턴이 물체·장면·화면 중 어디에 고정되는지가 달라진다.

좌표를 함수에 넣으면 서로 다른 타입의 필드를 얻을 수 있다.

| 필드 | 예시 타입 | 패턴에서 하는 일 |
| --- | --- | --- |
| 스칼라 필드 | `float` | 거리, 높이, 밀도, 밝기, 마스크 |
| 벡터 필드 | `float2`, `float3` | 좌표 변위, 흐름 방향, 법선 변화 |
| 색 필드 | `float3`, `float4` | 픽셀 또는 재질의 최종 출력 |

스칼라 필드를 임계값으로 자르면 마스크가 되고, 반복 구간으로 접으면 줄무늬나 등고선이 된다. 벡터 필드는 좌표를 밀거나 방향을 나타내며, 색 필드는 여러 필드를 팔레트와 합성한 결과다. 이 값들이 연결되면 작은 수의 수학 함수로도 복잡한 화면을 구성할 수 있다.

## 좌표 왜곡과 타일 패턴

다음 예제는 전체 화면을 덮는 지오메트리의 픽셀 셰이더를 가정한다. `PSInput.uv`는 정점 단계에서 전달되어 0~1 범위로 보간된 UV이고, `targetSize`와 `time`은 호스트가 상수 버퍼에 설정한다. 좌표를 휘는 벡터 필드에 따라 반복 원형 패턴이 변형되고, 스칼라 필드는 색 띠를 만든다.

```c
cbuffer PatternParameters : register(b0)
{
    float2 targetSize;
    float time;
    float padding;
};

struct PSInput
{
    float4 position : SV_Position;
    float2 uv : TEXCOORD0;
};

float4 PSMain(PSInput input) : SV_Target0
{
    float2 p = input.uv * 2.0 - 1.0;
    p.x *= targetSize.x / targetSize.y;

    float t = time * 0.2;
    float2 warp = 0.12 * float2(
        sin(3.0 * p.y + t),
        cos(3.0 * p.x - t)
    );
    float2 q = p + warp;

    float2 cell = frac(q * 7.0) - 0.5;
    float distanceToDot = length(cell) - 0.2;
    float edgeWidth = max(fwidth(distanceToDot), 1e-4);
    float dotMask = 1.0 - smoothstep(-edgeWidth, edgeWidth, distanceToDot);

    float field = 0.5 + 0.5 * sin(2.0 * q.x - 3.0 * q.y + t);
    float bands = 0.5 + 0.5 * cos(16.0 * field);

    float3 darkColor = float3(0.02, 0.12, 0.20);
    float3 lightColor = float3(0.15, 0.72, 0.62);
    float3 accentColor = float3(0.95, 0.72, 0.30);
    float3 color = lerp(darkColor, lightColor, bands);
    color = lerp(color, accentColor, dotMask);

    return float4(color, 1.0);
}
```

`p`는 화면 중심이 원점이 되도록 UV를 변환한 좌표다. x축에 화면 종횡비를 곱해 원형 패턴이 직사각형 화면에서 타원으로 찌그러지는 것을 막는다. `warp`는 각 좌표에 더할 2차원 벡터이고, `q`는 변형된 좌표다. `frac(q * 7.0)`은 좌표를 반복 셀마다 접어 한 셀의 원을 화면 전체에 배열한다.

`distanceToDot`은 각 셀 중심의 원까지의 부호 있는 거리다. `distanceToDot < 0`인 영역이 원 내부이며, `smoothstep`으로 가장자리를 부드럽게 바꿔 마스크를 만든다. 별도의 `field`는 `q`에서 평가한 스칼라 파동이다. `bands`로 변환한 뒤 `lerp`를 사용해 두 색 사이를 오가게 하고, 마지막에 원 마스크로 강조색을 합성한다.

이 예제의 `warp`는 두 사인·코사인 함수를 벡터 성분으로 사용한 간단한 공간 변형이다. 두 성분의 주파수, 위상, 진폭을 바꾸면 패턴이 흐르는 방향과 굴곡이 달라진다. 실제 유체처럼 보이는 흐름이나 자연스러운 얼룩이 필요하다면 노이즈 기반 벡터 필드나 여러 스케일을 합성한 필드를 사용할 수 있다. 노이즈는 직접 구현하거나 검증된 텍스처·엔진 기능을 입력으로 사용하며, 각 알고리즘의 특성은 27.7을 참고한다.

## 픽셀 크기에 맞춘 경계

필드는 연속적인 좌표에서 계산되지만 화면은 이산적인 픽셀 격자다. 경계가 한 픽셀보다 얇거나 반복 주파수가 너무 높으면 선이 끊기고 깜빡이는 앨리어싱이 생길 수 있다. 예제의 `fwidth(distanceToDot)`은 화면의 x·y 방향에서 값이 얼마나 변하는지 추정하고, 그 크기를 `smoothstep`의 전환 폭에 사용한다.

HLSL의 미분 함수 `ddx`, `ddy`, `fwidth`는 픽셀 셰이더에서 사용할 수 있다. `fwidth(x)`는 화면 x와 y 방향에서의 변화량 크기를 결합한 값이다. 따라서 코드처럼 거리값에 따라 경계 폭을 정하면 해상도나 패턴 크기가 달라져도 가장자리를 비교적 안정적으로 표시한다. 이는 기하학적 도형의 외곽선을 실제로 늘리는 것이 아니라, 한 픽셀 안에서 경계가 차지하는 비율을 색으로 근사하는 안티앨리어싱이다.

보정 폭이 지나치게 넓으면 작은 원이나 얇은 띠가 흐려진다. 반대로 고주파 패턴을 계속 늘리면 미분 보정만으로 모든 세부를 보존할 수 없다. 출력 크기에서 보이지 않는 세부는 줄이거나, 밉맵 텍스처 또는 더 낮은 주파수의 필드를 고려한다.

## 같은 필드를 여러 결과에 연결하기

한 필드가 하나의 결과에만 쓰여야 하는 것은 아니다. 예를 들어 `field`를 색상 띠에 사용하면서 임계값으로 마스크를 만들고, 같은 마스크를 발광량이나 거칠기에도 연결할 수 있다. 하나의 원인 필드가 색과 표면 속성에 함께 반영되면 시각적으로 통일된 재질이 된다. 반대로 필드마다 서로 다른 공간과 주파수를 쓰면 색과 모양이 독립적으로 움직이는 느낌을 만들 수 있다.

픽셀 셰이더는 보통 현재 좌표와 파라미터를 입력으로 결과를 계산하며, 이전 프레임의 값을 자동으로 기억하지 않는다. 시간에 따라 움직이는 패턴도 `time`을 좌표 함수에 넣어 매 프레임 새로 평가하는 것이다. 잔상, 확산, 입자 위치처럼 이전 단계의 상태를 다음 프레임으로 넘겨야 한다면 렌더 타깃이나 GPU 버퍼를 별도 입력·출력으로 구성해야 한다.

## 픽셀 패턴과 컴퓨트 작업의 경계

이미지의 각 위치에서 색을 계산하는 것이 목적이면 전체 화면 픽셀 셰이더가 자연스럽다. 셰이더가 렌더 타깃의 각 픽셀을 채우고, 값의 공간적 이웃은 필요할 때 텍스처를 추가로 읽어 계산한다. 반면 입자 상태를 업데이트하거나 셀 그리드의 새 데이터를 버퍼에 기록하는 것처럼 출력이 화면 색이 아니라 일반 데이터라면 컴퓨트 셰이더가 더 적합할 수 있다.

이 구분은 속도만으로 결정되지 않는다. 픽셀 셰이더는 래스터화와 컬러 출력 경로에 자연스럽게 연결되고, 컴퓨트 셰이더는 쓰기 가능한 버퍼·텍스처와 명시적인 디스패치 구조를 제공한다. 필드가 화면에 표시될 최종 색인지, 이후 여러 렌더 단계에서 재사용할 데이터인지 먼저 정한다. 대규모 상태 갱신과 시뮬레이션 구조는 28.7에서 다룬다.

## 이 절의 핵심

HLSL 픽셀 셰이더는 화면 또는 표면의 좌표를 받아 스칼라·벡터 필드를 평가하고, `lerp`와 마스크를 조합해 픽셀 색으로 바꾼다. `frac`은 반복 좌표를 만들고, 좌표에 벡터 필드를 더하면 도메인을 변형할 수 있다. `fwidth` 기반 경계 보정은 필드의 윤곽을 픽셀 크기에 맞추지만, 지나치게 높은 주파수의 세부까지 복원하지는 않는다. 화면 색을 바로 계산하는 렌더링과 지속 상태를 갱신하는 컴퓨트 작업을 목적에 따라 나눈다.
