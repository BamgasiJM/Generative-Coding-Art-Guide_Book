# 30.4 격자와 타일 패턴

격자와 타일 패턴은 하나의 규칙을 공간 전체에 반복 적용해 만든다. 드로잉 API에서는 보이는 셀을 순회해 사각형과 선을 제출할 수 있고, 프래그먼트 셰이더에서는 각 위치를 셀 인덱스와 셀 내부 좌표로 나눠 같은 반복 규칙을 계산할 수 있다. 여기서는 바둑판처럼 번갈아 채운 정사각형 타일 위에 얇은 격자선을 그린다.

화면 중심을 원점으로 하고 짧은 변을 1로 정규화한 위치를 $\mathbf{p}=(x,y)$, 셀의 한 변 길이를 $s$라 하자. 위치를 셀 크기로 나누면 셀 인덱스와 셀 안의 위치가 분리된다.

$$
\mathbf{g} = \frac{\mathbf{p}}{s}, \qquad
\mathbf{i} = \lfloor \mathbf{g} \rfloor, \qquad
\mathbf{q} = \operatorname{fract}(\mathbf{g})
$$

정수 벡터 $\mathbf{i}$는 셀 번호이고, $\mathbf{q}$는 각 축에서 0 이상 1 미만인 셀 내부 좌표다. 바둑판 색은 $i_x+i_y$의 짝홀로 정한다. 이 절의 예제는 $s=0.16$을 사용하므로 짧은 변이 480픽셀일 때 셀 한 변은 76.8픽셀이다.

## p5.js: 셀을 순회하며 사각형과 선 그리기

p5.js에서는 현재 캔버스에 보이는 범위의 셀 인덱스를 구하고, 각 인덱스에 맞는 색의 사각형을 그린다. 그 뒤 셀 경계 위치를 순회해 수직선과 수평선을 겹쳐 격자를 만든다.

```javascript
function setup() {
  createCanvas(640, 480);
  pixelDensity(1);
  noLoop();
}

function draw() {
  const shortSide = Math.min(width, height);
  const cellSize = 0.16;
  const cellPixels = shortSide * cellSize;
  const tileA = [236, 92, 46];
  const tileB = [26, 123, 117];
  const gridColor = [14, 22, 34];

  const firstI = Math.floor((-width * 0.5) / cellPixels) - 1;
  const lastI = Math.ceil((width * 0.5) / cellPixels);
  const firstJ = Math.floor((-height * 0.5) / cellPixels) - 1;
  const lastJ = Math.ceil((height * 0.5) / cellPixels);

  background(...gridColor);
  noStroke();
  rectMode(CORNER);

  for (let j = firstJ; j <= lastJ; j++) {
    for (let i = firstI; i <= lastI; i++) {
      const x = width * 0.5 + i * cellPixels;
      const y = height * 0.5 - (j + 1) * cellPixels;
      const tileColor = (i + j) % 2 === 0 ? tileA : tileB;

      fill(...tileColor);
      rect(x, y, cellPixels, cellPixels);
    }
  }

  stroke(...gridColor);
  strokeWeight(shortSide * 0.003);

  for (let i = firstI; i <= lastI + 1; i++) {
    const x = width * 0.5 + i * cellPixels;
    line(x, 0, x, height);
  }

  for (let j = firstJ; j <= lastJ + 1; j++) {
    const y = height * 0.5 - j * cellPixels;
    line(0, y, width, y);
  }
}
```

`i`와 `j`는 화면 중심을 기준으로 한 셀 번호다. p5.js의 화면 y축은 아래로 증가하므로 수학 좌표의 셀 `j`가 커질수록 화면 사각형의 위쪽에 놓인다. 코드의 `height * 0.5 - (j + 1) * cellPixels`가 그 방향을 변환한다. 셀을 먼저 채우고 경계선을 나중에 그려야 내부 경계가 한 번의 선으로 정돈된다.

반복문의 실행 횟수는 화면에 들어오는 셀 수에 따라 달라진다. 화면 전체를 덮는 격자에서는 보통 셀 수에 비례해 사각형과 선 그리기 호출을 구성한다. 셀을 수십만 개로 늘릴 때에는 도형 호출을 계속 늘리는 대신 메시나 텍스처, 셰이더처럼 반복 계산을 다른 표현으로 옮기는 방법을 고려할 수 있다.

## GLSL: 셀 인덱스와 내부 좌표 계산하기

GLSL에서는 타일마다 사각형을 제출하지 않는다. 각 프래그먼트의 위치를 셀 단위로 변환하고, `floor()`로 셀 번호를, `fract()`로 셀 내부 좌표를 얻는다. 셀 번호는 타일의 색을 선택하고 내부 좌표는 셀 경계까지의 거리를 계산하는 데 사용한다.

```glsl
#version 460 core

uniform vec4 uViewport;
uniform float uCellSize;
uniform float uHalfLineWidth;
uniform vec3 uTileA;
uniform vec3 uTileB;
uniform vec3 uGridColor;

layout(location = 0) out vec4 outColor;

void main() {
    vec2 size = uViewport.zw;
    vec2 pixel = gl_FragCoord.xy - uViewport.xy;
    float shortSide = min(size.x, size.y);
    vec2 p = (pixel - 0.5 * size) / shortSide;

    vec2 gridCoordinate = p / uCellSize;
    vec2 cellIndex = floor(gridCoordinate);
    vec2 local = fract(gridCoordinate);

    float parity = mod(cellIndex.x + cellIndex.y, 2.0);
    vec3 tileColor = mix(uTileA, uTileB, parity);

    float edgeFraction = min(
        min(local.x, 1.0 - local.x),
        min(local.y, 1.0 - local.y)
    );
    float edgeDistance = edgeFraction * uCellSize;
    float aa = max(fwidth(edgeDistance), 1e-5);
    float gridMask = 1.0 - smoothstep(
        uHalfLineWidth - aa,
        uHalfLineWidth + aa,
        edgeDistance
    );

    vec3 color = mix(tileColor, uGridColor, gridMask);
    outColor = vec4(color, 1.0);
}
```

호스트 프로그램은 실제 프레임버퍼 픽셀 기준의 `(x, y, width, height)`를 `uViewport`로 전달하고 전체 화면을 덮는 도형을 렌더링한다. `uCellSize`는 양수여야 한다. `uCellSize`를 `0.16`, `uHalfLineWidth`를 `0.0015`로 설정하면 앞의 p5.js 예제와 셀 크기 및 명목상 선 두께가 대응한다. 선의 전체 두께는 반폭의 두 배이므로 정규화 좌표에서 0.003, 즉 짧은 변이 480픽셀일 때 약 1.44픽셀이다. p5.js의 기본 RGB 입력값은 0~255이므로 GLSL 색상 유니폼에는 각 채널을 255로 나눈 값을 전달한다. 가장자리 색까지 정확히 비교하려면 호스트의 색 공간과 출력 변환도 일치시켜야 한다.

`floor()`는 음수 좌표에서도 셀 인덱스를 일관되게 나누고, `fract()`는 셀마다 반복되는 0~1 범위의 내부 좌표를 만든다. 화면 중심을 기준으로 그리드를 놓았기 때문에 GLSL의 셀 번호와 p5.js의 `i`, `j`가 같은 위치에서 같은 짝홀을 가진다. `mod(cellIndex.x + cellIndex.y, 2.0)`은 두 인덱스의 합이 짝수인지 홀수인지 판정한다.

`edgeFraction`은 셀 내부에서 네 변 중 가장 가까운 변까지의 거리를 셀 크기 기준으로 나타낸다. 여기에 `uCellSize`를 곱해 정규화 화면 좌표의 거리로 바꾸고, 반선폭을 빼서 경계 마스크를 만든다. `fwidth()`는 이 거리가 한 픽셀에서 얼마나 변하는지 추정하며 `smoothstep()`은 경계의 색 전이를 부드럽게 한다. 안티앨리어싱 덕분에 셀 경계가 픽셀 사이를 지나도 선이 계단처럼 보이는 현상을 줄일 수 있다.

## 반복 규칙은 같고 계산 단위는 다르다

| 비교 항목 | p5.js | GLSL 프래그먼트 셰이더 |
| --- | --- | --- |
| 셀 구분 | 중첩 반복문의 정수 인덱스 `i`, `j` | 각 위치에 `floor(p / uCellSize)` 적용 |
| 셀 내부 좌표 | 사각형의 꼭짓점과 크기를 직접 계산 | `fract(p / uCellSize)`로 계산 |
| 타일 색 | 셀마다 `fill()`을 선택 | 인덱스 짝홀로 색을 선택 |
| 격자선 | 화면을 가로지르는 `line()` 명령 | 프래그먼트와 셀 경계 사이의 거리로 마스크 계산 |
| 반복 규모 | 보이는 셀과 선의 수에 따라 그리기 명령 증가 | 화면의 각 프래그먼트에서 셀 규칙 평가 |

같은 $s$와 색, 그리드 원점, 선 폭을 사용하면 패턴의 배치는 대응한다. 다만 p5.js는 타일을 개별 사각형으로 만들고 별도의 선을 그리는 반면, GLSL은 한 번의 화면 도형 안에서 모든 셀의 결과를 계산한다. 또 p5.js 경로의 래스터화와 셰이더의 `fwidth()` 기반 마스크는 가장자리 표본화가 다르므로 경계 픽셀이 완전히 같아지지는 않을 수 있다.

`fract()`는 셀 안의 좌표를 반복시키므로 격자뿐 아니라 타일마다 되풀이되는 점·원·아이콘에도 쓸 수 있다. 셀 내부 좌표를 이용해 타일마다 같은 도형을 그린 뒤, 셀 인덱스를 추가 입력으로 사용하면 색이나 크기에 규칙적인 변화를 줄 수 있다. 좌표를 셀 단위로 바꾸는 이 발상은 반복되는 문양과 텍스처를 만드는 데 공통으로 활용된다.

성능은 어느 구현이 언제나 빠르다고 단정할 수 없다. p5.js의 작업량은 셀 수와 제출하는 도형·선 명령에 영향을 받고, GLSL은 셀 수와 무관하게 화면에 그려지는 프래그먼트마다 셀 계산을 수행한다. 셀이 화면보다 훨씬 많거나 패턴이 복잡하다면 양쪽의 실제 렌더 비용을 목표 해상도와 하드웨어에서 측정해야 한다.

## 이 절의 핵심

격자는 위치를 셀 번호와 셀 내부 좌표로 분해하면 간결하게 표현할 수 있다. p5.js는 셀 인덱스를 순회해 사각형과 선을 제출하고, GLSL은 `floor()`와 `fract()`로 각 프래그먼트가 속한 셀을 계산한다. 동일한 패턴을 비교하려면 셀 크기와 그리드 원점, 짝홀 규칙, 선 폭, y축 방향을 맞추고, 래스터화와 안티앨리어싱의 차이는 별도로 고려한다.
