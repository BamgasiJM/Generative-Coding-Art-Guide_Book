# 30.7 노이즈 필드

노이즈 필드는 공간의 각 위치에 연속적으로 변하는 값을 대응시킨다. 이 값으로 회색 명암을 만들거나, 임계값에 따라 영역을 나누거나, 이후 절의 흐름 필드처럼 다른 계산의 입력을 만들 수 있다. 여기서는 같은 2D 값 노이즈를 p5.js와 GLSL에 각각 구현하고, p5.js는 일정 간격의 블록으로 표본화하며 셰이더는 화면의 각 프래그먼트에서 평가한다.

공정한 비교를 위해 p5.js의 내장 `noise()`와 서로 다른 GLSL 해시 함수를 곧바로 맞대지 않는다. 라이브러리별 내장 함수는 알고리즘과 좌표·시드 관례가 다를 수 있다. 대신 양쪽에서 같은 격자 해시와 5차 보간 함수를 사용한다. 격자 꼭짓점마다 결정적인 값을 만들고 그 사이를 부드럽게 보간하는 값 노이즈다.

계산 좌표 $\mathbf{p}$의 정수부는 격자 셀을, 소수부는 셀 내부 위치를 나타낸다. 각 셀 꼭짓점의 값은 정수 격자 좌표를 해시해 얻고, 다음 5차 곡선으로 가중치를 만든다.

$$
f(t) = 6t^5 - 15t^4 + 10t^3
$$

이 곡선은 셀 경계에서 값뿐 아니라 1차·2차 미분도 부드럽게 이어준다. 예제는 옥타브를 더하지 않은 단일 노이즈 층을 사용해, 노이즈 알고리즘 자체와 표본 밀도의 차이를 분리한다.

## p5.js: 일정 간격으로 필드를 표본화하기

JavaScript 쪽에서는 정수 격자 좌표를 32비트 해시로 바꾸고, 네 꼭짓점의 값을 5차 가중치로 보간한다. 이 함수를 캔버스의 4픽셀 간격 표본에 적용하고, 각 결과를 작은 회색 사각형으로 표시한다.

```javascript
function hashLattice(ix, iy) {
  let n = (Math.imul(ix, 0x1f123bb5) ^ Math.imul(iy, 0x5f356495)) >>> 0;
  n ^= n >>> 16;
  n = Math.imul(n, 0x7feb352d) >>> 0;
  n ^= n >>> 15;
  n = Math.imul(n, 0x846ca68b) >>> 0;
  n ^= n >>> 16;
  return (n & 0x00ffffff) / 16777215;
}

function fade5(t) {
  return t * t * t * (t * (t * 6 - 15) + 10);
}

function mixValue(a, b, t) {
  return a + (b - a) * t;
}

function valueNoise2D(x, y) {
  const ix = Math.floor(x);
  const iy = Math.floor(y);
  const fx = x - ix;
  const fy = y - iy;
  const u = fade5(fx);
  const v = fade5(fy);

  const a = hashLattice(ix, iy);
  const b = hashLattice(ix + 1, iy);
  const c = hashLattice(ix, iy + 1);
  const d = hashLattice(ix + 1, iy + 1);

  return mixValue(mixValue(a, b, u), mixValue(c, d, u), v);
}

function setup() {
  createCanvas(640, 480);
  pixelDensity(1);
  noLoop();
}

function draw() {
  const shortSide = Math.min(width, height);
  const frequency = 5.0;
  const sampleStep = 4;
  noStroke();
  background(14, 22, 34);

  for (let y = 0; y < height; y += sampleStep) {
    for (let x = 0; x < width; x += sampleStep) {
      const sampleX = x + sampleStep * 0.5;
      const sampleY = y + sampleStep * 0.5;
      const px = (sampleX - width * 0.5) / shortSide;
      const py = (height * 0.5 - sampleY) / shortSide;
      const value = valueNoise2D(px * frequency, py * frequency);

      fill(value * 255);
      rect(x, y, sampleStep, sampleStep);
    }
  }
}
```

`frequency`는 정규화된 화면 좌표를 노이즈 격자 좌표로 확대한다. 값이 커질수록 같은 화면 안에 더 많은 변화가 들어간다. p5.js 표본점은 각 4×4픽셀 블록의 중심이며, 그 한 값으로 블록 전체를 칠한다. 따라서 이 예제의 계단 모양은 노이즈 보간이 불연속이어서가 아니라, 연속 필드를 4픽셀 간격으로 평가한 결과를 확대해 보여주기 때문에 생긴다.

해시 함수는 난수 시드를 받지 않고 고정된 정수 연산을 사용하므로 같은 격자 좌표에는 언제나 같은 값이 나온다. JavaScript의 `Math.imul()`과 비트 연산은 정수의 하위 32비트를 사용해 GLSL의 `uint` 해시와 같은 계산을 만든다. 다만 최종 보간은 JavaScript의 배정밀도와 GLSL의 일반적인 단정밀도 부동소수점에서 수행되므로 모든 결과 비트가 같다고 가정하지 않는다.

## GLSL: 프래그먼트마다 같은 함수를 평가하기

GLSL에서는 각 프래그먼트 위치를 같은 정규화 좌표로 변환하고, 같은 해시·보간 규칙을 적용한다. 아래 코드는 노이즈 스칼라값을 회색으로 출력하며 `uFrequency`는 앞의 예제와 같이 5.0으로 설정한다.

```glsl
#version 460 core

uniform vec4 uViewport;
uniform float uFrequency;

layout(location = 0) out vec4 outColor;

uint hashLattice(ivec2 cell) {
    uint n = (uint(cell.x) * 0x1f123bb5u) ^ (uint(cell.y) * 0x5f356495u);
    n ^= n >> 16;
    n *= 0x7feb352du;
    n ^= n >> 15;
    n *= 0x846ca68bu;
    n ^= n >> 16;
    return n & 0x00ffffffu;
}

float latticeValue(ivec2 cell) {
    return float(hashLattice(cell)) / 16777215.0;
}

float fade5(float t) {
    return t * t * t * (t * (t * 6.0 - 15.0) + 10.0);
}

float valueNoise2D(vec2 p) {
    ivec2 cell = ivec2(floor(p));
    vec2 f = fract(p);
    vec2 u = vec2(fade5(f.x), fade5(f.y));

    float a = latticeValue(cell);
    float b = latticeValue(cell + ivec2(1, 0));
    float c = latticeValue(cell + ivec2(0, 1));
    float d = latticeValue(cell + ivec2(1, 1));

    return mix(mix(a, b, u.x), mix(c, d, u.x), u.y);
}

void main() {
    vec2 size = uViewport.zw;
    vec2 pixel = gl_FragCoord.xy - uViewport.xy;
    float shortSide = min(size.x, size.y);
    vec2 p = (pixel - 0.5 * size) / shortSide;

    float value = valueNoise2D(p * uFrequency);
    outColor = vec4(vec3(value), 1.0);
}
```

호스트는 실제 프레임버퍼 픽셀 단위의 `(x, y, width, height)`를 `uViewport`로 보내고 전체 화면을 덮는 도형을 렌더링한다. 이 노이즈 함수의 값은 0~1 범위이므로 p5.js에서는 `value * 255`로 회색을 지정하고 GLSL에서는 값을 그대로 `vec3`에 전달한다. 최종 밝기까지 비교하려면 호스트의 색 공간과 출력 변환도 같게 맞춘다. `gl_FragCoord`의 기본 원점은 뷰포트 왼쪽 아래이므로 GLSL의 `p.y`는 위쪽으로 증가한다. p5.js 코드에서도 표본의 y좌표를 `height * 0.5 - sampleY`로 변환해 같은 방향의 필드를 계산한다.

GLSL에서 `floor()`로 얻은 셀 번호는 `ivec2`로 바뀌고, 정수 좌표는 unsigned 해시로 전달된다. `fract()`로 얻은 셀 내부 좌표에는 JavaScript와 같은 5차 가중치를 적용한다. 이처럼 두 환경의 격자 해시와 보간식을 통일하면 함수 수준의 비교가 가능하다. `uFrequency`, 화면 크기, 좌표 원점 중 하나라도 다르면 해시와 보간이 같아도 화면에 나타나는 무늬는 달라진다.

## 필드는 같아도 표본은 다르다

| 비교 항목 | p5.js | GLSL 프래그먼트 셰이더 |
| --- | --- | --- |
| 노이즈 함수 | 직접 작성한 2D 값 노이즈 | 같은 정수 해시와 5차 보간을 사용한 값 노이즈 |
| 위치 입력 | 블록 중심의 정규화 좌표 | 각 프래그먼트의 정규화 좌표 |
| 출력 단위 | 한 번의 평가값을 4×4픽셀 사각형에 적용 | 픽셀마다 한 번 평가해 출력 색으로 변환 |
| 품질을 조절하는 값 | `sampleStep`과 캔버스 픽셀 밀도 | 프레임버퍼 해상도와 셰이더 평가량 |
| 반복 비용 | 표본마다 해시와 보간을 계산하고 사각형 명령을 제출 | 프래그먼트마다 해시와 보간을 수행 |

두 구현은 같은 연속 함수를 정의하지만 p5.js의 4픽셀 표본은 셰이더의 픽셀별 결과와 완전히 겹치지 않는다. `sampleStep`을 1로 낮추면 p5.js도 픽셀 단위로 표본화할 수 있지만, 640×480 캔버스에서 약 30만 개의 사각형 그리기 명령을 구성하게 된다. 실제로는 픽셀 버퍼를 직접 채우거나 표본 해상도를 낮추고, 셰이더는 전체 화면에 대해 병렬로 값을 계산하는 식으로 작업 표현이 달라질 수 있다. 어느 구현이 더 빠른지는 해상도와 백엔드, 노이즈 계산량에 따라 측정해야 한다.

노이즈 주파수를 픽셀 표본이 표현할 수 있는 한계보다 높이면 어느 방식에서도 앨리어싱이 생길 수 있다. p5.js는 `sampleStep`을 줄여 표본 밀도를 높일 수 있고, 셰이더는 렌더 해상도를 높이거나 화면 공간 미분에 맞춘 필터링을 적용할 수 있다. 또한 여러 주파수 층을 합산하는 fBm에서는 옥타브마다 노이즈 함수를 추가로 평가하므로, 옥타브 수와 표본 수를 따로 기록해야 성능을 비교할 수 있다. 여기서는 함수와 표본화의 차이에 집중하기 위해 단일 옥타브만 사용했다.

## 이 절의 핵심

노이즈 비교에서는 같은 이름의 내장 함수를 호출했는지가 아니라 격자 값, 해시, 보간, 좌표와 주파수가 같은지를 확인해야 한다. 이 예제는 공유 가능한 정수 격자 해시와 5차 보간으로 하나의 값 노이즈 함수를 정의한 뒤, p5.js에서는 블록 표본으로, GLSL에서는 프래그먼트별 표본으로 평가한다. 따라서 보이는 차이와 비용은 노이즈 수학뿐 아니라 표본 간격, 해상도, 출력 방식에서 비롯된다.
