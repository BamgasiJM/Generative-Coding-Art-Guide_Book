# 30.5 방사형 패턴

방사형 패턴은 화면 중심에서의 거리와 방향을 이용해 만든다. 여기서는 같은 중심을 공유하는 동심원과 일정한 각도 간격의 방사선을 그린다. p5.js는 각 원과 선을 도형 명령으로 제출하고, GLSL 프래그먼트 셰이더는 각 화면 위치의 반지름과 각도를 계산해 원형·방사형 경계까지의 거리를 구한다.

화면 중심을 원점으로 하고 짧은 변을 1로 정규화한 위치를 $\mathbf{p}=(x,y)$라고 하면 극좌표는 다음과 같다.

$$
r = \lVert \mathbf{p} \rVert, \qquad
\theta = \operatorname{atan2}(y,x)
$$

동심원의 반지름은 $r_n = n\Delta r$이고, $\Delta r$은 링 사이 간격이다. 방사선 $N$개는 $\theta_k = 2\pi k/N$의 방향을 향한다. 두 구현에서 $\Delta r=0.10$, $N=16$, 선의 전체 두께는 정규화 단위 0.003으로 맞춘다. 짧은 변이 480픽셀이라면 링 간격은 48픽셀, 명목 선 두께는 약 1.44픽셀이다.

## p5.js: 원과 선을 반복해서 배치하기

p5.js에서는 동심원의 반지름을 증가시키며 `circle()`을 호출하고, 각도별로 중심에서 캔버스 모서리까지 `line()`을 그린다. 캔버스 중심을 수학적 원점으로 취급하고 y축 방향을 화면 좌표로 변환한다.

```javascript
function setup() {
  createCanvas(640, 480);
  pixelDensity(1);
  noLoop();
}

function draw() {
  const shortSide = Math.min(width, height);
  const ringSpacing = 0.10;
  const spokeCount = 16;
  const maxRadius = Math.hypot(width * 0.5, height * 0.5) / shortSide;
  const centerX = width * 0.5;
  const centerY = height * 0.5;

  background(14, 22, 34);
  noFill();
  stroke(236, 92, 46);
  strokeWeight(shortSide * 0.003);

  for (let radius = ringSpacing; radius <= maxRadius; radius += ringSpacing) {
    const diameter = 2 * radius * shortSide;
    circle(centerX, centerY, diameter);
  }

  for (let i = 0; i < spokeCount; i++) {
    const angle = TWO_PI * i / spokeCount;
    const endX = centerX + Math.cos(angle) * maxRadius * shortSide;
    const endY = centerY - Math.sin(angle) * maxRadius * shortSide;
    line(centerX, centerY, endX, endY);
  }
}
```

`maxRadius`는 중심에서 캔버스의 가장 먼 모서리까지의 정규화 거리다. 이 길이까지 선을 뻗으면 가로세로 비율이 달라도 모든 모서리까지 방사선이 닿는다. y좌표의 `- Math.sin(angle)`은 수학 좌표의 위쪽 방향을 p5.js 캔버스의 아래쪽 방향으로 바꾼다. 첫 링은 중심에 그리지 않고 반지름 `ringSpacing`부터 시작한다.

이 구현에서 그리기 호출 수는 링 개수와 방사선 개수에 따라 증가한다. 링 사이 간격을 좁히면 더 많은 `circle()` 명령이 필요하고, 방사선 수를 늘리면 `line()` 명령도 늘어난다. 도형을 개별적으로 지정하므로 각 원과 선의 위치·색·두께를 직접 제어하기 쉽다.

## GLSL: 반지름과 각도에서 경계까지의 거리 구하기

프래그먼트 셰이더에서는 `gl_FragCoord`를 뷰포트 중심 기준의 정규화 좌표로 바꾼 뒤, `length()`와 `atan()`으로 극좌표를 구한다. 링 경계와 방사선까지의 거리를 각각 계산해 하나의 마스크로 합친다.

```glsl
#version 460 core

uniform vec4 uViewport;
uniform float uRingSpacing;
uniform int uSpokeCount;
uniform float uHalfLineWidth;
uniform vec3 uBackground;
uniform vec3 uPatternColor;

layout(location = 0) out vec4 outColor;

void main() {
    const float TAU = 6.28318530718;

    vec2 size = uViewport.zw;
    vec2 pixel = gl_FragCoord.xy - uViewport.xy;
    float shortSide = min(size.x, size.y);
    vec2 p = (pixel - 0.5 * size) / shortSide;
    float radius = length(p);

    float ringIndex = max(1.0, floor(radius / uRingSpacing + 0.5));
    float ringDistance = abs(radius - ringIndex * uRingSpacing);
    float ringAA = max(fwidth(ringDistance), 1e-5);
    float ringMask = 1.0 - smoothstep(
        uHalfLineWidth - ringAA,
        uHalfLineWidth + ringAA,
        ringDistance
    );

    vec2 angularPosition = p;
    if (dot(p, p) < 1e-12) {
        angularPosition = vec2(1e-6, 0.0);
    }

    float angle = atan(angularPosition.y, angularPosition.x);
    float sector = TAU / float(uSpokeCount);
    float deltaAngle = mod(angle + 0.5 * sector, sector) - 0.5 * sector;
    float spokeDistance = radius * abs(sin(deltaAngle));
    float spokeAA = max(fwidth(spokeDistance), 1e-5);
    float spokeMask = 1.0 - smoothstep(
        uHalfLineWidth - spokeAA,
        uHalfLineWidth + spokeAA,
        spokeDistance
    );

    float patternMask = max(ringMask, spokeMask);
    vec3 color = mix(uBackground, uPatternColor, patternMask);
    outColor = vec4(color, 1.0);
}
```

호스트는 실제 프레임버퍼 픽셀 단위의 `(x, y, width, height)`를 `uViewport`로 전달하고 화면 전체를 덮는 도형을 그린다. `uRingSpacing`은 양수, `uSpokeCount`는 2 이상의 정수로 둔다. 앞의 p5.js 예제와 맞추려면 `uRingSpacing = 0.10`, `uSpokeCount = 16`, `uHalfLineWidth = 0.0015`를 사용한다. `uHalfLineWidth`는 전체 선 두께가 아니라 반폭이다.

가장 가까운 링의 번호는 `floor(radius / uRingSpacing + 0.5)`로 구한다. 중심에는 링을 그리지 않으므로 번호가 0이 되지 않도록 `max(1.0, ...)`을 적용한다. 이렇게 하면 중심에 반지름 0인 추가 원을 만들지 않고, 실제로 그린 첫 링부터 거리를 잰다.

각 방사선의 각도 간격은 `sector = 2π / N`이다. `mod()`를 이용해 현재 각도에서 가장 가까운 방사선까지의 각도 차이를 $-\text{sector}/2$와 $\text{sector}/2$ 사이로 접는다. 그 각도 차이를 $\delta\theta$라 할 때, 해당 방사선까지의 거리는 $r|\sin(\delta\theta)|$다. $N\ge2$이면 가장 가까운 방향은 반지름 방향으로 투영되는 구간에 있으므로 이 식은 중심에서 뻗는 선분까지의 수직 거리로 쓸 수 있다.

중심에서는 방향각이 정의되지 않는다. 일부 구현에서 `atan(0, 0)`은 유효한 각도를 보장하지 않으므로 코드에서는 위치가 원점에 매우 가까울 때 각도 계산용 벡터를 작은 값으로 대체한다. 반지름은 원래 `p`에서 계산한 값을 계속 사용하므로 이 보정은 중심의 방사선 거리를 바꾸지 않는다.

## 중심 주변의 표본과 가장자리

극좌표는 중심에서 특이점을 갖는다. 반지름은 0으로 부드럽게 줄어들지만 방향각은 중심에서 정해지지 않는다. 또한 각도 간격이 같더라도 반지름이 작아질수록 화면에서 이웃한 방사선 사이의 거리가 좁아진다. 따라서 중심 가까이에서는 여러 선이 한두 픽셀 폭 안에 모여 서로 합쳐져 보일 수 있다. 이는 단순한 코드 오류라기보다 연속적인 방사형 무늬를 유한한 픽셀 격자로 표본화할 때 생기는 한계다.

코드의 `fwidth()`는 링이나 방사선 경계까지의 거리가 프래그먼트 주변에서 변하는 정도를 추정해 `smoothstep()` 전이 폭에 반영한다. 화면에서 선이 한 픽셀보다 가늘 때 계단 현상을 줄이는 데 도움이 되지만, 중심의 방향각 변화가 매우 빠른 구간에서 서로 구분되지 않는 방사선을 복원하지는 못한다. 중심의 과밀한 무늬를 완화하려면 중심에 작은 빈 영역을 두거나, 반지름에 따라 방사선 수를 줄이는 별도 규칙을 추가할 수 있다. 이 예제는 두 구현의 규칙을 대응시키기 위해 방사선 수를 일정하게 유지한다.

| 비교 항목 | p5.js | GLSL 프래그먼트 셰이더 |
| --- | --- | --- |
| 동심원 | 반지름을 늘려 `circle()` 반복 호출 | `radius`에서 가장 가까운 링까지 거리 계산 |
| 방사선 | 각도별 끝점을 계산해 `line()` 호출 | 각도를 섹터 주기로 접어 선까지 거리 계산 |
| 중심·방향 | 캔버스 중심과 삼각함수 좌표로 구성 | 뷰포트 중심 좌표에서 `length()`·`atan()` 평가 |
| 경계 처리 | 그래픽 백엔드가 원과 선의 래스터화를 처리 | 거리 필드와 `fwidth()`로 마스크 구성 |
| 중심 주변 | 겹치는 도형과 래스터화 결과로 표현 | 각도 특이점과 픽셀 내 방사선 과밀에 영향받음 |

수학적 패턴은 같지만 p5.js는 도형 명령을 링과 방사선 수만큼 제출하고, GLSL은 화면을 덮는 각 프래그먼트에서 극좌표와 경계 거리를 계산한다. 비용이 어느 쪽에서 더 낮은지는 링·방사선 수뿐 아니라 화면 해상도와 구현 백엔드에 따라 달라진다. 셰이더는 도형 수가 늘어도 전체 화면의 프래그먼트를 처리하고, 드로잉 API는 화면에 필요한 도형만 구성한다는 차이를 고려해 실제 환경에서 측정해야 한다.

## 이 절의 핵심

동심원과 방사선은 반지름과 각도를 이용해 같은 화면 패턴으로 만들 수 있다. p5.js는 원과 선분을 직접 배치하고, GLSL은 프래그먼트마다 링·방사선 경계까지의 거리를 계산해 마스크를 만든다. 좌표 중심과 단위, y축 방향, 링 간격, 방사선 개수를 맞춰 비교하되, 중심의 각도 특이점과 중심부의 픽셀 표본 한계는 방사형 패턴 특유의 조건으로 살펴야 한다.
