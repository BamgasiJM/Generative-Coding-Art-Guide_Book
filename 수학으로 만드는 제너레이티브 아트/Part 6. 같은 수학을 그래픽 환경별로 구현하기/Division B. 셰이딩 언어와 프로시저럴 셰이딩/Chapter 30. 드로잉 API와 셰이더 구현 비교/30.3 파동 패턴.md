# 30.3 파동 패턴

주기 함수로 만든 파동은 드로잉 API와 프래그먼트 셰이더의 계산 단위 차이를 보기 좋은 예다. 여기서는 같은 사인 곡선을 p5.js에서는 정점이 있는 경로로 그리고, GLSL에서는 각 프래그먼트가 파동까지의 근사 거리를 계산해 띠로 표시한다. 파형은 다음 식으로 고정한다.

$$
y(x) = A\sin\left(\frac{2\pi}{\lambda}x + \phi\right)
$$

여기서 $A$는 진폭, $\lambda$는 한 주기의 길이, $\phi$는 위상이다. $\lambda$는 양수이며, 사인 함수에 넣는 위상은 라디안 단위다. 두 예제 모두 화면의 짧은 변을 1 단위로 정규화해 계산한다. 따라서 캔버스가 640×480일 때 $A=0.12$는 57.6픽셀의 진폭이고, $\lambda=0.55$는 264픽셀의 파장이다. 화면을 넓히거나 세로로 늘려도 짧은 변을 기준으로 파형 크기가 유지된다.

## p5.js: 곡선을 표본화해 경로로 그리기

p5.js에서는 x 위치를 일정 간격으로 순회하면서 사인 함수의 y를 계산하고, 결과를 `vertex()`로 연결한다. 다음 코드는 화면 좌표의 원점이 왼쪽 위이고 y축이 아래로 증가한다는 p5.js의 관례에 맞춰 수학 좌표의 y를 화면 좌표로 뒤집는다.

```javascript
function setup() {
  createCanvas(640, 480);
  pixelDensity(1);
  noLoop();
}

function draw() {
  const shortSide = Math.min(width, height);
  const amplitude = 0.12;
  const wavelength = 0.55;
  const phase = 0.0;
  const segments = Math.ceil(width / 2);

  background(14, 22, 34);
  noFill();
  stroke(236, 92, 46);
  strokeWeight(shortSide * 0.012);
  strokeCap(ROUND);

  beginShape();
  for (let i = 0; i <= segments; i++) {
    const pixelX = width * i / segments;
    const x = (pixelX - width * 0.5) / shortSide;
    const y = amplitude * Math.sin(TWO_PI * x / wavelength + phase);
    const pixelY = height * 0.5 - y * shortSide;
    vertex(pixelX, pixelY);
  }
  endShape();
}
```

`segments`는 캔버스 너비를 약 2픽셀 간격으로 나눈 선분 수다. 각 정점은 파동 위의 한 점이며, 렌더러는 이 점들을 직선으로 연결해 경로를 그린다. 파장이 짧아지거나 곡선의 진폭이 커져 굴곡이 심해지면 표본 간격을 더 좁혀야 직선 조각이 눈에 띄지 않는다. 여기서 `strokeWeight()`는 경로의 전체 두께를 픽셀 단위로 지정한다.

`pixelDensity(1)`은 논리 캔버스 픽셀과 프레임버퍼 픽셀을 일치시켜 예제의 단위를 단순하게 만든다. 고해상도 디스플레이에서 이를 생략한다면 셰이더에 전달할 뷰포트 크기는 논리 크기가 아니라 실제 렌더 타깃의 픽셀 크기여야 한다.

## GLSL: 각 프래그먼트에서 파동 필드 평가하기

프래그먼트 셰이더에는 선 경로 대신 화면 위치가 들어온다. 같은 파동 함수로 해당 x에서의 곡선 높이를 계산하고, 프래그먼트가 곡선 띠 안에 있는지 판정한다. 아래 예제는 짧은 변을 1로 정규화하며, `uViewport`는 실제 프레임버퍼 픽셀 단위의 `(x, y, width, height)`다. 호스트는 이 뷰포트를 설정하고 화면 전체를 덮는 삼각형이나 사각형을 렌더링해야 한다.

```glsl
#version 460 core

uniform vec4 uViewport;
uniform float uAmplitude;
uniform float uWavelength;
uniform float uPhase;
uniform float uHalfWidth;
uniform vec3 uBackground;
uniform vec3 uWaveColor;

layout(location = 0) out vec4 outColor;

void main() {
    vec2 size = uViewport.zw;
    vec2 pixel = gl_FragCoord.xy - uViewport.xy;
    float shortSide = min(size.x, size.y);
    vec2 p = (pixel - 0.5 * size) / shortSide;

    float k = 6.28318530718 / uWavelength;
    float angle = k * p.x + uPhase;
    float waveY = uAmplitude * sin(angle);
    float slope = uAmplitude * k * cos(angle);

    float distanceToWave = abs(p.y - waveY) * inversesqrt(1.0 + slope * slope);
    float d = distanceToWave - uHalfWidth;
    float aa = max(fwidth(d), 1e-5);
    float mask = 1.0 - smoothstep(-aa, aa, d);

    vec3 color = mix(uBackground, uWaveColor, mask);
    outColor = vec4(color, 1.0);
}
```

호스트는 `uAmplitude = 0.12`, `uWavelength = 0.55`, `uPhase = 0.0`을 전달한다. 전체 선 두께를 p5.js 예제의 0.012 단위와 맞추려면 반폭인 `uHalfWidth = 0.006`을 사용한다. 셰이더 좌표는 뷰포트 중심이 원점이고 y가 위로 증가한다. `gl_FragCoord`의 기본 원점은 뷰포트 왼쪽 아래이므로, 화면의 아래쪽 원점을 쓰는 p5.js 경로와 파형 방향을 맞추려면 앞의 `pixelY = height * 0.5 - y * shortSide`처럼 y축을 뒤집는다.

`abs(p.y - waveY)`는 같은 x에서 곡선까지의 수직 차이다. 여기에 파형의 기울기 $y'(x)=A(2\pi/\lambda)\cos(2\pi x/\lambda+\phi)$를 이용한 보정값 $\sqrt{1+y'(x)^2}$를 나누면 곡선의 접선에 수직인 거리의 국소 근사가 된다. 이 값에서 반폭을 빼면 선의 안팎을 나타내는 부호 필드가 된다. `fwidth(d)`와 `smoothstep()`은 경계가 픽셀을 가로지를 때 마스크를 부드럽게 만들어 계단 현상을 줄인다.

이 접선 거리 계산은 곡선의 가장 가까운 점을 반복해서 찾는 정확한 최단 거리 공식이 아니다. 완만한 파형과 가는 선에서는 유용하지만, 진폭이 크거나 파장이 매우 짧아 곡률이 큰 경우 실제 경로 스트로크와 두께나 가장자리 모양이 달라질 수 있다. 그런 경우에는 최근접점 계산을 추가하거나, 셰이더에서도 선분 메시를 그려야 한다.

## 두 표현을 같은 기준으로 읽기

| 비교 항목 | p5.js 경로 | GLSL 프래그먼트 필드 |
| --- | --- | --- |
| 수학 규칙 | 각 표본 x에서 사인 함수로 y 계산 | 각 프래그먼트 x에서 같은 사인 함수로 `waveY` 계산 |
| 화면 좌표 | 중심 이동 후 픽셀 좌표로 변환, y축 아래 방향 | 뷰포트 중심 기준 정규화 좌표, y축 위 방향 |
| 계산 결과 | `vertex()`로 연결할 경로 표본 | 파동 띠까지의 거리와 색 마스크 |
| 선 두께 | `strokeWeight()`의 전체 두께 | `uHalfWidth`의 두 배를 전체 두께로 사용 |
| 가장자리 | 경로 렌더러의 스트로크 래스터화 | `fwidth()`와 `smoothstep()`으로 마스크 전이 |
| 표본화 | 코드가 만든 정점 간격에 영향받음 | 프래그먼트와 화면 픽셀의 표본화에 영향받음 |

차이는 수학 함수가 아니라 함수 평가와 결과 표현에 있다. p5.js는 x축을 따라 제한된 수의 정점을 계산해 경로를 제출하고, 셰이더는 화면을 덮는 도형의 프래그먼트마다 파동 식과 띠 마스크를 계산한다. 따라서 p5.js의 `segments`와 선 두께는 경로의 기하 표현을 조절하고, 셰이더의 `uHalfWidth`와 픽셀 단위의 안티앨리어싱 폭은 필드에서 화면 마스크로 바꾸는 과정을 조절한다.

## 위상으로 파형 이동시키기

파동을 애니메이션하려면 위상에 시간 항을 더하면 된다.

$$
y(x,t) = A\sin(kx - \omega t + \phi_0), \qquad k = \frac{2\pi}{\lambda}
$$

여기서 $\omega$는 각진동수이고 $\phi_0$는 초기 위상이다. p5.js는 매 프레임 위상을 계산해 경로 정점을 다시 만들고, 셰이더 구현은 같은 위상을 유니폼으로 전달해 필드를 다시 평가한다. 두 구현을 비교할 때 시간 단위와 위상 부호를 맞춰야 이동 방향과 속도가 같다. 이 절에서는 정적인 파형을 중심으로 보았지만, 파형이 이동해도 비교 기준은 변하지 않는다.

## 이 절의 핵심

같은 사인파를 p5.js는 표본화된 정점 경로로, GLSL은 프래그먼트마다 평가하는 파동 띠 필드로 표현할 수 있다. 비교를 위해 진폭·파장·위상과 정규화 단위, 화면 중심과 y축 방향을 일치시킨다. 경로의 표본 간격은 곡선 근사에 영향을 주고, 셰이더의 거리 근사와 `fwidth()`는 선의 두께와 화면 가장자리 처리에 영향을 준다.
