# 24.4 창, 좌표계, 이벤트 입력

nannou 창은 화면에 그림을 표시하는 표면인 동시에 포인터와 키 입력, 크기 변경 같은 운영체제 이벤트가 들어오는 경계다. 창을 어떤 크기로 만들지 정하고, 창 좌표를 작품에서 쓰는 좌표로 해석하며, 이벤트가 바뀐 상태를 `Model`에 반영하는 흐름을 이해하면 정적인 드로잉을 인터랙티브 작업으로 확장할 수 있다.

## 창 만들기와 창 크기

창은 `App`의 `new_window()` 빌더에서 생성한다. 크기와 뷰 함수를 정하고 필요에 따라 마우스나 키 입력 콜백을 연결한 뒤 `build()`를 호출한다.

```rust
use nannou::prelude::*;

struct Model {
    pointer: Point2,
    click_position: Option<Point2>,
    key_press_count: u32,
}

fn main() {
    nannou::app(model).run();
}

fn model(app: &App) -> Model {
    app.new_window()
        .size(900, 600)
        .view(view)
        .mouse_moved(mouse_moved)
        .mouse_pressed(mouse_pressed)
        .key_pressed(key_pressed)
        .build()
        .expect("창을 만들지 못했습니다");

    Model {
        pointer: pt2(0.0, 0.0),
        click_position: None,
        key_press_count: 0,
    }
}
```

`size(900, 600)`은 창의 초기 너비와 높이를 지정한다. nannou 창의 크기와 포인터 좌표는 DPI에 독립적인 논리 단위(points)로 다루므로, 고해상도 디스플레이에서 물리 픽셀 수와 다를 수 있다. 화면 캡처나 픽셀 셰이더의 해상도와 직접 연결할 때는 논리 크기인지 물리 픽셀 크기인지 구별한다.

창 설정은 작품의 용도에 맞춰 선택한다. 개발 중에는 창 모드와 크기 조절을 허용해 다른 비율에서 레이아웃을 시험하기 편리하고, 전시에서는 전체 화면이나 고정 크기가 적합할 수 있다. 창을 여러 개 만들거나 여러 모니터에서 실행할 때는 각 창의 ID와 크기를 함께 고려해야 한다. 현재 포커스된 창의 사각형을 반환하는 `app.window_rect()`를 무조건 모든 창의 크기로 간주하지 않는다.

## nannou의 기본 2D 좌표계

nannou의 기본 2D 좌표계는 창의 중심을 원점으로 둔다. x축은 오른쪽이 양수이고 y축은 위쪽이 양수다. 따라서 창의 너비가 `W`, 높이가 `H`라면 화면 경계는 대략 다음 범위에 놓인다.

$$
-\frac{W}{2}\le x\le\frac{W}{2},\qquad
-\frac{H}{2}\le y\le\frac{H}{2}
$$

예를 들어 900×600 창의 중심은 `(0, 0)`이고, 가장자리는 가로로 약 `-450`부터 `450`, 세로로 약 `-300`부터 `300`까지다. 창 크기를 고정 상수로 쓰기보다 `app.window_rect()`에서 현재 창의 사각형을 얻으면 크기 조절에 대응하기 쉽다. `Rect`의 `left()`, `right()`, `bottom()`, `top()`, `w()`, `h()` 메서드로 경계와 크기를 읽을 수 있다.

이 좌표계는 Processing이나 브라우저 캔버스에서 흔히 보는 왼쪽 위 원점, 아래쪽으로 증가하는 y축과 다르다. 이미지의 행 번호, 화면 픽셀 배열, 외부 센서가 왼쪽 위 원점 좌표를 제공한다면 nannou 좌표로 변환해야 한다. 축 방향을 확인하지 않고 데이터를 그대로 사용하면 위아래가 뒤집히거나 원점이 어긋난다.

## 창 좌표를 작품 좌표로 매핑하기

마우스 이동 콜백은 포인터 위치를 `Point2`로 전달한다. 그 좌표는 창 중심을 기준으로 하며, 드로잉 좌표와 같은 방향을 사용한다. 다음 콜백은 가장 최근의 포인터 위치를 모델에 저장한다.

```rust
fn mouse_moved(_app: &App, model: &mut Model, position: Point2) {
    model.pointer = position;
}
```

작품 규칙이 창 크기와 무관한 0에서 1 사이 값을 필요로 한다면 현재 창의 경계를 이용해 정규화한다.

$$
u=\frac{x-left}{right-left},\qquad
v=\frac{top-y}{top-bottom}
$$

여기서 `(x, y)`는 nannou의 포인터 좌표다. `u`는 왼쪽에서 오른쪽으로 증가하고 `v`는 위에서 아래로 증가하도록 정의했다. 두 번째 식에서 `top-y`를 사용하는 이유는 nannou의 y축과 이미지 행 좌표의 방향이 반대이기 때문이다. 계산한 값은 입력 장치가 창 바깥 좌표를 보낼 수 있는 상황에서 `0..1` 범위로 제한하거나, 범위 밖 입력을 무시할 수 있다.

정규화한 좌표는 다시 작품의 파라미터나 격자 좌표로 바꿀 수 있다. 예를 들어 `u`를 입자 방출률에 대응시키면 창의 왼쪽에서 오른쪽으로 포인터를 움직일수록 입자가 더 자주 생성된다. 창 크기가 달라져도 같은 상대 위치는 비슷한 입력값을 만들므로, 특정 픽셀 크기에 묶이지 않는 인터랙션을 설계할 수 있다.

```rust
let rect = app.window_rect();
let u = (model.pointer.x - rect.left()) / rect.w();
let v = (rect.top() - model.pointer.y) / rect.h();
let u = u.clamp(0.0, 1.0);
let v = v.clamp(0.0, 1.0);
```

창이 최소화되거나 크기 변경 중인 순간처럼 너비나 높이가 0에 가까울 수 있는 상황을 다룬다면 나눗셈 전에 크기를 확인한다. `window_rect()`의 값은 논리 좌표 단위이므로, 물리 픽셀의 이미지 데이터에 접근할 때는 DPI 배율도 함께 고려한다.

## 마우스와 키보드 이벤트

마우스 이동은 연속적인 위치 변화이고, 버튼 누름과 놓기는 상태가 전환되는 사건이다. 드래그를 만들려면 현재 위치뿐 아니라 버튼이 눌린 상태인지도 기억해야 한다. 누름 이벤트에서 `is_dragging`을 켜고 놓기 이벤트에서 끈 뒤, 이동 콜백에서 그 상태가 참일 때만 선이나 궤적의 점을 추가한다.

```rust
fn mouse_pressed(_app: &App, model: &mut Model, _button: MouseButton) {
    model.click_position = Some(model.pointer);
}

fn key_pressed(_app: &App, model: &mut Model, _key: Key) {
    model.key_press_count += 1;
}
```

예제는 버튼 종류와 관계없이 현재 포인터 위치를 저장한다. 왼쪽·오른쪽 버튼에 서로 다른 기능을 주려면 콜백의 `MouseButton` 값을 비교해 동작을 분기한다. 누름과 놓기를 각각 처리하면 버튼을 누른 순간 한 번 수행할 명령과 누르고 있는 동안 지속할 동작을 구분할 수 있다.

키보드도 키 누름과 키 놓임을 구분한다. 한 번의 누름으로 색상 팔레트를 바꾸거나 시뮬레이션을 초기화할 때는 눌림 이벤트에서 상태를 변경한다. 키를 누르고 있는 동안 계속 움직이게 하려면 눌림에서 해당 키의 상태를 `true`로, 놓임에서 `false`로 기록하고 `update()`에서 이동량을 계산한다. 창이 포커스를 잃었을 때 놓임 이벤트를 받지 못하면 눌린 상태가 남을 수 있으므로, 포커스 상실 시 입력 상태를 초기화하는 것도 고려한다.

창 빌더의 `.mouse_moved()`, `.mouse_pressed()`, `.mouse_released()`, `.key_pressed()`, `.key_released()` 같은 콜백은 필요한 사건만 직접 연결할 때 편리하다. 여러 종류의 창·장치 이벤트를 한곳에서 분기하고 싶다면 앱 빌더의 `.event()`를 사용한다. 한 사건을 두 경로에 모두 연결하면 같은 동작이 중복 실행될 수 있으므로 이벤트 처리 경계를 정해 둔다.

## 이벤트에서 상태로, 상태에서 화면으로

이벤트 콜백은 들어온 사건을 `Model`에 기록하고, `update()`는 시간에 따른 규칙을 계산하며, `view()`는 그 결과를 그리는 역할로 분리할 수 있다.

```text
마우스 이동: model.pointer 갱신
마우스 누름: model.click_position 저장
키 누름: model.paused 또는 팔레트 상태 변경
        ↓
update: 지속 입력과 시간 변화 처리
        ↓
view: 포인터, 클릭 지점, 작품 상태 표현
```

이 방식은 이벤트 콜백 안에서 드로잉을 직접 수행하는 것보다 흐름을 예측하기 쉽다. 콜백은 사건을 기록하고, 화면은 매번 현재 모델에서 다시 구성한다. 마우스를 누를 때 입자를 생성하더라도 이벤트에서 입자 상태를 추가한 뒤 `view()`가 입자를 그리도록 하면 입력 처리와 표현이 분리된다.

다음 뷰는 모델의 포인터와 마지막 클릭 지점을 시각화한다. `Option<Point2>`는 클릭이 아직 없을 수 있음을 표현한다.

```rust
fn view(app: &App, model: &Model, frame: Frame) {
    let draw = app.draw();
    draw.background().color(BLACK);

    let pointer_color = if model.key_press_count % 2 == 0 {
        rgb(0.25, 0.68, 0.82)
    } else {
        rgb(0.92, 0.48, 0.25)
    };

    draw.ellipse()
        .x_y(model.pointer.x, model.pointer.y)
        .w_h(18.0, 18.0)
        .color(pointer_color);

    if let Some(point) = model.click_position {
        draw.ellipse()
            .x_y(point.x, point.y)
            .w_h(36.0, 36.0)
            .no_fill()
            .stroke(rgb(0.96, 0.78, 0.32))
            .stroke_weight(2.0);
    }

    draw.to_frame(app, &frame)
        .expect("프레임을 렌더링하지 못했습니다");
}
```

이 코드가 사용하는 `Model`은 앞의 창 예제에 `pointer: Point2`, `click_position: Option<Point2>`, `key_press_count: u32` 필드를 둔 구조다. 키 입력 콜백에서는 키 종류에 따라 처리하기보다 예제를 단순하게 만들기 위해 카운터만 증가시킨다. 뷰는 카운터의 홀짝에 따라 포인터 색을 바꾼다. 클릭 원의 테두리는 `no_fill()`로 내부를 비우고 `stroke()`로 윤곽만 표현한다.

## 창 크기 변경과 좌표 의존성

사용자가 창 크기를 바꾸거나 전체 화면 모드로 전환하면 창의 경계도 달라진다. 현재 너비와 높이는 `app.window_rect()`에서 읽고, 화면의 중심이나 정규화 좌표를 그때 계산하면 고정된 개발 해상도에 덜 의존한다. 특정 크기에 맞춰 만든 고정 구성은 창의 가로세로 비율이 달라졌을 때 늘릴지, 여백을 둘지, 가장자리를 자를지 결정해야 한다.

크기 변경 콜백 `.resized()`를 연결하면 새 창 크기에 맞춰 렌더 타깃이나 분석용 격자를 다시 만들 수 있다. 다만 크기 이벤트가 올 때마다 무거운 버퍼를 반복 생성하지 말고, 실제 크기가 바뀌었는지 확인해 필요한 자원만 갱신한다. 한편 창 크기와 픽셀 단위 텍스처 크기는 DPI 배율에 따라 다를 수 있으므로, 논리 좌표를 기대하는 API와 실제 픽셀을 기대하는 API를 혼동하지 않는다.

## 이 절의 핵심

nannou의 창은 논리 단위로 크기를 지정하며, 기본 2D 좌표는 창 중심이 원점이고 y축 양의 방향이 위쪽이다. 마우스 좌표도 이 창 좌표계를 따르므로 `app.window_rect()`의 경계를 사용해 정규화하거나 작품의 좌표로 변환할 수 있다. 이벤트 콜백은 키와 마우스 사건을 모델 상태로 기록하고, `update()`와 `view()`가 지속 동작과 화면 표현을 맡도록 나누면 창 크기와 입력에 대응하는 인터랙션을 체계적으로 만들 수 있다.
