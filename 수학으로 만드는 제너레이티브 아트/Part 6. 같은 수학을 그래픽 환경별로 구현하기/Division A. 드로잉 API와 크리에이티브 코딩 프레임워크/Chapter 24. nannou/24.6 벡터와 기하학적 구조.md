# 24.6 벡터와 기하학적 구조

nannou에서 벡터는 위치와 방향, 속도처럼 2차원 또는 3차원 값을 표현하는 기본 도구다. `nannou::prelude::*`는 자주 쓰는 기하 타입과 생성 함수를 가져오며, 벡터 연산은 glam 기반 타입으로 수행한다. 이 절의 예제는 nannou 0.20 계열을 기준으로 한다.

## 위치와 벡터를 구분하기

2차원 그래픽에서 `Point2`는 점의 위치, `Vec2`는 방향이나 변위처럼 해석하는 것이 자연스럽다. `Point3`와 `Vec3`는 3차원에 대응한다.

| 타입 | 의미로 읽기 | 예시 |
| --- | --- | --- |
| `Point2` | 창 안의 위치 | `(x, y)`에 놓인 입자 |
| `Vec2` | 방향과 크기를 가진 값 | 속도, 가속도, 힘, 위치 간 차이 |
| `Point3` | 3차원 공간의 위치 | `(x, y, z)`에 놓인 정점 |
| `Vec3` | 3차원 방향과 크기 | 3D 속도나 표면 법선 |

점에서 점을 빼면 두 점 사이의 변위 벡터가 된다. 위치에 변위 벡터를 더하면 새로운 위치를 얻는다.

$$
\mathbf{d}=\mathbf{p}_{target}-\mathbf{p}_{current},\qquad
\mathbf{p}_{next}=\mathbf{p}_{current}+\mathbf{v}\Delta t
$$

여기서 `p`는 위치, `d`와 `v`는 벡터, `Δt`는 시간 간격이다. Rust API에서 `Point2`와 `Vec2`는 같은 기반 타입으로 표현되므로 컴파일러가 점과 방향의 의미를 완전히 구분해 주지는 않는다. 따라서 위치끼리 더하는 연산처럼 수학적으로 의미가 모호한 식을 피하고, 변수 이름과 연산 순서로 의도를 명확히 한다.

```rust
use nannou::prelude::*;

let position: Point2 = pt2(-80.0, 25.0);
let target: Point2 = pt2(140.0, 100.0);
let displacement: Vec2 = target - position;

let distance = displacement.length();
```

`pt2(x, y)`는 2차원 점을 만들고 `vec2(x, y)`는 벡터를 만든다. 둘은 같은 수의 성분을 가지지만, 앞의 값은 공간상의 위치로, 뒤의 값은 이동이나 변화량으로 해석한다. 위치와 속도를 구조체에 별도 필드로 보관하면 이 역할 구분이 코드에서도 드러난다.

## 길이와 정규화

벡터의 길이는 `length()`로 구한다. 길이로 나누어 크기를 1로 만들면 방향만 가진 단위 벡터(unit vector)가 된다. 목표점으로 향하는 방향을 구하거나 방향을 일정한 힘·속도 크기에 맞출 때 사용한다.

```rust
let offset = target - position;
let distance = offset.length();

let direction = if distance > 0.0001 {
    offset / distance
} else {
    Vec2::ZERO
};
```

두 점이 같으면 `offset`은 영벡터이고 길이가 0이다. 그 상태에서 정규화하거나 길이로 나누면 유효하지 않은 값이 생길 수 있으므로, 일정한 작은 기준값보다 길이가 큰지 먼저 확인한다. `Vec2::ZERO`는 두 성분이 모두 0인 벡터다. 입자가 목표점에 도달한 상황에서 방향을 0으로 두거나 이동을 멈추도록 처리할 수 있다.

정규화한 방향에 크기를 곱하면 원하는 길이의 벡터가 된다.

```rust
let desired_velocity = direction * 120.0;
```

위 예에서 `120`은 좌표 단위를 초당 얼마나 움직일지 정하는 크기로 해석할 수 있다. `length()`는 거리나 속력처럼 크기만 필요할 때 사용하고, 정규화는 방향과 크기를 분리할 때 사용한다. 힘의 합과 가속도에 대한 물리적 의미는 16.3에서 다룬 원리를 그대로 적용한다.

## 벡터 연산으로 이동 계산하기

위치와 속도를 타입에 맞춰 보관하면 프레임마다 상태를 갱신하기 쉽다. 아래 구조체에서 위치는 `Point2`, 속도와 가속도는 `Vec2`다.

```rust
struct Particle {
    position: Point2,
    velocity: Vec2,
    acceleration: Vec2,
}

fn integrate(particle: &mut Particle, dt: f32) {
    particle.velocity += particle.acceleration * dt;
    particle.position += particle.velocity * dt;
    particle.acceleration = Vec2::ZERO;
}
```

속도는 위치의 시간에 따른 변화량이므로 `velocity * dt`를 위치에 더한다. 가속도는 속도의 시간에 따른 변화량이므로 먼저 속도를 갱신한다. 좌표를 픽셀 또는 논리 단위로 취급한다면 속도는 단위/초, 가속도는 단위/초²로 해석할 수 있다. `dt`를 곱하지 않고 프레임마다 같은 값을 더하면 프레임률이 높을수록 움직임도 빨라진다.

업데이트 순서에 따라 같은 수식도 조금 다른 궤적을 만들 수 있다. 위 코드는 갱신한 속도로 위치를 이동하는 단순한 오일러 적분 방식이다. 이전 속도로 위치를 먼저 옮길 수도 있으며, 정밀도가 필요한 시뮬레이션에서는 고정 시간 단계나 더 높은 차수의 적분법을 고려한다. 제너레이티브 아트에서는 계산 비용과 시각적 안정성에 맞춰 적절한 방법을 선택한다.

벡터의 내적(dot product)은 두 벡터가 얼마나 같은 방향을 향하는지 계산한다.

```rust
let alignment = velocity.normalize().dot(direction);
```

두 벡터가 모두 정규화되어 있다면 내적은 `-1`에서 `1` 사이가 된다. `1`에 가까울수록 같은 방향, `0`에 가까울수록 직각, `-1`에 가까울수록 반대 방향이다. 다만 `velocity`가 영벡터일 때는 정규화에 앞서 길이를 확인해야 한다. 내적은 입자의 진행 방향을 목표 방향으로 맞추거나, 두 흐름 방향의 차이를 평가할 때 쓸 수 있다.

## 점을 만들고 곡선을 구성하기

각도와 반지름으로 원 위의 점을 만들면 벡터를 기하학적 구조로 연결할 수 있다. 중심이 원점인 원의 매개변수 표현은 다음과 같다.

$$
\mathbf{p}(\theta)=\begin{bmatrix}
r\cos\theta\\
r\sin\theta
\end{bmatrix}
$$

임의의 중심 `center`를 사용하려면 이 원점 기준 좌표에 중심 위치를 더한다.

```rust
fn point_on_circle(center: Point2, radius: f32, angle: f32) -> Point2 {
    center + vec2(radius * angle.cos(), radius * angle.sin())
}
```

`angle`은 라디안이다. 점을 일정한 각도 간격으로 계산하면 다각형의 꼭짓점이나 방사형 배열을 만들 수 있고, 각도에 따라 반지름을 변화시키면 꽃잎이나 물결 모양 윤곽을 만들 수 있다.

```rust
let segments = 120;
let points = (0..=segments).map(|i| {
    let angle = std::f32::consts::TAU * i as f32 / segments as f32;
    let radius = 120.0 + 22.0 * (5.0 * angle).sin();
    point_on_circle(pt2(0.0, 0.0), radius, angle)
});

draw.polyline()
    .weight(2.0)
    .points(points)
    .color(rgb(0.26, 0.72, 0.78));
```

`TAU`는 한 바퀴인 `2π` 라디안이다. 반복 범위를 `0..=segments`로 설정해 처음 점과 같은 각도까지 계산하므로 윤곽이 닫힌다. `segments`는 0보다 커야 각도 계산에서 0으로 나누지 않는다. `polyline()`은 점들을 순서대로 선분으로 잇고, `weight()`와 `color()`가 선의 표현을 정한다. 면을 채우는 다각형이 필요하면 같은 점 목록을 `polygon()`에 전달한다.

## 좌표·방향·변환을 조합하기

같은 벡터를 위치, 이동량, 속도 가운데 어떤 의미로 쓰는지 분명히 하면 기존 수학 규칙을 nannou의 드로잉 API로 옮기기 쉽다. 예를 들어 점 목록을 먼저 계산한 뒤 `draw.polyline().points(points)`로 연결하면 기하 계산과 화면 표현을 분리할 수 있다. 도형을 반복 배치할 때는 각 점을 직접 회전시켜 계산하거나, 24.5에서 본 `Draw` 변환 문맥으로 로컬 구조를 회전할 수 있다.

화면에서 입자의 방향을 화살표로 나타내려면 시작점은 위치, 끝점은 위치와 방향 벡터의 합으로 계산한다.

```rust
let arrow_length = 32.0;
let start = particle.position;
let end = particle.position + direction * arrow_length;

draw.line()
    .start(start)
    .end(end)
    .weight(2.0)
    .color(WHITE);
```

여기서 `direction`은 정규화된 벡터라서 길이는 1이고, `arrow_length`가 화면에 표시할 길이를 정한다. 속도 자체를 끝점에 더하면 빠른 입자일수록 긴 선이 된다. 정규화된 방향을 사용하면 속력과 관계없이 방향만 비교할 수 있다. 시각화가 실제 속력의 크기를 표현하는지, 방향만 표시하는지 구분해 벡터의 스케일을 선택한다.

벡터 기반 계산은 3차원으로도 확장된다. `Point3`와 `Vec3`에 세 번째 성분을 추가해 위치와 방향을 표현할 수 있지만, 3D 좌표를 창에 표시하려면 카메라와 투영 변환이 필요하다. 자료의 차원이 3D라는 사실과 화면에 보이는 2D 좌표는 서로 다른 단계다. 이번 장의 Draw와 기하 API는 주로 2D 작업에 집중하고, GPU와 렌더링 파이프라인은 24.8에서 이어진다.

## 자주 생기는 오류

영벡터를 정규화하면 방향을 정의할 수 없다. 거리나 속도의 크기가 충분히 큰지 확인한 뒤 나누거나, 크기가 작을 때 사용할 대체 방향과 동작을 정한다. 프레임률에 따라 이동이 달라지는 문제는 벡터 크기에 `dt`를 적용했는지 확인한다. 벡터가 지나치게 커지는 경우에는 힘·가속도·속도의 단위와 적용 순서를 검토하고, 필요하면 최대 크기를 제한한다.

또한 2D 화면에서 y축이 위쪽으로 증가한다는 점을 기억한다. 이미지 좌표처럼 y가 아래로 증가하는 데이터와 결합할 때는 변환이 필요하다. 마지막으로 점과 벡터가 같은 성분 타입으로 보이더라도 코드에서는 `position`, `offset`, `velocity`, `direction`처럼 역할을 나타내는 이름을 사용한다. 이 작은 습관이 잘못된 덧셈과 단위 혼합을 줄여 준다.

## 이 절의 핵심

nannou의 `Point2`와 `Vec2`는 2차원 좌표와 방향을 표현하며, 점의 차이로 변위를 구하고 벡터의 길이·정규화·내적으로 기하 관계를 계산한다. 속도와 가속도는 `dt`를 사용해 위치와 함께 갱신하고, 극좌표로 계산한 점들을 `polyline()`이나 `polygon()`에 전달해 곡선과 윤곽을 구성할 수 있다. 영벡터, 좌표축 방향, 단위와 업데이트 순서를 확인하면 같은 수학을 안정적인 화면 구조로 옮길 수 있다.
