# 24.5 Draw API와 변환 상태

nannou의 `Draw` API는 화면에 표현할 도형을 빌더(builder) 방식으로 구성한다. 도형의 위치와 크기, 색, 윤곽선, 회전 같은 속성을 메서드 체이닝(method chaining)으로 연결한 뒤 `to_frame()`을 호출해 프레임에 제출한다. 전역 드로잉 상태를 명령마다 바꾸는 방식과 달리, 각 도형의 표현과 변환 문맥을 코드에서 명시적으로 구성할 수 있다.

## 프레임 안에 도형 구성하기

`view()`에서 `app.draw()`로 `Draw` 값을 얻고, 그 값으로 배경과 도형을 구성한다. 예를 들어 원, 사각형, 선을 한 프레임에 함께 그릴 수 있다.

```rust
fn view(app: &App, model: &Model, frame: Frame) {
    let draw = app.draw();
    draw.background().color(rgb(0.04, 0.06, 0.08));

    draw.ellipse()
        .x_y(-150.0, 30.0)
        .w_h(90.0, 90.0)
        .color(rgb(0.22, 0.70, 0.78));

    draw.rect()
        .x_y(90.0, 30.0)
        .w_h(150.0, 72.0)
        .color(rgb(0.92, 0.48, 0.28));

    draw.line()
        .start(pt2(-250.0, -100.0))
        .end(pt2(250.0, -100.0))
        .weight(2.0)
        .color(WHITE);

    draw.to_frame(app, &frame)
        .expect("프레임을 렌더링하지 못했습니다");
}
```

`ellipse()`, `rect()`, `line()`은 각각 타원, 사각형, 선의 드로잉 빌더를 만든다. `x_y()`와 `w_h()`는 도형의 중심 위치와 크기를 지정하고, 선의 `start()`와 `end()`는 양 끝점을 지정한다. 각 메서드는 도형 빌더에 속성을 이어 붙여 최종 모양을 구성한다. `draw`는 창의 기본 좌표계를 사용하며, 그 원점과 방향은 24.4에서 설명했다.

`Draw` 호출은 CPU 코드에서 화면의 픽셀을 즉시 수정하는 명령과 같지 않다. `view()` 안에서 프레임에 들어갈 드로잉 데이터를 구성하고, `to_frame()`에서 현재 프레임에 그 결과를 제출한다. 프레임마다 배경색을 다시 지정하면 이전 프레임을 지우고 새 장면을 그리는 일반적인 애니메이션이 된다. 이전 결과를 남기는 누적 효과는 별도의 렌더 타깃이나 피드백 구조가 필요하며 24.9에서 이어진다.

## 도형별 스타일

색과 윤곽선은 각 도형의 빌더에 지정한다. `color()`는 도형의 채움색을 정한다. 내부를 비우고 윤곽만 표시하려면 `no_fill()`과 `stroke()`를 함께 사용하고, 선 굵기는 `stroke_weight()`로 지정한다.

```rust
draw.ellipse()
    .x_y(0.0, 0.0)
    .w_h(180.0, 100.0)
    .no_fill()
    .stroke(rgb(0.96, 0.78, 0.32))
    .stroke_weight(3.0);
```

채움색과 윤곽선을 동시에 쓰는 도형은 `color()`와 `stroke()`를 함께 지정할 수 있다. 반대로 채움 없이 테두리만 그릴 때에는 `no_fill()`을 명시한다. 굵은 선과 작은 도형의 조합은 겹치거나 형태를 가릴 수 있으므로, 화면 크기와 작품의 시각적 위계에 맞춰 굵기를 정한다. 선, 면, 투명도는 같은 규칙으로 다른 도형에도 적용할 수 있다.

여러 도형에 같은 색을 쓸 때도 각각의 빌더에 색을 지정한다. 이는 하나의 전역 색 상태를 바꾼 뒤 이후 모든 도형이 그 상태를 암묵적으로 물려받는 방식과 다르다. 그래서 특정 도형의 색을 수정해도 뒤에 작성한 다른 도형의 스타일이 우연히 바뀌지 않는다.

## 도형의 위치와 좌표계 변환

도형 빌더의 `.x_y(x, y)`는 해당 도형을 지정한 위치에 둔다. 반면 `Draw` 문맥의 `.x_y(x, y)`는 그 문맥 안에서 그릴 도형들의 좌표 원점을 이동시킨다. 비슷한 이름이지만 적용 범위가 다르다.

```rust
// 이 원 하나의 중심을 이동
draw.ellipse()
    .x_y(120.0, 40.0)
    .radius(24.0)
    .color(WHITE);

// 새로운 문맥을 만들고, 그 안의 도형을 함께 이동
let group = draw.x_y(-180.0, 40.0);
group.ellipse().radius(24.0).color(rgb(0.22, 0.70, 0.78));
group.rect().y(55.0).w_h(70.0, 16.0).color(rgb(0.92, 0.48, 0.28));
```

첫 번째 위치 설정은 원 하나에만 적용된다. 두 번째는 이동한 `group` 문맥을 만들고, 그 문맥으로 그린 원과 사각형 모두에 같은 기준 원점 이동을 적용한다. 여러 도형을 하나의 구조로 움직이거나 회전할 때 문맥 변환을 이용하면 각 도형의 좌표를 매번 전체 화면 좌표로 계산하지 않아도 된다.

`Draw`의 `x_y()`, `translate()`, `rotate()`, `scale()`은 변환된 새 `Draw` 값을 반환한다. 기존 `draw`의 좌표계가 전역적으로 바뀌지 않으므로, 기본 문맥과 변환 문맥을 나란히 사용할 수 있다.

| 변환 | 역할 | 일반적인 사용 |
| --- | --- | --- |
| 이동(translation) | 좌표 원점을 옮김 | 객체를 장면 안의 위치에 배치 |
| 회전(rotation) | 좌표축을 회전 | 가지, 바늘, 방사형 요소 방향 지정 |
| 스케일(scale) | 좌표의 크기를 조절 | 그룹 확대·축소, 반복 무늬의 단계 구성 |

`rotate()`의 각도 단위는 라디안이다. 도 단위 각도를 사용한다면 Rust의 `to_radians()` 등으로 변환해 전달한다. 변환을 체이닝하면 변환 행렬이 합성되므로 순서를 바꾸면 결과도 달라진다. 좌표계를 먼저 이동한 뒤 그 안에서 회전할지, 원점을 기준으로 회전한 다음 이동할지 구분해야 한다.

## 로컬 좌표로 방사형 패턴 만들기

그룹 변환의 장점은 같은 로컬 좌표로 여러 방향의 형태를 만들 때 잘 드러난다. 다음 코드는 중심에서 위쪽으로 뻗는 사각형 하나를 기본 가지로 정하고, `Draw` 문맥을 회전시켜 12개 방향으로 배치한다.

```rust
let branch_count = 12;

for i in 0..branch_count {
    let angle = std::f32::consts::TAU * i as f32 / branch_count as f32;
    let branch = draw.rotate(angle);

    branch
        .rect()
        .x_y(0.0, 150.0)
        .w_h(12.0, 70.0)
        .color(rgb(0.25, 0.68, 0.82));
}
```

각 사각형의 중심은 로컬 좌표 `(0, 150)`에 동일하게 놓이고, 회전각만 반복에 따라 달라진다. `TAU`는 한 바퀴에 해당하는 `2π` 라디안이다. 같은 규칙으로 `i`를 나누어 회전각을 계산하므로 12개 사각형이 원을 따라 균일한 간격을 이룬다. 기본 `draw`는 회전되지 않으므로 이 반복 이후에 그리는 다른 도형은 원래 좌표계에 놓인다.

이 패턴을 바꾸려면 분기 수, 거리, 너비, 색상, 각도 간격을 각각 독립적인 매개변수로 다룬다. `branch_count`가 커질수록 각도 간격은 작아지고, 가지의 길이나 중심 위치를 조정하면 밀도와 전체 실루엣이 달라진다. 동일한 로컬 도형에 여러 변환을 적용하면 프랙탈 가지, 꽃잎, 시계 눈금, 방사형 입자 배치처럼 다양한 구조로 확장할 수 있다.

## 변환 순서와 기준 원점

이동, 회전, 스케일은 단순히 도형에 붙이는 장식이 아니라 이후 좌표를 해석하는 기준을 바꾼다. 예를 들어 중심을 이동한 문맥에서 회전하면 이동된 중심을 기준으로 도형을 배치할 수 있고, 회전을 먼저 적용한 문맥에서 이동하면 이동 방향도 회전된 축을 따라갈 수 있다. 변환이 예상과 다를 때는 전체 좌표를 다시 계산하기보다 변환이 적용되는 기준 원점과 체이닝 순서를 확인한다.

스케일은 문맥 안의 위치와 도형 크기에도 영향을 줄 수 있다. 도형의 폭만 조절하고 위치 간격은 유지하려면 각 도형의 `w_h()`를 바꾸는 방식이 더 적합할 수 있다. 반면 하나의 그룹 전체를 같은 비율로 축소하려면 `Draw`의 `scale()` 변환을 사용한다. x축과 y축의 스케일을 다르게 하면 원형 도형도 타원으로 변하므로, 화면 비율 보정과 의도된 형태 변형을 구별한다.

## 프레임 제출과 작성 습관

모든 도형을 구성한 뒤 `draw.to_frame(app, &frame)`으로 렌더링한다. 호출 결과는 `Result`이므로 예제에서는 `expect()`로 실패를 드러낸다. 실제 프로그램에서는 오류 상황과 작업 환경에 맞게 기록하거나 복구 방법을 마련할 수 있다. 같은 `Draw` 값을 기준으로 여러 도형 문맥을 만들어도 되며, 변환된 문맥이 부모 문맥 자체를 수정한다고 생각할 필요는 없다.

드로잉 코드를 읽기 쉽게 하려면 객체 하나를 만드는 코드와 반복 규칙을 분리한다. 반복문 안에서 생성하는 변환 문맥은 그 반복 단계의 좌표계로 사용하고, 도형의 크기와 색은 빌더 체인 가까이에 둔다. 도형 수가 많아지면 이 규칙을 별도 함수로 묶거나 데이터를 먼저 만들고 표현 단계에서 순회할 수 있다. 계산된 기하와 드로잉 API를 분리하면 같은 좌표 데이터를 다른 렌더 방식으로 옮기기도 쉽다.

## 이 절의 핵심

nannou의 `Draw` API는 도형 빌더에 위치·크기·색·윤곽선을 체이닝해 프레임을 구성하고, `to_frame()`으로 결과를 제출한다. 도형 빌더의 위치 지정은 개별 도형에 적용되고, `Draw` 문맥의 이동·회전·스케일은 그 문맥에서 그리는 여러 도형의 로컬 좌표에 적용된다. 변환 문맥을 새 값으로 조합하고 순서와 기준 원점을 의식하면 반복적인 기하 패턴을 간결하게 만들 수 있다.
