# 24.1 nannou와 Rust 기반 크리에이티브 코딩 환경

nannou는 Rust로 그래픽과 인터랙티브 작업을 만드는 오픈소스 크리에이티브 코딩 툴킷이다. 창을 만들고, 도형을 그리며, 시간에 따라 상태를 갱신하고, 키보드나 마우스 같은 이벤트에 반응하는 기본 구조를 제공한다. 작가는 그 구조 안에 좌표와 색을 계산하는 수식, 입자와 도형을 관리하는 자료 구조, 작품만의 규칙을 작성한다.

nannou는 시각 편집 프로그램이나 Rust 언어 자체가 아니다. Rust는 코드를 작성하는 프로그래밍 언어이고, nannou는 Rust 프로젝트에서 그래픽·창·이벤트·렌더링 기능을 제공하는 라이브러리다. Cargo는 프로젝트와 의존성을 관리하고 코드를 빌드하는 Rust 도구다. 이 역할을 나누어 보면 작품의 계산 규칙은 Rust 코드에, 화면과 이벤트를 다루는 기능은 nannou API에, 빌드와 라이브러리 버전 관리는 Cargo에 놓인다.

이 절의 예제는 nannou 0.20 계열을 기준으로 한다. Cargo 의존성은 다음과 같이 지정할 수 있다.

```toml
[dependencies]
nannou = "0.20"
```

이 버전 요구사항은 0.20 계열의 호환 가능한 릴리스를 사용하겠다는 뜻이며, Cargo의 잠금 파일 `Cargo.lock`은 실제 빌드에 선택된 세부 버전과 의존성 구성을 기록한다. 다른 버전의 예제를 가져올 때는 함수 이름뿐 아니라 타입과 창 설정 방식도 현재 사용하는 버전의 문서와 대조한다. 특히 0.x 라이브러리는 마이너 버전 변경에서 API가 바뀔 수 있으므로, 예제의 버전과 프로젝트의 의존성 버전을 함께 확인하는 습관이 중요하다.

## Rust와 크리에이티브 코딩

Rust는 정적 타입과 소유권(ownership) 시스템을 갖춘 컴파일 언어다. 정적 타입은 값의 종류와 함수가 주고받는 자료를 컴파일 시점에 확인하게 해준다. 소유권과 빌림(borrowing)은 값의 수명과 접근 규칙을 명시해, 메모리 해제와 동시 접근에서 발생하는 여러 오류를 예방하는 데 도움을 준다. 이 특성은 입자 목록, 기하 데이터, 이미지 처리처럼 상태와 자료가 늘어나는 프로젝트에서 유용하다.

그만큼 처음에는 JavaScript나 Processing의 간단한 스케치보다 배워야 할 개념이 많다. 변수의 가변성, 소유권, 참조, 제네릭 타입, 오류 처리와 컴파일 과정을 이해해야 한다. 컴파일러의 진단은 잘못된 타입이나 빌림 관계를 찾아 주지만, 처음 보는 오류 메시지가 작품의 수학적 문제와 직접 관계없는 Rust 규칙을 가리킬 수도 있다. 한 번에 모든 규칙을 외우기보다 작은 스케치를 컴파일하며 자료 구조와 함수의 경계를 익히는 편이 좋다.

또한 Rust가 사용된다는 이유만으로 모든 계산이 자동으로 빨라지는 것은 아니다. 성능은 알고리즘과 메모리 접근, 자료 복사, 렌더링 비용에 달려 있다. Rust의 타입 체계와 소유권 모델은 프로그램의 구조를 명확하게 하고 안전한 최적화를 지원하지만, 어떤 제너레이티브 규칙을 계산할지는 작가가 설계해야 한다.

## nannou가 맡는 역할

nannou는 애플리케이션의 반복 구조와 드로잉 API를 제공한다. 프로그램은 애플리케이션 상태를 준비하고, 프레임마다 그 상태를 갱신하고, 현재 상태를 화면으로 표현한다. nannou가 창과 이벤트 루프, 프레임 전달을 관리하므로 작가는 운영체제별 창 생성 코드를 처음부터 작성하지 않고 작품의 규칙에 집중할 수 있다.

| 구성 요소 | 역할 | 작품에서 맡는 일 |
| --- | --- | --- |
| `App` | 애플리케이션과 창, 이벤트 환경에 접근 | 창 생성, 입력 확인, 실행 환경 조회 |
| `Model` | 작품이 직접 정의하는 데이터 구조 | 입자, 파라미터, 시간에 따라 변하는 상태 보관 |
| `update` | 반복되는 상태 갱신 함수 | 위치·속도·위상·작품 규칙 계산 |
| `view` | 한 프레임을 그리는 함수 | 현재 상태를 화면 표현으로 변환 |
| `Draw` | 도형과 색 등 드로잉 명령을 구성하는 API | 원, 선, 다각형, 텍스트 등의 렌더링 |

이 구분은 전형적인 구조를 설명한다. 간단한 정적 이미지 작업은 상태를 거의 바꾸지 않을 수 있고, 입력 이벤트나 별도의 렌더링 요구가 있으면 추가 콜백과 자료가 필요하다. `Model`, `update`, `view`의 실행 순서는 24.3에서, 창 설정과 입력 이벤트는 24.4에서 자세히 살펴본다.

## 최소한의 실행 구조

다음 예제는 `Model`에 원의 위상을 보관하고, 경과 시간에 따라 원을 타원 궤도로 움직인다. 코드 문법은 nannou 0.20 계열의 `App` 빌더와 `Draw` API를 사용하는 형태다.

```rust
use nannou::prelude::*;

struct Model {
    phase: f32,
}

fn main() {
    nannou::app(model)
        .update(update)
        .run();
}

fn model(app: &App) -> Model {
    app.new_window()
        .size(800, 600)
        .view(view)
        .build()
        .expect("창을 만들지 못했습니다");

    Model { phase: 0.0 }
}

fn update(_app: &App, model: &mut Model, update: Update) {
    model.phase += update.since_last.as_secs_f32();
}

fn view(app: &App, model: &Model, frame: Frame) {
    let draw = app.draw();
    draw.background().color(BLACK);

    let x = model.phase.cos() * 180.0;
    let y = model.phase.sin() * 120.0;
    draw.ellipse()
        .x_y(x, y)
        .w_h(24.0, 24.0)
        .color(rgb(0.25, 0.68, 0.82));

    draw.to_frame(app, &frame)
        .expect("프레임을 렌더링하지 못했습니다");
}
```

`main()`은 nannou 앱을 만들고 실행한다. `model()`은 창을 설정하고 작품의 초기 상태를 반환한다. `update()`는 이전 갱신 이후의 경과 시간(`since_last`)을 초 단위로 바꾸어 위상을 진행시킨다. `view()`는 그 위상에서 위치를 계산해 원을 그린다. 사인과 코사인이 만드는 좌표는 다음과 같이 타원 궤도를 이룬다.

$$
x(t)=a\cos(t),\qquad y(t)=b\sin(t)
$$

여기서 `a`와 `b`는 각각 가로와 세로 반지름이며 예제에서는 180과 120이다. `update()`와 `view()`를 분리했기 때문에 운동 규칙과 화면에 표시하는 모양을 각각 바꿀 수 있다. `view()`의 `Draw` 호출은 도형을 구성하고 `to_frame()`은 그 프레임의 결과를 제출한다. 변환과 도형 속성의 조합은 24.5에서 다룬다.

## 그래픽 처리와 작업 방식

nannou는 고수준 드로잉 API와 GPU에 접근할 수 있는 그래픽 기반을 함께 제공한다. 보통의 도형과 텍스트는 `Draw` API로 작성하고, 특수한 정점 처리나 프래그먼트 계산이 필요하면 더 낮은 수준의 wgpu 기능을 고려할 수 있다. GPU 파이프라인과 셰이더는 별도의 개념과 설정이 필요하므로 24.8에서 자세히 살펴본다. 고수준 API를 사용한다고 그래픽 하드웨어가 전혀 관여하지 않는다는 뜻도 아니며, 반대로 Rust 코드가 곧 셰이더 코드를 의미하는 것도 아니다.

프로젝트는 Cargo를 통해 의존성을 내려받고 빌드한다. 브라우저에서 코드를 저장하자마자 실행되는 스케치 환경과 달리, 변경 사항을 확인하려면 다시 컴파일하고 애플리케이션을 실행하는 흐름이 기본이다. 그 과정은 초기 설정과 반복 시간이 더 들 수 있지만, 프로젝트와 의존성이 명시적으로 관리되고 네이티브 애플리케이션으로 배포할 수 있다. Cargo 프로젝트 구조와 Rust 문법의 기초는 24.2에서 이어진다.

nannou는 수학 규칙으로 생성한 형태, 시간에 따른 애니메이션, 인터랙티브 그래픽, 오디오·미디어 작업을 Rust 프로젝트 안에서 구성할 때 적합하다. Rust의 자료 구조와 반복자(iterator)를 활용해 생성 데이터를 다루고, nannou의 창·이벤트·드로잉 기능으로 결과를 보여줄 수 있다. 단순한 한 번짜리 스케치를 빠르게 공유하려는 경우에는 브라우저 기반 도구가 더 간편할 수 있다. 반면 프로그램의 상태와 자료 흐름을 명시적으로 관리하고, 그래픽 작업을 Rust 애플리케이션으로 확장하고 싶다면 nannou의 구조가 잘 맞는다.

## 이 장에서 살펴볼 내용

이 장은 먼저 Cargo 프로젝트와 Rust의 타입·소유권을 소개하고, 이어 `App`, `Model`, `update`, `view`가 연결되는 실행 흐름을 살펴본다. 이후 창과 좌표계, 이벤트 입력, `Draw` API와 변환, 벡터 기반 기하 구조로 확장한다. 시간·랜덤·노이즈 애니메이션을 거쳐 wgpu와 셰이더, 이미지와 텍스처 출력까지 다루며, 각 절의 예제는 nannou 0.20 계열을 기준으로 읽는다.

## 이 절의 핵심

nannou는 Rust로 창·이벤트·그래픽 애플리케이션을 만드는 오픈소스 크리에이티브 코딩 툴킷이며, 이 절은 nannou 0.20 계열을 기준으로 한다. Rust가 자료와 상태를 표현하고 Cargo가 프로젝트와 의존성을 관리하며, nannou가 실행 루프와 그래픽 API를 제공한다. `Model`에 작품 상태를 두고 `update()`에서 계산한 뒤 `view()`에서 그리는 흐름이 이후 절의 출발점이다.
