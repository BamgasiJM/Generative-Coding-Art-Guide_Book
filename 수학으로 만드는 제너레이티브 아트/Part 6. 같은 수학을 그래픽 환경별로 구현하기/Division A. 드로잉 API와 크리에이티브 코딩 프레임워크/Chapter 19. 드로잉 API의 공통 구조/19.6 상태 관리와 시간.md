# 19.6 상태 관리와 시간

드로잉 API는 도형을 호출하는 도구이지만, 실시간 제너레이티브 작업은 도형 명령만으로 완성되지 않는다. 화면이 시간에 따라 달라지려면 프로그램은 현재 시간과 이전 상태를 구분해 다뤄야 한다. 시간은 계속 변하는 외부 입력이고, 상태는 프로그램이 이전 프레임에서 보존한 데이터다.

예를 들어 사인파로 움직이는 원은 현재 시각만으로 위치를 계산할 수 있다.

$$
x(t)=x_c+A\sin(\omega t)
$$

```text
time = elapsedSeconds()
x = centerX + amplitude * sin(time * angularSpeed)
drawCircle(x, centerY, radius)
```

이 방식에는 이전 위치를 저장할 필요가 없다. 임의의 시각 $t$를 넣으면 언제든 같은 위치를 다시 얻는다. 이를 시간 기반 또는 무상태(stateless) 애니메이션이라고 볼 수 있다. 루프 영상, 파동, 좌표 변형, 시간 노이즈처럼 함수가 현재 시각에 바로 응답하는 작업에 잘 맞는다.

반면 입자가 속도를 누적하거나, 선을 그린 흔적이 남거나, 사용자가 추가한 도형이 화면에 유지되려면 이전 결과를 저장해야 한다.

$$
\mathbf{v}_{t+\Delta t}=\mathbf{v}_t+\mathbf{a}\Delta t,qquad
\mathbf{p}_{t+\Delta t}=\mathbf{p}_t+\mathbf{v}_{t+\Delta t}\Delta t
$$

```text
particle.velocity += particle.acceleration * deltaTime
particle.position += particle.velocity * deltaTime
drawCircle(particle.position, particle.radius)
```

여기서 위치와 속도는 상태다. 현재 프레임의 값은 이전 프레임의 값에서 계산되므로, 같은 시간값만 알아도 장면을 즉시 복원할 수는 없다. 초기 상태와 그 뒤의 모든 업데이트를 다시 적용해야 한다. Part 5에서 다룬 상태 시스템의 개념이 드로잉 API 환경에서도 그대로 필요해지는 지점이다.

## 상태의 범위 정하기

작은 스케치에서는 캔버스 크기, 마우스 위치, 입자 배열, 팔레트처럼 여러 값을 전역 변수에 두기 쉽다. 빠른 실험에는 편리하지만, 값이 늘어나면 어느 함수가 무엇을 바꾸는지 알기 어려워진다. 관련된 값을 하나의 상태 구조로 묶으면 데이터의 역할이 더 분명해진다.

```text
state = {
    time: 0,
    particles: [],
    paletteIndex: 0,
    pointer: { x: 0, y: 0 },
    seed: 184729
}
```

모든 값을 하나의 거대한 객체에 넣어야 한다는 뜻은 아니다. 화면 전체에 공통인 상태, 개별 입자에 속한 상태, 렌더링 설정, 변하지 않는 설정값을 구분하는 것이 중요하다.

| 종류 | 예 | 갱신 방식 |
| --- | --- | --- |
| 고정 설정 | 캔버스 비율, 팔레트, 최대 입자 수 | 시작 시 설정, 필요할 때만 변경 |
| 전역 상태 | 시간, 현재 모드, 시드, 카메라 | 프레임 또는 이벤트마다 갱신 |
| 개체 상태 | 위치, 속도, 나이, 크기 | 각 개체의 업데이트에서 갱신 |
| 입력 상태 | 마우스, 키, 센서 값 | 장치 이벤트 또는 프레임마다 읽기 |
| 렌더링 상태 | 선 두께, 블렌딩 모드, 버퍼 | 그리기 전 설정하고 복원 |

설정값(configuration)과 상태(state)를 구분하면 특히 편하다. 예를 들어 `particleSpeed`는 사용자가 조절하는 설정일 수 있고, `particle.position`은 시뮬레이션이 계속 바꾸는 상태다. 설정값이 바뀌었다고 해서 모든 상태를 초기화할지, 다음 업데이트부터 새 설정을 적용할지도 명시적으로 결정할 수 있다.

## 초기화와 리셋

상태가 있는 작업에는 초기화 규칙이 필요하다. 프로그램을 시작할 때뿐 아니라 창 크기가 바뀌거나, 사용자가 키를 누르거나, 새로운 시드를 선택할 때도 상태를 다시 만들 수 있다.

```text
function reset(seed):
    state.time = 0
    state.seed = seed
    state.particles = createParticles(seed)
    clear(trailBuffer)
```

리셋이 무엇을 되돌리는지 구체적으로 정한다. 입자만 다시 배치하고 배경 버퍼는 남길지, 난수 시드를 유지할지 바꿀지, 시간도 0으로 되돌릴지를 선택한다. 리셋이 불완전하면 이전 버퍼의 흔적이나 남은 난수 상태 때문에 같은 시드에서도 다른 결과가 나올 수 있다.

재현 가능한 결과가 필요하다면 시드를 상태 또는 설정으로 기록한다. 난수 호출 순서가 바뀌면 같은 시드의 결과도 달라질 수 있으므로, 셀 좌표나 개체 ID를 기반으로 값을 만들면 구조 변화에 더 강한 경우가 많다.

```text
variation = hash(particle.id, state.seed)
```

## 시간의 두 형태

그래픽 환경이 제공하는 시간값은 보통 두 가지로 나뉜다. 하나는 프로그램 시작 후 누적된 경과 시간이고, 다른 하나는 이전 프레임 이후 흐른 시간 간격이다.

$$
t=\text{elapsed time},\qquad \Delta t=t_{now}-t_{previous}
$$

경과 시간 $t$는 사인파, 반복 루프, 시간 노이즈처럼 절대 시각에서 계산하는 함수에 알맞다. 시간 간격 $\Delta t$는 속도와 가속도, 감쇠, 생성률처럼 "초당 얼마나 변하는가"를 표현할 때 필요하다.

```text
wave = sin(elapsedTime * frequency)
position += velocity * deltaTime
opacity -= fadePerSecond * deltaTime
```

두 값을 혼동하면 흔한 문제가 생긴다. `position += velocity * elapsedTime`은 시간이 흐를수록 한 프레임의 이동량이 계속 커져 가속처럼 보인다. 반대로 사인파의 입력에 `deltaTime`만 넣으면 매 프레임 거의 같은 값이 되어 움직임이 보이지 않는다.

## 업데이트와 렌더링의 경계

상태를 다루는 가장 안정적인 구조는 업데이트 함수가 상태를 바꾸고, 렌더링 함수는 상태를 읽기만 하게 하는 것이다.

```text
function update(state, input, deltaTime):
    state.time += deltaTime
    updateParticles(state.particles, deltaTime)
    applyInput(state, input)

function draw(state):
    clearBackground()
    drawParticles(state.particles)
```

이 경계가 있으면 같은 상태를 여러 방식으로 시각화할 수 있다. 예를 들어 하나의 입자 배열을 화면에는 점으로, 오프스크린 버퍼에는 선분으로 동시에 그릴 수 있다. 반대로 `draw()` 안에서 위치를 갱신하면 렌더링을 두 번 호출했을 때 시뮬레이션이 두 번 진행하는 문제가 생긴다.

함수형 스타일의 환경에서는 이전 상태를 직접 수정하는 대신 새 상태를 반환하기도 한다. Quil의 `update-state` 같은 구조가 여기에 해당한다. 객체를 직접 바꾸는 방식과 새 상태를 만드는 방식은 문법과 메모리 특성이 다르지만, 이전 상태에서 다음 상태를 계산하고 렌더링은 그 결과를 읽는다는 원리는 같다.

```text
nextState = update(previousState, input, deltaTime)
draw(nextState)
state = nextState
```

## 시간 기반 규칙과 상태 기반 규칙의 결합

실제 작업에서는 무상태 규칙과 상태 규칙을 섞는 경우가 많다. 입자는 상태에 저장된 위치에서 움직이지만, 그 움직임을 흔드는 힘은 전역 시간에 따라 변하는 노이즈 필드일 수 있다. 배경은 시간 함수로 움직이고, 관람객이 그린 선은 누적 버퍼에 상태로 남을 수 있다.

```text
fieldDirection = noiseVector(particle.position, elapsedTime)
particle.velocity += fieldDirection * deltaTime
```

이때 어떤 값이 다시 계산 가능한 시간 함수인지, 어떤 값이 과거를 기억해야 하는 상태인지 표시해 두면 시스템을 이해하기 쉽다. 시간 기반 값은 임의의 프레임을 건너뛰어도 계산할 수 있지만, 상태 기반 값은 앞선 업데이트를 생략하면 다른 결과가 된다.

## 일시 정지와 단계 실행

상태를 명시적으로 관리하면 애니메이션을 멈추고, 한 단계씩 진행하고, 현재 상태를 저장하는 기능을 추가하기 쉬워진다.

```text
if not paused:
    update(state, input, deltaTime)

if stepRequested:
    update(state, input, fixedStep)
    stepRequested = false

draw(state)
```

이 기능은 단순한 사용자 편의가 아니다. 시뮬레이션의 특정 순간을 관찰하고, 비정상적인 상태가 언제 생기는지 찾고, 마음에 드는 프레임을 이미지로 내보내는 작업에 유용하다. 프레임 번호, 시드, 주요 파라미터를 함께 기록하면 결과를 나중에 다시 재현할 수 있다.

## 이 절의 핵심

시간은 현재 시각과 프레임 간격으로 나뉘며, 시간 함수는 현재 시각만으로 평가할 수 있지만 상태 시스템은 이전 결과를 저장해야 한다. 설정·전역 상태·개체 상태·입력·렌더링 상태를 구분하고, 업데이트에서 상태를 바꾸며 렌더링에서는 상태를 읽기만 하게 구성하면 드로잉 API 기반 작업을 안정적으로 확장할 수 있다.
