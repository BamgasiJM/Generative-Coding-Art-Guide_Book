# 19.1 캔버스와 렌더링 표면

드로잉 API에서 가장 먼저 만드는 대상은 대개 캔버스(canvas) 또는 렌더링 표면(rendering surface)이다. 캔버스는 단순히 흰 사각형 배경이 아니다. 도형과 픽셀을 기록할 수 있는 크기, 해상도, 색상 형식, 투명도, 좌표계를 가진 출력 대상이다. 이후의 모든 `line`, `circle`, `image` 호출은 결국 이 표면의 어느 위치에 어떤 색을 남길지를 지정한다.

```text
canvas = createSurface(width, height)
setRenderTarget(canvas)
clear(backgroundColor)
drawScene()
present(canvas)
```

`createSurface`의 정확한 이름은 환경마다 다르다. p5.js와 Processing에서는 `createCanvas(width, height)` 또는 `size(width, height)`로 화면용 캔버스를 만들고, raylib에서는 `InitWindow()`로 윈도우와 기본 렌더링 표면을 연다. openFrameworks에서는 창 설정과 `ofFbo` 같은 오프스크린 표면을 별도로 만들 수 있다. 문법은 달라도, 프로그램이 그릴 대상의 크기와 형식을 정한다는 역할은 같다.

## 논리적 크기와 실제 픽셀 크기

캔버스의 너비와 높이는 보통 논리적 좌표 공간의 크기다. 예를 들어 `800 x 600` 캔버스에서는 왼쪽 위가 $(0,0)$이고 오른쪽 아래가 대략 $(800,600)$이 되는 좌표계를 기대할 수 있다. 그러나 실제 화면의 물리 픽셀 수는 장치의 픽셀 밀도에 따라 더 클 수 있다.

고밀도 디스플레이에서는 논리적 800 x 600 캔버스가 실제로는 1,600 x 1,200 픽셀 버퍼를 사용할 수 있다. 이를 장치 픽셀 비율(device pixel ratio) 또는 픽셀 밀도(pixel density)라고 한다.

$$
W_{physical}=W_{logical}\,d,\qquad
H_{physical}=H_{logical}\,d
$$

여기서 $d$는 픽셀 밀도다. 도형 API로 선과 원을 그릴 때는 보통 논리적 좌표만 신경 쓰면 되지만, 픽셀 배열을 직접 다루거나 텍스처 크기를 계산할 때는 실제 버퍼 크기가 중요해진다.

```javascript
// p5.js 예제
function setup() {
  createCanvas(800, 600);
  pixelDensity(1); // 픽셀 단위 결과를 고정하고 싶을 때 선택할 수 있다.
}
```

픽셀 밀도를 무조건 1로 낮추는 것이 정답은 아니다. 고밀도 화면에서는 선과 곡선이 더 선명하게 보일 수 있다. 다만 고해상도 전체 픽셀을 매 프레임 계산하는 노이즈나 후처리 효과는 비용이 픽셀 수에 비례해 늘어난다. 표현의 선명도와 계산 비용 사이에서 의도적인 선택이 필요하다.

## 캔버스의 비율과 좌표 설계

화면 크기는 작품의 구도뿐 아니라 수식의 의미에도 영향을 준다. 가로가 긴 캔버스에서 픽셀 좌표 $(x,y)$를 그대로 사용해 원의 거리를 계산하면, 같은 수치 반지름이 가로와 세로에서 다르게 느껴질 수 있다. 화면 비율과 무관한 패턴을 원한다면 좌표를 정규화하고, 한 축의 길이를 기준으로 맞춘다.

$$
\mathbf{p}=\frac{(x,y)-\frac{1}{2}(W,H)}{\min(W,H)}
$$

이 변환 뒤의 $\mathbf{p}$는 화면 중심이 원점이고, 짧은 변의 반폭이 일정한 단위가 된다. 따라서 다음 거리 함수는 세로형, 가로형, 정사각형 화면에서 모두 원으로 보인다.

$$
d=\|\mathbf{p}\|-r
$$

드로잉 API에서 직접 도형을 배치할 때도 같은 원칙을 적용할 수 있다. 반지름, 선 두께, 격자 간격을 화면 너비의 고정 픽셀 수가 아니라 `min(width, height)`의 비율로 정하면 창 크기를 바꾸어도 패턴의 성격이 유지된다.

```text
unit = min(canvasWidth, canvasHeight)
radius = 0.04 * unit
margin = 0.08 * unit
```

## 색을 기록하는 표면

렌더링 표면은 각 위치의 색을 저장한다. 일반적인 2D 캔버스는 RGB 또는 RGBA 채널을 사용한다. RGBA의 A는 알파(alpha)로, 색이 얼마나 투명한지 또는 기존 색과 얼마나 섞일지를 나타내는 데 쓰인다.

$$
\mathbf{C}_{out}=\alpha\mathbf{C}_{src}+(1-\alpha)\mathbf{C}_{dst}
$$

이 식은 가장 흔한 알파 합성의 단순화한 형태다. `src`는 새로 그리는 색, `dst`는 캔버스에 이미 기록된 색이다. 같은 반투명 도형을 여러 번 겹치면 색이 누적되는 이유도 여기에 있다. 블렌딩 모드는 이후 절에서 자세히 다루지만, 캔버스가 이미지를 한 번에 완성하는 종이가 아니라 색이 계속 기록되고 합성되는 버퍼라는 점은 여기서 기억해 둘 필요가 있다.

색상 형식도 표면에 따라 다르다. 화면 출력용 캔버스는 흔히 8비트 채널을 사용하지만, HDR 렌더링이나 누적 피드백에는 더 넓은 범위와 높은 정밀도를 가진 부동소수점 텍스처가 필요할 수 있다. 예를 들어 밝은 값을 여러 번 더하는 효과를 8비트 표면에 바로 기록하면 값이 빠르게 최대치에 도달해 하얗게 포화될 수 있다.

## 기본 렌더링 표면과 오프스크린 표면

창에 연결된 기본 캔버스는 최종적으로 관람자에게 보이는 렌더링 표면이다. 그러나 프로그램은 보이지 않는 표면, 즉 오프스크린 렌더 타깃도 만들 수 있다. 오프스크린 표면은 임시 그림을 저장하고, 나중에 다른 캔버스에 이미지처럼 그리거나 셰이더의 입력 텍스처로 사용할 수 있다.

```text
clear(mainCanvas)

begin(offscreenSurface)
clear(transparent)
drawParticles()
end(offscreenSurface)

drawImage(offscreenSurface, mainCanvas)
drawInterface(mainCanvas)
```

이 구조는 잔상, 마스크, 블러, 그림자, 합성, 고해상도 내보내기에 유용하다. 예를 들어 입자 궤적은 낮은 해상도의 오프스크린 표면에 누적해 부드러운 연기처럼 만든 뒤, 최종 캔버스에 확대해 올릴 수 있다. 반대로 고해상도 표면을 만들어 한 장의 인쇄용 이미지를 내보내는 방법도 있다.

오프스크린 표면은 메모리와 렌더링 비용을 사용한다. 표면의 가로·세로가 두 배가 되면 픽셀 수는 네 배가 된다. 여러 개의 큰 버퍼를 만들 때는 실제로 필요한 해상도와 갱신 빈도를 먼저 정한다. 매 프레임 변하지 않는 배경이라면 한 번만 그려 두고 재사용하는 편이 낫다.

## 화면 지우기와 보존

프레임 루프에서 캔버스를 어떻게 초기화하는지는 이미지의 시간적 성격을 결정한다. 매 프레임 불투명한 배경색으로 채우면 이전 흔적이 완전히 사라진다. 반투명한 배경색을 덮으면 흔적이 서서히 사라지고, 아예 지우지 않으면 그리기가 계속 누적된다.

```text
clear(opaqueBackground)    # 매 프레임 초기화
fill(background, alpha=20) # 느린 감쇠
# clear를 호출하지 않음    # 완전한 누적
```

이 선택은 단순한 장식이 아니다. 이전 프레임을 보존하는 표면은 Part 5에서 다룬 상태와 피드백 구조의 저장소가 된다. 따라서 어떤 표면이 매 프레임 새로 만들어지는지, 어느 표면이 과거를 기억하는지를 명확히 구분하는 습관이 중요하다.

## 캔버스는 출력이면서 입력이다

처음에는 캔버스를 코드의 마지막 단계, 즉 그림을 보여 주는 곳으로 생각하기 쉽다. 하지만 픽셀 접근, 오프스크린 렌더링, 셰이더 텍스처 표본화를 사용하면 캔버스는 다음 계산이 읽는 입력 데이터가 된다. 한 프레임에 그린 선의 밝기를 다음 프레임의 입자 힘으로 사용하거나, 마스크 표면을 다른 패턴의 알파 값으로 사용할 수 있다.

이 관점은 렌더링 표면을 단순한 화면에서 이미지 버퍼이자 필드로 바꾼다. 이후 절에서는 이 표면 위에서 좌표와 도형 명령이 어떻게 작동하는지, 시간과 입력이 어떻게 그리기 상태를 바꾸는지 다룬다.

## 이 절의 핵심

캔버스와 렌더링 표면은 도형과 픽셀을 기록하는 버퍼다. 논리적 크기와 실제 픽셀 크기, 화면 비율, 색상 형식, 알파 합성, 초기화 방식은 모두 생성 결과에 영향을 준다. 화면용 캔버스뿐 아니라 오프스크린 표면도 만들 수 있으며, 렌더링 표면은 최종 출력이면서 다음 계산에 쓰이는 입력이 될 수 있다.
