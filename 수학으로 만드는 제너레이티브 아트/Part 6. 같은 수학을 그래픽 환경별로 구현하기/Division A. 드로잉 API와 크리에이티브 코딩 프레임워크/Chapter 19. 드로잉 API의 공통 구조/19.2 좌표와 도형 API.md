# 19.2 좌표와 도형 API

드로잉 API는 수학적 좌표와 화면의 픽셀을 연결하는 인터페이스다. 프로그램은 점의 위치, 선의 끝점, 원의 중심과 반지름, 경로의 제어점을 숫자로 전달하고, API는 그 값을 렌더링 표면 위의 도형으로 바꾼다. 함수 이름은 Canvas 2D, p5.js, Processing, raylib, openFrameworks마다 다르지만, 대부분의 2D API는 점·선·사각형·원·경로·이미지라는 공통된 도형 언어를 공유한다.

## 화면 좌표의 기본 규약

많은 2D 환경은 캔버스의 왼쪽 위를 원점 $(0,0)$으로 사용한다. x축은 오른쪽으로, y축은 아래쪽으로 증가한다. 이는 교과서의 데카르트 좌표와 y축 방향이 반대이므로, 수학식을 화면에 옮길 때 의식해야 한다.

$$
\mathbf{p}_{screen}=(x,y),\qquad
\mathbf{p}_{math}=(x,H-y)
$$

화면 중심을 원점으로 쓰고 싶다면 캔버스 크기의 절반만큼 좌표계를 옮긴다. 이후 회전, 극좌표, 대칭, 거리 함수처럼 중심 기준의 수학을 훨씬 직접적으로 적용할 수 있다.

```text
translate(canvasWidth / 2, canvasHeight / 2)
scale(1, -1)  # 필요하다면 y축을 위로 향하게 한다.
```

`scale(1, -1)`은 많은 API에서 y축을 반전하는 개념적 예시다. 실제 환경에서는 텍스트와 이미지까지 뒤집힐 수 있으므로, 전체 화면에 적용할지 수학적 도형을 그리는 범위에만 적용할지 결정한다. 좌표계를 바꾸지 않고 수식의 y값에 음수를 곱하는 방식도 가능하지만, 여러 도형과 변환이 쌓일수록 전역 좌표 규약을 하나 정하는 편이 안전하다.

## 점과 선: 가장 작은 기하 명령

점은 위치 하나로 정의되는 가장 단순한 도형이다. 하지만 화면의 픽셀보다 작은 수학적 점은 보이지 않으므로, API에서는 보통 선 두께나 점 크기를 가진 표시로 그려진다. 입자, 표본점, 격자 교차점, 데이터 시각화는 점 명령으로 시작할 수 있다.

```text
drawPoint(x, y)
setStrokeWidth(4)
drawPoint(x, y)
```

선은 두 점 $\mathbf{a}$, $\mathbf{b}$를 잇는다.

$$
\mathbf{l}(t)=(1-t)\mathbf{a}+t\mathbf{b},\qquad 0\le t\le1
$$

드로잉 API에서는 선분의 모든 점을 직접 계산하지 않아도 된다. 두 끝점을 넘기면 내부적으로 래스터화와 안티앨리어싱이 처리된다. 그러나 선을 작은 선분의 연속으로 만들면, Part 5의 입자 궤적이나 흐름 필드처럼 함수로 만든 경로를 표현할 수 있다.

```text
previous = pathPoint(0)
for i from 1 to segments:
    current = pathPoint(i / segments)
    drawLine(previous, current)
    previous = current
```

## 사각형과 원: 매개변수의 의미

사각형과 원은 흔히 사용하는 도형이지만, API마다 인자의 의미가 조금씩 다르다. 사각형은 왼쪽 위 모서리와 너비·높이를 받을 수도 있고, 중심과 반폭을 받을 수도 있다. 원은 중심과 반지름을 받을 수도 있고, 중심과 지름을 받을 수도 있다. 이 차이를 확인하지 않으면 수식은 맞는데 크기가 두 배가 되는 실수가 생긴다.

| 도형 | 자주 쓰는 매개변수 | 확인할 점 |
| --- | --- | --- |
| 사각형 | `(x, y, width, height)` | `(x,y)`가 모서리인지 중심인지 |
| 원·타원 | `(cx, cy, diameter)` 또는 `(cx, cy, radius)` | 반지름인지 지름인지 |
| 호 | 중심, 반지름, 시작·끝 각도 | 각도의 단위와 회전 방향 |
| 다각형 | 꼭짓점 목록 | 꼭짓점 순서와 채우기 규칙 |

`p5.js`의 `circle(x, y, d)`는 세 번째 인자가 지름이고, `ellipse(x, y, w, h)`는 너비와 높이다. 반면 raylib의 `DrawCircle(centerX, centerY, radius, color)`는 반지름을 받는다. 코드를 다른 API로 옮길 때 단위와 기준점을 함께 번역해야 하는 이유다.

```javascript
// p5.js 예제: 세 번째 인자는 지름이다.
circle(cx, cy, radius * 2);
```

```c
// raylib 예제: 세 번째 인자는 반지름이다.
DrawCircle(cx, cy, radius, color);
```

## 경로와 곡선

복잡한 도형은 선분과 곡선을 연결한 경로(path)로 표현한다. 경로 API는 보통 새 경로를 시작하고, 이동한 뒤, 선·베지어 곡선·호를 추가하고, 마지막에 채우거나 외곽선을 그리는 흐름을 갖는다.

```text
beginPath()
moveTo(start)
lineTo(pointA)
curveTo(controlA, controlB, end)
closePath()
fillPath()
strokePath()
```

3차 베지어 곡선은 시작점 $\mathbf{p}_0$, 두 제어점 $\mathbf{p}_1$, $\mathbf{p}_2$, 끝점 $\mathbf{p}_3$로 정의된다.

$$
B(t)=(1-t)^3\mathbf{p}_0+3(1-t)^2t\mathbf{p}_1+3(1-t)t^2\mathbf{p}_2+t^3\mathbf{p}_3
$$

제어점은 곡선이 반드시 통과하는 점이 아니라, 시작과 끝에서 나가는 방향과 휘어짐을 정하는 손잡이다. 베지어 곡선은 문자 윤곽, 유기적인 가지, 데이터 곡선, 펜 입력 경로처럼 부드러운 선을 만들 때 쓰인다. 함수로 만든 점열을 경로로 연결하는 것과 달리, 적은 수의 제어점으로 연속적인 곡선을 지정할 수 있다.

## 채우기와 외곽선

도형 API는 대개 채우기(fill)와 외곽선(stroke)을 별도의 상태로 관리한다. 채우기는 닫힌 경로 내부의 색이고, 외곽선은 경계의 색과 두께다. 같은 삼각형도 채우기만 쓰면 면이 되고, 외곽선만 쓰면 선 구조가 된다.

```text
setFill(fillColor)
setStroke(strokeColor)
setStrokeWidth(lineWidth)
drawPolygon(vertices)
```

채움의 안쪽을 판단하는 규칙은 자기 교차 경로에서 중요하다. 대표적인 규칙은 짝홀(even-odd) 규칙과 비영(non-zero winding) 규칙이다. 생성형 패턴에서 복잡하게 겹친 경로를 다룰 때 두 규칙은 구멍이 생기는 위치를 다르게 만들 수 있다. 대부분의 기본 도형에서는 API의 기본값을 따르면 되지만, 경로 기반 작업에서는 렌더러의 채움 규칙을 확인한다.

외곽선에는 선 끝 모양(cap), 선 연결 모양(join), 두께, 대시 패턴 같은 속성이 있다. 수학적으로 같은 폴리라인도 둥근 끝과 각진 끝, 뾰족한 연결과 둥근 연결에 따라 전혀 다른 리듬을 만든다. 얇은 선을 반복해 밀도를 만드는 작업에서는 이 속성이 특히 눈에 띈다.

## 변환 상태와 도형의 로컬 좌표

도형 API의 강력한 기능은 모든 꼭짓점을 직접 계산하지 않고도 좌표계를 이동·회전·확대할 수 있다는 점이다. 현재 변환 행렬에 변환을 쌓고, 그 좌표계 안에서 간단한 도형을 그린다.

```text
pushTransform()
translate(position)
rotate(angle)
scale(size)
drawRectangle(-0.5, -0.5, 1, 1)
popTransform()
```

이 예제에서 사각형은 항상 원점 근처의 단위 도형으로 정의된다. 위치, 회전, 크기는 바깥의 변환이 담당한다. 많은 개체를 그릴 때 도형의 로컬 정의와 월드 배치를 분리하면 코드가 단순해진다. `pushTransform()`과 `popTransform()`은 환경마다 `push()/pop()`, `save()/restore()`, 행렬 스택 등 다른 이름을 갖지만 역할은 같다.

변환 상태를 복원하지 않으면 한 도형을 위해 적용한 회전과 색이 다음 도형에도 남는 문제가 생긴다. 드로잉 API는 편리한 상태를 제공하는 대신, 어떤 상태가 현재 활성화되어 있는지 관리해야 한다. 개체 하나를 그리는 함수를 만들 때 변환과 스타일을 지역적으로 저장·복원하는 습관이 안전하다.

## 좌표와 도형 API를 선택하는 기준

기본 도형 API는 수학 함수를 눈에 보이는 형태로 바꾸는 빠른 수단이다. 격자나 반복 구조에는 사각형·원·선의 반복이, 극좌표와 파동에는 선분으로 표본화한 곡선이, 로컬 회전이 많은 장면에는 변환 스택이 잘 맞는다. 반면 픽셀마다 거리나 노이즈를 평가해야 하는 패턴, 부드러운 도형 합성, 복잡한 화면 효과는 다음 절의 픽셀 접근과 셰이더 방식이 더 직접적일 수 있다.

중요한 것은 API의 도형 명령이 수학을 대체하지 않는다는 점이다. API는 좌표와 매개변수를 화면에 표시하는 수단이다. 점의 위치를 결정하는 함수, 도형의 크기를 정하는 분포, 회전을 만드는 각도, 색을 고르는 규칙은 여전히 프로그램이 설계한다.

## 이 절의 핵심

드로잉 API는 좌표와 매개변수로 점·선·도형·경로를 렌더링 표면에 기록한다. 원점과 y축 방향, 도형 인자의 의미, 채우기·외곽선 상태, 변환 스택을 명확히 이해하면 같은 수학적 규칙을 여러 환경의 도형 명령으로 안정적으로 옮길 수 있다.
