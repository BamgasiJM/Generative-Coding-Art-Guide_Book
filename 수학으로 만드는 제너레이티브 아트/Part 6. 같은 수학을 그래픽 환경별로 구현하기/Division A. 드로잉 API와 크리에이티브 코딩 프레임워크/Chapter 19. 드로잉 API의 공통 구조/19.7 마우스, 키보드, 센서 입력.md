# 19.7 마우스, 키보드, 센서 입력

드로잉 API의 입력은 화면 밖에서 들어오는 값을 작품의 규칙 안으로 가져오는 통로다. 마우스와 터치는 위치와 움직임을, 키보드는 이산적인 명령을, 센서는 기울기·방향·소리·거리 같은 물리적 변화를 제공한다. 입력 자체는 아직 그림이 아니다. 입력을 좌표, 파라미터, 상태 변화, 힘, 시드 같은 수학적 값으로 번역할 때 인터랙션이 만들어진다.

```text
raw input -> normalize -> filter or interpret -> update state -> render
```

이 흐름을 분리하면 특정 API의 이벤트 함수에 작품의 모든 규칙이 얽히는 일을 줄일 수 있다. 예를 들어 마우스 이동 이벤트는 최신 포인터 위치를 저장하고, 실제 입자 생성이나 패턴 변형은 업데이트 단계에서 처리할 수 있다.

## 마우스와 터치 좌표

마우스와 터치의 가장 기본적인 입력은 캔버스 안의 위치 $(x,y)$다. 많은 2D 환경은 이 값을 화면 픽셀 좌표로 제공한다. 하지만 작품의 수학은 화면 크기와 독립적인 정규화 좌표를 요구하는 경우가 많다.

$$
u=\frac{x}{W},\qquad v=\frac{y}{H}
$$

```text
pointerUV.x = pointerX / canvasWidth
pointerUV.y = pointerY / canvasHeight
```

$(u,v)$는 일반적으로 $[0,1]$ 범위에 들어간다. 화면 중심이 원점인 좌표가 필요하면 다음처럼 바꾼다.

$$
\mathbf{p}=\frac{(x,y)-\frac{1}{2}(W,H)}{\min(W,H)}
$$

이 변환을 한 번 정해 두면 포인터 위치를 거리 함수, 극좌표, 벡터 필드, 셰이더 유니폼에 같은 의미로 전달할 수 있다. 가로세로 비율이 바뀌어도 원형 반응 영역이 타원으로 찌그러지지 않게 하려면 짧은 변 기준 정규화가 유용하다.

```javascript
// p5.js 예제
const unit = Math.min(width, height);
const pointer = {
  x: (mouseX - width * 0.5) / unit,
  y: (mouseY - height * 0.5) / unit,
};
```

터치 장치는 한 손가락 이상의 위치를 제공할 수 있다. 단일 포인터만 가정한 규칙을 여러 터치에 적용하려면 각 접점을 별도 객체로 관리하고, 접점의 시작·이동·종료를 구분한다. 여러 손가락 사이의 거리와 각도는 확대·회전 제스처의 입력이 될 수 있다.

## 연속 입력과 이산 이벤트

포인터 위치는 매 프레임 바뀔 수 있는 연속 입력이다. 반면 마우스 버튼을 눌렀는지, 키를 처음 눌렀는지, 창 크기가 바뀌었는지는 사건(event)으로 다루기 좋다. 두 종류를 구분하지 않으면 키를 한 번 눌렀는데 프레임마다 같은 동작이 반복되거나, 계속 눌러야 할 동작이 한 번만 실행되는 문제가 생긴다.

| 입력 성격 | 예 | 적합한 처리 |
| --- | --- | --- |
| 연속 값 | 포인터 위치, 압력, 기울기, 마이크 레벨 | 매 프레임 읽고 완화·매핑 |
| 유지 상태 | 키가 눌린 상태, 버튼 누름 | 매 프레임 조건 확인 |
| 이산 사건 | 클릭 시작, 키를 처음 누름, 터치 종료 | 이벤트 콜백 또는 상태 전환 |

```text
onKeyPressed('Space'):
    state.paused = not state.paused

update():
    if isKeyDown('ArrowRight'):
        state.cameraX += cameraSpeed * deltaTime
```

스페이스바는 누를 때마다 일시 정지 상태를 한 번 바꾸는 사건이고, 오른쪽 화살표는 누르고 있는 동안 계속 이동시키는 유지 상태다. 환경에 따라 키 자동 반복을 기본으로 처리할 수 있으므로, 토글 동작에는 "방금 눌렸는가"를 별도로 확인하는 편이 안전하다.

## 입력을 파라미터로 번역하기

원시 입력값을 도형의 속성에 직접 연결하면 즉각적인 반응을 얻는다. 그러나 마우스의 x 픽셀을 반지름으로 바로 쓰면 캔버스 크기에 따라 의미가 달라지고, 작은 손 떨림까지 화면에 과장될 수 있다. 입력을 정규화하고 목적에 맞는 범위로 매핑한다.

$$
r=r_{min}+(r_{max}-r_{min})u
$$

```text
radius = interpolate(minRadius, maxRadius, pointerUV.x)
frequency = interpolate(lowFrequency, highFrequency, pointerUV.y)
```

한 입력을 여러 속성에 연결하면 관람객이 관계를 학습하기 쉽다. 예를 들어 포인터가 오른쪽으로 갈수록 원의 크기와 밝기가 함께 커지고, 위아래 위치는 파동의 주파수를 정하게 할 수 있다. 반대로 서로 무관한 여러 속성을 하나의 포인터에 모두 연결하면 반응은 화려해도 조작의 인과관계가 읽히지 않을 수 있다.

입력의 역할도 구분한다. 포인터가 단순히 관찰점을 옮기는지, 힘을 가하는지, 새 요소를 생성하는지, 파라미터를 조절하는지에 따라 적합한 상태 구조가 달라진다.

```text
pointer as position: draw a cursor-related form
pointer as force: accelerate nearby particles
pointer as emitter: spawn particles while pressed
pointer as control: adjust a global parameter
```

## 입력 완화와 임계값

실제 입력에는 잡음과 급격한 변화가 있다. 마우스 움직임도 빠르게 방향을 바꾸고, 센서 값은 미세하게 흔들린다. 현재값을 목표값으로 바로 대입하는 대신 보간하면 반응이 부드러워진다.

$$
x_{smooth}\leftarrow(1-\lambda)x_{smooth}+\lambda x_{input}
$$

```text
state.smoothPointer = lerp(state.smoothPointer, rawPointer, response)
```

$\lambda$가 작으면 반응은 느리지만 안정되고, 크면 즉각적이지만 흔들림도 남는다. 단순 이동 평균, 지수 이동 평균, 스프링 모델도 비슷한 목적으로 쓸 수 있다. 입력이 일정한 크기를 넘을 때만 반응하게 하는 데드 존(dead zone)과 임계값도 유용하다.

```text
if abs(sensorValue - baseline) > threshold:
    triggerChange()
```

임계값은 잡음을 줄이지만, 경계 근처에서 켜졌다 꺼졌다 반복될 수 있다. 켜는 임계값과 끄는 임계값을 다르게 두는 히스테리시스(hysteresis)를 사용하면 이런 떨림을 줄일 수 있다.

## 센서 입력의 특성

모바일 장치의 가속도계와 자이로스코프, 웹캠, 마이크, MIDI 컨트롤러, 시리얼 장치, 네트워크 데이터는 모두 입력원이 될 수 있다. 그러나 마우스 좌표보다 단위와 신뢰도가 다양하다. 센서 값은 기기 방향, 주변 소음, 조명, 브라우저·운영체제의 권한 설정에 영향을 받는다.

| 입력원 | 흔한 값 | 해석할 때 고려할 점 |
| --- | --- | --- |
| 가속도계 | 축별 가속도 | 중력, 기기 방향, 흔들림 |
| 자이로스코프 | 각속도 | 드리프트, 초기 보정 |
| 마이크 | 음량, 주파수 대역 | 주변 소음, 자동 게인 |
| 웹캠 | 밝기, 움직임, 추적 위치 | 조명, 개인정보·권한 |
| MIDI | 노브, 슬라이더, 노트 | 장치 범위, 연결 해제 |

센서 작업에서는 초기 보정(calibration)이 중요하다. 사용자가 정지한 상태의 평균값을 기준점으로 저장하고, 이후 변화량을 사용하는 방식이 흔하다. 예를 들어 기울기 센서의 절대값을 쓰기보다 현재 기울기에서 시작 자세를 빼면 설치 장소가 바뀌어도 반응을 맞추기 쉽다.

```text
relativeTilt = currentTilt - calibratedTilt
force = clamp(relativeTilt * sensitivity, -maxForce, maxForce)
```

웹과 모바일 환경에서는 사용자 동작 뒤에야 센서 또는 오디오 접근을 허용하는 경우가 많다. 입력을 사용할 수 없을 때의 기본 동작도 준비한다. 마이크가 없거나 권한이 거부되었을 때 화면이 멈추는 대신, 시뮬레이션 값이나 마우스 입력으로 대체할 수 있다.

## 입력과 재현성

관람객 입력은 작품을 매번 다르게 만들지만, 기록할 수 없는 입력은 결과를 다시 재현하기 어렵게 한다. 결과 저장이 중요하다면 입력 이벤트와 발생 시각, 사용한 시드, 주요 파라미터를 함께 기록할 수 있다.

```text
record(time, eventType, normalizedInput)
```

나중에 기록을 시간 순서대로 재생하면 같은 상호작용 과정을 다시 적용할 수 있다. 모든 작품에 입력 기록이 필요한 것은 아니지만, 라이브 퍼포먼스·설치 작업·긴 시뮬레이션에서는 디버깅과 아카이브에 큰 도움이 된다.

## 입력은 규칙의 일부다

입력은 작품에 "기능을 추가하는" 별도 층이 아니라, 좌표·시간·난수와 같은 또 하나의 함수 입력이다. 좋은 인터랙션은 많은 반응을 한꺼번에 붙이는 데서 나오기보다, 입력값이 어떤 수학적 규칙을 거쳐 어떤 시각적 결과로 이어지는지 관람객이 감각적으로 읽을 수 있게 만드는 데서 나온다.

## 이 절의 핵심

마우스·키보드·터치·센서 입력은 원시값을 정규화하고, 완화·임계값·매핑을 거쳐 상태와 시각 규칙에 연결해야 한다. 연속값, 유지 상태, 이산 사건을 구분하고, 센서의 보정·권한·대체 입력을 고려하면 다양한 드로잉 환경에서 견고한 인터랙션을 만들 수 있다.
