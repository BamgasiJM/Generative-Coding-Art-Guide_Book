# 19.4 색, 선, 채움, 블렌딩

좌표와 도형이 형태를 정한다면, 색·선·채움·블렌딩은 그 형태가 화면에서 어떤 재료처럼 보일지를 정한다. 대부분의 드로잉 API는 현재 스타일 상태를 설정한 뒤 이어지는 도형 명령에 적용하는 방식을 사용한다. 도형 하나를 그릴 때마다 색 정보를 모두 넘기는 API도 있지만, 내부 개념은 대체로 비슷하다.

```text
setFill(fillColor)
setStroke(strokeColor)
setStrokeWidth(lineWidth)
drawShape(geometry)
```

스타일 상태는 편리하지만 누적된다. 한 도형을 위해 바꾼 선 두께나 블렌딩 모드가 다음 도형에도 남을 수 있다. 독립적인 개체를 그리는 함수에서는 변환 상태뿐 아니라 스타일 상태도 저장하고 복원하는 습관이 좋다.

```text
pushStyle()
setFill(color)
setStrokeWidth(width)
drawShape()
popStyle()
```

## 색상 모델과 범위

화면의 색은 보통 RGB 채널로 표현한다. 각 채널은 빨강, 초록, 파랑의 양을 뜻하며, API에 따라 $0$~$1$, $0$~$255$, 또는 부동소수점의 더 넓은 범위를 사용한다. 알파 채널까지 포함한 RGBA는 색과 투명도를 함께 표현한다.

$$
\mathbf{c}=(r,g,b,\alpha)
$$

```javascript
// p5.js 예제: 기본 색상 범위는 0~255이다.
fill(30, 100, 210, 180);
stroke(255, 255, 255);
```

같은 숫자라도 색상 범위가 다르면 결과가 달라진다. GLSL의 `vec3(1.0, 0.0, 0.0)`은 완전한 빨강이지만, p5.js의 `fill(1, 0, 0)`은 거의 검은 빨강에 가깝다. 환경을 옮길 때는 색상 값뿐 아니라 범위, 색 공간, 알파 처리 방식을 함께 확인한다.

RGB는 화면 장치에 직접 대응하는 편리한 모델이지만, 색조·채도·명도를 독립적으로 조절하기에는 불편할 수 있다. 팔레트를 설계하거나 노이즈 값을 색에 연결할 때는 HSB/HSV 또는 HSL 모델이 유용하다. 색상환의 각도 $h$를 바꾸면 색조가 순환하고, 채도와 명도를 일정 범위에 두면 화면의 대비를 관리하기 쉽다.

```text
hue = baseHue + noiseValue * hueRange
saturation = 60
brightness = map(noiseValue, 30, 90)
```

단, 색상 모드가 바뀌면 `fill()`에 전달하는 같은 세 숫자의 의미도 바뀐다. 작업 초기에 어떤 색 모델과 범위를 쓸지 정하고, 팔레트 함수의 입력과 출력을 명확히 두는 편이 좋다.

## 채움과 외곽선의 역할

채움(fill)은 닫힌 도형 내부를 색으로 채우고, 외곽선(stroke)은 도형의 경계를 선으로 그린다. 둘을 동시에 사용하면 형태의 경계가 또렷해지고, 채움 없이 선만 사용하면 구조와 방향성이 강조된다.

```text
setFill(transparent)
setStroke(ink)
drawPolygon(vertices)
```

제너레이티브 패턴에서 채움과 외곽선은 단순한 장식보다 구성의 계층을 만들 수 있다. 큰 도형은 낮은 대비의 채움으로 면을 만들고, 중요한 윤곽만 얇은 선으로 표시하면 복잡한 구조도 읽기 쉬워진다. 반대로 격자의 모든 셀에 굵은 외곽선을 주면 도형보다 선의 밀도가 먼저 보일 수 있다.

선 두께는 일반적으로 화면 픽셀 단위다. 따라서 캔버스 해상도가 크게 바뀌는 작업에서는 선 두께도 화면 크기에 비례하게 계산할지 결정해야 한다.

$$
w=\lambda\min(W,H)
$$

얇은 선을 여러 개 그리는 패턴에서는 선 끝(cap)과 연결(join)도 중요하다. 둥근 끝은 선을 점처럼 보이게 하며, 각진 끝은 격자와 기하학적 구조를 강조한다. 꺾이는 경로에서 뾰족한 연결은 날카로운 별이나 다각형에 어울릴 수 있지만, 작은 각도에서는 과도하게 튀어나올 수 있다.

## 알파와 기본 합성

반투명한 도형을 그리면 새 색은 기존 캔버스의 색과 섞인다. 가장 널리 쓰이는 보통 알파 합성은 새 도형의 알파를 기준으로 두 색을 보간한다.

$$
\mathbf{C}_{out}=\alpha_s\mathbf{C}_s+(1-\alpha_s)\mathbf{C}_d
$$

여기서 $\mathbf{C}_s$는 새로 그리는 색, $\mathbf{C}_d$는 이미 표면에 있는 색, $\alpha_s$는 새 색의 알파다. 실제 구현은 대상 알파까지 포함한 조금 더 긴 식을 사용하지만, 색이 그리는 순서에 따라 쌓인다는 핵심은 같다.

```text
background(white)
setFill(blue, alpha=40)
drawCircle(a)
drawCircle(b)  # 겹치는 부분은 더 진하게 보인다.
```

같은 반투명 도형을 반복해서 그리면 기대보다 빠르게 불투명해질 수 있다. 이는 오류가 아니라 합성의 결과다. 점묘나 입자 잔상에서 균일한 밀도를 원한다면 도형 수와 알파를 함께 조절하고, 누적 횟수가 달라질 때 밝기가 어떻게 변하는지 확인한다.

## 블렌딩 모드

블렌딩 모드(blend mode)는 새 색과 기존 색을 섞는 규칙을 바꾼다. API마다 이름과 세부 구현이 조금 다르지만, 자주 만나는 모드는 다음과 같다.

| 모드 | 대략적인 효과 | 활용 예 |
| --- | --- | --- |
| Normal / Alpha | 새 색을 알파로 덮음 | 일반 레이어, 투명 도형 |
| Add / Lighter | 색 값을 더해 밝아짐 | 빛, 입자, 발광 흔적 |
| Multiply | 색을 곱해 어두워짐 | 잉크, 그림자, 종이 질감 |
| Screen | 어두운 부분보다 밝은 부분을 강조 | 광택, 밝은 합성 |
| Difference | 색 차이를 강조 | 반전적 패턴, 실험적 효과 |

가산 합성은 밝은 선과 입자가 겹칠수록 빛이 쌓이는 느낌을 준다. 하지만 8비트 표면에서는 값이 최대치에 빠르게 도달해 넓은 영역이 하얗게 포화될 수 있다. 곱셈 합성은 종이에 잉크가 겹치는 듯한 효과를 내지만, 배경이 검정이면 대부분의 결과가 검게 사라진다. 블렌딩 모드는 색상뿐 아니라 배경색과 알파 값의 관계로 이해해야 한다.

```text
setBlendMode(ADD)
drawGlowParticles()

setBlendMode(NORMAL)
drawLabels()
```

블렌딩 모드는 보통 전역 렌더링 상태다. 가산 합성을 쓴 뒤 일반 텍스트나 UI를 그릴 때 모드를 되돌리지 않으면 예기치 않게 밝아질 수 있다. 의도적인 레이어 단위로 모드를 설정하고 복원한다.

## 색을 함수로 다루기

제너레이티브 작업에서 색은 상수가 아니라 좌표·시간·거리·노이즈·상태에서 계산한 값일 때가 많다. 예를 들어 거리 필드 $d(\mathbf{p})$를 색상 보간의 입력으로 사용할 수 있다.

$$
t=\operatorname{clamp}\left(\frac{d-d_0}{d_1-d_0},0,1\right),\qquad
\mathbf{C}=\operatorname{mix}(\mathbf{C}_0,\mathbf{C}_1,t)
$$

```text
value = noise(position * frequency)
color = interpolate(darkColor, lightColor, value)
setFill(color)
drawCircle(position, radius)
```

여러 속성에 같은 값을 연결하면 화면에 관계가 생긴다. 밝은 셀을 더 크게 만들거나, 중심에서 멀어질수록 채도를 낮추는 식이다. 반대로 색과 크기에 서로 다른 난수나 노이즈 채널을 쓰면 표면의 다양성이 늘어난다. 어느 쪽이든 팔레트의 명도 범위와 배경 대비를 먼저 정하면 결과를 제어하기 쉽다.

## 색 공간과 보간의 주의점

디지털 화면은 보통 sRGB 색 공간을 사용한다. 하지만 사람이 밝기의 차이를 느끼는 방식과 RGB 숫자의 변화는 정확히 비례하지 않는다. 검정과 흰색을 RGB에서 단순 선형 보간하면 중간 회색이 기대보다 어둡거나 밝게 느껴질 수 있고, 보색을 섞으면 탁한 중간색이 생길 수 있다.

작업에서 정밀한 색 보정이 필요하다면 선형 색 공간에서 빛의 양을 합성한 뒤 sRGB로 변환하거나, 지각적 균일성을 고려한 색 공간을 사용할 수 있다. 그러나 모든 스케치에 복잡한 색 관리가 필요한 것은 아니다. 우선은 사용하는 API가 색을 어떤 범위와 알파 규칙으로 해석하는지, 그리고 선택한 팔레트가 실제 화면에서 충분한 대비를 내는지 확인하는 것이 더 중요하다.

## 스타일은 상태이자 규칙의 출력이다

드로잉 API의 색·선·채움은 "그리기 전에 정하는 장식"이 아니라 렌더링 상태이자 함수의 출력이다. 도형의 위치와 크기를 계산하는 규칙처럼, 어떤 색을 선택하고 어떤 합성으로 쌓을지도 제너레이티브 시스템의 일부다. 색상 함수, 선 두께 함수, 알파 감쇠, 블렌딩 레이어를 명시적으로 설계하면 형태와 재료감이 서로 분리되지 않고 함께 작동한다.

## 이 절의 핵심

색, 채움, 외곽선, 선 두께, 블렌딩은 도형의 시각적 재료를 결정하는 렌더링 상태다. 색의 범위와 모델, 알파 합성, 레이어 순서, 블렌딩 모드를 의식하고, 좌표·시간·필드에서 계산한 값을 스타일 속성에 연결하면 수학적 규칙을 더 풍부한 이미지로 표현할 수 있다.
