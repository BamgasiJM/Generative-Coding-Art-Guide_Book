# 20.4 프레임 기반 애니메이션

p5.js와 Processing 스케치는 한 번 그림을 그리고 끝나는 프로그램만이 아니다. 캔버스를 준비한 뒤 `draw()`를 반복 호출하고, 매 호출에서 상태를 갱신하고 화면을 다시 그려 움직임을 만든다. 앞 절의 `for`문이 한 번의 함수 호출 안에서 여러 도형을 배치했다면, 여기서 다루는 프레임 루프(frame loop)는 시간에 따라 그 함수 호출 자체를 반복한다.

## `setup()`과 `draw()`의 실행 순서

일반적인 스케치에서는 캔버스와 초기 상태를 준비한 뒤 `draw()`가 프레임마다 실행된다. Processing Java 모드에서는 캔버스의 크기와 렌더러를 `settings()`에서 먼저 지정한다. `setup()`은 한 번만 실행되고, `draw()`는 반복된다.

| 단계 | p5.js | Processing Java 모드 | 역할 |
| --- | --- | --- | --- |
| 캔버스 설정 | `createCanvas()`를 `setup()`에서 호출 | `size()`를 `settings()`에서 호출 | 렌더링 표면과 크기를 준비한다. |
| 초기화 | `setup()` | `setup()` | 시작 위치, 색, 난수 시드 같은 초기 상태를 정한다. |
| 매 프레임 실행 | `draw()` | `draw()` | 상태를 갱신하고 화면을 그린다. |

프레임마다 실행되는 함수 안에는 대체로 두 작업이 들어간다. 첫째, 위치나 각도 같은 상태를 다음 값으로 갱신한다. 둘째, 갱신된 상태를 도형과 색으로 화면에 표현한다. 이 순서를 분리하면 움직임이 예상과 다를 때 계산 문제와 그리기 문제를 나누어 확인하기 쉽다.

## 프레임마다 같은 양을 움직이는 방식

가장 단순한 애니메이션은 `draw()`가 호출될 때마다 위치에 고정된 값을 더하는 것이다.

```text
x += 2
```

여기서 2의 단위는 픽셀/프레임이다. 매 프레임 오른쪽으로 2픽셀씩 이동하며, $n$프레임 뒤의 위치는 다음과 같다.

$$
x_n=x_0+2n
$$

이 방식은 변화가 프레임 횟수에 묶여 있다. 초당 60프레임으로 실행되면 초당 약 120픽셀을 이동하지만, 실제 프레임률이 30이면 약 60픽셀만 이동한다. `frameCount`는 지금까지 실행된 프레임 수를 나타내며 주기적인 색이나 위치 변화를 만들 때 편리하지만, 프레임률이 달라지면 실제 시간에 따른 변화 속도도 달라진다.

두 환경은 `frameRate(30)`처럼 초당 목표 프레임 수를 지정할 수 있다. 그러나 이는 목표값이지 매초 그 횟수를 반드시 보장하는 설정은 아니다. 복잡한 계산, 브라우저나 운영체제의 스케줄링, 화면 주사율에 따라 실제 실행률은 더 낮거나 달라질 수 있다. 프레임마다 고정량을 바꾸는 방식은 매 프레임의 변화가 의도인 경우에는 적절하지만, 속도를 초 단위로 일정하게 유지해야 한다면 실제 경과 시간을 사용한다.

## 실제 경과 시간으로 움직이기

속도를 픽셀/초로 정의하면, 한 프레임 사이에 이동할 거리는 속도에 실제 경과 시간 $\Delta t$를 곱해 계산한다.

$$
\Delta x=v\Delta t,\qquad x_{new}=x_{old}+v\Delta t
$$

`deltaTime`은 이전 프레임에서 현재 프레임까지 걸린 시간이다. p5.js에는 이 시간이 밀리초 단위로 제공된다. Processing에서는 `millis()`로 현재까지의 시간을 읽어 이전 값과의 차이를 구한다. 초 단위의 속도를 사용하려면 밀리초를 1000으로 나누어 초로 변환한다.

```javascript
let x = 40;
const speed = 120; // pixels per second

function setup() {
  createCanvas(640, 200);
  noStroke();
  fill(40);
}

function draw() {
  const dt = Math.min(deltaTime / 1000, 0.05);
  x += speed * dt;
  if (x > width + 12) x = -12;

  background(248);
  circle(x, height / 2, 24);
}
```

Processing에서는 `millis()`의 차이로 같은 시간 간격을 계산한다.

```java
float x = 40;
float speed = 120;
int previousMillis;

void settings() {
  size(640, 200);
}

void setup() {
  previousMillis = millis();
  noStroke();
  fill(40);
}

void draw() {
  int currentMillis = millis();
  float dt = min((currentMillis - previousMillis) / 1000.0f, 0.05f);
  previousMillis = currentMillis;

  x += speed * dt;
  if (x > width + 12) x = -12;

  background(248);
  ellipse(x, height / 2, 24, 24);
}
```

두 예제에서 `speed`의 단위는 픽셀/초이고 `dt`는 초이므로 `speed * dt`의 단위는 픽셀이다. 프레임률이 낮아지면 한 프레임의 이동량은 커지고, 높아지면 작아지지만 일정 시간 동안 움직이는 총거리는 대체로 유지된다. 위치와 속도 갱신의 단위 해석은 16.2절에서 다룬 원리와 같다.

예제는 프레임 사이의 시간이 0.05초를 넘으면 그 값으로 제한한다. 프로그램이 잠시 멈춘 뒤 매우 큰 시간 간격을 한 번에 적용하면 물체가 화면을 건너뛰거나 충돌을 놓칠 수 있기 때문이다. 대신 제한한 시간보다 더 지난 구간은 이 간단한 예제에서는 움직임에 반영되지 않아, 멈춤 뒤 잠시 느려진 것처럼 보일 수 있다. 정확한 시뮬레이션 시간이 중요하다면 고정 시간 간격으로 업데이트를 여러 번 수행하는 누적기(accumulator) 방식을 고려한다. 그 방식은 15.3절에서 다룬다.

프레임률에 좌우되지 않는 다른 방법은 상태를 누적 갱신하는 대신, 시작 상태와 현재 시간으로 위치를 직접 계산하는 것이다.

$$
x(t)=x_0+vt
$$

일정한 속도로 움직이는 장면에서는 시간을 다시 계산하거나 특정 시점의 상태를 찾기 쉽다. 가속도, 충돌, 상호작용처럼 이전 상태가 다음 상태에 영향을 주는 시스템에는 매 프레임 `deltaTime`을 반영해 상태를 갱신하는 방식이 더 자연스럽다.

## 반복을 멈추고 한 프레임만 그리기

모든 스케치가 계속 움직일 필요는 없다. 정적인 패턴을 한 번 계산하거나 입력이 바뀔 때만 다시 그리려면 `noLoop()`로 자동 프레임 반복을 멈출 수 있다. `loop()`는 반복을 다시 시작하고, `redraw()`는 필요한 시점에 한 프레임을 요청한다. p5.js와 Processing에서 이 세 명령의 이름과 기본 역할은 같다.

정지된 화면에서도 `setup()`은 실행되고, `noLoop()` 상태에서 요청한 `redraw()`는 화면을 한 번 다시 계산한다. 마우스나 키 입력이 올 때만 이미지를 다시 만드는 스케치에서는 불필요한 프레임 계산을 줄일 수 있다. 반대로 움직이는 장면에서 프레임 루프를 멈추면 `draw()` 안의 상태 갱신도 멈춘다.

## 화면을 지우거나 흔적을 남기기

애니메이션에서 `background()`를 매 프레임 호출하면 이전 프레임의 그림이 지워지고 현재 상태만 남는다. 호출하지 않으면 이전 그림 위에 새 그림이 계속 쌓여 궤적이 만들어진다. 반투명한 배경색을 매 프레임 덮으면 과거 흔적이 서서히 흐려지는 잔상 효과를 만들 수 있다. 이는 상태 자체의 갱신과 별도로 화면 버퍼에 과거 픽셀을 남기는 선택이다. 누적과 잔상을 세밀하게 조절하는 방법은 16.8절에서 자세히 다룬다.

## 이 절의 핵심

`setup()`은 한 번 초기화하고 `draw()`는 프레임마다 상태를 갱신하고 화면을 그린다. 프레임마다 고정량을 더하면 속도는 픽셀/프레임이 되어 실제 프레임률에 따라 달라진다. 초당 속도를 유지하려면 p5.js의 `deltaTime`이나 Processing의 `millis()` 차이로 구한 실제 경과 시간에 이동량을 곱한다. `noLoop()`, `loop()`, `redraw()`와 매 프레임의 배경 초기화는 애니메이션의 실행 및 흔적을 제어한다.
