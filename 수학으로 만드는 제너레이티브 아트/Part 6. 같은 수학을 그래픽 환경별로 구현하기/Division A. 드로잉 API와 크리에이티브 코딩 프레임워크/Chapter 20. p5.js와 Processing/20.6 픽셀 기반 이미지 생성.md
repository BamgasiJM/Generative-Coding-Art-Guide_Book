# 20.6 픽셀 기반 이미지 생성

도형 API에서는 원이나 선을 하나의 명령으로 그린다. 픽셀 기반 이미지 생성(pixel-based image generation)에서는 각 픽셀의 색을 직접 계산해 표면을 채운다. 좌표마다 함수의 값을 구해 색으로 바꾸므로, 거리장과 파동, 노이즈, 마스크처럼 화면 전체에서 반복되는 규칙에 적합하다. 픽셀 접근의 공통 원리는 19.8절에서 다루었고, 이 절에서는 p5.js와 Processing의 실제 배열 형식과 호출 순서를 비교한다.

## 픽셀 버퍼 읽기와 반영

두 환경 모두 픽셀을 직접 바꾸기 전에 `loadPixels()`를 호출하고, 수정을 마친 뒤 `updatePixels()`를 호출한다. 앞 명령은 캔버스의 현재 픽셀 데이터를 작업 가능한 배열로 준비하고, 뒤 명령은 배열의 변경을 렌더링 표면에 반영한다. `loadPixels()`는 기존 이미지를 읽어 변경할 때도 필요하다. 새 이미지를 만들며 모든 항목을 덮어쓰는 경우에도 배열을 준비하고 마지막에 반영하는 순서는 같다. 픽셀마다 `set()`을 반복하는 대신 배열을 한 번 준비하고 이중 반복문으로 순회하면 대량 처리에 적합하다.

두 배열의 구조는 다르다.

| 환경 | 픽셀 배열 | 픽셀 `(x, y)`의 인덱스 | 색 지정 |
| --- | --- | --- | --- |
| p5.js | 픽셀마다 R, G, B, A 네 값 | `4 * (x + y * width)` | 네 채널을 연속된 네 칸에 기록 |
| Processing Java 모드 | 픽셀마다 `color` 값 하나 | `x + y * width` | `color(r, g, b, a)`로 만든 색을 대입 |

인덱스 식의 `x`, `y`는 0부터 시작하는 정수 픽셀 좌표이며, `width`는 한 행의 픽셀 수다. 예를 들어 `(3, 2)` 픽셀은 행 우선 배열에서 `3 + 2 * width`번째 항목이다. p5.js에서는 그 위치에 네 채널이 있으므로 채널 시작점에 4를 곱한다. 이 차이를 놓치면 색 채널이 엇갈려 예상하지 못한 색이나 줄무늬가 생긴다.

일반적인 p5.js 캔버스는 기기 픽셀 비율에 따라 논리적 크기보다 큰 픽셀 버퍼를 사용할 수 있다. 인덱스를 `4 * (x + y * width)`로 단순하게 계산하려면 캔버스를 만든 뒤 `pixelDensity(1)`을 설정한다. Processing에서도 `pixelDensity(1)`을 사용하면 논리적 좌표와 픽셀 배열의 크기를 일치시킬 수 있다. 고밀도 화면의 선명도를 유지해야 한다면 밀도를 1로 고정하지 말고 실제 픽셀 버퍼의 너비와 높이에 맞춰 순회해야 한다. 픽셀 밀도와 논리 좌표의 관계는 19.8절을 참고한다.

## 수식으로 동심원 무늬 만들기

예제에서는 각 픽셀의 중심 좌표를 캔버스 중심에서 얼마나 떨어졌는지 계산하고, 거리에 따라 밝기가 오르내리는 동심원 무늬를 만든다. 논리 좌표를 짧은 변으로 나누면 가로세로 비율이 다른 캔버스에서도 거리가 원형으로 유지된다.

$$
u=\frac{x+0.5-width/2}{\min(width,height)},\qquad
v=\frac{y+0.5-height/2}{\min(width,height)}
$$

$$
d=\sqrt{u^2+v^2},\qquad
I=128+127\cos(80d)
$$

여기서 $I$는 0부터 255 사이의 회색 밝기다. $x+0.5$, $y+0.5$는 픽셀 정수 좌표의 한가운데를 표본 위치로 사용한다. 코사인 함수의 입력에서 거리에 곱한 80을 바꾸면 동심원 간격이 바뀐다. 계수를 크게 하면 거리에 따라 밝기가 더 빠르게 진동해 고리가 촘촘해지고, 작게 하면 고리 사이가 넓어진다. 삼각 함수의 입력은 라디안이다.

### p5.js 구현

p5.js의 `pixels`는 RGBA 채널을 픽셀마다 네 칸에 저장한다. 따라서 픽셀의 첫 채널 위치를 계산한 다음 네 채널을 각각 기록한다.

```javascript
function setup() {
  createCanvas(320, 240);
  pixelDensity(1);
  noLoop();
}

function draw() {
  loadPixels();

  const scale = Math.min(width, height);

  for (let y = 0; y < height; y++) {
    for (let x = 0; x < width; x++) {
      const u = (x + 0.5 - width / 2) / scale;
      const v = (y + 0.5 - height / 2) / scale;
      const distance = Math.sqrt(u * u + v * v);
      const intensity = Math.round(128 + 127 * Math.cos(80 * distance));
      const index = 4 * (x + y * width);

      pixels[index] = intensity;
      pixels[index + 1] = intensity;
      pixels[index + 2] = intensity;
      pixels[index + 3] = 255;
    }
  }

  updatePixels();
}
```

R, G, B에 같은 밝기를 넣으면 회색이 되고, A에 255를 넣으면 완전히 불투명해진다. 모든 픽셀을 덮어쓰므로 별도의 `background()` 호출은 필요하지 않다. 색상 채널에 넣는 값은 0에서 255 사이로 유지한다.

### Processing Java 모드 구현

Processing은 픽셀 배열의 한 항목에 색 하나를 저장한다. 채널별 배열 위치를 계산하는 대신 `color()`로 색 값을 만든다.

```java
void settings() {
  size(320, 240);
  pixelDensity(1);
}

void setup() {
  noLoop();
}

void draw() {
  loadPixels();

  float scale = min(width, height);

  for (int y = 0; y < height; y++) {
    for (int x = 0; x < width; x++) {
      float u = (x + 0.5f - width / 2.0f) / scale;
      float v = (y + 0.5f - height / 2.0f) / scale;
      float distance = sqrt(u * u + v * v);
      float intensity = 128 + 127 * cos(80 * distance);
      int index = x + y * width;

      pixels[index] = color(intensity);
    }
  }

  updatePixels();
}
```

Processing의 `pixels[index]`는 `color` 형식의 값 하나다. 위 예제는 `color(intensity)`로 회색을 만들며, 색의 내부 채널 순서를 직접 조립하지 않는다. 색상 범위와 투명도 표현이 필요하면 `color(gray)` 대신 `color(red, green, blue, alpha)`를 사용할 수 있다.

## 색상 함수로 확장하기

회색 밝기 하나만 계산하는 대신 좌표에서 여러 채널을 각각 계산하면 색상 필드를 만들 수 있다. 화면 위치를 0부터 1 사이로 정규화한 좌표를 사용하면 캔버스 크기가 달라져도 색의 배치가 화면 비율에 맞춰 유지된다.

$$
u_{01}=\frac{x+0.5}{width},\qquad v_{01}=\frac{y+0.5}{height}
$$

예를 들어 $u_{01}$을 빨강 채널, $v_{01}$을 초록 채널에 대응시키고, 거리에 따른 코사인 파동을 파랑 채널에 연결한다.

```text
red   = 255 * u01
green = 255 * v01
blue  = 127.5 + 127.5 * cos(distance * frequency)
```

다음은 안쪽 반복문에서 좌표와 `distance`를 계산한 뒤 실행하는 부분이다. `distance`는 앞 예제처럼 화면 중심으로부터의 정규화된 거리이고, `frequency`는 색 띠의 간격을 정한다. 여기서는 동심원 예제와 같은 80을 사용한다.

```javascript
const u01 = (x + 0.5) / width;
const v01 = (y + 0.5) / height;
const frequency = 80;
const red = Math.round(255 * u01);
const green = Math.round(255 * v01);
const blue = Math.round(127.5 + 127.5 * Math.cos(distance * frequency));
const index = 4 * (x + y * width);

pixels[index] = red;
pixels[index + 1] = green;
pixels[index + 2] = blue;
pixels[index + 3] = 255;
```

Processing에서는 채널 값을 색으로 묶어 픽셀 한 칸에 넣는다.

```java
float u01 = (x + 0.5f) / width;
float v01 = (y + 0.5f) / height;
float frequency = 80;
float red = 255 * u01;
float green = 255 * v01;
float blue = 127.5f + 127.5f * cos(distance * frequency);
int index = x + y * width;

pixels[index] = color(red, green, blue);
```

RGBA의 마지막 채널인 알파는 불투명도를 나타낸다. 전체 이미지를 불투명하게 덮어쓸 때는 p5.js에서 알파를 255로 기록하고, Processing에서는 `color(red, green, blue, alpha)`를 사용한다. 노이즈나 마스크를 채널 값 대신 입력하면 질감과 윤곽을 결합한 이미지로 확장할 수 있다. 채널 값은 일반적으로 0에서 255 사이에서 해석되므로, 다른 범위의 함수를 연결할 때는 먼저 `map()`이나 보간으로 범위를 맞춘다.

## 픽셀 밀도와 성능

`pixelDensity(1)`을 쓰지 않으면 고밀도 화면에서 논리 좌표 한 칸이 실제 픽셀 여러 개와 연결된다. 그러면 논리적 `width * height`에 맞춘 인덱스 계산만으로는 전체 배열을 올바르게 다루지 못한다. 픽셀별 알고리즘을 설명하거나 결과를 논리 해상도에서 일정하게 만들 때는 밀도를 1로 고정하는 편이 단순하다. 출력 선명도가 중요하다면 실제 밀도와 물리 버퍼 크기에 맞게 순회해야 한다. 해상도와 밀도를 모두 반영하면 처리해야 하는 픽셀 수가 늘어나는 점도 성능에 포함해야 한다.

픽셀 전체를 도는 계산량은 대략 `width * height`에 비례한다. 320 x 240은 76,800번의 계산이지만, 1920 x 1080은 약 207만 번이다. 애니메이션에서 매 프레임 전체 배열을 다시 계산하면 해상도 증가가 곧 비용 증가로 이어진다. 정적인 이미지는 `noLoop()`로 한 번만 계산하고, 움직이는 이미지에서는 해상도를 낮추거나 일부 프레임에서만 갱신하거나 계산을 간소화할 수 있다. 픽셀 접근이 성능 병목이 된다면 오프스크린 표면이나 GPU 셰이더가 더 적합한지도 검토한다.

## 이 절의 핵심

픽셀 기반 이미지는 각 좌표에서 함수를 평가해 색상 값으로 바꾼다. p5.js는 `pixels` 배열에 RGBA 네 채널을 저장하고, Processing은 픽셀마다 `color` 값 하나를 저장하므로 인덱스와 색을 기록하는 방식이 다르다. `loadPixels()`로 배열을 준비하고 `updatePixels()`로 반영하며, 픽셀 밀도와 전체 픽셀 수가 인덱싱 정확도와 계산 비용에 미치는 영향을 함께 고려한다.
