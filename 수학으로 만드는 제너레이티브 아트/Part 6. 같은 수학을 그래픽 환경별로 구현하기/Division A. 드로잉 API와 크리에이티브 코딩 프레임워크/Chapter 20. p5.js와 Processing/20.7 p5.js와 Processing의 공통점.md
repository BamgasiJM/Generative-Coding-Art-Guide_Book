# 20.7 p5.js와 Processing의 공통점

p5.js와 Processing은 서로 다른 언어와 실행 환경을 사용하지만, 화면에 수학적 규칙을 그리는 기본 사고방식은 많이 공유한다. 캔버스를 준비하고, 좌표를 계산하고, 도형과 색으로 결과를 표현한다. 따라서 한쪽에서 익힌 규칙을 다른 쪽으로 옮길 때 핵심은 코드를 그대로 복사하는 것이 아니라, 수학적 의도와 라이브러리 문법을 나누어 보는 일이다.

## 같은 수학에서 출발하기

두 환경에서 제너레이티브 이미지를 만드는 과정은 대체로 다음 흐름을 따른다.

1. 파라미터와 입력값을 정한다.
2. 함수와 좌표 연산으로 점이나 색을 계산한다.
3. 드로잉 API를 사용해 선, 원, 면을 그린다.
4. 필요하면 시간이나 입력에 따라 값을 갱신하고 다시 그린다.

예를 들어 원 둘레에 점을 균등하게 배치하는 수학은 환경과 관계없이 같다. 점의 개수를 $N$, 반지름을 $r$, 점의 번호를 $i$라고 하면 각 점의 각도와 위치는 다음과 같다.

$$
\theta_i=\frac{2\pi i}{N},\qquad
x_i=r\cos\theta_i,\qquad
y_i=r\sin\theta_i
$$

여기서 달라지는 것은 계산 결과를 화면에 전달하는 방식이다. 두 예제는 캔버스 중심을 원점으로 옮긴 뒤 같은 계산으로 방사형 선과 끝점을 그린다.

### p5.js

```javascript
function setup() {
  createCanvas(420, 420);
  noLoop();
}

function draw() {
  background(248);
  translate(width * 0.5, height * 0.5);
  noFill();
  stroke(35, 95, 130);

  const count = 24;
  const radius = Math.min(width, height) * 0.34;

  for (let i = 0; i < count; i++) {
    const angle = TWO_PI * i / count;
    const x = radius * cos(angle);
    const y = radius * sin(angle);

    line(0, 0, x, y);
    circle(x, y, 10);
  }
}
```

### Processing Java 모드

```java
void settings() {
  size(420, 420);
}

void setup() {
  noLoop();
}

void draw() {
  background(248);
  translate(width * 0.5f, height * 0.5f);
  noFill();
  stroke(35, 95, 130);

  int count = 24;
  float radius = min(width, height) * 0.34f;

  for (int i = 0; i < count; i++) {
    float angle = TWO_PI * i / count;
    float x = radius * cos(angle);
    float y = radius * sin(angle);

    line(0, 0, x, y);
    ellipse(x, y, 10, 10);
  }
}
```

각도는 두 환경에서 기본적으로 라디안이다. 화면 좌표의 $y$축이 아래를 향하므로 이 식의 각도는 화면에서 시계 방향으로 증가해 보인다. 두 프로그램 모두 같은 좌표와 같은 반복 규칙을 사용하지만, p5.js는 JavaScript 문법을, Processing은 Java 문법을 사용한다. 끝점의 원도 p5.js에서는 `circle(x, y, diameter)`, Processing에서는 가로와 세로 지름을 받는 `ellipse(x, y, width, height)`로 표현했다.

## 공유하는 스케치 구조와 API

두 환경은 초기화와 반복 그리기를 나누는 스케치 구조를 제공한다. `setup()`은 캔버스나 초기 상태를 준비하고, `draw()`는 화면을 그린다. 기본 설정에서는 `draw()`가 계속 호출되므로 정지 이미지에는 `noLoop()`를 사용할 수 있다. 애니메이션이나 입력에 반응하는 작품에서는 매 프레임 상태를 갱신하고 화면을 다시 그린다.

| 개념 | p5.js | Processing Java 모드 | 공통으로 기억할 점 |
| --- | --- | --- | --- |
| 캔버스 준비 | `createCanvas(w, h)` | `settings()` 안의 `size(w, h)` | 너비와 높이를 정하고 `width`, `height`로 읽는다 |
| 반복 그리기 | `setup()`, `draw()` | `setup()`, `draw()` | 초기화와 프레임별 작업을 구분한다 |
| 화면 좌표 | 왼쪽 위 원점, 아래로 증가하는 $y$ | 왼쪽 위 원점, 아래로 증가하는 $y$ | 수학 좌표와 방향을 바꿀 때 축 방향을 확인한다 |
| 도형 | `line()`, `rect()`, `circle()` | `line()`, `rect()`, `ellipse()` | 위치 기준과 크기 인자의 의미를 확인한다 |
| 무작위와 노이즈 | `random()`, `noise()` | `random()`, `noise()` | 비슷한 기능이어도 같은 시드가 같은 결과를 보장하지 않는다 |
| 벡터 | `createVector(x, y)` | `new PVector(x, y)` | 위치·속도·방향을 벡터로 계산한다 |

색상, 채우기, 선 굵기, 좌표 변환처럼 그리기 상태를 설정하는 API도 두 환경에 공통된 개념이 있다. 예를 들어 `fill()`은 채우기 색을, `noFill()`은 채우지 않는 상태를 지정한다. 다만 설정은 다음 도형에도 영향을 주므로, 상태를 어디서 바꾸고 언제 되돌리는지 관리해야 한다. 변환과 스타일을 저장하는 명령은 이름과 범위가 다르다. p5.js의 `push()`와 `pop()`은 변환과 스타일 상태를 함께 저장·복원하지만, Processing에서는 변환 행렬에 `pushMatrix()`와 `popMatrix()`, 스타일에 `pushStyle()`과 `popStyle()`을 사용한다.

픽셀 접근 역시 각 픽셀의 색을 계산한다는 목적은 같지만 배열 구조는 다르다. p5.js는 `pixels`에 RGBA 채널 네 개를 연속해서 두고, Processing은 픽셀마다 `color` 값 하나를 둔다. API 이름이 비슷하다고 내부 표현까지 같다고 가정하지 않는다. 구체적인 인덱스와 픽셀 밀도는 20.6절에서 다루었다.

## 코드 이식 때 바꿀 것과 지킬 것

다른 환경으로 옮길 때 보존할 것은 수식과 그 수식이 표현하는 관계다. 예를 들어 “각 점의 각도는 번호에 비례한다”, “거리로 색의 밝기를 정한다”, “속도에 시간 간격을 곱해 위치를 갱신한다” 같은 규칙은 그대로 유지할 수 있다. 바꿔야 하는 것은 변수 선언, 함수 이름과 인자, 자료형, 캔버스 생성 위치, 상태 관리 방식처럼 실행 환경에 가까운 부분이다.

이식 과정에서는 다음 항목을 차례로 확인하면 실수를 줄일 수 있다.

1. **좌표와 단위:** 원점, $y$축 방향, 각도 단위, 정규화 기준이 같은가?
2. **도형 인자:** 위치가 중심인지 모서리인지, 크기가 지름인지 반지름인지 확인했는가?
3. **자료형과 문법:** Java의 자료형 선언과 세미콜론을 JavaScript 문법에 그대로 옮기지 않았는가?
4. **그리기 상태:** 채우기, 선, 변환이 다음 도형에 남지 않도록 관리했는가?
5. **프레임과 버퍼:** 정지 이미지인지 애니메이션인지, 픽셀 밀도와 배열 형식이 무엇인지 확인했는가?

수학 계산과 그리기 코드를 함수로 나누면 이식이 더 쉬워진다. 예를 들어 `pointOnCircle(angle, radius)`처럼 점을 계산하는 부분은 환경에 독립적인 규칙으로 두고, 결과를 `circle()`, `ellipse()` 또는 다른 도형 API에 전달한다. 코드가 커질수록 이런 분리는 작품의 수학적 모델과 화면에 그리는 방법을 따로 수정할 수 있게 해 준다.

## 공통점은 같음이 아니라 대응 관계다

p5.js와 Processing은 친척처럼 닮았지만, 하나의 언어에 두 가지 표기법이 있는 것은 아니다. JavaScript와 Java는 자료형, 함수 선언, 배열, 객체 사용 방식이 다르고 라이브러리 API도 완전히 일치하지 않는다. 또한 난수 생성기나 노이즈 구현이 다를 수 있으므로 동일한 시드만으로 화면 결과까지 같아진다고 기대해서는 안 된다. 재현이 중요하다면 환경과 버전, 시드, 주요 파라미터를 함께 기록한다.

그러므로 두 환경을 함께 익힐 때는 API 이름을 일대일로 암기하기보다, “이 명령은 수학적 모델의 어느 부분을 화면에 연결하는가?”를 먼저 묻는다. 좌표와 함수의 의미를 이해하면 문법이 달라져도 대응되는 API를 찾아 다시 표현할 수 있다. 다음 절에서는 이 공통 수학이 웹과 데스크톱이라는 서로 다른 실행 환경에서 어떻게 달라지는지 살펴본다.

## 이 절의 핵심

p5.js와 Processing은 스케치의 생명주기, 화면 좌표, 도형 중심의 드로잉, 수학 함수와 반복문을 공유한다. 그러나 언어와 API, 벡터·픽셀 자료 구조, 상태 저장 방식은 다를 수 있다. 수학적 규칙은 보존하고 환경 의존적인 입출력과 문법은 해당 라이브러리에 맞춰 다시 표현하는 것이 두 환경을 오가는 기본 원칙이다.
