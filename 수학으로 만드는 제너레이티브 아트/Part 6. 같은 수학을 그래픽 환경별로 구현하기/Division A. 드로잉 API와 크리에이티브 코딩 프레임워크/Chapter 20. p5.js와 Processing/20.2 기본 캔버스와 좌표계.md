# 20.2 기본 캔버스와 좌표계

캔버스(canvas)는 도형이 그려지는 표면이면서, 각 그리기 명령이 해석될 좌표 공간이다. Processing과 p5.js의 기본 좌표계는 화면을 기준으로 한다. 캔버스의 왼쪽 위가 $(0,0)$이고, $x$는 오른쪽으로, $y$는 아래쪽으로 증가한다. 이 절에서는 두 환경에서 캔버스를 만들고, 수학에서 사용하는 좌표를 화면에 맞게 옮기는 방법을 살펴본다. 캔버스의 픽셀 밀도와 메모리 같은 공통 원리는 19.1절을 참고한다.

## 캔버스 만들기

p5.js에서는 보통 `setup()` 안에서 `createCanvas(width, height)`를 호출한다. 아래 예제는 너비 640, 높이 400의 캔버스를 만들고 가운데에 원을 그린다.

```javascript
function setup() {
  createCanvas(640, 400);
  noStroke();
}

function draw() {
  background(248);
  circle(width / 2, height / 2, 80);
}
```

Processing의 Java 모드에서는 캔버스 크기와 렌더러 같은 사전 설정을 `settings()`에서 정한다. `settings()`는 `setup()`보다 먼저 실행된다. 초기화할 다른 값은 `setup()`에서 준비하고, 화면을 그리는 코드는 `draw()`에 둔다.

```java
void settings() {
  size(640, 400);
}

void setup() {
  noStroke();
}

void draw() {
  background(248);
  ellipse(width / 2, height / 2, 80, 80);
}
```

두 예제는 같은 크기의 캔버스 중심에 지름 80인 원을 그린다. p5.js의 `createCanvas()`와 Processing의 `size()`는 크기와 렌더링 표면을 준비한다. 두 환경 모두 `width`와 `height`로 현재 캔버스의 논리적 너비와 높이를 읽을 수 있다. 크기를 코드에 반복해서 직접 적기보다 이 값을 사용하면, 캔버스 크기를 바꾸어도 배치 규칙을 유지하기 쉽다.

## 화면 좌표의 원점과 방향

기본 화면 좌표계의 원점은 왼쪽 위다. 오른쪽으로 이동하면 $x$가 커지고, 아래로 이동하면 $y$가 커진다. 도형 위치에는 정수가 아닌 실수 좌표도 사용할 수 있으며, 캔버스 바깥으로 나간 부분은 보통 화면에 보이지 않도록 잘린다.

```text
(0, 0) ------------------> +x
  |
  |
  v +y
```

캔버스 크기가 `width x height`라면 화면의 기하학적 범위는 대략 $0\leq x\leq width$, $0\leq y\leq height$로 생각할 수 있다. 다만 픽셀 배열의 인덱스는 보통 정수이며 마지막 픽셀은 각각 `width - 1`, `height - 1`이다. 연속적인 도형 좌표와 픽셀 인덱스를 직접 다룰 때의 범위를 혼동하지 않는다. 픽셀 배열을 읽고 쓰는 방법은 20.6절에서 다룬다.

이 좌표계는 수학 교과서에서 흔히 보는 데카르트 좌표계와 $y$축의 방향이 반대다. 수학 좌표에서 $y$가 커질수록 위로 올라가지만, 화면에서는 아래로 내려간다. 따라서 원점이 화면 중심인 수학 좌표 $(x_m,y_m)$를 화면 좌표 $(x_s,y_s)$로 옮길 때는 다음처럼 계산할 수 있다.

$$
x_s=c_x+s x_m,\qquad y_s=c_y-s y_m
$$

여기서 $(c_x,c_y)$는 화면에서 수학적 원점을 둘 위치이고, $s$는 수학 단위를 픽셀로 바꾸는 배율이다. 중심을 원점으로 둘 때 $c_x=width/2$, $c_y=height/2$다. 앞의 빼기 부호는 수학에서 위쪽을 향하는 양의 $y$를 화면 위쪽으로 보낸다.

예를 들어 수학 좌표에서 반지름 $r$인 원을 그릴 때는 각도 $\theta$에 대해 다음 점들을 계산한다.

$$
x_s=c_x+s r\cos\theta,\qquad y_s=c_y-s r\sin\theta
$$

$\theta=\pi/2$일 때 점이 화면 중심의 위쪽에 놓인다. 화면 좌표에 그대로 $+r\sin\theta$를 더하면 회전 방향이 수학 좌표계와 반대로 보일 수 있다. p5.js와 Processing의 삼각 함수와 회전 API는 기본적으로 라디안(radian)을 사용하므로 각도의 단위도 함께 확인한다. p5.js에서는 `angleMode(DEGREES)`로 도(degree)를 선택할 수 있지만, 한 스케치 안에서 단위를 일관되게 유지해야 한다.

## 도형의 기준점과 크기

좌표가 도형의 어느 지점을 가리키는지도 함수마다 확인해야 한다. 원과 타원의 기본 위치는 중심이고, 사각형의 기본 위치는 왼쪽 위 모서리다. 선은 시작점과 끝점의 좌표를 받는다.

| 도형 명령 | 위치 인자의 의미 | 크기 인자의 의미 |
| --- | --- | --- |
| `circle(x, y, d)` 또는 `ellipse(x, y, w, h)` | 원·타원의 중심 | 지름 또는 가로·세로 크기 |
| `rect(x, y, w, h)` | 기본적으로 왼쪽 위 모서리 | 가로·세로 크기 |
| `line(x1, y1, x2, y2)` | 선의 시작점과 끝점 | 별도의 크기 인자 없음 |

`rectMode()`를 사용하면 사각형의 위치를 모서리가 아니라 중심으로 해석하게 바꿀 수 있다. `ellipseMode()`도 타원의 위치와 크기 인자를 해석하는 방식을 바꾼다. 이 모드는 좌표계를 이동시키는 것이 아니라 도형 함수의 인자 의미를 바꾼다. 특히 사각형을 화면 중심에 놓으려는 경우, 기본 모드에서는 좌표가 중심이 아닌 왼쪽 위를 가리킨다는 점을 기억한다.

```javascript
rectMode(CENTER);
rect(width / 2, height / 2, 120, 60);
```

Processing에서도 같은 모드 이름을 사용할 수 있다.

```java
rectMode(CENTER);
rect(width / 2, height / 2, 120, 60);
```

모드를 바꾸면 이후에 그리는 도형에도 설정이 남는다. 한 구간에서만 다른 기준점을 쓰려면 기본 모드로 되돌리거나, 환경의 상태 저장 기능으로 변환과 스타일을 저장·복원한다. 이처럼 좌표 값이 같아도 원점과 기준점의 의미가 달라지면 도형의 위치는 달라진다.

## 화면 크기에 맞춰 배치하기

고정된 픽셀 좌표만 사용하면 캔버스 크기를 바꿀 때 패턴의 위치와 비율이 달라진다. 중심이나 가장자리를 기준으로 놓을 요소는 `width`와 `height`의 비율로 계산할 수 있다. 크기나 간격을 양쪽 화면에서 비슷한 비율로 유지하려면 짧은 변을 기준 단위로 삼는 방법이 있다.

```text
centerX = width * 0.5
centerY = height * 0.5
unit = min(width, height)
radius = unit * 0.12
```

이렇게 하면 가로형과 세로형 캔버스 모두에서 원이 찌그러지지 않고, 중심을 기준으로 비슷한 크기를 유지한다. 화면 너비와 높이로 각각 좌표를 나누어 정규화하는 방법과 종횡비(aspect ratio)를 고려하는 원리는 19.1절에서 설명한 내용을 적용하면 된다. 캔버스의 논리적 크기와 실제 픽셀 버퍼 크기는 고밀도 디스플레이에서 다를 수 있으므로, 좌표를 배치하는 일과 픽셀을 직접 읽고 쓰는 일을 구분한다.

## 중심을 원점으로 하는 로컬 좌표

수학 식이 원점 중심으로 정의되어 있다면, 매 점마다 화면 중심을 더하는 대신 좌표 변환으로 원점을 옮길 수 있다. `translate()`는 이후의 그리기 좌표에 이동을 적용한다. 예를 들어 캔버스 중심을 새 원점으로 두면 $(0,0)$에 원을 그리는 코드가 화면 가운데에 나타난다.

```javascript
translate(width / 2, height / 2);
circle(0, 0, 80);
```

Processing에서도 `translate()`를 같은 방식으로 사용할 수 있다. 다만 변환은 이후에 그리는 도형에도 계속 적용되므로, 일부 도형에만 적용하려면 변환 상태를 저장했다가 복원해야 한다. p5.js의 `push()`와 `pop()`, Processing의 `pushMatrix()`와 `popMatrix()`가 이때 쓰인다. 변환의 수학적 의미와 순서는 7장에서 다룬 좌표 변환과 같다. 달라지는 것은 각 환경에서 변환 상태를 저장하고 명령을 호출하는 API다.

## 이 절의 핵심

p5.js는 `createCanvas()`, Processing Java 모드는 `settings()` 안의 `size()`로 캔버스를 준비한다. 두 환경의 기본 원점은 왼쪽 위이고 화면의 $y$축은 아래 방향으로 증가한다. 도형마다 위치 기준점과 크기 인자의 의미가 다를 수 있으므로 API를 확인하고, 수학 좌표를 사용할 때는 원점 이동과 $y$축 반전을 적용한다. 캔버스 비율에 맞는 배치에는 `width`, `height`와 짧은 변을 기준으로 한 단위를 활용한다.
