# 20.1 교육과 실험을 위한 드로잉 환경

수학적 규칙을 화면에 옮기는 첫 단계는 복잡한 그래픽 엔진을 직접 만드는 일이 아니다. 좌표와 색, 도형을 몇 줄의 코드로 지정하고 결과를 바로 확인할 수 있는 환경을 고르면 된다. Processing과 p5.js는 이런 작업을 위해 널리 쓰이는 크리에이티브 코딩(creative coding) 환경이다. 코드를 실행하면 화면에 선과 도형이 나타나고, 숫자나 함수를 조금 바꾸면 결과가 어떻게 달라지는지 곧바로 실험할 수 있다.

여기서 드로잉 환경은 단순히 도형을 그리는 함수 모음만을 뜻하지 않는다. 코드를 작성하고 실행하는 편집기, 캔버스를 준비하는 방법, 프로그램의 시작과 반복을 관리하는 구조, 입력과 결과를 확인하는 도구가 함께 작동한다. 이러한 틀을 이용하면 렌더링의 세부 구현에 매달리기보다 수학적 규칙과 그 규칙이 만드는 형태에 집중할 수 있다.

## 스케치로 생각하기

Processing과 p5.js에서는 작은 프로그램을 스케치(sketch)처럼 다룬다. 아이디어를 작게 구현하고, 실행 결과를 살펴보고, 규칙이나 파라미터를 바꿔 다시 실행하는 순환이 짧다. 완성된 프로그램을 한 번에 작성하기보다, 간단한 결과를 출발점으로 삼아 관찰과 수정을 반복하기 좋다.

이 방식은 수학을 시각적으로 실험할 때 특히 유용하다. 반복문의 횟수를 바꾸면 패턴의 밀도가 어떻게 달라지는지, 함수의 주파수를 바꾸면 물결 간격이 어떻게 변하는지 화면에서 비교할 수 있다. 코드는 결과를 만드는 절차이면서, 변수와 규칙 사이의 관계를 탐색하는 실험 장치가 된다. 그렇다고 내부 원리를 감추는 도구는 아니다. 좌표, 반복, 함수, 상태 갱신 같은 계산은 코드에 드러나며, 라이브러리는 그것을 화면에 연결하는 공통 작업을 맡는다.

## Processing과 p5.js

Processing은 Casey Reas와 Ben Fry가 시각 예술과 디자인을 위한 프로그래밍을 쉽게 실험할 수 있도록 시작한 오픈 소스 환경이다. 표준 Java 모드에서는 Java 언어로 스케치를 작성하고, Processing 개발 환경에서 실행한다. p5.js는 Processing의 아이디어와 스케치 방식을 JavaScript와 웹 브라우저 환경으로 확장한 라이브러리다. 브라우저에서 코드를 실행하거나 웹 프로젝트 안에 스케치를 포함할 수 있다.

두 환경은 스케치의 구조와 드로잉 명령에서 닮은 점이 많지만 같은 프로그램이나 같은 언어는 아니다.

| 구분 | Processing | p5.js |
| --- | --- | --- |
| 주로 사용하는 언어 | Java 표준 모드 | JavaScript |
| 주된 실행 환경 | Processing 개발 환경의 데스크톱 스케치 | 웹 브라우저와 JavaScript 실행 환경 |
| 시작 구조의 예 | `void settings()`, `void setup()`, `void draw()` | `function setup()`과 `function draw()` |
| 캔버스를 만드는 예 | `size(width, height)` | `createCanvas(width, height)` |
| 익숙해지기 좋은 경우 | Java와 데스크톱 작업 흐름을 활용할 때 | 웹 기술과 브라우저 공유를 활용할 때 |

표의 차이는 대표적인 기본 사용 방식이다. Processing에는 여러 모드와 라이브러리가 있고, p5.js는 웹 에디터뿐 아니라 로컬 프로젝트 환경에서도 개발할 수 있다. 실제 프로젝트에서는 사용하는 버전과 개발 환경의 문서를 확인해야 한다.

## 같은 아이디어, 다른 문법

두 환경의 공통점은 같은 기하학적 생각을 각 환경의 문법으로 표현할 수 있다는 데 있다. 아래 예제는 캔버스의 가운데에 원을 그린다.

```javascript
// p5.js
function setup() {
  createCanvas(320, 200);
}

function draw() {
  background(245);
  circle(width / 2, height / 2, 60);
}
```

```java
// Processing, Java mode
void settings() {
  size(320, 200);
}

void setup() {
  noStroke();
}

void draw() {
  background(245);
  ellipse(width / 2, height / 2, 60, 60);
}
```

두 코드 모두 캔버스의 너비와 높이의 절반을 중심 좌표로 사용한다. 하지만 함수 이름과 인자의 의미, 언어 문법은 완전히 같지 않다. 예를 들어 p5.js의 `circle()`은 중심과 지름을 받고, Processing의 `ellipse()`는 중심과 가로·세로 크기를 받는다. 그러므로 한 환경의 코드를 다른 환경에 그대로 붙여 넣기보다, 먼저 수학적 의도를 파악하고 그 환경의 API에 맞게 표현해야 한다. 다음 절에서는 캔버스와 좌표계부터 차례로 그 차이를 살펴본다.

이 예제에서 Processing의 `settings()`는 캔버스 크기를 지정하며 `setup()`보다 먼저 실행된다. p5.js는 `setup()`에서 캔버스를 만든다. 두 환경의 `setup()`은 초기 준비를, `draw()`는 화면을 그리는 부분을 나타내지만, 언제 몇 번 실행되는지와 화면을 매번 지우는지 이전 결과를 남기는지는 뒤의 프레임 애니메이션 절에서 자세히 다룬다. 여기서는 스케치가 실행을 준비하는 부분과 그림을 만드는 부분을 나누어 작성한다는 정도로 이해하면 충분하다.

## 어떤 환경을 선택할까

p5.js는 결과를 브라우저에서 쉽게 공유하거나 웹페이지와 연결하려는 작업에 잘 맞는다. JavaScript와 HTML, CSS를 함께 사용하고 싶을 때도 자연스럽다. Processing은 Java를 사용하거나 데스크톱 중심의 스케치 작업을 선호할 때 편리하다. 두 환경 모두 작은 그림과 반복 패턴을 빠르게 시험할 수 있으므로, 어느 쪽이 본질적으로 더 낫다기보다 익숙한 언어, 배포 방식, 필요한 라이브러리에 따라 선택한다.

환경을 고르더라도 수학적 규칙은 그대로 가져갈 수 있다. 원의 방정식이나 벡터의 움직임은 특정 API에 속하지 않는다. 캔버스를 만드는 명령, 도형을 그리는 함수, 입력을 받는 방식처럼 실행과 출력에 가까운 부분이 환경에 따라 달라진다. 이 차이를 분리해 익히면 한 환경에서 배운 개념을 다른 환경으로 옮길 때도 계산의 의미를 잃지 않는다.

## 이 장에서 살펴볼 내용

다음 절에서는 기본 캔버스와 좌표계를 만들고, 함수와 반복문으로 여러 도형을 배치한다. 이어 프레임에 따라 변하는 애니메이션, 랜덤·노이즈·벡터, 픽셀 단위 이미지 생성을 살펴본다. 마지막에는 p5.js와 Processing에서 공유하는 생각과 웹·데스크톱 실행 환경의 차이를 정리한다. 각 절에서 중요한 것은 함수 이름을 외우는 데 그치지 않고, 익숙한 수학적 규칙이 어떤 API를 통해 실제 화면이 되는지 확인하는 일이다.

## 이 절의 핵심

Processing과 p5.js는 코드를 화면의 결과와 연결해 수학적 아이디어를 빠르게 시험할 수 있는 크리에이티브 코딩 환경이다. 두 도구는 스케치 방식과 드로잉 개념을 공유하지만 언어와 API가 다르다. 공통 수학과 환경별 문법을 구분하면 각 환경의 명령을 익히면서도 규칙의 의미를 유지할 수 있다.
