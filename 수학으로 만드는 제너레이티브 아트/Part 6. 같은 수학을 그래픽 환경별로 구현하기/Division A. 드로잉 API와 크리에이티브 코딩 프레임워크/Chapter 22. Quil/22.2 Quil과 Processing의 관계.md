# 22.2 Quil과 Processing의 관계

Quil은 Clojure에서 Processing 스타일의 스케치와 그래픽 API를 사용할 수 있게 해 주는 라이브러리다. Quil의 중심적인 JVM 실행 경로는 Processing의 그래픽 기반을 활용하면서, 개발자가 Clojure의 함수와 자료 구조로 스케치를 작성하도록 연결한다. 따라서 Quil은 Processing과 무관하게 같은 도형 함수만 흉내 낸 별도 렌더러라기보다, Processing의 작업 모델을 Clojure에서 사용할 수 있도록 감싼 층으로 이해하는 편이 정확하다.

이 관계는 두 가지를 동시에 뜻한다. Processing에서 익숙한 캔버스, 도형, 색, 변환의 개념을 이어서 사용할 수 있고, 프로그램의 표현은 Clojure 문법과 관용구에 맞춰 달라진다. 수학적 규칙은 공통으로 유지할 수 있지만, Java 코드나 Processing 프로젝트를 그대로 Quil에 복사해 실행할 수 있는 것은 아니다.

## Processing API를 Clojure에서 부르기

Processing Java 모드에서는 스케치 안에서 `ellipse()` 같은 함수를 호출한다. Quil에서는 보통 `quil.core` 네임스페이스를 짧은 별칭으로 불러오고, 그 API를 네임스페이스 접두어와 함께 호출한다.

아래는 각각 프레임별 그리기 함수 안에 들어갈 호출 부분이다. Quil 파일에서는 보통 `[quil.core :as q]`로 네임스페이스를 불러온다.

```java
// Processing의 draw() 본문
ellipse(250, 250, 40, 40);
```

```clojure
;; Quil의 draw 콜백 본문
(q/ellipse 250 250 40 40)
```

두 호출 모두 중심이 `(250, 250)`이고 가로·세로 크기가 40인 타원을 그린다. Quil의 `q/ellipse`는 Clojure의 네임스페이스 규칙을 따르는 함수 호출이고, Processing의 `ellipse`는 Java 스케치 문맥의 메서드 호출이다. 괄호와 인자 구분이 달라져도 도형의 기하학적 의미는 대응시킬 수 있다. 다만 한 API의 인자 단위, 오버로드, 기본 상태가 다른 API와 항상 똑같다고 가정해서는 안 된다.

Processing에서 익숙한 채우기와 외곽선 같은 드로잉 상태도 Quil에서 비슷한 방식으로 설정할 수 있다. 예를 들어 채우기 색을 먼저 지정한 다음 여러 도형을 그리는 스타일은 이어진다. 이런 상태 기반 호출의 이점은 간단한 스케치를 빠르게 구성한다는 것이고, 주의점은 현재 스타일이 다음 호출에 영향을 줄 수 있다는 것이다. 변환과 스타일 상태를 어떻게 다루는지는 실제 스케치 구조와 함께 뒤에서 살펴본다.

## 무엇을 계승하고 무엇이 달라지는가

| 관점 | Processing | Quil |
| --- | --- | --- |
| 언어 | 주로 Java 표준 모드 | Clojure |
| 그래픽 기반 | Processing의 스케치·렌더링 API | JVM에서 Processing 기반을 활용하고 Clojure API로 노출 |
| 함수 호출 | 스케치 문맥의 `ellipse(...)` | `quil.core` 별칭을 통한 `(q/ellipse ...)` |
| 데이터 표현 | Java의 원시형·배열·객체 | Clojure의 숫자·벡터·맵·시퀀스 등 |
| 생성 규칙 구성 | 반복문과 메서드 호출을 중심으로 작성 가능 | 함수와 데이터 변환을 조합하는 스타일과 잘 맞음 |

표는 일반적인 사용 방식의 비교다. Processing도 Java의 함수와 객체를 자유롭게 구성할 수 있고, Quil도 스케치와 그래픽 출력이라는 Processing의 흐름을 따른다. 차이는 한쪽이 함수형이고 다른 쪽이 그렇지 않다는 단순한 이분법이 아니다. Quil에서는 Clojure의 값과 함수가 기본 재료가 되고, Processing의 그래픽 기능은 그 결과를 시각화하는 기반이 된다.

## p5.js와의 관계

p5.js도 Processing의 시각적 프로그래밍 방식에서 영감을 받은 스케치 라이브러리지만, Quil의 렌더링 기반은 아니다. p5.js는 JavaScript와 브라우저 중심의 독립적인 구현이고, Quil은 Clojure와 Processing 생태계를 연결한다. 두 도구는 `setup`·`draw`에 해당하는 반복 구조, 기본 도형, 좌표 변환처럼 비슷한 개념을 제공할 수 있지만, 언어와 실행 환경, 함수 인자, 자료형, 렌더러가 다르다.

예를 들어 p5.js의 `circle(x, y, diameter)`는 원의 지름을 인자로 받지만, Processing 계열의 `ellipse(x, y, width, height)`는 가로·세로 크기를 받는다. Quil에서 쓰는 도형 함수도 Processing의 API와 의미가 가까운 경우가 많지만, 실제 코드를 옮길 때는 Quil 문서에서 해당 함수와 인자를 확인한다. Processing이나 Quil의 코드를 p5.js로 가져갈 때도 구문을 치환하는 데 그치지 말고 함수의 기하학적 의미를 비교해야 한다.

## Clojure 생태계의 다른 그래픽 라이브러리

Quil만이 Clojure에서 그래픽을 만드는 방법은 아니다. 라이브러리마다 스케치 실행, 2D 이미지 처리, 기하 데이터 생성 중 어디에 초점을 두는지가 다르다.

| 도구 | 주된 역할 | Quil과의 관계 |
| --- | --- | --- |
| Processing | Java 기반 크리에이티브 코딩 환경과 그래픽 API | Quil의 JVM 그래픽 기반이자 API 모델의 직접적인 계보 |
| p5.js | 브라우저에서 실행하는 JavaScript 스케치 라이브러리 | Processing에서 영감을 받은 별도 구현. Quil의 백엔드는 아님 |
| clojure2d | Clojure/JVM에서 2D 그래픽과 이미지 작업을 구성하는 라이브러리 | Processing 중심의 스케치 모델과 다른 API·작업 흐름을 제공하는 대안 |
| thi.ng/geom | Clojure 및 관련 환경에서 쓰는 기하·벡터·메시 데이터 도구 모음 | 생성한 기하 데이터를 만들고 다루는 데 보완적으로 사용 가능하며, Quil 같은 스케치 프레임워크 자체는 아님 |

`clojure2d`는 이미지와 2D 그래픽을 직접 구성하는 작업에 관심이 있을 때 살펴볼 수 있고, `thi.ng/geom`은 벡터, 도형, 메시 같은 기하 데이터를 만들고 변환하는 데 도움을 줄 수 있다. 이런 라이브러리는 Quil을 대체할 수도 있고, 필요한 기능에 따라 데이터 생성 계층에서 Quil과 함께 사용할 수도 있다. 단, 함께 쓸 수 있는지는 플랫폼, 의존성, 자료형이 맞는지에 달려 있으며 라이브러리 이름이 모두 Clojure라고 해서 API가 서로 호환되는 것은 아니다.

Processing 생태계의 Java 라이브러리를 Clojure 프로젝트에서 활용하는 것도 가능하다. Clojure는 JVM 언어이므로 Java 클래스와 상호작용할 수 있지만, Processing의 스케치 생명주기나 특정 렌더러를 전제로 한 라이브러리는 Quil의 구조에 맞게 연결해야 할 수 있다. Java 인터롭이 가능하다는 사실과 두 라이브러리가 별도 설정 없이 함께 동작한다는 것은 다른 주장이다.

## 어떤 관계를 기억하면 좋을까

Quil을 배울 때 Processing을 알면 도형·색·변환과 스케치라는 시각적 모델을 이해하는 데 도움이 된다. Clojure를 알면 함수와 컬렉션을 이용해 규칙과 데이터를 구성하는 방식이 자연스러워진다. 둘 중 하나를 다른 하나로 대체한다고 보기보다, Processing이 제공해 온 크리에이티브 코딩의 표현 영역을 Quil이 Clojure 쪽에서 연결한다고 생각하면 된다.

다른 라이브러리와 비교할 때는 먼저 필요한 역할을 정한다. 프레임별로 반응하는 스케치와 Processing 계열의 도형 API가 중요하다면 Quil이 적합할 수 있다. 브라우저에서 공유하는 것이 우선이면 p5.js가 직접적인 선택이고, 이미지만 생성하거나 파일로 변환하는 작업이면 Clojure의 2D 이미지 도구가 더 맞을 수 있다. 기하 계산과 메시 변환이 중심이면 `thi.ng/geom` 같은 데이터 중심 라이브러리를 검토할 수 있다. 라이브러리 선택은 이름이나 계보보다 실행 환경, 출력 방식, 필요한 추상화에 따라 달라진다.

## 이 절의 핵심

Quil은 Clojure 문법으로 Processing 스타일의 스케치와 그래픽 기능을 사용하는 라이브러리이며, JVM 경로에서는 Processing의 그래픽 기반과 연결된다. p5.js는 비슷한 아이디어를 공유하지만 JavaScript와 브라우저를 위한 별도 구현이다. `clojure2d`와 `thi.ng/geom`은 각각 2D 그래픽·이미지 작업과 기하 데이터 처리에 초점을 둔 다른 선택지다. 각 도구의 계보와 역할을 구분하면 공통 수학은 재사용하면서 실행 구조와 API는 목적에 맞게 선택할 수 있다.
