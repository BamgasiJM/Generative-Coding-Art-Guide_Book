# 22.1 Clojure와 함수형 제너레이티브 아트

제너레이티브 아트 프로그램은 파라미터와 수학적 규칙으로 점·선·색 같은 데이터를 만들고, 이를 화면에 그린다. Clojure는 이 과정을 값과 함수의 변환으로 구성하기에 잘 맞는 프로그래밍 언어다. 같은 규칙을 서로 다른 파라미터에 적용하고, 그 결과를 순서대로 조합해 패턴을 만들 수 있다. 뒤에서 살펴볼 Quil은 이런 Clojure 코드와 Processing 계열 드로잉을 연결하는 라이브러리다.

## Clojure의 언어적 성격

Clojure는 Lisp 계열의 언어이며 주로 JVM(Java Virtual Machine)에서 실행된다. 연산자나 함수 이름이 앞에 오는 표기법을 사용한다. 예를 들어 덧셈은 `(+ 2 3)`처럼 쓰며, 괄호는 함수 호출과 표현식의 범위를 나타낸다. 처음에는 괄호가 낯설 수 있지만, 코드의 구조가 명시적이고 작은 표현식을 조합하기 쉽다는 장점이 있다.

숫자와 함수 외에도 벡터(vector), 맵(map), 리스트(list), 집합(set) 같은 컬렉션이 언어의 기본 요소다. 벡터는 순서가 있는 값을 담고, 맵은 키와 값의 관계를 표현한다. 예를 들어 점의 좌표를 두 값의 벡터 `[x y]`로, 입자의 위치·색·크기 같은 속성을 맵으로 나타낼 수 있다. 이 데이터 구조를 함수에 전달하고 새로운 값으로 변환하는 방식이 Clojure 프로그래밍의 중심을 이룬다.

Clojure의 기본 컬렉션은 불변(immutable)이다. 값을 바꾸는 대신 기존 값을 바탕으로 새 값을 만든다. 내부적으로는 구조를 공유하는 영속 자료구조(persistent data structure)를 사용하므로, 변경할 때마다 전체 컬렉션을 무조건 복사하는 방식은 아니다. 원본 데이터가 갑자기 바뀌지 않기 때문에 함수의 입력과 결과를 추적하기 쉽고, 패턴 생성의 어느 단계에서 값이 달라졌는지 확인하기 편하다.

## 함수를 규칙으로 다루기

순수 함수(pure function)는 같은 입력에 대해 같은 결과를 반환하고, 함수 바깥의 상태를 몰래 바꾸지 않는다. 예를 들어 각도와 반지름을 받아 원 둘레의 좌표를 반환하는 함수는 화면을 그리지 않고 기하 계산만 수행한다.

```clojure
(defn polar-point
  [radius angle]
  [(* radius (Math/cos angle))
   (* radius (Math/sin angle))])

(defn radial-point
  [index count radius]
  (let [angle (* 2.0 Math/PI (/ index count))]
    (polar-point radius angle)))

(radial-point 3 24 100.0)
```

`defn`은 함수를 정의하고, 함수 이름 뒤의 벡터는 인자 목록을 나타낸다. `let`은 함수 안에서 사용할 이름과 값을 묶는다. `radial-point`는 점의 번호, 전체 개수, 반지름으로 각도를 계산한 뒤 `polar-point`에 전달한다. 예를 들어 24개 점 중 세 번째 점의 좌표를 구하면 원점 기준의 2차원 좌표가 반환된다. 함수 안에는 그리기 명령이 없으므로, 결과를 Quil이 아닌 다른 그래픽 API에 전달해도 계산 규칙은 그대로 쓸 수 있다.

이런 식으로 생성 규칙을 작은 함수로 나누면 조합이 쉬워진다. 한 함수는 각도를 정하고, 다른 함수는 좌표를 만들며, 또 다른 함수는 크기나 색을 계산할 수 있다. 그 결과를 화면에 표현하는 작업은 계산과 별도의 단계로 둔다. 시퀀스에 함수를 적용하고 여러 변환을 연결하는 구체적인 방법은 22.5와 22.6에서 다룬다.

## 함수형 사고와 시각 작업

함수형 프로그래밍은 모든 동작을 한 번에 변경하는 대신, 값을 받아 다른 값을 반환하는 작은 계산으로 문제를 나누는 접근이다. 생성형 패턴에서는 입력 파라미터가 기하 데이터로, 기하 데이터가 색과 크기 정보로, 그 결과가 드로잉 호출로 이어지는 파이프라인을 만들 수 있다.

1. 파라미터와 시드에서 요소별 입력을 만든다.
2. 함수로 좌표, 크기, 색 같은 속성을 계산한다.
3. 계산 결과를 컬렉션으로 모으거나 필요한 순서로 처리한다.
4. 드로잉 계층에서 요소를 화면에 표현한다.

각 계산 단계가 분리되어 있으면 파라미터를 바꾸거나 함수를 교체했을 때 어떤 시각적 속성이 달라지는지 살펴보기 쉽다. 예를 들어 배치 규칙은 유지하고 색을 계산하는 함수만 바꾸거나, 동일한 점 데이터를 선과 원으로 각각 표현할 수 있다. 수학적 모델과 표현 방식을 느슨하게 연결하는 것은 다른 라이브러리로 옮길 때도 도움이 된다.

다만 Clojure는 부수 효과를 금지하는 순수 함수형 언어가 아니다. 그래픽을 그리고 입력을 읽으며 애니메이션 상태를 갱신하는 과정에는 외부 세계와 상호작용하는 코드가 필요하다. 실용적인 방식은 순수한 계산을 가능한 한 명확히 유지하고, 입력·상태 갱신·화면 출력처럼 부수 효과가 필요한 부분을 경계가 분명한 단계에 둔 뒤 연결하는 것이다. Quil의 스케치 생명주기에서 이 경계가 어떻게 구성되는지는 뒤의 절에서 살펴본다.

## REPL에서 빠르게 실험하기

Clojure는 REPL(Read-Eval-Print Loop)을 이용한 대화형 작업과 잘 어울린다. REPL은 표현식을 읽고 실행한 뒤 결과를 출력하는 반복 환경이다. 함수 하나를 정의하고, 특정 입력을 전달하고, 반환된 좌표나 컬렉션을 확인하면서 규칙을 점진적으로 다듬을 수 있다. 전체 스케치를 실행해 결과만 확인하는 것보다 계산의 중간 결과를 관찰하기 쉽다.

예를 들어 원 둘레 점의 개수나 반지름을 바꾸면서 `radial-point`가 만드는 좌표를 먼저 확인할 수 있다. 계산 결과가 예상과 다르면 화면 표현 문제와 수학 규칙 문제를 분리해 점검할 수 있다. 이러한 짧은 실험 주기는 라이브 코딩과도 연결되며, 22.8에서 작업 방식과 함께 다시 다룬다.

## Clojure와 Quil의 역할

Clojure는 언어이고 Quil은 그 언어로 Processing 스타일의 스케치와 드로잉을 사용할 수 있게 하는 라이브러리다. Clojure의 함수와 컬렉션은 패턴의 규칙과 데이터를 구성하고, Quil은 캔버스와 그래픽 출력의 통로를 제공한다. 따라서 Clojure를 사용한다고 해서 그래픽 API 자체를 새로 설계해야 하는 것은 아니다. 반대로 Quil이 수학적 패턴을 자동으로 만들어 주는 것도 아니다. 어떤 데이터를 생성하고 어떤 규칙으로 그릴지는 프로그램이 정한다.

이 구분을 기억하면 학습 순서도 자연스럽다. 먼저 Clojure의 함수와 값을 이용해 생성 규칙을 표현하고, 이어 Quil이 Processing과 어떤 관계인지 확인한다. 그다음 상태를 함수로 다루고, 스케치의 초기화·갱신·그리기 구조를 살펴본다. 이후 시퀀스 변환, 함수 조합, 랜덤과 노이즈, 라이브 코딩을 차례로 연결한다.

## 이 절의 핵심

Clojure는 함수와 불변 컬렉션을 조합해 수학적 규칙과 생성 데이터를 구성하는 데 적합한 Lisp 계열 언어다. 계산 함수를 드로잉 명령과 분리하면 결과를 검사하고 다른 표현 방식에 재사용하기 쉽다. Clojure가 규칙과 데이터를 표현하고 Quil이 스케치와 화면 출력을 연결한다는 역할 구분이 이 장의 출발점이다.
