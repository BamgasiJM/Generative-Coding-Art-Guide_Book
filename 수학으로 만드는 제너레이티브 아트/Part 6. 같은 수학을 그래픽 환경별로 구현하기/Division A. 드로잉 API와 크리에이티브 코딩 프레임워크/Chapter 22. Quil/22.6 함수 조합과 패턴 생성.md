# 22.6 함수 조합과 패턴 생성

22.5에서는 시퀀스의 각 요소를 변환하고 필요한 요소를 고르는 방법을 살펴봤다. 이번 절에서는 한 걸음 더 나아가, 좌표를 변환하는 함수들을 조합해 재사용 가능한 생성 규칙을 만드는 방법을 다룬다. 점을 이동하는 규칙, 회전하는 규칙, 크기를 바꾸는 규칙을 작은 함수로 나누면 이들을 조합해 복잡한 배치와 반복 패턴을 만들 수 있다.

함수 조합은 입력값에 적용할 여러 규칙을 하나의 함수로 묶는 것이다. 하나의 점이나 모티프를 먼저 로컬 좌표계(local coordinate system)에서 정의하고, 회전과 이동 같은 변환을 덧붙이면 같은 모양을 다른 위치와 방향에 배치할 수 있다.

## 좌표 변환을 함수로 만들기

2차원 점을 `[x y]` 벡터로 표현하고, 점을 이동·확대·회전하는 함수를 정의해보자. 아래 함수들은 점을 직접 바꾸지 않고 변환된 새 벡터를 반환한다.

```clojure
(defn translate [dx dy]
  (fn [[x y]]
    [(+ x dx) (+ y dy)]))

(defn scale [factor]
  (fn [[x y]]
    [(* x factor) (* y factor)]))

(defn rotate [angle]
  (let [c (Math/cos angle)
        s (Math/sin angle)]
    (fn [[x y]]
      [(- (* x c) (* y s))
       (+ (* x s) (* y c))])))
```

각 함수는 변환량이나 각도를 인자로 받아 점 하나를 입력받는 함수를 반환한다. 따라서 `(translate 10.0 20.0)`은 임의의 점을 오른쪽으로 10, 아래쪽으로 20만큼 옮기는 함수가 된다. 이런 식으로 다른 함수를 입력으로 받거나 결과로 반환하는 함수를 고차 함수(higher-order function)라고 한다. 변환의 설정값과 실제 적용을 분리했기 때문에 같은 이동이나 회전 규칙을 여러 점에 재사용할 수 있다.

`rotate`의 내부 계산은 2차원 회전 변환이다.

$$
\begin{bmatrix}
x' \\
y'
\end{bmatrix}
=
\begin{bmatrix}
\cos\theta & -\sin\theta \\
\sin\theta & \cos\theta
\end{bmatrix}
\begin{bmatrix}
x \\
y
\end{bmatrix}
$$

여기서 `angle`은 라디안 단위다. 원점에서 점을 회전시키므로, 특정 지점을 중심으로 회전하려면 회전 중심을 원점으로 옮긴 뒤 회전하고 다시 원래 위치로 이동해야 한다. 변환을 차례대로 조합하면 이 과정을 하나의 함수로 만들 수 있다.

## `comp`로 변환을 조합하기

Clojure의 `comp`는 여러 함수를 합쳐 새로운 함수를 반환한다. 중요한 규칙은 가장 오른쪽 함수가 먼저 실행된다는 점이다. 예를 들어 다음 조합은 점을 먼저 확대하고, 이어서 회전한 다음, 마지막으로 캔버스 중심으로 이동시킨다.

```clojure
(def transform-point
  (comp
   (translate 320.0 240.0)
   (rotate (/ Math/PI 4.0))
   (scale 1.5)))

(transform-point [40.0 0.0])
```

`(comp f g h)`는 `f(g(h(x)))`와 같은 순서로 적용된다. 따라서 위 예제에서는 `scale`이 먼저, `rotate`가 다음, `translate`가 마지막이다. 점 `[40 0]`은 원점 기준으로 1.5배 커지고 45도 회전한 뒤, 화면의 `[320 240]`을 기준 위치로 삼는다.

변환 순서는 일반적으로 바꿔 쓸 수 없다. 먼저 이동하고 회전하면 이동된 점이 원점 주위를 회전하지만, 먼저 회전하고 이동하면 회전한 뒤 정해진 위치로 옮겨진다. 확대와 이동의 순서도 마찬가지다. 변환을 설계할 때는 각 점이 어떤 좌표계에서 정의되어 있는지, 어떤 변환이 먼저 적용되어야 하는지 확인해야 한다.

데이터를 지금 당장 순서대로 변환하는 `->>`와도 구별할 필요가 있다. `->>`는 컬렉션 값을 단계별 함수에 전달해 실행하고, `comp`는 함수들을 묶어 나중에 입력을 받을 새 함수를 만든다. 이미 여러 점이 있고 그 점들을 즉시 변환하려면 시퀀스 변환을, 같은 변환 규칙을 여러 점이나 모티프에 반복 적용하려면 조합된 함수를 사용할 수 있다.

## 로컬 모티프를 원형으로 배치하기

로컬 모티프는 자기 자신의 중심을 `[0 0]`으로 하는 작은 도형 데이터다. 아래 예제의 모티프는 중심 주변에 놓인 여섯 점이다. 이 점들을 각각 이동시켜 작은 모티프 하나를 만들고, 그 모티프 전체를 회전·이동해 큰 원을 따라 반복 배치한다.

```clojure
(def local-motif
  [[-8.0 -5.0]
   [0.0 -10.0]
   [8.0 -5.0]
   [8.0 5.0]
   [0.0 10.0]
   [-8.0 5.0]])

(defn place-on-orbit [angle orbit-radius center-x center-y]
  (comp
   (translate center-x center-y)
   (rotate angle)
   (translate orbit-radius 0.0)))

(defn orbit-motifs [motif copy-count orbit-radius center-x center-y]
  (mapv
   (fn [index]
     (let [angle (* 2.0 Math/PI (/ index copy-count))
           transform (place-on-orbit
                      angle orbit-radius center-x center-y)]
       (mapv transform motif)))
   (range copy-count)))
```

각 복사본의 좌표에 적용되는 순서는 `comp`의 오른쪽부터 읽는다. 먼저 로컬 모티프를 `[orbit-radius 0]`만큼 옮겨 큰 원 위의 한 지점에 놓는다. 다음으로 원점 주위에서 `angle`만큼 회전시키고, 마지막으로 캔버스 중심으로 이동한다. 이 세 변환의 조합이 복사본 하나를 배치하는 함수가 된다. `orbit-motifs`는 각 복사본의 각도를 다르게 하여 그 함수를 만들고, 같은 로컬 모티프의 모든 점에 적용한다.

여기서는 `mapv`가 복사본마다 점 좌표를 계산해 벡터로 저장한다. 모티프의 점 수나 복사본 수, 궤도 반지름을 바꾸면 같은 함수 구조로 다른 밀도와 크기의 패턴을 만들 수 있다. 로컬 모티프 자체를 바꾸면 배치 규칙은 유지하면서 반복되는 작은 형태만 교체할 수 있다.

## Quil로 그리기

다음 스케치는 변환 함수들을 실제 Quil 스케치에 연결한다. 로컬 모티프를 24회 복제하고, 각 모티프를 캔버스 중심을 기준으로 원형 배치한다.

```clojure
(ns generative-art.function-composition
  (:require [quil.core :as q]
            [quil.middleware :as m]))

(defn translate [dx dy]
  (fn [[x y]]
    [(+ x dx) (+ y dy)]))

(defn rotate [angle]
  (let [c (Math/cos angle)
        s (Math/sin angle)]
    (fn [[x y]]
      [(- (* x c) (* y s))
       (+ (* x s) (* y c))])))

(def local-motif
  [[-8.0 -5.0] [0.0 -10.0] [8.0 -5.0]
   [8.0 5.0] [0.0 10.0] [-8.0 5.0]])

(defn place-on-orbit [angle orbit-radius center-x center-y]
  (comp
   (translate center-x center-y)
   (rotate angle)
   (translate orbit-radius 0.0)))

(defn orbit-motifs [motif copy-count orbit-radius center-x center-y]
  (mapv
   (fn [index]
     (let [angle (* 2.0 Math/PI (/ index copy-count))
           transform (place-on-orbit
                      angle orbit-radius center-x center-y)]
       (mapv transform motif)))
   (range copy-count)))

(defn setup []
  (let [center-x (/ (q/width) 2.0)
        center-y (/ (q/height) 2.0)]
    {:motifs (orbit-motifs local-motif 24 110.0 center-x center-y)}))

(defn update-state [state]
  state)

(defn draw-state [{:keys [motifs]}]
  (q/background 248)
  (q/no-stroke)
  (doseq [[motif-index points] (map-indexed vector motifs)
          [x y] points]
    (if (even? motif-index)
      (q/fill 210 85 70)
      (q/fill 40 125 175))
    (q/ellipse x y 7.0 7.0)))

(q/defsketch function-composition
  :title "Function composition"
  :size [640 480]
  :setup setup
  :update update-state
  :draw draw-state
  :middleware [m/fun-mode])
```

`setup`은 한 번만 필요한 좌표 계산을 수행하고 결과를 상태에 저장한다. `update-state`는 정지 이미지이므로 상태를 그대로 반환하며, `draw-state`는 각 점을 Quil의 원으로 표현한다. 색은 바깥쪽 모티프의 인덱스에 따라 번갈아 지정했다. 생성 규칙은 Quil의 그리기 호출과 분리되어 있으므로, 같은 좌표를 선이나 사각형으로 그리거나 다른 드로잉 환경의 API에 전달해도 좌표 변환 함수는 유지할 수 있다.

## 조합 가능한 규칙의 장점

변환 함수가 작고 명확하면 패턴의 어느 부분을 바꾸는지 추적하기 쉽다. 회전 함수를 다른 각도 규칙으로 바꾸거나, 이동 대신 다른 배치 함수를 쓰거나, 로컬 모티프의 점을 바꾸는 식으로 한 요소씩 실험할 수 있다. 동일한 로컬 형태를 여러 좌표계와 크기에 적용하는 것도 간단해진다.

함수 조합은 예측 가능한 입력·출력 관계를 전제로 할 때 특히 유용하다. 위 좌표 함수들은 같은 점과 같은 파라미터에서 항상 같은 결과를 내며 외부 상태를 바꾸지 않는다. 그래서 특정 좌표를 따로 시험하거나 여러 변환 단계의 결과를 비교하기 쉽다. 반대로 Quil의 `q/ellipse` 같은 그리기 명령은 화면에 영향을 주는 부수 효과이므로, 좌표 변환 함수 안에 넣기보다 최종 좌표가 만들어진 뒤 렌더링 단계에서 호출하는 편이 좋다.

## 이 절의 핵심

함수 조합은 여러 변환 규칙을 하나의 재사용 가능한 함수로 묶는 방법이다. Clojure의 `comp`는 오른쪽 함수부터 적용하므로, 확대·회전·이동의 순서를 의도에 맞게 구성해야 한다. 로컬 좌표로 만든 모티프에 조합된 변환을 적용하면 같은 작은 형태를 반복·회전·배치할 수 있고, 계산 규칙을 Quil 렌더링과 분리해 쉽게 변형하고 재사용할 수 있다.
