# 22.4 setup, update, draw의 구조

Quil 스케치는 프로그램이 시작될 때 한 번 실행하는 준비 단계와, 프레임마다 반복하는 갱신·그리기 단계로 구성된다. `setup`은 스케치의 초기 조건을 만들고, `update`는 현재 상태를 다음 상태로 바꾸며, `draw`는 전달받은 상태를 화면에 표현한다. Quil은 이 함수들을 연결해 반복 실행하므로 직접 무한 루프를 작성하지 않아도 된다.

앞 절에서 살펴본 함수형 상태 흐름을 Quil의 실제 스케치에 적용하면 다음과 같다.

```text
setup()          -> 초기 상태 S0
update(S0)       -> 다음 상태 S1
draw(S1)         -> 화면에 S1을 표현
update(S1)       -> 다음 상태 S2
draw(S2)         -> 화면에 S2를 표현
                 ... 반복
```

이 구조의 핵심은 `update`가 시뮬레이션을 진행하고 `draw`가 그 결과를 보여준다는 역할 분담이다. 상태를 계산하는 규칙과 화면에 그리는 명령을 섞지 않으면, 움직임을 검사하거나 모양을 바꾸기가 쉬워진다.

## `setup`: 시작 상태 준비하기

`setup`은 스케치가 시작할 때 한 번 호출된다. 이 함수는 애니메이션의 첫 프레임에 필요한 상태를 반환한다. 위치, 속도, 각도, 난수 시드, 사용자 조절 파라미터처럼 실행 중 참조할 값을 맵으로 묶을 수 있다. 스케치에서 사용할 프레임률을 설정하거나 리소스를 준비하는 일도 초기화 시점에 둘 수 있다.

`setup`의 반환값은 뒤이어 실행되는 `update`와 `draw`에 전달될 상태다. 따라서 상태 기반 스케치에서는 필요한 키를 빠짐없이 초기화하고, 이후 함수가 기대하는 자료형과 구조를 일관되게 유지해야 한다. `setup`이 `nil`을 반환하거나 상태의 구조가 프레임마다 달라지면 다음 단계의 처리가 어려워진다.

## `update`: 다음 상태 계산하기

`update`는 현재 상태를 인자로 받아 다음 상태를 반환한다. Quil의 함수형 모드에서는 이전 상태를 직접 수정하지 않고, 새 상태 값을 반환하는 방식으로 프레임마다 시뮬레이션을 진행한다. 위치를 속도만큼 이동시키거나, 위상을 증가시키거나, 수명을 줄이는 계산이 여기에 들어간다.

갱신 함수가 프레임마다 같은 양만큼 각도를 더하면 실제 움직임은 실행 프레임률에 영향을 받는다. 프레임이 빨라지면 초당 각도 변화도 커진다. 초당 변화량을 일정하게 하려면 프레임 사이에 실제로 흐른 시간 `dt`를 계산해 변화량에 곱한다.

아래 예제의 `advance-state`는 상태와 시간 간격만 받아 새 위상을 계산하는 순수 함수다. `update-state`는 Quil의 시계를 읽어 `dt`를 구한 뒤 순수 계산을 호출하는 연결부 역할을 한다.

```clojure
(ns generative-art.lifecycle
  (:require [quil.core :as q]
            [quil.middleware :as m]))

(defn setup []
  (q/frame-rate 60)
  {:phase 0.0
   :angular-speed 1.2
   :radius 90.0
   :last-ms (q/millis)})

(defn advance-state [state dt]
  (update state :phase
          + (* dt (:angular-speed state))))

(defn update-state [state]
  (let [now-ms (q/millis)
        dt (/ (- now-ms (:last-ms state)) 1000.0)
        dt (min dt 0.05)]
    (-> state
        (advance-state dt)
        (assoc :last-ms now-ms))))
```

`q/millis`는 스케치가 시작된 뒤 경과한 시간을 밀리초로 돌려준다. 두 프레임의 시각 차이를 1000으로 나누면 초 단위 `dt`가 된다. `:angular-speed`는 초당 라디안 단위로 두었으므로, `angular-speed * dt`가 이번 갱신에서 더할 각도다. `q/frame-rate 60`은 목표 프레임률을 설정하지만 매 순간 정확히 초당 60회 호출된다는 보장은 아니다. `dt`를 사용하면 실제 프레임 간격이 달라져도 시간에 따른 변화량을 비슷하게 유지할 수 있다.

예제에서는 `dt`를 최대 `0.05`초로 제한한다. 창을 다른 작업으로 가리거나 시스템이 잠시 멈춘 뒤 큰 시간 간격이 한 번에 들어오면 물체가 순간이동하듯 움직일 수 있기 때문이다. 이 제한은 시각적으로 큰 점프를 줄이는 간단한 선택이다. 다만 제한된 시간만큼만 시뮬레이션하므로 긴 멈춤 동안의 경과 시간을 모두 따라잡지는 않는다. 정확한 물리 시뮬레이션이나 누락된 시간을 보정해야 하는 작업은 고정 시간 간격으로 여러 번 갱신하는 구조를 고려할 수 있다.

## `draw`: 상태를 화면으로 표현하기

`draw`는 현재 상태를 읽고 Quil의 드로잉 함수를 호출한다. 아래에서는 위상과 반지름으로 원의 위치를 계산해 캔버스 중심 주위를 움직이게 한다.

```clojure
(defn draw-state [{:keys [phase radius]}]
  (let [cx (/ (q/width) 2.0)
        cy (/ (q/height) 2.0)
        x (+ cx (* radius (Math/cos phase)))
        y (+ cy (* radius (Math/sin phase)))]
    (q/background 248)
    (q/no-stroke)
    (q/fill 45 120 185)
    (q/ellipse x y 28 28)))
```

`Math/cos`와 `Math/sin`은 원 위의 좌표를 계산하고, `q/ellipse`가 그 좌표에 원을 그린다. `q/background`는 매 프레임 캔버스를 다시 채워 이전 프레임의 흔적을 지운다. 이 호출을 생략하거나 투명한 색으로 덮으면 이전 그림이 남아 궤적이나 잔상이 만들어질 수 있다.

`draw-state`는 상태를 받아 새 상태를 반환하지 않는다. 화면 출력은 렌더러에 명령을 보내는 부수 효과이지만, 그 명령을 수행하는 동안 시뮬레이션 상태는 바꾸지 않는 것이 좋다. 그러면 동일한 상태를 다시 그릴 수 있고, 상태 계산에서 생긴 문제와 렌더링 문제를 구별하기 쉬워진다.

## 콜백을 스케치에 연결하기

함수를 정의하는 것만으로는 스케치가 실행되지 않는다. `q/defsketch`에 캔버스 설정과 각 콜백을 전달하고, `m/fun-mode` 미들웨어를 지정하면 Quil이 상태를 함수 인자로 전달하는 모드로 스케치를 구성한다.

```clojure
(q/defsketch lifecycle-sketch
  :title "Quil lifecycle"
  :size [640 480]
  :setup setup
  :update update-state
  :draw draw-state
  :middleware [m/fun-mode])
```

여기서 `:setup`, `:update`, `:draw`에는 함수를 호출한 결과가 아니라 함수 자체를 전달한다. Quil이 실행 시점에 알맞은 상태를 인자로 넣어 호출하기 때문이다. `m/fun-mode`가 상태의 생성·전달·반환 규약을 연결한다. 이 설정을 빠뜨리면 콜백이 기대하는 상태 전달 방식과 스케치 모드가 일치하지 않을 수 있다.

전체 예제에서 `setup`은 초기 상태를 만들고, `update-state`는 시계를 읽어 순수 함수 `advance-state`로 다음 위상을 계산하며, `draw-state`는 그 위상을 원의 화면 좌표로 바꾼다. `q/defsketch`는 이 함수들을 한 스케치의 프레임 흐름에 연결한다. 실제 프로젝트에서는 위 코드 블록들을 같은 네임스페이스에 두면 하나의 스케치로 구성할 수 있다.

## 입력과 렌더링의 경계

키 입력이나 마우스 입력도 상태 변화의 원인이 될 수 있다. 입력 콜백에서 상태를 갱신하거나 입력 값을 상태 전이 함수에 전달하면, 입력 처리와 움직임 계산을 분리할 수 있다. 예를 들어 키보드는 속도나 방향을 바꾸고, `update`는 바뀐 값을 이용해 위치를 진행시키며, `draw`는 그 위치를 그리는 식이다. Quil의 입력 콜백과 인터랙션은 다음 절에서 다룬다.

정지 화면이나 프레임 간 흔적을 남기는 작품에서는 `draw`가 매번 배경을 지우는지 여부도 설계의 일부다. 완전히 다시 그리는 방식은 현재 상태만으로 화면을 재구성하기 쉽고, 캔버스에 누적해서 그리는 방식은 과거 프레임이 시각적 결과에 영향을 준다. 누적형 표현을 택했다면 캔버스 자체가 상태의 일부처럼 동작한다는 점을 염두에 두어야 한다.

## 이 절의 핵심

Quil의 `setup`, `update`, `draw`는 각각 초기 상태 생성, 상태 전이, 화면 표현을 맡는다. 함수형 모드에서는 `update`가 현재 상태를 받아 다음 상태를 반환하고 `draw`가 그 상태를 읽어 그린다. `dt`를 이용하면 프레임률이 달라져도 시간에 따른 움직임을 조절할 수 있으며, `q/defsketch`와 `m/fun-mode`가 이 흐름을 스케치로 연결한다.
