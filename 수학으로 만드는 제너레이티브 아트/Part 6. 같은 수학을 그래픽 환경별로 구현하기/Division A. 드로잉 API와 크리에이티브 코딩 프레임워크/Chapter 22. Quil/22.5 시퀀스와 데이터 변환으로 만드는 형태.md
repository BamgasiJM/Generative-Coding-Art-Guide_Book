# 22.5 시퀀스와 데이터 변환으로 만드는 형태

제너레이티브 아트에서는 같은 규칙을 여러 점이나 도형에 적용하는 일이 많다. 점의 번호를 차례로 만들고, 번호마다 좌표와 크기를 계산한 뒤, 조건에 맞는 요소만 골라 화면에 그리는 식이다. Clojure에서는 이 과정을 시퀀스(sequence)와 데이터 변환 함수로 표현할 수 있다.

중요한 관점은 드로잉 명령을 반복하는 것보다 먼저 그릴 요소를 데이터로 만드는 것이다. 점 하나를 `{:x 120.0 :y 80.0 :size 10.0}` 같은 맵으로 표현하면 위치·크기·색을 계산하고 검사하기 쉽다. 데이터 생성 규칙과 Quil의 화면 출력이 분리되므로 같은 점 데이터를 원, 사각형, 선 등 다른 도형으로 표현할 수도 있다.

## 번호에서 좌표로

`range`는 순서가 있는 숫자 범위를 만든다. 원 둘레에 48개 점을 배치하려면 우선 `0`부터 `47`까지의 인덱스를 준비하고, 각 인덱스를 각도와 좌표로 변환한다.

```clojure
(defn ring-points [count radius center-x center-y]
  (mapv
   (fn [index]
     (let [angle (* 2.0 Math/PI (/ index count))]
       {:index index
        :x (+ center-x (* radius (Math/cos angle)))
        :y (+ center-y (* radius (Math/sin angle)))}))
   (range count)))
```

원의 한 바퀴는 `2π` 라디안이므로 `index / count`를 곱해 각 요소의 각도를 얻는다. 코사인과 사인에 반지름을 곱하면 중심에서 해당 각도 방향으로 떨어진 거리가 되고, 중심 좌표를 더하면 캔버스 좌표가 된다. 인덱스도 점 데이터에 함께 넣어 두면 그 번호에 따라 크기나 색을 달리할 때 사용할 수 있다.

`mapv`는 `range`의 각 값을 함수에 전달하고 결과를 벡터로 모은다. 여기서 함수는 인덱스 하나를 점의 속성을 담은 맵 하나로 바꾼다. 즉, 숫자의 시퀀스가 화면에 그릴 수 있는 점 데이터의 벡터로 변환된다. 중심과 반지름을 함수의 인자로 받았으므로, 같은 규칙으로 크기나 위치가 다른 원형 배열도 생성할 수 있다.

## 변환하고 선택하기

이미 만든 점 데이터는 `map`으로 꾸미고 `filter`로 선택할 수 있다. 예를 들어 인덱스가 짝수인 점을 크게 하고, 일곱 번째마다 하나씩 제외하면 크기에 리듬이 있고 일부가 비어 있는 고리를 만들 수 있다.

```clojure
(defn style-point [point]
  (assoc point :diameter
         (if (even? (:index point)) 12.0 7.0)))

(defn visible-point? [point]
  (not= 0 (mod (:index point) 7)))

(def styled-points
  (->> (ring-points 48 150.0 320.0 240.0)
       (map style-point)
       (filter visible-point?)
       vec))
```

`map`은 각 요소를 다른 값으로 바꾼다. 여기서는 `assoc`가 점 맵에 `:diameter` 키를 추가하므로 기존 좌표와 인덱스는 유지하면서 크기 정보가 더해진다. `filter`는 조건 함수가 참을 반환하는 요소만 남긴다. `mod`는 나머지를 구하므로 인덱스를 7로 나눈 나머지가 0인 점을 제외하는 조건을 만들 수 있다.

`->>`는 컬렉션을 다음 함수의 마지막 인자로 차례로 전달한다. 위 코드는 개념적으로 다음 변환을 왼쪽에서 오른쪽 순서로 읽는다.

```text
인덱스별 점 생성 -> 크기 추가 -> 일부 점 제외 -> 벡터로 확정
```

`map`과 `filter`는 보통 결과를 즉시 전부 계산하지 않고, 요청될 때 요소를 계산하는 지연 시퀀스(lazy sequence)를 반환한다. 여러 변환을 이어 붙이면 중간 컬렉션을 매번 만들지 않고 필요한 요소를 다음 단계로 전달할 수 있다. 하지만 렌더링이나 성능을 고려해 결과를 재사용하려면 `vec`나 `mapv`로 실제 벡터를 만들어 둘 수 있다. 위 예에서는 `setup`에서 패턴을 한 번 생성하고 프레임마다 다시 계산하지 않도록 마지막에 `vec`로 확정한다.

## 격자와 다차원 반복

원형 배열 외에도 격자는 행과 열의 조합으로 만들 수 있다. `for`는 여러 바인딩을 중첩해 조합을 생성하므로, 각 행과 각 열에 해당하는 모든 셀을 순회하기 편하다.

```clojure
(defn grid-points [columns rows spacing origin-x origin-y]
  (for [row (range rows)
        column (range columns)]
    {:column column
     :row row
     :x (+ origin-x (* column spacing))
     :y (+ origin-y (* row spacing))}))
```

`row`와 `column`의 모든 조합마다 하나의 맵이 만들어진다. 좌표는 열 번호와 행 번호에 간격을 곱해 계산한다. `for` 역시 기본적으로 지연된 시퀀스를 반환하므로, 필요하면 `vec`로 저장할 수 있고 바로 `doseq`에 전달해 그릴 수도 있다. 행과 열을 좌표뿐 아니라 색상 단계, 크기, 모양 선택에 함께 사용하면 규칙적인 격자에 변화를 줄 수 있다.

## 시퀀스를 화면에 그리기

계산된 데이터는 Quil 드로잉 API에 전달한다. 다음 스케치는 앞의 원형 점 생성과 변환을 연결해, 화면에 점 크기가 교차하고 일부가 빠진 고리를 그린다.

```clojure
(ns generative-art.sequence-pattern
  (:require [quil.core :as q]
            [quil.middleware :as m]))

(defn ring-points [count radius center-x center-y]
  (mapv
   (fn [index]
     (let [angle (* 2.0 Math/PI (/ index count))]
       {:index index
        :x (+ center-x (* radius (Math/cos angle)))
        :y (+ center-y (* radius (Math/sin angle)))}))
   (range count)))

(defn style-point [point]
  (assoc point :diameter
         (if (even? (:index point)) 12.0 7.0)))

(defn visible-point? [point]
  (not= 0 (mod (:index point) 7)))

(defn setup []
  (let [center-x (/ (q/width) 2.0)
        center-y (/ (q/height) 2.0)]
    {:points
     (->> (ring-points 48 150.0 center-x center-y)
          (map style-point)
          (filter visible-point?)
          vec)}))

(defn update-state [state]
  state)

(defn draw-state [{:keys [points]}]
  (q/background 248)
  (q/no-stroke)
  (doseq [{:keys [index x y diameter]} points]
    (if (even? index)
      (q/fill 210 85 70)
      (q/fill 40 125 175))
    (q/ellipse x y diameter diameter)))

(q/defsketch sequence-pattern
  :title "Sequence pattern"
  :size [640 480]
  :setup setup
  :update update-state
  :draw draw-state
  :middleware [m/fun-mode])
```

`setup`은 캔버스 크기에서 중심을 구해 점 데이터를 한 번 만든 뒤 상태 맵에 넣는다. `update-state`는 이 정지 패턴에서 상태를 바꾸지 않으므로 받은 상태를 그대로 반환한다. `draw-state`는 각 점의 맵을 읽어 색과 크기를 설정하고 원을 그린다. 데이터 생성과 렌더링의 경계가 분명해서, 좌표 생성 규칙을 유지한 채 그리기 부분만 바꾸거나 다른 좌표 데이터를 같은 렌더러에 전달할 수 있다.

여기서 `doseq`는 컬렉션의 요소마다 드로잉처럼 부수 효과를 수행할 때 쓰인다. `map`으로 `q/ellipse` 호출 결과를 만들면 지연 시퀀스가 실제로 소비되기 전까지 그리기가 일어나지 않을 수 있고, 결과값을 만들려는 의도와 화면에 명령을 보내려는 의도도 섞인다. 계산과 화면 출력을 구분하고, 출력 반복에는 `doseq`를 쓰는 편이 명확하다.

## 집계와 데이터의 크기

모든 시퀀스 변환이 요소별 변환이나 선택인 것은 아니다. `reduce`는 컬렉션의 여러 값을 하나의 결과로 모은다. 예를 들어 각 점의 지름을 모두 더해 총합을 구할 수 있다.

```clojure
(reduce + 0 (map :diameter points))
```

`map :diameter`는 각 점 맵에서 지름을 꺼내고, `reduce`는 그 값들을 `+`로 누적한다. 시작값 `0`은 컬렉션이 비어 있을 때의 결과이자 누적 계산의 초기값이다. 총합, 평균을 위한 합계와 개수, 최소·최대값처럼 전체 데이터에 대한 요약이 필요할 때 유용하다. 화면에 그릴 요소 하나하나를 바꾸는 작업에는 `map`, 일부만 남기는 작업에는 `filter`, 여러 요소를 하나의 요약값으로 모으는 작업에는 `reduce`를 우선 고려하면 된다.

시퀀스는 많은 요소를 간결하게 표현하지만, 요소 수가 커지면 계산량과 메모리 사용량도 함께 커진다. 예를 들어 가로·세로 각각 500칸인 격자는 25만 개의 셀 데이터를 만든다. 실제로 필요한 정보만 저장하거나, 매 프레임 반복되는 계산은 초기화 단계에서 미리 처리하거나, 화면에 보이는 영역만 생성하는 방법을 고려한다. 컬렉션을 변환하는 표현이 간결하더라도 그 비용은 데이터의 개수와 변환 횟수에 따라 달라진다.

## 이 절의 핵심

Clojure의 시퀀스 연산을 이용하면 인덱스에서 좌표를 만들고, 각 요소에 시각 속성을 더하고, 조건에 따라 일부만 선택하는 데이터 파이프라인을 구성할 수 있다. `map`은 변환, `filter`는 선택, `reduce`는 집계에 쓰이며, `mapv`와 `vec`는 결과를 벡터로 확정한다. 이렇게 만들어진 데이터는 `doseq`와 Quil 드로잉 API로 표현할 수 있고, 규칙 계산과 렌더링을 분리할수록 패턴을 수정하고 재사용하기 쉬워진다.
