# 21.5 입력 처리와 인터랙션

실시간 그래픽은 화면을 보여 주는 데서 끝나지 않는다. 키보드와 마우스 같은 입력으로 파라미터를 바꾸면 사용자는 패턴을 탐색하고 시뮬레이션에 영향을 줄 수 있다. raylib의 입력은 프레임 루프 안에서 상태를 확인하는 방식으로 다룬다. 입력을 읽고, 프로그램의 상태를 갱신하고, 그 결과를 그리는 흐름을 만들면 조작과 화면이 자연스럽게 이어진다.

## 한 번 눌림과 누르고 있는 상태

입력을 처리할 때 가장 먼저 구분할 것은 버튼이 눌린 순간과 계속 눌려 있는 상태다. raylib의 키보드와 마우스 API에는 이 두 경우를 구분하는 함수가 있다.

| 입력 상태 | 키보드 함수 | 마우스 함수 | 일반적인 용도 |
| --- | --- | --- | --- |
| 눌린 동안 | `IsKeyDown(key)` | `IsMouseButtonDown(button)` | 이동, 연속 조작, 누르는 동안 힘 적용 |
| 이번 프레임에 눌림 | `IsKeyPressed(key)` | `IsMouseButtonPressed(button)` | 선택, 토글, 한 번 생성하기 |
| 이번 프레임에 놓임 | `IsKeyReleased(key)` | `IsMouseButtonReleased(button)` | 드래그 종료, 동작 확정 |

`IsKeyDown()`은 키를 누르고 있는 매 프레임 참이다. 이동처럼 누르는 동안 계속 적용해야 하는 동작에 적합하다. 반면 `IsKeyPressed()`는 키가 눌린 순간에 해당하는 프레임에만 참이므로, 설정 화면 열기나 패턴 다시 만들기처럼 한 번만 일어나야 하는 동작에 쓴다. 눌림 상태를 매 프레임 확인하면서 토글 값을 바꾸면 키를 누르고 있는 동안 값이 계속 뒤집힐 수 있다. 이때는 `Pressed` 계열 함수를 사용한다.

raylib은 보통 입력 상태를 매 프레임 확인하는 폴링(polling) 방식으로 제공한다. 별도 이벤트 콜백을 먼저 등록하기보다, 루프에서 `IsKeyDown(KEY_SPACE)`처럼 필요한 상태를 묻는다. 한 프레임 동안 눌린 키를 순서대로 받아야 할 때는 `GetKeyPressed()`를 사용해 반환값이 `0`이 될 때까지 확인할 수 있다. 일반적인 단축키와 연속 이동에는 `IsKeyDown()`과 `IsKeyPressed()`가 더 간단하다.

## 키보드로 상태 움직이기

연속 이동은 눌린 키로 방향을 만들고, `GetFrameTime()`을 곱해 위치를 갱신한다. 이렇게 하면 키를 누르고 있는 시간이 같을 때 실행 프레임률에 상관없이 비슷한 거리를 이동한다. 다음 예제는 방향키로 원을 움직이고, 마우스로 원을 선택하거나 선택을 해제한다.

```c
#include "raylib.h"

int main(void)
{
    const int screenWidth = 640;
    const int screenHeight = 400;
    const float radius = 24.0f;
    const float speed = 220.0f;

    InitWindow(screenWidth, screenHeight, "input example");
    SetTargetFPS(60);

    Vector2 startPosition = { screenWidth * 0.5f, screenHeight * 0.5f };
    Vector2 position = startPosition;
    int selected = 0;

    while (!WindowShouldClose())
    {
        const float dt = GetFrameTime();

        if (IsKeyDown(KEY_LEFT)) position.x -= speed * dt;
        if (IsKeyDown(KEY_RIGHT)) position.x += speed * dt;
        if (IsKeyDown(KEY_UP)) position.y -= speed * dt;
        if (IsKeyDown(KEY_DOWN)) position.y += speed * dt;

        if (IsKeyPressed(KEY_R))
        {
            position = startPosition;
            selected = 0;
        }

        const Vector2 mouse = GetMousePosition();
        const int isHovered = CheckCollisionPointCircle(mouse, position, radius);
        if (isHovered && IsMouseButtonPressed(MOUSE_BUTTON_LEFT))
        {
            selected = !selected;
        }

        BeginDrawing();
        ClearBackground(RAYWHITE);
        Color circleColor = BLUE;
        if (selected) circleColor = ORANGE;
        DrawCircleV(position, radius, circleColor);
        DrawText("Arrow keys: move   R: reset   Click: select", 20, 20, 18, DARKGRAY);
        EndDrawing();
    }

    CloseWindow();
    return 0;
}
```

방향키는 `IsKeyDown()`으로 검사하므로 누르는 동안 매 프레임 이동한다. 이동 속도는 초당 픽셀 수로 정하고 `speed * dt`만큼 좌표를 바꾼다. `R` 키는 `IsKeyPressed()`로 검사해 누른 순간 한 번만 초기화한다. 마우스 위치가 원 안에 있는지는 `CheckCollisionPointCircle()`로 판정하고, 그 상태에서 왼쪽 버튼이 눌린 순간 선택 상태를 뒤집는다.

위 예제는 입력을 곧바로 그리기 명령으로 바꾸지 않는다. 먼저 위치와 선택 상태를 바꾸고, 그 상태를 마지막 그리기 구간에서 화면에 나타낸다. 이 구조에서는 원을 텍스처로 바꾸거나 선택 색을 바꾸더라도 입력과 시뮬레이션의 규칙을 그대로 둘 수 있다.

방향키를 대각선으로 동시에 누르면 x축과 y축의 이동이 함께 적용되어 수평·수직 이동보다 빠르게 느껴질 수 있다. 속도를 방향에 관계없이 일정하게 맞추려면 입력으로 만든 방향 벡터의 길이가 1을 넘을 때 정규화한다. 여러 입력을 벡터로 모아 처리하면 키보드와 게임패드가 같은 이동 규칙을 공유하기도 쉽다.

## 마우스 위치와 클릭 판정

`GetMousePosition()`은 커서의 현재 위치를 `Vector2`로 반환한다. 기본 화면 좌표계에서는 왼쪽 위가 원점이고 y축이 아래쪽으로 증가한다. `GetMouseDelta()`는 프레임 사이 마우스 이동량을 제공하며, `GetMouseWheelMove()`는 휠의 세로 이동량을 제공한다. 마우스 위치는 캔버스 안에서 직접 조작 대상을 가리키고, 휠은 확대 비율이나 브러시 크기처럼 연속 파라미터를 조정하는 데 쓸 수 있다.

마우스가 도형 위에 있는지 판정할 때는 도형의 형태에 맞는 충돌 검사 함수를 쓴다. `CheckCollisionPointRec(point, rectangle)`은 점이 사각형 안에 있는지, `CheckCollisionPointCircle(point, center, radius)`는 점이 원 안에 있는지 확인한다. 클릭 입력과 결합하면 버튼, 노드, 입자, 조절점 등을 선택할 수 있다. 직접 거리 공식을 구현한다면 원의 중심과 커서 사이 거리 `d`를 구해 `d <= radius`인지 검사하는 것과 같은 원리다.

누르고 있는 동안 움직이는 드래그는 보통 다음 상태를 별도로 관리한다. 버튼이 눌린 순간 대상이 선택되면 `dragging`을 켜고, 버튼을 누르고 있는 동안 위치를 갱신하며, 버튼이 놓이면 `dragging`을 끈다. 대상이 선택된 지점과 중심 사이의 차이를 오프셋으로 저장하면, 클릭한 지점이 대상의 중심으로 갑자기 이동하는 현상 없이 자연스럽게 끌 수 있다.

## 카메라가 있을 때 좌표 변환

`GetMousePosition()`이 반환하는 좌표는 화면 좌표다. `Camera2D`가 적용된 월드 공간의 도형을 클릭하거나 드래그하려면 커서 좌표를 같은 월드 좌표계로 변환해야 한다.

```c
Vector2 mouseScreen = GetMousePosition();
Vector2 mouseWorld = GetScreenToWorld2D(mouseScreen, camera);

if (CheckCollisionPointCircle(mouseWorld, objectPosition, objectRadius))
{
    // 월드 좌표에서 개체가 선택되었다.
}
```

카메라의 이동이나 확대가 적용된 화면에서 `mouseScreen`을 곧바로 월드 개체의 위치와 비교하면 선택 위치가 어긋난다. `GetScreenToWorld2D()`는 화면 위치를 지정한 카메라의 월드 좌표로 바꾸고, 반대 방향은 `GetWorldToScreen2D()`로 변환한다. 반대로 카메라 밖에서 화면에 고정한 사용자 인터페이스를 처리할 때는 화면 좌표를 그대로 사용한다. 입력 좌표와 대상의 좌표가 같은 공간에 있는지 확인하는 습관이 중요하다.

## 텍스트 입력과 다른 장치

단축키의 `IsKeyPressed()`와 사용자가 입력한 문자는 서로 다른 종류의 입력이다. 키 상태 함수는 물리적 키 조작을 감지하므로 키보드 배열이나 키보드 레이아웃에 따라 같은 키가 다른 문자로 입력될 수 있다. 텍스트 필드처럼 실제 문자를 받아야 할 때는 `GetCharPressed()`를 사용한다. 이 함수는 입력 대기열에서 문자 코드 포인트를 하나씩 반환하고, 더 읽을 값이 없으면 `0`을 반환하므로 한 프레임 안에서 반복해 비워야 한다.

```c
int codepoint = GetCharPressed();
while (codepoint > 0)
{
    // codepoint를 텍스트 입력으로 처리한다.
    codepoint = GetCharPressed();
}
```

반환값은 C의 `char` 하나로 항상 표현할 수 있는 ASCII 문자에 한정되지 않는다. 한글 등 유니코드 텍스트를 저장하거나 편집하려면 코드 포인트와 UTF-8 같은 문자열 인코딩을 고려해야 한다. 게임 조작에는 키 상태 함수를, 사용자 이름이나 문장 입력에는 문자 입력 함수를 사용한다.

마우스와 키보드 외에도 raylib은 게임패드와 터치 입력을 제공한다. 게임패드는 `IsGamepadAvailable()`, `IsGamepadButtonDown()` 같은 함수로 연결 여부와 버튼 상태를 확인하고, `GetGamepadAxisMovement()`로 아날로그 축의 값을 읽을 수 있다. 터치 환경에서는 `GetTouchPointCount()`와 `GetTouchPosition()`으로 활성 터치 수와 각 위치를 확인한다. 장치가 다르더라도 입력을 방향 벡터, 선택 동작, 파라미터 변경처럼 공통된 의미로 변환하면 하나의 시뮬레이션 규칙에 연결할 수 있다.

## 입력을 작품의 조절기로 사용하기

인터랙션은 입력을 감지하는 데서 끝나지 않는다. 어떤 입력이 작품의 어떤 파라미터를 바꾸는지 설계해야 한다. 마우스 위치를 중심점으로 삼으면 커서를 따라 움직이는 장면이 되고, 클릭할 때 입자를 생성하면 사용자의 동작이 구성 요소가 된다. 키를 눌러 노이즈 세기나 반복 횟수를 바꾸면 같은 알고리즘에서 다양한 결과를 탐색할 수 있다. 휠로 확대율을 바꾸거나 게임패드 축으로 회전 속도를 조절하는 식으로 연속값도 연결할 수 있다.

입력을 계산과 그리기 사이의 상태 변화로 다루면 인터랙션을 테스트하기 쉽다. 먼저 입력을 읽어 원하는 동작을 정하고, 그 동작으로 파라미터나 객체 상태를 갱신한 다음, 그 결과를 그린다. 입력 장치를 바꾸더라도 동작을 표현하는 상태와 규칙을 유지할 수 있고, 작품의 반응도 일관되게 만들 수 있다.

## 이 절의 핵심

raylib의 입력은 프레임 루프에서 상태를 확인하는 폴링 방식으로 처리한다. `Down`은 누르는 동안의 연속 동작에, `Pressed`와 `Released`는 한 번 발생하는 동작에 적합하다. 마우스 좌표는 기본적으로 화면 공간에 있으므로 카메라가 적용된 장면과 비교하기 전에 `GetScreenToWorld2D()`로 변환한다. 입력은 파라미터와 객체 상태를 바꾸고, 그 상태를 그리는 순서로 구성하면 키보드·마우스·게임패드 등 다양한 장치를 같은 규칙에 연결할 수 있다.
