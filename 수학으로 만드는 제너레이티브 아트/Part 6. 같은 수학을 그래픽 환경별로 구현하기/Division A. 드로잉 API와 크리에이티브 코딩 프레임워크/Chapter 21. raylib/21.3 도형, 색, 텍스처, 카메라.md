# 21.3 도형, 색, 텍스처, 카메라

raylib의 화면은 여러 드로잉 호출을 차례로 쌓아 만든다. 단순한 기하 도형은 좌표와 크기를 직접 전달하고, 이미지가 필요한 곳에는 텍스처를 그리며, 장면 전체를 이동하거나 확대하고 싶을 때는 카메라 변환을 사용한다. 이 절에서는 이 세 가지 표현 수단과 색을 연결해 살펴본다.

## 기하 도형으로 그리기

점, 선, 원, 사각형, 삼각형은 반복 패턴과 그래프를 만드는 기본 재료다. raylib은 도형의 위치와 크기, 색을 그리기 함수의 인자로 받는다. 채워진 원에는 `DrawCircleV()`, 사각형에는 `DrawRectangleRec()`, 삼각형에는 `DrawTriangle()`처럼 목적이 드러나는 함수를 쓸 수 있다. 외곽선만 필요하면 `DrawCircleLines()`, `DrawRectangleLines()` 또는 두께를 받는 `DrawRectangleLinesEx()`를 선택한다. 두 점을 잇는 선의 두께를 직접 지정하려면 `DrawLineEx()`를 사용할 수 있다.

일반적인 기본 도형 함수는 호출할 때마다 그릴 색을 전달한다. p5.js나 Processing처럼 현재 채우기 색과 외곽선 색을 설정해 두고 다음 도형에 이어 쓰는 흐름과 다르다. 개별 호출에 모양과 색이 함께 드러나므로, 반복문에서 각 도형을 다른 색으로 만들거나 같은 색을 재사용할 때 동작을 읽기 쉽다.

```c
Vector2 center = { 160.0f, 120.0f };
Vector2 a = { 40.0f, 200.0f };
Vector2 b = { 130.0f, 40.0f };
Vector2 c = { 220.0f, 200.0f };
Rectangle tile = { 280.0f, 70.0f, 120.0f, 90.0f };

DrawCircleV(center, 28.0f, BLUE);
DrawCircleLines((int)center.x, (int)center.y, 42.0f, DARKBLUE);
DrawTriangle(a, b, c, ORANGE);
DrawRectangleRec(tile, LIGHTGRAY);
DrawRectangleLinesEx(tile, 2.0f, DARKGRAY);
```

각 함수는 하나의 도형을 화면에 그린다. 나중에 호출한 도형은 앞서 그린 도형 위에 겹쳐 보일 수 있으므로, 겹침이 있는 장면에서는 그리기 순서가 곧 앞뒤 관계가 된다. 이 예제는 호출부만 보여 준다. 실제 프로그램에서는 앞 절과 같이 이 호출들을 `BeginDrawing()`과 `EndDrawing()` 사이에 둔다.

## 색과 투명도

raylib의 `Color`는 빨강(red), 초록(green), 파랑(blue), 알파(alpha) 네 채널로 색을 표현한다. 각 채널은 0에서 255 사이의 정수값을 사용한다. 투명도를 생략할 수 없는 사용자 정의 색은 다음처럼 네 값을 모두 지정한다.

```c
Color coral = { 235, 95, 75, 255 };
Color translucentBlue = { 65, 130, 220, 128 };
```

알파가 255이면 완전히 불투명하고 0이면 완전히 투명하다. 중간값은 배경과 섞여 보이므로, 반투명 원이나 선을 겹치면 누적되는 색과 밀도를 표현할 수 있다. raylib은 `BLUE`, `RAYWHITE`, `DARKGRAY` 같은 미리 정의된 색 상수도 제공한다. 반복 패턴에서 팔레트를 바꾸고 싶다면 색을 개별 호출에 직접 적기보다 `Color` 변수나 색 배열에 모아 두면 규칙과 표현을 따로 조정하기 편하다.

도형의 알파와 텍스처의 알파는 모두 겹침과 투명한 가장자리를 표현하는 데 쓰인다. 다만 결과는 현재 블렌딩 설정과 그려진 순서의 영향을 받는다. 불투명한 배경을 먼저 그리고, 그 위에 반투명 요소를 그리는 순서를 기본으로 삼으면 장면의 합성 결과를 예측하기 쉽다.

## 이미지와 텍스처

텍스처(texture)는 이미지 데이터를 그래픽 장치에서 그릴 수 있도록 준비한 자원이다. `LoadTexture()`는 파일을 읽어 `Texture2D`로 만든다. `Texture2D`에는 텍스처의 너비와 높이도 들어 있어, 원본 크기로 그리거나 비율을 유지한 크기를 계산할 때 사용할 수 있다. 이미지 파일을 CPU 메모리에서 편집하는 `Image`와, 화면에 그리기 위해 그래픽 장치에 올리는 `Texture2D`는 용도가 다르다. 픽셀 값을 직접 계산하거나 바꾸는 작업은 CPU 쪽 이미지 처리와 텍스처 갱신을 구분해서 설계해야 한다.

다음은 `raylib.h`를 포함한 소스 파일의 `main()` 안에서 사용할 수 있는 간단한 흐름이다. 텍스처를 한 번 불러온 뒤 반복 프레임에서 재사용하고, 반복문을 빠져나온 다음 해제한다.

```c
InitWindow(640, 400, "texture example");
SetTargetFPS(60);

Texture2D texture = LoadTexture("resources/leaf.png");
if (!IsTextureValid(texture))
{
    CloseWindow();
    return 1;
}

while (!WindowShouldClose())
{
    BeginDrawing();
    ClearBackground(RAYWHITE);

    DrawTexture(texture, 40, 40, WHITE);
    DrawTextureEx(texture, (Vector2){ 180.0f, 40.0f }, 25.0f, 0.5f, WHITE);

    EndDrawing();
}

UnloadTexture(texture);
CloseWindow();
```

이 예제에서 `DrawTexture()`는 텍스처의 왼쪽 위를 지정한 위치에 놓고 원래 크기로 그린다. `DrawTextureEx()`는 위치, 회전 각도, 확대·축소 비율을 추가로 받으며 간편한 대신 회전 기준은 텍스처의 왼쪽 위다. 중심을 축으로 회전하거나 화면에서 차지할 크기를 별도로 지정하려면 `DrawTexturePro()`가 적합하다. `WHITE`는 원본 이미지의 색을 바꾸지 않는 틴트(tint)로 사용할 수 있다. 다른 색을 전달하면 텍스처의 색에 그 색이 곱해진 것처럼 조정되고, 알파를 낮추면 전체 이미지를 반투명하게 표현할 수 있다.

텍스처의 일부를 잘라 쓰거나 크기와 회전 중심을 더 세밀하게 제어하려면 `DrawTexturePro()`를 사용한다. 이 함수에는 텍스처에서 가져올 픽셀 영역인 `source` 사각형, 화면에 배치할 크기와 위치인 `dest` 사각형, 회전 기준점인 `origin`, 회전 각도, 틴트 색을 전달한다. `origin`은 `dest` 사각형 안의 로컬 픽셀 좌표이므로, 중심 회전에는 목적지 너비와 높이의 절반을 지정한다. 이렇게 하면 스프라이트 시트에서 한 칸만 선택하거나 이미지의 중심을 축으로 회전시킬 수 있다. `DrawTextureRec()`는 원본의 일부를 선택해 지정한 위치에 그릴 때 쓸 수 있다.

텍스처는 프레임마다 다시 읽는 데이터가 아니다. 일반적으로 창과 그래픽 문맥을 초기화한 뒤 필요한 텍스처를 한 번 불러오고, 여러 프레임에서 재사용한 다음 작업이 끝날 때 `UnloadTexture()`로 해제한다. 반복문 안에서 매 프레임 `LoadTexture()`를 호출하면 불필요한 파일 읽기와 그래픽 자원 생성이 반복된다. 파일 경로는 프로그램 실행 위치를 기준으로 해석될 수 있으므로, 프로젝트를 배포할 때 이미지 파일이 어디에 있고 실행 파일을 어떤 작업 디렉터리에서 시작하는지도 확인해야 한다.

## 월드 좌표와 `Camera2D`

카메라가 없는 기본 드로잉에서는 도형 좌표가 화면 좌표와 직접 연결된다. 하지만 큰 공간을 조금씩 탐색하거나 장면 전체를 확대·회전하려면 각 도형의 좌표를 모두 직접 바꾸기보다 카메라를 사용한다. `Camera2D`는 월드 좌표(world coordinates)를 화면 좌표(screen coordinates)로 변환하는 설정을 담는다. 월드 좌표는 장면의 개체 위치를 정의하고, 화면 좌표는 그 개체가 창의 어느 위치에 나타나는지를 정의한다.

`Camera2D`의 주요 필드는 다음과 같다.

| 필드 | 역할 |
| --- | --- |
| `target` | 카메라가 바라볼 월드 좌표상의 기준점 |
| `offset` | `target`을 화면의 어느 위치에 놓을지 지정하는 화면 좌표 |
| `rotation` | 카메라 회전 각도(도 단위) |
| `zoom` | 확대 비율. `1.0f`는 기본 배율 |

다음 예제에서는 월드 좌표 `(160, 100)`을 화면 중앙에 놓는다. 카메라가 적용된 영역 안에서는 원의 좌표가 월드 기준이고, 카메라 영역을 끝낸 뒤 그리는 글자는 화면 기준이다.

```c
Camera2D camera = { 0 };
Vector2 target = { 160.0f, 100.0f };

camera.target = target;
camera.offset = (Vector2){ screenWidth * 0.5f, screenHeight * 0.5f };
camera.rotation = 0.0f;
camera.zoom = 1.0f;

BeginDrawing();
ClearBackground(RAYWHITE);

BeginMode2D(camera);
DrawCircleV(target, 24.0f, BLUE);
DrawRectangle(220, 80, 90, 50, ORANGE);
EndMode2D();

DrawText("screen-space overlay", 20, 20, 20, DARKGRAY);
EndDrawing();
```

`BeginMode2D(camera)`와 `EndMode2D()` 사이에서 그린 도형에는 카메라 변환이 적용된다. `target`을 움직이면 카메라가 장면을 따라가고, `zoom`을 바꾸면 장면의 크기가 달라진다. `offset`은 바라보는 기준점이 화면에서 놓일 위치이므로, 화면 중심에 맞추면 `target`이 화면 중앙에 나타난다. 반면 `EndMode2D()` 다음에 그린 사용자 인터페이스나 안내 문구는 카메라의 확대와 이동에 영향을 받지 않는다. 장면과 화면 고정 요소를 구분해 그릴 때 이 경계가 유용하다.

카메라가 있는 장면에서 마우스의 화면 위치를 월드 위치로 바꿔야 할 때는 `GetScreenToWorld2D()`를, 월드 위치를 화면에 표시할 위치로 바꿀 때는 `GetWorldToScreen2D()`를 사용할 수 있다. 입력 이벤트와 좌표 변환의 실제 사용은 21.5에서 다룬다. 여기서는 카메라가 도형을 옮기는 명령이 아니라, 월드 좌표를 화면 좌표로 매핑하는 변환이라는 점을 기억하면 충분하다.

## 표현 수단을 고르는 기준

규칙으로 만든 단순한 기하 형태는 도형 API로 그리는 편이 직접적이다. 같은 이미지를 반복해서 배치하거나 픽셀 아트를 재사용하려면 텍스처가 적합하다. 여러 개체가 공유하는 공간을 움직이거나 확대해야 한다면 카메라 변환으로 좌표계를 분리할 수 있다. 한 작품 안에서 이 방법들을 함께 사용해도 된다. 예를 들어 카메라 아래에는 월드의 입자와 텍스처를 그리고, 카메라 밖에는 화면 고정형 안내와 수치를 그릴 수 있다.

표현 수단이 달라도 계산과 렌더링의 역할은 같다. 프로그램은 규칙에 따라 도형의 위치, 이미지의 배치, 카메라의 목표점을 결정하고, raylib은 그 값을 받아 화면에 표시한다. 각 프레임에서 어떤 좌표계가 활성화되어 있는지, 텍스처 자원이 준비되어 있는지, 어떤 색과 순서로 그리는지를 분명히 하면 복잡한 장면도 작은 명령의 조합으로 이해할 수 있다.

## 이 절의 핵심

raylib은 도형 함수에 색을 직접 전달해 선과 면을 그리며, `Color`의 RGBA 채널로 불투명도와 틴트를 표현한다. 이미지 텍스처는 한 번 불러와 프레임마다 재사용하고, 사용이 끝나면 해제해야 한다. `Camera2D`는 월드 좌표를 화면 좌표로 변환하며, `BeginMode2D()`와 `EndMode2D()` 사이의 드로잉에 적용된다. 도형·텍스처·카메라를 적절히 나누어 쓰면 수학적 규칙과 화면 표현을 유연하게 결합할 수 있다.
