# 21.1 가벼운 그래픽 프로그래밍 환경으로서의 raylib

제너레이티브 아트 프로그램은 수학적 규칙으로 좌표와 색을 계산하고, 그 결과를 화면에 그린다. 앞 장에서 살펴본 Processing과 p5.js는 스케치의 시작과 반복 구조를 마련해 주는 환경이다. raylib은 C 프로그램 안에서 그래픽 창을 열고, 입력을 받고, 매 프레임 무엇을 그릴지 직접 작성하도록 돕는 라이브러리다. 작은 API로 2D와 3D 그래픽, 입력, 오디오 같은 실시간 프로그램의 기본 기능을 제공한다.

raylib은 완성된 장면을 편집하는 시각 도구나 별도의 스케치 편집기가 아니다. C 소스 코드를 작성하고 컴파일해 실행하는 일반적인 프로그램 개발 흐름을 사용한다. 따라서 화면에 무엇을 그리는지뿐 아니라 창을 언제 만들고, 반복을 언제 끝내며, 사용한 자원을 언제 정리하는지도 프로그램에 드러난다. 이 구조는 처음에는 준비할 것이 더 많아 보일 수 있지만, 계산과 화면 갱신이 어떻게 연결되는지 이해하고 싶을 때 장점이 된다.

## 작고 직접적인 라이브러리

라이브러리가 가볍다는 말은 기능이 적거나 작품의 표현력이 제한된다는 뜻이 아니다. raylib은 프로그램의 모든 구조를 대신 결정하는 큰 프레임워크 대신, 창 생성과 입력 확인, 도형 그리기처럼 자주 쓰는 기능을 비교적 직접적인 함수로 제공한다. 개발자는 그 함수들을 조합해 필요한 구조를 만든다. 화면에 원 하나를 그리는 작은 프로그램에서 시작해 입자 시스템이나 3D 장면으로 확장할 수 있다.

이 방식에서는 `raylib.h`를 포함하고, `InitWindow()`로 창을 연 뒤, 그리기 함수로 화면을 구성한다. API의 이름과 인자가 비교적 명시적이어서 코드의 각 줄이 어떤 작업을 하는지 따라가기 쉽다. 동시에 Processing이나 p5.js처럼 전용 편집기와 자동 실행 구조가 준비되어 있지는 않으므로, C 컴파일러와 raylib을 프로젝트에 연결하는 개발 환경이 필요하다. 운영체제와 도구에 따라 프로젝트 설정이나 빌드 방법은 달라질 수 있다.

## 프로그램이 프레임을 만드는 방식

raylib 프로그램은 보통 `main()`에서 시작한다. 초기화가 끝나면 창이 닫힐 때까지 반복문을 실행하고, 반복할 때마다 화면을 그린다. 이 반복의 한 차례가 한 프레임(frame)이다. 다음 예제는 창을 열고, 매 프레임 배경을 지운 뒤 가운데에 원을 그린다.

```c
#include "raylib.h"

int main(void)
{
    const int screenWidth = 640;
    const int screenHeight = 400;

    InitWindow(screenWidth, screenHeight, "raylib generative sketch");
    SetTargetFPS(60);

    while (!WindowShouldClose())
    {
        BeginDrawing();
        ClearBackground(RAYWHITE);

        DrawCircle(screenWidth / 2, screenHeight / 2, 36.0f, BLUE);
        DrawText("raylib", 20, 20, 20, DARKGRAY);

        EndDrawing();
    }

    CloseWindow();
    return 0;
}
```

각 함수는 프로그램의 한 단계를 나타낸다. `InitWindow()`는 지정한 크기와 제목으로 창을 준비하고, `SetTargetFPS()`는 반복 속도의 목표를 설정한다. `WindowShouldClose()`가 참이 되면 반복문을 끝낸다. 보통 창의 닫기 버튼이나 기본 종료 입력이 이에 반영된다. `BeginDrawing()`과 `EndDrawing()`은 한 프레임의 그리기 구간을 감싸며, 그 사이에서 배경과 도형을 그린다. 반복이 끝나면 `CloseWindow()`로 창과 그래픽 자원을 정리한다.

`ClearBackground()`는 매 프레임 새 배경색으로 화면을 채운다. 이 예제처럼 매 프레임 장면 전체를 다시 그리는 방식에서는 이전 프레임의 그림을 남기지 않도록 배경을 먼저 지우는 것이 기본이다. 반대로 선의 흔적을 누적하거나 잔상을 만들고 싶다면 화면을 지우는 방식과 그리는 순서를 의도적으로 바꿀 수 있다. 이 차이는 뒤에서 실시간 프레임과 드로잉 기법을 살펴볼 때 다시 다룬다.

## 수학 규칙을 드로잉 호출로 옮기기

raylib을 쓴다고 해서 기하학이나 패턴을 만드는 수학이 달라지는 것은 아니다. 예를 들어 원 둘레에 점을 일정하게 놓으려면 반복 변수 `i`로 각도 `angle = 2 * PI * i / count`를 계산하고, 중심과 반지름으로 좌표를 구한다. 이어 그 좌표를 `DrawCircle()` 같은 함수에 전달한다. 즉, 계산은 위치와 모양을 결정하고, 드로잉 API는 계산 결과를 화면에 표시한다.

이 분리는 중요하다. 패턴의 점 개수를 바꾸거나 간격 규칙을 수정할 때에는 수학적 계산을 바꾸고, 점을 사각형이나 선으로 표현하고 싶을 때에는 드로잉 호출을 바꾸면 된다. 작은 예제에서는 한 반복문 안에 두 역할을 함께 적어도 충분하지만, 입자가 많아지고 상태와 입력이 추가되면 계산 부분과 그리기 부분을 나누는 편이 수정하기 쉽다. raylib은 이 구조를 강제하지 않으므로 프로그램의 크기에 맞게 구성할 수 있다.

## 어떤 작업에 잘 맞을까

raylib은 C를 사용해 그래픽과 상호작용을 직접 다루고 싶거나, 창과 프레임 반복이 내부에서 어떻게 이어지는지 배우려는 작업에 잘 맞는다. 별도의 장면 편집기 없이 코드로 모든 요소를 지정하므로 규칙과 계산이 프로그램에 분명히 남는다. 2D 드로잉으로 시작해 텍스처, 카메라, 3D 표현으로 넓힐 수 있다는 점도 장점이다.

대신 스케치 실행 환경이 제공하는 편의까지 라이브러리가 대신해 주지는 않는다. 컴파일과 빌드 설정을 준비해야 하고, 프로젝트가 커지면 자료 구조와 코드 구성을 직접 설계해야 한다. 빠르게 한 줄을 수정해 브라우저에서 공유하는 것이 가장 중요한 경우에는 p5.js가 더 편리할 수 있다. C와 데스크톱 실행 흐름에 관심이 있고, 필요한 만큼 구조를 직접 통제하고 싶다면 raylib이 좋은 선택이다. 어느 도구가 더 우수한지보다 작업 언어, 배포 방식, 원하는 통제 수준을 기준으로 고르는 편이 현실적이다.

## 이 장에서 살펴볼 내용

다음 절에서는 raylib의 C 드로잉 API와 좌표계를 확인하고, 도형·색·텍스처·카메라를 차례로 살펴본다. 이어 프레임 반복과 입력 처리의 구조를 다룬 뒤, 이를 2D 제너레이티브 아트에 적용한다. 마지막에는 3D 공간으로 확장하는 방법과 raylib이 크리에이티브 코딩 프레임워크와 어떻게 다른지 비교한다. 이 절의 코드는 전체 흐름을 미리 보여 주는 최소 예제이며, 각 기능의 세부 사용법은 해당 절에서 이어서 설명한다.

## 이 절의 핵심

raylib은 C 프로그램에서 창, 입력, 그래픽 출력을 직접 구성하도록 돕는 가벼운 라이브러리다. `main()`에서 창과 반복을 관리하고, 프레임마다 수학적 규칙의 결과를 드로잉 API에 전달한다. 스케치 환경보다 개발 준비와 구조 설계가 필요하지만, 계산과 화면 갱신의 연결을 명시적으로 다룰 수 있다.
