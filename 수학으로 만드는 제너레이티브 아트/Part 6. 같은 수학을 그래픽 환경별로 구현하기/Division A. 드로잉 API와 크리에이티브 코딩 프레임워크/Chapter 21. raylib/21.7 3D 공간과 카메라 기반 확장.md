# 21.7 3D 공간과 카메라 기반 확장

2D 제너레이티브 규칙을 3D로 확장하는 일은 좌표에 z값 하나를 덧붙이는 것만으로 끝나지 않는다. 개체의 위치와 크기는 3차원 월드 공간에 정의되고, 카메라는 그 공간을 어느 위치와 방향에서 볼지 정한다. 원근 또는 직교 투영은 같은 장면을 화면에 서로 다르게 옮긴다. raylib에서는 `Vector3`로 3D 위치를 지정하고, `Camera3D`와 `BeginMode3D()`로 카메라가 적용되는 그리기 구간을 만든다.

## 월드 공간과 3차원 좌표

raylib의 `Vector3`는 실수형 `x`, `y`, `z` 성분을 가진다. 일반적으로 x축은 좌우, y축은 위아래, z축은 깊이 방향을 나타낸다. 기본 2D 좌표가 화면 픽셀 위치를 뜻했다면, 3D 좌표는 장면 안의 월드 좌표(world coordinates)다. 월드 단위는 픽셀과 같을 필요가 없다. 예를 들어 큐브의 한 변을 1 단위로 정하고, 카메라와 다른 개체의 위치도 같은 단위 체계로 표현하면 된다.

raylib의 기본 3D 예제에서는 y축을 위쪽으로 사용한다. 카메라를 z축의 양의 쪽에 두고 원점을 바라보게 하면 원점의 개체가 보이고, z값이 다른 개체는 카메라 방향에 따라 앞이나 뒤에 놓인다. 다만 “앞”과 “뒤”는 월드 축만으로 정해지는 것이 아니라 카메라가 어디에 있고 어느 방향을 바라보는지에 따라 달라진다.

위치와 도형의 크기를 직접 전달하는 3D 함수도 있다. `DrawLine3D()`는 두 `Vector3`를 잇고, `DrawTriangle3D()`는 세 꼭짓점으로 삼각형을 그린다. 기본 입체에는 `DrawCubeV()`나 `DrawSphere()` 등을 쓸 수 있다. 많은 점으로 곡선이나 표면을 표현할 때는 수학 함수로 3D 위치를 생성한 뒤 점·선·입체를 반복해서 그린다.

## 카메라가 맡는 일

`Camera3D`는 카메라의 위치와 시선, 화면에 투영하는 방법을 담는다. raylib에서는 `Camera`와 `Camera3D`가 같은 카메라 자료형을 가리키는 이름으로 제공된다. 주요 필드는 다음과 같다.

| 필드 | 역할 |
| --- | --- |
| `position` | 월드 공간에서 카메라가 놓인 위치 |
| `target` | 카메라가 바라보는 월드 좌표 |
| `up` | 화면에서 위쪽을 정하는 방향 벡터. 흔히 `(0, 1, 0)` |
| `fovy` | 원근 투영의 세로 시야각(도 단위) |
| `projection` | 원근 또는 직교 투영을 선택 |

시야 방향은 `position`에서 `target`을 향한다. 두 값이 같으면 바라볼 방향을 정할 수 없으므로 서로 다른 위치여야 한다. `up`은 카메라 화면에서 위쪽을 정한다. 일반적인 y-up 장면에서는 `(0, 1, 0)`을 사용하지만, 시선 방향과 평행한 벡터를 지정하면 화면의 위쪽 방향을 안정적으로 결정할 수 없다.

## 원근 투영과 직교 투영

원근 투영(perspective projection)은 카메라에서 먼 물체가 작게 보이고, 평행한 선도 화면에서 한 점을 향해 모이는 듯 보이게 한다. 사람의 시각이나 사진과 비슷한 깊이감을 만들기 좋다. `CAMERA_PERSPECTIVE`를 사용하며 `fovy`는 세로 방향의 시야각을 도 단위로 지정한다. 시야각이 작으면 좁은 영역이 확대되어 보이고, 크면 더 넓은 장면이 들어온다.

직교 투영(orthographic projection)은 거리에 따라 물체의 화면상 크기가 작아지지 않는다. 평행선의 방향도 유지되므로 기하 구조를 비교하거나 깊이 왜곡을 줄인 그래픽에 잘 맞는다. `CAMERA_ORTHOGRAPHIC`를 선택해 사용할 수 있다. 투영 방식은 개체의 3D 위치를 바꾸지 않고 화면에 보이는 관계를 바꾸므로, 작품에서 깊이감이 중요한지 정확한 비례가 중요한지에 따라 선택한다.

## 카메라 안에서 그리기

다음 예제는 3차원 나선 위에 작은 구를 일정한 간격으로 놓고, 전체 형태를 y축 주위로 천천히 회전시킨다. 각 구의 위치는 매개변수 `t`에서 계산되고, 카메라는 원점을 향한다.

```c
#include "raylib.h"
#include <math.h>

int main(void)
{
    const int screenWidth = 800;
    const int screenHeight = 600;
    const int pointCount = 96;
    const float tau = 6.2831853f;

    InitWindow(screenWidth, screenHeight, "3D generative helix");
    SetTargetFPS(60);

    Camera3D camera = { 0 };
    camera.position = (Vector3){ 7.0f, 6.0f, 7.0f };
    camera.target = (Vector3){ 0.0f, 0.0f, 0.0f };
    camera.up = (Vector3){ 0.0f, 1.0f, 0.0f };
    camera.fovy = 45.0f;
    camera.projection = CAMERA_PERSPECTIVE;

    while (!WindowShouldClose())
    {
        const float time = (float)GetTime();

        BeginDrawing();
        ClearBackground(RAYWHITE);

        BeginMode3D(camera);
        DrawGrid(20, 1.0f);

        for (int i = 0; i < pointCount; i++)
        {
            const float t = (float)i / (float)(pointCount - 1);
            const float angle = tau * 3.0f * t + time * 0.25f;
            const Vector3 position = {
                2.0f * cosf(angle),
                -1.2f + 2.4f * t,
                2.0f * sinf(angle)
            };

            Color color = BLUE;
            if (i % 6 < 3) color = ORANGE;
            DrawSphere(position, 0.075f, color);
        }

        EndMode3D();
        DrawText("A procedural helix in 3D", 20, 20, 20, DARKGRAY);
        EndDrawing();
    }

    CloseWindow();
    return 0;
}
```

나선의 점은 다음과 같은 매개변수 규칙으로 만든다.

$$
\mathbf{p}(t) =
\left(2\cos(6\pi t),\; -1.2 + 2.4t,\; 2\sin(6\pi t)\right),
\qquad 0 \le t \le 1
$$

코드에서는 `t`를 0부터 1까지 `pointCount`개의 표본으로 나눈다. x와 z 성분이 원을 그리는 동안 y 성분은 일정하게 증가하므로 나선이 된다. `time * 0.25f`는 각도에 더해져 나선 전체를 천천히 회전시키며, `DrawSphere()`의 반지름은 각 점에 그릴 구의 크기를 정한다. `DrawGrid()`는 월드 공간에서 높이 0인 기준면을 보여 주므로 구들의 위치와 크기를 가늠하기 쉽다.

## 3D 그리기 구간과 화면 고정 요소

`BeginMode3D(camera)`와 `EndMode3D()`는 카메라 변환이 적용되는 영역을 감싼다. 이 사이의 도형은 월드 좌표를 사용하고 원근 또는 직교 투영을 거쳐 화면에 나타난다. `EndMode3D()` 뒤에서 `DrawText()`나 2D 도형을 그리면 카메라의 이동과 투영에 영향을 받지 않는 화면 좌표로 표시된다. 작품 안의 입체 구조와 제목·안내·조작 패널을 함께 그릴 때 편리하다.

3D에서는 깊이 버퍼가 앞뒤 관계를 계산하므로, 불투명한 물체는 단순히 나중에 그렸다는 이유만으로 항상 앞에 나타나는 것은 아니다. 카메라에 가까운 물체가 뒤쪽 물체를 가리는 것이 기본이다. 반면 투명한 표면은 색을 섞는 순서가 결과에 영향을 줄 수 있으므로, 투명 재질을 여러 겹 그릴 때는 그리는 순서를 따로 고려해야 한다.

## 수학 규칙을 입체로 확장하기

2D 규칙은 다양한 방식으로 3D가 될 수 있다. 평면의 점 `(x, y)`에 높이 함수 `z = h(x, y)`를 더하면 표면이나 지형을 만들 수 있다. 원 둘레의 좌표에 높이를 추가하면 나선이나 층층이 쌓인 구조가 된다. 점의 색을 깊이, 높이, 카메라와의 거리, 벡터장의 방향에 연결하면 기하 형태뿐 아니라 데이터도 시각화할 수 있다.

점의 수를 늘리는 것만으로 매끄러운 3D 표면이 만들어지는 것은 아니다. 점 사이를 선분이나 삼각형으로 연결할지, 격자 간격을 어떻게 둘지, 표본 수를 얼마나 사용할지 결정해야 한다. 표본이 적으면 형태가 각지고, 지나치게 많으면 계산과 렌더링 비용이 커진다. 곡선은 `DrawLine3D()`로 이웃한 표본을 이어 표현할 수 있고, 표면은 삼각형 메시(mesh)로 구성할 수 있다. 복잡한 반복 구조에서는 매 프레임 변하지 않는 점이나 연결 관계를 미리 계산해 재사용하는 편이 효율적이다.

3D 벡터의 덧셈·뺄셈·길이·정규화·외적 같은 연산은 직접 성분별로 계산하거나 `raymath.h`의 `Vector3` 함수들을 사용할 수 있다. 특히 외적은 두 방향 벡터에 수직인 법선 방향을 구할 때 유용하며, 카메라 방향과 표면 방향을 다룰 때 기초가 된다. 다만 API의 벡터 함수는 계산을 편리하게 할 뿐, 좌표계와 방향 규칙을 대신 결정하지는 않는다.

## 어떤 투영과 구조를 고를까

깊이와 원근감을 강조하는 장면에는 원근 투영을, 크기와 평행 관계를 비교하는 도식에는 직교 투영을 먼저 시험한다. 카메라 위치를 바꾸면 같은 형태도 전혀 다른 실루엣으로 보일 수 있으므로, 모델의 수식만큼 카메라 구도도 작품 설계의 일부다. 2D 패턴을 3D로 옮길 때는 z값을 추가하는 목적이 깊이인지, 높이 데이터인지, 카메라 이동인지부터 분명히 한다.

처음에는 `DrawGrid()`와 기본 입체로 축의 방향을 확인한 다음, 한 개의 매개변수 곡선을 그리고, 마지막에 반복 표본과 색·시간 변화를 더하는 순서가 좋다. 화면에서 형태가 보이지 않을 때에는 먼저 카메라의 `position`과 `target`, 개체의 월드 위치와 크기, 투영 방식을 차례로 확인한다. 이런 분리는 수식이 틀린 문제와 카메라가 장면을 비추지 않는 문제를 구별하는 데 도움이 된다.

## 이 절의 핵심

raylib의 3D 장면은 `Vector3` 월드 좌표로 개체를 정의하고 `Camera3D`로 시점과 투영을 정한다. `BeginMode3D()`와 `EndMode3D()` 사이에는 카메라가 적용되고, 그 밖에는 화면 고정형 2D 요소를 그릴 수 있다. 원근 투영은 깊이감을, 직교 투영은 거리와 무관한 크기 표현을 제공한다. 2D 수학 규칙에 깊이 함수나 3D 매개변수 곡선을 더하고 표본 밀도와 카메라를 함께 설계하면 기존 생성 규칙을 입체 장면으로 확장할 수 있다.
