# 21.4 게임 루프와 실시간 시각화

raylib은 프로그램이 실행되는 동안 반복해서 프레임을 만든다. 한 프레임에서 상태를 갱신하고, 그 상태를 그림으로 표현한 뒤, 다음 프레임으로 넘어간다. 이 반복 구조는 게임뿐 아니라 입자 시뮬레이션, 움직이는 그래프, 실시간 데이터 시각화에도 쓰인다. 중요한 점은 프레임마다 한 번 계산한다는 사실보다, 실제 프레임 간격이 달라져도 시간의 흐름과 움직임이 의도한 대로 유지되도록 만드는 것이다.

## 갱신과 그리기

실시간 프로그램의 반복은 개념적으로 두 작업으로 나눌 수 있다.

1. **상태 갱신(update)**: 위치, 속도, 색, 수명처럼 다음 화면에 영향을 주는 값을 계산한다.
2. **그리기(draw/render)**: 현재 상태를 읽어 도형과 이미지로 화면에 표현한다.

raylib은 이 구분을 강제하는 `update()`나 `draw()` 콜백을 제공하는 대신, 개발자가 `main()`의 반복문 안에 두 작업을 직접 배치한다. 앞 절의 `BeginDrawing()`과 `EndDrawing()`은 그리기 구간을 표시한다. 상태 갱신은 보통 그 구간에 들어가기 전에 수행하고, 그리기 함수는 구간 안에서 호출한다.

```c
while (!WindowShouldClose())
{
    float dt = GetFrameTime();
    updateState(dt);

    BeginDrawing();
    ClearBackground(RAYWHITE);
    drawScene();
    EndDrawing();
}
```

여기서 `updateState()`와 `drawScene()`은 역할을 보여 주기 위한 사용자 함수 이름이다. 실제 코드에서는 입자 배열을 갱신하는 반복문과 `DrawCircleV()` 호출이 각각 들어갈 수 있다. 계산과 그리기를 분리하면 화면에 표시하는 모양을 바꾸어도 시뮬레이션 규칙은 유지할 수 있고, 반대로 움직임을 바꾸어도 그리는 코드는 그대로 둘 수 있다.

## 프레임률은 시간 자체가 아니다

프레임률(frame rate)은 1초 동안 화면을 몇 번 갱신했는지를 나타낸다. 초당 60프레임은 한 프레임에 평균 약 `1 / 60`초가 걸린다는 뜻이지, 매 프레임이 정확히 그 시간에 실행된다는 보장은 아니다. 장면이 복잡해지거나 운영체제가 다른 작업을 처리하면 프레임 간격은 길어질 수 있다.

raylib의 시간 관련 함수는 서로 다른 목적을 가진다.

| 함수 | 의미 | 주된 용도 |
| --- | --- | --- |
| `SetTargetFPS(fps)` | 목표 최대 프레임률을 설정 | 반복 속도를 일정 수준으로 제한 |
| `GetFrameTime()` | 직전 프레임에 걸린 시간(초)을 반환 | 프레임 사이 상태 변화량 계산 |
| `GetTime()` | 창 초기화 뒤 흐른 시간(초)을 반환 | 시간에 직접 연결된 애니메이션 계산 |
| `GetFPS()` | 현재의 프레임률 측정값을 반환 | 성능을 화면에 표시하거나 점검 |

`SetTargetFPS(60)`은 초당 60프레임을 목표로 삼게 하지만, 장면이 무거우면 목표보다 낮아질 수 있다. 모니터의 새로 고침이나 실행 환경도 실제 결과에 영향을 준다. `GetFPS()`는 성능을 살펴보는 진단값으로는 유용하지만, 움직임의 양을 계산하는 기준으로 삼기에는 적절하지 않다. 프레임률은 순간적으로 변하고 정수로 표시될 수 있기 때문이다. 움직임에는 실제 프레임 간격을 나타내는 `GetFrameTime()`을 사용한다.

## 델타 타임으로 속도 유지하기

델타 타임(delta time, `dt`)은 이전 프레임과 현재 프레임 사이에 흐른 시간이다. `GetFrameTime()`이 반환하는 값은 초 단위다. 어떤 물체가 초당 180픽셀의 속도로 오른쪽으로 움직인다면 한 프레임의 이동량은 속도에 `dt`를 곱해 구한다.

```text
이동 거리 = 초당 속도 × 프레임 사이 시간
```

프레임률이 약 60이면 `dt`는 대략 `0.0167`초이고, 한 프레임에 약 3픽셀 이동한다. 프레임률이 30으로 떨어지면 `dt`는 대략 `0.0333`초가 되어 한 프레임에 약 6픽셀 이동한다. 두 경우 모두 1초 동안의 총 이동량은 약 180픽셀로 유지된다.

```c
#include "raylib.h"

int main(void)
{
    const int screenWidth = 640;
    const int screenHeight = 400;
    const float radius = 16.0f;

    InitWindow(screenWidth, screenHeight, "delta time example");
    SetTargetFPS(60);

    Vector2 position = { 40.0f, screenHeight * 0.5f };
    const float speed = 180.0f;

    while (!WindowShouldClose())
    {
        const float dt = GetFrameTime();
        position.x += speed * dt;

        if (position.x > screenWidth + radius)
        {
            position.x = -radius;
        }

        BeginDrawing();
        ClearBackground(RAYWHITE);
        DrawCircleV(position, radius, BLUE);
        EndDrawing();
    }

    CloseWindow();
    return 0;
}
```

`speed`의 단위는 픽셀/초이고 `dt`의 단위는 초이므로, 곱의 단위는 픽셀이다. 이 예제는 원이 화면 오른쪽을 벗어나면 왼쪽에서 다시 나타나게 한다. `position.x += 3.0f`처럼 프레임마다 같은 거리를 더하는 방식은 프레임률에 따라 실제 속도가 달라진다. 반면 `speed * dt`를 더하면 프레임 간격이 바뀌어도 시간당 이동량이 비슷하게 유지된다.

가속도가 있는 운동도 같은 원리로 시간 간격을 반영한다. 예를 들어 가속도에 `dt`를 곱해 속도를 갱신하고, 새 속도에 다시 `dt`를 곱해 위치를 갱신한다.

```c
velocity.x += acceleration.x * dt;
velocity.y += acceleration.y * dt;
position.x += velocity.x * dt;
position.y += velocity.y * dt;
```

`Vector2`의 성분을 직접 갱신한 예다. `velocity`는 초당 위치 변화량, `acceleration`은 초당 속도 변화량이므로, 각 갱신식에 시간이 곱해지는 이유를 단위로 확인할 수 있다. 위치 갱신에서 이전 속도를 쓸지 갱신된 속도를 쓸지는 수치 적분 방식에 따른 차이를 만든다. 여기서는 프레임 사이에 힘이 속도를 바꾸고, 바뀐 속도가 위치에 반영되는 순서를 사용한다.

## 프레임 간격이 크게 달라질 때

창이 가려졌다가 다시 나타나거나, 프로그램이 잠깐 멈추거나, 한 프레임의 계산량이 갑자기 커지면 `dt`가 평소보다 훨씬 커질 수 있다. 그 순간 물체가 경계를 건너뛰거나 충돌을 놓치고, 시뮬레이션이 한꺼번에 크게 변할 수 있다. 단순한 시각 효과라면 사용할 `dt`에 상한을 둘 수 있다.

```c
float dt = GetFrameTime();
if (dt > 0.05f) dt = 0.05f;
```

이 처리는 한 번에 적용되는 변화량을 제한해 큰 도약을 줄인다. 다만 긴 멈춤 동안 흘렀던 시간을 버리는 셈이므로, 실제 경과 시간을 정확히 재현하는 방법은 아니다. 충돌이나 상호작용이 안정적으로 계산되어야 하는 시뮬레이션에서는 고정 시간 간격(fixed timestep) 갱신을 고려할 수 있다.

고정 시간 간격 방식은 렌더링 프레임 간격과 시뮬레이션 갱신 간격을 분리한다. 프레임마다 경과 시간을 누적하고, 누적값이 정해 둔 한 단계를 넘을 때마다 같은 크기의 시간으로 상태를 갱신한다.

```c
const double fixedStep = 1.0 / 60.0;
double accumulator = 0.0;

while (!WindowShouldClose())
{
    accumulator += GetFrameTime();

    while (accumulator >= fixedStep)
    {
        updateState((float)fixedStep);
        accumulator -= fixedStep;
    }

    BeginDrawing();
    ClearBackground(RAYWHITE);
    drawScene();
    EndDrawing();
}
```

이 구조에서는 화면을 초당 60번 그리는지와 관계없이 시뮬레이션을 약 `1 / 60`초 단위로 갱신한다. 프레임이 늦어지면 한 렌더링 프레임에서 여러 번 갱신이 실행될 수 있다. 따라서 모든 작품에 고정 간격을 적용할 필요는 없다. 단순한 애니메이션이나 시각화는 가변 `dt`로 충분한 경우가 많고, 충돌과 상호작용이 민감한 시뮬레이션은 고정 간격을 시험해 볼 가치가 있다. 한 프레임에 갱신이 지나치게 많이 밀리지 않도록 단계 수를 제한하는 방법도 함께 고려한다.

## 시간으로 직접 장면 계산하기

모든 애니메이션이 이전 프레임의 상태를 갱신해야 하는 것은 아니다. 반복되는 진동처럼 시간에 따른 값을 직접 계산할 수 있는 효과는 `GetTime()`을 이용해 현재 시간을 함수에 대입하면 된다.

```c
float t = (float)GetTime();
float pulse = 0.5f + 0.5f * sinf(t * 2.0f);
float radius = 20.0f + 8.0f * pulse;
```

여기서 `sinf()`를 사용하려면 `<math.h>`를 포함해야 하며, 삼각함수의 입력은 라디안이다. `GetTime()`은 창 초기화 뒤의 경과 시간을 주므로 프레임마다 값을 누적하지 않아도 진동의 위상을 계산할 수 있다. 이 방식은 주기 운동이나 색의 변화처럼 특정 시각의 상태를 바로 정할 수 있을 때 간결하다. 반면 입자의 충돌, 힘에 따른 가속, 이전 위치에 의존하는 움직임처럼 과거 상태가 필요한 시스템은 `dt`를 사용해 상태를 갱신한다.

## 화면을 다시 그릴지 흔적을 남길지

일반적인 프레임은 배경을 지운 뒤 현재 상태를 전부 다시 그린다. 그러면 위치가 바뀐 도형은 이전 위치에 남지 않고, 각 프레임이 현재 장면을 정확히 보여 준다. 화면에 움직임의 궤적이나 잔상을 남기려면 이전 프레임의 결과를 어떻게 보존할지 별도로 설계해야 한다. 기본 프레임 버퍼의 내용이 다음 프레임에도 보존된다고 가정하지 말고, `RenderTexture2D` 같은 지속되는 렌더 표면에 결과를 누적한다. 필요하면 그 표면 위에 낮은 알파의 배경을 덧그려 이전 흔적을 서서히 약화시킨다. 잔상과 누적 드로잉의 시각적 효과는 16.8에서 다룬 원리와 연결된다.

## 이 절의 핵심

raylib의 게임 루프는 상태를 갱신하고 그 상태를 프레임으로 그리는 반복이다. `SetTargetFPS()`는 목표 프레임률을 설정하지만 이를 보장하지 않으며, 시간에 따른 움직임은 `GetFrameTime()`을 이용해 계산해야 한다. 주기 효과는 `GetTime()`으로 직접 계산할 수 있고, 충돌처럼 안정적인 시간 단계가 중요한 경우에는 고정 시간 간격 갱신을 고려한다. 프레임률과 시간 간격을 구분하면 같은 시뮬레이션을 다양한 실행 성능에서 더 일관되게 시각화할 수 있다.
