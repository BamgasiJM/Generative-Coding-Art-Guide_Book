# 21.6 2D 제너레이티브 아트 구현

raylib으로 2D 제너레이티브 아트를 만들 때는 수학적 규칙을 좌표와 색으로 계산하고, 그 값을 도형 API에 전달한다. 구현의 기본 골격은 앞 절에서 살펴본 프레임 루프와 같다. 매 프레임 입력과 시간을 반영해 필요한 상태를 갱신하고, 현재 상태에서 도형을 배치한 뒤, 다음 프레임으로 넘어간다.

작업을 몇 가지 역할로 나누면 구조를 파악하기 쉽다.

1. **파라미터**: 반복 횟수, 간격, 진폭, 색 팔레트처럼 작품의 성격을 정하는 값
2. **계산 규칙**: 격자나 극좌표, 함수, 벡터 필드로 각 요소의 위치와 크기를 구하는 과정
3. **표현**: 계산 결과를 원·선·사각형·텍스처로 그리는 과정
4. **시간과 입력**: 애니메이션과 사용자 조작이 파라미터 또는 상태를 바꾸는 과정

작은 스케치에서는 이 역할이 한 프레임 루프에 함께 있어도 괜찮다. 작품이 커지면 계산을 별도 함수로 분리하거나, 생성한 요소를 배열에 저장해 시뮬레이션과 그리기를 나누면 수정과 성능 점검이 쉬워진다.

## 파동 격자 예제

다음 프로그램은 일정한 격자에 원을 배치하고, 각 위치의 사인파 값으로 원의 크기와 색을 정한다. 시간에 따라 파동의 위상이 이동하며, 위쪽·아래쪽 화살표로 가로 방향의 파동 수를 바꾸고 스페이스바로 애니메이션을 멈추거나 다시 시작한다.

```c
#include "raylib.h"
#include <math.h>

int main(void)
{
    const int screenWidth = 800;
    const int screenHeight = 600;
    const int columns = 24;
    const int rows = 16;
    const float tau = 6.2831853f;

    InitWindow(screenWidth, screenHeight, "2D generative pattern");
    SetTargetFPS(60);

    float phase = 0.0f;
    float frequency = 3.0f;
    int paused = 0;

    while (!WindowShouldClose())
    {
        const float dt = GetFrameTime();

        if (IsKeyPressed(KEY_SPACE)) paused = !paused;
        if (IsKeyPressed(KEY_UP)) frequency += 0.25f;
        if (IsKeyPressed(KEY_DOWN) && frequency > 0.5f)
        {
            frequency -= 0.25f;
        }
        if (!paused) phase += dt;

        BeginDrawing();
        ClearBackground(RAYWHITE);

        for (int row = 0; row < rows; row++)
        {
            for (int column = 0; column < columns; column++)
            {
                const float u = (float)column / (float)(columns - 1);
                const float v = (float)row / (float)(rows - 1);
                const float x = 40.0f + u * (screenWidth - 80.0f);
                const float y = 55.0f + v * (screenHeight - 110.0f);
                const float angle = tau * (frequency * u + 0.8f * v) + phase;
                const float wave = 0.5f + 0.5f * sinf(angle);
                const float radius = 2.0f + 7.0f * wave;

                Color color = BLUE;
                if (wave > 0.5f) color = ORANGE;

                DrawCircleV((Vector2){ x, y }, radius, color);
            }
        }

        DrawText("UP/DOWN: frequency   SPACE: pause", 20, 18, 18, DARKGRAY);
        EndDrawing();
    }

    CloseWindow();
    return 0;
}
```

`u`와 `v`는 열과 행의 정수 번호를 0에서 1 사이로 정규화한 값이다. 따라서 점은 창의 가장자리에 붙지 않고 일정한 여백을 두고 배치된다. `angle`은 각 격자점에서 평가할 파동의 위상이다. `frequency * u`가 가로 방향의 반복 수를 조절하고 `0.8f * v`는 세로 방향으로 위상을 조금씩 바꾼다. `phase`를 시간에 따라 증가시키면 파동이 격자를 가로질러 움직인다.

`sinf()`의 출력 범위는 -1에서 1이므로, `0.5f + 0.5f * sinf(angle)`로 바꾸면 `wave`는 0에서 1 사이가 된다. 이 값을 원의 반지름과 색 선택에 사용한다. 한 가지 계산 결과를 여러 시각 속성에 연결하면 크기와 색이 서로 관련된 패턴이 된다. `DrawCircleV()`는 각 점을 원으로 표현하고, `ClearBackground()`는 매 프레임 이전 화면을 지워 현재 파동만 남긴다.

## 파라미터를 구조화하기

제너레이티브 아트에서 반복 횟수와 간격은 단순한 구현 세부가 아니라 작품의 밀도와 리듬을 정하는 파라미터다. 이 예제의 `columns`와 `rows`를 늘리면 점이 촘촘해지고, `frequency`를 높이면 가로 방향 파동이 더 많이 반복된다. `phase`의 증가 속도를 바꾸면 움직임이 빨라지거나 느려진다. 원의 반지름 범위와 `wave`를 색에 연결하는 기준을 바꾸면 같은 위치 규칙에서 다른 시각적 성격을 만들 수 있다.

화면 크기가 바뀌어도 패턴의 비율을 유지하려면 고정 픽셀 좌표만 사용하지 말고, 예제처럼 `u`, `v`를 화면의 사용 가능한 영역에 대응시킨다. 화면 여백을 `margin` 파라미터로 빼면 배치 영역을 조정하기 쉽다. 각 격자점의 간격은 다음처럼 계산할 수 있다.

```text
x = margin + u * (screenWidth - 2 * margin)
y = margin + v * (screenHeight - 2 * margin)
```

가로·세로 비율이 크게 다른 창에서 원형 무늬가 타원처럼 늘어나는 것이 싫다면, 화면의 짧은 변을 기준으로 스케일을 정하거나 정사각형의 작업 영역을 중앙에 배치한다. 좌표의 비율과 도형의 크기 기준을 함께 관리해야 해상도 변경에도 작품의 구성이 안정적이다.

## 랜덤 변형과 재현성

규칙적인 격자에 작은 차이를 더하면 기계적인 반복을 완화할 수 있다. 예를 들어 각 점에 위치 오프셋, 크기 변화, 색상 선택을 추가할 수 있다. 이때 장면을 그릴 때마다 `GetRandomValue()`를 호출하면 같은 요소의 값이 매 프레임 바뀌어 화면이 깜박이거나 불규칙하게 떨릴 수 있다. 랜덤값은 일반적으로 작품을 생성하거나 사용자가 재생성을 요청한 순간 한 번 만들고, 그 결과를 배열에 저장해 여러 프레임에서 재사용한다.

```c
enum { count = 48 };
const unsigned int seed = 2026;
float offsets[count];

SetRandomSeed(seed);
for (int i = 0; i < count; i++)
{
    offsets[i] = (float)GetRandomValue(-8, 8);
}
```

같은 시드와 같은 호출 순서를 유지하면 같은 실행 환경에서 같은 의사 난수 흐름을 재현할 수 있다. 플랫폼이나 C 런타임 구현까지 달라도 완전히 같은 결과가 필요하다면 라이브러리의 기본 난수 발생기에만 의존하지 말고, 인덱스에서 직접 값을 만드는 해시 기반 규칙이나 명시적인 난수 생성기를 사용해야 한다. 재현성은 결과 비교, 버그 수정, 작품 저장에 유용하다. 시드를 바꾸면 새로운 구성을 만들고, 시드를 기록하면 특정 구성을 다시 불러올 수 있다.

## 애니메이션과 흔적

애니메이션할 때는 어떤 값이 시간에 따라 변하는지 먼저 정한다. 예제에서는 `phase`만 갱신하고 각 점의 위치와 크기는 매 프레임 그 값에서 다시 계산한다. 이 방식은 파동처럼 시각적 상태를 시간의 함수로 직접 표현할 때 간단하다. 반면 입자처럼 이전 위치와 속도가 다음 상태에 영향을 주는 시스템은 각 입자의 상태를 저장하고 `dt`로 갱신해야 한다. 둘 다 프레임 루프에서 그리지만, 하나는 시간에서 현재 상태를 계산하고 다른 하나는 과거 상태를 이어 간다는 차이가 있다.

화면을 매 프레임 지우면 현재 상태만 보이는 깔끔한 애니메이션이 된다. 궤적이나 잔상을 만들고 싶으면 `RenderTexture2D` 같은 지속되는 렌더 표면에 이전 결과를 보존하고, 낮은 알파의 배경을 덧그려 흔적이 서서히 사라지게 할 수 있다. 단순히 `ClearBackground()`를 생략한다고 이전 프레임의 그림이 안정적으로 남는 것은 아니다. 누적할 표면과 지우는 규칙을 명시적으로 설계해야 한다.

## 요소 수와 그리기 비용

격자 예제는 한 프레임마다 `rows * columns`개의 원을 그린다. 요소 수가 증가하면 위치 계산과 드로잉 작업도 함께 늘어난다. 우선 실제로 필요한 시각적 밀도를 정하고, 화면에 거의 구분되지 않는 작은 도형을 과도하게 많이 만들지 않는다. 계산이 비싼 필드는 낮은 해상도 격자에서 구한 뒤 보간하거나, 화면 밖에 있는 요소의 계산과 그리기를 생략할 수 있다.

요소가 많아지면 데이터 갱신과 드로잉 호출을 분리하고, 매 프레임 불필요하게 바뀌지 않는 기하 구조를 미리 계산하는 것도 도움이 된다. 반복문 수를 줄이는 것만이 최적화는 아니다. 시각적으로 중요한 세부만 남기고, 작업의 해상도와 갱신 빈도를 조절하는 것이 제너레이티브 아트에서는 효과적인 성능 설계다. 픽셀마다 계산하는 패턴이나 GPU 셰이더가 더 적합한 경우는 이후의 픽셀·셰이더 절과 비교해 선택할 수 있다.

## 작업을 진행하는 순서

처음부터 복잡한 효과를 만들기보다, 작은 규칙을 단계적으로 쌓으면 원인을 추적하기 쉽다.

1. 반복문으로 고정 격자나 점열을 그려 좌표와 여백을 확인한다.
2. 수학 함수 하나를 위치, 크기, 색 가운데 한 속성에 연결한다.
3. 파라미터를 조정해 밀도와 형태가 어떻게 바뀌는지 살핀다.
4. 시간이나 입력을 하나씩 추가해 애니메이션과 조작을 만든다.
5. 필요하면 재현 가능한 랜덤값, 텍스처, 누적 렌더링을 결합한다.

한 번에 여러 규칙을 추가하면 결과가 예상과 다를 때 어느 요소가 원인인지 찾기 어렵다. 한 파라미터만 바꾸어 전후를 비교하고, 의미 있는 설정을 저장하면 작품의 형태를 의도적으로 다듬을 수 있다.

## 이 절의 핵심

raylib의 2D 제너레이티브 작업은 수학 규칙으로 위치와 모양을 계산하고, 도형·색 API로 결과를 그리는 구조다. 시간과 입력은 파라미터나 상태에 반영하고, 정적 랜덤 변형은 한 번 생성해 재사용하면 깜박임을 막고 재현성을 얻을 수 있다. 요소 수와 화면 비율, 프레임마다 지우거나 누적하는 방식을 함께 설계하면 작은 패턴에서 복잡한 인터랙티브 작품까지 확장할 수 있다.
