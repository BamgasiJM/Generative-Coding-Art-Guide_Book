# 21.2 C 기반 드로잉 API와 좌표계

raylib의 드로잉 함수는 좌표와 크기, 색을 인자로 받아 화면에 도형을 그린다. 수학식이 점의 위치를 계산한다면, 드로잉 API는 그 점을 선이나 원으로 표시한다. 이때 좌표의 원점이 어디인지, 각 함수의 좌표가 도형의 중심을 가리키는지 모서리를 가리키는지 알아야 계산 결과가 예상한 위치와 크기로 나타난다.

이 절에서는 카메라 변환을 적용하지 않은 기본 2D 화면 좌표를 기준으로 한다. 즉, 앞 절처럼 `BeginDrawing()`과 `EndDrawing()` 사이에서 직접 도형을 그리는 경우다. `Camera2D`를 적용해 좌표를 이동하거나 확대하는 방법은 21.3에서 다룬다.

## 기본 화면 좌표

raylib의 기본 화면 좌표에서 원점 `(0, 0)`은 창의 왼쪽 위다. x값은 오른쪽으로 갈수록 커지고 y값은 아래쪽으로 갈수록 커진다. 좌표값은 기본적으로 화면상의 픽셀 위치를 기준으로 하므로, 창 너비가 `640`이면 가로 방향의 화면 영역은 대략 `0`부터 `640`까지의 길이를 갖는다.

이는 수학 시간에 익힌 데카르트 좌표와 y축 방향이 반대다. 수학 좌표에서 양의 y방향은 위쪽이지만, 화면 좌표에서는 아래쪽이다. 그러므로 수학식의 결과를 그대로 화면의 y에 대입하면 위아래가 뒤집힌 모양으로 나타날 수 있다. 다만 이 차이는 좌표 변환식에서 부호 하나로 처리할 수 있다.

화면의 너비와 높이를 `W`, `H`라 하고 화면 중심을 기준으로 한 수학 좌표를 `(x_m, y_m)`이라고 하자. 수학 좌표의 원점은 화면 중심이며 양의 y방향은 위쪽이라고 정하면, 화면 좌표 `(x_s, y_s)`는 다음처럼 계산한다.

$$
x_s = \frac{W}{2} + x_m, \qquad
y_s = \frac{H}{2} - y_m
$$

가로 좌표에는 중심의 위치를 더하고, 세로 좌표에는 수학적 y값을 뺀다. 예를 들어 화면 중심에서 오른쪽으로 40, 위쪽으로 25만큼 떨어진 점은 `(W / 2 + 40, H / 2 - 25)`에 그린다. 화면 크기에서 중심을 계산할 때는 정수 나눗셈에 따른 소수부 손실을 피하고 싶다면 `W * 0.5f`처럼 실수 연산을 사용한다.

## 도형 함수가 받는 좌표

모든 도형 함수가 같은 기준점을 사용하는 것은 아니다. 선은 두 끝점으로 정해지고, 원은 중심점과 반지름으로 정해지며, 사각형은 기본적으로 왼쪽 위 모서리와 너비·높이로 정해진다. 함수 이름과 인자 순서를 확인하지 않고 숫자만 전달하면 도형이 반지름 대신 지름만큼 커지거나, 사각형의 중심 대신 모서리가 원하는 위치에 놓일 수 있다.

| 함수 | 위치와 크기의 의미 | 인자 형태 |
| --- | --- | --- |
| `DrawLine(x1, y1, x2, y2, color)` | 시작점과 끝점 | 좌표를 각각 전달 |
| `DrawLineV(start, end, color)` | 시작점과 끝점 | `Vector2` 두 개를 전달 |
| `DrawCircle(x, y, radius, color)` | 중심과 반지름 | 중심 좌표는 정수, 반지름은 실수 |
| `DrawCircleV(center, radius, color)` | 중심과 반지름 | 중심을 `Vector2`로 전달 |
| `DrawRectangle(x, y, width, height, color)` | 왼쪽 위 모서리와 너비·높이 | 정수 인자 |
| `DrawRectangleRec(rectangle, color)` | 사각형의 위치와 너비·높이 | `Rectangle` 하나를 전달 |

`DrawCircle()`의 `(x, y)`는 원의 중심이다. 반면 `DrawRectangle()`의 `(x, y)`는 사각형의 중심이 아니라 왼쪽 위 모서리다. 따라서 원과 사각형을 같은 점을 기준으로 나란히 놓고 싶다면 사각형 위치를 직접 조정하거나, 중심 기준으로 계산한 뒤 너비와 높이의 절반을 빼야 한다. 개체의 기준점을 통일해 계산하면 반복 배치와 회전 규칙을 설계하기 쉽다.

## C 자료형으로 좌표 묶기

좌표를 매번 x와 y 두 인자로 전달하는 대신 `Vector2` 자료형에 담을 수 있다. `Vector2`는 실수형 `x`, `y` 성분을 가진 구조체다. 사각형은 위치와 크기를 `Rectangle`에 담으며, 그 구조체의 필드는 `x`, `y`, `width`, `height`다. `Color`는 빨강·초록·파랑·알파 채널을 담는다. 이 구조체들을 사용하면 한 점이나 사각형을 여러 함수에 전달할 때 코드가 읽기 쉬워진다.

```c
Vector2 lineStart = { 60.0f, 80.0f };
Vector2 lineEnd = { 250.0f, 170.0f };
Vector2 circleCenter = { 430.0f, 120.0f };
Rectangle box = { 300.0f, 220.0f, 120.0f, 70.0f };

BeginDrawing();
ClearBackground(RAYWHITE);

DrawLineV(lineStart, lineEnd, DARKGRAY);
DrawCircleV(circleCenter, 32.0f, BLUE);
DrawRectangleRec(box, RED);

EndDrawing();
```

이 코드는 반복문의 그리기 구간에서 사용할 수 있는 호출 예다. `lineStart`와 `lineEnd`는 각각 선의 양 끝점이며, `circleCenter`는 원의 중심이다. `box`의 `x`, `y`는 사각형의 왼쪽 위 모서리이고 뒤의 두 값은 너비와 높이다. 각 그리기 함수에 색을 직접 전달하므로, 여기서는 앞서 설정한 채우기 색이 다음 도형에 남는다고 가정하지 않는다.

`Vector2`는 좌표 두 개를 묶어 주는 자료형이지, 그 자체로 벡터 계산을 자동 수행하는 연산자는 아니다. C에는 구조체에 대한 덧셈 연산자를 새로 정의하는 기능이 없으므로 좌표 계산은 각 성분에 대해 직접 하거나 raylib과 함께 제공되는 `raymath` 유틸리티를 활용한다. 예를 들어 위치에 이동량을 더한다면 x와 y를 각각 갱신한다. 수학적 벡터와 화면에 전달하는 좌표 자료형이 서로 관련은 있지만, 그 역할은 구분해야 한다.

## 정수 좌표와 실수 좌표

기본 도형 함수 중 일부는 좌표를 정수로 받으며, `Vector2`를 사용하는 변형 함수는 실수 좌표를 받을 수 있다. 예를 들어 `DrawLine()`은 정수형 시작점과 끝점을 받고, `DrawLineV()`는 실수 성분을 가진 `Vector2`를 받는다. 격자 칸이나 정수 픽셀을 정확히 가리킬 때에는 정수 좌표가 편리하다. 반면 애니메이션 중 위치를 조금씩 이동시키거나, 수식에서 계산한 소수 좌표를 유지하고 싶다면 실수 좌표를 사용하는 함수가 자연스럽다.

실수 좌표를 전달한다고 화면이 무한한 정밀도로 표시되는 것은 아니다. 최종 결과는 픽셀 격자에 그려지므로 렌더링 과정에서 화면의 픽셀로 표현된다. 하지만 계산 과정에서 소수부를 유지하면 프레임마다 위치가 정수 단위로만 뛰는 현상을 줄이고, 여러 프레임에 걸친 움직임을 더 세밀하게 표현할 수 있다. 단, 선이나 도형의 가장자리가 부드럽게 보이는지는 좌표의 실수 여부만이 아니라 그리기 방식과 안티앨리어싱 설정에도 영향을 받는다.

픽셀 배열을 직접 다룰 때는 또 다른 구분이 필요하다. 화면에 도형을 그리는 함수는 위치와 크기를 기하학적 좌표로 받지만, 픽셀 배열은 `(x, y)`를 배열의 정수 인덱스로 사용한다. 배열의 유효한 인덱스 범위는 보통 `0`부터 너비 또는 높이보다 1 작은 값까지다. 도형의 경계 좌표와 픽셀 배열 인덱스를 같은 규칙이라고 생각하지 않도록 주의한다. 픽셀 접근은 21.6에서 자세히 다룬다.

## 수학 좌표를 화면에 연결하기

극좌표로 계산한 점을 화면에 표시하는 경우를 생각해 보자. 수학적 각도 `theta`와 반지름 `r`에서 중심 기준 좌표는 `x_m = r cos(theta)`, `y_m = r sin(theta)`다. 화면의 y축은 아래를 향하므로, 화면 중심을 `(centerX, centerY)`라고 하면 다음처럼 변환한다.

$$
x_s = centerX + r\cos(\theta), \qquad
y_s = centerY - r\sin(\theta)
$$

이 식을 사용하면 수학 좌표계에서 반시계 방향으로 도는 점이 화면에서도 같은 방향으로 보인다. 반대로 화면 좌표에 `+ r sin(theta)`를 그대로 더하면 각도 증가 방향이 시계 방향으로 보인다. 어느 방식이 맞는지는 목적에 따라 다르지만, 점의 계산과 화면의 y축 규약이 서로 일치하도록 끝까지 유지해야 한다. C의 `sinf()`와 `cosf()`를 사용할 때 각도 인자는 라디안이라는 점도 기억한다.

중심 기준 좌표를 매번 화면 좌표로 바꾸는 것이 번거롭더라도, 수학 좌표계를 화면 전체에 무조건 적용할 필요는 없다. 계산은 중심 원점의 좌표로 유지하고, 화면에 그리기 직전에 변환할 수 있다. 이렇게 하면 수식은 익숙한 데카르트 좌표계에서 읽히고, raylib 호출에는 화면이 요구하는 좌표가 전달된다. 여러 개체를 공통으로 옮기거나 확대해야 한다면 카메라 변환을 고려할 수 있으며, 그 사용법은 다음 절에서 설명한다.

## 이 절의 핵심

raylib의 기본 2D 화면은 왼쪽 위가 원점이고 x축은 오른쪽, y축은 아래쪽으로 증가한다. 도형 함수마다 중심점과 모서리, 반지름과 너비·높이처럼 인자의 기준이 다르므로 API의 의미를 확인해야 한다. `Vector2`와 `Rectangle`은 좌표와 크기를 묶어 전달하는 C 구조체이며, 실수 좌표를 사용하면 계산의 소수부를 보존할 수 있다. 수학 좌표와 화면 좌표를 변환하는 규칙을 명시하면 극좌표나 벡터 계산을 raylib 화면에 일관되게 옮길 수 있다.
