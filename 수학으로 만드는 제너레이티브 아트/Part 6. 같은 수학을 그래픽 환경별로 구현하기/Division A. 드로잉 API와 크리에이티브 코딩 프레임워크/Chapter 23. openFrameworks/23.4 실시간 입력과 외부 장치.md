# 23.4 실시간 입력과 외부 장치

인터랙티브 작품은 화면 밖에서 들어오는 값을 화면 안의 규칙으로 연결한다. 키보드와 마우스는 관람객의 명령과 위치를 전달하고, 센서나 컨트롤러는 기울기·거리·압력 같은 물리적 값을 전달한다. openFrameworks에서는 `ofApp`의 입력 콜백으로 사건을 받고, 정리된 입력 상태를 `update()`에서 시뮬레이션이나 생성 규칙에 반영한 뒤, `draw()`에서 결과를 표현할 수 있다.

입력값이 곧바로 도형을 그리는 것은 아니다. 입력을 저장하고 해석해 작품의 파라미터나 상태로 바꾸는 단계가 필요하다.

```text
장치 입력 -> 읽기와 파싱 -> 보정·정규화·필터링 -> 작품 상태 갱신 -> 화면 표현
```

이 경계를 분명히 두면 마우스나 센서를 다른 장치로 바꾸더라도 시각 규칙을 다시 작성하지 않아도 된다.

## 사건과 유지 상태

키보드 입력에는 한 번의 사건과 누르고 있는 상태가 있다. `keyPressed(int key)`는 키를 누를 때 호출되고, `keyReleased(int key)`는 놓을 때 호출된다. 클릭 순간 한 번 실행할 동작은 누름 콜백에서 처리하고, 키를 누르는 동안 계속 이동하는 동작은 눌림 여부를 변수에 저장한 뒤 `update()`에서 처리한다.

마우스도 이동, 누름, 놓기, 드래그, 스크롤에 해당하는 콜백을 제공한다. 콜백은 대체로 창의 픽셀 좌표와 버튼 같은 사건 정보를 전달한다. `mousePressed(x, y, button)`에서 클릭 위치를 저장하거나, `mouseMoved(x, y)`에서 최신 포인터 위치를 기록할 수 있다. 창 크기가 바뀔 때는 `windowResized` 계열 콜백에서 캔버스 크기에 의존하는 상태를 조정할 수 있다.

아래 예제는 화살표 키를 누르고 있는 동안 원을 이동시키고, 마우스를 클릭하면 원을 클릭 위치로 옮긴다. 키 입력 콜백은 입력 상태만 기록하고, 실제 이동은 매 프레임 `update()`에서 수행한다.

```cpp
// ofApp.h
#include "ofMain.h"

class ofApp : public ofBaseApp {
public:
    void setup() override;
    void update() override;
    void draw() override;
    void keyPressed(int key) override;
    void keyReleased(int key) override;
    void mousePressed(int x, int y, int button) override;

private:
    glm::vec2 marker {0.0f, 0.0f};
    bool leftDown = false;
    bool rightDown = false;
    bool upDown = false;
    bool downDown = false;
    float markerRadius = 16.0f;
};
```

```cpp
// ofApp.cpp
#include "ofApp.h"

void ofApp::setup() {
    marker = glm::vec2(ofGetWidth() * 0.5f,
                       ofGetHeight() * 0.5f);
}

void ofApp::keyPressed(int key) {
    if (key == OF_KEY_LEFT) leftDown = true;
    if (key == OF_KEY_RIGHT) rightDown = true;
    if (key == OF_KEY_UP) upDown = true;
    if (key == OF_KEY_DOWN) downDown = true;
    if (key == 'r') {
        marker = glm::vec2(ofGetWidth() * 0.5f,
                           ofGetHeight() * 0.5f);
    }
}

void ofApp::keyReleased(int key) {
    if (key == OF_KEY_LEFT) leftDown = false;
    if (key == OF_KEY_RIGHT) rightDown = false;
    if (key == OF_KEY_UP) upDown = false;
    if (key == OF_KEY_DOWN) downDown = false;
}

void ofApp::mousePressed(int x, int y, int) {
    marker = glm::vec2(static_cast<float>(x),
                       static_cast<float>(y));
}

void ofApp::update() {
    glm::vec2 direction(
        static_cast<float>(rightDown) - static_cast<float>(leftDown),
        static_cast<float>(downDown) - static_cast<float>(upDown));

    const float length = glm::length(direction);
    if (length > 0.0f) {
        direction /= length;
        const float dt = ofClamp(ofGetLastFrameTime(), 0.0f, 0.05f);
        marker += direction * 220.0f * dt;
    }

    marker.x = ofClamp(marker.x, markerRadius,
                       ofGetWidth() - markerRadius);
    marker.y = ofClamp(marker.y, markerRadius,
                       ofGetHeight() - markerRadius);
}

void ofApp::draw() {
    ofBackground(248);
    ofSetColor(40, 120, 170);
    ofDrawCircle(marker.x, marker.y, markerRadius);
}
```

화살표 키를 눌렀을 때마다 위치를 직접 바꾸는 대신 눌림 상태를 기록하면, 키를 계속 누르는 동안 부드럽게 움직일 수 있다. 반대 방향 키를 동시에 누르면 두 입력이 상쇄된다. 대각선 방향은 벡터의 길이가 더 커지므로 `glm::length()`와 나눗셈으로 방향을 정규화했다. 이동에는 `dt`를 곱해 프레임률에 따라 이동 속도가 달라지는 문제를 줄인다. `r` 키는 누르는 사건에 반응해 위치를 초기화하는 예다.

이벤트 입력과 프레임별 상태 확인은 서로 다른 도구다. 키를 눌렀다 놓은 전환을 알고 싶다면 이벤트 콜백이 적합하고, 현재 포인터 위치나 키가 눌려 있는 동안의 지속적인 효과는 `update()`에서 읽고 계산하기 좋다. 둘을 조합하면 입력 콜백은 사실을 기록하고 업데이트는 그 사실을 시간에 따라 처리한다.

## 화면 좌표를 작품 파라미터로 바꾸기

입력 장치의 값은 작품의 좌표계나 파라미터 범위와 다를 수 있다. 예를 들어 마우스 x좌표를 창 너비로 나누면 창 크기에 덜 의존하는 0에서 1 사이 값으로 만들 수 있다.

```cpp
const float normalizedX = ofGetWidth() > 0
    ? static_cast<float>(ofGetMouseX()) / ofGetWidth()
    : 0.0f;
```

이 값에 파라미터 범위를 적용하면 포인터의 가로 위치를 반지름, 주파수, 색상 단계 등으로 바꿀 수 있다.

$$
u = \operatorname{clamp}\left(\frac{x}{W}, 0, 1\right),\qquad
p = p_{min} + u(p_{max} - p_{min})
$$

창 너비가 0인 경우를 먼저 확인하는 이유는 0으로 나누는 것을 막기 위해서다. 해상도가 바뀌어도 같은 의미를 유지하려면 픽셀 좌표보다 정규화 좌표를 저장하는 편이 나을 수 있다. 반대로 화면의 특정 픽셀에 직접 반응해야 하는 브러시나 커서에는 픽셀 좌표가 자연스럽다. 입력을 어떤 단위로 보관할지는 작품에서 그 값이 맡을 역할에 따라 정한다.

## 센서와 외부 장치

openFrameworks는 주변 장치와 연결할 수 있고, 기본 기능이나 애드온을 통해 시리얼 장치, MIDI 컨트롤러, OSC 네트워크 메시지 같은 입력을 받을 수 있다. 마이크나 카메라처럼 이미지·영상·사운드가 주요 데이터인 경우는 다음 절에서 다룬다. 이 절에서는 버튼, 노브, 거리 센서, 가속도계처럼 제어값을 보내는 장치에 초점을 둔다.

외부 센서의 값은 대개 작품이 바로 사용할 수 있는 형태가 아니다. 예를 들어 센서가 0부터 1023 사이의 원시값을 보내고, 작품은 0부터 1 사이의 힘을 필요로 한다면 범위를 보정하고 제한해야 한다.

```cpp
float normalizeSensor(float raw, float inputMin, float inputMax) {
    if (inputMax <= inputMin) return 0.0f;

    const float value = (raw - inputMin) / (inputMax - inputMin);
    return ofClamp(value, 0.0f, 1.0f);
}
```

`inputMin`과 `inputMax`는 장치의 이론상 범위와 실제 설치 환경에서 측정한 범위가 다를 수 있으므로 보정(calibration) 과정에서 조정한다. 정규화된 값을 색상, 속도, 입자 방출률 등 작품의 파라미터 범위에 다시 매핑할 수 있다.

센서는 전기적 잡음이나 환경 변화 때문에 값이 흔들린다. 간단한 지수 이동 평균으로 입력을 부드럽게 만들 수 있다.

```cpp
filteredValue += response * (normalizedValue - filteredValue);
```

`response`가 작으면 변화가 부드러워지지만 반응이 늦고, 크면 입력을 빠르게 따라가지만 잡음도 더 많이 보인다. 값이 특정 임계값을 넘을 때 이벤트를 발생시키는 센서라면, 켜지는 기준과 꺼지는 기준을 조금 다르게 두는 히스테리시스(hysteresis)가 경계에서의 반복적인 켜짐·꺼짐을 줄인다.

## 시리얼 데이터는 메시지 단위로 읽기

마이크로컨트롤러에서 시리얼(serial)로 데이터를 받을 때는 전송한 한 줄이 한 번의 읽기 호출과 정확히 일치한다고 가정하지 않는다. 시리얼은 바이트 스트림이므로 한 번 읽기에 메시지 일부만 도착할 수 있고, 여러 메시지가 한 번에 들어올 수도 있다. 예를 들어 장치가 `0.24,0.81\n` 형식으로 값을 보낸다면 줄바꿈까지 바이트를 모은 뒤 한 레코드로 파싱하는 식으로 메시지 경계를 정한다.

```text
사용 가능한 바이트를 버퍼에 추가
완전한 구분자(예: 줄바꿈)가 있는지 확인
완성된 메시지만 파싱
필드 수와 숫자 범위를 검증
유효한 값만 최신 입력 상태에 반영
```

장치가 보낸 문자열이 잘못되었거나 값의 범위를 벗어날 수 있으므로 파싱 결과와 필드 개수를 확인한다. `update()` 안에서 데이터가 올 때까지 막힌 채 기다리면 화면 프레임도 멈출 수 있다. 사용 가능한 데이터만 읽고, 완전한 메시지가 없으면 마지막으로 유효했던 값을 유지하는 방식이 실시간 화면에 더 적합하다. 실제 포트 선택, 연결, 읽기 함수는 사용하는 openFrameworks 버전과 시리얼 애드온, 운영체제에 따라 달라질 수 있으므로 해당 장치의 API와 프로토콜을 함께 확인한다.

장치 연결이 끊겼을 때의 동작도 설계한다. 마지막 값을 계속 유지할지, 입력을 중립값으로 되돌릴지, 연결 상태를 화면에 알릴지를 결정한다. 보정 범위, 필터 응답, 장치가 보내는 단위와 샘플 주기를 기록하면 설치 환경에서 반응을 조정하기 쉽다.

## 입력은 업데이트를 거쳐 시각 규칙이 된다

외부 입력이 들어오는 빈도와 화면 프레임률은 서로 다를 수 있다. 키보드는 사건 단위로 바뀌고, 센서는 일정한 주기로 값을 보내며, `draw()`는 화면 갱신에 맞춰 호출된다. 장치 콜백이나 읽기 코드에서 드로잉을 직접 수행하기보다, 입력값을 짧게 저장하고 `update()`에서 작품 상태로 반영한 뒤 `draw()`가 그 상태를 표현하도록 한다. 스레드를 사용하는 장치 애드온이라면 입력 데이터를 메인 애플리케이션 루프에 안전하게 전달해야 한다.

이 구조에서는 입력 장치와 생성 규칙이 느슨하게 연결된다. 마우스 대신 노브가 들어와도 같은 0에서 1 사이 파라미터를 만들면 기존의 크기·색상 규칙을 그대로 사용할 수 있다. 중요한 것은 어느 장치를 사용하느냐보다 원시 입력을 작품의 수학적 의미로 어떻게 변환하느냐이다.

## 이 절의 핵심

openFrameworks의 입력 콜백은 키·마우스 사건을 전달하고, 유지 상태와 연속 입력은 `update()`에서 시간에 따라 처리할 수 있다. 외부 장치의 데이터는 메시지 경계, 파싱, 범위 보정, 필터링을 거쳐 작품 파라미터로 변환한다. 입력을 드로잉 코드와 분리하면 장치와 시각 규칙을 독립적으로 바꾸고, 프레임 흐름을 안정적으로 유지할 수 있다.
