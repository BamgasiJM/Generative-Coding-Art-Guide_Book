# 23.6 파티클과 시뮬레이션

파티클 시스템(particle system)은 같은 운동 규칙을 공유하는 여러 입자를 생성하고, 시간에 따라 갱신하고, 화면에 표현하는 구조다. 입자 하나는 위치·속도·가속도·나이·수명 같은 상태를 갖고, 시스템은 입자 목록과 중력·방출률·최대 개수 같은 공통 규칙을 관리한다. openFrameworks에서는 입자 데이터를 C++ 구조체로 정의하고 `std::vector`에 모은 뒤, `update()`에서 상태를 갱신하고 `draw()`에서 표현할 수 있다.

```text
시스템 설정과 emitter
        ↓ 입자 생성
입자 상태 갱신 -> 수명 확인과 만료 제거 -> 현재 입자 그리기
        ↑______________________________________________|
```

## 입자 자료 구조

입자마다 필요한 값을 구조체로 모으면 각 요소가 어떤 상태를 갖는지 분명해진다. 다음 구조체는 2D 위치와 속도, 가속도, 질량, 나이와 수명, 화면에 사용할 반지름을 가진다.

```cpp
#include "ofMain.h"

struct Particle {
    glm::vec2 position {0.0f, 0.0f};
    glm::vec2 velocity {0.0f, 0.0f};
    glm::vec2 acceleration {0.0f, 0.0f};
    float mass = 1.0f;
    float age = 0.0f;
    float lifetime = 2.0f;
    float radius = 4.0f;

    void applyForce(const glm::vec2& force) {
        if (mass > 0.0f) {
            acceleration += force / mass;
        }
    }

    void integrate(float dt) {
        velocity += acceleration * dt;
        position += velocity * dt;
        age += dt;
        acceleration = glm::vec2(0.0f, 0.0f);
    }

    bool isAlive() const {
        return age < lifetime;
    }
};
```

`position`은 픽셀 좌표, `velocity`는 초당 픽셀, `acceleration`은 초당 픽셀의 제곱 단위로 해석할 수 있다. `applyForce()`는 힘을 질량으로 나눠 가속도에 더한다. 반면 중력은 모든 입자에 공통으로 적용하는 가속도라고 모델링할 수 있어, 시스템에서 입자의 `acceleration`에 직접 더할 수 있다. 힘을 매 프레임 다시 계산해야 하는 이유는 이전 프레임의 합력이 계속 누적되는 일을 막기 위해서다. `integrate()`는 그 프레임의 가속도를 속도와 위치에 반영한 뒤 임시 가속도를 0으로 되돌린다.

위치 갱신에는 먼저 속도를 바꾸고, 바뀐 속도를 이용해 위치를 바꾸는 순서를 사용했다. 각 단계에 `dt`를 곱하므로 프레임률이 달라져도 초 단위로 정의한 운동을 유지하기 쉽다. 시간 간격이 너무 크면 한 번의 업데이트에서 입자가 크게 움직일 수 있으므로, `dt`의 상한이나 23.2에서 다룬 고정 시간 단계가 필요할 수 있다.

## 시스템과 emitter

입자 하나가 자신의 운동과 생애를 관리한다면, 시스템은 입자들을 모아 공통 규칙을 적용한다. 다음 멤버들은 입자 목록, 방출 위치, 초당 방출 수, 분수 입자를 보관할 누적기, 최대 입자 수를 나타낸다.

```cpp
#include <algorithm>
#include <vector>

class ofApp : public ofBaseApp {
public:
    void setup() override;
    void update() override;
    void draw() override;

private:
    void emitParticle();

    std::vector<Particle> particles;
    glm::vec2 emitterPosition {0.0f, 0.0f};
    float emissionRate = 45.0f;
    float spawnAccumulator = 0.0f;
    std::size_t maxParticles = 1000;
};
```

emitter는 입자의 출발 위치와 초기 조건을 제공한다. 아래에서는 화면 위쪽의 한 지점에서 입자를 만들고, 초기 속도와 수명, 반지름을 범위 안에서 선택한다. `ofRandom(min, max)`는 지정한 범위의 난수 값을 얻는 openFrameworks 함수다.

```cpp
void ofApp::setup() {
    emitterPosition = glm::vec2(ofGetWidth() * 0.5f, 50.0f);
    particles.reserve(maxParticles);
}

void ofApp::emitParticle() {
    Particle particle;
    particle.position = emitterPosition;
    particle.velocity = glm::vec2(ofRandom(-35.0f, 35.0f),
                                  ofRandom(-125.0f, -65.0f));
    particle.lifetime = ofRandom(1.2f, 2.4f);
    particle.radius = ofRandom(2.0f, 5.0f);
    particles.push_back(particle);
}
```

매 프레임 한 개씩 생성하면 방출 속도가 프레임률에 종속된다. 초당 방출률을 지키려면 `emissionRate * dt`를 누적하고 정수 부분만큼 입자를 생성한다. 예를 들어 초당 45개를 60 FPS로 실행하면 프레임당 평균 0.75개에 해당한다. 누적기를 쓰면 매 프레임 생성할 개수의 소수 부분을 다음 프레임으로 넘길 수 있다.

## 갱신과 만료 처리

다음 `update()`는 시간 간격에 맞춰 생성하고, 모든 입자에 중력과 바람을 적용한 뒤, 수명이 끝난 입자를 목록에서 제거한다.

```cpp
void ofApp::update() {
    const float dt = ofClamp(ofGetLastFrameTime(), 0.0f, 0.05f);

    spawnAccumulator += emissionRate * dt;
    while (spawnAccumulator >= 1.0f) {
        if (particles.size() < maxParticles) {
            emitParticle();
        }
        spawnAccumulator -= 1.0f;
    }

    const glm::vec2 gravity(0.0f, 90.0f);
    const glm::vec2 wind(18.0f, 0.0f);

    for (Particle& particle : particles) {
        particle.acceleration += gravity;
        particle.applyForce(wind);
        particle.integrate(dt);
    }

    particles.erase(
        std::remove_if(particles.begin(), particles.end(),
                       [](const Particle& particle) {
                           return !particle.isAlive();
                       }),
        particles.end());
}
```

화면 좌표에서 아래쪽이 양의 y방향이므로 예제의 중력 `(0, 90)`은 입자를 아래로 가속한다. 바람은 질량으로 나누는 실제 힘의 예이며, 질량이 클수록 같은 바람에 덜 가속된다. 최대 입자 수에 도달하면 방출 시각은 계속 소비하되 새 입자를 추가하지 않는다. 무제한 방출로 메모리와 그리기 비용이 계속 커지는 일을 막는 간단한 정책이다.

`std::remove_if`와 `erase`를 함께 쓰는 방식은 조건에 맞는 요소를 벡터 끝으로 모은 다음 그 구간을 제거한다. 이 과정에서 남은 요소가 이동할 수 있으므로, 범위 기반 `for` 반복 도중 같은 벡터에서 요소를 삭제하거나 `push_back()`하지 않는다. 벡터가 재할당되면 반복 중인 참조가 무효가 될 수도 있기 때문이다. 예제는 반복이 끝난 뒤 만료된 요소를 한 번에 정리한다.

## 상태를 시각화하기

그리기 단계는 현재 입자 상태를 읽어 도형으로 표현한다. 수명 진행도를 0에서 1 사이로 정규화하면 반지름이나 투명도를 생애에 따라 바꿀 수 있다.

```cpp
void ofApp::draw() {
    ofBackground(248);

    for (const Particle& particle : particles) {
        const float life = ofClamp(particle.age / particle.lifetime,
                                   0.0f, 1.0f);
        const float radius = particle.radius * (1.0f - life);
        const int alpha = static_cast<int>(255.0f * (1.0f - life));

        ofSetColor(45, 125, 170, alpha);
        ofDrawCircle(particle.position.x,
                     particle.position.y,
                     radius);
    }
}
```

입자의 생애가 진행될수록 원이 작아지고 투명해진다. `draw()`는 입자의 위치나 나이를 수정하지 않고, 현재 상태를 화면으로 옮긴다. `ofBackground()`를 매 프레임 호출하므로 이전 프레임은 지워진다. 움직이는 입자 궤적을 남기려면 배경을 지우는 방식을 바꾸거나 별도의 렌더 타깃에 흔적을 누적한다.

## 입자 수와 계산 비용

입자마다 독립적으로 위치를 갱신하고 그리는 기본 시스템의 비용은 입자 수에 비례한다. 입자 수가 `N`이면 보통 한 프레임에 `N`번 갱신하고 `N`번 그린다. 입자끼리 모두 서로의 거리를 확인하거나 힘을 계산하면 쌍마다 비교가 필요해 비용이 대략 `N²`에 비례할 수 있다. 근처 입자만 찾도록 공간을 셀이나 격자로 나누는 방법은 17.6의 근접 이웃 탐색과 연결된다.

`std::vector`는 입자를 연속된 메모리에 저장해 순회하기 좋다. `reserve()`는 예상 용량을 미리 확보해 반복적인 재할당을 줄인다. 다만 벡터 중간에서 입자를 많이 지우면 뒤의 요소들이 이동할 수 있다. 규모가 작고 단순한 시스템에는 erase-remove 방식이 명료하고, 생성·소멸이 매우 잦거나 개수가 큰 시스템에는 비활성 슬롯을 재사용하는 객체 풀(object pool)을 고려할 수 있다. 풀을 사용한다면 재사용할 때 나이, 위치, 속도, 수명, 표시 속성을 모두 초기화해야 한다.

각 입자의 점과 원을 CPU에서 개별 호출로 그리는 방식은 구현이 간단하다. 수만 개 이상을 표현하거나 입자마다 같은 셰이딩 규칙을 적용해야 할 때는 배치 드로잉이나 GPU 렌더링이 더 효율적일 수 있다. 시뮬레이션 계산과 렌더링은 별개의 비용이므로, 어느 쪽이 병목인지 측정하고 그에 맞게 최적화한다.

## 이 절의 핵심

입자 구조체는 개별 운동과 생애 상태를 보관하고, 시스템은 입자 목록·방출·공통 힘·최대 개수를 관리한다. `update()`에서 초당 방출률을 누적해 입자를 만들고 `dt`에 따라 갱신한 뒤 만료 요소를 제거하며, `draw()`는 현재 상태를 표현한다. 입자 수가 커질수록 컨테이너 관리와 상호작용 계산, 그리기 호출의 비용을 함께 고려해야 한다.
