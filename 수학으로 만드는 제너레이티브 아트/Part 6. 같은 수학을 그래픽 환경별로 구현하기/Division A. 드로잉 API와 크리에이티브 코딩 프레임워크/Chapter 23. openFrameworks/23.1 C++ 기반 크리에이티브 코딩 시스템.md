# 23.1 C++ 기반 크리에이티브 코딩 시스템

openFrameworks는 C++로 그래픽, 인터랙션, 미디어 작업을 만들 수 있도록 여러 기능을 묶어 제공하는 오픈소스 툴킷이다. 점과 도형을 그리는 함수뿐 아니라 창과 이벤트 처리, 이미지·영상·사운드 입출력, 셰이더와 같은 기능을 하나의 애플리케이션 구조 안에서 사용할 수 있다. 수학 규칙으로 형태를 만들고, 카메라·센서·영상 같은 실시간 입력과 결합하는 제너레이티브 아트에 적합한 환경이다.

openFrameworks는 C++ 언어 자체가 아니며, 작품을 시각적으로 편집하는 프로그램도 아니다. C++로 작성한 소스 코드를 컴파일해 데스크톱 애플리케이션을 만든다. 프레임워크는 창을 열고 이벤트를 전달하며 그래픽 기능을 초기화하는 반복 구조를 마련하고, 작가는 그 구조 안에 작품의 규칙을 작성한다. 수학적 규칙과 화면 표현은 여전히 프로그램에서 직접 설계해야 한다.

## 언어와 프레임워크의 역할

C++는 숫자와 벡터를 계산하고, 자료 구조와 함수를 정의하며, 프로그램의 실행 흐름을 표현하는 프로그래밍 언어다. 컴파일러는 C++ 소스 코드를 기계가 실행할 수 있는 프로그램으로 변환한다. openFrameworks는 그 언어로 그래픽과 멀티미디어 애플리케이션을 만들 때 필요한 기능과 기본 구조를 제공한다.

따라서 `ofDrawCircle()` 같은 API는 C++ 문법이 아니라 openFrameworks가 제공하는 함수다. 반면 변수 선언, 함수, 클래스, `std::vector` 같은 표준 라이브러리 자료 구조는 C++의 기능이다. 두 층을 구분하면 문제가 생겼을 때 어느 부분을 살펴야 할지 명확해진다. 좌표 계산이 잘못되었다면 수학과 C++ 코드를, 창이나 입력·그리기 동작이 잘못되었다면 openFrameworks API와 애플리케이션 구조를 점검할 수 있다.

openFrameworks는 `ofMain.h`를 통해 자주 쓰는 API와 타입을 제공하며, 프로젝트에는 `ofApp`이라는 애플리케이션 클래스를 두는 방식이 널리 사용된다. 이 클래스는 기본 애플리케이션 타입인 `ofBaseApp`을 상속하고, 프레임워크가 호출할 함수들을 구현한다. 프로젝트는 여러 소스 파일과 설정, 라이브러리로 구성되며, 운영체제와 개발 도구에 맞춰 컴파일하고 링크한다.

## 최소 애플리케이션의 구성

다음 예는 앱 진입점에서 그래픽 창을 준비하고 `ofApp`을 실행하는 전형적인 구조다. `std::make_shared`는 현대 C++의 공유 포인터를 만들어 앱 객체의 수명을 관리한다.

```cpp
// src/main.cpp
#include "ofMain.h"
#include "ofApp.h"
#include <memory>

int main() {
    ofSetupOpenGL(800, 600, OF_WINDOW);
    ofRunApp(std::make_shared<ofApp>());
}
```

작품의 기본 동작은 보통 `ofApp`에 작성한다.

```cpp
// src/ofApp.h
#pragma once

#include "ofMain.h"

class ofApp : public ofBaseApp {
public:
    void setup() override;
    void update() override;
    void draw() override;
};
```

```cpp
// src/ofApp.cpp
#include "ofApp.h"

void ofApp::setup() {
    ofSetFrameRate(60);
}

void ofApp::update() {
}

void ofApp::draw() {
    ofBackground(248);
    ofSetColor(40, 120, 170);
    ofDrawCircle(ofGetWidth() * 0.5f,
                 ofGetHeight() * 0.5f,
                 36.0f);
}
```

헤더 파일(`ofApp.h`)에는 클래스와 함수의 형태를 선언하고, 구현 파일(`ofApp.cpp`)에는 각 함수의 동작을 작성한다. `setup()`은 초기 설정, `update()`는 작품 상태의 계산, `draw()`는 화면 표현을 맡는다. `main()`에서 애플리케이션을 시작하면 openFrameworks가 창과 이벤트 흐름을 준비하고 이 함수들을 적절한 시점에 호출한다. 반복 루프와 `update`·`draw`의 정확한 역할은 23.2에서 자세히 살펴본다.

`ofBackground()`는 프레임의 바탕색을 정하고, `ofSetColor()`는 이후 드로잉 호출의 색을 지정한다. `ofGetWidth()`와 `ofGetHeight()`는 현재 창 크기를 읽으므로, 원의 중심을 창 크기에서 계산할 수 있다. `ofDrawCircle()`은 그 좌표와 반지름에 원을 그린다. 이 작은 예제에서도 C++ 코드가 수학적인 좌표 계산과 화면 API를 연결하는 방식을 볼 수 있다.

## 컴파일과 작업 흐름

브라우저에서 스크립트를 실행하는 방식과 달리, openFrameworks 프로젝트는 C++ 소스 파일을 컴파일하고 필요한 라이브러리와 링크해 실행 파일을 만든다. 프로젝트 생성 도구나 제공된 프로젝트 템플릿은 플랫폼별 빌드 설정과 기본 소스 구조를 준비하는 데 도움을 준다. 개발자는 보통 C++ 파일을 수정하고, 프로젝트를 다시 빌드한 뒤 실행 결과를 확인한다. 이 과정은 텍스트 한 줄을 평가해 바로 반영하는 REPL 기반 작업과 다르며, 코드 수정이 실행 중인 프로그램에 자동 적용된다고 가정해서는 안 된다.

컴파일 과정은 변수 타입 오류나 선언 누락 같은 문제를 실행 전에 발견하는 데 도움을 준다. 반면 프로젝트 설정, 컴파일러, 라이브러리 연결이 필요하므로 처음 환경을 준비하는 부담은 브라우저 기반 스케치보다 클 수 있다. 프레임워크가 창과 이벤트 반복을 제공하더라도 C++ 프로그램의 구조와 빌드 과정을 이해해야 한다.

이 구조는 작업 규모가 커질 때 장점도 갖는다. 기하 계산을 일반 C++ 함수로 작성하고, 점이나 입자를 `std::vector` 같은 자료 구조에 저장하며, 화면 출력은 openFrameworks의 드로잉 API에 맡길 수 있다. 렌더링과 계산을 나누면 동일한 수학 규칙을 다른 출력 방식에 적용하기 쉬워진다. 필요에 따라 애드온(addon)을 연결해 영상 처리나 통신 같은 기능을 확장할 수도 있다. 애드온은 프레임워크가 제공하는 기능을 보완하는 라이브러리이므로, 프로젝트의 플랫폼과 버전 호환성을 함께 고려해야 한다.

## 다른 크리에이티브 코딩 환경과 비교하기

p5.js는 브라우저에서 빠르게 실행하고 공유하기 좋은 JavaScript 스케치 환경이고, Quil은 Clojure의 함수와 값 중심 구조로 Processing 계열의 그래픽을 다룬다. raylib은 C/C++ 애플리케이션에서 창과 반복을 비교적 직접 구성하는 라이브러리다. openFrameworks도 C++로 네이티브 프로그램을 만들지만, `ofApp` 구조와 그래픽·입력·미디어 기능을 함께 제공해 더 큰 설치형·실시간 프로젝트로 확장하기 편리하다.

이 차이는 특정 도구의 우열이라기보다 작업에서 중요하게 여기는 조건의 차이다. 빠른 웹 공유와 간단한 스케치가 중심이면 p5.js가 편리할 수 있고, C++의 실행 구조를 직접 다루려면 raylib이 잘 맞을 수 있다. 카메라나 영상, 사운드, 센서 같은 여러 입력을 하나의 애플리케이션에 통합하고 플랫폼별 네이티브 실행물을 만들고 싶다면 openFrameworks의 기능 구성이 도움이 된다. 프로젝트의 배포 대상, 주변 장치, 팀의 언어 경험에 따라 선택한다.

## 이 장에서 살펴볼 내용

이 장에서는 우선 `update()`와 `draw()`가 프레임마다 어떻게 협력하는지 살펴본다. 이어 `glm` 기반 벡터와 좌표 변환, 도형 API를 이용해 기하 규칙을 화면으로 옮긴다. 이후 마우스·키보드·센서 같은 실시간 입력, 이미지·영상·사운드 데이터, 파티클 시뮬레이션으로 확장한다. 마지막에는 GPU 셰이더와 CPU 드로잉의 역할을 비교하고, 인터랙티브 설치와 배포를 고려한다.

## 이 절의 핵심

openFrameworks는 C++로 그래픽과 미디어 애플리케이션을 만들기 위한 오픈소스 툴킷이다. `ofApp`의 `setup`, `update`, `draw`와 앱 진입점을 통해 창과 프레임 흐름을 구성하며, 컴파일과 빌드 과정을 거쳐 네이티브 프로그램으로 실행한다. 수학 규칙은 C++로 작성하고 openFrameworks API는 입력과 그래픽 표현을 맡는다는 역할 구분이 이 장의 출발점이다.
