# 25.7 시간, 입력 이벤트, 애니메이션

25.3에서는 `extend`가 프레임마다 실행되고, 프로그램 상태를 그 바깥에 두어 유지할 수 있음을 살펴보았다. 이번 절에서는 OPENRNDR이 제공하는 경과 시간과 입력 상태를 이용해 그 상태를 시각적 변화로 연결한다. 예제는 OPENRNDR 0.5.0과 Kotlin 2.4.20을 기준으로 한다.

## 시간으로 움직임 정의하기

애니메이션은 시간에 따라 변하는 값을 계산하는 과정이다. `extend` 안의 `seconds`는 프로그램이 시작된 뒤 흐른 시간을 초 단위로 나타낸다. 이 값을 삼각 함수의 입력에 넣으면 프레임마다 일정량을 더하는 대신, 특정 시각의 위치나 크기를 직접 구할 수 있다.

원 궤도를 도는 점은 다음처럼 쓸 수 있다.

$$
\theta(t)=\omega t+\phi,\qquad
x(t)=c_x+r_x\cos\theta(t),\qquad
y(t)=c_y+r_y\sin\theta(t)
$$

$\omega$는 초당 각도 변화량이고 $\phi$는 시작 위상이다. 원형 궤도라면 $r_x$와 $r_y$가 같고, 서로 다르면 타원 궤도가 된다. 각진동수 $\omega=2\pi f$로 두면 초당 $f$회 반복한다. Kotlin의 `sin()`과 `cos()`에는 라디안이 들어가므로 각도 단위를 섞지 않도록 한다. 화면 좌표에서 y축은 아래쪽으로 증가한다는 점도 회전 방향을 해석할 때 고려한다.

`seconds`를 이용한 계산은 프레임률이 조금 달라져도 같은 시각에 같은 위치를 만든다. 반면 `phase += 0.02`처럼 프레임마다 고정량을 더하면 초당 프레임 수가 바뀔 때 움직임의 속도도 달라진다. 반복되는 파형, 궤도, 맥동처럼 시각만으로 상태를 정할 수 있는 애니메이션에는 시간 함수가 간결하고 안정적이다.

## 시간과 입력을 결합한 스케치

아래에서는 원이 시간에 따라 타원 궤도를 돌고 크기가 맥동한다. 마우스 위치에는 작은 표식을 그리고, 키보드 입력이 들어오면 궤도의 위상을 바꾼다.

```kotlin
import kotlin.math.PI
import kotlin.math.cos
import kotlin.math.sin
import org.openrndr.application
import org.openrndr.color.ColorRGBa
import org.openrndr.math.Vector2

fun main() = application {
    configure {
        width = 800
        height = 600
    }

    program {
        var phaseOffset = 0.0

        keyboard.keyDown.listen { _ ->
            phaseOffset += PI / 4.0
        }

        extend {
            val t = seconds
            val phase = 2.0 * PI * 0.12 * t + phaseOffset
            val pulse = 0.5 + 0.5 * sin(2.0 * PI * 0.7 * t)
            val center = Vector2(
                width / 2.0 + cos(phase) * 180.0,
                height / 2.0 + sin(phase) * 100.0
            )
            val radius = 12.0 + 22.0 * pulse

            drawer.clear(ColorRGBa.fromHex("#101820"))
            drawer.fill = ColorRGBa.fromHex("#F4B860")
            drawer.stroke = null
            drawer.circle(center, radius)

            drawer.fill = ColorRGBa.CYAN
            drawer.circle(mouse.position, 8.0)
        }
    }
}
```

위상은 프로그램 실행 중 유지되는 `var`이고, 키보드의 `keyDown` 이벤트가 발생할 때마다 45도만큼 증가한다. 이벤트 리스너는 `program` 안에서 한 번 등록한다. 이를 `extend` 안에 두면 프레임마다 리스너가 추가되어 키 입력 한 번에 콜백이 여러 번 실행될 수 있다. 이벤트 콜백에서는 위상처럼 상태를 갱신하고, 실제 화면 표현은 프레임마다 호출되는 `extend`에서 수행한다.

## 상태 조회와 이벤트 구분하기

입력을 다루는 방법은 현재 상태를 읽는 것과 변화가 발생한 순간을 받는 것으로 나뉜다.

| 방식 | 의미 | 예시 |
| --- | --- | --- |
| 상태 조회 | 지금 입력 장치가 어떤 상태인지 확인 | `mouse.position`, `keyboard.pressedKeys` |
| 이벤트 리스너 | 입력이 발생한 순간에 콜백 실행 | `keyboard.keyDown.listen { ... }`, `mouse.buttonDown.listen { ... }` |

마우스 포인터처럼 계속 변하는 위치는 `mouse.position`을 프레임마다 읽으면 현재 위치를 얻는다. 키를 누르고 있는 동안 계속 움직이게 할 때는 `keyboard.pressedKeys`에서 해당 키가 눌려 있는지 매 프레임 확인하는 방식이 맞다. 반대로 키를 누르는 순간 색을 바꾸거나 위상을 한 번 이동시키는 동작은 `keyDown` 이벤트에 연결한다.

이벤트는 누르고 있는 상태와 같지 않다. 키를 한 번 눌렀다가 계속 누르는 동안 상태 조회는 여러 프레임에 걸쳐 참일 수 있지만, 이벤트 리스너는 입력 변화에 반응한다. 운영체제의 키 반복 설정에 따라 키를 길게 누를 때 추가 `keyDown` 이벤트가 올 수 있으므로, 토글처럼 한 번만 실행되어야 하는 동작은 반복 입력도 고려한다. 홀드 동작과 명령 입력을 구별하면 가속이나 토글이 의도치 않게 반복되는 일을 줄일 수 있다.

## 프레임률과 상태 갱신

`seconds`를 수식에 직접 넣는 애니메이션은 프레임을 건너뛰어도 현재 시각의 값을 다시 계산한다. 그러나 속도나 가속도를 누적해 시뮬레이션 상태를 갱신하는 경우에는 프레임마다 같은 양을 더하지 말고, 이전 갱신 이후 실제로 흐른 시간 $\Delta t$를 사용한다.

$$
\mathbf{p}_{n+1}=\mathbf{p}_n+\mathbf{v}_n\Delta t,\qquad
\mathbf{v}_{n+1}=\mathbf{v}_n+\mathbf{a}_n\Delta t
$$

여기서 $\mathbf{p}$는 위치, $\mathbf{v}$는 속도, $\mathbf{a}$는 가속도다. 이 방식은 시간 단위에 맞는 속도를 정의하게 해 주지만, 프레임 간격이 크게 흔들리면 한 번의 갱신 폭도 커진다. 물리 시뮬레이션에서는 최대 간격 제한이나 고정 시간 간격의 하위 단계를 두는 방법을 고려한다. 반대로 시각적 파형만 필요하다면 상태를 누적하지 않고 `seconds`로 직접 그 값을 계산하는 편이 단순하다.

## 표현과 상태를 나누기

입력 콜백은 사용자 명령을 프로그램 상태로 바꾸고, 프레임 블록은 그 상태와 현재 시각을 화면 좌표와 색으로 바꾼다. 예를 들어 키 이벤트는 속도나 위상을 조정하고, `extend`는 그 값으로 위치를 계산해 그린다. 이 경계를 두면 키 입력 처리와 애니메이션 식을 서로 독립적으로 수정할 수 있다.

마우스 위치가 도형의 기준점이 되는 경우에는 해당 위치를 그대로 사용하거나, 위치와 도형 사이의 거리로 크기·색·방향을 계산할 수 있다. 좌표 원점과 y축 방향은 25.4에서 다룬 화면 좌표계를 따른다. 프레임마다 바뀌지 않는 도형 목록은 25.6처럼 초기화 시점에 준비해 재사용하고, 시간이나 입력에 반응하는 값만 매 프레임 계산하면 된다.

## 이 절의 핵심

`seconds`는 경과 시간에 따른 연속 애니메이션을 정의하며, `mouse.position`과 `keyboard.pressedKeys`는 현재 입력 상태를 알려 준다. `keyboard.keyDown.listen`과 같은 이벤트 리스너는 입력이 발생한 순간에 상태를 갱신한다. 고정량을 프레임마다 누적하는 대신 시간 기반 함수를 사용하고, 리스너는 초기화 중 한 번 등록하며, 상태 갱신과 그리기 역할을 구분하면 프레임률 변화와 입력 동작을 더 예측하기 쉽다.
