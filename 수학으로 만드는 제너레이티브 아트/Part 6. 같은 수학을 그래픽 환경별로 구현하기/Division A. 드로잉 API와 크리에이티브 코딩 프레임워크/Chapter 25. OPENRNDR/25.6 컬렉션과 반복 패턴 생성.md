# 25.6 컬렉션과 반복 패턴 생성

25.5에서는 벡터와 도형을 기하 자료로 구성하는 방법을 살펴보았다. 이번 절에서는 여러 위치와 도형을 Kotlin 컬렉션으로 만들고, 조건에 따라 선택하고, 반복 패턴으로 그리는 흐름을 다룬다. 예제는 OPENRNDR 0.5.0과 Kotlin 2.4.20을 기준으로 한다.

## 반복 인덱스를 패턴 데이터로 바꾸기

반복 패턴의 각 요소는 행과 열 같은 인덱스에서 출발할 수 있다. 인덱스를 바로 그리기 명령에 넣는 대신, 먼저 위치나 도형의 목록으로 변환하면 규칙과 렌더링을 분리해 생각할 수 있다. 아래 예제는 격자의 각 셀 중심을 `Vector2` 위치로 만들고, 두 삼각 함수가 만든 값을 그 위치에 함께 보관한다.

```kotlin
import kotlin.math.PI
import kotlin.math.cos
import kotlin.math.sin
import org.openrndr.application
import org.openrndr.color.ColorRGBa
import org.openrndr.math.Vector2
import org.openrndr.shape.Circle

data class GridSample(val position: Vector2, val signal: Double)

fun main() = application {
    configure {
        width = 800
        height = 600
    }

    program {
        val columns = 36
        val rows = 24

        val samples = (0 until rows).flatMap { row ->
            (0 until columns).map { column ->
                val u = (column + 0.5) / columns
                val v = (row + 0.5) / rows
                val phaseX = 2.0 * PI * (3.0 * u + v)
                val phaseY = 2.0 * PI * (2.0 * v - u)

                GridSample(
                    position = Vector2(u * width, v * height),
                    signal = sin(phaseX) + cos(phaseY)
                )
            }
        }

        val circles = samples
            .filter { it.signal > 0.15 }
            .map { sample ->
                val radius = 1.5 + 2.0 * (sample.signal + 2.0)
                Circle(sample.position.x, sample.position.y, radius)
            }

        extend {
            drawer.clear(ColorRGBa.fromHex("#101820"))
            drawer.fill = ColorRGBa.fromHex("#F4B860")
            drawer.stroke = null
            drawer.circles(circles)
        }
    }
}
```

`0 until rows`는 0부터 `rows - 1`까지의 정수 범위를 만든다. 바깥쪽 `flatMap`은 각 행마다 열의 목록을 생성한 뒤, 그 목록들을 하나의 평평한 컬렉션으로 합친다. 따라서 결과는 행을 따라 순서대로 배열된 `rows * columns`개의 표본이다. `u`와 `v`는 셀의 중앙을 0과 1 사이의 값으로 나타내므로, 창 크기를 바꾸더라도 격자 규칙은 같은 비율로 적용된다.

각 표본에는 화면 위치뿐 아니라 `signal` 값도 저장된다. `filter`는 이 값이 기준보다 큰 위치만 남기고, `map`은 남은 표본을 실제로 그릴 `Circle` 객체로 변환한다. 신호 값이 반지름에도 반영되므로 선택된 점들은 위치에 따라 크기가 달라진다. 삼각 함수는 여기서 격자 전체에 반복되는 스칼라 패턴을 만드는 한 가지 방법일 뿐이며, 같은 자리에 다른 수식을 넣어도 컬렉션의 구성 단계는 그대로 유지된다.

## `map`, `filter`, `forEach`의 역할

컬렉션 연산은 서로 다른 목적을 가진다.

| 연산 | 결과 | 반복 패턴에서의 역할 |
| --- | --- | --- |
| `map` | 요소마다 변환한 새 컬렉션 | 인덱스를 위치로, 위치를 도형으로 변환 |
| `filter` | 조건을 만족하는 요소의 컬렉션 | 격자에서 그릴 지점이나 도형을 선택 |
| `forEach` | 별도 결과 없이 수행한 작업 | 요소마다 그리기나 상태 변경 수행 |
| `flatMap` | 여러 하위 컬렉션을 평평하게 합친 컬렉션 | 행별 결과를 하나의 격자 목록으로 결합 |

`map`과 `filter`는 그리기 전에 사용할 데이터를 만들 때 적합하다. 반면 `drawer.circle()` 같은 호출은 화면에 명령을 보내는 부수 효과이므로, 결과 목록이 필요하지 않다면 `map`보다 `forEach`가 의도를 정확히 표현한다.

```kotlin
drawer.isolated {
    stroke = null
    circles.forEachIndexed { index, item ->
        fill = if (index % 2 == 0) ColorRGBa.PINK else ColorRGBa.CYAN
        circle(item)
    }
}
```

이 방식은 요소마다 색을 바꾸거나 인덱스를 이용해 개별 규칙을 적용할 때 유용하다. 모든 원이 같은 스타일을 공유한다면 예제처럼 스타일을 한 번 지정하고 `drawer.circles(circles)`를 사용하는 편이 간결하다. 배치 API는 동일한 종류의 도형을 많이 그릴 때 개별 호출의 반복을 줄이는 데 적합하다.

## 패턴 데이터를 프레임에서 재사용하기

위 예제에서 `samples`와 `circles`는 `program` 초기화 과정에서 한 번 만들어지고, `extend`에서는 이미 준비된 원 목록을 매 프레임 그린다. 패턴의 위치와 크기가 고정되어 있다면 이처럼 데이터 생성과 렌더링을 나누어 매 프레임의 불필요한 재계산을 피할 수 있다. 반대로 시간이나 입력에 따라 크기와 위치가 달라져야 한다면 해당 값만 프레임마다 다시 계산한다. 시간과 이벤트를 이용한 변화는 25.7에서 다룬다.

Kotlin의 일반적인 `List` 변환 연산은 호출 시점에 결과 컬렉션을 만든다. 따라서 큰 목록에 여러 변환을 연이어 적용할 때는 중간 목록이 생길 수 있다는 점을 기억하자. 작은 규모에서는 각 단계가 분명한 파이프라인이 규칙을 읽기 쉽게 해 주며, 매우 큰 데이터에서는 필요한 연산만 남기거나 OPENRNDR의 배치 그리기와 GPU 처리를 검토한다. 어떤 방식을 선택하든 도형을 계산하는 규칙과 이를 화면에 전달하는 코드를 분리하면 패턴을 바꾸고 비교하기 쉽다.

## 이 절의 핵심

범위와 인덱스를 컬렉션으로 변환하면 격자 같은 패턴을 규칙적으로 만들 수 있다. `flatMap`은 행별 목록을 하나로 합치고, `filter`는 그릴 데이터를 선택하며, `map`은 위치 자료를 도형으로 변환한다. 그리기 같은 부수 효과에는 `forEach`를 사용하고, 공통 스타일의 동일한 도형이 많을 때는 `drawer.circles()` 같은 배치 API를 활용한다.
