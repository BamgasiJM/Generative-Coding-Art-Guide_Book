# 25.8 이미지, 레이어, 렌더 타깃

OPENRNDR 장면은 직접 그린 도형만으로 구성되지 않는다. 파일에서 읽은 이미지를 배경으로 사용하거나, 내용을 별도의 버퍼에 그린 뒤 화면에 합성할 수 있다. 이 절에서는 `ColorBuffer`, `RenderTarget`, ORX compositor의 역할을 구분하고, OPENRNDR 0.5.0과 Kotlin 2.4.20 기준으로 기본 흐름을 살펴본다.

## 이미지 읽기와 화면에 배치하기

`loadImage()`는 이미지 파일을 읽어 그래픽스에서 사용할 `ColorBuffer`로 만든다. 파일을 읽고 필터를 정하는 작업은 매 프레임 반복하지 말고 `program` 구성 중 한 번 수행한다. `drawer.image()`는 그 버퍼를 현재 그리기 대상에 배치한다.

```kotlin
import org.openrndr.application
import org.openrndr.color.ColorRGBa
import org.openrndr.draw.*

fun main() = application {
    configure {
        width = 800
        height = 600
    }

    program {
        val image = loadImage("data/images/background.jpg")
        image.filter(
            MinifyingFilter.LINEAR_MIPMAP_NEAREST,
            MagnifyingFilter.LINEAR
        )

        extend {
            drawer.clear(ColorRGBa.BLACK)
            drawer.image(image, 0.0, 0.0)
        }
    }
}
```

예제의 `drawer.image(image, 0.0, 0.0)`은 이미지를 왼쪽 위에 기본 크기로 배치한다. 따라서 원본 파일은 프로젝트의 `data/images` 경로에 있어야 하며, 창 전체를 덮으려면 원본 크기와 창 크기를 맞추거나 배치 영역을 의도에 맞게 조절한다.

이미지 필터는 화면에서 이미지가 축소되거나 확대될 때 샘플링하는 방식을 정한다. `MinifyingFilter`는 원본보다 작게 표시할 때, `MagnifyingFilter`는 크게 표시할 때 영향을 준다. 축소 필터에 밉맵을 포함하면 크기가 많이 줄어든 이미지의 깜박임과 계단 현상을 완화할 수 있다. 파일에서 읽은 이미지는 이미 `ColorBuffer`이므로, 그대로 표시하는 것과 셰이더 안에서 텍스처로 샘플링하는 것은 서로 다른 사용 방식이다. 텍스처 좌표와 셰이더 샘플링은 25.9에서 다룬다.

## RenderTarget을 오프스크린 표면으로 사용하기

`RenderTarget`은 화면 대신 그리기 명령을 받아들이는 GPU 렌더링 대상이다. 보통 색을 저장하는 `colorBuffer()`를 붙이고, 필요한 도형 기능에 따라 깊이·스텐실 버퍼를 추가한다. 렌더 타깃의 컬러 버퍼는 다시 이미지처럼 화면에 그리거나 다음 합성 단계의 입력으로 사용할 수 있다.

```kotlin
fun main() = application {
    configure {
        width = 800
        height = 600
    }

    program {
        val background = loadImage("data/images/background.jpg")
        val overlay = renderTarget(width, height) {
            colorBuffer()
            depthBuffer()
        }

        extend {
            drawer.isolatedWithTarget(overlay) {
                drawer.clear(ColorRGBa.TRANSPARENT)
                drawer.fill = ColorRGBa.PINK.opacify(0.35)
                drawer.stroke = null
                drawer.circle(mouse.position, 90.0)
            }

            drawer.clear(ColorRGBa.fromHex("#101820"))
            drawer.image(background, 0.0, 0.0)
            drawer.image(overlay.colorBuffer(0), 0.0, 0.0)
        }
    }
}
```

첫 번째 그리기 블록은 `overlay`를 현재 대상으로 삼아 반투명 원을 그린다. `isolatedWithTarget()`은 지정된 타깃에 그리는 동안 상태를 격리하고, 블록이 끝나면 원래 대상인 창으로 돌아온다. 이후 `overlay.colorBuffer(0)`을 `drawer.image()`에 전달해 배경 이미지 위에 합성한다. 이 예제의 배경 이미지는 800×600 창에 맞는 크기라고 가정한다.

버퍼는 프레임 사이에도 내용을 보존할 수 있으므로, 매 프레임 새로 그리는 레이어라면 렌더 타깃 안에서 먼저 지워야 한다. `ColorRGBa.TRANSPARENT`로 지우면 이전 프레임의 색이 남지 않는 투명 오버레이가 된다. 반대로 이전 내용을 남기거나 반투명하게 덮으면 잔상 효과를 만들 수 있다. 의도적으로 누적하는 경우가 아니라면 매 프레임 지워 이전 그림이 섞이지 않도록 한다.

`RenderTarget`은 컬러 버퍼를 하나 이상 가질 수 있으며, `colorBuffer(0)`은 첫 번째 첨부 버퍼를 선택한다. 단순한 2D 도형과 이미지 합성에는 컬러 버퍼가 중심이 된다. `ShapeContour`나 `Shape`의 채우기처럼 스텐실 처리가 필요한 작업을 타깃에 그릴 때는 `depthBuffer()`도 추가해야 한다. 화면과 다른 크기의 타깃을 사용할 경우에는 타깃에 맞는 투영과 좌표 영역도 설정해야 한다.

## ORX compositor로 레이어 구성하기

여러 오프스크린 타깃과 합성 순서를 직접 관리하는 대신, `orx-compositor`의 `compose { }` DSL로 장면을 레이어 단위로 구성할 수 있다. 합성 구조는 프로그램 초기화 때 만들고, 각 레이어의 `draw { }`에서 매 프레임 그릴 내용을 지정한다.

```kotlin
program {
    val image = loadImage("data/images/background.jpg")

    val composition = compose {
        draw {
            drawer.clear(ColorRGBa.fromHex("#101820"))
        }

        layer {
            draw {
                drawer.image(image, 0.0, 0.0)
            }
        }

        layer {
            draw {
                drawer.fill = ColorRGBa.PINK.opacify(0.35)
                drawer.stroke = null
                drawer.circle(mouse.position, 90.0)
            }
        }
    }

    extend {
        composition.draw(drawer)
    }
}
```

각 `layer`는 독립된 렌더 결과로 취급되므로, 레이어 순서와 블렌드 설정을 통해 배경 이미지와 전경 요소를 조합할 수 있다. `draw { }`의 내용은 프레임마다 실행되지만 compositor와 레이어의 구조 자체는 한 번 구성한다. 마스크, 블렌드 모드, 레이어별 후처리까지 필요한 작업은 compositor DSL이 편리하고, 타깃별 크기나 합성 순서를 세밀하게 제어해야 한다면 `RenderTarget`을 직접 관리하는 편이 명확하다. ORX 모듈이 프로젝트 의존성에 포함되어 있어야 한다.

## 세 가지 역할을 구별하기

| 객체 | 맡는 역할 | 대표적인 사용 |
| --- | --- | --- |
| `ColorBuffer` | 이미지 색 데이터를 보관하는 버퍼 | 파일 이미지 표시, 텍스처 또는 합성 입력 |
| `RenderTarget` | 하나 이상의 버퍼를 묶은 렌더링 대상 | 장면 일부를 오프스크린에서 그리기 |
| compositor 레이어 | 여러 그리기 결과의 구조와 합성 순서를 표현 | 배경·마스크·전경·후처리 조합 |

렌더 타깃은 그 자체가 이미지 파일이나 레이어 관리 언어가 아니다. 오프스크린 렌더링을 위한 대상으로, 여기에 붙은 버퍼를 다른 그리기 단계에서 소비한다. 반면 compositor는 여러 단계의 관계를 선언적으로 표현해 준다. 둘 다 화면에 표시하기 전 중간 결과를 만들지만, 어느 쪽을 고를지는 필요한 제어 수준에 달려 있다.

이미지와 렌더 타깃은 GPU 자원이므로 프레임마다 새로 만들기보다 `program` 초기화 중 생성해 재사용한다. 렌더 타깃에 그린 결과를 일반 파일로 저장하려면 화면에 표시하는 것과는 별도의 읽기·내보내기 과정이 필요하다. 고정된 도형 또는 픽셀 내용을 매 프레임 다시 계산하지 않도록 생성 시점과 소비 시점을 분리한다.

## 이 절의 핵심

`loadImage()`로 읽은 이미지는 `ColorBuffer`로 사용할 수 있고, `RenderTarget`은 그리기 결과를 화면 밖의 버퍼에 저장한다. `isolatedWithTarget()`으로 타깃을 전환해 그린 뒤 컬러 버퍼를 이미지처럼 합성할 수 있으며, 여러 레이어와 블렌드·마스크의 관계는 ORX compositor로 표현할 수 있다. 이미지와 렌더 타깃은 초기화 시 한 번 만들고, 매 프레임 갱신할 콘텐츠만 다시 그리는 것이 기본 구조다.
