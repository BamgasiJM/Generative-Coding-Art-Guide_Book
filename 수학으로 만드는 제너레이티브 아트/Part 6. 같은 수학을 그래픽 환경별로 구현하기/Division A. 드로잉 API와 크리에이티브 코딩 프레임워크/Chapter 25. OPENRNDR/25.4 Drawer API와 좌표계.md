# 25.4 Drawer API와 좌표계

OPENRNDR에서 `Drawer`는 현재 프레임에 도형과 선을 그리는 주요 인터페이스다. `Program`의 프레임 확장점 안에서 `drawer`를 통해 배경을 지우고, 채움과 윤곽선 스타일을 지정한 다음, 좌표를 전달해 그리기 명령을 만든다. 이 절은 OPENRNDR 0.5.0의 기본 Drawer API와 화면 좌표계에 집중한다. 벡터 자료형, 복합 윤곽, 변환 행렬은 25.5에서 이어서 다룬다.

## Drawer가 맡는 역할

`Drawer`는 수학적 규칙 자체가 아니라 계산한 값을 그래픽 명령으로 표현하는 도구다. 예를 들어 반복 규칙이 만든 점의 위치를 `drawer.circle()`에 전달하고, 선분의 양 끝점을 `drawer.lineSegment()`에 전달한다. 프로그램의 프레임 흐름과 `extend`의 실행 시점은 25.3에서 살펴보았으므로, 여기서는 그 블록 안에서 Drawer를 사용하는 기본 문법을 보자.

```kotlin
extend {
    drawer.clear(ColorRGBa.fromHex("#101820"))

    drawer.fill = ColorRGBa.fromHex("#5ED0C1")
    drawer.stroke = null
    drawer.circle(width / 2.0, height / 2.0, 70.0)

    drawer.fill = null
    drawer.stroke = ColorRGBa.fromHex("#F4B860")
    drawer.strokeWeight = 3.0
    drawer.rectangle(40.0, 40.0, 120.0, 80.0)
    drawer.lineSegment(40.0, 150.0, 160.0, 150.0)
}
```

`drawer.clear()`는 프레임의 바탕색을 정한다. `drawer.fill`은 닫힌 도형의 내부 색, `drawer.stroke`는 윤곽선과 선의 색, `drawer.strokeWeight`는 선의 두께를 지정한다. `null`을 넣으면 채움이나 윤곽선을 생략한다. 색을 지정하지 않으면 기본 스타일이 적용되지만, 작품의 모양을 의도대로 유지하려면 필요한 스타일을 코드에서 분명히 설정하는 편이 좋다.

스타일 설정은 다음에 호출하는 그리기 명령에 영향을 준다. 따라서 색과 굵기를 바꾸는 순서를 살피면 도형의 외관을 읽기 쉽다. 위 예에서는 첫 원을 채움만으로 그린 뒤, 채움을 끄고 윤곽선을 켜 사각형을 그린다. `lineSegment()`는 내부 채움 없이 윤곽선 스타일을 사용한다. 스타일 상태를 저장하고 복원하는 API는 더 복잡한 장면을 구성할 때 유용하지만, 이 절에서는 기본 속성의 적용 순서를 익히는 데 초점을 둔다.

## 화면 좌표계

OPENRNDR의 기본 2D 화면 좌표에서 원점 `(0, 0)`은 창의 왼쪽 위다. x 값은 오른쪽으로 갈수록 커지고 y 값은 아래쪽으로 갈수록 커진다. `width`와 `height`는 창의 크기를 나타내는 정수 값이며, 실제 드로잉 위치와 도형 크기는 대개 `Double`로 전달한다.

| 위치 | 좌표의 의미 |
| --- | --- |
| `(0, 0)` | 왼쪽 위 모서리 |
| `(width, 0)` | 오른쪽 위 모서리 |
| `(0, height)` | 왼쪽 아래 모서리 |
| `(width, height)` | 오른쪽 아래 모서리 |
| `(width / 2.0, height / 2.0)` | 창의 중심 |

컴퓨터 그래픽 입문에서 자주 사용하는 데카르트 좌표는 보통 원점이 중심이고 y축이 위쪽을 향한다. 이를 OPENRNDR의 화면 좌표로 옮길 때는 중심점을 더하고 y축 방향을 반대로 바꾼다.

$$
x_{screen}=\frac{W}{2}+x_{math},\qquad
y_{screen}=\frac{H}{2}-y_{math}
$$

여기서 `W`와 `H`는 창 너비와 높이다. 반대로 화면 위치를 중심 기준의 수학 좌표로 바꾸려면 `x_math = x_screen - W/2`, `y_math = H/2 - y_screen`을 사용한다. 따라서 `sin(angle)` 값을 화면 y에 더하면 각도가 증가할 때 점은 아래 방향으로 움직인다. 삼각함수로 원운동을 만들 때 화면 좌표계의 y 방향을 고려하면 회전 방향이 예상과 일치한다.

너비나 높이를 홀수로 정해도 중심 계산에서 반 픽셀 위치가 나올 수 있다. 이는 실수 좌표계에서는 자연스러운 값이며, 정수 좌표에 맞추어야 하는 픽셀 처리와 구분해야 한다. `width / 2.0`처럼 실수 나눗셈을 사용하면 중심 계산에서 소수 부분을 보존한다. Kotlin의 숫자 타입 변환은 25.2에서 다룬 내용을 참고한다.

## 기본 도형 호출과 기준점

Drawer의 도형 함수마다 좌표가 가리키는 기준점이 다를 수 있다. 특히 원과 사각형의 기준을 혼동하면 같은 좌표를 전달해도 배치가 어긋난다.

| 함수 | 좌표 인자의 의미 | 나머지 인자 |
| --- | --- | --- |
| `circle(x, y, radius)` | `(x, y)`는 원의 중심 | 반지름 |
| `rectangle(x, y, width, height)` | `(x, y)`는 사각형의 왼쪽 위 | 너비와 높이 |
| `lineSegment(x0, y0, x1, y1)` | 첫 번째 점에서 두 번째 점까지 | 두 끝점 좌표 |

예를 들어 `circle(100.0, 80.0, 20.0)`의 중심은 `(100, 80)`이고, `rectangle(100.0, 80.0, 40.0, 30.0)`의 왼쪽 위 모서리가 `(100, 80)`이다. 도형의 중심을 기준으로 배치하려면 위치와 크기로 꼭짓점을 직접 계산하거나, 25.5에서 다룰 `Rectangle` 같은 기하 객체를 사용할 수 있다.

화면 밖의 좌표를 전달하는 것도 가능하다. 그려진 부분 중 현재 렌더링 영역과 겹치는 부분만 보이므로, 가장자리에서 잘리는 도형이나 창을 가로지르는 선을 만들 수 있다. 일부만 보이도록 의도한 경우와 좌표 계산 실수로 잘린 경우를 구분하려면 먼저 중심과 경계의 위치를 확인한다.

## 정규화 좌표로 수식을 이식하기

화면의 픽셀 단위를 직접 수식에 넣으면 창 크기를 바꿀 때 패턴의 비율도 달라진다. 위치를 0에서 1 사이로 정규화하면 화면 크기와 독립적인 규칙을 만들 수 있다.

$$
u=\frac{x}{W},\qquad v=\frac{y}{H}
$$

화면의 중심을 기준으로 원형 필드나 거리 함수를 계산하려면 짧은 변의 길이를 기준으로 좌표를 정규화한다.

$$
u_c=\frac{x-W/2}{\min(W,H)},\qquad
v_c=\frac{H/2-y}{\min(W,H)}
$$

이 정의에서는 `v_c`의 양의 방향이 위쪽이므로 데카르트 좌표와 비슷하게 해석할 수 있다. 분모를 짧은 변으로 잡으면 창의 가로세로 비율이 달라져도 원형 패턴의 형태가 유지된다. 예를 들어 `sqrt(u_c * u_c + v_c * v_c)`를 사용하면 창 중심부터의 정규화된 거리를 얻는다. 거리장이나 셰이더로 이 수식을 확장하는 내용은 Part 2와 25.9에서 이어진다.

정규화 좌표를 다시 화면 위치로 바꾸려면 `x = u * width`, `y = v * height`를 계산한다. 이때 `v`를 위쪽 기준으로 정의했다면 화면 y축이 아래쪽으로 증가하므로 `y = (1 - v) * height`처럼 방향을 뒤집는다. 좌표가 어느 원점과 방향을 사용하는지 수식 옆에 명시하면 셰이더나 다른 프레임워크로 옮길 때 혼란이 줄어든다.

## 반복 명령에서 스타일을 관리하기

여러 도형을 한 프레임에 그릴 때는 스타일 속성이 변경된 위치를 따라가며 읽는다. 배경과 전경, 채움과 테두리의 규칙을 명확히 하면 도형 수가 늘어도 의도하지 않은 색상 상속을 줄일 수 있다. 반복 패턴을 데이터와 함수로 구성하는 방법은 25.6에서 다루므로 여기서는 개별 도형의 기본 렌더링 계약만 기억하자.

도형의 중심 좌표와 사각형의 기준점은 다르며, 화면 좌표의 y축 방향은 수학 교과서의 기본 좌표와 반대다. 좌표 변환을 적용하거나 `Vector2`, `ShapeContour`, `Shape`로 복합 기하를 구성할 때는 기준 원점과 변환 순서가 추가된다. 이 내용은 다음 절에서 다룬다.

## 이 절의 핵심

`Drawer`는 `clear()`, 스타일 속성, 도형 함수를 통해 현재 프레임의 그래픽 명령을 구성한다. 기본 화면 좌표의 원점은 왼쪽 위이고 x는 오른쪽, y는 아래쪽으로 증가한다. `circle()`은 중심 좌표, `rectangle()`은 왼쪽 위 좌표를 받으므로 인자의 기준점을 구별해야 한다. 수학 좌표와 화면 좌표 사이의 변환 및 정규화 좌표를 명시하면 창 크기와 좌표 방향에 덜 묶이는 규칙을 만들 수 있다.
