# 25.9 ShadeStyle과 GLSL 셰이더

앞 절에서는 이미지 버퍼와 오프스크린 렌더 타깃을 화면에 합성하는 방법을 살펴보았다. 이번 절에서는 도형을 덮는 픽셀의 색과 모양을 GPU에서 계산하는 `ShadeStyle`을 다룬다. OPENRNDR 0.5.0은 완성된 셰이더 프로그램 전체를 직접 작성하는 대신, 프레임워크가 구성하는 셰이더의 정해진 위치에 GLSL 코드를 제공하는 방식을 사용한다. 예제는 Kotlin 2.4.20을 기준으로 한다.

## ShadeStyle이 맡는 일

`ShadeStyle`은 그리기 명령에 GPU 셰이더 동작을 연결하는 객체다. 드로잉 API가 원이나 사각형의 경계를 정한다면, 셰이더는 그 경계 안쪽의 각 프래그먼트에서 색을 계산할 수 있다. 따라서 기하를 수많은 작은 도형으로 나누지 않고도 줄무늬, 파동, 그라디언트처럼 픽셀 단위로 변하는 패턴을 만들 수 있다.

| 속성 | 셰이더 단계 | 주된 역할 |
| --- | --- | --- |
| `vertexTransform` | 정점 셰이더 | 정점 위치나 관련 값을 변형 |
| `fragmentTransform` | 프래그먼트 셰이더 | 도형 내부의 채움색이나 선 색을 계산 |
| `vertexPreamble` | 정점 셰이더의 `main()` 앞 | 정점 단계에서 쓸 함수와 선언 추가 |
| `fragmentPreamble` | 프래그먼트 셰이더의 `main()` 앞 | 프래그먼트 단계에서 쓸 함수와 선언 추가 |

처음에는 가장 자주 쓰는 `fragmentTransform`에 집중하면 된다. 이 코드는 프레임워크가 만드는 프래그먼트 함수 안에 삽입되므로, 별도의 `main()`이나 전체 입출력 인터페이스를 작성하지 않는다. 실제 결과를 담는 `x_fill`과 `x_stroke` 같은 이름도 OPENRNDR의 셰이더 계약에 맞춰 사용한다.

## 픽셀마다 색 계산하기

다음 예제는 사각형 내부의 가로 좌표를 반복되는 파동의 위상으로 사용한다. 시간에 따라 두 색 사이의 경계가 움직이고, Kotlin에서 전달한 값이 셰이더의 입력으로 사용된다.

```kotlin
import org.openrndr.application
import org.openrndr.color.ColorRGBa
import org.openrndr.draw.*

fun main() = application {
    configure {
        width = 800
        height = 500
    }

    program {
        val waveStyle = shadeStyle {
            fragmentTransform = """
                float u = c_boundsPosition.x;
                float wave = 0.5 + 0.5 * sin(6.2831853 * p_frequency * u + p_time);
                x_fill.rgb = mix(p_colorA.rgb, p_colorB.rgb, wave);
            """.trimIndent()

            parameter("frequency", 4.0)
            parameter("colorA", ColorRGBa.fromHex("#16A6A1"))
            parameter("colorB", ColorRGBa.fromHex("#F4B860"))
        }

        extend {
            waveStyle.parameter("time", seconds)

            drawer.clear(ColorRGBa.fromHex("#101820"))
            drawer.isolated {
                drawer.shadeStyle = waveStyle
                drawer.fill = ColorRGBa.WHITE
                drawer.stroke = null
                drawer.rectangle(80.0, 80.0, width - 160.0, height - 160.0)
            }
        }
    }
}
```

`fragmentTransform`은 각 프래그먼트에서 `c_boundsPosition.x`를 읽는다. 이 좌표는 도형의 경계 상자 안에서 0부터 1까지 변하므로, 셰이더 패턴이 도형의 위치와 크기에 맞춰 정규화된다. `sin()`의 결과를 0과 1 사이로 옮긴 `wave`를 `mix()`의 보간값으로 사용해 두 색을 섞는다. `x_fill.rgb`만 바꾸므로 원래 채움색의 알파는 유지된다.

## 좌표 선택과 패턴의 기준

셰이더 안에서 선택한 좌표에 따라 패턴이 도형에 붙을지, 화면에 고정될지가 달라진다.

| 좌표 | 기준 | 용도 |
| --- | --- | --- |
| `c_boundsPosition.xy` | 각 도형의 경계 상자, 정규화된 0~1 | 도형 크기에 맞춰 늘어나는 무늬 |
| `c_boundsSize.xy` | 도형 경계 상자의 픽셀 크기 | 픽셀 단위로 주기나 간격을 조절 |
| `c_screenPosition` | 화면 좌표 | 도형이 움직여도 화면에 고정된 무늬 |
| `c_contourPosition` | 선 윤곽을 따라간 거리 | 선 위를 흐르는 점선이나 색 변화 |

예제처럼 `c_boundsPosition`을 쓰면 서로 다른 도형마다 0~1 좌표가 다시 시작된다. 도형이 커져도 파동의 횟수가 유지되며, 도형 크기와 함께 무늬의 물리적 크기도 늘어난다. 반대로 여러 도형에 걸쳐 이어지는 한 장의 화면 고정 패턴이 필요하면 `c_screenPosition`을 기준으로 수식을 구성한다. 화면 좌표의 y축 방향은 25.4의 좌표계 설명과 동일하게 고려한다.

## Kotlin에서 셰이더 파라미터 전달하기

`parameter("name", value)`는 Kotlin 값과 GLSL 변수를 연결한다. Kotlin 코드에서는 이름을 접두사 없이 전달하고, GLSL에서는 `p_`를 붙여 읽는다. 따라서 `parameter("frequency", 4.0)`은 셰이더에서 `p_frequency`가 된다.

| Kotlin 값 | GLSL에서 사용하는 형식 |
| --- | --- |
| `Double` | `float` |
| `Vector2`, `Vector3`, `Vector4` | `vec2`, `vec3`, `vec4` |
| `ColorRGBa` | `vec4` |
| `Matrix44` | `mat4` |
| `ColorBuffer`, `DepthBuffer` | `sampler2D` |

`ShadeStyle`은 프로그램 초기화 때 한 번 만들고, 프레임마다 바뀌는 값은 `waveStyle.parameter("time", seconds)`처럼 갱신한다. 매 프레임 새 스타일을 만드는 대신 같은 객체의 파라미터를 바꾸면 셰이더 구성과 애니메이션 입력을 분리할 수 있다. 셰이더 안에서 읽는 `p_` 이름과 Kotlin의 `parameter()` 문자열이 일치해야 한다.

## 보조 함수와 이미지 샘플링

`fragmentTransform`은 생성된 `main()` 내부에 들어가므로 그 안에 GLSL 함수를 선언할 수 없다. 재사용할 함수나 선언은 `fragmentPreamble`에 두고, 변환 코드에서 호출한다.

```kotlin
val style = shadeStyle {
    fragmentPreamble = """
        float rn_wave(float x, float t) {
            return 0.5 + 0.5 * sin(6.2831853 * x + t);
        }
    """.trimIndent()

    fragmentTransform = """
        float value = rn_wave(c_boundsPosition.x, p_time);
        x_fill.rgb = mix(p_colorA.rgb, p_colorB.rgb, value);
    """.trimIndent()

    parameter("colorA", ColorRGBa.PINK)
    parameter("colorB", ColorRGBa.CYAN)
}
```

사용자 함수에는 `rn_`처럼 고유한 접두사를 붙이면 프레임워크가 생성하는 변수 이름과의 충돌을 피하는 데 도움이 된다. 여러 프래그먼트에서 계산하는 노이즈 함수나 복합 패턴 함수를 분리할 때 특히 유용하다.

`ColorBuffer`도 파라미터로 전달할 수 있다. 그러면 GLSL에서 `sampler2D`로 이미지의 색을 읽어 도형의 채움에 사용할 수 있다.

```glsl
vec2 uv = c_boundsPosition.xy;
uv.y = 1.0 - uv.y;
x_fill = texture(p_image, uv);
```

이 조각을 사용하려면 Kotlin 쪽에서 `parameter("image", image)`로 이미지 버퍼를 연결해야 한다. `uv.y`를 뒤집는 줄은 좌표 원점과 이미지 데이터의 방향 차이를 보정하는 예다. 결과가 거꾸로 나오면 텍스처 좌표 방향을 확인한다. 이미지 로딩과 일반적인 버퍼 합성은 25.8에서 다루었으므로, 여기서는 픽셀 셰이더에서 이미지를 샘플링하는 관계만 기억하면 된다.

## 적용 범위와 디버깅

`drawer.shadeStyle`에 스타일을 지정하면 이후 그리는 도형에 적용된다. 특정 도형에만 사용하려면 `drawer.isolated { }` 안에서 스타일을 지정한다. 블록이 끝날 때 그리기 상태가 복원되므로 다음 도형에 셰이더가 뜻하지 않게 남는 일을 막을 수 있다.

GLSL은 Kotlin과 숫자 문법이 다르다. 부동소수점 수에는 `1`보다 `1.0`을 쓰고, `vec2`·`vec3` 같은 벡터의 성분 수와 색의 `vec4` 형식을 맞춘다. 셰이더가 컴파일되지 않으면 GLSL 오류 메시지와 함께 프로젝트 루트의 `ShaderError.glsl`을 확인한다. 이 파일에는 OPENRNDR가 조합한 최종 셰이더 코드가 있어, 파라미터 이름이나 삽입 위치를 점검하는 데 도움이 된다.

## 이 절의 핵심

`ShadeStyle`은 OPENRNDR가 생성하는 셰이더에 GLSL 조각을 연결한다. `fragmentTransform`은 프래그먼트의 채움이나 선 색을 바꾸고, `c_boundsPosition`과 `c_screenPosition`은 무늬의 기준 좌표를 결정한다. Kotlin에서는 `parameter()`로 값을 전달하고 `p_` 이름으로 GLSL에서 읽으며, 스타일은 초기화 때 한 번 만들어 프레임별 값만 갱신한다. 함수 선언은 `fragmentPreamble`에 두고, 적용 범위는 `drawer.isolated { }`로 관리한다.
