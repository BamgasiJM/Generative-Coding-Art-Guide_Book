# 25.5 벡터, 도형, 좌표 변환

25.4에서는 `Drawer`에 화면 좌표를 전달해 기본 도형을 그리는 방법을 살펴보았다. 이번 절은 좌표를 `Vector2`와 같은 기하 자료로 다루고, 여러 선분으로 구성된 윤곽과 도형을 표현하며, 로컬 좌표계에 이동·회전·스케일을 적용하는 방법을 설명한다. 예제는 OPENRNDR 0.5.0과 Kotlin 2.4.20을 기준으로 한다.

## 점과 벡터를 값으로 표현하기

`Vector2`는 2차원 좌표를 하나의 값으로 묶는다. x와 y를 매번 별도 인자로 전달하는 대신, 점의 위치·이동량·방향을 벡터 연산으로 계산할 수 있다.

```kotlin
val position = Vector2(120.0, 80.0)
val velocity = Vector2(2.0, -0.5)
val elapsed = 10.0

val nextPosition = position + velocity * elapsed
```

벡터 덧셈은 위치에 이동량을 더하고, 스칼라 곱셈은 벡터의 크기를 조절한다. 위 예에서 `velocity`는 한 시간 단위 동안의 x·y 이동량이고, `elapsed`를 곱하면 그 시간 동안 이동한 변위를 얻는다. 기본 화면 좌표에서는 y가 아래쪽으로 증가하므로 y 성분이 음수인 벡터는 화면에서 위쪽을 향한다.

벡터를 사용하면 기하 계산을 그리기 API와 분리할 수 있다. 계산 함수에서 새 위치를 만든 뒤 Drawer에는 그 결과를 넘기면 된다.

```kotlin
val points = listOf(
    Vector2(100.0, 120.0),
    Vector2(180.0, 80.0),
    Vector2(260.0, 140.0),
)

drawer.lineStrip(points)
```

점 목록은 여기서 꺾은선의 정점 데이터로 사용된다. `Vector2`는 수학적 좌표값이고, `drawer.lineStrip()`은 그 값을 화면에 표현하는 명령이다. 점 집합을 반복해서 배치하거나 함수형 연산으로 변환하는 패턴은 25.6에서 다룬다.

## 기하 객체와 렌더 명령 구분하기

기하 객체는 화면에 그리는 명령과 별도로 존재할 수 있다. 예를 들어 `Circle`이나 `Rectangle`은 중심·크기·경계 같은 기하 정보를 보관하고, 필요할 때 윤곽이나 `Shape`로 변환한 뒤 Drawer로 전달한다. 이렇게 분리하면 같은 도형을 그리기, 교차 판정, 경계 계산 등 서로 다른 목적으로 활용할 수 있다.

복잡한 윤곽은 대체로 다음 단계로 구성된다.

| 기하 자료 | 역할 |
| --- | --- |
| `Segment2D` | 직선 또는 제어점을 가진 베지에 곡선 조각 |
| `ShapeContour` | 연결된 선분들의 열린 윤곽 또는 닫힌 윤곽 |
| `Shape` | 하나 이상의 윤곽을 묶어 내부와 구멍을 표현하는 도형 |

점들을 순서대로 연결해 정다각형 윤곽을 만들 수 있다.

```kotlin
import kotlin.math.PI
import kotlin.math.cos
import kotlin.math.sin
import org.openrndr.math.Vector2
import org.openrndr.shape.ShapeContour

fun regularPolygonContour(
    center: Vector2,
    radius: Double,
    sides: Int,
    startAngle: Double = -PI / 2.0,
): ShapeContour {
    require(sides >= 3)

    val points = List(sides) { index ->
        val angle = startAngle + 2.0 * PI * index / sides
        center + Vector2(cos(angle), sin(angle)) * radius
    }

    return ShapeContour.fromPoints(points, closed = true)
}
```

각 꼭짓점은 중심에서 반지름만큼 떨어진 위치다. 전체 각도 `2π`를 변의 수로 나누어 꼭짓점 간 각도 간격을 정한다. `sin()`과 `cos()`에는 라디안 각도를 전달한다. `ShapeContour.fromPoints()`는 점을 순서대로 직선으로 연결하고 `closed = true`일 때 마지막 점과 처음 점을 닫는다. 만들어진 윤곽은 `drawer.contour(contour)`로 그릴 수 있다. 내부가 채워진 다중 윤곽이나 구멍을 가진 형태는 `Shape`로 표현한다.

도형을 코드에서 매 프레임 다시 만들 필요는 없다. 정적인 윤곽과 복합 도형은 `program` 초기화 단계에서 만들어 두고, 프레임에서는 그 결과를 재사용한다. 점이나 곡선이 시간에 따라 달라지는 경우에만 해당 기하를 다시 계산한다. 이 배치 원칙은 25.3에서 살펴본 초기화와 `extend`의 수명 구분과 연결된다.

## 로컬 좌표계와 변환

이동(translation), 회전(rotation), 스케일(scale)은 도형의 모든 점에 같은 규칙을 적용하는 좌표 변환이다. OPENRNDR의 `Drawer` 변환은 기본 좌표계의 원점을 기준으로 작동한다. 각 도형의 화면 좌표를 직접 다시 계산하는 대신, 로컬 원점에 도형을 만든 뒤 좌표계를 변환해 배치할 수 있다.

```kotlin
drawer.isolated {
    translate(width / 2.0, height / 2.0)
    rotate(30.0)
    scale(1.2)

    fill = ColorRGBa.fromHex("#F4B860")
    stroke = null
    rectangle(-60.0, -35.0, 120.0, 70.0)
}
```

사각형의 로컬 좌표는 중심을 `(0, 0)`으로 삼도록 좌상단을 음수 방향에 둔다. `translate()`가 이 로컬 원점을 창 중심으로 옮기고, `rotate()`가 그 기준 주위로 회전시키며, `scale()`이 크기를 조절한다. OPENRNDR의 `rotate()` 인자는 도(degree) 단위이고, `sin()`·`cos()` 같은 Kotlin 수학 함수는 라디안을 사용한다. 수식에서 각도를 계산해 두 API 사이에 전달한다면 단위를 명시적으로 변환한다.

변환은 행렬로 합성되므로 코드에 쓴 순서와 점에 실제로 적용되는 순서를 구별해야 한다. 위 변환을 행렬로 쓰면 다음과 같다.

$$
\mathbf{p}_{screen}=T R S\mathbf{p}_{local}
$$

오른쪽의 점에 먼저 적용되므로, 도형은 로컬 공간에서 스케일된 다음 회전되고 마지막으로 이동한다. `translate()`를 먼저 적었다고 점이 가장 먼저 이동하는 것이 아니다. 이 순서를 의식하면 도형의 중심을 기준으로 돌릴지, 이동된 기준점 주위를 돌릴지 예측할 수 있다.

기본 화면 좌표의 y축은 아래쪽을 향한다. 따라서 같은 행렬과 각도를 사용해도 수학 교과서의 y축 위쪽 좌표에서 떠올리는 회전 방향과 화면에서 보이는 방향이 다를 수 있다. 회전의 중심과 방향이 예상과 다르면 변환 순서뿐 아니라 좌표계의 y축 방향도 확인한다.

## 변환과 스타일 상태 분리하기

`drawer.isolated { }`는 블록 안의 스타일과 변환 상태를 저장하고, 블록이 끝나면 이전 값으로 복원한다. 하나의 변환이 다음 도형에 누적되거나, 색과 선 굵기가 의도치 않게 전달되는 것을 막는다.

```kotlin
drawer.isolated {
    translate(160.0, 200.0)
    rotate(20.0)
    fill = ColorRGBa.PINK
    rectangle(-40.0, -30.0, 80.0, 60.0)
}

drawer.isolated {
    translate(360.0, 200.0)
    rotate(-20.0)
    fill = ColorRGBa.CYAN
    rectangle(-40.0, -30.0, 80.0, 60.0)
}
```

두 블록은 각자 변환 원점과 스타일을 설정한다. 첫 블록의 회전이나 채움색이 두 번째 도형에 남지 않으므로 서로 독립적으로 조절할 수 있다. `isolated`는 변환과 스타일의 경계를 만든다. 변환을 조합하는 일반 원리와 함수 호출은 25.4의 기본 Drawer 사용법을 바탕으로 이해하면 된다.

## 표현 방식 선택하기

원이나 직사각형처럼 간단한 요소는 Drawer의 기본 도형 함수로 직접 그리는 것이 간결하다. 꼭짓점과 제어점이 작품의 규칙에 따라 계산되거나, 여러 윤곽이 하나의 경계로 동작해야 한다면 `Vector2`, `Segment2D`, `ShapeContour`, `Shape`를 사용해 기하 데이터를 먼저 구성한다. 이 선택은 수학적 구조와 화면 표현을 분리할지에 달려 있다.

좌표를 모두 화면 공간에서 계산하면 변환 행렬이 필요 없는 대신, 회전·크기 변경 때 모든 점을 다시 계산해야 한다. 로컬 좌표와 변환을 사용하면 하나의 기본 형태를 여러 위치와 방향에 적용하기 쉽다. 반복 대상이 많아지면 기하의 재사용과 배치 렌더링을 함께 고려하고, 컬렉션을 통한 패턴 구성은 25.6에서 살펴본다.

## 이 절의 핵심

`Vector2`는 점과 이동량을 연산 가능한 값으로 표현하고, `Segment2D`·`ShapeContour`·`Shape`는 선분에서 복합 도형까지 기하 구조를 단계적으로 구성한다. `translate()`, `rotate()`, `scale()`은 로컬 좌표계를 변환하며, 행렬 합성 때문에 점에는 코드에서 보이는 순서의 역방향으로 적용된다. `drawer.isolated { }`로 변환과 스타일의 범위를 제한하면 각 도형의 배치를 독립적으로 설계할 수 있다.
