# 1.3 도형을 함수로 정의하기

앞 절에서는 이미지를 입력, 함수, 출력의 관계로 바라보았다. 이번 절에서는 그 관점을 도형에 적용한다. 일반적으로 도형은 화면에 그려진 대상처럼 보인다. 원, 선, 사각형, 삼각형은 각각 독립적인 그래픽 객체처럼 느껴진다. 하지만 제너레이티브 아트에서는 도형을 함수로 정의할 수도 있다.

도형을 함수로 정의한다는 말은, 화면의 한 점이 그 도형과 어떤 관계를 갖는지 계산한다는 뜻이다. 어떤 점이 원 안에 있는지 밖에 있는지, 선에서 얼마나 떨어져 있는지, 사각형의 경계에 가까운지 먼지 등을 함수로 판단한다. 이 관점에서는 도형이 더 이상 단순한 객체가 아니라, 좌표를 입력으로 받아 값을 출력하는 계산이 된다.

이 방식은 처음에는 낯설 수 있다. 예를 들어 p5.js에서는 `circle(x, y, diameter)`처럼 원을 그리는 명령이 이미 준비되어 있다. 하지만 셰이더나 프로시저럴 재질에서는 원을 직접 그리는 명령이 없는 경우가 많다. 대신 현재 좌표가 원의 중심에서 얼마나 떨어져 있는지 계산하고, 그 거리를 바탕으로 색을 정한다. 이때 원은 명령으로 그려진 객체가 아니라 거리 함수의 결과로 나타난다.

## 객체로서의 도형과 함수로서의 도형

객체로서의 도형은 그리는 명령으로 화면에 보여진다. 예를 들어 원은 중심 좌표와 반지름을 가진 객체이고 사각형은 위치와 너비, 높이를 가진 객체로 기술되며 이 직관적인 방식을 사용한 명령은 사용자가 도형을 배치하고 조작하기 쉽게 해준다.

함수로서의 도형은 좌표에 대한 판단을 통해 화면에 보여진다. 화면의 어떤 점 `p`가 있을 때, 함수는 그 점이 도형 안에 있는지, 밖에 있는지, 경계에서 얼마나 떨어져 있는지를 알려 준다. 점에 대한 함수의 결과값에 따라 도형의 모양이 표현되는 것이다.

```text
value = shape(p)
```

여기서 `p`는 좌표이고, `shape`는 도형을 정의하는 함수다. `value`는 여러 방식으로 해석될 수 있는데 가장 단순하게 0 또는 1일 수 있다. 1이면 도형 안쪽, 0이면 바깥쪽으로 정의하는 것이다. 혹은 거리값으로 사용하여 값이 0에 가까우면 경계에 가깝고, 값이 작거나 크면 안쪽이나 바깥쪽에 있다는 뜻으로 정의될 수 있다.

| 관점       | 도형의 의미               | 주로 사용하는 곳             |
| -------- | -------------------- | --------------------- |
| 객체로서의 도형 | 화면에 배치되는 그래픽 요소      | 드로잉 API, 벡터 그래픽, 레이아웃 |
| 함수로서의 도형 | 좌표를 입력으로 받아 값을 내는 규칙 | 셰이더, 거리장, 프로시저럴 패턴    |

도형을 만드는 두 방식은 서로 배타적이지 않다. p5.js에서도 도형을 함수처럼 생각할 수 있고, 셰이더에서도 도형의 중심과 크기를 객체의 속성처럼 관리할 수 있다.

## 원을 함수로 정의하기

가장 이해하기 쉬운 도형인 원을 이용해 함수로 도형을 그리는 원리를 이해해보자. 원은 중심점에서 같은 거리에 있는 점들의 집합이다. 어떤 점이 원 안에 있는지 알고 싶다면, 그 점과 중심점 사이의 거리를 계산하면 된다. 수식으로 쓰면 다음과 같다.

```text
d = distance(p, center)
```

여기서 `p`는 현재 좌표, `center`는 원의 중심, `d`는 두 점 사이의 거리다. 반지름이 `r`일 때, `d < r`이면 점은 원 안에 있고, `d > r`이면 원 밖에 있다. 원을 “그리는 명령”이 아니라 “어떤 좌표가 중심에서 반지름보다 가까운지 판단하는 함수”로 표현할 수 있게 된다.

```glsl
float circle(vec2 p, vec2 center, float radius) {
    float d = distance(p, center);
    return step(d, radius);
}
```

위 셰이더 스타일로 쓴 코드 속 함수는 현재 좌표 `p`가 원 안에 있으면 1에 가까운 값을, 밖에 있으면 0에 가까운 값을 반환한다. 반환값을 색에 연결하면 원이 그려진다.

```glsl
float v = circle(p, vec2(0.5), 0.25);
vec3 color = vec3(v);
```

같은 원을 p5.js에서 객체로 그리면 `circle(width / 2, height / 2, 200)`처럼 쓸 수 있다. 함수로 정의하면 좌표마다 원 안인지 밖인지 계산한다. 결과는 같지만 사고방식은 다르다는 것을 볼 수 있다.

## 경계는 값의 변화로 만들어진다

도형을 함수로 정의하면 경계를 더 섬세하게 다룰 수 있다. 원 안쪽을 1, 바깥쪽을 0으로 갑자기 나누면 경계가 딱딱하게 생긴다. 하지만 거리값을 이용하면 경계 주변을 부드럽게 만들 수 있다.

```glsl
float d = distance(p, center);
float v = smoothstep(radius, radius - softness, d);
```

`smoothstep`은 두 값 사이를 부드럽게 보간하는 함수다. 이 함수를 사용하면 원의 가장자리가 계단처럼 끊기지 않고 자연스럽게 사라진다. 즉 도형의 경계는 단순한 선이 아니라, 값이 변화하는 구간이 된다. 이 개념은 앞으로 계속 중요하게 쓰인다. 외곽선, 채움, 그림자, 글로우, 마스크, 블렌딩은 모두 경계 주변의 값을 어떻게 처리하느냐와 관련이 있다. 도형을 함수로 보면 이런 효과를 같은 방식으로 설명할 수 있다.

## 선과 사각형도 함수가 될 수 있다

원 뿐만 아니라 선, 사각형, 다각형도 좌표와의 관계를 계산하는 함수로 볼 수 있다.

선은 어떤 점이 선에 얼마나 가까운지를 계산해 정의할 수 있다. 선분이라면 점에서 선분까지의 최단 거리를 구한다. 그 거리가 일정한 두께보다 작으면 선이 보이고, 크면 보이지 않는다.

```text
d = distanceToSegment(p, a, b)
visible = d < thickness
```

여기서 `a`와 `b`는 선분의 양 끝점이다. 이 방식으로 보면 선은 무한히 얇은 기하학적 대상이 아니라, 일정한 두께를 가진 영역이 된다. 두께를 바꾸면 선이 굵어지고, 거리값을 색에 연결하면 선 주변에 그라데이션을 만들 수 있다.

사각형도 좌표의 범위로 정의할 수 있다. 어떤 점의 x좌표가 왼쪽과 오른쪽 경계 사이에 있고, y좌표가 위쪽과 아래쪽 경계 사이에 있으면 그 점은 사각형 안에 있다.

```text
insideX = left < x < right
insideY = top < y < bottom
inside = insideX and insideY
```

셰이더에서는 이런 판단을 `step` 함수의 조합으로 만들 수 있다. 더 나아가 중심점과 크기를 기준으로 사각형까지의 거리 함수를 만들면 둥근 사각형이나 부드러운 경계도 쉽게 만들 수 있다. 이 내용은 뒤의 거리 함수와 SDF 장에서 더 자세히 다룬다.

## 함수로 정의한 도형은 조합하기 쉽다

도형을 함수값으로 다루면 여러 도형을 조합하기 쉬워진다. 예를 들어 원 함수가 0 또는 1을 반환하고, 사각형 함수도 0 또는 1을 반환한다고 하자. 두 값을 더하거나, 곱하거나, 최댓값과 최솟값을 취하면 새로운 형태를 만들 수 있다.

```text
circleValue = circle(p)
boxValue = box(p)

union = max(circleValue, boxValue)
intersection = min(circleValue, boxValue)
difference = circleValue * (1 - boxValue)
```

이런 방식은 레이어를 겹치는 것과 비슷해 보이지만, 실제로는 값의 조합이다. 도형이 픽셀마다 계산되는 값이라면 그 값들을 수학적으로 합성할 수 있다. 두 도형의 합집합, 교집합, 차집합뿐 아니라 부드러운 전환이나 마스크 효과도 만들 수 있다.

이 개념을 셰이더와 SDF에서 사용하면 간단한 거리 함수들을 조합해 새로운 형태를 만들 수 있다. 원, 사각형, 선, 반복 좌표, 회전 변환을 조합하면 많은 패턴이 만들어진다.

## 도형 함수의 출력은 여러 방식으로 사용할 수 있다

도형 함수의 출력을 반드시 색으로만 연결할 필요는 없다. 원 안이면 흰색, 밖이면 검은색으로 칠하고 끝낼 수도 있지만 같은 값을 투명도, 크기, 변위, 입자의 힘, 재질 속성에도 연결할 수 있다.

예를 들어 원 함수의 값이 1이면 도형 안쪽, 0이면 바깥쪽이라고 하자. 이 값을 알파 값으로 쓰면 마스크가 된다. 이 값을 입자의 속도에 곱하면 원 안에서만 움직임이 나타나게 할 수 있다. 이 값을 3D 표면의 변위에 연결하면 원형으로 솟아오른 패턴을 만들 수 있다.

| 도형 함수의 출력 | 연결 대상 | 결과 |
| --- | --- | --- |
| 안/밖 값 | 색 | 채워진 도형 |
| 거리값 | 밝기 | 부드러운 그라데이션 |
| 경계 근처 값 | 알파 | 마스크와 페이드 |
| 거리 변화 | 변위 | 표면의 높낮이 |
| 도형 내부 여부 | 힘 또는 속도 | 특정 영역에서만 움직이는 입자 |

이처럼 도형을 함수로 정의하면 도형은 단순히 보이는 모양이 아니라 다른 계산을 제어하는 값이 된다. 이는 뒤에서 필드, 마스크, 입자 시스템, 프로시저럴 재질을 다룰 때 중요한 기반이 된다.

## 드로잉 명령과 도형 함수의 선택

그렇다면 언제 드로잉 명령을 쓰고, 언제 도형 함수를 써야 할까? 정답은 작업의 성격에 따라 달라진다.

도형을 명확하게 배치하고 싶거나, 많은 요소를 객체처럼 관리해야 한다면 드로잉 API의 도형 명령이 적합하다. 예를 들어 p5.js로 포스터형 구성, 인터랙티브 스케치, 입자 표현을 만들 때는 `circle()`, `line()`, `rect()` 같은 함수가 편리하다. 반면 픽셀 단위 패턴, 부드러운 경계, 마스크, 거리 기반 변형, 프로시저럴 텍스처를 만들고 싶다면 도형을 함수로 정의하는 방식이 유리하다. 특히 셰이더에서는 거의 모든 것이 좌표를 입력으로 한 함수 계산으로 이루어진다.

| 상황                    | 적합한 접근      |
| --------------------- | ----------- |
| 개별 도형을 배치하고 관리할 때     | 드로잉 명령      |
| 픽셀마다 색을 계산할 때         | 도형 함수       |
| 경계와 그라데이션을 섬세하게 제어할 때 | 거리 함수       |
| 여러 도형을 수학적으로 합성할 때    | 함수값 조합      |
| 3D 표면의 재질 패턴을 만들 때    | 좌표 기반 도형 함수 |

같은 작업 안에서도 객체로 그린 도형과 함수로 정의한 패턴이 함께 쓰일 수 있다는 점을 기억하자. 그 때 객체는 작업을 구성하는 단위가 되고, 함수는 그 내부의 색, 질감, 경계, 변화를 만든다.

## 이 절의 핵심

도형은 화면에 그려지는 객체일 수도 있지만, 좌표를 입력으로 받아 값을 출력하는 함수일 수도 있다. 원은 중심점과의 거리로 정의할 수 있고, 선은 선분까지의 거리로 정의할 수 있으며, 사각형은 좌표의 범위나 거리 함수로 정의할 수 있다.

도형을 함수로 바라보면 경계, 마스크, 그라데이션, 조합, 변형을 더 유연하게 다룰 수 있다. 이 관점은 셰이더, SDF, 프로시저럴 재질에서 특히 중요하지만, 일반적인 드로잉 API에서도 유용하다.

다음 절에서는 이렇게 정의한 규칙을 어떻게 반복 가능하게 만들고, 어떤 파라미터를 통해 조절할 수 있는지 살펴본다. 제너레이티브 아트에서 중요한 것은 한 번 좋은 결과를 얻는 것만이 아니라, 그 결과를 다시 만들고 변주할 수 있는 구조를 갖추는 것이다.
