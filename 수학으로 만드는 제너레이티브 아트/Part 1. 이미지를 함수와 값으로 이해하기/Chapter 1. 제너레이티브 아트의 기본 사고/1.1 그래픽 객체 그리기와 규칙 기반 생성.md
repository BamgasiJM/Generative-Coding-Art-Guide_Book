# 1.1 그래픽 객체 그리기와 규칙 기반 생성

그래픽 프로그래밍을 처음 배울 때 가장 자연스러운 방식은 화면에 도형을 하나씩 그리는 것이다. 배경색을 정하고, 선을 긋고, 원을 그리고, 사각형을 배치한다. 이 방식에서는 화면에 나타나는 각각의 요소가 작업의 기본 단위가 된다. 원 하나, 선 하나, 사각형 하나가 독립적인 그래픽 객체처럼 다루어진다.

예를 들어 화면 가운데에 원을 하나 그리고 싶다면 우리는 보통 원의 중심 좌표와 크기를 정한다. 그다음 `circle()`이나 `ellipse()` 같은 함수를 호출한다. 사각형을 그리고 싶다면 왼쪽 위 좌표와 너비, 높이를 정한다. 선을 그리고 싶다면 시작점과 끝점을 지정한다. 이 방식은 명확하다. 무엇을 어디에 그릴지 직접 말하면, 화면에는 그에 해당하는 형태가 나타난다.

이런 객체 중심의 드로잉은 그래픽 프로그래밍의 중요한 출발점이다. 대부분의 드로잉 API는 실제로 이런 방식으로 설계되어 있다. p5.js, Processing, raylib, openFrameworks 같은 환경에서는 원, 선, 사각형, 다각형, 이미지, 텍스처 같은 단위를 명령으로 화면에 보낸다. 이때 코드는 하나의 지시문처럼 읽힌다. 다음은 p5.js로 작성한 예제다.

**p5.js 예제**

```javascript
background(255);
fill(0);
circle(300, 200, 80);
line(100, 100, 500, 300);
rect(220, 260, 160, 90);
```

이 코드는 “배경을 칠하고, 원을 그리고, 선을 그리고, 사각형을 그린다”는 순서로 이해할 수 있다. 화면의 결과는 코드의 명령 순서와 밀접하게 연결된다. 이러한 방식은 개별 요소를 정확히 배치하고 싶을 때 매우 유용하다. 포스터의 레이아웃을 잡거나, 인터페이스 요소를 배치하거나, 특정한 구성을 직접 설계할 때 객체 중심 드로잉은 직관적이고 강력하다.

하지만 제너레이티브 아트에서는 여기서 한 걸음 더 나아간다. 목표는 단순히 원 하나를 그리는 것이 아니라, 원들이 만들어지는 조건을 정하는 것이다. 선 하나를 그리는 것이 아니라, 선들이 어디에서 시작하고 어디로 향하는지 결정하는 규칙을 만드는 것이다. 다시 말해 화면의 개별 객체보다, 객체를 만들어 내는 관계와 절차가 중요해진다.

## 객체를 직접 배치하는 방식

객체 중심 드로잉에서는 결과를 구성하는 요소를 하나씩 지정한다. 이 방식의 질문은 대체로 다음과 같다.

- 이 도형은 어디에 놓을 것인가?
- 크기는 얼마인가?
- 색은 무엇인가?
- 어떤 순서로 그릴 것인가?
- 다른 도형 위에 올라갈 것인가, 아래에 깔릴 것인가?

이 질문들은 모두 개별 도형을 기준으로 한다. 원을 하나 그릴 때는 그 원의 위치와 반지름을 정한다. 원을 열 개 그릴 때는 열 개의 위치와 반지름을 정한다. 물론 반복문을 사용할 수도 있지만, 반복문 안에서도 핵심은 “몇 번째 도형을 어디에 그릴 것인가”라는 배치의 문제다.

예를 들어 원 다섯 개를 가로로 나란히 배치한다고 해 보자.

**p5.js 예제**

```javascript
circle(100, 200, 40);
circle(180, 200, 40);
circle(260, 200, 40);
circle(340, 200, 40);
circle(420, 200, 40);
```

이 코드는 이해하기 쉽다. 하지만 원의 개수가 늘어나거나 간격이 바뀌면 코드를 계속 수정해야 한다. 원을 5개가 아니라 50개로 만들고 싶다면 같은 패턴을 반복해야 한다. 이때 반복문을 사용하면 코드가 짧아진다.

**p5.js 예제**

```javascript
for (let i = 0; i < 5; i++) {
  circle(100 + i * 80, 200, 40);
}
```

여기서 중요한 변화가 일어난다. 이제 우리는 원의 좌표를 하나씩 적지 않는다. 대신 `i`라는 반복 인덱스를 이용해 위치를 계산한다. 원의 x좌표는 `100 + i * 80`이라는 규칙으로 정해진다. 이 작은 변화가 제너레이티브 아트의 출발점이다. 화면 위의 결과를 직접 나열하는 대신, 결과를 만들어 내는 규칙을 작성하기 시작했기 때문이다.

물론 이 예시는 아직 단순하다. 하지만 같은 생각을 확장하면 훨씬 복잡한 이미지를 만들 수 있다. 원의 y좌표를 사인 함수로 바꿀 수 있고, 크기를 중심점과의 거리로 정할 수 있으며, 색을 노이즈 값으로 바꿀 수 있다. 원의 개수, 간격, 크기, 색, 움직임은 더 이상 고정된 값이 아니라 계산되는 값이 된다.

## 규칙으로 생성하는 방식

규칙 기반 생성에서는 도형 하나하나보다 도형을 만드는 계산이 중요하다. 여기서 질문은 조금 달라진다.

- 위치는 어떤 값으로부터 계산되는가?
- 크기는 무엇에 따라 달라지는가?
- 색은 어떤 범위의 값을 시각적으로 바꾼 것인가?
- 반복되는 구조가 있다면 그 반복의 단위는 무엇인가?
- 변화가 필요하다면 어떤 파라미터를 조절할 것인가?

객체 중심 드로잉이 “무엇을 어디에 그릴 것인가”를 묻는다면, 규칙 기반 생성은 “무엇이 무엇을 결정하는가”를 묻는다. 이 차이는 작아 보이지만 작업 방식 전체를 바꾼다. 이미지는 더 이상 손으로 배치한 요소들의 목록이 아니라, 입력값과 규칙이 만들어 낸 결과가 된다.

다시 원의 예로 돌아가 보자. 원 다섯 개를 나란히 그리는 대신, 원의 위치와 크기를 모두 규칙으로 만들 수 있다.

**p5.js 예제**

```javascript
for (let i = 0; i < count; i++) {
  let x = 100 + i * spacing;
  let y = height / 2;
  let diameter = 20 + i * 5;
  circle(x, y, diameter);
}
```

이 코드에서 원의 개수는 `count`, 간격은 `spacing`, 크기 변화는 `i * 5`에 의해 결정된다. 즉 결과 이미지는 여러 파라미터의 조합으로 만들어진다. `count`를 바꾸면 원의 개수가 달라지고, `spacing`을 바꾸면 밀도가 달라지며, 크기 계산식을 바꾸면 전체 리듬이 바뀐다.

이때 우리는 원을 직접 조작하는 것이 아니라, 원이 만들어지는 조건을 조작한다. 이것이 규칙 기반 생성의 핵심이다.

규칙은 반드시 복잡할 필요가 없다. 오히려 많은 제너레이티브 이미지는 단순한 규칙에서 시작한다. 일정한 간격으로 점을 배치한다. 화면 중심에서 멀어질수록 크기를 줄인다. 왼쪽에서 오른쪽으로 갈수록 색을 바꾼다. 프레임이 지날수록 각도를 조금씩 회전시킨다. 이런 규칙들은 하나씩 보면 단순하지만, 서로 결합되면 풍부한 시각적 결과를 만든다.

## 객체와 규칙은 서로 반대가 아니다

여기서 조심해야 할 점이 있다. 객체 중심 드로잉이 낮은 수준의 방식이고, 규칙 기반 생성이 더 높은 수준의 방식이라는 뜻은 아니다. 두 방식은 서로 경쟁하지 않는다. 대부분의 실제 작업에서는 두 방식이 함께 쓰인다.

드로잉 API에서는 여전히 원, 선, 사각형 같은 객체를 그린다. 다만 그 객체의 위치, 크기, 색, 회전, 개수, 생성 시점이 규칙에 의해 정해진다. 즉 객체는 결과를 화면에 표시하는 단위이고, 규칙은 그 객체의 속성을 결정하는 구조다.

다음 표는 두 관점의 차이를 간단히 정리한 것이다.

| 관점 | 중심 질문 | 코드에서 주로 다루는 것 | 결과의 성격 |
| --- | --- | --- | --- |
| 객체 중심 드로잉 | 무엇을 어디에 그릴 것인가? | 도형, 좌표, 색, 그리기 순서 | 직접 배치된 이미지 |
| 규칙 기반 생성 | 무엇이 무엇을 결정하는가? | 반복, 함수, 파라미터, 조건 | 계산으로 생성된 이미지 |

예를 들어 나무를 그린다고 생각해 보자. 객체 중심으로 접근하면 줄기, 가지, 잎을 하나씩 배치한다. 규칙 기반으로 접근하면 줄기가 어느 지점에서 몇 개의 가지로 갈라지는지, 가지의 길이가 얼마나 줄어드는지, 각도가 어느 범위에서 변하는지, 어느 깊이까지 반복할 것인지 정한다. 화면에는 여전히 선과 잎 모양이 그려지지만, 그 배치는 규칙이 만든다.

격자 패턴도 마찬가지다. 객체 중심으로 보면 많은 사각형을 배치한 이미지다. 규칙 중심으로 보면 좌표를 일정한 크기의 셀로 나누고, 각 셀 안에서 도형의 위치와 색을 계산한 결과다. 같은 결과라도 어떤 관점에서 보느냐에 따라 이후의 확장 가능성이 달라진다.

## 직접 지정한 값에서 계산된 값으로

제너레이티브 아트의 중요한 전환 중 하나는 직접 지정한 값을 계산된 값으로 바꾸는 것이다. 처음에는 `x = 100`, `y = 200`, `r = 40`처럼 구체적인 숫자를 사용한다. 그러나 규칙을 만들기 시작하면 이 숫자들은 다른 값으로부터 계산된다. 다음 표의 표현은 특정 언어의 문법이 아니라 계산 관계를 나타내는 의사코드다.

예를 들어 x좌표는 반복 인덱스로부터 계산될 수 있다. y좌표는 사인 함수로부터 계산될 수 있다. 반지름은 마우스 위치나 시간값으로부터 계산될 수 있다. 색은 노이즈나 거리값으로부터 계산될 수 있다.

| 직접 지정한 값 | 계산된 값의 예 |
| --- | --- |
| `x = 100` | `x = margin + i * spacing` |
| `y = 200` | `y = height / 2 + sin(t) * amplitude` |
| `r = 40` | `r = remap(distanceToCenter, 0, maxDistance, 60, 10)` |
| `color = black` | `color = interpolateColor(colorA, colorB, noiseValue)` |

이 변화는 단순히 코드를 효율적으로 만드는 일이 아니다. 값이 계산되기 시작하면 이미지가 하나의 구조를 갖게 된다. 같은 규칙을 다른 입력에 적용할 수 있고, 파라미터를 바꾸어 다양한 결과를 만들 수 있으며, 시간이나 사용자 입력을 연결해 움직임을 만들 수 있다.

직접 지정한 값은 한 번 정하면 고정된다. 계산된 값은 조건이 바뀌면 함께 바뀐다. 제너레이티브 아트는 바로 이 성질을 적극적으로 사용한다.

## 반복은 복사가 아니라 관계를 만든다

반복문은 제너레이티브 아트에서 매우 자주 쓰인다. 하지만 반복문을 단순히 같은 도형을 여러 번 복사하는 도구로만 보면 그 가능성을 충분히 사용할 수 없다. 반복의 핵심은 “몇 번째인가”라는 정보를 통해 각 요소가 서로 다른 값을 갖게 하는 데 있다.

반복 인덱스 `i`는 단순한 번호가 아니다. 그것은 위치가 될 수 있고, 시간 차이가 될 수 있으며, 크기 변화의 기준이 될 수 있다. 두 개의 반복 인덱스 `x`, `y`를 사용하면 격자를 만들 수 있고, 셀의 위치에 따라 색이나 형태를 다르게 만들 수 있다. 반복은 같은 것을 늘어놓는 방식이 아니라, 요소들 사이의 관계를 만드는 방식이다.

예를 들어 가로 방향으로 반복되는 원들이 있다고 하자. 모든 원의 크기가 같다면 단순한 나열이 된다. 하지만 왼쪽에서 오른쪽으로 갈수록 크기가 커진다면 방향성이 생긴다. 중심에 가까울수록 커지고 가장자리로 갈수록 작아진다면 공간의 중심성이 생긴다. 각 원의 크기가 노이즈 값으로 정해진다면 불규칙하지만 연결된 질감이 생긴다.

이처럼 반복 구조에서 중요한 것은 개수 자체가 아니다. 반복되는 요소들이 어떤 규칙으로 서로 달라지는지가 더 중요하다. 같은 형태를 반복하더라도 값의 변화가 있으면 패턴이 되고, 변화의 규칙이 있으면 구조가 된다.

## 제어와 우연 사이에서 작업하기

규칙 기반 생성은 모든 것을 자동으로 만드는 방식처럼 보일 수 있다. 그러나 실제로는 매우 섬세한 제어가 필요하다. 규칙을 만든다는 것은 결과를 포기하는 일이 아니라, 결과가 나올 수 있는 범위와 조건을 정하는 일이다.

랜덤을 사용하는 경우를 생각해 보자. 원의 위치를 무작위로 정하면 매번 다른 이미지가 나온다. 하지만 위치의 범위, 원의 개수, 최소 거리, 크기 분포, 색의 범위를 정하지 않으면 결과는 쉽게 산만해진다. 좋은 규칙은 우연을 허용하지만, 아무 결과나 받아들이지는 않는다.

제너레이티브 아트에서 작가는 직접 모든 요소를 배치하지 않는다. 대신 시스템이 어떤 선택을 할 수 있는지 정한다. 어떤 값은 고정하고, 어떤 값은 범위 안에서 변하게 하고, 어떤 값은 다른 값에 따라 달라지게 한다. 이때 작가의 역할은 도형을 하나씩 놓는 사람에서, 변화가 일어나는 조건을 설계하는 사람으로 바뀐다.

이 관점은 작업 과정을 더 실험적으로 만든다. 규칙을 조금 바꾸면 결과 전체가 달라질 수 있다. 반복 간격을 바꾸면 밀도가 달라지고, 노이즈의 스케일을 바꾸면 질감이 달라지며, 시간값을 더하면 정적인 이미지가 움직이는 시스템으로 바뀐다. 하나의 완성된 결과보다, 결과를 만들어 내는 가능성의 공간이 중요해진다.

## 그래픽 환경에 따라 달라지는 표현 방식

객체와 규칙의 관계는 그래픽 환경에 따라 다르게 표현된다. p5.js나 Processing 같은 드로잉 API에서는 반복문 안에서 도형 그리기 함수를 호출하는 방식이 흔하다. 이때 규칙은 주로 도형의 위치, 크기, 색, 회전을 계산하는 데 사용된다.

반면 GLSL 같은 프래그먼트 셰이더에서는 화면의 각 픽셀이 스스로 자신의 색을 계산한다. 여기서는 원을 “그린다”기보다, 현재 픽셀이 원 안에 있는지 밖에 있는지를 판단한다. 객체를 배치하는 방식보다 좌표와 함수로 이미지를 정의하는 방식이 더 강하게 드러난다.

OSL처럼 표면 재질을 계산하는 환경에서는 화면이 아니라 표면 위의 점이 기본 단위가 된다. 같은 원형 패턴이라도 캔버스 위의 원이 아니라, 물체 표면의 색이나 변위로 나타날 수 있다. 즉 규칙은 그대로이지만 그 규칙이 적용되는 공간이 달라진다.

이 책이 여러 그래픽 환경을 함께 다루는 이유가 여기에 있다. 중요한 것은 특정 함수 이름 하나를 외우는 것이 아니라, 어떤 환경에서든 “값을 계산하고 그 값을 시각 요소로 바꾼다”는 공통 구조를 이해하는 것이다.

## 이 절의 핵심

그래픽 객체 그리기는 화면에 나타날 요소를 직접 지정하는 방식이다. 규칙 기반 생성은 그 요소들이 만들어지는 조건을 설계하는 방식이다. 제너레이티브 아트에서는 두 방식이 함께 쓰인다. 객체는 화면에 나타나는 결과의 단위가 되고, 규칙은 그 객체의 속성과 변화를 결정한다.

이 절에서 가장 중요한 전환은 직접 배치에서 계산으로 이동하는 것이다. 위치를 직접 적는 대신 위치를 계산하고, 크기를 고정하는 대신 크기가 변하는 규칙을 만들고, 색을 하나로 정하는 대신 값에 따라 색이 달라지게 한다. 이 전환이 이루어지면 이미지는 고정된 구성이 아니라 조절 가능한 시스템이 된다.

다음 절에서는 이 생각을 조금 더 일반화한다. 이미지를 입력, 함수, 출력의 관계로 바라보면 제너레이티브 아트의 많은 구조를 더 명확하게 설명할 수 있다. 화면에 나타나는 모든 결과는 어떤 입력값이 규칙을 통과해 나온 출력으로 볼 수 있다.
