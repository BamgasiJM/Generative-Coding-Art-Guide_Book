# 1.1 그래픽 객체 그리기와 규칙 기반 생성

그래픽 프로그래밍을 시작할 때는 화면에 도형을 하나씩 그리는 경우가 많다. 배경색을 정하고 선을 긋고, 원과 사각형을 배치한다. 이때 원 하나, 선 하나, 사각형 하나가 각각 작업의 기본 단위가 된다.

화면 가운데 원을 놓으려면 중심 좌표와 지름을 정한 뒤 `circle()`이나 `ellipse()`를 호출한다. 사각형에는 왼쪽 위 좌표와 너비, 높이가 필요하고, 선에는 시작점과 끝점이 필요하다. 무엇을 어느 위치에 그릴지 명령하면 화면에 해당 형태가 나타난다.

객체 중심 드로잉은 그래픽 프로그래밍의 중요한 출발점이다. 대부분의 드로잉 API는 이런 방식으로 설계되어 있다. p5.js, Processing, OPENRNDR, openFrameworks에서는 원, 선, 사각형, 다각형, 이미지, 텍스처 같은 단위를 명령으로 화면에 보낸다. 코드는 그리기 지시의 순서로 읽힌다. 다음은 p5.js 예제다.

**p5.js 예제**

```javascript
background(255);
fill(0);
circle(300, 200, 80);
line(100, 100, 500, 300);
rect(220, 260, 160, 90);
```

배경을 칠하고 도형 색을 정한 다음 원, 선, 사각형을 그리는 순서다. 각 요소를 원하는 위치에 정확히 놓을 수 있어 포스터 레이아웃이나 인터페이스, 구성이 분명한 이미지에 잘 맞는다.

제너레이티브 아트에서는 개별 도형을 그리는 데서 나아가 도형이 만들어지는 조건을 정한다. 원을 하나 놓는 대신 원들이 어디에 생길지 정하고, 선 하나의 양 끝을 지정하는 대신 선들의 시작점과 방향을 결정하는 규칙을 만든다. 화면의 객체만큼 그 객체 사이의 관계와 생성 절차가 중요해진다.

## 객체를 직접 배치하는 방식

객체 중심 드로잉에서는 이미지를 구성하는 요소를 하나씩 지정한다. 작업하면서 다음과 같은 질문을 하게 된다.

- 이 도형은 어디에 놓을 것인가?
- 크기는 얼마인가?
- 색은 무엇인가?
- 어떤 순서로 그릴 것인가?
- 다른 도형 위에 올라갈 것인가, 아래에 깔릴 것인가?

원 하나에는 위치와 반지름을 정하고, 원 열 개에는 각 원의 위치와 반지름을 정한다. 반복문을 사용하더라도, 각 반복에서 몇 번째 도형을 어디에 놓을지가 중심이 된다.

p5.js에서 원 다섯 개를 가로로 배치하는 코드는 다음과 같다.

```javascript
circle(100, 200, 40);
circle(180, 200, 40);
circle(260, 200, 40);
circle(340, 200, 40);
circle(420, 200, 40);
```

배치는 한눈에 들어온다. 다만 원의 수나 간격을 바꾸려면 해당 좌표들을 수정해야 한다. 다섯 개를 쉰 개로 늘릴 때도 같은 명령을 계속 적는 대신 반복문으로 중복을 줄일 수 있다.

```javascript
for (let i = 0; i < 5; i++) {
  circle(100 + i * 80, 200, 40);
}
```

이제 각 좌표를 따로 적지 않고 반복 인덱스 `i`로 위치를 계산한다. 원의 x좌표는 `100 + i * 80`이라는 규칙을 따른다. 결과를 하나씩 나열하던 코드가 결과를 만들어 내는 규칙을 기술하기 시작한다. 이런 전환이 제너레이티브 아트의 출발점이다.

이 단순한 규칙은 더 복잡한 이미지로 확장할 수 있다. y좌표를 사인 함수로 계산하고, 크기를 중심과의 거리로 정하거나, 색을 노이즈 값에 연결할 수 있다. 원의 수와 간격, 크기, 색, 움직임도 고정된 수치 대신 계산 결과로 정해진다.

## 규칙으로 생성하는 방식

규칙 기반 생성에서는 도형을 하나씩 지정하기보다 도형을 만들어 내는 계산을 정한다. 질문도 달라진다.

- 위치는 어떤 값으로부터 계산되는가?
- 크기는 무엇에 따라 달라지는가?
- 색은 어떤 범위의 값을 시각적으로 바꾼 것인가?
- 반복되는 구조가 있다면 그 반복의 단위는 무엇인가?
- 변화가 필요하다면 어떤 파라미터를 조절할 것인가?

객체 중심 드로잉은 “무엇을 어디에 그릴 것인가?”를 묻고, 규칙 기반 생성은 “무엇이 무엇을 결정하는가?”를 묻는다. 작가가 정한 관계에 따라 이미지가 만들어지면서, 결과는 손으로 배치한 요소의 목록에서 입력값과 규칙이 만든 결과로 바뀐다.

원 다섯 개를 나란히 그리는 대신 위치와 크기를 계산하는 예를 보자.

```javascript
for (let i = 0; i < count; i++) {
  let x = 100 + i * spacing;
  let y = height / 2;
  let diameter = 20 + i * 5;
  circle(x, y, diameter);
}
```

원 개수는 `count`, 간격은 `spacing`이 정한다. 지름은 `i * 5`만큼 순번에 따라 커진다. 결과 이미지는 이 파라미터들의 조합으로 만들어진다. `count`를 바꾸면 원의 수가 달라지고, `spacing`을 바꾸면 배열의 밀도가 바뀐다. 지름의 계산식을 조정하면 배열의 리듬도 달라진다.

여기서는 원 하나하나를 따로 조작하지 않고 원이 만들어지는 조건을 조작한다. 이것이 규칙 기반 생성의 핵심이다. 많은 제너레이티브 이미지는 이처럼 단순한 규칙에서 시작한다.

## 객체와 규칙은 경쟁하지 않는다

객체 중심 드로잉이 낮은 단계이고 규칙 기반 생성이 높은 단계라는 뜻은 아니다. 두 방식은 경쟁하지 않으며, 실제 작업에서는 함께 쓰이는 경우가 많다.

| 관점 | 중심 질문 | 코드에서 주로 다루는 것 | 결과의 성격 |
| --- | --- | --- | --- |
| 객체 중심 드로잉 | 무엇을 어디에 그릴 것인가? | 도형, 좌표, 색, 그리기 순서 | 직접 배치된 이미지 |
| 규칙 기반 생성 | 무엇이 무엇을 결정하는가? | 반복, 함수, 파라미터, 조건 | 계산으로 생성된 이미지 |

나무를 객체 중심으로 그리면 줄기와 가지, 잎을 하나씩 배치한다. 규칙 중심으로 그릴 때는 줄기가 갈라지는 지점과 가지의 수, 길이 감소량, 각도의 변화 범위, 반복 깊이를 정한다. 화면에는 여전히 선과 잎 모양이 나타나지만 배치는 규칙에서 나온다.

격자 패턴도 사각형을 많이 배치한 이미지로 볼 수 있고, 좌표를 일정한 크기의 셀로 나눈 뒤 각 셀 안의 도형 위치와 색을 계산한 결과로 볼 수도 있다. 결과가 같아도 어떤 관점으로 기술하느냐에 따라 확장하는 방법은 달라진다.

## 직접 지정한 값에서 계산된 값으로

제너레이티브 아트에서는 직접 입력한 값을 다른 값으로부터 계산하도록 바꾸곤 한다. 처음에는 `x = 100`, `y = 200`, `r = 40`처럼 구체적인 숫자를 쓴다. 규칙을 만들면 x좌표는 반복 인덱스에서, y좌표는 사인 함수에서, 반지름은 마우스 위치나 시간값에서 계산할 수 있다. 색은 노이즈나 거리값에 따라 정해질 수도 있다. 다음 표는 특정 언어의 문법이 아니라 계산 관계를 나타낸 의사코드다.

| 직접 지정한 값 | 계산된 값의 예 |
| --- | --- |
| `x = 100` | `x = margin + i * spacing` |
| `y = 200` | `y = height / 2 + sin(t) * amplitude` |
| `r = 40` | `r = remap(distanceToCenter, 0, maxDistance, 60, 10)` |
| `color = black` | `color = interpolateColor(colorA, colorB, noiseValue)` |

이렇게 관계를 정해 두면 같은 규칙을 다른 입력에 적용하거나 파라미터를 바꿔 결과를 변형할 수 있다. 시간이나 사용자 입력을 연결하면 움직임도 만들 수 있다.

직접 지정한 값은 그대로 유지되지만, 계산된 값은 조건이 바뀔 때 함께 달라진다. 제너레이티브 아트는 이 성질을 활용한다.

## 반복은 복사가 아니라 관계를 만든다

반복문은 제너레이티브 아트에서 자주 쓰인다. 핵심은 같은 동작을 여러 번 실행하는 데 그치지 않고, “몇 번째인가”라는 정보를 이용해 요소마다 다른 값을 정하는 데 있다.

반복 인덱스 `i`는 위치나 시간 차이, 크기 변화의 기준이 될 수 있다. 두 개의 반복 인덱스 `x`, `y`를 사용하면 격자를 만들고, 셀의 위치에 따라 색과 형태를 다르게 정할 수 있다.

가로로 원을 반복해 그릴 때 모든 원의 크기가 같으면 나열이 된다. 한쪽으로 갈수록 크기를 키우면 방향이 생기고, 중심에 가까운 원을 크게 하면 화면에 시선이 모인다. 각 원의 크기를 노이즈 값으로 정하면 불규칙하면서도 이어지는 질감이 생긴다.

같은 형태를 반복하면서 값이 달라지면 패턴이 되고, 그 변화가 규칙을 따르면 구조가 된다.

## 제어와 우연 사이에서 작업하기

규칙 기반 생성이 모든 것을 자동으로 처리하는 것은 아니다. 실제 작업에서는 세밀한 제어가 필요하다. 규칙을 설계한다는 것은 가능한 결과의 범위와 조건을 정하는 일이기도 하다.

원의 위치를 무작위로 정하면 실행할 때마다 이미지가 달라진다. 위치 범위와 원의 개수, 최소 거리, 크기 분포, 색 범위를 정하지 않으면 결과가 산만해질 수 있다. 좋은 규칙은 우연을 허용하면서도 아무 결과나 나오지 않도록 범위를 둔다.

작가는 모든 요소를 직접 배치하는 대신 시스템이 선택할 수 있는 조건을 정한다. 어떤 값은 고정하고, 어떤 값은 일정 범위 안에서 변하게 하며, 또 어떤 값은 다른 값에 따라 달라지게 한다. 작가의 역할은 도형을 하나씩 놓는 데서 변화가 일어나는 조건을 설계하는 쪽으로 옮겨간다. 규칙을 조금 바꾸면 결과 전체가 달라진다. 그 변화를 이용해 다양한 밀도와 질감, 애니메이션을 실험한다.

## 그래픽 환경에 따라 달라지는 표현 방식

객체와 규칙은 그래픽 환경마다 다른 방식으로 표현된다. p5.js나 Processing 같은 드로잉 API에서는 반복문 안에서 도형 그리기 함수를 호출하는 경우가 많다. 이때 규칙은 주로 도형의 위치와 크기, 색, 회전을 계산한다.

GLSL 같은 프래그먼트 셰이더에서는 화면의 각 픽셀이 자신의 색을 계산한다. 원을 그리기 위한 명령을 내리는 대신, 현재 픽셀이 원 안에 있는지 바깥에 있는지 판단한다. 좌표와 함수로 이미지를 정의하고 계산 결과를 색으로 표현한다.

OSL처럼 표면 재질을 계산하는 환경에서는 화면의 픽셀이 아니라 표면 위의 점이 기준이 된다. 같은 원형 패턴도 캔버스의 원이 아닌 물체 표면의 색이나 변위를 정하는 마스크로 쓰일 수 있다. 규칙 자체는 같아도 적용되는 공간이 달라진다.

## 이 절의 핵심

그래픽 객체 그리기는 화면에 나타낼 요소를 직접 지정하고, 규칙 기반 생성은 원하는 아트워크를 만들 요소의 조건을 정한다. 두 방식은 함께 쓰일 수 있다. 객체는 화면에 나타나는 결과의 단위이며, 규칙은 객체의 속성과 변화를 결정한다. 위치를 계산하고 크기가 변하는 규칙을 만들며 값에 따라 색을 바꾸면서 구조를 만들어 간다.

다음 절에서는 이 관계를 입력, 함수, 출력의 구조로 살펴본다. 화면에 나타나는 결과가 어떤 입력값에서 시작해 규칙을 거쳐 출력되는지 정리하면 제너레이티브 아트의 여러 구조를 더 분명하게 설명할 수 있다.
