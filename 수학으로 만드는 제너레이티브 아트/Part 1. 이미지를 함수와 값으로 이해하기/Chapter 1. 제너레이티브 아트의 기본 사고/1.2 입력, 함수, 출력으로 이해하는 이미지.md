# 1.2 입력, 함수, 출력으로 이해하는 이미지

앞 절에서는 그래픽 객체를 하나씩 배치하는 방식에서, 객체를 만들어 내는 규칙을 설계하는 방식으로 관점을 옮겼다. 이번 절에서는 그 규칙을 조금 더 일반적인 형태로 바라본다. 제너레이티브 아트에서 이미지는 입력, 함수, 출력의 관계로 이해할 수 있다.

여기서 입력은 함수가 받아들이는 값이다. 좌표, 시간, 마우스 위치, 반복 인덱스, 랜덤 값, 노이즈 값, 이미지의 픽셀 값 등이 입력이 될 수 있다. 함수는 입력을 변환하는 규칙이다. 출력은 그 결과로 얻어지는 값이다. 출력은 색이 될 수도 있고, 도형의 위치나 크기, 회전각, 투명도, 속도, 밀도, 재질 속성이 될 수도 있다.

이렇게 생각하면 이미지는 단순히 화면에 놓인 도형의 모음이 아니다. 이미지는 많은 입력값이 여러 함수를 통과해 시각적인 출력으로 바뀐 결과다. 화면의 모든 점, 반복되는 모든 도형, 시간에 따라 변하는 모든 프레임은 어떤 입력과 함수의 결과로 볼 수 있다.

## 이미지를 계산 결과로 보기

프로그래밍에서 함수는 입력을 받아 출력을 반환한다. 수학에서도 함수는 어떤 값을 다른 값으로 대응시킨다. 그래픽에서도 같은 생각을 사용할 수 있다. 예를 들어 다음과 같은 아주 단순한 함수를 생각해 보자.

$$
B=f(x)
$$

이 식은 x좌표를 입력으로 받아 밝기 값을 출력한다는 뜻이다. x좌표가 작을 때는 어둡고, x좌표가 클 때는 밝아지게 만들 수 있다. 그러면 화면은 왼쪽에서 오른쪽으로 밝아지는 그라데이션이 된다.

조금 더 구체적으로 쓰면 다음과 같다.

$$
B=\frac{x}{W}
$$

여기서 $x$는 현재 위치의 x좌표이고, $W$는 화면의 너비다. $x$가 0이면 밝기 $B$는 0이 되고, $x$가 화면 오른쪽 끝에 가까워지면 1에 가까워진다. 이 값을 일반적인 8비트 밝기 범위로 바꾸려면 255를 곱한다.

$$
G=255B=255\frac{x}{W}
$$

이 예시는 단순하지만 중요한 관점을 보여 준다. 화면의 밝기는 직접 칠한 값이 아니라 좌표로부터 계산된 값이다. 좌표가 입력이고, 나눗셈이 함수이며, 밝기가 출력이다.

제너레이티브 아트의 많은 구조가 이와 같은 방식으로 만들어진다. 중심점에서의 거리를 계산해 원을 만들고, 각도를 계산해 방사형 패턴을 만들고, 시간값을 넣어 파동을 움직이고, 노이즈 값을 사용해 표면의 질감을 만든다. 어떤 경우든 핵심은 입력값을 시각적인 출력으로 바꾸는 함수다.

## 입력에는 여러 종류가 있다

입력은 반드시 하나의 숫자일 필요가 없다. 그래픽 작업에서 입력은 매우 다양하다. 화면 좌표처럼 공간을 나타내는 값도 있고, 시간처럼 변화를 나타내는 값도 있다. 마우스나 키보드 입력처럼 사용자의 행동을 반영하는 값도 있으며, 랜덤이나 노이즈처럼 예측하기 어려운 변화를 제공하는 값도 있다.

| 입력의 종류 | 예 | 주로 만드는 결과 |
| --- | --- | --- |
| 좌표 | `x`, `y`, `uv`, `position` | 위치 기반 색, 패턴, 도형 |
| 시간 | 경과 시간, 프레임 번호, 프레임 간 시간 | 애니메이션, 반복 루프, 변화 |
| 반복 인덱스 | `i`, `row`, `col` | 배열, 격자, 순차적 변화 |
| 사용자 입력 | 마우스 위치, 키 입력, 센서 값 | 인터랙션, 실시간 조절 |
| 랜덤 값 | 난수, 시드 기반 랜덤 | 불규칙한 배치, 변주 |
| 노이즈 값 | Perlin Noise, Simplex Noise | 연속적인 질감, 유기적 변화 |
| 외부 데이터 | 이미지, 사운드, 텍스트, CSV | 데이터 기반 시각화 |

입력이 달라지면 이미지의 성격도 달라진다. 좌표를 입력으로 쓰면 공간적 구조가 만들어진다. 시간값을 입력으로 쓰면 움직임이 생긴다. 반복 인덱스를 입력으로 쓰면 순서와 배열이 만들어진다. 랜덤 값을 입력으로 쓰면 예측하기 어려운 변화가 생기고, 노이즈 값을 입력으로 쓰면 부드럽게 이어지는 변화가 생긴다.

중요한 것은 입력을 의식적으로 선택하는 일이다. 같은 원을 그리더라도 중심 좌표를 고정하면 정적인 이미지가 되고, 중심 좌표를 마우스 위치로 정하면 인터랙티브한 이미지가 된다. 반지름을 시간값으로 바꾸면 원이 커졌다 작아지고, 반지름을 노이즈 값으로 바꾸면 불규칙하지만 부드러운 떨림이 생긴다.

## 함수는 변환 규칙이다

함수는 입력을 그대로 출력하지 않는다. 입력을 어떤 방식으로 바꾼다. 이 변환 방식이 이미지의 성격을 결정한다. 같은 입력을 사용하더라도 어떤 함수를 통과시키느냐에 따라 결과는 크게 달라진다.

가장 단순한 함수는 입력을 일정한 비율로 바꾸는 선형 함수다.

$$
y=ax+b
$$

이 식에서 `a`는 변화의 기울기이고, `b`는 시작점을 옮기는 값이다. 그래픽에서는 이런 식이 값의 범위를 바꾸거나, 좌표를 이동하거나, 크기를 조절하는 데 자주 사용된다.

하지만 제너레이티브 아트에서는 선형 함수만으로는 부족할 때가 많다. 부드러운 움직임을 만들기 위해 사인 함수를 쓰고, 급격한 경계를 만들기 위해 임계값을 쓰고, 값의 변화를 완만하게 만들기 위해 보간 함수를 쓴다. 거리를 계산하는 함수는 도형의 경계를 만들고, 노이즈 함수는 유기적인 변화를 만든다.

| 함수의 종류 | 역할 | 시각적 결과 |
| --- | --- | --- |
| 선형 함수 | 값을 일정한 비율로 변환 | 균일한 변화, 그라데이션 |
| 삼각함수 | 주기적인 값을 생성 | 파동, 진동, 원형 운동 |
| 거리 함수 | 두 점 사이의 관계 계산 | 원, 링, 방사형 패턴 |
| 임계값 함수 | 값을 두 영역으로 나눔 | 마스크, 경계, 패턴 분리 |
| 보간 함수 | 두 값 사이를 연결 | 부드러운 변화, 전환 |
| 노이즈 함수 | 연속적인 불규칙성 생성 | 질감, 자연스러운 변형 |

함수를 고른다는 것은 이미지의 변화 방식을 고르는 일이다. 직선적인 변화가 필요한지, 주기적인 변화가 필요한지, 중심에서 퍼져 나가는 변화가 필요한지, 불규칙하지만 연결된 변화가 필요한지에 따라 사용할 함수가 달라진다.

## 출력은 시각 요소가 된다

함수의 출력은 그 자체로는 숫자일 뿐이다. 이 숫자가 이미지가 되려면 시각 요소에 연결되어야 한다. 예를 들어 어떤 함수의 출력값이 0에서 1 사이의 숫자라면, 이 값을 여러 방식으로 사용할 수 있다.

```text
v = someFunction(x, y)

size = v * 80
alpha = v * 255
angle = v * 2 * PI
gray = v * 255
```

같은 값 `v`가 크기, 투명도, 회전각, 밝기로 바뀔 수 있다. 이때 함수의 출력이 무엇을 조절하는지에 따라 이미지의 의미가 달라진다. 거리값을 밝기에 연결하면 중심에서 퍼지는 그라데이션이 되고, 거리값을 크기에 연결하면 중심을 기준으로 도형의 크기가 달라진다. 노이즈 값을 색에 연결하면 질감이 되고, 노이즈 값을 좌표 변형에 연결하면 형태가 일그러진다.

따라서 제너레이티브 아트에서는 “어떤 값을 계산할 것인가”만큼 “그 값을 어디에 연결할 것인가”가 중요하다. 같은 수학적 구조도 출력의 연결 방식에 따라 전혀 다른 이미지가 된다.

## 하나의 이미지는 여러 함수의 결합이다

실제 이미지는 하나의 함수만으로 만들어지지 않는 경우가 많다. 여러 입력과 함수가 연결되어 하나의 결과를 만든다. 예를 들어 반복되는 원 패턴을 만든다고 해 보자. 원의 위치는 반복 인덱스로부터 계산되고, 크기는 중심점과의 거리로부터 계산되며, 색은 노이즈 값으로부터 계산될 수 있다.

의사코드로 쓰면 다음과 같다.

```text
for each cell:
    position = cellIndexToPosition(cell)
    distance = distanceToCenter(position)
    size = map(distance, near, far, large, small)
    color = noiseToColor(noise(position))
    drawCircle(position, size, color)
```

이 구조에서는 여러 함수가 차례로 연결된다. 셀 인덱스는 위치가 되고, 위치는 거리 계산의 입력이 되며, 거리는 크기로 변환된다. 같은 위치는 노이즈 함수의 입력이 되어 색을 만든다. 최종 출력은 원의 위치, 크기, 색이다.

이런 흐름을 이해하면 복잡한 이미지도 작은 변환들의 연결로 나누어 볼 수 있다. 어떤 이미지가 어려워 보일 때는 “이 결과를 만드는 입력은 무엇인가?”, “중간에서 어떤 값이 계산되는가?”, “마지막에 그 값이 무엇으로 출력되는가?”라고 물어보면 된다.

## 드로잉 API와 셰이더에서의 차이

입력, 함수, 출력이라는 관점은 드로잉 API와 셰이더에서 모두 사용할 수 있다. 다만 계산이 이루어지는 방식은 다르다.

드로잉 API에서는 보통 반복문이 도형을 하나씩 생성한다. 각 반복에서 위치, 크기, 색을 계산한 뒤 도형을 그린다. 다음은 p5.js로 표현한 예제다.

**p5.js 예제**

```javascript
for (let i = 0; i < count; i++) {
  let x = i * spacing;
  let y = height / 2;
  let diameter = sin(i * 0.4 + time) * 20 + 30;
  circle(x, y, diameter);
}
```

여기서 입력은 반복 인덱스 `i`와 시간 `time`이다. 함수는 x좌표 계산, 사인 함수, 크기 계산이다. 출력은 원의 위치와 지름이다.

반면 프래그먼트 셰이더에서는 각 픽셀이 자신의 좌표를 입력으로 삼아 색을 계산한다.

```glsl
vec2 p = gl_FragCoord.xy / u_resolution.xy;
float d = distance(p, vec2(0.5));
float v = smoothstep(0.3, 0.28, d);
vec3 color = vec3(v);
```

여기서 입력은 픽셀 좌표 `p`이고, 함수는 중심점과의 거리 계산과 `smoothstep`이다. 출력은 픽셀의 색이다. 드로잉 API에서는 도형을 생성하고, 셰이더에서는 픽셀의 색을 계산한다. 하지만 두 경우 모두 입력이 함수에 들어가 출력이 된다는 구조는 같다.

## 이 절의 핵심

제너레이티브 아트에서 이미지는 입력, 함수, 출력의 관계로 이해할 수 있다. 좌표, 시간, 반복 인덱스, 랜덤 값, 노이즈 값은 입력이 된다. 함수는 그 입력을 변환하고, 출력은 색, 위치, 크기, 회전, 속도, 밀도 같은 시각 요소로 연결된다.

이 관점을 가지면 이미지를 분석하고 설계하기 쉬워진다. 복잡한 결과도 입력이 무엇인지, 어떤 함수가 쓰였는지, 출력이 어디에 연결되었는지로 나누어 볼 수 있다. 다음 절에서는 이 구조를 도형에 적용해 본다. 도형을 고정된 객체로만 보지 않고, 좌표를 입력으로 받아 값을 출력하는 함수로 정의하는 방법을 살펴볼 것이다.
