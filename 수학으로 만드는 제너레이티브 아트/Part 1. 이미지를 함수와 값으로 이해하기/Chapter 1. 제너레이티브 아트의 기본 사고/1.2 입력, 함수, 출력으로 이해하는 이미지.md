# 1.2 입력, 함수, 출력으로 이해하는 이미지

앞 절에서는 그래픽 객체를 하나씩 그리는 방식과 객체를 만들어 내는 규칙을 설계하는 방식을 살펴봤다. 이번 절에서는 그 규칙을 수학적 언어로 나타내고 계산을 구성한다.

제너레이티브 아트의 이미지는 입력을 함수에 넣고, 그 결과를 시각 요소로 표현하는 과정에서 만들어진다. 입력은 함수가 받아들이는 값이다. 좌표와 시간, 마우스 위치, 반복 인덱스, 랜덤 값, 노이즈 값, 이미지의 픽셀 값이 입력으로 쓰인다. 함수는 이 입력을 변환하는 규칙이고, 출력은 계산 결과다. 출력은 정해 둔 방식에 따라 색이나 도형의 위치·크기·회전각·투명도·속도·밀도·재질 속성이 된다.

이 관점에서 이미지는 화면에 놓인 도형의 모음에 그치지 않는다. 여러 입력값이 함수를 거쳐 시각적 출력으로 바뀐 결과다. 화면의 각 점과 반복되는 도형, 시간에 따라 달라지는 프레임도 입력과 함수의 계산으로 만들어진다.

## 이미지를 계산 결과로 보기

수학에서 함수는 어떤 값을 다른 값에 대응시킨다. 프로그래밍에서도 함수는 입력을 받아 출력을 돌려준다. 그래픽 프로그램의 함수 역시 같은 방식으로 작동한다. 간단한 예를 보자.

$$
B=f(x)
$$

이 식은 x좌표를 입력으로 받아 밝기 $B$를 계산한다는 뜻이다. x좌표가 작으면 어둡고 커질수록 밝아지게 정할 수 있다. 화면에는 왼쪽에서 오른쪽으로 밝아지는 그라데이션이 나타난다. 이 관계를 구체적인 식으로 쓰면 다음과 같다.

$$
B=\frac{x}{W}
$$

여기서 $x$는 현재 위치의 x좌표이고 $W$는 화면의 너비다. $x$가 0이면 밝기 $B$는 0이며, x좌표가 화면 오른쪽 끝에 가까워질수록 밝기는 1에 가까워진다. 일반적인 8비트 밝기 범위로 표현하려면 이 값에 255를 곱한다.

$$
G=255B=255\frac{x}{W}
$$

화면의 밝기는 직접 칠하는 대신 좌표에서 계산할 수 있다. 이 예에서는 좌표가 입력이고 나눗셈이 변환 규칙이며 밝기가 출력이다.

중심점까지의 거리로 원을 만들고, 각도로 방사형 패턴을 구성하고, 시간값으로 파동을 움직이는 것도 같은 방식이다. 입력값을 시각적 출력으로 바꾸는 함수가 그 바탕에 놓인다.

## 입력에는 여러 종류가 있다

그래픽 작업에는 여러 종류의 입력이 쓰인다. 좌표는 공간을 나타내고 시간은 변화를 나타낸다. 마우스나 키보드 입력은 사용자의 행동을 반영한다. 랜덤이나 노이즈는 예측하기 어려운 변화를 제공한다. 입력이 언제나 하나의 숫자인 것은 아니다.

| 입력의 종류 | 예 | 주로 만드는 결과 |
| --- | --- | --- |
| 좌표 | `x`, `y`, `uv`, `position` | 위치 기반 색, 패턴, 도형 |
| 시간 | 경과 시간, 프레임 번호, 프레임 간 시간 | 애니메이션, 반복 루프, 변화 |
| 반복 인덱스 | `i`, `row`, `col` | 배열, 격자, 순차적 변화 |
| 사용자 입력 | 마우스 위치, 키 입력, 센서 값 | 인터랙션, 실시간 조절 |
| 랜덤 값 | 난수, 시드 기반 랜덤 | 불규칙한 배치, 변주 |
| 노이즈 값 | Perlin Noise, Simplex Noise | 연속적인 질감, 유기적 변화 |
| 외부 데이터 | 이미지, 사운드, 텍스트, CSV | 데이터 기반 시각화 |

입력의 종류에 따라 이미지의 성격이 달라진다. 좌표는 공간 구조를 만들고, 시간값은 움직임을 만든다. 랜덤 값은 예측하기 어려운 변화를, 노이즈 값은 부드럽게 이어지는 변화를 준다.

원 하나도 어떤 입력을 쓰느냐에 따라 달라진다. 중심 좌표를 고정하면 정적인 이미지가 되고, 마우스 위치를 중심으로 삼으면 인터랙티브한 이미지가 된다. 시간값으로 반지름을 정하면 원이 커졌다 작아지고, 노이즈 값으로 정하면 불규칙하면서도 부드럽게 떨린다. 만들려는 아트워크에 맞춰 입력을 고르는 이유다.

## 함수는 변환 규칙이다

함수는 입력을 변환하며, 그 방식이 이미지의 성격을 좌우한다. 같은 입력도 어떤 함수에 넣느냐에 따라 다른 결과를 낸다. 가장 단순한 예는 입력을 일정한 비율로 바꾸는 선형 함수다.

$$
y=ax+b
$$

여기서 `a`는 변화의 기울기이고 `b`는 시작점을 옮기는 값이다. 그래픽에서는 값의 범위를 바꾸거나 좌표를 이동하고 크기를 조절할 때 이런 관계를 쓴다.

선형 함수만으로 표현하기 어려운 변화도 많다. 부드러운 움직임에는 사인 함수를, 급격한 경계에는 임계값을 쓸 수 있다. 보간 함수는 값의 변화를 완만하게 만들고, 거리 함수는 도형의 경계를 정의한다. 노이즈 함수는 유기적인 변화를 만든다. 아래 표는 함수의 종류와 역할, 시각적 결과를 정리한다.

| 함수의 종류 | 역할            | 시각적 결과            |
| ------ | ------------- | ----------------- |
| 선형 함수  | 값을 일정한 비율로 변환 | 균일한 변화, 그라데이션     |
| 삼각함수   | 주기적인 값을 생성    | 파동, 진동, 원형 운동     |
| 거리 함수  | 두 점 사이의 관계 계산 | 원, 링, 방사형 패턴      |
| 임계값 함수 | 값을 두 영역으로 나눔  | 마스크, 경계, 패턴 분리    |
| 보간 함수  | 두 값 사이를 연결    | 부드러운 변화, 전환       |
| 노이즈 함수 | 연속적인 불규칙성 생성  | 유기적인 질감, 자연스러운 변형 |

어떤 함수를 쓸지는 만들려는 변화와 아트워크의 연출 방식에 따라 달라진다.

## 출력은 시각 요소가 된다

함수의 출력은 숫자다. 이미지로 표현하려면 그 값을 시각 요소에 연결해야 한다. 함수가 0과 1 사이의 값을 낸다고 가정하면 다음처럼 사용할 수 있다.

```text
v = someFunction(x, y)

size = v * 80
alpha = v * 255
angle = v * 2 * PI
brightness = v * 255
```

같은 값 `v`를 크기(size), 투명도(alpha), 회전각(angle), 밝기(brightness)에 연결할 수 있다. 무엇을 조절하느냐에 따라 아트워크의 연출도 달라진다. 거리값을 밝기에 연결하면 중심에서 퍼지는 그라데이션이 되고, 크기에 연결하면 중심에서 멀어질수록 도형의 크기가 달라진다. 노이즈 값을 색에 연결하면 질감이 생기고, 좌표에 연결하면 형태가 일그러진다. 어떤 값을 계산하는지만큼 그 값을 어디에 연결하는지도 중요하다.

## 하나의 이미지는 여러 함수의 결합이다

제너레이티브 아트에서는 여러 입력과 함수가 연결되어 하나의 결과를 만든다. 반복되는 원 패턴을 예로 들어 보자. 반복 인덱스로 원의 위치를 정하고, 중심점까지의 거리로 크기를 계산하며, 노이즈 값으로 색을 정할 수 있다.

의사코드로 나타내면 다음과 같다.

```text
for each cell:
    position = cellIndexToPosition(cell)
    distance = distanceToCenter(position)
    size = map(distance, near, far, large, small)
    color = noiseToColor(noise(position))
    
    drawCircle(position, size, color)
```

여러 계산이 순서대로 연결된다. 셀 인덱스에서 위치를 구하고, 그 위치를 거리 계산에 사용해 크기로 바꾼다. 같은 위치를 노이즈 함수에 넣어 색도 정한다. 최종 출력은 원의 위치와 크기, 색이다. 복잡한 이미지도 이런 변환의 연결로 나누어 볼 수 있다. 아트워크의 원리를 살필 때는 “이 결과를 만드는 입력은 무엇인가?”, “중간에서 어떤 값이 계산되는가?”, “마지막에 그 값이 무엇으로 출력되는가?”를 따라가면 된다.

## 드로잉 API와 셰이더에서의 차이

입력, 함수, 출력이라는 관점은 p5.js 같은 드로잉 API와 GLSL 같은 셰이더에 모두 적용된다. 다만 계산이 이루어지는 방식은 다르다.

드로잉 API에서는 보통 반복문으로 도형을 하나씩 만든다. 각 반복에서 위치와 크기, 색을 계산한 뒤 도형을 그린다.

**드로잉 API의 코드 예시**

```javascript
for (let i = 0; i < count; i++) {
  let x = i * spacing;
  let y = height / 2;
  let diameter = sin(i * 0.4 + time) * 20 + 30;
  circle(x, y, diameter);
}
```

이 p5.js 코드에서 반복 인덱스 `i`와 시간 `time`이 입력이다. x좌표와 사인 함수, 지름 계산이 변환 규칙이고, 출력은 원의 위치와 지름이다. 프래그먼트 셰이더에서는 각 픽셀이 자기 좌표를 입력으로 삼아 색을 계산한다.

**셰이더 코드 예시**

```glsl
vec2 p = gl_FragCoord.xy / u_resolution.xy;
float d = distance(p, vec2(0.5));
float v = smoothstep(0.3, 0.28, d);
vec3 color = vec3(v);
```

GLSL 코드에서 입력은 픽셀 좌표 `p`다. `distance`는 중심점까지의 거리를 구하고 `smoothstep`은 경계를 부드럽게 만든다. 출력은 픽셀의 색이다. 드로잉 API는 도형을 만들고 셰이더는 픽셀의 색을 계산하지만, 두 경우 모두 입력이 함수에 들어가 출력을 만든다는 구조는 같다.

## 이 절의 핵심

제너레이티브 아트의 이미지는 입력, 함수, 출력의 관계로 만들어진다. 좌표와 시간, 반복 인덱스, 랜덤 값, 노이즈 값이 입력이 된다. 함수는 입력을 수식으로 변환하고, 출력은 색과 위치, 크기, 회전, 속도, 밀도 같은 시각 요소에 연결된다.

복잡한 결과도 입력과 함수, 출력으로 나누어 살펴볼 수 있다. 다음 절에서는 이 구조를 도형에 적용한다. 도형을 고정된 객체로만 보지 않고 좌표를 입력으로 받아 값을 출력하는 함수로 정의하는 방법을 다룬다.
