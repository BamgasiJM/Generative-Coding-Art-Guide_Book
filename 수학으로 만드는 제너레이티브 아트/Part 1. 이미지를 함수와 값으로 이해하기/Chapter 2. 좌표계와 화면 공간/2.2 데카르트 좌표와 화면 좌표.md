# 2.2 데카르트 좌표와 화면 좌표

좌표값만으로는 위치를 알 수 없다. 원점의 위치, 각 축의 증가 방향, 좌표의 단위를 함께 알아야 한다. 같은 $(100,50)$도 좌표계에 따라 가리키는 위치가 달라진다.

수학의 데카르트 좌표와 그래픽 환경의 화면 좌표는 모두 $(x,y)$로 나타내지만 관례가 다르다. 차이를 이해하면 도형이 뒤집히거나 회전 방향이 예상과 달라지는 문제를 피하기 쉽다.

## 데카르트 좌표계

2차원 데카르트 좌표계는 서로 수직인 $x$축과 $y$축으로 평면의 위치를 나타낸다. 두 축이 만나는 점은 원점 $(0,0)$이다. 일반적인 수학 관례에서 $x$는 오른쪽으로, $y$는 위쪽으로 갈수록 증가한다.

$$
\mathbf{p}=(x,y)
$$

원점의 오른쪽 위에서는 $x$와 $y$가 모두 양수다. 왼쪽으로 가면 $x$가 음수이고, 아래쪽으로 가면 $y$가 음수다. 함수 그래프, 벡터, 삼각함수, 기하학 공식은 대체로 이 관례를 따른다.

예를 들어 양의 각도를 반시계 방향으로 측정하면 단위원 위의 위치는 다음과 같다.

$$
x=\cos\theta,\qquad y=\sin\theta
$$

$\theta=\frac{\pi}{2}$이면 점은 $(0,1)$에 놓인다. $y$축이 위로 증가하므로 이 점은 원점 위에 있다.

## 화면 좌표의 일반적인 관례

많은 2차원 그래픽 환경과 이미지 버퍼는 화면의 왼쪽 위를 원점으로 둔다. $x$는 오른쪽으로, $y$는 아래쪽으로 증가한다. 이미지를 위에서 아래로 행 단위로 저장하고 처리하는 방식에 맞는 관례다.

화면 너비를 $W$, 높이를 $H$라고 하면 흔히 다음 범위를 사용한다.

$$
0\le x<W,\qquad 0\le y<H
$$

왼쪽 위는 $(0,0)$이며 오른쪽 아래에 가까운 픽셀은 $(W-1,H-1)$이다. 벡터 그래픽, 게임 엔진, 3D API, 셰이더 단계에 따라 원점과 축 방향은 달라질 수 있다. 화면 좌표의 관례를 하나로 외우기보다 사용하는 환경에서 확인해야 한다.

| 항목 | 전형적인 데카르트 좌표 | 흔한 2D 화면 좌표 |
| --- | --- | --- |
| 원점 | 평면의 기준점, 흔히 중앙 | 화면의 왼쪽 위 |
| $x$의 증가 방향 | 오른쪽 | 오른쪽 |
| $y$의 증가 방향 | 위쪽 | 아래쪽 |
| 단위 | 문제에 따라 결정 | 흔히 픽셀 |
| 음수 좌표 | 자연스럽게 사용 | 화면 밖을 가리키는 경우가 많음 |

표는 대표적인 관례를 비교한다. 실제 API가 다른 좌표계를 쓸 수 있으므로 문서나 렌더링 결과로 확인한다.

## y축 방향이 만드는 차이

$y$축 방향이 반대이면 위아래 위치뿐 아니라 회전과 각도의 해석도 달라진다. 수학 좌표에서 다음 식은 각도 $\theta$가 증가할 때 반시계 방향으로 움직이는 점을 만든다.

$$
\mathbf{p}(\theta)=(r\cos\theta,r\sin\theta)
$$

하지만 $y$가 아래로 증가하는 화면에 같은 값을 적용하면 눈에 보이는 회전은 시계 방향이 된다. 수학에서의 회전 방향을 유지하려면 $y$ 성분의 부호를 바꾼다.

$$
\mathbf{p}_{screen}(\theta)=(r\cos\theta,-r\sin\theta)
$$

또 다른 방법은 계산 전에 화면 좌표를 중심 기준의 데카르트 좌표로 변환하는 것이다. 이 좌표계에서는 거리, 각도, 회전 공식을 일관되게 적용하기 쉽다.

## 화면 좌표를 중심 기준 좌표로 바꾸기

화면의 왼쪽 위가 $(0,0)$이고 크기가 $W\times H$라고 하자. 화면 중심을 새 원점으로 두려면 각 좌표에서 화면 중심을 뺀다.

$$
x_c=x-\frac{W}{2},\qquad y_c=y-\frac{H}{2}
$$

이 변환은 원점만 옮기므로 $y_c$는 여전히 아래로 증가한다. $y$축이 위로 향하는 데카르트 좌표를 얻으려면 $y$의 부호도 뒤집는다.

$$
x_c=x-\frac{W}{2},\qquad y_c=\frac{H}{2}-y
$$

역변환은 다음과 같다.

$$
x=x_c+\frac{W}{2},\qquad y=\frac{H}{2}-y_c
$$

두 변환을 함수로 분리하면 좌표 관례가 코드 곳곳에 흩어지는 일을 막을 수 있다.

```text
function screenToCartesian(position, screenSize):
    return (
        position.x - screenSize.x / 2,
        screenSize.y / 2 - position.y
    )

function cartesianToScreen(position, screenSize):
    return (
        position.x + screenSize.x / 2,
        screenSize.y / 2 - position.y
    )
```

변환을 명시하면 데카르트 좌표에서 계산하고 마지막 출력 단계에서 화면 좌표로 바꿀 수 있다.

## 픽셀의 위치와 픽셀의 중심

정수 좌표가 픽셀의 어느 부분을 가리키는지도 확인해야 한다. 시스템에 따라 정수 좌표는 픽셀의 중심이거나 픽셀 셀의 경계다. 픽셀 중심을 명시적으로 샘플링할 때는 다음처럼 $0.5$를 더하기도 한다.

$$
\mathbf{p}_{center}=(i+0.5,j+0.5)
$$

$i$와 $j$는 각각 픽셀의 열과 행 인덱스다. 픽셀 중심과 경계의 차이는 한 픽셀 두께의 선, 텍스처 샘플링, 렌더링 API 사이의 좌표 변환에서 드러난다. 고수준 드로잉에서는 렌더러가 대부분 처리하지만, 픽셀 단위 계산에서는 기준이 중심인지 경계인지 확인해야 한다.

## 여러 그래픽 환경의 좌표 관례

하나의 프로젝트 안에서도 좌표 관례가 여럿 쓰일 수 있다. CPU에서 도형을 배치할 때는 왼쪽 위 원점의 픽셀 좌표를, 정점 셰이더에서는 중심이 원점인 클립 공간을, 텍스처를 읽을 때는 0~1 범위의 UV 좌표를 사용할 수 있다.

| 사용 맥락 | 흔한 원점과 범위 | 확인할 점 |
| --- | --- | --- |
| 2D 캔버스와 이미지 | 왼쪽 위, 픽셀 단위 | $y$축 방향, 픽셀 중심 |
| 벡터 그래픽 문서 | 문서 또는 뷰포트 기준 | 단위, 뷰박스, 변환 |
| 게임 엔진의 2D·3D 공간 | 프로젝트 설정과 엔진 관례에 따름 | 위쪽 축, 좌·우수 좌표계 |
| 프래그먼트 셰이더 | 픽셀 좌표 또는 보간된 좌표 | 원점, 해상도, API 차이 |
| 텍스처 좌표 | 보통 0에서 1 | 세로 방향, 래핑 방식 |
| 클립 공간 | 보통 중심 기준의 정규화된 범위 | 깊이 범위, 그래픽 API 차이 |

좌표가 예상과 다르면 값보다 먼저 좌표계의 정의를 확인한다. 원점, 축 방향, 범위, 단위를 살펴보면 많은 문제가 좌표 변환으로 해결된다.

## 계산용 좌표와 출력용 좌표 분리하기

제너레이티브 작업에서는 목적에 맞는 계산용 좌표를 따로 두면 편리하다. 중심에서 퍼지는 패턴은 화면 중앙을 원점으로 두고, 삼각함수로 회전할 때는 $y$가 위로 증가하는 좌표를 쓰는 편이 자연스럽다.

```text
screenPosition = currentPixel
mathPosition = screenToCartesian(screenPosition, resolution)

value = radialPattern(mathPosition)
outputColor(value)
```

사용자 인터페이스나 문서형 레이아웃에는 왼쪽 위 원점의 화면 좌표가 자연스럽다. 좌표계는 작업에 맞게 선택하면 된다. 선택한 관례를 일관되게 적용하고 다른 공간으로 옮길 때 변환을 명시해야 한다.

## 이 절의 핵심

데카르트 좌표와 화면 좌표는 모두 점을 $(x,y)$로 나타내지만 원점과 축 방향은 다를 수 있다. 화면에서 $y$가 아래로 증가하면 수학 공식의 위아래와 회전 방향이 시각적으로 뒤집힌다.

원점, 축 방향, 단위, 범위를 확인하고 계산용 좌표와 출력용 좌표를 구분하면 여러 그래픽 환경에서 같은 수학을 일관되게 적용할 수 있다. 다음 절에서는 픽셀 크기에 의존하는 좌표를 0~1 범위로 바꾸는 정규화 좌표와 UV 좌표를 살펴본다.
