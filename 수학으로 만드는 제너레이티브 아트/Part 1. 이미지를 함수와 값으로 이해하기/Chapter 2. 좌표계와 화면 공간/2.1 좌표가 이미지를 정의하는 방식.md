# 2.1 좌표가 이미지를 정의하는 방식

이미지에는 색과 형태가 드러나지만, 컴퓨터 그래픽의 계산은 좌표에서 시작한다. 점에는 위치가 필요하고, 선에는 시작점과 끝점이 필요하다. 도형을 배치하거나 픽셀의 색을 계산할 때도 화면의 어느 위치를 다루는지 정해야 한다. 좌표는 이미지의 각 요소에 위치를 부여하는 공통 언어다.

제너레이티브 아트에서 좌표는 도형을 놓을 자리를 지정하는 데 그치지 않는다. 좌표를 함수의 입력으로 사용하면 위치에 따라 색, 크기, 방향, 밀도, 움직임을 바꿀 수 있다. 이때 이미지는 미리 준비한 요소를 좌표 위에 놓은 결과가 아니라, 각 좌표에서 규칙을 계산해 얻은 결과다.

## 위치를 숫자로 표현하기

2차원 평면의 한 점은 보통 두 수의 순서쌍으로 나타낸다.

$$
\mathbf{p}=(x,y)
$$

$x$와 $y$는 각각 한 축에서의 위치를 나타내며, 두 값을 함께 사용해 한 점의 위치를 정한다. 그래픽 라이브러리는 이 값을 두 개의 숫자로 받거나 `vec2`, `Point`, `Vector2` 같은 자료형으로 묶어 다룬다.

```text
position = (x, y)
drawPoint(position)
```

좌표만으로는 이미지가 만들어지지 않는다. 좌표가 지정한 위치에 색이나 도형 같은 시각적 출력을 연결해야 한다. 어떤 출력을 어느 위치에 둘지 결정하는 기준이 좌표다.

| 시각 요소 | 좌표가 하는 일 |
| --- | --- |
| 점 | 점이 놓일 위치를 정한다. |
| 선 | 시작점과 끝점, 또는 선이 지나가는 경로를 정한다. |
| 도형 | 중심이나 모서리의 위치를 정한다. |
| 픽셀 | 현재 계산하고 있는 화면 위치를 나타낸다. |
| 텍스처 | 이미지의 어느 지점을 읽을지 정한다. |
| 입자 | 현재 위치와 이동할 다음 위치를 나타낸다. |

## 좌표를 배치에 사용하는 방식

좌표를 그래픽 객체의 위치로 전달하는 것이 가장 직접적인 사용법이다. 다음 의사코드는 일정한 간격으로 점을 배치한다.

```text
for row from 0 to rowCount - 1:
    for column from 0 to columnCount - 1:
        x = margin + column * spacing
        y = margin + row * spacing
        drawCircle(x, y, radius)
```

`row`와 `column`은 격자 안의 순서이고, `x`와 `y`는 화면상의 위치다. 인덱스에 간격을 곱하고 여백을 더해 좌표를 계산하므로 원이 일정한 간격으로 배치된다. 좌표 계산을 바꾸면 전체 배치도 달라진다.

$y$좌표에 사인 함수의 결과를 더하면 원을 파동을 따라 배치할 수 있다.

$$
y=y_0+A\sin(kx)
$$

$A$는 파동의 높이를, $k$는 공간에서 파동이 반복되는 빈도를 조절한다. 도형은 그대로여도 좌표 생성 규칙이 바뀌면 이미지의 구조가 달라진다. 좌표를 설계하는 일은 배치 규칙을 설계하는 일이다.

## 좌표를 함수의 입력으로 사용하는 방식

좌표는 도형을 그릴 위치를 정하는 값인 동시에, 그 위치에 무엇을 그릴지 계산하는 입력이다. 화면의 각 위치 $\mathbf{p}=(x,y)$를 색으로 대응시키는 함수를 생각해 보자.

$$
C(x,y)=(r,g,b)
$$

이 함수는 좌표 하나를 받아 색 하나를 반환한다. 화면의 모든 위치에서 계산하면 이미지 전체가 만들어진다. 프래그먼트 셰이더, 이미지 처리, 프로시저럴 텍스처는 이 방식을 직접 사용한다.

가장 간단한 예는 $x$좌표를 밝기에 연결하는 것이다.

$$
B(x,y)=\frac{x}{W}
$$

$W$를 화면 너비라고 하면 밝기 $B$는 왼쪽에서 0에 가깝고 오른쪽으로 갈수록 1에 가까워진다. 식에 포함되지 않은 $y$는 결과에 영향을 주지 않으므로 같은 $x$좌표의 위치는 밝기가 같다. 따라서 가로 방향 그라데이션이 만들어진다.

GLSL 계열 셰이더에서는 다음과 비슷하게 표현한다.

```glsl
vec2 uv = fragCoord / resolution;
float brightness = uv.x;
vec3 color = vec3(brightness);
```

이 코드는 그래픽 객체를 생성하는 대신 현재 픽셀의 좌표를 읽어 색을 계산한다. 이 규칙을 모든 픽셀에서 실행하면 이미지 전체가 나타난다.

## 같은 좌표에서 여러 값을 계산하기

한 좌표를 여러 함수의 입력으로 사용할 수 있다. 중심에서의 거리는 밝기에, 좌표의 각도는 색상에, 노이즈 함수는 표면 질감에 연결할 수 있다.

```text
for each position p:
    distanceValue = distance(p, center)
    angleValue = angle(p - center)
    noiseValue = noise(p * scale)

    brightness = distanceToBrightness(distanceValue)
    hue = angleToHue(angleValue)
    texture = noiseToTexture(noiseValue)

    outputColor = combine(brightness, hue, texture)
```

복잡한 이미지도 좌표에서 파생한 여러 값을 조합해 분석할 수 있다. 거리, 방향, 각도, 반복 셀, 노이즈 샘플 위치 등 여러 중간값이 같은 좌표에서 계산된다.

## 좌표를 바꾸면 이미지가 바뀐다

색을 계산하는 함수는 그대로 두고 입력 좌표만 변환해도 결과가 달라진다. 좌표에 값을 더하면 패턴이 이동하고, 배율을 곱하면 확대·축소된다. 회전 변환은 패턴의 방향을 바꾼다.

```text
p = currentPosition
p = p - center
p = rotate(p, angle)
p = p / scale

value = pattern(p)
```

완성된 이미지를 회전하거나 확대하는 것처럼 보이지만, 이 과정에서는 함수에 넣을 좌표를 먼저 변환한다. 함수는 변환된 좌표를 입력받아 결과를 계산한다. 반복 패턴, 좌표 왜곡, 프로시저럴 텍스처, SDF 모델링에서 이 원리를 널리 사용한다.

좌표 변환의 순서도 결과를 바꾼다. 원점에서 먼 좌표를 회전하면 위치까지 크게 돌아간다. 반면 먼저 중심을 원점으로 옮긴 뒤 회전하면 그 중심을 기준으로 제자리에서 회전한다. 변환할 때는 기준점과 적용 순서를 함께 살펴야 한다.

## 연속 좌표와 이산 이미지

수학적 평면의 좌표는 연속적이다. 두 좌표 사이에는 언제나 다른 좌표가 존재한다. 디지털 이미지는 이와 달리 유한한 픽셀 격자로 이루어진다. 화면이 800픽셀 너비, 600픽셀 높이라면 출력할 픽셀 수도 정해져 있다.

그래픽 계산에서 정수 좌표만 사용하는 것은 아니다. 도형의 중심이 $(135.4, 72.8)$처럼 픽셀 사이에 놓일 수 있고, 렌더러는 그 결과를 주변 픽셀에 반영한다. 텍스처 좌표와 보간된 정점 속성도 대개 실수로 계산된다.

두 층의 차이는 다음과 같다.

| 층 | 성격 | 예 |
| --- | --- | --- |
| 기하와 함수의 좌표 | 연속적인 실수로 계산할 수 있다. | 도형의 중심, 곡선 위의 위치, UV 좌표 |
| 출력 이미지 | 정해진 픽셀 격자에 기록된다. | 화면, PNG 이미지, 렌더 타깃 |

연속적인 규칙을 유한한 픽셀로 표현하면 계단 현상이나 샘플링 문제가 생길 수 있다. 이 차이는 안티앨리어싱, 텍스처 샘플링, 주파수를 다룰 때 다시 중요해진다.

## 이 절의 핵심

좌표는 이미지 요소의 위치를 정하고, 위치에 따른 값을 계산하는 기본 입력이다. 그래픽 객체를 배치하는 데 쓸 수도 있고, 각 픽셀의 색을 반환하는 함수에 넣을 수도 있다.

제너레이티브 아트에서 좌표는 고정된 주소에 머물지 않는다. 좌표를 이동·확대·회전하거나 거리와 각도로 변환해 이미지의 구조를 만든다. 다음 절에서는 수학에서 익숙한 데카르트 좌표와 실제 화면에서 흔히 사용하는 좌표의 차이를 살펴본다.
