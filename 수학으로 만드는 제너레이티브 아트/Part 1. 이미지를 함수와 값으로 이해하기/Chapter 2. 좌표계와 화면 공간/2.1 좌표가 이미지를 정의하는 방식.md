# 2.1 좌표가 이미지를 정의하는 방식

이미지는 색과 형태로 보이지만, 컴퓨터 그래픽에서 그 바탕을 이루는 것은 좌표다. 점을 놓으려면 위치가 필요하고, 선을 그으려면 시작점과 끝점이 필요하다. 도형을 배치하거나 픽셀의 색을 계산할 때도 먼저 화면의 어느 위치를 다루고 있는지 알아야 한다. 좌표는 이미지를 구성하는 모든 요소에 위치를 부여하는 공통 언어다.

제너레이티브 아트에서 좌표는 단순히 도형을 놓을 장소를 지정하는 데 그치지 않는다. 좌표 자체를 함수의 입력으로 사용하면 위치에 따라 색, 크기, 방향, 밀도, 움직임을 바꿀 수 있다. 이때 이미지는 좌표 위에 미리 준비된 요소를 올려놓은 결과가 아니라, 좌표마다 규칙을 계산한 결과가 된다.

## 위치를 숫자로 표현하기

2차원 평면의 한 점은 보통 두 수의 순서쌍으로 나타낸다.

$$
\mathbf{p}=(x,y)
$$

$x$는 한 축에서의 위치를, $y$는 다른 축에서의 위치를 나타낸다. 두 값은 함께 하나의 위치를 정의한다. 그래픽 라이브러리에 따라 이를 두 개의 독립된 숫자로 전달하기도 하고, `vec2`, `Point`, `Vector2` 같은 자료형으로 묶어 다루기도 한다.

```text
position = (x, y)
drawPoint(position)
```

좌표만으로는 아직 아무것도 보이지 않는다. 좌표에 색이나 도형 같은 시각적 출력을 연결해야 이미지가 된다. 그러나 어느 위치에 어떤 출력을 연결할지 결정하는 기준이 바로 좌표다.

| 시각 요소 | 좌표가 하는 일 |
| --- | --- |
| 점 | 점이 놓일 위치를 정한다. |
| 선 | 시작점과 끝점, 또는 선이 지나가는 경로를 정한다. |
| 도형 | 중심이나 모서리의 위치를 정한다. |
| 픽셀 | 현재 계산하고 있는 화면 위치를 나타낸다. |
| 텍스처 | 이미지의 어느 지점을 읽을지 정한다. |
| 입자 | 현재 위치와 이동할 다음 위치를 나타낸다. |

## 좌표를 배치에 사용하는 방식

가장 직접적인 사용법은 좌표를 그래픽 객체의 위치로 전달하는 것이다. 다음 의사코드는 일정한 간격으로 점을 배치한다.

```text
for row from 0 to rowCount - 1:
    for column from 0 to columnCount - 1:
        x = margin + column * spacing
        y = margin + row * spacing
        drawCircle(x, y, radius)
```

여기서 `row`와 `column`은 격자 안의 순서를 나타내고, `x`와 `y`는 실제 화면 위치다. 곱셈과 덧셈으로 인덱스를 좌표로 변환했기 때문에 모든 원이 일정한 간격으로 놓인다. 이 규칙에서 좌표 계산을 바꾸면 배치 전체가 바뀐다.

예를 들어 $y$좌표에 사인 함수의 결과를 더하면 원들이 파동을 따라 배치된다.

$$
y=y_0+A\sin(kx)
$$

$A$는 파동의 높이를, $k$는 공간 안에서 파동이 반복되는 빈도를 조절한다. 도형의 종류는 그대로지만 좌표를 만드는 규칙이 달라져 이미지의 구조가 변한다. 제너레이티브 작업에서 좌표를 설계한다는 것은 곧 배치 규칙을 설계한다는 뜻이다.

## 좌표를 함수의 입력으로 사용하는 방식

좌표는 도형을 어디에 그릴지 정하는 값일 뿐 아니라, 그 위치에서 무엇을 그릴지 계산하는 입력이기도 하다. 화면의 각 위치 $\mathbf{p}=(x,y)$를 색으로 대응시키는 함수를 생각해 보자.

$$
C(x,y)=(r,g,b)
$$

이 함수는 좌표 하나를 받아 색 하나를 반환한다. 화면의 모든 위치에서 함수를 계산하면 완전한 이미지가 만들어진다. 프래그먼트 셰이더, 이미지 처리, 프로시저럴 텍스처는 이 관점을 직접 사용한다.

가장 단순한 예로 $x$좌표를 밝기에 연결할 수 있다.

$$
B(x,y)=\frac{x}{W}
$$

$W$가 화면 너비라면 밝기 $B$는 왼쪽에서 0, 오른쪽에서 1에 가까워진다. $y$는 식에 들어 있지만 결과에 영향을 주지 않으므로, 같은 $x$좌표에 있는 위치는 모두 같은 밝기를 가진다. 결과는 가로 방향 그라데이션이다.

GLSL 계열 셰이더에서는 다음과 비슷하게 표현할 수 있다.

```glsl
vec2 uv = fragCoord / resolution;
float brightness = uv.x;
vec3 color = vec3(brightness);
```

이 코드는 특정 그래픽 객체를 생성하지 않는다. 현재 픽셀의 좌표를 읽고, 그 좌표로 색을 계산할 뿐이다. 모든 픽셀에서 같은 규칙이 실행되면 이미지 전체가 나타난다.

## 같은 좌표에서 여러 값을 계산하기

한 위치는 여러 함수의 입력이 될 수 있다. 중심에서의 거리는 밝기를 정하고, 좌표의 각도는 색상을 정하며, 노이즈 함수는 표면의 질감을 정할 수 있다.

```text
for each position p:
    distanceValue = distance(p, center)
    angleValue = angle(p - center)
    noiseValue = noise(p * scale)

    brightness = distanceToBrightness(distanceValue)
    hue = angleToHue(angleValue)
    texture = noiseToTexture(noiseValue)

    outputColor = combine(brightness, hue, texture)
```

복잡한 이미지도 이렇게 좌표에서 파생된 여러 값을 조합한 것으로 나누어 볼 수 있다. 중요한 것은 계산의 출발점이 같은 위치라는 점이다. 좌표는 거리, 방향, 각도, 반복 셀, 노이즈 샘플 위치 등 다양한 중간값으로 변환된다.

## 좌표를 바꾸면 이미지가 바뀐다

색을 계산하는 함수를 그대로 두고 입력 좌표만 바꾸어도 결과는 달라진다. 좌표에 값을 더하면 패턴이 이동하고, 좌표에 배율을 곱하면 확대되거나 축소된다. 좌표를 회전하면 패턴도 회전한다.

```text
p = currentPosition
p = p - center
p = rotate(p, angle)
p = p / scale

value = pattern(p)
```

이 방식은 완성된 이미지를 나중에 돌리거나 확대하는 것과 비슷해 보이지만, 실제로는 함수에 들어가는 위치를 먼저 변환한다. 함수는 변환된 좌표를 원래 좌표인 것처럼 받아 결과를 계산한다. 이 원리는 반복 패턴, 좌표 왜곡, 프로시저럴 텍스처, SDF 모델링에서 널리 사용된다.

좌표 변환의 순서는 결과에 영향을 준다. 원점에서 멀리 떨어진 상태로 회전하면 위치까지 크게 돌아가지만, 먼저 중심을 원점으로 옮긴 뒤 회전하면 그 중심을 기준으로 제자리에서 회전한다. 좌표를 다룰 때는 어떤 기준점을 사용하고 어떤 순서로 변환하는지 함께 살펴야 한다.

## 연속 좌표와 이산 이미지

수학적 평면은 위치가 연속적이다. 두 좌표 사이에는 언제나 다른 좌표가 있다. 반면 디지털 이미지는 유한한 픽셀 격자로 이루어진다. 화면 너비가 800픽셀이고 높이가 600픽셀이라면, 출력할 수 있는 픽셀의 수는 정해져 있다.

그렇다고 그래픽 계산에서 정수 좌표만 사용하는 것은 아니다. 도형의 중심은 $(135.4, 72.8)$처럼 픽셀 사이의 위치에 놓일 수 있고, 렌더러는 그 결과를 주변 픽셀에 반영한다. 텍스처 좌표와 보간된 정점 속성도 대개 실수로 계산된다.

이 차이는 다음 두 층을 구분하게 한다.

| 층 | 성격 | 예 |
| --- | --- | --- |
| 기하와 함수의 좌표 | 연속적인 실수로 계산할 수 있다. | 도형의 중심, 곡선 위의 위치, UV 좌표 |
| 출력 이미지 | 정해진 픽셀 격자에 기록된다. | 화면, PNG 이미지, 렌더 타깃 |

연속적인 규칙을 유한한 픽셀로 표현하는 과정에서는 계단 현상이나 샘플링 문제가 생길 수 있다. 뒤에서 안티앨리어싱, 텍스처 샘플링, 주파수를 다룰 때 이 차이가 다시 중요해진다.

## 이 절의 핵심

좌표는 이미지의 요소에 위치를 부여하고, 위치에 따라 값을 계산하게 하는 기본 입력이다. 좌표를 그래픽 객체의 배치에 사용할 수도 있고, 각 픽셀의 색을 반환하는 함수의 입력으로 사용할 수도 있다.

제너레이티브 아트에서는 좌표를 고정된 주소로만 보지 않는다. 좌표를 이동하고, 확대하고, 회전하고, 거리나 각도로 변환하면서 이미지의 구조를 만든다. 다음 절에서는 수학에서 익숙한 데카르트 좌표와 실제 화면에서 흔히 사용하는 좌표가 어떻게 다른지 살펴본다.
