# 2.5 로컬 공간과 월드 공간

장면에 여러 도형과 객체가 있으면 위치를 모두 화면 좌표 하나로 관리하기 어렵다. 도형을 이동할 때 구성 요소의 좌표를 다시 계산해야 하고, 회전과 크기 변경도 장면의 원점을 기준으로 처리해야 한다. 좌표 공간을 나누면 이 문제를 정리할 수 있다.

로컬 공간은 개별 객체의 기준이 되는 좌표 공간이고, 월드 공간은 객체들을 한 장면에 배치하는 공통 좌표 공간이다. 같은 점도 어느 공간에 표현하느냐에 따라 좌표값이 달라진다. 좌표값을 해석할 때는 숫자뿐 아니라 그 좌표가 속한 공간도 확인해야 한다.

## 객체 자체를 기준으로 하는 로컬 공간

로컬 공간에서는 객체의 기준점을 원점으로 둔다. 예를 들어 중심이 원점이고 반지름이 1인 원은 다음과 같이 정의할 수 있다.

$$
x^2+y^2\le 1
$$

이 원은 화면의 특정 위치에 놓인 상태가 아니라 로컬 좌표에서 모양만 정의된 상태다. 장면의 위치에 배치하려면 로컬 좌표를 월드 좌표로 변환한다.

```text
local circle:
    center = (0, 0)
    radius = 1

object transform:
    position = (120, 80)
    rotation = 30 degrees
    scale = (40, 40)
```

모양과 배치를 분리하면 여러 객체가 같은 원 정의를 공유하면서 위치, 회전, 크기를 각각 다르게 가질 수 있다.

로컬 원점이 반드시 기하학적 중심일 필요는 없다. 문은 경첩을 원점으로 삼아야 자연스럽게 회전하고, 팔은 어깨나 팔꿈치를 기준점으로 삼을 수 있다. 그래픽 도구에서는 이 기준점을 피벗이라고 부르기도 한다.

## 장면의 공통 기준인 월드 공간

월드 공간은 장면 안의 객체들이 공유하는 좌표계다. 객체 사이의 거리나 조명과 물체의 상대적 위치를 계산하려면 두 좌표를 같은 공간으로 표현해야 한다.

로컬 공간의 점 $\mathbf{p}_{local}$에 크기 변경, 회전, 이동을 적용하면 월드 공간의 점 $\mathbf{p}_{world}$를 얻는다.

$$
\mathbf{p}_{world}=T\,R\,S\,\mathbf{p}_{local}
$$

$S$는 크기 변경, $R$은 회전, $T$는 이동이다. 행렬과 벡터의 표기 관례에 따라 곱셈 순서는 달라질 수 있으므로 실제 적용 순서를 확인해야 한다. 일반적으로 로컬 모양의 크기를 조절하고 회전한 다음 장면의 위치로 옮긴다.

2차원에서 이를 개별 연산으로 쓰면 다음과 같다.

```text
world = local * scale
world = rotate(world, rotation)
world = world + position
```

이 변환은 객체의 모든 점에 적용된다. 모양은 로컬 공간에 남고 배치 정보는 변환에 담긴다.

## 같은 숫자라도 공간이 다르면 다른 위치다

로컬 좌표 $(10,0)$은 객체의 원점에서 오른쪽으로 10만큼 떨어진 점이다. 객체가 월드 공간의 $(100,50)$에 있고 회전하지 않았다면 이 점의 월드 좌표는 $(110,50)$이다. 객체를 90도 회전하면 같은 로컬 점도 다른 월드 위치에 놓인다.

따라서 다음과 같은 계산은 의미가 없다.

```text
distance = length(localPoint - worldLightPosition)
```

두 좌표가 서로 다른 공간에 있으므로 직접 뺄 수 없다. 거리를 계산하려면 로컬 점을 월드 공간으로 변환하거나 월드의 조명 위치를 객체의 로컬 공간으로 옮긴다.

```text
worldPoint = localToWorld(localPoint)
distance = length(worldPoint - worldLightPosition)
```

자료형이 같아도 좌표 공간과 단위가 다르면 직접 연산할 수 없다. 위치 관계를 계산하려면 둘을 같은 공간과 단위로 맞춘다.

## 역변환으로 패턴을 객체에 적용하기

객체를 그릴 때는 로컬 좌표를 월드 좌표로 변환한다. 반대로 화면이나 월드의 각 위치가 객체 안에 있는지 판정할 때는 샘플 좌표를 객체의 로컬 공간으로 되돌리는 편이 유용하다.

객체 변환을 $M$이라고 하면 다음 관계가 있다.

$$
\mathbf{p}_{world}=M\mathbf{p}_{local}
$$

역행렬 $M^{-1}$은 월드 좌표를 로컬 좌표로 변환한다.

$$
\mathbf{p}_{local}=M^{-1}\mathbf{p}_{world}
$$

```text
localPosition = worldToLocal(worldPosition)
value = evaluateShape(localPosition)
```

이 구조에서 원이나 사각형을 정의하는 함수는 이동과 회전을 알 필요가 없다. 함수는 원점 주변의 표준 도형을 계산하고, 입력 좌표를 역변환해 객체의 로컬 공간으로 가져온다. SDF, 레이 마칭, 프로시저럴 텍스처에서 널리 쓰이는 방식이다.

예를 들어 이동된 원을 판단하려면 현재 좌표에서 원의 중심을 뺀다.

```glsl
vec2 local = worldPosition - circlePosition;
float distanceToCircle = length(local) - radius;
```

이 뺄셈은 이동 변환의 역변환이다. 객체를 오른쪽으로 옮기는 대신 샘플 좌표를 왼쪽으로 이동해 표준 원 함수에 넣는다.

## 부모와 자식의 계층 구조

로컬 공간은 객체를 계층적으로 구성할 때 유용하다. 자식의 위치를 부모의 로컬 공간에서 정의하면 부모가 움직일 때 자식도 함께 이동한다.

사람의 팔에서 위팔은 몸통을, 아래팔은 위팔 끝의 팔꿈치를 기준으로 회전한다. 손은 아래팔 끝을 기준으로 배치된다. 손의 월드 변환은 각 단계의 변환을 차례로 결합해 얻는다.

$$
M_{hand}^{world}=M_{body}^{world}M_{upperArm}^{local}M_{forearm}^{local}M_{hand}^{local}
$$

제너레이티브 아트의 가지 구조, 로봇 관절, 반복되는 위성 궤도, 문자 조각, 장식 요소도 계층적으로 구성할 수 있다.

```text
drawBranch(transform, depth):
    draw current branch in its local space

    childA = transform * rotate(leftAngle) * scale(childScale)
    childB = transform * rotate(rightAngle) * scale(childScale)

    drawBranch(childA, depth - 1)
    drawBranch(childB, depth - 1)
```

각 가지는 로컬 공간에서 같은 모양을 사용하고, 월드 위치와 방향은 부모부터 누적된 변환에 따라 달라진다.

## 월드 공간 이후의 좌표 공간

화면에 결과를 출력하기까지 로컬 공간과 월드 공간 외에 여러 좌표 공간을 거칠 수 있다. 이름과 세부 정의는 렌더링 시스템마다 다르지만, 일반적인 흐름은 다음과 같다.

| 공간 | 기준 | 주된 역할 |
| --- | --- | --- |
| 로컬 또는 오브젝트 공간 | 개별 객체 | 객체의 모양 정의 |
| 월드 공간 | 장면 전체 | 객체 사이의 배치와 관계 계산 |
| 뷰 또는 카메라 공간 | 카메라 | 카메라에서 본 위치 계산 |
| 클립 공간 | 투영 변환 | 보이는 범위와 원근 처리 |
| 정규화 장치 공간 | 표준화된 출력 범위 | 화면으로 옮기기 전 좌표 |
| 화면 공간 | 픽셀 또는 뷰포트 | 최종 출력 위치 |

2차원 드로잉 API는 이 과정의 많은 부분을 내부에서 처리하므로 모든 공간을 직접 다룰 필요는 없다. 카메라, 3D 렌더링, 셰이더, 여러 렌더 타깃을 사용하면 공간의 구분이 분명해진다.

## 변환의 순서

이동, 회전, 크기 변경은 적용 순서에 따라 결과가 달라진다. 원점 기준으로 회전하기 전에 이동하면 이동 벡터까지 회전해 객체가 원점 주위를 돈다. 먼저 회전한 뒤 이동하면 방향을 바꾼 객체가 지정한 위치에 놓인다.

```text
resultA = translate(rotate(point))
resultB = rotate(translate(point))
```

`resultA`와 `resultB`는 대개 다르다. 변환을 행렬로 결합하는 라이브러리에서는 코드에 적힌 순서와 실제 적용 순서가 다르게 보일 수 있다. 행 우선·열 우선 저장 방식만 볼 것이 아니라 API가 벡터를 어느 쪽에 곱하고 변환을 어떻게 누적하는지 확인해야 한다.

회전이나 이동 결과가 예상과 다르면 다음을 확인한다.

- 현재 좌표는 어느 공간에 있는가?
- 변환의 기준점은 어디인가?
- 변환은 어떤 순서로 적용되는가?
- 이 함수는 좌표를 다른 공간으로 보내는가, 되돌리는가?
- 벡터가 위치인지 방향인지 구분되어 있는가?

## 위치와 방향의 변환 차이

이동은 위치를 바꾸지만 방향은 바꾸지 않는다. 객체를 오른쪽으로 옮겨도 바라보는 방향은 그대로다. 회전은 위치와 방향 모두에 영향을 줄 수 있다.

동차 좌표 행렬에서는 위치를 $(x,y,z,1)$로, 방향을 $(x,y,z,0)$으로 나타내 이동의 적용 여부를 구분한다. 행렬을 자세히 다루기 전이라도 위치와 방향을 같은 방식으로 변환하지 않는다는 점을 기억하자.

비균일 크기 변경에서 표면 법선은 별도의 변환이 필요하다. 3차원 변환과 조명을 다룰 때 자세히 살펴본다.

## 이 절의 핵심

로컬 공간은 객체의 모양과 구성 요소를 정의하는 좌표계이고, 월드 공간은 여러 객체를 한 장면에 배치하는 공통 좌표계다. 좌표값이 같아도 공간이 다르면 위치는 다르다.

객체 변환은 로컬 좌표를 월드 좌표로 옮기고, 역변환은 월드의 샘플 위치를 로컬 공간으로 가져온다. 공간과 변환을 분리하면 도형을 재사용하고 계층을 구성하며 복잡한 장면을 일관되게 관리할 수 있다. 다음 절에서는 두 좌표의 차이에서 거리, 방향, 각도를 구하는 방법을 살펴본다.
