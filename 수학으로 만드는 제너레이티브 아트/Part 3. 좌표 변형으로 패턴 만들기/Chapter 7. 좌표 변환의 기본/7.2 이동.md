# 7.2 이동

이동은 모든 점에 같은 벡터를 더해 위치를 바꾸는 변환이다. 모든 점이 같은 만큼 움직이므로 도형 안의 거리와 각도는 유지되고, 크기나 방향은 달라지지 않는다. 이동은 가장 단순한 변환이지만 로컬 도형을 여러 위치에 배치하고, 중심을 기준으로 패턴을 만들고, 시간에 따라 화면을 흐르게 할 때 계속 쓰인다.

객체의 점 $\mathbf{p}$를 이동 벡터 $\mathbf{t}$만큼 직접 옮긴다면 다음 식을 쓴다.

$$
\mathbf{p}'=\mathbf{p}+\mathbf{t}
$$

2차원에서는 $\mathbf{p}=(x,y)$, $\mathbf{t}=(t_x,t_y)$이므로 성분별 계산은 다음과 같다.

$$
\begin{pmatrix}
x'\\
y'
\end{pmatrix}
=
\begin{pmatrix}
x\\
y
\end{pmatrix}
+
\begin{pmatrix}
t_x\\
t_y
\end{pmatrix}
$$

오른쪽으로 80만큼, 아래로 30만큼 옮기려면 $\mathbf{t}=(80,30)$으로 둔다. 화면 좌표계에서는 보통 $y$가 아래쪽으로 증가한다. 따라서 수학 좌표계에서 위쪽을 나타내는 양의 $y$와 화면 좌표계에서 위쪽을 나타내는 음의 $y$를 혼동하면, 계산은 맞아도 도형이 예상과 반대 방향으로 움직인다.

## 객체를 옮기는 것과 좌표를 옮기는 것

도형을 직접 그리는 명령형 API에서는 도형의 위치에 이동 벡터를 더하는 방식이 직관적이다.

```text
circleCenter = baseCenter + translation
drawCircle(circleCenter, radius)
```

반면 거리 함수, 노이즈, 셰이더처럼 각 위치에서 값을 평가할 때는 도형 좌표 자체를 옮기기보다 현재 화면 위치를 도형의 원래 좌표계로 되돌린다. 이동된 도형을 현재 위치 $\mathbf{p}$에서 평가하는 식은 다음과 같다.

$$
d_{\text{moved}}(\mathbf{p})=d(\mathbf{p}-\mathbf{t})
$$

```glsl
vec2 local = position - translation;
float d = sdCircle(local, vec2(0.0), radius);
```

`translation`이 오른쪽으로 커질수록 원은 화면에서 오른쪽으로 이동한다. `position - translation`은 이동 방향과 반대처럼 보이지만, 각 화면 위치가 원래 좌표계에서 어디에 해당하는지 계산하는 역변환이다. 오른쪽으로 옮겨진 원의 중심에서는 `position`과 `translation`이 같아 `local`이 $(0,0)$이 된다. 이때 `sdCircle`은 중심까지의 거리에서 반지름을 뺀 값, 즉 $-radius$를 반환한다.

| 관점 | 계산 | 적합한 상황 |
| --- | --- | --- |
| 점이나 객체를 직접 이동 | $\mathbf{p}'=\mathbf{p}+\mathbf{t}$ | 드로잉 API, 객체 목록, 기하 데이터 |
| 함수 평가 좌표를 역이동 | $F(\mathbf{p}-\mathbf{t})$ | SDF, 셰이더, 프로시저럴 패턴 |

두 방식은 서로 다른 계산으로 같은 기하학적 이동을 표현한다. 하나는 원래 점이 이동한 뒤 어디에 놓이는지 계산하고, 다른 하나는 화면의 한 위치가 원래 도형의 어느 좌표에 해당하는지 계산한다.

## 로컬 공간을 만드는 가장 기본적인 방법

이동은 세계 좌표를 도형의 로컬 좌표로 바꾸는 첫 단계이기도 하다. 위치와 중심이 같은 세계 좌표계에 있을 때, 중심점 $\mathbf{c}$를 빼면 도형의 중심이 원점이 되는 로컬 좌표를 얻는다.

$$
\mathbf{p}_{\text{local}}=\mathbf{p}_{\text{world}}-\mathbf{c}
$$

```text
local = position - center
distanceValue = length(local)
```

방사형 패턴, 원과 다각형의 거리 함수, 극좌표 변환은 대부분 이 과정에서 시작한다. 도형을 화면 어디에 배치하더라도 함수에는 중심이 원점인 표준 형태의 좌표를 넣으면 된다.

```text
function circleDistance(position, center, radius):
    local = position - center
    return length(local) - radius
```

이 함수에서 `center`만 바꾸면 같은 원을 어느 위치에나 배치할 수 있다. `radius`나 색, 테두리 폭 같은 다른 속성과 위치를 분리해 두면, 하나의 표준 도형 함수를 반복해서 재사용할 수 있다.

## 여러 도형을 독립적으로 배치하기

같은 모양의 도형을 여러 위치에 배치할 때 각 도형은 서로 다른 이동 벡터를 갖는다. 각 위치에서 모든 도형 함수를 평가하는 방식은 셰이더나 SDF 합성에서 자주 사용한다.

```text
circleA = circleDistance(position, centerA, radiusA)
circleB = circleDistance(position, centerB, radiusB)
scene = min(circleA, circleB)
```

여기서 `circleA`, `circleB`는 원점 중심 원 함수에 서로 다른 중심점을 적용한 결과다. 도형의 정의와 배치를 분리하면 중심 목록만 바꿔 군집이나 격자, 경로를 따른 배치로 확장할 수 있다.

객체 목록을 직접 그릴 때도 같은 분리를 적용할 수 있다.

```text
for each instance:
    localShape = standardShape(instance.localParameters)
    worldPosition = instance.translation + localShape.position
    draw(worldPosition)
```

`translation`은 인스턴스의 위치를 뜻하고, `localParameters`는 도형 내부의 크기나 색 같은 성질을 뜻한다. 이동은 이렇게 도형 자체의 규칙과 그 도형이 놓이는 장소를 분리하는 역할을 한다.

이 예제에서 `localShape.position`은 표준 형태 안에서 정의된 점의 로컬 좌표다. 이를 인스턴스의 이동 벡터와 더해 월드 좌표로 바꾼 뒤 그린다.

## 이동 벡터의 합성과 기준점

이동은 덧셈이므로 여러 이동을 합쳐 하나의 이동으로 만들 수 있다.

$$
\mathbf{p}'=\mathbf{p}+\mathbf{t}_1+\mathbf{t}_2
$$

예를 들어 부모 객체의 위치, 자식 객체의 상대 위치, 마우스에 따른 오프셋을 더해 최종 위치를 만들 수 있다.

```text
worldPosition = parentPosition + localOffset + inputOffset
```

이 식은 간단하지만 각 좌표의 의미를 구분하지 않으면 같은 이동을 두 번 적용하기 쉽다. `parentPosition`은 월드 공간의 위치이고 `localOffset`은 부모를 기준으로 한 상대 위치다. 이 식은 이동만 있고 좌표축 방향이 서로 같을 때 그대로 쓸 수 있다. 부모에 회전이나 확대가 적용되어 있다면 `localOffset`도 그 변환을 거쳐 월드 공간으로 옮긴 뒤 더해야 한다.

이동 결과를 해석할 때는 도형의 기준점도 고려해야 한다. 사각형의 좌표가 왼쪽 위 모서리인지 중심인지, 선의 좌표가 시작점인지 중점인지에 따라 같은 `translation`을 적용해도 보이는 위치가 달라진다. 기준점을 명시하면 여러 도형을 정렬하기 쉽다.

```text
# 중심 기준 사각형을 그리기 위한 좌상단 위치
topLeft = center - (width, height) * 0.5
drawRectangle(topLeft, width, height)
```

## 시간에 따른 이동

이동 벡터를 시간의 함수로 만들면 일정한 속도의 움직임이 된다.

$$
\mathbf{t}(t)=\mathbf{t}_0+\mathbf{v}t
$$

여기서 $\mathbf{t}_0$는 시작 위치, $\mathbf{v}$는 속도 벡터다. 속도 벡터의 방향은 이동 방향을, 길이는 단위 시간당 이동 거리를 정한다.

```text
translation = initialPosition + velocity * elapsedTime
local = position - translation
value = shape(local)
```

좌표 단위를 픽셀, 시간을 초로 사용한다면 `velocity`의 단위는 픽셀/초다. 시작 위치에서 매 프레임 위치를 계산할 때는 누적 경과 시간인 `elapsedTime`을 사용하고, 직전 위치에 이동량을 누적할 때는 해당 프레임이 지난 시간인 `deltaTime`을 사용한다. 프레임 번호를 시간처럼 곧바로 곱하면 프레임 속도에 따라 실제 이동 속도가 달라진다. 시간에 따른 움직임의 상세한 설계는 Part 5에서 다룬다.

패턴 전체를 흐르게 만들 때도 같은 원리를 쓴다.

$$
v(\mathbf{p},t)=F(\mathbf{p}-\mathbf{v}t)
$$

여기서 $v(\mathbf{p},t)$는 해당 위치와 시간의 패턴값이고, 굵은 글씨의 $\mathbf{v}$는 패턴을 이동시키는 속도 벡터다.

```text
direction = normalize((1, 1))
samplePosition = position - direction * speed * elapsedTime
value = pattern(samplePosition)
```

대각선 벡터 $(1,1)$의 길이는 $\sqrt{2}$다. 정규화하지 않으면 가로 또는 세로 방향으로 움직일 때보다 대각선 이동 속도가 커진다. 방향 벡터를 정규화하고 속도는 별도 스칼라 `speed`로 곱하면 방향과 이동 속도를 독립적으로 조절할 수 있다.

## 화면 경계와 이동의 의미

도형이나 패턴이 이동하면 화면 또는 버퍼의 경계를 지나게 된다. 그 뒤의 처리는 이동 규칙과 함께 정해야 한다. 화면 밖으로 나간 객체를 제거할지, 반대편으로 보낼지, 경계에서 멈추거나 반사시킬지에 따라 움직임의 인상이 달라진다.

| 경계 처리 | 좌표 또는 객체 처리 | 시각적 인상 |
| --- | --- | --- |
| 제거 | 화면 밖의 객체를 목록에서 삭제한다. | 흘러나가고 사라지는 흐름 |
| 래핑 | 좌표를 화면 범위로 다시 감싼다. | 끝없이 이어지는 공간 |
| 고정 | 좌표를 경계값으로 제한한다. | 벽에 닿아 멈추는 느낌 |
| 반사 | 경계에서 속도 성분의 부호를 바꾼다. | 튕김, 닫힌 공간 |

```text
position.x = wrap(position.x, 0, width)
position.y = wrap(position.y, 0, height)
```

이 예제는 객체의 기준점이 화면 범위 $[0,width)$와 $[0,height)$ 안에 오도록 감싼다. 크기가 있는 도형이 경계를 통과할 때 전체 모양이 자연스럽게 이어지게 하려면 중심점뿐 아니라 도형의 크기도 고려해야 한다.

반복 좌표와 타일링의 구체적인 원리는 다음 장에서 다룬다. 이 절에서는 이동이 단순히 화면 안의 위치를 바꾸는 것에 그치지 않고, 경계를 통과한 뒤 어떤 세계 규칙을 따를지도 결정한다는 점을 이해하면 충분하다.

## 이동을 점검하는 방법

이동 수식은 단순하지만 좌표계나 기준점을 혼동하면 위치 오류가 생긴다. 문제를 찾을 때는 복잡한 노이즈와 여러 도형을 잠시 제외하고, 원점과 축을 표시해 좌표가 어떻게 바뀌는지 확인한다.

```text
drawAxisAt(origin)
drawPoint(center)
drawShape(position - center)
```

다음 항목을 점검하면 대부분의 이동 문제를 빠르게 구분할 수 있다.

- 함수 평가 좌표에서 이동 벡터를 더해야 하는지 빼야 하는지 확인한다.
- 화면 좌표계의 $y$축 방향과 사용 중인 수학 좌표계의 방향을 구분한다.
- 위치가 중심 기준인지 모서리 기준인지 확인한다.
- 시간 기반 이동에서는 속도의 단위가 거리/초인지 확인한다.
- 여러 오프셋이 같은 좌표 공간에서 더해지고 있는지 확인한다.

이동은 형태를 바꾸지 않는 변환이다. 먼저 이동만 적용해 중심과 단위를 확인한 뒤 회전이나 확대, 왜곡을 더하면 문제의 원인을 찾기 쉽다.

## 이 절의 핵심

객체의 좌표에는 이동 벡터를 더하고, 함수 평가용 샘플 좌표에는 그 벡터를 뺀다. 중심을 빼면 월드 공간의 위치를 로컬 좌표로 바꿔 표준 도형 함수를 여러 위치에서 재사용할 수 있다. 이동 벡터의 단위와 기준점, 경계 처리, 좌표 공간의 의미를 분명히 하면 정적인 배치와 시간에 따른 움직임을 안정적으로 설계할 수 있다.
