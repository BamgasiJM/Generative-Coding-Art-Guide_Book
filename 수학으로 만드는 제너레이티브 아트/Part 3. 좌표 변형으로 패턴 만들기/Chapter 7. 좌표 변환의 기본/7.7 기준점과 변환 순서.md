# 7.7 기준점과 변환 순서

같은 이동·확대·회전도 기준점을 어디에 두고 어떤 순서로 적용하는지에 따라 결과가 달라진다. 예상하지 못한 공전이나 위치 변화는 기준점 또는 변환 순서를 잘못 해석했을 때 자주 생긴다.

## 기준점 바꾸기

원점이 아닌 점 $\mathbf{c}$를 기준으로 회전하려면 세 단계를 사용한다.

$$
\mathbf{p}'=\mathbf{c}+R(\mathbf{p}-\mathbf{c})
$$

이 식은 회전 중심을 바꾸는 과정을 나타낸다. 먼저 $\mathbf{p}-\mathbf{c}$로 기준점 $\mathbf{c}$를 원점으로 옮기고, 원점 기준 회전 $R$을 적용한 뒤, $\mathbf{c}$를 다시 더해 월드 좌표로 돌아간다. $\mathbf{p}=\mathbf{c}$를 대입하면 로컬 좌표가 $(0,0)$이고 회전 뒤에도 그대로이므로 결과는 다시 $\mathbf{c}$다. 기준점이 회전 중 움직이지 않는 이유다.

```text
local = position - pivot
rotated = rotate(local, angle)
result = rotated + pivot
```

확대도 같은 구조를 쓴다.

$$
\mathbf{p}'=\mathbf{c}+S(\mathbf{p}-\mathbf{c})
$$

여기서 $S$는 축별 배율을 적용하는 확대·축소 변환이다. 회전과 마찬가지로 먼저 기준점을 원점으로 옮겨야 그 점이 고정된다. 화면 중앙을 기준으로 확대하면 중앙은 제자리에 남고 주변이 바깥으로 멀어진다. 왼쪽 위 원점을 기준으로 확대하면 화면의 점들이 그 원점에서 멀어진다. 도형 중심, 선분의 끝점, 화면 중앙 중 무엇을 기준으로 삼는지는 어떤 부분을 고정할지 정하는 선택이다.

같은 도형도 중심을 기준으로 회전하면 제자리에서 방향만 바뀌고, 도형 바깥의 점을 기준으로 회전하면 그 점을 중심으로 공전한다. 기준점이 도형의 일부인지, 장면 전체의 기준인지, 다른 객체의 위치인지 이름으로 구분해 두면 여러 변환을 결합할 때 혼동이 줄어든다.

## 순서는 교환되지 않는다

일반적으로 이동 후 회전과 회전 후 이동은 다르다.

$$
R(T(\mathbf{p}))\ne T(R(\mathbf{p}))
$$

이 부등식은 이동과 회전의 순서를 바꾸면 결과가 일반적으로 달라진다는 뜻이다. 원점 기준 회전은 도형의 방향뿐 아니라 원점에 대한 위치도 바꾼다. 이동을 먼저 적용하면 이동 벡터까지 회전하지만, 회전한 뒤 이동하면 도형을 지정한 위치에 놓을 수 있다.

먼저 이동하고 원점 기준으로 회전하면 이동 벡터까지 함께 돌아간다. 먼저 회전하고 이동하면 도형의 방향만 바뀐 뒤 지정한 위치에 놓인다.

```text
orbiting = rotate(position + offset, angle)
oriented = rotate(position, angle) + offset
```

`orbiting`에서는 `offset`을 더한 위치까지 원점을 중심으로 회전하므로 도형이 궤도를 돈다. `oriented`에서는 먼저 도형의 방향을 바꾸고 회전 뒤 `offset`을 더하므로 지정한 위치에 놓인다. 두 코드의 항 순서는 움직임을 궤도로 만들지, 위치를 유지한 방향 전환으로 만들지를 결정한다.

확대와 이동의 순서도 결과를 바꾼다. 먼저 확대하고 이동하면 크기가 바뀐 도형을 지정한 위치로 옮긴다. 이동한 뒤 확대하면 이동량까지 확대되어 기준점에서 더 멀어진다. 무엇을 마지막에 배치하거나 고정할지 생각하면 원하는 순서를 정하기 쉽다.

## 역변환 순서

함수 평가에서 순방향 변환의 역변환을 적용할 때는 순서도 반대가 된다. 도형에 순서대로 확대, 회전, 이동을 적용했다면, 현재 샘플 좌표에는 이동을 되돌리고, 회전을 되돌리고, 확대를 되돌린다.

```text
local = position - translation
local = rotate(local, -angle)
local = local / scale
value = shape(local)
```

순방향으로 `scale -> rotate -> translate`를 적용했다면, 로컬 좌표를 되찾을 때는 마지막에 한 이동부터 취소한다. 따라서 `translation`을 빼고, 반대 각도로 회전한 뒤, 배율을 나눈다. 각 연산을 역연산으로 바꾸고 **적용 순서도 거꾸로 하는 것**이 역변환의 핵심이다.

간단한 검증 방법은 로컬 원점 $(0,0)$을 확인하는 것이다. 순방향 변환 뒤 이 점은 도형의 중심 위치에 놓인다. 역변환에 그 중심 위치를 넣었을 때 다시 $(0,0)$이 나와야 한다. 그렇지 않다면 변환 순서, 기준점, 부호를 점검한다.

이 역변환을 사용하면 표준 도형 함수는 로컬 공간에서 같은 정의를 유지한다.

## 변환을 읽는 방향

순방향 변환은 로컬 도형의 점을 월드 공간으로 보내고, 역변환은 현재 화면 위치를 로컬 좌표로 되돌린다. 구현 전에 두 흐름을 나란히 적으면 순서를 혼동하기 어렵다.

```text
local shape -> scale -> rotate -> translate -> world
world sample -> subtract translation -> inverse rotate -> divide scale -> local
```

첫째 줄은 표준 도형의 로컬 점을 월드 공간으로 보내는 순방향이고, 둘째 줄은 화면 샘플을 로컬 공간으로 되돌리는 역방향이다. SDF나 셰이더에서는 보통 두 번째 흐름을 직접 계산한다.

열벡터에 행렬을 곱하는 표기에서는 행렬 곱의 오른쪽 변환이 먼저 점에 적용된다. 따라서 코드를 읽을 때 곱셈 순서와 벡터에 작용하는 순서를 구분한다. 비대칭 화살표와 기준점을 그려 공전과 제자리 회전을 비교하면 사용 중인 API의 관례를 확인할 수 있다.

변환 오류를 찾을 때는 원이나 정사각형처럼 대칭적인 도형에만 의존하지 않는다. 방향이 있는 화살표, 한쪽 모서리에 점이 찍힌 사각형, 기준점을 표시하는 점을 함께 그리면 회전 방향과 기준점, 이동 순서를 확인하기 쉽다.

## 이 절의 핵심

변환의 기준점은 무엇을 고정할지 정하고, 변환 순서는 결과를 바꾼다. 함수 평가에서는 순방향 연산을 각각 역연산으로 바꾸고 적용 순서를 거꾸로 해 로컬 좌표를 찾는다.
