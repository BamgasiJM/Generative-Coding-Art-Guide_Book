# 들어가며

제너레이티브 아트(Generative Art)는 화면에 무엇을 그릴지 하나씩 정하기보다, 어떤 규칙으로 이미지를 만들어 낼지 설계하는 작업이다.

선의 시작점과 끝점을 직접 정할 수도 있고, 두 점의 위치를 계산하는 규칙을 만들 수도 있다. 원을 한 곳에 그리는 대신 화면의 각 점과 중심점 사이의 거리를 계산해 원의 경계를 정의할 수도 있다.

이 책은 후자의 관점에서 이미지를 다룬다. 완성된 도형의 집합이 아니라 좌표와 함수, 값이 만들어 내는 결과로 본다. 화면의 각 점에는 좌표가 있고, 좌표는 함수의 입력이 된다. 함수는 거리와 각도, 밝기, 색, 방향, 속도 같은 값을 계산한다. 그 값이 도형과 패턴, 움직임을 만들고 서로 연결되어 하나의 시스템을 이룬다.

이 구조를 이해하면 그래픽 환경이 달라져도 아이디어를 옮기기 쉬워진다. p5.js의 원형 패턴을 GLSL 프래그먼트 셰이더로 다시 만들거나, Processing의 반복 구조를 openFrameworks나 nannou로 옮길 수 있다. 화면의 2D 패턴을 Blender의 프로시저럴 재질이나 OSL 셰이더로 확장하는 것도 가능하다. 문법은 달라도 바탕이 되는 수학과 구조는 이어진다.

이 책은 수학을 먼저 공부한 뒤 그래픽에 적용하기보다, 이미지를 만들면서 필요한 수학을 만나는 과정을 보여준다. 좌표를 움직이다 보면 벡터를 만나고, 원을 만들다 보면 거리를 계산하게 된다. 부드러운 경계에는 보간이, 반복 패턴에는 나머지 연산과 정규화된 좌표가 쓰인다. 수학을 이미지를 만드는 도구로 다루는 것이 이 책의 목표다.

## 그림을 직접 그리기보다 규칙을 설계한다

일반적인 드로잉에서는 결과를 먼저 떠올리고 필요한 도구를 고른다. 한쪽에 선을 긋고 다른 곳에 원을 놓은 뒤 배경색을 정한다. 제너레이티브 아트에서도 시각적 목표는 중요하다. 다만 개별 요소를 배치하는 데 그치지 않고, 요소들이 만들어지는 관계를 설계한다.

화면에 원 여러 개를 그리는 장면을 생각해 보자. 각 원의 위치와 크기를 정해 하나씩 놓는 것이 직관적이다. 하지만 원이 많아지거나 서로 영향을 주고, 시간이 흐르며 움직여야 하면 다른 접근이 필요하다. 원의 위치를 격자 셀의 인덱스(순번)로 계산하고, 크기를 중심점까지의 거리로 정할 수 있다. 색은 노이즈 값에 연결하고 시간값을 더해 움직임을 만들 수도 있다. 그러면 이미지는 고정된 배치가 아니라 계산과 규칙에 따라 그려지는 구조가 된다.

제너레이티브 아트는 작가가 세운 규칙으로 생성된다. 화면에 보이는 모양과 크기, 색, 변화에 대한 반응을 하나하나 지정할 필요는 없다. 모든 요소를 직접 통제하는 대신 변화가 일어날 범위와 조건을 정한다. 무작위 값을 쓰더라도 시드와 범위, 분포, 제한 조건으로 결과의 성격을 조절한다. 반복 구조도 단순히 복사하는 데 그치지 않고 각 반복에 변화를 줄 수 있다. 규칙을 조합하면 작가가 미리 예상하지 못한 형태가 나타나고, 관객에게 새로운 인상을 줄 수 있다.

이 책에서는 다음 질문을 따라 수학적 규칙이 제너레이티브 아트를 만드는 과정을 살펴본다.

- 이 이미지는 어떤 입력값에서 시작하는가?
- 그 입력값은 어떤 함수나 규칙을 통과하는가?
- 함수의 결과는 색, 위치, 크기, 회전, 밀도, 속도 중 무엇으로 바뀌는가?
- 변화가 있다면 어떤 파라미터로 조절되는가?
- 같은 규칙을 다른 그래픽 환경에서는 어떻게 표현할 수 있는가?

이 질문은 책 전체에 걸쳐 이어진다. 좌표를 정하고, 거리장을 다루고, 노이즈나 입자 시스템을 설계할 때도 같은 틀을 사용한다. 단순한 값을 색으로 바꾸는 데서 시작해 여러 규칙이 연결된 아트워크 구조를 설계하는 데까지 나아간다.

## 이 책이 다루는 그래픽 시스템과 환경

제너레이티브 아트는 특정 프로그램이나 언어에 한정되지 않는다. 브라우저에서 실행하는 p5.js, C++ 기반의 openFrameworks, GPU 셰이더로도 작업할 수 있다. 같은 수학적 아이디어가 2D 캔버스와 3D 공간, 표면 재질, 실시간 그래픽 시뮬레이션에서 서로 다른 역할을 맡는다.

이 책은 여러 그래픽 라이브러리와 프레임워크의 문법을 깊게 다루는 레퍼런스라기보다, 각 시스템이 이미지를 계산하는 방식의 차이를 비교하는데 집중한다. 어떤 환경은 도형을 명령으로 그리고, 어떤 환경은 픽셀마다 함수를 평가한다. 프레임마다 상태를 갱신하는 라이브러리도 있고, 표면 위 한 점에서 재질 값을 계산하는 언어도 있다. 차이와 공통 원리를 함께 이해하면 환경이 달라져도 아트워크의 핵심 아이디어를 이어갈 수 있다.

이 책에서 주로 다루는 그래픽 시스템은 다음과 같다.

| 구분            | 그래픽 시스템           | 이 책에서 보는 관점                            |
| ------------- | ----------------- | -------------------------------------- |
| 크리에이티브 코딩     | p5.js, Processing | 주로 2D에서 좌표, 도형, 반복, 애니메이션을 빠르게 실험하는 환경 |
| 게임 루프 기반 드로잉  | raylib            | 명시적인 루프와 입력 처리를 바탕으로 실시간 그래픽을 구성하는 환경  |
| 함수형 크리에이티브 코딩 | Quil              | 상태와 드로잉을 함수 중심으로 조직하는 환경               |
| C++ 크리에이티브 코딩 | openFrameworks    | 입력, 미디어, 시뮬레이션, 셰이더를 결합하는 환경           |
| 현대적 크리에이티브 코딩 | nannou, OPENRNDR  | Rust와 Kotlin 기반으로 그래픽 구조를 설계하는 환경      |
| 실시간 셰이딩       | GLSL, HLSL        | GPU에서 픽셀, 정점, 텍스처, 필드를 계산하는 환경         |
| 프로시저럴 재질      | OSL               | 화면이 아니라 메시 표면 위의 재질과 변위를 계산하는 환경       |

각 시스템은 작업 방식과 강점이 다르다. p5.js는 웹에서 빠르게 실험하기 좋고, openFrameworks는 그래픽뿐 아니라 설치 예술의 미디어 연동에도 강하다. GLSL은 픽셀 단위 패턴과 실시간 효과에 적합하며, OSL은 3D 표면의 재질을 수학적으로 만드는 데 쓰인다. 어떤 시스템을 고를지는 아트워크의 규칙에 필요한 계산과 결과를 보여줄 매체에 따라 달라진다.

## 수학적 모델과 구현 시스템의 관계

수학적 모델은 이미지를 만드는 데 필요한 규칙을 수식이나 알고리즘으로 정리한 것이다. 중심에서 멀어질수록 색이 어두워지는 이미지라면 거리값을 이용하는 모델이 필요하다. 좌표를 일정한 간격으로 반복해 무늬를 만든다면 타일링 모델을 사용한다. 입자가 보이지 않는 흐름을 따라 움직이는 장면에는 벡터 필드와 시간 업데이트가 들어간다.

구현 시스템은 이 모델을 실제 코드로 옮기는 환경이다. 같은 모델도 시스템에 따라 다르게 표현된다. 드로잉 API에서는 반복문으로 여러 도형을 그릴 수 있고, 셰이더에서는 화면의 각 픽셀이 자기 좌표를 입력으로 받아 색을 계산한다. 프로시저럴 재질에서는 표면 위의 점이 위치와 노멀, UV 좌표를 바탕으로 색과 거칠기, 변위를 정한다.

원의 예를 보자. 드로잉 API에서는 `circle()`이나 `ellipse()`를 호출해 원을 그리는 경우가 많다. 셰이더에서는 이런 도형 함수를 호출하는 대신 픽셀 좌표와 중심점 사이의 거리를 계산하고, 그 거리가 반지름보다 작은지 판단해 색을 정한다. OSL에서는 표면 좌표를 기준으로 거리 패턴을 계산해 재질의 색이나 범프 값에 연결할 수 있다. 결과는 모두 원형 패턴이지만 이를 만드는 수학적 모델과 구현 방식은 다르다.

어떤 환경에서는 도형이, 어떤 환경에서는 픽셀이, 또 어떤 환경에서는 표면 위의 샘플 지점이 기본 단위가 된다. 더 아래로 내려가면 공통된 질문이 남는다. 좌표는 무엇인가? 거리는 어떻게 계산하는가? 값의 범위는 어디까지인가? 그 값을 색이나 형태로 어떻게 바꾸는가?

이 책은 이러한 공통 질문에서 제너레이티브 아트를 탐구한다.

## 이 책의 기본 흐름

책은 단순한 개념에서 복잡한 시스템으로 나아간다. 먼저 좌표와 숫자 값을 다루고, 함수를 이용해 형태를 만든 뒤 좌표를 변형해 패턴을 만든다. 이어 랜덤과 노이즈, 필드, 시간, 상태, 피드백을 더해 이미지가 변화하는 시스템으로 확장한다. 마지막에는 같은 수학적 아이디어를 여러 그래픽 환경으로 옮기고, 프로젝트를 통해 앞에서 다룬 흐름을 다시 묶는다.

학습 흐름을 요약하면 다음과 같다.

| 단계 | 핵심 질문 | 결과 |
| --- | --- | --- |
| 좌표 | 화면의 한 점을 어떻게 표현할 것인가? | 위치, 거리, 방향, 각도 |
| 함수 | 입력값을 어떤 규칙으로 바꿀 것인가? | 그래프, 곡선, 파동 |
| 값 | 계산 결과를 어떻게 시각 요소로 연결할 것인가? | 색, 밝기, 크기, 회전 |
| 변형 | 좌표계를 어떻게 움직일 것인가? | 이동, 회전, 확대, 접기 |
| 도형 | 형태를 어떻게 정의할 것인가? | 원, 선, 사각형, 다각형, SDF |
| 조합 | 여러 형태와 값을 어떻게 합칠 것인가? | 마스크, 레이어, 블렌딩 |
| 반복 | 같은 규칙을 어떻게 배열할 것인가? | 격자, 타일, 패턴 |
| 필드 | 공간 전체에 값을 어떻게 배치할 것인가? | 스칼라 필드, 벡터 필드, 흐름 필드 |
| 시간 | 값이 어떻게 변하게 할 것인가? | 애니메이션, 루프, 움직임 |
| 시스템 | 상태와 피드백을 어떻게 다룰 것인가? | 입자, 성장, 시뮬레이션 |
| 작품 | 여러 규칙을 어떻게 하나로 구성할 것인가? | 정적 이미지, 애니메이션, 인터랙티브 작업 |

실제 작업에서 이 순서를 그대로 따를 필요는 없다. 특정 시각 효과에서 출발해 필요한 개념을 찾아갈 수도 있고, 수학적 구조를 실험하다 작품의 방향을 발견할 수도 있다. 학습은 좌표와 값에서 시작해 시스템으로 확장하는 편이 안정적이다. 복잡한 구조도 앞에서 익힌 좌표와 함수, 값의 조합으로 돌아가 이해할 수 있기 때문이다.

## 각 장의 구성 방식

각 장은 네 가지 층위로 내용을 전개한다. 먼저 이미지를 만드는 데 필요한 수학 개념과 그 개념이 해결하는 시각적 문제를 살펴본다.

다음으로 개념이 이미지에서 어떻게 나타나는지 해석한다. 사인 함수는 선 그래프와 밝기 패턴, 파동 애니메이션에서 서로 다르게 보인다. 거리 함수도 숫자 계산에 그치지 않고 경계와 외곽선, 그라데이션, 마스크를 만드는 도구가 된다. 수식이 이미지의 재료로 쓰이는 방식에 주목한다.

세 번째로 구현 전략을 정리한다. 어떤 값이 입력과 출력인지, 어느 단계에서 정규화해야 하는지, 조절할 파라미터를 어떻게 둘지 살펴본다. 특정 언어의 문법보다 알고리즘의 뼈대를 이해하는 데 초점을 둔다.

마지막으로 그래픽 환경에 따라 구현이 어떻게 달라지는지 비교한다. 같은 원리를 p5.js, Processing, raylib, Quil, openFrameworks, nannou, OPENRNDR, GLSL, HLSL, OSL에서 어떻게 표현하는지 살펴본다. 모든 장에서 모든 환경을 같은 깊이로 다루지는 않는다. 개념에 적합한 환경을 중심으로 설명하고, Part 6과 Part 7에서 여러 환경을 본격적으로 비교한다.

코드를 읽을 때는 그대로 옮기는 데 그치지 말고 코드가 어떤 계산을 하는지 따라가자. 변수나 함수 이름이 달라져도 입력과 출력이 무엇인지 알면 다른 환경으로 옮길 수 있다.

## 이 책을 읽는 방법

이 책은 처음부터 차례로 읽을 수 있게 구성했다. 제너레이티브 아트나 그래픽 프로그래밍을 처음 접한다면 Part 1부터 시작하는 것이 좋다. 좌표와 값의 범위, 정규화, 보간은 뒤의 여러 장에서 반복해서 쓰인다.

p5.js나 Processing에 익숙하다면 Part 2와 Part 3에서 함수 기반 형태와 좌표 변형을 먼저 살펴봐도 좋다. 셰이더에 관심이 있다면 Part 5까지의 개념을 익힌 뒤 Part 6의 셰이딩 언어로 넘어갈 수 있다. GLSL이나 HLSL을 처음 다루더라도 앞부분의 좌표와 거리 함수, 반복, 노이즈가 바탕이 된다.

3D 재질이나 Blender 작업에 관심이 있다면 OSL과 프로시저럴 재질을 다루는 장을 중심으로 읽을 수 있다. 이때 2D 패턴을 화면 효과로만 보지 않고 표면 위에서 계산되는 값으로 확장해 본다. 원과 격자, 노이즈, 방사형 패턴은 화면과 표면 양쪽에서 쓰인다. 값이 색이나 거칠기, 변위 중 무엇으로 연결되는지가 달라진다.

후반부의 프로젝트는 앞에서 배운 개념을 다시 묶는다. 하나의 완성 예제를 제시하기보다 여러 그래픽 시스템으로 옮길 수 있는 구조를 보여준다. 같은 아이디어를 다른 언어로 구현해 보면 수학적 모델과 그래픽 환경의 문법을 구분하는 데 도움이 된다.

## 결과보다 구조를 보는 연습

제너레이티브 아트는 예측과 우연이 함께 작동한다. 규칙을 세워도 결과가 늘 예상대로 나오지는 않는다. 파라미터의 작은 변화가 여러 함수를 거치며 전혀 다른 이미지를 만들고, 단순한 반복이 복잡한 질감으로 이어지기도 한다. 마음에 드는 결과를 얻는 데서 멈추지 말고, 왜 그런 형태가 나왔는지 어떤 값이 이미지의 성격을 바꾸었는지 살펴보자. 그래야 그 변화를 다시 조절할 수 있다.

좋은 제너레이티브 작업은 보통 하나의 효과를 내는 함수만으로 끝나지 않는다. 좌표와 값의 범위, 반복 구조, 랜덤을 넣는 위치, 시간 변화의 속도가 서로 영향을 주며 작동한다. 이 책은 개별 기법뿐 아니라 기법들이 연결되는 방식도 다룬다.

작은 규칙 하나로 시작해도 충분하다. 화면 중심에서 멀어질수록 색이 바뀌거나, 좌표를 반복해 격자를 만들거나, 시간값으로 파동을 움직이는 식이다. 규칙을 하나씩 더해 거리값에 노이즈를 섞고, 반복 좌표를 회전시키고, 필드의 방향을 따라 입자를 움직일 수 있다. 이전 프레임의 결과를 다음 입력으로 사용하면 시스템은 다시 확장된다. 규칙들이 쌓이면서 하나의 시각 예술 시스템을 이룬다.

완벽한 공식을 찾기보다 이미지가 계산되는 방식을 익히는 일이 중요하다. 좌표를 입력으로, 함수를 변환 규칙으로, 값을 시각 요소로 다루고 시간도 계산의 한 축으로 생각해 보자. 이 사고방식은 그래픽 환경이 달라져도 같은 아이디어를 이어가는 데 도움이 된다.

첫 장에서는 제너레이티브 아트의 기본 사고방식을 살펴본다. 그림을 하나씩 그리는 대신, 그림이 만들어지는 조건을 설계하는 일부터 시작한다.
