# 들어가며
 
제너레이티브 아트(Generative Art)에서 중요한 것은 화면에 무엇을 그릴지 하나씩 정하는 것이 아니라 어떤 규칙을 거쳐서 이미지를 만들어내는지를 정하는 일이다. 

선 하나의 시작과 끝을 직접 지정할 수도 있지만, 두 점의 위치를 계산하는 규칙을 만들 수도 있다. 원 하나를 특정 위치에 그릴 수도 있지만, 화면의 모든 점이 중심점에서 얼마나 떨어져 있는지 계산한 뒤 그 결과로 원의 경계를 만들 수도 있다.

이 책은 위 예시의 두 번째 관점을 다룬다. 이미지를 완성된 도형의 집합으로 보기보다, 좌표와 함수와 값이 만들어 내는 결과로 본다. 화면 위의 한 점에는 좌표가 있고, 좌표는 함수의 입력이 된다. 함수는 거리, 각도, 밝기, 색, 방향, 속도 같은 값을 만든다. 그 값들이 다시 도형이 되고, 패턴이 되고, 움직임이 되고, 모여서 하나의 시스템이 된다.

이 개념에 익숙해지면 아트워크 제작을 위한 환경이 달라져도 그래픽 아이디어를 쉽게 옮겨 갈 수 있다. p5.js에서 만든 원형 패턴을 GLSL 프래그먼트 셰이더로 다시 만들 수 있고, Processing에서 만든 반복 구조를 openFrameworks나 nannou로 옮길 수 있다. 화면 위의 2D 패턴을 Blender의 프로시저럴 재질이나 OSL 셰이더로 확장할 수도 있다. 코드의 문법은 달라지지만, 그 아래에서 작동하는 수학 개념과 구조는 동일하다.

이 책은 수학을 공부한 후 그래픽에 적용하기 보다는 이미지를 만들면서 필요한 수학을 만나는 다양한 길을 보여준다. 좌표를 움직이다 보면 벡터를 만나고, 원을 만들다 보면 거리를 만나고, 부드러운 경계를 만들다 보면 보간을 만나고, 반복 패턴을 만들다 보면 나머지 연산과 정규화된 좌표를 만나게 된다. 이미지를 직조하는 도구로써 수학을 사용하는 방법을 익히도록 하는 것이 목표이다.

## 그림을 직접 그리기보다 규칙을 설계한다

일반적인 드로잉 작업에서는 결과를 먼저 떠올리고 필요한 도구를 꺼낸다. 여기에 선을 긋고, 저기에 원을 놓고, 배경색을 정한다. 물론 제너레이티브 아트에서도 시각적 목표는 중요하다. 하지만 요소를 만들어 내는 관계를 설계하는 것이 개별 요소를 배치하는 것보다 더 강한 흐름으로 작용한다.

예를 들어 여러 개의 원을 화면에 그리는 작업을 떠올려보자. 직관적인 방법은 원의 위치와 크기를 하나씩 정해서 배치하는 것이다. 그러나 원의 개수가 늘어나거나, 각 원이 서로 영향을 주거나, 시간이 지나며 움직여야 한다면 다른 방식으로 작업에 접근해야 한다. 제너레이티브 아트 스타일로 작업을 한다면 원의 위치를 격자 셀의 인덱스(순번)로부터 계산하고, 크기를 중심점과의 거리로 정하고, 색을 노이즈 값으로 바꾸고, 시간이 흐른 정도를 더해 움직임을 만들 수 있다. 이렇게 하면 이미지는 고정된 배치가 아니라 계산이 가능하고 자동으로 그려지는 하나의 구조가 된다.

제너레이티브 아트는 작가가 세운 규칙을 통해 생성된다. 이렇게 '생성'이 되는 아트워크의 특징은 화면 위에 보이는 모든 것, 즉 모양이나 크기, 색, 변화에 따른 반응을 일일이 규정하게 할 필요는 없다는 것이다. 직접 통제하지 않는 대신에 어떤 범위 안에서 변화가 일어나도록 조건을 만든다. 무작위 값을 쓰더라도 완전히 우연에 맡기는 것이 아니라, 시드, 범위, 분포, 제한 조건을 통해 결과의 성격을 조절한다. 반복 구조를 만들더라도 단순히 복사하는 것이 아니라 각 반복이 조금씩 달라지는 방식을 설계한다. 이런 규칙과 방식의 조합을 통해 작가가 의도하지 않은 형태가 '생성'되고 아트워크를 즐기는 관객에게 신선함을 선사하게 되는 것이다.

이 책에서는 다음과 같은 질문을 통해 수학의 규칙이 제너레이티브 아트를 만드는 과정을 살펴본다.

- 이 이미지는 어떤 입력값에서 시작하는가?
- 그 입력값은 어떤 함수나 규칙을 통과하는가?
- 함수의 결과는 색, 위치, 크기, 회전, 밀도, 속도 중 무엇으로 바뀌는가?
- 변화가 있다면 어떤 파라미터로 조절되는가?
- 같은 규칙을 다른 그래픽 환경에서는 어떻게 표현할 수 있는가?

이 질문들은 책 전체를 관통하며 각 장과 절의 기능에 녹아있다. 좌표를 정할 때도, 거리장을 다룰 때도, 노이즈와 입자 시스템을 다듬을 때도 같은 틀을 사용한다. 단순한 값 하나를 색으로 바꾸는 일에서 시작하여 마지막에는 여러 규칙이 서로 연결된 하나의 아트워크 구조를 설계하는 데까지 나아간다.

## 이 책이 다루는 그래픽 시스템과 환경

제너레이티브 아트는 특정 프로그램이나 특정 언어에만 속한 분야가 아니다. 브라우저에서 실행되는 p5.js로도 만들 수 있고, C++ 기반의 openFrameworks로도 만들 수 있으며, GPU를 사용하는 셰이더로도 만들 수 있다. 같은 수학 아이디어가 2D 캔버스, 3D 공간, 표면 재질, 그리고 실시간 그래픽 시뮬레이션 안에서 서로 다른 목적을 가지고 나타난다.

이 책은 다양한 프로그래밍 언어를 사용하는 각각의 그래픽 라이브러리와 프레임워크를 깊게 다루는 레퍼런스의 역할을 한다기 보다는 각 그래픽 시스템이 이미지를 계산하는 방식의 차이를 비교하는데 주력한다. 어떤 시스템은 도형을 명령으로 그리고, 어떤 환경에서는 픽셀마다 함수를 평가한다. 어떤 라이브러리는 프레임마다 상태를 업데이트하고, 어떤 언어의 함수는 표면 위의 한 점에서 재질 값을 계산한다. 이 차이와 그 속에서의 공통 원리를 이해하면 라이브러리나 언어가 달라져도 아트워크를 만드는 핵심 아이디어를 잃지 않을 수 있다.

이 책에서 주로 등장하는 그래픽 시스템은 다음과 같다.

| 구분            | 그래픽 시스템           | 이 책에서 보는 관점                            |
| ------------- | ----------------- | -------------------------------------- |
| 크리에이티브 코딩     | p5.js, Processing | 주로 2D에서 좌표, 도형, 반복, 애니메이션을 빠르게 실험하는 환경 |
| 게임 루프 기반 드로잉  | raylib            | 명시적인 루프와 입력 처리를 바탕으로 실시간 그래픽을 구성하는 환경  |
| 함수형 크리에이티브 코딩 | Quil              | 상태와 드로잉을 함수 중심으로 조직하는 환경               |
| C++ 크리에이티브 코딩 | openFrameworks    | 입력, 미디어, 시뮬레이션, 셰이더를 결합하는 환경           |
| 현대적 크리에이티브 코딩 | nannou, OPENRNDR  | Rust와 Kotlin 기반으로 그래픽 구조를 설계하는 환경      |
| 실시간 셰이딩       | GLSL, HLSL        | GPU에서 픽셀, 정점, 텍스처, 필드를 계산하는 환경         |
| 프로시저럴 재질      | OSL               | 화면이 아니라 메시 표면 위의 재질과 변위를 계산하는 환경       |

이 표에 등장하는 각 그래픽 시스템은 서로 다른 작업 방식과 강점을 가진다. p5.js는 웹 베이스의 빠른 실험에 적합한 라이브러리이고 openFrameworks는 그래픽 뿐만 아니라 설치 예술의 미디어 연동에 강한 프레임워크이다. GLSL은 픽셀 단위 패턴과 실시간 효과에 적합한 셰이딩 언어며, OSL은 3D 표면의 재질을 수학적으로 만들 때 유용하다. 자신이 만들려고 하는 아트워크의 규칙이 어떤 방식의 수학 계산을 필요로 하는지, 어떤 미디어를 통해 보여지게 되는지가 이 그래픽 시스템을 선택하는 중요한 요소가 된다.

## 수학적 모델과 구현 시스템의 관계

이 책에서 말하는 수학적 모델은 어떤 이미지를 만들기 위해 필요한 규칙으를 간단한 수식이나 알고리즘으로 정리한 것이다. 예를 들어 한 이미지를 중심점에서 멀어질수록 색이 어두워지게 만든다면, 그 이미지는 거리값을 사용하는 모델을 갖는다. 좌표를 일정한 간격으로 반복해 무늬를 만든다면, 그 이미지는 타일링 모델을 갖는다. 입자가 보이지 않는 흐름을 따라 움직인다면, 그 이미지는 벡터 필드와 시간 업데이트를 사용하는 모델을 갖는다.

구현 시스템은 이 모델을 실제 코드로 옮기는 장소다. 같은 모델이라도 시스템에 따라 표현 방식이 달라진다. 드로잉 API에서는 반복문으로 여러 도형을 그릴 수 있다. 셰이더에서는 화면의 각 픽셀이 자신의 좌표를 입력으로 받아 색을 계산한다. 프로시저럴 재질에서는 표면 위의 점이 자신의 위치, 노멀, UV 좌표를 바탕으로 색과 거칠기, 변위를 계산한다.

예를 들어 원을 만든다고 해 보자. 드로잉 API에서는 `circle()`이나 `ellipse()` 같은 함수를 호출해 원을 그리는 경우가 많다. 셰이더에서는 정해진 함수를 사용하는게 아니라 픽셀 좌표와 중심점 사이의 거리를 계산하고, 그 거리가 반지름보다 작은지 판단해 색을 정한다. OSL에서는 표면 위의 좌표를 기준으로 거리 패턴을 계산해 재질의 색이나 범프 값에 연결할 수 있다. 결과는 모두 원이지만 원을 만드는 수학적인 모델과 방식은 다르다.

어떤 환경에서는 도형이 기본 단위이고, 어떤 환경에서는 픽셀이 기본 단위이며, 어떤 환경에서는 표면 위의 샘플 지점이 기본 단위다. 하지만 더 아래로 내려가면 공통된 질문이 남는다. 좌표는 무엇인가? 거리는 어떻게 계산하는가? 값은 어떤 범위에 있는가? 그 값을 색이나 형태로 어떻게 바꾸는가?

이 책은 바로 그 공통 질문에서 제너레이티브 아트의 탐구를 시작한다. 

## 이 책의 기본 흐름

이 책은 단순한 개념에서 시작해 복잡한 시스템으로 이동한다. 처음에는 좌표와 숫자 값을 다룬다. 그다음 함수를 이용해 형태를 만들고, 좌표를 변형해 패턴을 만든다. 이후 랜덤, 노이즈, 필드, 시간, 상태, 피드백을 더해 이미지가 스스로 변화하는 시스템으로 확장한다. 마지막에는 같은 수학적 아이디어를 여러 그래픽 환경으로 옮기는 방법을 살펴보고, 프로젝트를 통해 전체 흐름을 다시 묶는다.

전체 흐름은 다음과 같이 요약할 수 있다.

| 단계 | 핵심 질문 | 결과 |
| --- | --- | --- |
| 좌표 | 화면의 한 점을 어떻게 표현할 것인가? | 위치, 거리, 방향, 각도 |
| 함수 | 입력값을 어떤 규칙으로 바꿀 것인가? | 그래프, 곡선, 파동 |
| 값 | 계산 결과를 어떻게 시각 요소로 연결할 것인가? | 색, 밝기, 크기, 회전 |
| 변형 | 좌표계를 어떻게 움직일 것인가? | 이동, 회전, 확대, 접기 |
| 도형 | 형태를 어떻게 정의할 것인가? | 원, 선, 사각형, 다각형, SDF |
| 조합 | 여러 형태와 값을 어떻게 합칠 것인가? | 마스크, 레이어, 블렌딩 |
| 반복 | 같은 규칙을 어떻게 배열할 것인가? | 격자, 타일, 패턴 |
| 필드 | 공간 전체에 값을 어떻게 배치할 것인가? | 스칼라 필드, 벡터 필드, 흐름 필드 |
| 시간 | 값이 어떻게 변하게 할 것인가? | 애니메이션, 루프, 움직임 |
| 시스템 | 상태와 피드백을 어떻게 다룰 것인가? | 입자, 성장, 시뮬레이션 |
| 작품 | 여러 규칙을 어떻게 하나로 구성할 것인가? | 정적 이미지, 애니메이션, 인터랙티브 작업 |

제너레이티브 아트 작업을 할 때 이 순서를 반드시 따라야 할 필요는 없다. 작가는 특정 시각 효과에서 출발해 필요한 개념으로 거슬러 올라갈 수도 있고, 하나의 수학적 구조를 실험하다가 작품의 방향을 발견할 수도 있다. 그러나 학습의 관점에서는 좌표와 값에서 시작해 시스템으로 확장하는 순서가 가장 안정적이다. 뒤의 장에서 복잡한 구조를 다룰 때도 결국은 앞에서 배운 좌표, 함수, 값의 조합으로 돌아오기 때문이다.

## 각 장의 구성 방식

각 장은 네 가지 층위로 구성된다. 첫째, 이미지를 만들기 위한 수학적 개념을 설명한다. 이 개념이 왜 필요한지, 어떤 시각적 문제를 해결하는지부터 설명한다.

둘째, 그 개념이 이미지에서 어떻게 보이는지 해석한다. 같은 사인 함수라도 선 그래프로 볼 때와 밝기 패턴으로 볼 때, 파동 애니메이션으로 볼 때의 의미가 달라진다. 거리 함수도 단순한 숫자 계산으로 볼 수 있지만, 경계, 외곽선, 그라데이션, 마스크를 만드는 도구로 볼 수도 있다. 이 책은 수식이 이미지의 재료로 쓰이는 원리를 중요하게 다룬다.

셋째, 구현 전략을 정리한다. 어떤 값이 입력이고, 어떤 값이 출력인지, 어느 단계에서 정규화가 필요한지, 어떤 파라미터를 노출하면 조절하기 좋은지 살펴본다. 이 단계는 특정 언어의 문법보다 알고리즘의 뼈대를 이해하는 데 초점을 둔다.

넷째, 그래픽 환경마다 다르게 번역되는 과정을 살펴본다. 같은 원리를 p5.js, Processing, raylib, Quil, openFrameworks, nannou, OPENRNDR, GLSL, HLSL, OSL 같은 환경에서 어떻게 다르게 표현하는지 비교한다. 모든 장에서 모든 환경을 같은 깊이로 다루지는 않는다. 대신 해당 개념을 이해하는 데 적합한 환경을 중심으로 설명하고, Part 6과 Part 7에서 여러 환경을 본격적으로 비교한다.

각 장을 읽을 때는 코드를 그대로 옮기는 것보다, 코드가 어떤 계산을 하고 있는지 따라가는 것이 좋다. 변수 이름이 바뀌고 함수 이름이 달라져도, 입력값이 무엇이고 출력값이 무엇인지 알면 다른 환경으로 옮길 수 있다.

## 이 책을 읽는 방법

이 책은 처음부터 끝까지 순서대로 읽을 수 있도록 구성되어 있다. 제너레이티브 아트나 그래픽 프로그래밍을 처음 접한다면 Part 1부터 차근차근 읽는 것이 좋다. 좌표, 값의 범위, 정규화, 보간 같은 기초 개념은 뒤의 거의 모든 장에서 반복해서 사용된다.

이미 p5.js나 Processing 같은 환경에 익숙하다면 Part 2와 Part 3에서 함수 기반 형태와 좌표 변형을 먼저 살펴봐도 좋다. 셰이더에 관심이 있다면 Part 5까지의 개념을 읽은 뒤 Part 6의 셰이딩 언어 부분으로 넘어갈 수 있다. 다만 GLSL이나 HLSL을 처음 접할 때도 앞부분의 좌표와 거리 함수, 반복, 노이즈 개념은 반드시 도움이 된다.

3D 재질이나 Blender 기반 작업에 관심이 있다면 OSL과 프로시저럴 재질을 다루는 장을 중심으로 읽을 수 있다. 이때도 2D 패턴을 단순한 화면 효과로만 보지 말고, 표면 위에서 계산되는 값으로 확장해 보는 것이 중요하다. 원, 격자, 노이즈, 방사형 패턴은 화면에서도 쓰이고 표면에서도 쓰인다. 차이는 그 값이 색으로 갈지, 거칠기로 갈지, 변위로 갈지에 있다.

책의 후반부에 있는 프로젝트는 앞에서 배운 개념을 다시 묶는 역할을 한다. 각 프로젝트는 하나의 완성 예제가 아니라, 여러 그래픽 시스템으로 옮길 수 있는 구조를 보여 주는데 주력한다. 같은 아이디어를 다른 언어로 다시 구현해보는 과정을 통해 학습자는 어떤 부분이 수학적 모델이고 어떤 부분이 그래픽 환경을 위한 문법인지 구분하게 된다.

## 결과보다 구조를 보는 연습

제너레이티브 아트의 즐거움은 예측과 우연 사이에 있다. 규칙을 세워도 대개 결과가 예상대로 나오지는 않는다. 파라미터의 작은 변화가 여러 함수를 거친 후에 전혀 다른 이미지를 만들기도 하고, 단순한 반복이 복잡한 질감을 만들기도 한다. 작가는 우연히 마음에 드는 결과를 얻는 데서 멈추지 않고 왜 그런 결과가 나왔는지, 어떤 값이 이미지의 성격을 바꾸었는지, 그 변화를 다시 조절할 수 있는지 살펴봐야 한다.

좋은 제너레이티브 작업은 보통 하나의 효과를 만드는 함수로 끝나지 않는다. 좌표를 어떻게 잡는지, 값을 어떤 범위로 제한하는지, 반복 구조를 얼마나 규칙적으로 둘 것인지, 랜덤을 어디에 넣을 것인지, 시간 변화가 어떤 속도로 일어날 것인지가 연관되어 작동한다. 따라서 이 책은 개별 기법을 소개하는 것 뿐만 아니라 기법들이 서로 연결되는 방식을 보여 주려 한다.

처음에는 작은 규칙 하나로 시작해도 충분하다. 화면의 중심에서 멀어질수록 색이 바뀌는 규칙, 좌표를 반복해 격자를 만드는 규칙, 시간값으로 파동을 이동시키는 규칙처럼 단순한 구조에서 출발한다. 그런 다음 규칙을 하나씩 더한다. 거리값에 노이즈를 섞고, 반복 좌표를 회전시키고, 필드의 방향을 따라 입자를 움직이고, 이전 프레임의 결과를 다시 입력으로 사용한다. 이렇게 쌓인 규칙은 하나의 시각 예술 시스템으로 구조를 갖춘다.

이 책을 읽는 동안 완벽한 공식을 찾으려 하기보다, 이미지를 계산하는 사고방식에 익숙해지는 것이 더 중요하다. 좌표를 입력으로 보고, 함수를 변환 장치로 보고, 값을 시각 요소로 보고, 시간을 또 하나의 축으로 보는 연습을 하다 보면 그래픽 환경이 바뀌어도 같은 아이디어를 계속 사용할 수 있다.

이제 첫 번째 장에서 제너레이티브 아트의 기본 사고방식을 살펴보자. 우리는 그림을 하나씩 그리는 대신, 그림이 만들어지는 조건을 설계하는 일에서 출발할 것이다.
