# 11.3 재현 가능한 랜덤

재현 가능성은 우연을 없애기 위한 조건이 아니다. 같은 시드로 결과를 다시 만들면 수정 전후를 비교하거나 원하는 이미지 한 장을 다시 내보낼 수 있다. 순차 난수 생성기에서는 시드뿐 아니라 난수를 요청하는 순서도 각 값이 배정되는 대상에 영향을 준다.

다음 예시에서는 `enabled`가 참일 때만 두 번째 난수를 요청한다.

```text
value = random()
if enabled:
    accent = random()
```

같은 시드로 시작해도 `enabled`의 값이나 실행 경로가 달라지면 그 뒤의 요소들이 받는 난수는 달라질 수 있다. 예를 들어 `enabled`가 참이면 `value`가 첫 번째 표본을 받고 `accent`가 두 번째 표본을 받는다. 거짓이면 두 번째 표본은 요청되지 않으므로 다음 요소가 그 값을 받는다. 생성된 수열 자체는 같아도, 코드가 표본을 소비하는 방식에 따라 값과 요소의 연결이 달라진다. 따라서 코드 중간에 난수 호출을 추가하거나 반복 순서를 바꾸면 이후 요소에 배정된 값이 이동한다. 호출 순서에 덜 민감한 값 배정에는 키 기반 해시를 사용할 수 있다.

## 키 기반 해시로 값 고정하기

구조가 바뀌어도 각 요소의 값을 유지해야 한다면, 난수 수열의 다음 값을 꺼내는 대신 요소의 식별자에서 값을 직접 계산할 수 있다. 이런 방식은 순차 난수의 다음 출력을 소비하는 대신, 셀 좌표나 개체의 고유 ID와 시드를 키로 삼아 결정적 해시값을 만든다. 전체 시드와 셀 좌표를 키로 삼는 경우는 다음처럼 나타낼 수 있다.

$$
u_{ij}=H(i,j,s)
$$

여기서 $i,j$는 셀의 정수 좌표이고 $s$는 시드다. $H$는 같은 입력 키에 항상 같은 $[0,1)$ 값을 반환하는 결정적 함수다. 순차 생성기처럼 다음 출력에 영향을 주는 내부 상태를 진행시키지 않으므로, 셀의 값을 어떤 순서로 요청해도 결과가 같다. 셀을 새로 추가하거나 순회 순서를 바꾸더라도 기존 셀에 같은 키를 사용하면 그 셀의 값은 유지된다. 이때 키에는 셀 좌표처럼 구조가 바뀌어도 유지되는 식별자를 넣는 편이 좋다. 배열 순번처럼 삽입·삭제에 따라 달라지는 값을 ID로 쓰면 요소의 번호가 바뀔 때 그 요소의 값도 달라질 수 있다.

GPU 셰이더에서 자주 쓰이는 간단한 좌표 해시의 한 예는 다음과 같다.

```glsl
float hash31(vec3 key) {
  float h = dot(key, vec3(127.1, 311.7, 74.7));
  return fract(sin(h) * 43758.5453);
}

float value = hash31(vec3(cell, float(seed)));
```

`dot`은 셀 좌표와 시드를 가중합해 하나의 수 `h`로 섞는다. `sin`은 그 입력을 비선형적으로 변화시키고, 큰 상수를 곱한 뒤 `fract`를 취해 소수부를 $[0,1)$ 범위의 값으로 만든다. 계수들은 좌표에 반복되는 단순한 규칙이 결과에 드러나는 일을 줄이기 위해 고른 상수이지, 해시 품질을 수학적으로 보장하는 값은 아니다. 이런 식은 이해와 구현이 간단해 셀 장식값을 만드는 데 유용하지만, 출력이 완벽하게 균일하거나 서로 독립적이라는 보장은 없다.

색과 크기처럼 한 셀에서 여러 값을 만들 때는 셀 좌표와 시드 외에 속성 식별자도 키에 포함할 수 있다. 예를 들어 크기용 채널과 색상용 채널을 구분하면 한 셀에서 서로 다른 값을 얻는다. 다만 키가 다르다고 통계적으로 완전히 독립인 값이 되는 것은 아니다. 두 값이 우연히 비슷해질 수도 있고, 해시 함수의 상관이나 분포 특성이 남을 수도 있으므로 실제 결과를 살펴야 한다.

## 해시의 용도와 한계

해시는 각 셀이나 개체에 고정된 장식값을 배정할 때 적합하다. 개별 ID를 입력으로 쓰면 값은 안정적으로 유지되지만, 이웃한 ID의 출력이 서로 비슷해지지는 않는다. 좌표가 조금씩 달라질 때 부드럽게 이어지는 값을 원한다면 노이즈처럼 연속성을 고려한 함수를 사용한다. 특정 확률 분포를 따르거나 점 사이의 최소 간격을 보장하는 일도 해시만으로 해결되지 않는다. 분포는 11.5절에서, 격자와 셀 위의 배치는 11.6절에서 다룬다.

간단한 `sin` 기반 해시는 큰 좌표를 부동소수점으로 처리할 때 정밀도 한계가 드러나거나, 특정 입력 범위에서 반복 무늬가 보일 수 있다. GPU와 CPU는 부동소수점 계산 방식이 다를 수 있어 서로 다른 장치에서 결과가 비트 단위로 완전히 같지 않을 수도 있다. 작은 장식값이나 시각적 변형에는 충분할 수 있지만, 품질과 이식성이 중요하다면 정수 연산 기반의 검증된 해시나 라이브러리를 고려한다. 여러 장치에서 정확히 같은 출력을 재현해야 한다면 사용하는 연산의 정밀도와 구현도 함께 고정해야 한다. 어떤 해시도 보안용 난수 생성기를 대신하지 않는다.

해시의 출력이 실제로 어떤 모양을 만드는지는 수치 목록만으로 판단하기 어렵다. 작은 격자에서 셀마다 색이나 원 크기를 표시하고, 이웃 셀 사이의 줄무늬·반복·군집이 눈에 띄는지 확인한다. 난수 표본에서는 우연한 군집이나 빈 영역도 생길 수 있으므로, 한 번의 결과만으로 해시의 결함을 단정하지 않는다. 여러 시드와 좌표 범위에서 같은 흔적이 반복되는지 비교하면 우연한 편차와 함수의 구조적 흔적을 구별하는 데 도움이 된다.

## 이 절의 핵심

순차 난수 생성기는 시드와 호출 순서에 따라 값이 진행된다. 키 기반 해시는 셀 좌표와 시드 같은 식별자로 값을 직접 계산하므로 순회 순서가 바뀌어도 기존 요소의 값이 유지된다. 두 방식 모두 재현 가능하지만, 분포와 공간적 배치의 품질은 별도로 확인해야 한다.
