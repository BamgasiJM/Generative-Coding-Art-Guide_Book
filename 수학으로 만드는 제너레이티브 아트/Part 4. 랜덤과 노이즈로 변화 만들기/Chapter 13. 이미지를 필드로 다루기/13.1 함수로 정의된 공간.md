# 13.1 함수로 정의된 공간

제너레이티브 아트에서 화면은 도형을 놓는 빈 캔버스이면서, 각 좌표에서 값을 물어볼 수 있는 공간이다. 함수 $F$가 위치 $\mathbf{p}$를 받아 값을 돌려준다면, 그 함수는 화면 전체에 보이지 않는 구조를 만든다. 이처럼 공간의 각 위치에 값을 대응시키는 규칙을 필드(field)라고 부른다. 필드는 그 자체로 이미지가 아니라, 이미지나 형태를 만들 때 질문하고 값을 읽어 오는 규칙이다.

$$
F:\mathbb{R}^2\rightarrow\mathcal{V}
$$

$\mathcal{V}$는 실수, 색, 방향 벡터, 또는 이 값들을 묶은 자료형일 수 있다. 입력 위치와 출력 값의 종류를 함께 정하면 필드가 무엇을 나타내는지도 분명해진다. 예를 들어 높이 필드는 숫자를, 색상 필드는 색을, 속도 필드는 벡터를 반환한다. 이 관점을 쓰면 "원을 그린다"는 말도 각 위치에서 원에 대한 값을 평가하고 그 결과를 화면에 표시한다는 말로 바뀐다. 점, 선, 이미지, 입자도 필드값을 읽는 서로 다른 방법이 된다.

```text
for each pixel position p:
    value = field(p)
    writePixel(visualize(value))
```

필드는 저장된 이미지와 다르다. 이미지는 정해진 격자의 샘플이고, 함수 필드는 정의역 안의 좌표에서 규칙을 다시 평가해 값을 얻는다. 물론 실제 렌더링에서는 유한한 픽셀에서 표본을 얻는다. 이 차이는 확대, 애니메이션, 해상도 변경에서 특히 중요하다. 함수로 정의했다고 해서 모든 필드가 연속적이거나 무한한 정밀도를 갖는다는 뜻은 아니다. 임계값 마스크처럼 불연속인 필드도 있고, 실제 계산은 유한 정밀도와 픽셀 격자의 영향을 받는다.

함수로 공간을 생각하면 같은 필드를 색으로 보이게 할지, 등고선으로 그릴지, 입자를 움직일지 선택할 수 있다. 이후 절은 값의 종류에 따라 필드를 구분한다.

## 정의역은 어떤 공간을 읽을지 정한다

식 $F:\mathbb{R}^2\rightarrow\mathcal{V}$에서 $\mathbb{R}^2$는 2차원 좌표의 집합이다. 하지만 실제 작업에서 이 좌표가 무엇을 뜻하는지는 선택해야 한다. 화면 중심 기준 좌표, $[0,1]$ UV 좌표, 타일 내부 좌표, 오브젝트 공간, 월드 공간은 모두 필드의 입력이 될 수 있다.

```text
screen field:  F(screenPosition)
UV field:      F(uv)
object field:  F(localPosition)
world field:   F(worldPosition)
```

같은 노이즈 함수라도 화면 좌표에 넣으면 화면에 붙은 질감이 되고, 오브젝트 좌표에 넣으면 물체와 함께 움직이는 재질이 된다. 월드 좌표를 쓰면 카메라가 움직여도 세계 공간의 같은 위치에 필드가 남는다. 필드 자체와 필드에 넣는 좌표 변환을 구분하면, 같은 규칙을 여러 맥락에서 재사용할 수 있다.

좌표계는 필드가 붙는 위치뿐 아니라 입력의 단위와 모양도 정한다. 예를 들어 UV 좌표를 $[0,1]^2$로 정규화한 뒤 정사각형이 아닌 화면에 바로 적용하면, UV에서 원형인 패턴이 화면에서는 가로 또는 세로로 늘어져 보일 수 있다. 픽셀 단위의 원형 특징을 유지하고 싶다면 좌표에 화면의 가로·세로 크기를 반영한다.

```text
fieldPosition = (uv.x * canvasWidth,
                 uv.y * canvasHeight)
value = field(fieldPosition)
```

반대로 화면 비율에 맞춰 패턴이 늘어나는 것이 의도라면 정규화 UV를 그대로 사용해도 된다. 좌표는 단순한 입력 형식이 아니라, 필드의 크기와 왜곡, 다른 요소와의 정렬 방식을 정하는 선택이다.

3차원 공간의 필드는 $F:\mathbb{R}^3\rightarrow\mathcal{V}$처럼 정의한다. 이는 지형의 높이, 구름의 밀도, 물체 주변의 힘, 볼륨 재질처럼 화면 뒤쪽까지 값을 가진 구조를 다루는 기반이 된다. 화면은 3차원 필드의 한 단면이나 투영 결과를 보여 주는 방식 중 하나일 수 있다.

필드가 어떤 좌표에서 정의되는지도 중요하다. 같은 식이라도 2D 화면 좌표에 입력하면 이미지 전체의 패턴을 만들고, 3D 월드 좌표에 입력한 뒤 화면에 투영하면 깊이에 따라 달라지는 구조를 얻는다. 좌표의 차원이 늘어날수록 필드는 화면에 보이지 않는 깊이와 시간의 변화를 포함할 수 있다.

## 필드는 합성할 수 있다

필드의 강점은 여러 함수를 조합해 더 복잡한 공간 규칙을 만들 수 있다는 점이다. 두 스칼라 필드의 합, 최소값, 곱, 보간은 각각 다른 공간적 의미를 만든다.

$$
H(\mathbf{p})=F(\mathbf{p})+G(\mathbf{p})
$$

```text
largeStructure = noise(p * lowFrequency)
fineDetail = noise(p * highFrequency)
combined = largeStructure + detailAmount * fineDetail
```

두 필드를 섞을 때는 출력값의 종류가 서로 맞는지도 확인한다. 스칼라 두 개는 더하거나 보간할 수 있고, 색 두 개는 채널별 또는 선택한 색 공간에서 섞을 수 있다. 스칼라와 벡터처럼 종류가 다른 값은 그대로 더하지 않고, 스칼라를 크기나 확률로 해석하는 등 결합 규칙을 먼저 정해야 한다. 마스크 필드 $m(\mathbf{p})$로 두 스칼라 필드를 섞는 예는 다음과 같다.

$$
H(\mathbf{p})=(1-m(\mathbf{p}))F(\mathbf{p})+m(\mathbf{p})G(\mathbf{p})
$$

```text
mask = clamp(maskField(p), 0, 1)
result = lerp(fieldA(p), fieldB(p), mask)
```

마스크가 0이면 `fieldA`, 1이면 `fieldB`가 선택되고, 그 사잇값은 두 필드를 부드럽게 혼합한다. 마스크의 값 범위가 $[0,1]$이 아니면 먼저 변환해야 예상한 보간이 나온다.

좌표도 필드로 변형할 수 있다. 벡터 필드 $\mathbf{w}(\mathbf{p})$가 있다면, 다른 필드를 읽기 전에 입력 좌표를 이동시킨다.

$$
H(\mathbf{p})=F\bigl(\mathbf{p}+\mathbf{w}(\mathbf{p})\bigr)
$$

이것은 Part 3의 좌표 변환과 Part 4의 노이즈 워핑을 필드의 언어로 묶어 보는 관점이다. 결과 색을 섞는 방식과 입력 좌표를 바꾸는 방식은 다른 결과를 내므로, 어느 단계에서 합성하는지 명시한다.

이를 두 식으로 비교하면 차이가 분명해진다.

$$
\text{값 변환: }G(F(\mathbf{p})),\qquad
\text{좌표 변환: }F(T(\mathbf{p}))
$$

첫 식은 위치에서 얻은 값을 색상이나 밝기로 다시 매핑한다. 둘째 식은 필드를 평가할 위치를 먼저 옮긴다. 같은 함수와 변환이라도 어느 쪽을 적용하느냐에 따라 패턴의 구조가 달라진다.

## 연속 필드와 이산 이미지

함수로 정의한 필드는 정의된 범위 안의 실수 좌표에서 평가할 수 있다. 반면 이미지는 유한한 텍셀 격자에 저장된 이산 표본이다. 이미지에서 중간 위치의 값을 읽을 때는 최근접 텍셀을 고르거나 주변 텍셀을 보간한다.

```text
procedural field: value = F(p)
image field:      value = sample(image, uv, filtering)
```

따라서 이미지를 필드처럼 다룰 수는 있지만, 해상도·필터링·가장자리 처리의 영향을 받는다. 최근접 표본화는 셀 상태나 픽셀 아트를 보존하고, 선형 보간은 색·밀도 같은 연속 값에 적합하다. 이미지 바깥을 읽을 때 가장자리 값을 반복할지, 고정할지, 반사할지도 정해야 한다. 절차적 필드와 이미지 필드를 합성할 때는 어느 쪽이 실제 해상도를 갖는지 의식한다.

## 표본화는 필드를 보이는 이미지로 바꾼다

필드가 연속적이어도 렌더링은 유한한 위치에서 값을 읽는다. 이 과정을 표본화라고 한다. 해상도가 낮거나 필드의 변화가 너무 빠르면 작은 특징이 사라지거나 깜빡일 수 있다.

$$
I[i,j]\approx F\left(\frac{i+0.5}{W},\frac{j+0.5}{H}\right)
$$

여기서 $I[i,j]$는 이미지 픽셀, $W$와 $H$는 이미지 크기다. 좌표에 $0.5$를 더한 것은 픽셀 모서리가 아니라 픽셀 중심에서 값을 표본화한다는 간단한 모델이다. 실제 픽셀은 작은 면적을 가지므로 이 점 표본은 면적 평균을 근사한다. 픽셀 내부에서 값이 크게 달라진다면 한 점의 값만으로 결과를 충분히 표현하지 못할 수 있다. 얇은 경계와 높은 주파수 노이즈에는 부드러운 임계값, 낮은 주파수, 여러 표본의 평균, 미분 기반 안티앨리어싱 같은 보완이 필요할 수 있다.

필드의 수학적 정의와 최종 이미지의 해상도를 분리해 생각하면, 왜 같은 함수가 큰 화면과 작은 화면에서 다르게 보이는지 이해할 수 있다.

## 하나의 필드를 여러 방식으로 읽기

같은 스칼라 필드도 출력 변환에 따라 다른 정보를 드러낸다. 값을 회색조로 표시하면 전체 범위가 보이고, 등위선으로 표시하면 변화의 지형이 보이며, 임계값으로 자르면 영역이 보인다. 그래디언트를 계산하면 값이 증가하는 방향도 얻을 수 있다.

| 읽는 방식 | 필드값의 사용 | 보이는 구조 |
| --- | --- | --- |
| 회색조 | 값을 밝기로 매핑 | 연속적인 높낮이 |
| 팔레트 | 값을 색상 인덱스로 사용 | 색상 지대와 계층 |
| 등위선 | 특정 값 근처만 표시 | 윤곽과 지형도 |
| 마스크 | 임계값 안팎으로 분리 | 영역과 도형 |
| 입자 분포 | 값을 생성 확률로 사용 | 밀도와 군집 |
| 벡터화 | 변화율을 방향으로 사용 | 흐름과 이동 |

처음에는 회색조로 필드 자체를 확인한 뒤, 다른 읽기 방식을 하나씩 추가하는 편이 좋다. 최종 색이나 입자 결과만 보면 필드가 문제인지 출력 매핑이 문제인지 구분하기 어렵다.

예를 들어 스칼라 필드 하나를 계산한 뒤 여러 출력으로 읽을 수 있다. 필드는 한 번 정의하고, 그 값을 어떤 시각적 규칙에 연결할지는 별도로 선택한다.

```text
value = scalarField(p)
gray = mapToGrayscale(value)
color = samplePalette(value)
mask = value < threshold
contour = abs(value - contourLevel) < lineWidth
```

회색조에서 이미 예상한 구조가 보이지 않는다면 먼저 필드 입력 좌표와 범위를 확인한다. 구조는 보이지만 색이나 경계가 이상하다면 출력 매핑과 임계값을 조정한다. 이런 분리는 복잡한 이미지의 문제를 공간 규칙과 표시 규칙으로 나누어 살펴보게 해준다.

## 시간도 필드의 입력이 될 수 있다

시간을 추가하면 공간 필드는 공간-시간 필드가 된다.

$$
F:\mathbb{R}^2\times\mathbb{R}\rightarrow\mathcal{V},\qquad
v=F(\mathbf{p},t)
$$

같은 위치에서 시간이 지나며 값이 부드럽게 바뀌면 색·밀도·방향·도형이 연속적으로 움직인다. 시간은 필드의 본질을 바꾸기보다, 어느 시각의 단면을 볼지 정하는 추가 좌표축으로 생각할 수 있다. 순수한 시간 필드는 같은 위치와 시각을 입력하면 언제나 같은 값을 돌려주므로, 재생을 되감거나 임의의 시각을 다시 계산하기 쉽다. 반면 이전 프레임의 결과를 누적하는 피드백 필드는 현재 입력뿐 아니라 과거 상태에도 의존한다. 그런 구조는 다음 Part에서 다룬다.

## 이 절의 핵심

필드는 위치를 값으로 보내는 함수다. 이미지는 필드를 보는 한 가지 방법이며, 같은 필드에서 여러 시각 결과를 만들 수 있다.
