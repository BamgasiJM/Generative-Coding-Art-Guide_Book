# 12.7 주파수, 진폭, 옥타브

노이즈를 조절할 때 세 단어를 분리해 이해하면 혼동이 줄어든다. 주파수는 입력 좌표를 얼마나 빠르게 이동시킬지, 진폭은 계산된 값을 출력에 얼마나 크게 반영할지, 옥타브는 서로 다른 스케일을 몇 겹으로 더할지 정한다. 주파수를 높이면 작은 특징이 많아지고, 진폭을 높이면 밝기나 위치가 더 크게 달라진다.

$$
d(\mathbf{p})=A\,n(f\mathbf{p})
$$

$f$를 키우면 얼룩이 작고 촘촘해진다. $A$를 키우면 밝기 변화나 좌표 변위의 폭이 커진다. 좌표 변형에서는 두 값을 특히 분리한다. 높은 주파수와 큰 진폭을 함께 쓰면 이웃 좌표가 과도하게 뒤틀려 접힘이나 깜빡임이 생길 수 있다.

| 조절값 | 증가할 때 | 자주 연결하는 대상 |
| --- | --- | --- |
| 주파수 | 변화가 촘촘해짐 | 패턴의 세부 크기 |
| 진폭 | 변화 폭이 커짐 | 밝기, 변위, 높이 |
| 옥타브 | 스케일이 다양해짐 | 자연스러운 질감 |

노이즈 필드를 화면에 그릴 때는 연속적인 함수를 픽셀 위치에서 표본화한다. 특징이 픽셀보다 훨씬 작으면 표본 사이에서 변화가 빠져나가 무늬가 사라지거나, 실제와 다른 얼룩과 줄무늬로 나타날 수 있다. 이런 현상을 앨리어싱(aliasing)이라고 한다. 주기적인 파형은 이론적으로 픽셀당 0.5회보다 높은 주파수를 제대로 구분하지 못하지만, 노이즈는 한 가지 주파수만 가진 파형이 아니므로 그 경계값을 그대로 적용할 수 없다. 실무에서는 가장 작은 특징도 몇 픽셀에 걸쳐 보이도록 두고, 그보다 높은 스케일은 줄이거나 부드럽게 필터링하는 편이 안정적이다. 셰이더에서는 `fwidth`처럼 화면상 입력 변화량을 추정하는 미분 정보를 이용해 가장 가는 무늬를 완화하기도 한다.

## 입력의 주파수와 출력의 진폭

식 $A\,n(f\mathbf{p})$에서 $f$는 노이즈 함수의 입력 좌표를 얼마나 빠르게 훑을지를 정하고, $A$는 결과를 출력에 얼마나 크게 반영할지를 정한다. 따라서 두 값은 단위가 다르다. 좌표가 픽셀이라면 $f$는 픽셀당 노이즈 입력 좌표의 변화량이며, 좌표 변위에 쓰는 $A$는 픽셀 단위의 이동량이다. 좌표가 $[0,1]$로 정규화되어 있다면 같은 $A$라도 화면 전체에 대한 비율을 나타낸다.

노이즈의 입력 좌표에 곱하는 수를 관습적으로 주파수라고 부르지만, 사인파처럼 정확한 반복 횟수를 뜻하지는 않는다. 대부분의 노이즈 함수는 주기적이지 않으며, 구현마다 입력 공간에서 한 덩어리의 특징이 차지하는 크기도 다르다. 따라서 주파수는 우선 입력 공간의 스케일을 조절하는 배율로 이해하고, 최종 이미지에서 특징이 몇 픽셀 크기로 보이는지 확인해야 한다.

```text
brightness = baseBrightness + brightnessAmplitude * noise(p * frequency)
displacement = displacementAmplitude * noise(p * frequency)
height = heightAmplitude * noise(p * frequency)
```

밝기 진폭이 0.1인 것은 약한 명암 변화일 수 있지만, 좌표 변위가 0.1인 것은 정규화 화면에서 큰 이동일 수 있다. 같은 숫자를 다른 출력에 그대로 재사용하지 말고, 각 출력의 자연스러운 범위에서 진폭을 정한다.

진폭의 해석은 노이즈 함수의 출력 범위에도 달려 있다. 함수가 $[0,1]$을 반환하는데 값을 그대로 더하면 변화가 한쪽 방향으로 치우친다. 중심을 기준으로 양방향 변화가 필요하면 $[0,1]$을 $[-1,1]$로 옮긴 뒤 기준값에 더한다.

```text
noise01 = noise(position * frequency)   # 노이즈 출력이 [0, 1]이라고 가정
signedNoise = 2 * noise01 - 1           # [-1, 1]로 이동
brightness = baseBrightness + amplitude * signedNoise
offsetPixels = maxOffsetPixels * signedNoise
```

이 매핑에서 `amplitude`는 기준 밝기에서 위아래로 벗어나는 최대 폭이고, `maxOffsetPixels`는 좌표가 기준 위치에서 움직일 수 있는 최대 거리다. 밝기 범위가 $[0,1]$이라면 `baseBrightness ± amplitude`가 그 범위를 넘지 않게 잡거나 마지막에 제한해야 한다. 값을 제한하면 범위 밖의 밝기가 같은 최댓값이나 최솟값으로 눌리므로, 넓은 영역이 단색으로 뭉칠 수 있다는 점도 고려한다. 노이즈가 처음부터 $[-1,1]$을 반환한다면 중심 이동은 생략한다.

## 특징 크기로 주파수 생각하기

주파수는 숫자 자체보다 화면에서 보이는 특징의 크기로 판단하는 편이 직관적이다. 예를 들어 가로 폭이 $800$픽셀인 캔버스에서 좌표를 $[0,1]$로 정규화하고 노이즈 입력에 $f=20$을 곱하면, 입력 공간의 특징 크기를 대략 $800/20=40$픽셀 정도로 예상할 수 있다. 이는 노이즈 함수의 특성에 따른 근삿값이지, 화면에 정확히 20개의 반복이 생긴다는 뜻은 아니다.

원하는 특징의 크기를 먼저 픽셀 단위로 정하면 해상도가 달라져도 조절하기 쉽다. 특징 크기를 $\ell$픽셀로 두고 픽셀 좌표 $(x,y)$를 직접 쓸 때는 $(x/\ell,y/\ell)$을 노이즈 입력으로 사용한다. 정규화 좌표 $(u,v)$를 쓴다면 이를 $(uW/\ell,vH/\ell)$로 바꾸면 된다. 여기서 $W,H$는 화면의 가로와 세로 픽셀 수다.

```text
u = xPixel / canvasWidth
v = yPixel / canvasHeight

noiseX = u * canvasWidth / targetFeaturePixels
noiseY = v * canvasHeight / targetFeaturePixels
value = noise2D(noiseX, noiseY)
```

이렇게 하면 캔버스 크기에 맞춰 입력 스케일을 조절할 수 있다. 반대로 해상도가 바뀌어도 화면 전체에서 비슷한 개수의 큰 무늬를 유지하고 싶다면 정규화 좌표에 곱하는 주파수를 고정한다. 즉, 화면의 픽셀 크기를 유지할지 화면 전체에 대한 비율을 유지할지 먼저 선택한다.

도형의 크기와 노이즈 특징 크기의 관계도 중요하다. 도형보다 훨씬 큰 저주파 노이즈는 여러 도형을 같은 방향으로 묶고, 도형보다 작은 고주파 노이즈는 표면 질감이나 미세한 흔들림으로 읽힌다. fBm에서 옥타브가 높아질수록 특징 크기도 작아지므로, 화면에서 더는 구별되지 않는 옥타브를 계속 계산하지 않는 편이 결과와 성능 모두에 유리하다.

예를 들어 정규화된 화면 너비가 $800$픽셀이고 첫 옥타브의 특징 크기가 약 $40$픽셀이라면, 주파수를 두 배로 높일 때 특징 크기는 대략 $20$, $10$, $5$, $2.5$, $1.25$픽셀로 줄어든다. 마지막 단계는 픽셀 표본화에서 불안정해질 수 있다. 실제 특징 크기는 노이즈 구현에 따라 다르지만, 이 계산은 어떤 옥타브가 최종 해상도에서 보이지 않을지 가늠하는 데 도움이 된다.

```text
octaveFrequency = baseFrequency
for octave from 0 to octaveCount - 1:
    estimatedFeaturePixels = canvasWidth / octaveFrequency
    if estimatedFeaturePixels < minimumFeaturePixels:
        stop adding octaves
    add this octave to the field
    octaveFrequency *= lacunarity
```

`minimumFeaturePixels`는 보통 몇 픽셀 정도로 두고 출력 크기에서 조정한다. 작은 캔버스나 축소된 미리 보기에서는 옥타브를 줄이고, 큰 화면에서는 더 많은 세부를 허용할 수 있다. 화면의 가로세로 비율이 크게 다르다면 짧은 변이나 각 축의 입력 변화량을 기준으로 세부 한계를 판단한다.

## 시간 주파수는 별도 파라미터다

시간을 노이즈 입력으로 넣을 때는 공간 주파수와 시간에 따른 입력 변화 속도를 나눈다.

$$
v(\mathbf{p},t)=A\,n(f_s\mathbf{p},f_t t)
$$

```text
value = noise(position * spatialFrequency,
              elapsedTime * temporalFrequency)
```

$f_s$는 무늬의 공간 크기를 정한다. $f_t$는 시간 입력을 노이즈 공간에서 얼마나 빠르게 이동시킬지 정한다. 시간 $t$를 초 단위로 넣는다면 $f_t$의 단위는 초당 노이즈 입력 단위다. 노이즈는 보통 주기적이지 않으므로 이를 엄밀한 의미의 초당 반복 횟수(Hz)로 해석해서는 안 된다.

```text
timeSeconds = frameIndex / framesPerSecond
timeCoordinate = timeSeconds * temporalRate
value = noise3D(x / featureSizePixels,
                y / featureSizePixels,
                timeCoordinate)
```

이 코드에서 `temporalRate`가 초당 노이즈 입력 좌표의 이동량을 정한다. 예를 들어 초당 $0.12$ 입력 단위로 이동한다면 초당 60프레임에서 프레임마다 입력은 $0.12/60=0.002$씩 변한다. 반대로 `frameIndex * 0.12`처럼 프레임 번호에 직접 곱하면 프레임당 이동량이 0.12가 되어, 초당 속도는 프레임률에 따라 달라진다. 프레임률이 달라져도 같은 속도를 원한다면 경과 시간을 초 단위로 계산한다.

공간적으로 세밀한 무늬가 반드시 빠르게 움직일 이유는 없다. 고주파 세부에 높은 시간 변화 속도까지 더하면 한 프레임 사이에서도 값이 크게 달라져 반짝임이 생기기 쉽다. 미세한 스케일의 시간 변화 속도를 낮추거나, 작은 옥타브의 진폭을 줄이면 움직임이 더 안정적으로 보인다.

## 옥타브와 대비의 관계

옥타브 수를 늘리면 값의 세부가 많아지지만, 최종 화면의 대비가 자동으로 좋아지는 것은 아니다. 여러 옥타브의 합은 평균 근처에 모이거나 범위가 넓어질 수 있다. 색상 보간이나 임계값에 넣기 전에 정규화, 감마 조정, `smoothstep` 같은 대비 함수를 사용하면 필요한 구간을 강조할 수 있다.

```text
value = normalizedFbm(p)
contrastValue = smoothstep(low, high, value)
```

`low`와 `high`를 가까이 두면 작은 변화도 강한 얼룩으로 보이고, 멀리 두면 부드러운 그라데이션이 남는다. 이는 노이즈 자체의 주파수나 진폭과 다른, 출력 해석 단계의 대비 파라미터다.

## 조절 순서와 진단

여러 파라미터를 한꺼번에 바꾸면 어떤 값이 결과를 바꿨는지 알기 어렵다. 다음 순서는 노이즈 기반 패턴을 조절할 때 실용적이다.

1. 옥타브 하나로 원하는 특징 크기를 만드는 공간 주파수를 정한다.
2. 출력 진폭을 조절해 색·변위·높이의 변화 폭을 정한다.
3. 필요한 만큼만 옥타브를 추가하고 gain으로 세부의 강도를 맞춘다.
4. 최종 해상도와 애니메이션 속도에서 깜빡임과 과도한 변위를 확인한다.

처음에는 옥타브를 하나만 사용해 특징 크기를 확인하고, 이후 출력 범위를 정한 다음 필요한 세부를 추가한다. 각 단계의 표본을 회색조로 표시하면 공간 주파수와 진폭이 각각 어떻게 작용하는지 살펴보기 쉽다. 최종 해상도에서 패턴을 확인하고, 확대·축소되는 화면이나 애니메이션이라면 크기가 바뀌는 순간에도 고주파 세부가 깜빡이지 않는지 점검한다.

## 이 절의 핵심

주파수는 크기, 진폭은 폭, 옥타브는 계층을 정한다. 세 파라미터를 동시에 올리기보다 하나씩 조절하며 화면 해상도와 비교한다.
