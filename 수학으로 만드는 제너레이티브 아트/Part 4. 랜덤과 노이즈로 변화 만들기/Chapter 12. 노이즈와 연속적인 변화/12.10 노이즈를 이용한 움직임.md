# 12.10 노이즈를 이용한 움직임

프레임마다 새 난수를 뽑아 위치를 정하면 점은 한 위치에서 다른 위치로 튀어 다닌다. 노이즈에 시간 $t$를 입력으로 넣으면, 시간에 따라 연속적으로 변하는 필드를 따라 같은 객체가 부드럽게 움직인다. 매 시각에 노이즈 함수를 다시 평가해도 객체의 이전 위치가 필요하지 않은 방법과, 이전 위치와 속도를 다음 계산에 사용하는 방법이 있다.

$$
\mathbf{p}(t)=\mathbf{p}_0+A\,\mathbf{n}(id,\omega t)
$$

```text
for each particle:
    x = baseX + amplitude * noise(id, time * speed)
    y = baseY + amplitude * noise(id + 1000, time * speed)
```

`id`는 객체마다 다른 출발점을 만들고, `time * speed`는 변화 속도를 정한다. x와 y에 같은 노이즈를 사용하면 대각선 왕복처럼 보이기 쉬우므로 입력 오프셋을 나눈다. 밝기, 회전, 크기도 서로 다른 노이즈 채널에 연결하면 한 개체가 살아 있는 듯한 미세한 변화가 생긴다.

여기서 중요한 점은 같은 객체에는 프레임이 바뀌어도 같은 `id`를 사용하는 것이다. 매 프레임 새 난수로 ID를 바꾸면 노이즈 공간의 다른 위치를 계속 읽게 되어 연속성이 사라진다. 입자 배열의 현재 인덱스보다 생성 시 부여한 고정 식별자나 고정 시드가 적합하다. 서로 가까운 ID를 노이즈 입력으로 사용하면 객체끼리 비슷한 움직임을 공유할 수 있고, 입력값을 충분히 떨어뜨리면 각자의 움직임이 더 달라진다. 이 차이는 완전한 독립 여부가 아니라 움직임 사이의 상관을 조절한다.

노이즈 함수가 $[0,1]$을 반환하면 위치 오프셋을 만들기 전에 $[-1,1]$ 부근의 0 중심 값으로 옮긴다. 그렇지 않으면 모든 개체가 기준 위치의 한쪽으로 치우칠 수 있다. 프레임 번호에 임의 값을 더하는 방식과 달리, 고정된 ID와 연속적인 시간 입력을 사용하면 같은 시각의 결과도 언제나 동일하게 재현된다.

반복 애니메이션이 필요하다면 시간축을 직선으로 넣는 대신 원 위를 돈다. $n(x,y,\cos\theta,\sin\theta)$처럼 4차원 노이즈를 평가하면 시작 프레임과 끝 프레임이 같은 입력 위치로 이어질 수 있다. 원을 따라 움직이는 입력이므로 값뿐 아니라 프레임 사이의 변화도 부드럽게 연결된다. 반복 루프는 뒤에서 더 자세히 다룬다.

## 위치를 직접 평가하는 움직임

위 예제는 시간에서 현재 위치를 직접 계산한다. 이전 프레임의 위치를 저장하지 않아도 되고, 임의의 시각 $t$에 곧바로 이동할 수 있으므로 부유하는 장식이나 루프 영상에 적합하다.

$$
\mathbf{p}(t)=\mathbf{p}_0+A\,\mathbf{n}(id,t)
$$

노이즈 구현이 $[0,1]$ 범위를 반환한다면, 위치 오프셋에는 $2n-1$처럼 0 중심 범위로 옮긴 값을 사용한다. 그렇지 않으면 모든 객체가 기준점의 한쪽으로 치우친다.

```text
offset = 2 * vectorNoise(id, time * speed) - 1
position = basePosition + offset * travelAmplitude
```

이 방식에서 `travelAmplitude`는 기준 위치에서 움직일 수 있는 범위를 정한다. 두 좌표 성분 각각에 같은 진폭을 곱하면 가능한 영역은 중심을 둘러싼 정사각형에 가까워지며, 가장 먼 모서리까지의 거리는 진폭보다 커질 수 있다. 반경이 일정한 원 안에서만 움직이게 하고 싶다면 오프셋 벡터의 길이를 제한하거나, 방향과 반지름을 따로 계산한다.

직접 위치를 평가하는 움직임은 범위가 자동으로 제한된다는 장점이 있지만 속도가 일정하지 않다. 노이즈 곡선의 기울기가 큰 구간에서는 빨리 지나가고, 기울기가 작은 구간에서는 천천히 머문다. 천천히 떠다니는 생물이나 구름에는 자연스럽지만, 일정한 속도로 이동해야 하는 물체에는 적합하지 않을 수 있다. `speed` 또는 시간 스케일을 높이면 노이즈 입력이 시간축에서 더 빨리 이동해 위치 변화가 빨라질 수 있지만, 일정한 속도가 보장되지는 않는다.

속도가 아니라 위치를 계산하는 간단한 2D 예시는 다음과 같다.

```text
timeCoordinate = elapsedSeconds * timeRate
nx = 2 * noise2D(idX, timeCoordinate) - 1
ny = 2 * noise2D(idY, timeCoordinate) - 1
position = anchor + amplitude * (nx, ny)
```

`idX`와 `idY`는 고정 ID에서 만든 서로 다른 입력 좌표다. 이 예시에서는 매 프레임 `elapsedSeconds`만 갱신한다. 초 단위 시간을 사용하면 프레임률이 달라도 같은 시각에는 같은 위치가 계산된다.

## 속도를 노이즈로 정하는 움직임

노이즈를 위치가 아니라 속도 또는 가속도에 연결할 수도 있다. 이 경우에는 이전 위치가 다음 위치에 영향을 주므로 상태를 저장하고 시간 간격으로 적분해야 한다.

$$
\mathbf{v}_{t+\Delta t}=A\,\mathbf{n}(\mathbf{p}_t,t),\qquad
\mathbf{p}_{t+\Delta t}=\mathbf{p}_t+\mathbf{v}_{t+\Delta t}\Delta t
$$

```text
direction = vectorNoise(particle.position * spatialFrequency,
                        time * temporalFrequency)
direction = 2 * direction - 1             # vectorNoise가 [0, 1]을 반환한다고 가정
particle.velocity = normalize(direction) * speed
particle.position += particle.velocity * deltaTime
```

여기서는 노이즈 벡터의 방향을 단위 길이로 만든 뒤 속력을 곱하므로, 위치 함수 방식보다 이동 속도를 일정하게 유지하기 쉽다. 단, 노이즈 벡터의 길이가 0에 가까우면 정규화가 불안정할 수 있으므로 작은 임계값을 확인하고, 그런 경우에는 직전 방향을 유지하거나 잠시 움직임을 줄인다.

직접 위치 함수는 기준점 주변에서 움직임이 제한되지만, 속도 적분은 시간이 지나며 화면 멀리 이동할 수 있다. 흐름 필드와 입자 궤적에는 후자가 적합하며, 화면 경계에서 되돌리기·반복·제거·재생성 같은 규칙이 필요하다. 이 방식을 속도장을 따라가는 입자 운동이라고 볼 수 있다.

### 가속도에 노이즈를 연결해 관성 만들기

매 프레임 속도 방향을 노이즈로 바로 덮어쓰면 경로가 부드러워도 속도의 관성은 약하다. 노이즈를 가속도나 조향 힘으로 사용하면 현재 속도가 조금씩 바뀌어 더 묵직한 움직임을 만들 수 있다.

```text
steering = centeredVectorNoise(position * spatialScale,
                                elapsedSeconds * timeScale)
acceleration = steering * maxForce

velocity += acceleration * deltaTime
velocity = limitLength(velocity, maxSpeed)
position += velocity * deltaTime
```

`maxForce`는 방향을 바꾸는 힘의 크기, `maxSpeed`는 속도의 상한이다. 속도에 상한을 두지 않으면 여러 프레임에 걸쳐 작은 가속도가 계속 더해져 이동이 지나치게 빨라질 수 있다. 마찰을 넣고 싶다면 속도에 시간 간격을 고려한 감쇠를 적용한다. 가속도 적분은 이전 속도와 위치가 결과에 남기 때문에 직접 위치 평가와 달리 임의의 시각으로 즉시 건너뛰기 어렵다.

적분할 때 `deltaTime`은 프레임이 지난 시간(초)이다. 프레임 간격이 들쭉날쭉해도 같은 속도를 유지하려면 위치 갱신에 이 값을 곱한다. 큰 지연 뒤 한 번에 큰 값이 들어와 입자가 튀는 문제가 있으면 시간 간격을 작은 단계로 나누어 여러 번 업데이트하거나 한 업데이트의 간격에 상한을 둔다.

| 방식 | 저장하는 값 | 움직임 범위 | 잘 맞는 예 |
| --- | --- | --- | --- |
| 위치를 직접 평가 | 기준 위치와 ID | 기준점 주변으로 제한됨 | 부유하는 장식, 루프 애니메이션 |
| 속도를 노이즈로 지정 | 위치 | 계속 멀리 이동할 수 있음 | 입자, 흐름을 따르는 점 |
| 가속도를 노이즈로 지정 | 위치와 속도 | 관성에 따라 계속 이동 | 방향 전환이 느린 생물, 무거운 물체 |

## 시간 주파수와 채널의 분리

시간 주파수가 낮으면 객체는 천천히 방향을 바꾸고, 높으면 진동과 떨림이 커진다. 공간 주파수가 낮은 벡터 노이즈는 가까운 객체가 비슷한 흐름을 공유하게 하고, 객체 ID 중심의 입력은 각 요소를 더 독립적으로 움직이게 한다.

```text
# 공통 흐름
flow = centeredVectorNoise(position * lowSpatialFrequency, time * slowTime)

# 개체별 변화
individual = centeredVectorNoise(id * idScale, time * slowTime)
```

위치, 크기, 회전, 밝기가 모두 같은 채널을 사용하면 한 리듬으로 변해 기계적으로 보일 수 있다. 입력 오프셋을 나누거나 일부 속성만 채널을 공유해, 독립성과 관계를 의도적으로 섞는다.

채널을 나누는 일은 입력을 단순히 상수만큼 옮기는 것과, 완전히 다른 난수 시퀀스를 쓰는 것 사이에서 원하는 상관을 찾는 과정이다. 가까운 객체의 움직임을 묶고 싶다면 공간 좌표를 공유하는 흐름 값을 크게 섞고, 객체별 노이즈는 작게 더한다.

```text
sharedMotion = centeredVectorNoise(position * groupScale, time * slowRate)
personalMotion = centeredVectorNoise(stableId * idScale, time * personalRate)
motion = sharedWeight * sharedMotion + personalWeight * personalMotion
```

`centeredVectorNoise`는 각 성분의 평균이 0이 되도록 맞춘 벡터 노이즈를 뜻한다. 기반 노이즈가 $[0,1]$ 범위라면 성분마다 $2n-1$을 적용한다. `sharedWeight`가 크면 무리 전체가 비슷한 방향으로 움직이고, `personalWeight`가 크면 개체별 차이가 커진다. 위치, 회전, 크기 같은 속성에도 같은 원리를 적용할 수 있지만, 속성마다 단위가 다르므로 각자 알맞은 변동 폭을 둔다.

속도 적분을 사용할 때는 객체가 화면 밖으로 나가지 않도록 경계 규칙도 정한다. 화면 반대편으로 이어지는 래핑은 흐름이 끊기지 않는 효과를 내고, 반사는 입자가 벽에 부딪혀 되돌아오는 인상을 준다. 위치를 경계에 고정하는 클램프는 구현이 간단하지만, 입자가 가장자리에 달라붙어 움직임을 멈춘 것처럼 보일 수 있다.

```text
if position.x < leftEdge:
    position.x = leftEdge
    velocity.x = abs(velocity.x)
if position.x > rightEdge:
    position.x = rightEdge
    velocity.x = -abs(velocity.x)
```

위 예시는 좌우 경계에서 반사하는 규칙이다. 위아래 경계에도 같은 처리를 적용하거나, 작품의 공간에 맞춰 래핑·제거·재생성으로 바꾼다. 경계 규칙은 입자의 움직임만 정하는 것이 아니라 화면 가장자리에서 보이는 패턴의 연결 방식도 결정한다.

## 반복 루프의 시간 좌표

길이 $T$인 루프에서는 현재 시간을 각도 $\theta$로 바꾼다.

$$
\theta=2\pi\frac{t}{T}
$$

4D 노이즈를 사용할 수 있다면 원형 시간 좌표를 입력한다.

$$
v=n\left(\mathbf{p},r\cos\theta,r\sin\theta\right)
$$

```text
theta = TAU * frameIndex / totalFrames
value = noise4D(x, y, loopRadius * cos(theta), loopRadius * sin(theta))
```

`loopRadius`는 시간에 해당하는 두 입력 축에서 원이 얼마나 큰지를 정한다. 반지름이 커질수록 한 주기 동안 노이즈 입력 공간에서 더 먼 거리를 이동하므로 변화가 빠르고 복잡해질 수 있다. 이는 반복 횟수를 직접 지정하는 값은 아니다. 루프의 변화가 지나치게 잦으면 반지름을 줄이고, 변화가 거의 없으면 조금 키운다.

이미지 시퀀스에서는 보통 프레임을 0부터 `totalFrames - 1`까지만 생성한다. $t=T$의 프레임은 첫 프레임과 같은 입력이므로 중복 저장하지 않는다. 루프 안에서 위치뿐 아니라 크기나 색도 변한다면 각 속성이 같은 주기의 시간 좌표를 공유하는지 확인한다. 한 속성만 루프 끝에서 초기화되면 화면 전체의 연결이 끊겨 보인다.

4차원 노이즈를 사용할 수 없을 때에는 노이즈로 개체별 위상이나 크기를 정하고, 움직임 자체는 사인·코사인처럼 주기적인 함수로 만들 수도 있다.

```text
phaseOffset = TAU * noise(stableId)
theta = TAU * frameIndex / totalFrames
x = centerX + radiusX * cos(theta + phaseOffset)
y = centerY + radiusY * sin(theta + phaseOffset)
```

이 방법은 개체마다 궤도의 위상을 바꾸면서 루프의 연결은 유지한다. 다만 경로 모양은 기본적으로 타원이며, 4차원 노이즈를 원형 시간축으로 표본화하는 방식과 같은 궤적을 만들지는 않는다.

## 출력 안정성과 Chapter 12의 마무리

처음에는 위치 오프셋만 점이나 선으로 표시해 경로, 범위, 속도 변화를 확인한다. 시간 주파수, 진폭, 속성 연결을 한 번에 바꾸면 원인을 찾기 어려우므로 한 항목씩 추가한다. 같은 ID와 시각에서 결과가 재현되는지도 확인한다. 속도를 적분할 때는 `deltaTime`을 곱하고, 위치를 시간 함수로 직접 계산할 때는 `elapsedTime`을 입력으로 쓴다.

Chapter 12에서 다룬 노이즈는 무작위 이미지를 만드는 버튼이 아니라, 좌표와 시간에서 연속적인 필드를 만드는 함수다. 다음 Chapter 13에서는 이 필드를 색, 거리, 방향, 밀도, 움직임의 공통 입력으로 다룬다.

## 이 절의 핵심

시간을 노이즈 입력에 포함하면 프레임 간 연속성이 생긴다. 객체 식별자와 채널 오프셋으로 각 객체의 움직임을 구분한다.
