# 📘 WebGL의 기본 이해
## 1. 제너레이티브 아트의 핵심과 WebGL의 위치

제너레이티브 아트의 본질은 다음 세 가지로 요약할 수 있다.
- 수학적 규칙과 확률
- 시간에 따른 변화
- 공간 좌표계에서의 형태 생성

WebGL은 이 세 가지를 가장 원초적인 그래픽 파이프라인 수준에서 다룬다.

- 좌표 변환: 모델 좌표 → 월드 좌표 → 뷰 → 클립 공간
- 병렬 계산: 수천~수백만 개의 버텍스와 프래그먼트를 동시에 처리
- 셰이더 언어(GLSL): 이미지와 형태를 “함수”로 정의

즉, WebGL은
“선을 그린다”, “원을 그린다” 이전에
“픽셀 하나가 왜 이 색이 되는가”를 설명하는 도구다.

---
## 2. p5.js, Processing과 비교

### 2.1 p5.js / Processing

- 선언적, 즉각적
- 아이디어 스케치에 매우 유리
- CPU 중심 연산
- 그래픽 파이프라인이 추상화되어 있음

### 2.2 WebGL

- 명령형, 구조적
- 초기 진입 비용이 높음
- GPU 중심 병렬 처리
- 파이프라인을 직접 다룸

제너레이티브 아트 관점에서 중요한 차이는 이것이다.

>- `p5.js` “무엇을 그릴 것인가”
- `WebGL` “어떻게 그려지는가”

이 차이를 이해하면,
p5.js에서 쓴 코드의 표현적 한계가 왜 생기는지도 명확해진다.

---
## 3. 제너레이티브 아트의 사고방식을 바꾸는 Shader

WebGL을 공부하면서 가장 크게 달라지는 지점은 Shader의 적용이다.

- 루프 대신 좌표 기반 함수
- 상태 대신 시간 함수
- 객체 대신 필드(field)

예를 들어 원을 그릴 때도

- 기존 방식: “for 문으로 점을 찍는다”
- 셰이더 방식: “이 픽셀이 원 내부인가?”

이 전환은 제너레이티브 아트의 표현 범위를 크게 넓힌다.

- 노이즈 기반 패턴
- SDF(Signed Distance Field)
- 연속적인 형태 변형
- 해상도 독립적 이미지

이 사고방식은 WebGL을 넘어
TouchDesigner, Houdini, Blender Geometry Nodes, 심지어 After Effects의 표현식까지 연결된다.

  - GLSL
  - 실시간 렌더링과 오프라인 렌더링의 차이
  - WebGL과 OpenGL의 연속성
  
>
WebGL은 "즉각적 재미"보다 "표현의 근본을 이해하는 즐거움"

# 📘 WebGL 개념 목록
## 1. 그래픽 파이프라인의 전체 구조

WebGL을 공부할 때 가장 먼저 잡아야 할 것은 “순서”다.

- CPU(JavaScript)
- GPU 입력(Buffer, Attribute)
- Vertex Shader
- Primitive Assembly
- Rasterization
- Fragment Shader
- Framebuffer 출력

제너레이티브 아트에서 중요한 이유는 다음과 같다.

- 형태는 버텍스 단계에서 결정된다
- 패턴과 질감은 프래그먼트 단계에서 결정된다
- “무작위”처럼 보이는 결과도 실제로는 이 파이프라인을 통과한 결정론적 계산 결과다

이 구조를 이해하면,

- 왜 for 루프를 GPU에서 못 쓰는지
- 왜 프래그먼트 셰이더에 상태가 없는지
자연스럽게 이해된다.

---

## 2. 좌표계와 공간 변환

제너레이티브 아트에서 좌표계는 곧 언어다.

- Object Space
- World Space
- View Space
- Clip Space
- Normalized Device Coordinates
- Screen Space

특히 중요한 포인트는 다음 두 가지다.

- Vertex Shader는 좌표를 만드는 곳
- Fragment Shader는 좌표를 해석하는 곳

p5.js에서의 (x, y) 사고를 버리고
**“좌표를 함수의 입력값으로 쓰는 사고”**로 전환해야 한다.

---

## 3. Attribute, Uniform, Varying의 역할 구분

이 세 가지는 WebGL 사고의 핵심 축이다.
- Attribute
→ 버텍스마다 다른 데이터
→ 위치, 크기, 인덱스, 랜덤 시드

- Uniform
→ 모든 버텍스와 프래그먼트에 동일
→ 시간, 해상도, 마우스 입력

- Varying
→ 버텍스에서 프래그먼트로 보간되어 전달
→ 거리, 노멀, 색상 값

제너레이티브 아트에서는 **“랜덤을 어디에 두느냐”**가 곧 작품의 성격을 결정한다.

---

## 4. GLSL의 함수적 사고방식

GLSL은 일반적인 프로그래밍 언어와 사고가 다르다.

- 상태가 없다
- 객체가 없다
- 픽셀은 서로를 모른다

중요한 개념은 다음이다.

- 함수는 좌표를 받아 색을 반환한다
- 반복 대신 수학적 패턴 사용
- 분기(if)는 비용이 크다

이로 인해 다음 개념들이 자연스럽게 중요해진다.

- sin, cos, fract, step, smoothstep
- noise, hash 함수
- 시간 기반 함수 조합

---

## 5. Signed Distance Field(SDF)

SDF는 제너레이티브 아트에서 가장 강력한 표현 도구 중 하나다.

- 형태를 “면”이 아니라 “거리 함수”로 정의
- 해상도 독립
- 부드러운 변형과 결합이 쉬움

예:

- 원, 사각형, 다각형
- 형태 간 블렌딩
- 반복 패턴, 왜곡

SDF 사고를 익히면

- 드로잉이 아니라 “형태 정의”를 하게 된다.

---

## 6. 시간(Time)을 다루는 방식

WebGL에서 시간은 특별하다.
- 프레임 카운트 기반이 아니다
- 절대 시간 혹은 누적 시간 기반

중요 포인트:
- sin(time) 기반 반복
- phase offset으로 개체 간 차이 생성
- 시간과 좌표의 결합

이는 After Effects 표현식, TouchDesigner, Houdini와도 개념적으로 동일하다.

---

## 7. 병렬성에 대한 이해

GPU는 “빠른 CPU”가 아니다.
- 수천 개의 픽셀이 동시에 실행
- 서로의 결과를 참조하지 못함

이것을 이해하면 다음이 명확해진다.

- 왜 셰이더에서 전역 변수 업데이트가 불가능한지
- 왜 피드백이 필요하면 FBO를 써야 하는지

---

## 8. Framebuffer Object(FBO)

제너레이티브 아트에서 FBO는 기억(memory) 역할을 한다.
- 이전 프레임을 다음 프레임의 입력으로 사용
- 붓 자국, 잔상, 확산 효과 구현
- 시뮬레이션 기반 비주얼 가능

FBO를 이해하면

- “한 번 그린 그림”을 넘어
- “시간에 쌓이는 이미지”를 다룰 수 있다.

# 📘 WebGL1과 WebGL2
## 1. 기본적인 차이 요약

- WebGL1
→ OpenGL ES 2.0 기반

- WebGL2
→ OpenGL ES 3.0 기반

WebGL2는 단순한 확장이 아니라 그래픽 세대가 하나 올라간 것이다.

## 2. WebGL2에서 추가된 핵심 기능

제너레이티브 아트 관점에서 중요한 것만 정리하면 다음과 같다.

- Multiple Render Targets (MRT)
→ 한 번에 여러 버퍼 출력 가능

- 3D Texture
→ 볼륨 데이터, 시공간 노이즈

- Integer Texture
→ 정밀한 데이터 처리

- Vertex Array Object (VAO)
→ 구조 정리, 코드 안정성

- instanced rendering 강화
→ 대량 객체 처리에 유리

이 기능들은 모두 **“규모가 커질수록 의미를 갖는 기능”**들이다.

## 3. GLSL 차이

- WebGL1: GLSL ES 1.00
- WebGL2: GLSL ES 3.00

GLSL 3.00의 장점:

- 명확한 in / out 키워드
- layout(location) 사용 가능
- 코드 가독성과 구조 개선


## 4. 호환성과 현실적인 선택

- 최신 데스크톱 브라우저: WebGL2 안정적 지원
- 모바일 브라우저: 대부분 WebGL2 지원
- 특수 환경(아주 오래된 기기): WebGL1만 가능

제너레이티브 아트 작업이나 셰이더 작업은 WebGL2를 기본으로 선택하는 것이 합리적이다.
