## 개요

포토샵이나 일러스트레이터와 같은 무겁고 GUI 기반의 상업용 툴이 아니라 코딩을 통해 인터랙션이 있는 아트워크를 만들어 보고 싶은 디자이너에게 p5.js는 굉장히 좋은 선택일 것입니다.

p5.js는 아트워크를 보여줄 때 웹 브라우저를 사용합니다.만약 로컬 환경에서 어플리케이션 형식으로 제작하고 싶다면 몇가지 선택지가 더 있습니다. p5.js의 전신 격인 Processing, Rust를 사용하는 nannou, kotlin을 사용하는 OPENRNDR, C++를 사용하는 openFrameworks, 혹은 Blender에서 사용하는 Blender Python API를 공부하는 것도 좋은 선택입니다.

이 카테고리에서는 p5.js에 집중하고, p5.js를 통해 Computational Art, Generative Art를 경험해보도록 하겠습니다.

p5.js를 배우기 시작할 때 실행을 하기 위한 준비 과정이 은근히 복잡합니다. 튜토리얼을 보면 바로 뭔가를 만드는 코드를 쓰기 시작하지만, 막상 로컬 환경에서 내 폴더를 만드는 순간부터 창을 띄울 때 까지는 모종의 작업이 필요하고 방법도 다양합니다. 특히 컴퓨터 비전공자에게는 이런 환경 구축 자체가 진이 빠지는 일이 되곤 합니다.

이 글에서는 p5.js 실행을 위한 방법의 종류와 각 방법의 장단점을 살펴보도록 하겠습니다.  
난이도에 따라 순서를 매긴다면;

### 1\. p5.js 공식 웹 에디터 : editor.p5js.org
### 2\. Processing IDE에서 p5.js 모드
### 3\. VSCode에서 p5.js 익스텐션 + 라이브 서버
### 4\. Vite 서버 + ESM 방식
### 5\. Vite + React p5 wrapper

이정도가 될 거 같습니다. 아래에 각각 방법의 특징과 장단점을 정리해보았습니다.

## 1\. p5.js 공식 웹 에디터 : editor.p5js.org

이 방법은 p5.js의 온라인 에디터를 사용하는 것으로, 브라우저에서 바로 코드를 작성하고 실행할 수 있습니다. 설치 없이 클라우드 기반으로 동작합니다.

### 장점:

-   별도의 설치나 설정 없이 어떤 OS나 기기에서도 브라우저만 있으면 바로 시작할 수 있습니다.
-   튜토리얼과 예제가 내장되어 있어 공부하기 좋습니다.
-   코드 스케치를 URL로 공유하거나, 커뮤니티에 쉽게 업로드할 수 있습니다.
-   실시간으로 캔버스 결과를 볼 수 있습니다.

### 단점:

-   오프라인에서 사용할 수 없고, 연결이 불안정하면 작업이 중단될 수 있습니다.
-   고급 파일 관리(예: 여러 파일 프로젝트)나 외부 라이브러리 통합이 까다롭습니다.
-   대규모 프로젝트에는 부적합합니다.
-   브라우저 기반이라 복잡한 스케치에서는 속도가 느려집니다.
-   로컬 저장이 아니므로 작업물이 사라질 위험이 있습니다. (클라우드에 저장 가능)

## 3\. VSCode에서 p5.vscode + Live Server 가동

VSCode 에디터에 p5.js용 익스텐션(p5.vscode, Sam Lavigne 제작)을 설치하고, Live Server 익스텐션으로 로컬 서버를 띄워 HTML/JS 파일을 실행하는 방식입니다. 기본적인 로컬 개발 환경입니다.

### 장점:

-   VSCode의 자동 완성, 디버깅, Git 통합 등 고급 도구를 활용할 수 있어 코드 작성이 효율적입니다.
-   p5.js 확장이 스니펫과 문법 하이라이트를 제공합니다.
-   코드 작성은 인터넷 없이 가능하고, 실행 시 로컬 서버만 필요합니다. (브라우저는 필요)
-   여러 파일을 관리하거나, 외부 라이브러리를 쉽게 추가할 수 있습니다. 학습 중에 프로젝트를 확장하기 좋습니다.
-   VSCode와 익스텐션만 설치하면 되며, 서버 가동이 간단합니다.

### 단점:

-   완전 초보자라면 웹 에디터보다 번거로울 수 있습니다.
-   매번 서버를 수동으로 실행해야 하며, 포트 충돌이나 브라우저 호환성 문제가 발생할 수 있습니다.
-   React나 모듈 시스템처럼 현대적이지 않아, 나중에 큰 앱으로 확장할 때 파일 트리와 코드를 다시 만져야 합니다.

## 4\. Vite + Vanilla + ESM 방식

Vite를 빌드 도구로 사용해 Node.js 환경에서 프로젝트를 설정하고, ES Modules(ESM)로 p5.js를 import하는 방법입니다. 터미널에서 Vite를 설치하고 서버를 띄웁니다.

### 장점:

-   ESM을 통해 모듈화된 코드를 작성할 수 있어, 코드 구조가 깔끔하고 유지보수가 쉽습니다.
-   Vite의 빠른 HMR(Hot Module Replacement)로 변경 사항이 실시간 반영됩니다.
-   개발 중 빠른 로딩과 빌드 속도를 제공하며, 프로덕션 배포에 적합합니다.
-   p5.js를 다른 JS 라이브러리와 쉽게 결합할 수 있습니다.
-   여러 파일/모듈을 다루는 중급 이상 프로젝트에 좋고, 나중에 웹 앱으로 발전시킬 수 있습니다.

### 단점:

-   Node.js 설치, Vite / p5.js 설치, 라이브러리 설치 등 Terminal에서 명령어로 지시합니다.
-   p5.js 외에도 서버구동(Vite) 방법과 ESM 개념을 배워야 합니다.
-   의존성 업데이트를 위해 npm 패키지 관리가 필요합니다. 충돌을 신경써야 합니다.
-   초보자는 단순 p5.js의 로직에만 집중하기 어렵습니다.

## 5\. Vite + React p5 wrapper

Vite로 React 앱을 설정하고, react-p5나 p5-react-wrapper 같은 라이브러리를 사용해 p5.js 스케치를 React 컴포넌트로 통합하는 방식입니다.

### 장점:

-   p5.js를 React의 상태 관리, 컴포넌트 재사용과 결합할 수 있어, 인터랙티브 웹 앱(예: 대시보드나 게임)을 만들기 좋습니다. Vite의 속도가 더해져 효율적입니다.
-   복잡한 UI와 p5.js 캔버스를 모듈 형식으로 함께 다룰 수 있으며, props로 데이터 전달이 쉽습니다.
-   현대적인 웹 개발의 중심 중 하나인 React 생태계(라이브러리, 커뮤니티)를 활용할 수 있어, p5.js를 넘어선 실전 프로젝트에 적합합니다.
-   wrapper 덕분에 p5.js 코드를 React 스타일로 캡슐화하고 재사용할 수 있습니다.

### 단점:

-   React와 Vite 설정 외에 wrapper 라이브러리 이해가 필요합니다. p5.js 초보자가 React를 동시에 배우면 과부하될 수 있습니다.
-   단순 스케치 공부에 이 방식은 너무 과합니다.
-   React 문법, hooks, 상태 관리 등을 배워야 하며, 디버깅이 더 어렵습니다.
-   npm, Vite, React, wrapper 패키지 설치가 많아 초반 환경 설정이 번거롭습니다.

## 결론

p5.js를 처음 공부한다면 <방법 1> 웹 에디터 혹은 <방법 2> 프로세싱 IDE부터 시작하는 게 가장 간단하고 효과적입니다. 여기서 개념을 익히고 로컬에서 전문 에디터(VSCode)를 써서 더 효율적인 코딩을 해보세요.

<방법 3>는 웹에디터와 동일한 문법(쉽지만 올드)으로 개발할 수 있고 <방법 4>로는 자바스크립트 개발의 현대적인 스타일을 사용하게 됩니다.

만약 React를 함께 배우고 싶고, 웹 앱이나 홈페이지를 직접 구축하고 싶다면 <방법 5>가 좋습니다. 더 큰 프로젝트에 활용하기 좋은 방식입니다. React에서 사용할 수 있는 그래픽 라이브러리의 wrapper는 p5.js 이외에도 three.js를 감싼 R3F가 있습니다.
